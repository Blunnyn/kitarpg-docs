Referência

Solução de problemas

Problemas que você pode encontrar com o KitARPG, o que cada mensagem significa, por que acontece e como resolver. Encontre seu sintoma por seção: configuração inicial, jogar, serviços MMO, login, builds, bancos de dados, servidores e ferramentas de GM.

#Primeiras verificações

Antes de procurar um problema específico, estas quatro verificações resolvem a maioria deles:

  1. Pare o Play. Muitas configurações ficam bloqueadas durante o Play.
  2. Abra o Project Check (KitARPG > Project Check) e corrija todos os erros. A maioria tem um botão de correção.
  3. Aplique as atualizações do kit pendentes em Overview.
  4. No MMO, recompile e reinicie: em Play & Servers, use Rebuild nos serviços, Rebuild no servidor de mapa e depois Restart.

Logs para ler:

Log Onde
Console do Unity Window > General > Console
Serviços iniciados pelo editor Cartão Log em Play & Servers, ou UserSettings/KitARPG/services.log
Cada servidor de mapa UserSettings/KitARPG/data/logs/map-<id>.log
Shop iniciado pelo editor UserSettings/KitARPG/shop.log
Testes de Play Mode Logs/KitARPG-PlayMode-Tests.xml

#Configuração inicial e importação

#Os materiais estão rosa

O URP não é o pipeline de renderização ativo, ou algum nível de qualidade ainda usa outro pipeline. Os materiais do kit são materiais URP.

Solução: abra KitARPG > Setup Wizard e pressione Set everything up. Ele define o URP como pipeline padrão e em todos os níveis de qualidade, e define a cor Linear. Para verificar à mão: Project Settings > Graphics > Default Render Pipeline e Project Settings > Quality, em todos os níveis.

#Os rótulos não têm texto nem fonte

Os recursos essenciais do TextMesh Pro não estão no projeto. O Project Check mostra o erro "TextMesh Pro's essential resources aren't in the project, so every label in the kit's UI and sample has no font."

Solução: pressione Set everything up no Setup Wizard, ou o botão de importação no erro do Project Check, ou Window > TextMeshPro > Import TMP Essential Resources. No modo batch a importação fica na fila e não termina antes de o Unity fechar; rode-a uma vez no editor normal.

#Os menus não aceitam cliques

O EventSystem de uma cena tem o módulo de UI do outro sistema de input. O Project Check avisa: "<scene>'s EventSystem has the UI module of the other input system, so menus may not take clicks."

Solução: pressione Fix scenes no aviso, ou Set everything up no Setup Wizard. Como reserva, o kit também troca o módulo quando uma cena carrega sob o Input System.

#InvalidOperationException sobre a classe Input ao pressionar Play

O projeto usa só o Input System (os templates novos do Unity usam) e algum script lê UnityEngine.Input diretamente. O código do próprio kit nunca faz isso.

Solução: nos seus scripts, chame KitInput.GetKey, KitInput.GetKeyDown, KitInput.GetMouseButton, KitInput.mousePosition e os demais em vez de Input. Eles funcionam nos dois tipos de projeto. Ou defina Project Settings > Player > Active Input Handling como Both.

#As mudanças em Game Settings não chegam a uma cena

A cena sobrescreve campos do prefab Game Instance, então Game Settings (que edita o prefab) não chega até ela. Um caso comum: os controles de toque aparecem com Input Layout definido como Mouse And Keys. O Project Check avisa: "<scene> overrides Game Settings on its Game Instance (...), so changes in Game Settings don't reach that scene."

Solução: pressione Fix scenes no Project Check. Ele reverte as sobrescritas para que a cena siga o prefab.

#"Scenes in Build Settings" está vermelho

Title não é a primeira cena ativa ou, no MMO, Server não está na lista. O detalhe diz "The first scene must be Title, and Server must be listed."

Solução: pressione Use starter scenes. Ele coloca Title, Server, Town, Forest e Crypt em Build Settings, com Title primeiro. Se a amostra ainda não existe, ele oferece criá-la.

#"SQLite library for this platform" está faltando

O salvamento do modo de um jogador precisa da biblioteca nativa do SQLite em Assets/Blunnyn/KitARPG/Plugins/SQLite/ (macOS/libe_sqlite3.dylib, Windows/e_sqlite3.dll ou Linux/libe_sqlite3.so).

Solução: importe o pacote do KitARPG de novo com a pasta Plugins/SQLite marcada.

#"Stop Play before building the starter sample."

Gerar a amostra durante o Play salvaria objetos quebrados nos seus prefabs.

Solução: pare o Play e gere de novo.

#O Setup Wizard não abre

Ele abre sozinho uma vez por projeto. Depois disso, UserSettings/KitARPG/setup-done o mantém fechado.

Solução: abra KitARPG > Setup Wizard.

#Jogar no editor

#Não consigo mudar Game Settings nem Modules

Os campos ficam bloqueados durante o Play, porque são salvos no prefab de rede.

Solução: pare o Play antes.

#"Add the Title scene to Build Settings first."

Play & Servers abre a cena Title a partir de Build Settings.

Solução: pressione Use starter scenes, ou adicione sua cena Title como a primeira cena.

#O jogo começa sem tela de título

O botão Play do Unity roda a cena aberta. Uma cena de mapa sozinha não tem sessão.

Solução: abra Title, ou use Play em Overview ou em Play & Servers, que abrem Title para você.

#Jogadores ou monstros não se movem em um mapa novo

A cena do mapa não tem NavMesh gerado (baked). O movimento e os monstros usam o NavMesh no servidor.

Solução: adicione um NavMeshSurface à cena e gere o NavMesh (bake). Duplicar a Forest da amostra dá um já configurado. Veja Mapas.

#Os jogadores que chegam a um mapa não têm onde ficar

Project Check: "<scene> has no SpawnPoint; players arriving at '<map>' have nowhere to stand."

Solução: adicione um SpawnPoint à cena.

#Recursos no modo de um jogador respondem "Only on an online server."

Amigos, grupos, guildas, correio, o mercado, coletores, a loja do jogo e alguns comandos de moderação precisam de um servidor.

Solução: mude para MMO em Play & Servers, ou desligue esses sistemas em Módulos para que não apareçam.

#Serviços MMO

#O SDK do .NET 10 não é encontrado

A linha diz "dotnet was not found. Install the .NET 10 SDK, then check again." ou "Found ...; the services need 10." O Unity nem sempre recebe o PATH do seu shell.

Solução: instale o SDK do .NET 10 (não só o runtime) de https://dotnet.microsoft.com/download/dotnet/10.0 e pressione Check again. Se ele estiver instalado em um lugar incomum, coloque um link para dotnet em uma das pastas onde o kit procura: /usr/local/share/dotnet, /usr/local/bin, /opt/homebrew/bin, ~/.dotnet no Mac e no Linux, C:\Program Files\dotnet no Windows. Reiniciar o Unity Hub e o Unity depois de instalar também atualiza o PATH.

#"Services source: Not found."

O kit não encontrou uma pasta com KitARPG.Services.slnx. Ele procura ao lado da pasta do seu projeto Unity (../Services), dentro dela (Services) e em Assets/Blunnyn/KitARPG/Services~.

Solução: espere o editor terminar de carregar (ele descompacta Services.zip ao carregar), ou pressione Browse e escolha a pasta. Se Services~ não existe, verifique se Assets/Blunnyn/KitARPG/Services.zip foi importado.

#"dotnet build failed."

Os serviços não compilaram. Play & Servers mostra as primeiras linhas de erro. "dotnet build failed. Run it in a terminal to see why." significa que não havia nenhuma para mostrar.

Solução: abra um terminal na pasta dos serviços e rode dotnet build. Causas comuns: sem internet na primeira vez (os pacotes NuGet são baixados), um SDK anterior ao 10, ou arquivos alterados à mão em Services~. Importar o kit de novo restaura os serviços.

#"Something else is using port ..."

Serviços iniciados por um terminal ou por uma sessão anterior ocupam as portas 5100, 5200 ou 7700. Eles podem estar rodando código antigo.

Solução: pare-os. Se Play & Servers mostra "Services from an earlier editor session are still running (process ...)", pressione Stop the old services. Senão, encontre o processo (no Mac e no Linux lsof -i :5100, no Windows netstat -ano | findstr 5100) e encerre-o.

#"The services or the map server were rebuilt after they started, so they still run the old code. Restart them."

Você recompilou enquanto eles rodavam.

Solução: pressione Restart.

#"No map reached Central"

Overview mostra isso quando os serviços rodam mas nenhum servidor de mapa se registrou. Em geral a build do servidor de mapa está faltando ou desatualizada.

Solução: gere a build do servidor de mapa (Play & Servers, passo 1) e reinicie os serviços. Se persistir, leia UserSettings/KitARPG/data/logs/map-town.log.

#A build do servidor de mapa diz "Missing the scene of a map"

Falta na build a cena de um mapa, então os jogadores que viajam para lá voltam para o login.

Solução: pressione Rebuild. As builds pegam suas cenas dos mapas do Game Database. Se a própria build diz "No scene file named ...", o mapa aponta para uma cena que não existe: corrija o nome na página do mapa.

#"Two players need the MMO mode"

Jogar com dois jogadores só funciona no MMO.

Solução: mude para MMO em Play & Servers.

#Jogar com dois jogadores não inicia o Player 2

O Multiplayer Play Mode do Unity não conseguiu ativar o segundo jogador sozinho. O Console diz para ligar o Player 2.

Solução: em Window > Multiplayer > Multiplayer Play Mode, ligue o Player 2 e pressione Play with two de novo. A primeira execução importa o projeto no segundo editor, o que demora um pouco. Se o diálogo diz "Build the services first", faça o passo 1 de Play & Servers.

#Não consigo mudar o banco de dados

"Stop the services to change the database."

Solução: pressione Stop no passo 3, faça a mudança e inicie de novo.

#version_mismatch: "The game and the server are different versions"

O cliente envia um hash curto de tudo o que trafega pela rede (campos sincronizados, listas e mensagens). O servidor de mapa compara com o seu próprio e recusa um cliente compilado de código diferente, em vez de falhar depois ao ler dados.

Solução: recompile o servidor de mapa (ou o cliente) para que os dois venham do mesmo código e reinicie os serviços. Isso acontece com frequência depois de mudar código, atualizar o kit ou deixar um servidor de mapa antigo rodando.

#mode_mismatch: "The server plays a different game mode"

O cliente e o servidor de mapa foram compilados com Game Settings > Control Mode (controlMode) diferentes.

Solução: compile os dois com o mesmo modo. Depois de mudar o modo, recompile o servidor de mapa e todos os clientes.

#session_busy: "Your character is still being saved"

Você entrou de novo enquanto seu personagem ainda estava em um mapa. O Central pede para esse mapa salvar e soltar o personagem e espera até 5 segundos (Central:KickWaitSeconds). Se o salvamento não chegou, ele responde session_busy em vez de arriscar que um salvamento antigo sobrescreva itens mais novos.

Solução: espere alguns segundos e pressione Play de novo. Se nunca liberar, o servidor de mapa antigo está travado: verifique o log dele ou reinicie os serviços.

#map_unavailable: "That map is not running right now"

O Central não conseguiu iniciar o servidor de mapa a tempo (Central:LaunchTimeoutSeconds, 60), ou o mapa não está na lista dele.

Solução: verifique se a build do servidor de mapa existe e roda, se a porta do mapa está livre, e o log do mapa. No Docker, verifique se o mapa tem seu próprio serviço em docker-compose.yml e uma entrada Central__Maps__N.

#Jogadores que viajam para um mapa novo voltam para o login

Falta na build do servidor de mapa a cena desse mapa, ou o Central não conhece o mapa.

Solução: recompile o servidor de mapa; Play & Servers diz o nome da cena que falta. No Docker, adicione o serviço do mapa e sua entrada na lista de mapas do Central.

#"Kicked" por flooding

Um cliente que envia muito mais comandos do que uma pessoa conseguiria (bem acima de 30 por segundo) é desconectado com o motivo flooding. Isso acontece com clientes modificados ou bots.

Solução: nada para jogadores normais. Se o seu próprio código envia um comando a cada frame, envie com menos frequência.

#Builds

#"KitARPG found N problem(s)"

O Project Check roda antes de cada build e a interrompe quando há erros.

Solução: abra o Project Check, corrija os erros e gere a build de novo. Você pode desligar a interrupção no Project Check com Stop builds on errors, mas os problemas continuam.

#"The client talks to ... without HTTPS"

Um cliente MMO de release precisa alcançar Login e Central por HTTPS, exceto neste computador. A build para: "... so passwords and tokens would cross the internet readable."

Solução: defina Login Url e Central Url em Assets/Settings/Resources/KitARPGSettings.asset com seus endereços https://. Para testar contra um servidor sem HTTPS, use o cliente de teste, nunca para jogadores.

#"The client is built with Mono"

Um cliente MMO de release precisa ser compilado com IL2CPP, ou o código dele vai como DLLs legíveis.

Solução: defina Player Settings > Scripting Backend como IL2CPP. Gere clientes Windows no Windows e clientes Mac em um Mac; o IL2CPP não faz compilação cruzada entre eles.

#"... goes into the online client but uses ..., which is server code."

Um assembly que vai no cliente referencia código de servidor.

Solução: mova o código que precisa do servidor para um assembly cujo nome termine em .Server (Create > KitARPG > Scripts > Game Server Assembly). KitARPG > Check Build Separation mostra o que vai para onde.

#"Single player hosts its own world and needs ..."

Uma build de um jogador feita fora dos menus do kit não tem o código de servidor ou o salvamento local.

Solução: gere a build com KitARPG > Starter > Build Mac Single Player ou Build Windows Single Player, que adicionam os defines KITARPG_SERVER e KITARPG_SINGLEPLAYER.

#Uma build falha dentro do URP depois do Play

Se uma sessão de Play terminou sem devolver o pipeline de renderização do projeto, um nível de qualidade pode apontar para uma cópia destruída. O kit corrige isso sozinho quando o Play termina e antes de cada build.

Solução: se ainda acontecer, abra Project Settings > Quality e defina o asset do URP em cada nível, ou rode Set everything up de novo.

#A build do servidor Linux falha em um Mac

Gerar um servidor Linux em um Mac precisa do Linux Dedicated Server Build Support e do pacote com.unity.toolchain.macos-arm64-linux.

Solução: adicione o módulo no Unity Hub e o pacote no Package Manager.

#Bancos de dados

#Mensagens da configuração do PostgreSQL

Set up PostgreSQL... informa cada problema comum em palavras simples:

Mensagem Solução
"Wrong user or password." Verifique o login
"That database doesn't exist. Create it from here with an admin login." Use Create the database for me
"The server doesn't take this login from this computer (pg_hba.conf): ..." Libere seu endereço no pg_hba.conf do servidor, ou use o host que ele permite
"That login isn't allowed to do this: ..." Use um login de administrador para criar, ou um usuário dono do banco de dados
"No server answered there. Check the host and port, and that PostgreSQL is running." Inicie o PostgreSQL, verifique host e porta
"The server didn't answer in time. Check the host, the port and the firewall." Abra a porta no firewall
"Connected to PostgreSQL ..., but ... can't create tables in ..." Torne o usuário dono do banco de dados, ou crie o banco de dados pela janela
"Use a password of 8 characters or more." Uma senha mais longa

Servidores hospedados (RDS, Supabase, Neon) em geral precisam de SSL: Require.

#O Docker neste computador não inicia

A opção Docker precisa do Docker Desktop rodando. Ela inicia um contêiner chamado kitarpg-postgres na primeira porta livre a partir da 5432.

Solução: inicie o Docker Desktop e tente de novo. Se já existe um contêiner de antes, o kit reutiliza o volume dele e define uma senha nova.

#Onde fica o banco de dados local?

UserSettings/KitARPG/data/kitarpg.db para o MMO no seu computador. O salvamento do modo de um jogador é savegame.db na pasta de dados persistentes; Play & Servers mostra o caminho.

#Servidores em produção

#Um serviço se recusa a iniciar: "... is empty, too short or a sample value"

Fora de Development, Login, Central e o Shop recusam segredos de exemplo ou ausentes: a chave de assinatura, a chave dos mapas, a senha do banco de dados, as chaves do Shop.

Solução: defina valores longos e aleatórios em Deploy/.env (a chave de assinatura precisa de pelo menos 32 caracteres). Veja Segurança.

#Os clientes não conseguem se conectar aos mapas no servidor

Os servidores de mapa usam UDP. Os jogadores precisam das portas dos mapas abertas.

Solução: abra UDP 7777 a 7779 (uma por mapa) no firewall do servidor, e TCP 80 e 443 para o Caddy. Nunca publique o link dos mapas (UDP 7700) na internet.

#Os limites de taxa do Login contam todos como um só jogador

Atrás de um proxy, toda requisição parece vir do endereço do proxy.

Solução: ligue as configurações Proxy com o endereço do seu proxy. O arquivo do Docker Compose já confia no próprio Caddy. Veja Configuração.

#Ferramentas de GM

#Os comandos de GM dizem "Unknown command"

O nível da sua conta está abaixo do nível do comando. Comandos acima do seu nível respondem como se não existissem.

Solução: defina o primeiro administrador no banco de dados (veja Comandos de GM) e depois use /role para os outros. Um nível aumentado vale a partir da próxima vez que o jogador entrar em um mapa. Verifique também Game Settings > Gm Command Levels.

#"GM commands are paused: they can't be recorded right now."

Comandos da equipe só rodam quando podem ser registrados na auditoria, e o mapa não consegue alcançar o Central no momento.

Solução: espere e tente de novo. Se continuar, verifique se o Central está rodando e se o mapa está ligado a ele.

#O painel de GM não abre

F8 e /gm o abrem só para o nível 2 ou superior ("Unknown command /gm. Try /help." caso contrário).

Solução: aumente o nível da conta.

#A loja do jogo

#O botão da loja não aparece

A loja funciona só online, com o módulo In-game shop ligado e o serviço Shop rodando. O modo de um jogador não tem loja.

Solução: verifique Módulos, ligue a loja na página Shop e inicie o serviço Shop. A janela da loja avisa quando está carregando ou não consegue alcançar o serviço.

#"This map has no Shop service." depois de /currency gems

O servidor de mapa não recebeu o endereço e a chave do Shop.

Solução: inicie o Shop com The game has an in-game shop ligado, para que o Central passe KITARPG_SHOP_URL e KITARPG_SHOP_KEY aos mapas que ele inicia. Um mapa rodado no editor não os recebe.

#Testes

#Rodar os testes do kit

KitARPG > Run Play Mode Tests roda os testes de Play Mode do kit no modo de um jogador, em um salvamento descartável, então seus personagens não são tocados. O Console mostra quantos passaram e os resultados vão para Logs/KitARPG-PlayMode-Tests.xml. Pela linha de comando:

Unity -projectPath . -batchmode -executeMethod Blunnyn.KitARPG.Editor.KitTests.RunPlayMode

No modo batch o Unity sai com o código 1 quando um teste falha. O menu precisa do pacote Test Framework; sem ele o menu não aparece.
