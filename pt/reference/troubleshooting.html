Troubleshooting

Esta página ainda não foi traduzida. Ela aparece em inglês.

Problems you can run into with KitARPG, what each message means, why it happens and how to fix it. Find your symptom by section: setup, playing, MMO services, signing in, builds, databases, servers and GM tools.

#First checks

Before looking for a specific problem, these four checks solve most of them:

  1. Stop Play. Many settings are locked during Play.
  2. Open Project Check (KitARPG > Project Check) and fix every error. Most have a fix button.
  3. Apply pending kit updates in Overview.
  4. In MMO, rebuild and restart: Play & Servers > Rebuild the services, Rebuild the map server, then Restart.

Logs to read:

Log Where
Unity Console Window > General > Console
Services started from the editor Play & Servers > Log card, or UserSettings/KitARPG/services.log
Each map server UserSettings/KitARPG/data/logs/map-<id>.log
Shop started from the editor UserSettings/KitARPG/shop.log
Play mode tests Logs/KitARPG-PlayMode-Tests.xml

#Setup and import

#Materials are pink

URP isn't the active render pipeline, or a quality level still uses another pipeline. The kit's materials are URP materials.

Fix: open KitARPG > Setup Wizard and press Set everything up. It sets URP as the default pipeline and on every quality level, and sets Linear color. To check by hand: Project Settings > Graphics > Default Render Pipeline and Project Settings > Quality, every level.

#Labels have no text or font

TextMesh Pro's essential resources aren't in the project. Project Check shows the error "TextMesh Pro's essential resources aren't in the project, so every label in the kit's UI and sample has no font."

Fix: press Set everything up in the Setup Wizard, or the import button on the Project Check error, or Window > TextMeshPro > Import TMP Essential Resources. In batch mode the import is queued and doesn't finish before Unity exits; run it once in the normal editor.

#Menus don't take clicks

A scene's EventSystem has the UI module of the other input system. Project Check warns: "<scene>'s EventSystem has the UI module of the other input system, so menus may not take clicks."

Fix: press Fix scenes on the warning, or Set everything up in the Setup Wizard. The kit also switches the module when a scene loads under the Input System, as a fallback.

#InvalidOperationException about the Input class when pressing Play

The project uses only the Input System (new Unity templates do) and some script reads UnityEngine.Input directly. The kit's own code never does.

Fix: in your scripts, call KitInput.GetKey, KitInput.GetKeyDown, KitInput.GetMouseButton, KitInput.mousePosition and the rest instead of Input. They work in both kinds of project. Or set Project Settings > Player > Active Input Handling to Both.

#Changes in Game Settings don't reach a scene

The scene overrides fields of the Game Instance prefab, so Game Settings (which edits the prefab) doesn't reach it. A common case: the touch controls show up with Input Layout set to Mouse And Keys. Project Check warns: "<scene> overrides Game Settings on its Game Instance (...), so changes in Game Settings don't reach that scene."

Fix: press Fix scenes in Project Check. It reverts the overrides so the scene follows the prefab.

#"Scenes in Build Settings" is red

Title isn't the first enabled scene, or, in MMO, Server isn't listed. The detail reads "The first scene must be Title, and Server must be listed."

Fix: press Use starter scenes. It puts Title, Server, Town, Forest and Crypt in Build Settings, Title first. If the sample doesn't exist yet, it offers to build it.

#"SQLite library for this platform" is missing

The single player save needs the native SQLite library in Assets/Blunnyn/KitARPG/Plugins/SQLite/ (macOS/libe_sqlite3.dylib, Windows/e_sqlite3.dll or Linux/libe_sqlite3.so).

Fix: import the KitARPG package again with the Plugins/SQLite folder ticked.

#"Stop Play before building the starter sample."

Building the sample during Play would save broken objects into its prefabs.

Fix: stop Play and build again.

#The Setup Wizard doesn't open

It opens by itself once per project. After that, UserSettings/KitARPG/setup-done keeps it closed.

Fix: open KitARPG > Setup Wizard.

#Playing in the editor

#I can't change Game Settings or Modules

Their fields are locked during Play, because they are saved in the network prefab.

Fix: stop Play first.

#"Add the Title scene to Build Settings first."

Play & Servers opens Title from Build Settings.

Fix: press Use starter scenes, or add your Title scene as the first scene.

#The game starts without a title screen

Unity's Play button plays the open scene. A map scene alone has no session.

Fix: open Title, or use Play in Overview or Play & Servers, which open Title for you.

#Players or monsters don't move on a new map

The map's scene has no baked NavMesh. Movement and monsters use the NavMesh on the server.

Fix: add a NavMeshSurface to the scene and bake it. Duplicating the sample's Forest gives you one already set up. See Maps.

#Players arriving on a map have nowhere to stand

Project Check: "<scene> has no SpawnPoint; players arriving at '<map>' have nowhere to stand."

Fix: add a SpawnPoint to the scene.

#Single player features answer "Only on an online server."

Friends, parties, guilds, mail, the market, tax collectors, the in-game shop and some moderation commands need a server.

Fix: switch to MMO in Play & Servers, or turn those systems off in Modules so they don't show.

#MMO services

#The .NET 10 SDK isn't found

The row reads "dotnet was not found. Install the .NET 10 SDK, then check again." or "Found ...; the services need 10." Unity doesn't always get your shell's PATH.

Fix: install the .NET 10 SDK (not only the runtime) from https://dotnet.microsoft.com/download/dotnet/10.0, then press Check again. If it is installed in an unusual place, put a link to dotnet in one of the folders the kit searches: /usr/local/share/dotnet, /usr/local/bin, /opt/homebrew/bin, ~/.dotnet on Mac and Linux, C:\Program Files\dotnet on Windows. Restarting Unity Hub and Unity after installing also refreshes PATH.

#"Services source: Not found."

The kit didn't find a folder with KitARPG.Services.slnx. It looks next to your Unity project folder (../Services), inside it (Services), and in Assets/Blunnyn/KitARPG/Services~.

Fix: wait for the editor to finish loading (it unpacks Services.zip on load), or press Browse and pick the folder. If Services~ doesn't exist, check that Assets/Blunnyn/KitARPG/Services.zip was imported.

#"dotnet build failed."

The services didn't compile. Play & Servers shows the first error lines. "dotnet build failed. Run it in a terminal to see why." means there were none to show.

Fix: open a terminal in the services folder and run dotnet build. Common causes: no internet the first time (NuGet packages are downloaded), an SDK older than 10, or files changed by hand in Services~. Importing the kit again restores the services.

#"Something else is using port ..."

Services started from a terminal or an earlier session hold the ports 5100, 5200 or 7700. They may run older code.

Fix: stop them. If Play & Servers shows "Services from an earlier editor session are still running (process ...)", press Stop the old services. Otherwise find the process (on Mac and Linux lsof -i :5100, on Windows netstat -ano | findstr 5100) and end it.

#"The services or the map server were rebuilt after they started, so they still run the old code. Restart them."

You rebuilt while they ran.

Fix: press Restart.

#"No map reached Central"

Overview shows it when the services run but no map server registered. Usually the map server build is missing or out of date.

Fix: build the map server (Play & Servers, step 1) and restart the services. If it persists, read UserSettings/KitARPG/data/logs/map-town.log.

#The map server build "Missing the scene of a map"

The build lacks a map's scene, so players travelling there end up back at the login.

Fix: press Rebuild. Builds take their scenes from the maps in the Game Database. If the build itself says "No scene file named ...", the map names a scene that doesn't exist: fix the name on the map's page.

#"Two players need the MMO mode"

Play with two players only works in MMO.

Fix: switch to MMO in Play & Servers.

#Play with two players doesn't start Player 2

Unity's Multiplayer Play Mode couldn't activate the second player by itself. The Console says to turn on Player 2.

Fix: in Window > Multiplayer > Multiplayer Play Mode, turn on Player 2, then press Play with two again. The first launch imports the project in the second editor, which takes a while. If the dialog says "Build the services first", do step 1 of Play & Servers.

#I can't change the database

"Stop the services to change the database."

Fix: press Stop in step 3, change it, start again.

#version_mismatch: "The game and the server are different versions"

The client sends a short hash of everything that travels over the network (synced fields, lists and messages). The map server compares it with its own and refuses a client built from different code, instead of failing later when reading data.

Fix: rebuild the map server (or the client) so both come from the same code, then restart the services. This happens often after changing code, updating the kit, or leaving an old map server running.

#mode_mismatch: "The server plays a different game mode"

The client and the map server were built with different Game Settings > Control Mode (controlMode).

Fix: build both with the same mode. After changing the mode, rebuild the map server and every client.

#session_busy: "Your character is still being saved"

You signed in again while your character was still on a map. Central asks that map to save and drop the character and waits up to 5 seconds (Central:KickWaitSeconds). If the save hasn't arrived, it answers session_busy instead of risking an old save overwriting newer items.

Fix: wait a few seconds and press Play again. If it never clears, the old map server is stuck: check its log or restart the services.

#map_unavailable: "That map is not running right now"

Central couldn't start the map server in time (Central:LaunchTimeoutSeconds, 60), or the map isn't in its list.

Fix: check that the map server build exists and runs, that the map's port is free, and the map's log. In Docker, check that the map has its own service in docker-compose.yml and a Central__Maps__N entry.

#Players who travel to a new map end up back at the login

The map server build lacks that map's scene, or Central doesn't know the map.

Fix: rebuild the map server; Play & Servers names the missing scene. For Docker, add the map's service and its entry in Central's maps list.

#"Kicked" for flooding

A client that sends far more commands than a person could (well above 30 a second) is disconnected with the reason flooding. It happens with modified clients or bots.

Fix: nothing for normal players. If your own code sends a command every frame, send it less often.

#Builds

#"KitARPG found N problem(s)"

Project Check runs before every build and stops it on errors.

Fix: open Project Check, fix the errors, build again. You can turn the stop off in Project Check with Stop builds on errors, but the problems remain.

#"The client talks to ... without HTTPS"

A release MMO client must reach Login and Central over HTTPS, except on this computer. The build stops: "... so passwords and tokens would cross the internet readable."

Fix: set Login Url and Central Url in Assets/Settings/Resources/KitARPGSettings.asset to your https:// addresses. To test against a server without HTTPS, use the test client, never for players.

#"The client is built with Mono"

A release MMO client must be built with IL2CPP, or its code ships as readable DLLs.

Fix: set Player Settings > Scripting Backend to IL2CPP. Build Windows clients on Windows and Mac clients on a Mac; IL2CPP doesn't cross-compile between them.

#"... goes into the online client but uses ..., which is server code."

An assembly that goes into the client references server code.

Fix: move the code that needs the server into an assembly whose name ends in .Server (Create > KitARPG > Scripts > Game Server Assembly). KitARPG > Check Build Separation shows what goes where.

#"Single player hosts its own world and needs ..."

A single player build made outside the kit's menus lacks the server code or the local save.

Fix: build with KitARPG > Starter > Build Mac Single Player or Build Windows Single Player, which add the defines KITARPG_SERVER and KITARPG_SINGLEPLAYER.

#A build fails inside URP after Play

If a Play session ended without putting the project's render pipeline back, a quality level can point to a destroyed copy. The kit repairs this by itself when Play ends and before every build.

Fix: if it still happens, open Project Settings > Quality and set the URP asset on each level, or run Set everything up again.

#The Linux server build fails on a Mac

Building a Linux server from a Mac needs Linux Dedicated Server Build Support and the com.unity.toolchain.macos-arm64-linux package.

Fix: add the module in Unity Hub and the package in the Package Manager.

#Databases

#PostgreSQL setup messages

Set up PostgreSQL... reports each common problem in plain words:

Message Fix
"Wrong user or password." Check the login
"That database doesn't exist. Create it from here with an admin login." Use Create the database for me
"The server doesn't take this login from this computer (pg_hba.conf): ..." Allow your address in the server's pg_hba.conf, or use the host it allows
"That login isn't allowed to do this: ..." Use an admin login to create, or a user that owns the database
"No server answered there. Check the host and port, and that PostgreSQL is running." Start PostgreSQL, check host and port
"The server didn't answer in time. Check the host, the port and the firewall." Open the port in the firewall
"Connected to PostgreSQL ..., but ... can't create tables in ..." Make the user the database owner, or create the database from the window
"Use a password of 8 characters or more." A longer password

Hosted servers (RDS, Supabase, Neon) usually need SSL: Require.

#Docker on this computer doesn't start

The Docker option needs Docker Desktop running. It starts a container named kitarpg-postgres on the first free port from 5432.

Fix: start Docker Desktop and try again. If a container from before exists, the kit reuses its volume and sets a new password.

#Where is the local database?

UserSettings/KitARPG/data/kitarpg.db for the MMO on your computer. The single player save is savegame.db in the persistent data folder; Play & Servers shows its path.

#Servers in production

#A service refuses to start: "... is empty, too short or a sample value"

Outside Development, Login, Central and the Shop refuse sample or missing secrets: the signing key, the map key, the database password, the shop keys.

Fix: set long random values in Deploy/.env (the signing key needs at least 32 characters). See Security.

#Clients can't connect to maps on the server

Map servers use UDP. Players need the map ports open.

Fix: open UDP 7777 to 7779 (one per map) on the server's firewall, and TCP 80 and 443 for Caddy. Never publish the map link (UDP 7700) to the internet.

#Login rate limits count everyone as one player

Behind a proxy, every request seems to come from the proxy's address.

Fix: turn on the Proxy settings with your proxy's address. The Docker Compose file already trusts its own Caddy. See Configuration.

#GM tools

#GM commands say "Unknown command"

Your account's level is below the command's. Commands above your level answer as if they didn't exist.

Fix: set the first admin in the database (see GM commands), then use /role for others. A raised level takes effect the next time the player enters a map. Check also Game Settings > Gm Command Levels.

#"GM commands are paused: they can't be recorded right now."

Staff commands only run when they can be recorded in the audit, and the map can't reach Central at the moment.

Fix: wait and try again. If it lasts, check that Central runs and the map is linked to it.

#The GM panel doesn't open

F8 and /gm open it only for level 2 or more ("Unknown command /gm. Try /help." otherwise).

Fix: raise the account's level.

#The in-game shop

#The shop button doesn't show

The shop works online only, with the In-game shop module on and the Shop service running. Single player has no shop.

Fix: check Modules, turn the shop on in the Shop page and start the Shop service. The shop window says when it is loading or can't reach the service.

#"This map has no Shop service." after /currency gems

The map server wasn't given the Shop's address and key.

Fix: start the Shop with Premium shop on, so Central passes KITARPG_SHOP_URL and KITARPG_SHOP_KEY to the maps it starts. A map run in the editor doesn't receive them.

#Tests

#Running the kit's tests

KitARPG > Run Play Mode Tests runs the kit's Play mode tests in single player, on a throwaway save, so your characters are untouched. The Console shows how many passed and the results go to Logs/KitARPG-PlayMode-Tests.xml. From the command line:

Unity -projectPath . -batchmode -executeMethod Blunnyn.KitARPG.Editor.KitTests.RunPlayMode

In batch mode Unity exits with code 1 when a test fails. The menu needs the Test Framework package; without it the menu isn't there.

#Still stuck

  • Read the FAQ.
  • Search the Glossary for a word you don't know.
  • Check the services' README.md in Services~ for endpoints and settings.
