Referência

Perguntas frequentes

Respostas às perguntas que os compradores mais fazem sobre o KitARPG: o que ele faz, como o modo de um jogador e o MMO diferem, conteúdo, servidores, custos, segurança e como estendê-lo. Cada resposta leva à página com os detalhes.

#Sobre o kit

#Preciso saber programar?

Não. Você pode criar classes, itens, habilidades, monstros, missões, NPCs e mapas pela janela KitARPG e pelo Inspector, definir como o jogo é jogado em Game Settings e ligar e desligar sistemas em Modules. O código serve para quando você quer algo que o kit não faz. Veja Game Database.

#Qual versão do Unity eu preciso?

Unity 6000.6.0f1 (Unity 6.6) ou mais recente, com o Universal Render Pipeline. O Setup Wizard configura o URP para você. Veja Requisitos.

#Funciona com o pipeline Built-in ou com o HDRP?

Não. Os materiais e a amostra do kit são feitos para o URP 17.6 com cor Linear. Com outro pipeline eles aparecem rosa.

#Funciona com o novo Input System, com o antigo Input Manager ou com os dois?

Com os dois. O kit lê as teclas e o mouse por meio do KitInput, que usa o pacote Input System quando Active Input Handling o inclui e o Input Manager caso contrário. Set everything up e o Fix scenes do Project Check dão ao EventSystem de cada cena o módulo de UI do input que você usa. Veja Teclas.

#Que biblioteca de rede ele usa?

Mirror com o transporte KCP (UDP) entre clientes e servidores de mapa, e LiteNetLib entre os servidores de mapa e o Central. O Mirror vem dentro do pacote. Veja Arquitetura.

#Para quais plataformas posso gerar builds?

Os menus do kit geram clientes e jogos de um jogador para Mac e Windows, servidores de mapa Mac e Windows para testes locais, e servidores de mapa Linux para Docker. Há controles de toque incluídos para telas sensíveis ao toque. Veja Builds.

#A arte está incluída e posso usá-la no meu jogo?

Sim. Os personagens voxel, equipamentos, armas, monstros, ícones e animações vêm em Assets/Blunnyn/Art como parte do pacote.

#Um jogador e MMO

#Qual é a diferença entre um jogador e MMO?

No modo de um jogador, o jogo hospeda seu próprio mundo e salva no computador do jogador; não há mais nada para rodar. No MMO, os jogadores entram nos seus servidores (Login, Central e um servidor de mapa por mapa), que compartilham um banco de dados. As cenas, os dados e o código são os mesmos. Veja Introdução.

#Posso transformar um jogo de um jogador em MMO depois?

Sim. Escolha MMO em Play & Servers, gere a build dos serviços e do servidor de mapa e inicie-os. Seus mapas, dados e código continuam como estão. Os salvamentos do modo de um jogador não passam para o banco de dados do MMO.

#Posso jogar o MMO sem uma máquina servidora?

Sim. No seu computador, Play & Servers compila e inicia Login, Central e os servidores de mapa com um banco de dados SQLite local. Veja Início rápido: MMO.

#Quantos jogadores um mapa comporta?

O kit não define um limite fixo. Quantos jogadores um mapa comporta depende dos seus mapas, monstros, habilidades e da máquina servidora, então meça com o seu próprio conteúdo. Cada mapa roda no seu próprio processo, e os jogadores só recebem o que está perto deles, então você adiciona mapas em vez de sobrecarregar um. Veja Desempenho.

#Um jogador pode ter mais de um personagem?

Sim, até 6 por conta por padrão. Mude maxCharactersPerAccount nas configurações do Game Database.

#O que acontece se um jogador entrar duas vezes?

Uma sessão por conta. A segunda entrada fecha a primeira: o mapa antigo salva o personagem e o solta, e o primeiro cliente vê "You logged in from somewhere else." Se o salvamento ainda está em andamento, a nova entrada recebe "Your character is still being saved. Try again in a moment."

#Cheats funcionam no modo de um jogador?

Sim, os comandos de GM funcionam como cheats no modo de um jogador enquanto Game Settings > Single Player Commands está ligado (o padrão). Desligue para lançar um jogo sem eles. Veja Comandos de GM.

#Conteúdo

#Posso usar meus próprios modelos de personagem?

Sim, com + New player model em Game Database > Models. Um rig humanoide pode compartilhar as animações do kit e segurar armas nas mãos; qualquer rig funciona com suas próprias animações. Veja Modelos de jogador.

#Posso usar meus próprios modelos de monstro?

Sim, com + New monster em Game Database > Monsters. Com um Animator o monstro toca seus clipes; sem ele, o monstro pula e pisca ao ser atingido, como os slimes da amostra. Veja Monstros.

#Como adiciono um mapa novo?

Duplique a cena Forest da amostra, adicione um mapa em Game Database > Maps, escolha a cena, conecte-a com um portal ou um NPC de teleporte e recompile o servidor de mapa. Veja Mapas.

#Por que todo asset tem um id?

Os personagens salvos e o banco de dados apontam para os dados pelo id, como fire_bolt. O id é preenchido a partir do nome do arquivo quando o asset é criado e nunca muda depois, então renomear ou mover um arquivo não quebra os salvamentos. Mudar um id à mão quebra todos os personagens que o usam.

#Por que os bônus de stats são sempre números inteiros?

Para que os jogadores leiam números limpos e o arredondamento nunca seja diferente entre cliente e servidor. As porcentagens também são pontos inteiros. O equipamento sorteia cada bônus entre um mínimo e um máximo para cada cópia.

#Os jogadores podem vender itens para NPCs?

Não por padrão, para que os itens circulem entre jogadores, no mercado ou na forja. Ligue Game Settings > Players Sell To Npcs para permitir. Veja Lojas de NPC.

#O que acontece quando a bolsa está cheia?

O saque pode passar do limite de peso, e o personagem então não consegue andar até largar, vender ou guardar algo. Itens do correio, da guilda, dos coletores e das missões vão para o banco quando a bolsa não comporta. Nada se perde. Veja Inventário e banco.

#Como mudo as teclas?

A tecla de cada janela é um campo no seu componente no prefab do HUD, e as teclas de movimento são campos nos componentes de modo. Os jogadores não podem remapear teclas dentro do jogo. Veja Teclas.

#Qual modo de controle devo escolher?

Top-down para um jogo estilo Diablo com clique para mover; câmera livre para um jogo com mira pelo cursor e câmera orbital; terceira pessoa para mira com retícula e predição no cliente. As mesmas cenas funcionam para os três, e você pode mudar depois. Veja Modos de controle.

#Servidores e custos

#Do que preciso para rodar um MMO para jogadores de verdade?

Uma máquina Linux com Docker, dois nomes de domínio (um para o Login, um para o Central) e a build Linux do servidor de mapa. O arquivo do Docker Compose em Deploy roda PostgreSQL, Caddy (HTTPS), Login, Central e um contêiner por mapa. Veja Docker.

#SQLite ou PostgreSQL?

O SQLite é um arquivo local e não precisa de nada instalado: use-o para desenvolver e para servidores pequenos. Use o PostgreSQL em produção. Os serviços funcionam com qualquer um dos dois; você troca em Play & Servers ou nas configurações dos serviços. Veja Banco de dados.

#Posso rodar vários servidores Central para mais jogadores?

Não. Rode exatamente um Central por banco de dados: ele guarda sessões, tickets e travas de itens na memória, e dois entregariam os mesmos itens duas vezes. O Login pode rodar como várias instâncias. Os servidores de mapa escalam adicionando mapas. Rode também um Shop por banco de dados.

#Os servidores de mapa precisam estar na mesma máquina que o Central?

Não, mas o link dos mapas (UDP 7700) não é criptografado. Servidores de mapa em outras máquinas precisam alcançar o Central por uma rede privada ou um túnel WireGuard, nunca pela internet.

#Como me torno administrador?

Defina o Role da sua conta como 4 na tabela accounts uma vez e depois use /role dentro do jogo para os outros. Veja Comandos de GM.

#Posso vender itens por dinheiro real?

Sim, com a loja do jogo opcional. Ela roda como um serviço próprio, com sua própria moeda premium, guardada por conta. Os jogadores recarregam por meio de webhooks de pagamento: Stripe, ou um webhook assinado da sua própria loja na web. Os itens comprados vão direto para a bolsa. Veja Loja do jogo e Serviço Shop.

#A loja funciona no modo de um jogador?

Não. A loja do jogo precisa do serviço Shop e é só para MMO.

#Segurança

#Os jogadores podem trapacear modificando o cliente?

O servidor decide tudo: dano, saque, preços, trocas, missões e movimento. O cliente só pede, e cada pedido é verificado no servidor. Os alvos precisam estar visíveis para o jogador, os comandos têm limite de taxa e o texto dos jogadores não consegue injetar formatação. Uma build de cliente MMO não leva código de servidor, comandos de GM, salvamento local nem chaves. Veja Segurança.

#Itens podem ser duplicados?

Cada cópia de item tem exatamente um dono no banco de dados, e as mudanças de dono acontecem em transações por meio de um único livro-razão. Os tickets de mapa funcionam uma vez, e uma reconexão espera o salvamento antigo antes de deixar o personagem entrar de novo.

#Como as senhas são guardadas?

Com hash Argon2id. Os jogadores entram com um token de vida curta. "Remember me" guarda um token de uso único, nunca a senha, e reutilizar um token já gasto encerra a sessão em todos os computadores que o tinham.

#O que acontece depois de muitas senhas erradas?

Depois de 5 senhas erradas em 15 minutos, o nome de usuário fica bloqueado por 15 minutos ("Too many wrong passwords."), sem revelar se a conta existe. O Login também limita as requisições por endereço a 10 por minuto.

#Atualizar e estender

#Uma atualização vai sobrescrever minhas mudanças?

Não, se você mantiver seu jogo nas suas próprias pastas e usar as atualizações do kit. Importar um kit novo substitui os arquivos do kit; as atualizações do kit adicionam o que falta ao seu jogo sem regerá-lo. Só Start over gera a amostra de novo do zero. Veja Atualizar o kit.

#Posso editar o código do kit?

Pode, mas a próxima atualização o substitui. Em vez disso, estenda o kit a partir dos seus próprios assemblies: templates, eventos, métodos virtuais e tipos registráveis cobrem as necessidades comuns. Veja Visão geral do DevKit.

#Como adiciono meu próprio comando de GM, efeito de habilidade ou objetivo de missão?

Clique com o botão direito em uma pasta, escolha Create > KitARPG > Scripts e o template correspondente. Comece com Game Assembly para que seus scripts enxerguem o kit. Veja Templates.

#Posso estender o Login e o Central?

Sim, com módulos: uma biblioteca de classes .NET 10 com uma classe que implementa ILoginModule ou ICentralModule, colocada na pasta de módulos do serviço. Veja Módulos de serviço.

#Onde está a referência da API?

Em Assets/Blunnyn/KitARPG/Documentation/API/, uma página por tipo público.

#Como verifico se o kit funciona no meu projeto?

KitARPG > Run Play Mode Tests roda os testes do kit no modo de um jogador, em um salvamento descartável: entrar em um mapa, viajar por um portal, salvar ouro, lutar e cada modelo humanoide atacando com cada tipo de arma. Veja Solução de problemas.
