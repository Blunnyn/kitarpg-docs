Falando com o Central

Como os servidores de mapa trocam mensagens suas com um módulo no Central, para recursos que abrangem vários mapas ou personagens: rankings, eventos do mundo, contadores do servidor inteiro. Esta página cobre o lado do mapa (CentralMessages); o lado do Central está em Módulos de serviço.

#Quando você precisa do Central

Online, cada mapa roda no seu próprio processo de servidor e nunca toca no banco de dados. O Central liga todos eles, mantém as sessões e escreve no banco de dados. Qualquer coisa que um único mapa não pode saber precisa do Central:

  • um ranking entre todos os personagens (o quadro de caçadores do exemplo de recompensas),
  • um evento que começa em todos os mapas ao mesmo tempo,
  • um contador para o servidor inteiro,
  • dados sobre personagens que não estão online.

Dados por personagem que viajam com o personagem não precisam do Central: use flags ou PlayerData (veja Salvando dados).

No modo um jogador não existe Central. Todo recurso que o usa precisa de uma alternativa, mesmo que a alternativa seja "só online".

#Como uma mensagem viaja

Map server (Unity)                       Central (.NET)
CentralMessages.Send(new BountyFinished)  ->  module handler for BountyFinished
                                               m.Reply(new BountyBoardList)
CentralMessages.On<BountyBoardList>(...)  <-   (to the map that asked)
  1. No mapa, CentralMessages.Send escreve o nome da classe da mensagem e o JSON dela (JsonUtility da Unity) pela ligação autenticada do mapa com o Central (LiteNetLib, confiável e ordenada).
  2. O Central procura qual módulo registrou aquele nome de classe e entrega a ele a mensagem, desserializada com System.Text.Json, junto com qual mapa a enviou.
  3. O módulo responde ao mapa que perguntou (Reply), ao mapa onde está um personagem (SendToCharacter), a um mapa pelo id (Send) ou a todos os mapas (Broadcast).
  4. No mapa, os handlers de CentralMessages.On<T> rodam na thread principal.

#CentralMessages

CentralMessages fica em KitARPG.Server (namespace Blunnyn.KitARPG.Server), então o código que o usa vai em um assembly só de servidor, como Game.Server.

Membro O que faz
static bool Online O mapa está registrado no Central. False no modo um jogador e enquanto o Central está fora.
static bool Send<T>(T message) Envia aos módulos do Central. False quando o Central não pode ser alcançado; nada fica na fila. Lança exceção para um nome de mensagem do kit.
static void On<T>(Action<T> handler) Chama handler na thread principal para cada T que o Central envia. Um handler por tipo: uma segunda chamada substitui a primeira; null o remove. Lança exceção para um nome de mensagem do kit.

Os handlers são limpos no início de cada Play; registre-os em AfterSceneLoad (ou AfterAssembliesLoaded). Uma exceção dentro de um handler é registrada no log e não derruba a ligação.

#Escrevendo as mensagens

As mensagens são classes C# comuns, compiladas pela Unity e pelo seu módulo do Central a partir do mesmo arquivo:

using System;

namespace Game
{
    /// <summary>Map to Central: a character finished a bounty.</summary>
    [Serializable]
    public class BountyFinished
    {
        public long characterId;
        public string name;
        public string monster;
    }

    /// <summary>Central to the map the asking character is on.</summary>
    [Serializable]
    public class BountyBoardList
    {
        public long characterId;
        public BountyHunter[] top = new BountyHunter[0];
        public int mine;
    }

    [Serializable]
    public class BountyHunter
    {
        public string name;
        public int bounties;
    }
}

Regras, porque duas bibliotecas de JSON diferentes as leem:

  • Classes [Serializable] com campos públicos. Sem propriedades, sem construtores com parâmetros, sem dicionários.
  • Nomes de campo em lowerCamelCase. O Central escreve o JSON em camelCase; o JsonUtility da Unity compara os nomes exatamente, então um campo chamado CharacterId voltaria vazio no mapa.
  • Tipos que os dois lados leem: int, long, float, double, bool, string, enums (como números), arrays e listas desses e de outras classes de mensagem.
  • Nenhum tipo da Unity (Vector3, Color). Envie números.
  • Nomes próprios. As mensagens viajam só pelo nome da classe (sem namespace). Os nomes do kit são recusados dos dois lados: no mapa, Send e On lançam exceção; no Central, o módulo não inicia. Use um prefixo (BountyFinished, não Finished).

Mantenha o arquivo em um assembly sem referências à engine (noEngineReferences: true) para que nada exclusivo da Unity entre, e ligue-o a partir do .csproj do módulo. O exemplo o mantém em DevKit/Example/Bounties/Shared/BountyBoardMessages.cs, assembly Game.Bounties.Shared. Veja Assemblies.

#Enviando

// Offline the board just misses this one; the character's own history still has it.
CentralMessages.Send(new BountyFinished { characterId = player.State.id, name = player.characterName, monster = monster.Id });

player.State.id é o id do personagem no banco de dados. O Central verifica que este mapa realmente hospeda aquele personagem antes de agir (MapMessage.Hosts), então um mapa só pode falar pelos seus próprios jogadores.

Send retorna false quando o mapa não está conectado. Nada é guardado para depois: se os dados não podem se perder, guarde-os também no personagem (PlayerData) e envie de novo quando Online voltar, ou projete o módulo para aceitar um estado completo em vez de incrementos.

#Recebendo

using System.Text;
using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Server;
using UnityEngine;

namespace Game
{
    public static class HuntersBoard
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Register()
        {
            CentralMessages.On<BountyBoardList>(OnBoard);
        }

        static void OnBoard(BountyBoardList board)
        {
            var text = new StringBuilder("Best bounty hunters:");
            int rank = 1;
            foreach (BountyHunter hunter in board.top ?? new BountyHunter[0])
                text.Append($"\n{rank++}. {PlayerText.NoTags(hunter.name)}: {hunter.bounties}");
            if (rank == 1) text.Append("\nNobody yet.");
            text.Append($"\nYou: {board.mine}");
            SocialHub.Notice(board.characterId, text.ToString());
        }
    }
}
  • Uma resposta sobre um personagem traz o id dele, e o mapa encontra o jogador com PlayerCharacter.ServerFind(characterId) ou mostra uma linha do sistema com SocialHub.Notice(characterId, text). Os dois não fazem nada se o personagem saiu nesse meio-tempo.
  • Texto que veio de jogadores (nomes, notas) é mostrado com PlayerText.NoTags, para que não possa abrir tags de rich text nas telas dos outros.
  • Arrays podem chegar null do JSON; proteja-se com ?? new T[0].

#Um exemplo completo: um evento do mundo em todos os mapas

Um moderador inicia uma hora de "ouro em dobro" em todos os mapas. O módulo a guarda e a transmite a todos; cada mapa a aplica aos seus próprios jogadores.

Mensagens compartilhadas (em Game.Shared, ligado pelo módulo):

[Serializable]
public class GoldHourStart
{
    public long characterId;   // who asked, so Central can check the map hosts them
    public int minutes;
}

[Serializable]
public class GoldHourState
{
    public long endsUnixSeconds;   // 0 when none
}

Lado do mapa (em Game.Server):

using System;
using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Server;
using UnityEngine;

namespace Game
{
    public static class GoldHour
    {
        static long endsAt;

        public static bool Active => DateTimeOffset.UtcNow.ToUnixTimeSeconds() < endsAt;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void ResetStatics() => endsAt = 0;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Register()
        {
            CentralMessages.On<GoldHourState>(state => endsAt = state.endsUnixSeconds);
            GmCommands.Register(new GmCommand
            {
                name = "goldhour", rank = GmRank.GameMaster, usage = "goldhour minutes", description = "Double gold on every map.",
                run = c =>
                {
                    int minutes = Mathf.Clamp(c.Int(0, 60), 1, 24 * 60);
                    if (!CentralMessages.Send(new GoldHourStart { characterId = c.player.State.id, minutes = minutes }))
                        return "Only online.";
                    return $"Starting a {minutes} minute gold hour everywhere.";
                },
            });
        }
    }
}

Lado do Central (no módulo, veja Módulos de serviço):

public void OnMapLink(IMapLink link)
{
    link.On<GoldHourStart>(m =>
    {
        if (!m.Hosts(m.Message.characterId) || m.Message.minutes < 1 || m.Message.minutes > 1440) return Task.CompletedTask;
        long ends = DateTimeOffset.UtcNow.AddMinutes(m.Message.minutes).ToUnixTimeSeconds();
        link.Broadcast(new GoldHourState { endsUnixSeconds = ends });
        return Task.CompletedTask;
    });
}

Seu próprio código de recompensas lê GoldHour.Active. Para as taxas de experiência, saque e ouro do próprio kit, você não precisa de nada disso: o comando /rates já inicia eventos de taxa com tempo marcado que o Central entrega a todos os mapas.

O comando de GM já verificou o nível no mapa, e a auditoria o registrou. Um mapa que entra depois não sabe do evento; envie o estado aos mapas conforme eles pedirem, ou guarde-o no módulo e responda a um GoldHourAsk de cada mapa ao iniciar.

#Um jogador

CentralMessages.Online é false e Send retorna false. Decida por recurso:

  • Só online: diga isso ao jogador, como /hunters faz ("The hunters board is kept online").
  • Alternativa local: guarde uma versão por personagem com PlayerData, como o exemplo guarda as últimas caçadas de cada personagem.

#Erros comuns

  • Usar CentralMessages a partir do assembly Game. Ele fica em KitARPG.Server; o código vai em Game.Server.
  • Campos em PascalCase. As respostas do Central voltam vazias no mapa.
  • Confiar em um id de personagem no lado do Central sem m.Hosts(id).
  • Esperar que Send coloque na fila. Ele não coloca; planeje para quando o Central estiver fora.
  • Registrar dois handlers para um tipo. O segundo substitui o primeiro.
