Objetivos de missão

Como adicionar um novo tipo de meta de missão: a classe base QuestObjective, as duas formas de um objetivo contar (eventos ou estado atual), como avançá-lo com PlayerQuests.ServerAdvance e exemplos completos.

#O que é um objetivo

Uma missão tem uma lista de objetivos (QuestData.objectives). Cada um tem um texto, uma dica opcional e um número que precisa alcançar. O kit traz cinco tipos:

Tipo Conta Como
KillObjective Abates de um monstro, ou de qualquer um Evento: Monster.ServerKilled, compartilhado com membros do grupo próximos
CollectObjective Itens na bolsa Estado: lê a bolsa; pode tirá-los ao entregar
TalkObjective Falar com um NPC pelo id Evento: a conversa com o NPC
ExploreObjective Chegar a um ponto ou zona Verificado a cada Explore Interval (exploreInterval, 0,5 s)
TriggerObjective Acionar um disparador do mundo Evento: WorldTrigger

Um tipo novo é uma classe mais um trecho de código do servidor que o avança. Os objetivos são [Serializable] e guardados com [SerializeReference, PickType], então o seu aparece no menu + de Objectives de toda missão no Game Database.

Onde ficam os arquivos: no assembly Game. O registro de missões no cliente lê o texto e o ícone do objetivo.

#A classe base

QuestObjective fica em Blunnyn.KitARPG.Data.

Membro O que faz Padrão
string text Campo do inspector: mostrado no registro de missões. Vazio usa DefaultText. vazio
string hint Campo do inspector: abre embaixo do objetivo no registro de missões. vazio
string Text text ou DefaultText.
protected abstract string DefaultText { get; } O seu texto padrão, como "Slay Slimes". Obrigatório.
virtual int Required A contagem a alcançar. 1
virtual Sprite Icon Ícone no registro de missões. null
virtual int Current(IPlayerFacts holder) Para objetivos baseados em estado: a contagem neste momento. Devolva -1 para objetivos contados por eventos. -1
virtual void Visit(Action<GameData> visit) Entrega cada asset para o qual o objetivo aponta. Nada

#Duas formas de contar

#Contado por eventos

A maioria dos objetivos conta as coisas conforme acontecem. A missão guarda um contador por objetivo, salvo com o personagem. O seu código chama ServerAdvance quando a coisa acontece:

// PlayerQuests, server only.
public void ServerAdvance<T>(Predicate<T> match, int amount = 1) where T : QuestObjective

Ele percorre todas as missões ativas daquele jogador, encontra objetivos do tipo T para os quais match devolve true e que ainda não estão completos, soma amount (com teto em Required), mostra "Objective 2/5" sobre a cabeça do jogador, diz "ready to turn in" quando a missão está pronta e sincroniza o registro com o dono.

#Lido do estado atual

Sobrescreva Current para devolver a contagem a partir do que o personagem tem agora, como CollectObjective faz com a bolsa. A missão lê o valor:

  • quando a missão é aceita,
  • toda vez que a bolsa ou o equipamento do jogador mudam (PlayerInventory.ServerChanged),
  • quando o jogador tenta entregar a missão (a verificação final).

Current substitui o contador guardado. Se a contagem pode diminuir (itens vendidos), o objetivo também diminui.

Nota

Fora das mudanças na bolsa, nada atualiza uma contagem baseada em estado no registro de missões. Um Current que lê o nível, por exemplo, mostra o número antigo até a bolsa mudar, embora a entrega funcione assim que o nível é alcançado. Para estados que mudam sem mudanças na bolsa, conte por eventos.

#Exemplo: o template

Create > KitARPG > Scripts > Quest Objective cria um objetivo e um contador que o avança a cada subida de nível. Veja Templates.

#Exemplo: vencer duelos

Conta os duelos que o jogador vence. PlayerPvp.ServerDefeated informa quem matou, a vítima e se foi um duelo.

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class WinDuelsObjective : QuestObjective
    {
        public int count = 3;
        [Tooltip("Only opponents at this level or above count. 0 counts anyone.")]
        public int minOpponentLevel;

        protected override string DefaultText => "Win duels";

        public override int Required => Mathf.Max(1, count);

        public bool Counts(PlayerCharacter opponent) => minOpponentLevel <= 0 || opponent.level >= minOpponentLevel;
    }

    public static class WinDuelsCounter
    {
        // After the kit cleared its events in SubsystemRegistration.
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
        static void Hook()
        {
            PlayerPvp.ServerDefeated -= OnDefeated;
            PlayerPvp.ServerDefeated += OnDefeated;
        }

        static void OnDefeated(PlayerCharacter winner, PlayerCharacter loser, bool duel)
        {
            if (!duel || winner == null || loser == null) return;
            if (winner.TryGetComponent(out PlayerQuests quests))
                quests.ServerAdvance<WinDuelsObjective>(o => o.Counts(loser));
        }
    }
}

#Exemplo: melhorar equipamento na forja

PlayerForge.ServerUpgraded informa o jogador, o id do item, se o passo deu certo e o nível em que terminou.

[Serializable]
public class UpgradeObjective : QuestObjective
{
    [Tooltip("Upgrades that reach this level or more count.")]
    public int toLevel = 3;
    public int count = 1;

    protected override string DefaultText => $"Upgrade gear to +{toLevel}";

    public override int Required => Mathf.Max(1, count);
}

public static class UpgradeCounter
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
    static void Hook()
    {
        PlayerForge.ServerUpgraded -= OnUpgraded;
        PlayerForge.ServerUpgraded += OnUpgraded;
    }

    static void OnUpgraded(PlayerCharacter player, string itemId, bool success, int level)
    {
        if (success && player.TryGetComponent(out PlayerQuests quests))
            quests.ServerAdvance<UpgradeObjective>(o => level >= o.toLevel);
    }
}

#Exemplo: carregar ouro (baseado em estado)

Lê a carteira. Atualiza sempre que a bolsa muda, e a entrega verifica de novo.

[Serializable]
public class GoldObjective : QuestObjective
{
    public long gold = 1000;

    protected override string DefaultText => $"Gather {gold:N0} gold";

    // Counts are whole numbers; a large target is shown as one step.
    public override int Required => 1;

    public override int Current(IPlayerFacts holder) => holder.Balance(null) >= gold ? 1 : 0;
}

A atualização vem de PlayerInventory.ServerChanged, disparado quando a bolsa ou o equipamento são publicados. Uma mudança só no ouro não o dispara, então o registro pode mostrar 0 até a próxima mudança na bolsa, embora a entrega funcione. Prefira este padrão para itens. Para moedas, um objetivo baseado em eventos avançado pelo seu próprio código é mais confiável.

#Exemplo: um objetivo avançado pelo seu próprio recurso

Qualquer código do servidor pode avançar objetivos. O exemplo de recompensas poderia contar recompensas pagas para uma missão:

[Serializable]
public class BountiesObjective : QuestObjective
{
    public MonsterData monster;
    public int count = 3;

    protected override string DefaultText => monster != null ? $"Finish {monster.DisplayName} bounties" : "Finish bounties";
    public override int Required => Mathf.Max(1, count);
    public override Sprite Icon => monster != null ? monster.Icon : null;
    public override void Visit(Action<GameData> visit) => visit(monster);
}

// Wherever a bounty is paid, on the server:
if (player.TryGetComponent(out PlayerQuests quests))
    quests.ServerAdvance<BountiesObjective>(o => o.monster == null || o.monster == paidFor);

#Servidor e cliente

Roda em
ServerAdvance, o seu contador Só no servidor
Current Servidor (a contagem que vale)
Text, hint, Icon, Required Cliente, no registro de missões e no rastreador

As contagens chegam ao dono por PlayerQuests.active, uma lista sincronizada. O salvamento é automático: os contadores fazem parte do progresso da missão salvo com o personagem, no modo um jogador e online.

#Eventos de missão que você pode usar

Evento Quando
PlayerQuests.ServerCompleted (PlayerCharacter, QuestData) Uma missão foi entregue. Servidor.
PlayerQuests.Shown (Npc, QuestData) O cliente do dono recebeu uma missão mostrada por um NPC.
PlayerQuests.Changed (evento de instância) A lista de missões do dono mudou. Cliente.

Os métodos de servidor de PlayerQuests são virtual (ServerAccept, ServerTurnIn, ServerAbandon, ServerFinishObjectives, ServerForget, ServerTalked, ServerLoad) se você precisar mudar o próprio fluxo. Veja Sobrescrever o comportamento do kit.

#Erros comuns

  • Inscrever-se em SubsystemRegistration. O kit limpa os eventos ali; a ordem é indefinida. Use AfterAssembliesLoaded.
  • Avançar a partir do cliente. ServerAdvance é só do servidor; um pedido do cliente precisa ser verificado e transformado em progresso pelo código do servidor.
  • Filtrar de forma ampla demais. ServerAdvance<T>(o => true) avança todo objetivo daquele tipo em toda missão ativa. Coloque a regra no predicado.
  • Guardar contagens por jogador nos campos do objetivo. A missão guarda os contadores. Os campos são configurações do designer compartilhadas por todos os jogadores.
