Sobrescrevendo o comportamento do kit

Como mudar o que um componente do kit faz sem editá-lo: crie uma subclasse da janela, do sistema do jogador, do monstro ou do componente de NPC, sobrescreva seus métodos virtuais e troque o componente no prefab.

#Quando sobrescrever

A maioria das mudanças precisa de menos que isso. Antes de sobrescrever, confira:

  • uma configuração em Game Settings ou no componente,
  • um evento ao qual reagir (Eventos),
  • uma fórmula (Fórmulas),
  • um efeito, condição, ação, objetivo ou opção de NPC próprio.

Sobrescreva quando o próprio fluxo do kit precisa ser diferente: uma janela que lê o texto da sua localização, um monstro com seu próprio jeito de receber dano, um sistema de correio que recusa cartas com links.

Onde fica o arquivo: o assembly Game, já que o componente fica em prefabs que todas as builds carregam.

#O que pode ser sobrescrito

O kit deixa isto aberto para subclasses:

Em O que é virtual
Janelas e partes do HUD (KitARPG.Client) Os métodos do Unity (Awake, OnEnable, OnDisable, Update, OnDestroy) são protected virtual, mais os métodos feitos para mudar, como ShopWindow.Describe (texto de erro)
Sistemas do jogador (PlayerInventory, PlayerSkills, PlayerQuests, PlayerMail e os demais) Métodos do Unity protected virtual; métodos de servidor Server... public virtual (ou protected virtual para passos internos, como PlayerMail.ServerAnnounce(MailList))
Monster Métodos do Unity, ServerSetup, ServerDamage, ServerHeal, ServerAddBuff, ServerRemoveBuffs, ServerKnock, ServerRevive, ServerDespawn, Think, TryCast, RunPhase e outros
PlayerCharacter ServerSetup, ServerHeal, ServerAddExperience, ServerTryAttack, ServerAnnounce(string, Color) e outros métodos de servidor

A referência da API em Assets/Blunnyn/KitARPG/Documentation/API/ lista todos os membros virtual. Métodos que não são virtuais não foram feitos para mudar; leia a classe para achar o passo virtual que cobre o que você precisa.

#Como trocar um componente

  1. Escreva sua subclasse e deixe compilar.

  2. Abra o prefab que tem o componente do kit:

    Componente Prefab
    Sistemas do jogador, PlayerCharacter Todo prefab de modelo de jogador (KitARPG > Game Database > Models)
    Janelas e partes do HUD O prefab do HUD (GameInstance.hudPrefab, em Game Settings > Interface)
    Monster O prefab de cada monstro (o campo Prefab do monstro no Game Database)
    Npc O objeto do NPC na sua cena

  3. No componente do kit, abra o menu (os três pontos) e escolha Copy Component.

  4. Adicione seu componente. Nele, escolha Paste Component Values: todos os campos que o componente do kit tinha são copiados, já que sua classe os herda.

  5. Remova o componente do kit.

  6. Salve o prefab. Para sistemas do jogador, repita em todo prefab de modelo de jogador.

O código do kit encontra componentes com GetComponent<PlayerMail>() e chamadas parecidas, que também retornam sua subclasse. Nada mais precisa mudar.

Atenção

Em prefabs de rede (jogadores, monstros), a posição do componente na lista importa para o Mirror. Substituir um componente move o novo para o fim, o que não tem problema desde que as builds de cliente e de servidor usem o mesmo prefab. Nunca troque componentes em tempo de execução ou em uma build só.

#Exemplo: o template

Create > KitARPG > Scripts > Player System Override cria uma subclasse de PlayerMail:

using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Shared.Central;

namespace Game
{
    /// <summary>
    /// Changes how one of the kit's player systems behaves, here the mail, without editing the kit.
    /// On every player model prefab, remove the kit's component and add this one in its place
    /// (Copy Component, then Paste Component Values, keeps the settings).
    /// </summary>
    public class MyPlayerMail : PlayerMail
    {
        // Server methods decide for every player; call base for whatever you keep.
        protected override void ServerAnnounce(MailList list)
        {
            base.ServerAnnounce(list);
        }

        // Unity methods are protected virtual too.
        protected override void Awake()
        {
            base.Awake();
        }
    }
}

#Exemplo: um monstro que reduz o dano pela metade

using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    /// <summary>A monster with armor: every hit is reduced before it lands.</summary>
    public class ArmoredMonster : Monster
    {
        [Range(0, 1)] public float reduction = 0.5f;

        public override void ServerDamage(Hit hit, IFighter source)
        {
            hit.amount = Mathf.Max(1, Mathf.RoundToInt(hit.amount * (1 - reduction)));
            base.ServerDamage(hit, source);
        }
    }
}

Troque Monster por ArmoredMonster no prefab desse monstro. Os outros monstros mantêm o componente do kit.

#Exemplo: mensagens da loja localizadas

ShopWindow.Describe transforma códigos de erro em frases e foi feito para ser sobrescrito:

using Blunnyn.KitARPG.Client;
using Blunnyn.KitARPG.Net;

namespace Game
{
    public class MyShopWindow : ShopWindow
    {
        protected override string Describe(string code)
        {
            switch (code)
            {
                case NpcErrors.NotEnoughMoney: return Localize("shop.no_money");
                case NpcErrors.OutOfStock: return Localize("shop.sold_out");
                default: return base.Describe(code);
            }
        }

        static string Localize(string key) => key; // your localization lookup
    }
}

Troque-a no prefab do HUD, dentro do grupo Windows.

#Exemplo: uma regra em todo uso de item

PlayerInventory.UseItem é o passo do servidor que faz um item cumprir sua função. False mantém o item:

using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;

public class MyPlayerInventory : PlayerInventory
{
    protected override bool UseItem(IUsable item)
    {
        // No potions inside the arena maps.
        if (item.CooldownGroup == "potion" && gameObject.scene.name.StartsWith("Arena")) return false;
        return base.UseItem(item);
    }
}

#Exemplo: uma caixa de correio que abre a partir de um nível

PlayerMail.ServerOpen roda quando um NPC de caixa de correio abre o correio para um jogador:

using Blunnyn.KitARPG.Net;
using UnityEngine;

public class LevelGatedMail : PlayerMail
{
    public int minLevel = 5;

    public override string ServerOpen(Npc npc)
    {
        if (TryGetComponent(out PlayerCharacter player) && player.level < minLevel)
        {
            player.ServerAnnounce($"The mailbox opens at level {minLevel}.", new Color(1f, 0.5f, 0.45f));
            return null;
        }
        return base.ServerOpen(npc);
    }
}

A mesma regra poderia ser uma condição na opção do NPC da caixa de correio, sem código. Sobrescrever serve para regras que devem valer de qualquer lugar de onde o sistema seja acessado.

Os métodos de servidor decidem para todos os jogadores. Leia o método base antes de sobrescrevê-lo e chame base para cada passo que você mantém.

#Sobrescritas no servidor e no cliente

Sobrescrita Efeito
Um método Server... Muda a regra para todos os jogadores naquele servidor de mapa. Online, o que vale é a build do servidor de mapa.
Um método do Unity ou de uma janela Muda o que aquele jogador vê e como ele pede. Um cliente modificado pode desfazer isso, então nunca dependa disso para regras.

Tudo o que uma sobrescrita no cliente envia ao servidor deve ser verificado de novo no servidor, pelo kit ou por uma sobrescrita de servidor sua.

#Estáticos na classe base

Os sistemas do jogador definem estáticos como PlayerMail.Local no próprio OnStartAuthority. Se você sobrescrever OnStartAuthority, OnStopAuthority, Awake ou qualquer método do Unity, chame base primeiro, ou esses estáticos ficam vazios e as janelas do kit deixam de encontrar seu componente.

#Atualizações do kit e suas subclasses

As atualizações do kit também procuram os componentes do kit com GetComponent, então um prefab com sua subclasse conta como tendo o componente: a atualização não adiciona um segundo. Atualizações que adicionam campos a um componente do kit também chegam à sua subclasse, já que ela os herda.

Quando uma versão do kit muda um método virtual que você sobrescreve (parâmetros novos, um método removido), seu código para de compilar e o changelog diz o que mudou. Mantenha as sobrescritas pequenas e chame base para que o comportamento novo do kit chegue ao seu jogo.

#Erros comuns

  • Não chamar base nos métodos do Unity. Estáticos, inscrições e coleções sincronizadas preparados pela classe base ficam faltando.
  • Copiar uma classe inteira do kit em vez de criar uma subclasse. As atualizações deixam de chegar a ela.
  • Esquecer um modelo de jogador. Cada modelo é seu próprio prefab; um que tenha o componente do kit se comporta de outro jeito.
  • Sobrescritas no cliente que impõem regras. Faça isso no servidor.
