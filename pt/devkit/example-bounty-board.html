Exemplo: quadro de recompensas

Um passeio pelo exemplo do DevKit, arquivo por arquivo: um quadro de recompensas que entrega uma caçada por dia, conta abates, mostra o progresso no HUD, paga recompensas e mantém no Central um ranking dos melhores caçadores. Ele é feito só com os pontos de extensão desta seção, sem mudar o kit.

#O que ele faz

  1. Um quadro na cidade é um NPC com um botão Bounties.
  2. Cada personagem recebe uma caçada por dia da lista do quadro: matar uma quantidade de um monstro. A caçada é a mesma o dia inteiro para aquele personagem e diferente entre personagens.
  3. Os abates contam no servidor e uma linha embaixo do relógio mostra "Bounty: Slime 3/8".
  4. De volta ao quadro, o botão entrega a caçada e paga as recompensas definidas no quadro (ouro, experiência, qualquer coisa que as ações do kit podem fazer).
  5. Online, cada recompensa paga vai para um módulo no Central, e /hunters mostra os dez melhores caçadores de todos os mapas.

#Experimente

  1. Abra a cena Town ou Forest.
  2. Escolha KitARPG > DevKit > Add Bounty Board to the Open Scene. Um quadro de madeira aparece no pivô da Scene view e, na primeira vez, um asset Sample Bounty Board é criado a partir dos dois primeiros monstros normais do seu banco de dados. Salve a cena.
  3. Dê Play, vá até o quadro e aperte Today's bounty. Cace; a linha embaixo do relógio vai contando.
  4. De volta ao quadro, aperte Turn in the bounty.
  5. Para testar rápido: /bounty done completa os abates e /bounty reset limpa a caçada do dia (nível admin; em um jogador todo comando funciona).
  6. Online: compile o módulo do Central e instale-o (veja O módulo do Central abaixo), reinicie os serviços e digite /hunters.

#BountyBoardData.cs: os dados

[CreateAssetMenu(menuName = "KitARPG/DevKit Example/Bounty Board", order = 900)]
public class BountyBoardData : ScriptableObject
{
    [Serializable]
    public class Bounty
    {
        public MonsterData monster;
        public int count = 10;
        [Tooltip("Paid on turning it in.")]
        [SerializeReference, PickType] public GameAction[] rewards = new GameAction[0];
    }

    public Bounty[] bounties = new Bounty[0];

    /// <summary>Today's bounty for a character. The same all day, different between characters.</summary>
    public int Pick(long characterId, int day) =>
        bounties.Length == 0 ? -1 : (int)((characterId * 31 + day) % bounties.Length);

    public Bounty At(int index) => index >= 0 && index < bounties.Length ? bounties[index] : null;
}
  • Um ScriptableObject simples: só o código do exemplo aponta para ele, então não precisa ser um GameData com id.
  • rewards é uma lista de ações do kit com [SerializeReference, PickType], então os designers escolhem Give Currency, Experience, Give Item ou qualquer ação sua no mesmo menu que as missões usam. Veja Condições e ações em código.
  • Pick deriva a caçada do dia a partir do id do personagem e do número do dia, então nada precisa ser guardado para lembrar qual caçada foi oferecida.

#BountyOption.cs: o botão

[Serializable]
public class BountyOption : NpcOption
{
    public BountyBoardData board;

    protected override string DefaultLabel => "Bounties";

    public override string LabelFor(PlayerCharacter player) =>
        Bounties.Current(player.Facts, out _) != null ? "Turn in the bounty" : "Today's bounty";

    public override bool AvailableTo(PlayerCharacter player) => board != null;

    public override string Run(Npc npc, PlayerCharacter player)
    {
        Bounties.Register(board);
        string answer = Bounties.Current(player.Facts, out _) != null ? Bounties.TurnIn(player) : Bounties.Take(player, board);
        if (player.TryGetComponent(out PlayerChat chat)) chat.Tell(answer);
        return null;
    }
}
  • LabelFor dá a cada jogador o próprio texto.
  • AvailableTo esconde o botão em um quadro sem dados.
  • Run já sabe que o jogador está ao lado do quadro: o kit conferiu o alcance antes de chamá-lo. Ele responde no chat com PlayerChat.Tell e devolve null. Veja Opções de NPC.

#Bounties.cs: as regras do servidor

#Progresso em marcas

public const string BoardFlag = "bounty.board";
public const string IndexFlag = "bounty.index";
public const string KillsFlag = "bounty.kills";
public const string DayFlag = "bounty.day";
public const string DoneFlag = "bounty.done";
public const string LogKind = "bounty.done";

Todo o progresso são marcas do personagem, por meio de IPlayerActor.SetFlag e Flag. Elas são salvas com o personagem em um jogador e online, e sincronizadas com o dono, sem código de salvamento. O quadro é guardado como um hash do nome do asset (Animator.StringToHash(board.name)), a caçada como o índice mais um (0 significa nenhuma) e o dia como dias desde 2020-01-01 UTC. Veja Salvar dados.

#Encontrar quadros depois de um reinício

static readonly Dictionary<int, BountyBoardData> boards = ...;
static bool scanned;

static BountyBoardData Board(int key)
{
    if (boards.TryGetValue(key, out BountyBoardData board) || scanned) return board;
    scanned = true;
    foreach (Npc npc in UnityEngine.Object.FindObjectsByType<Npc>(FindObjectsSortMode.None))
        foreach (NpcOption option in npc.AllOptions())
            if (option is BountyOption b && b.board != null) Register(b.board);
    boards.TryGetValue(key, out board);
    return board;
}

As marcas de um personagem apontam para um quadro pelo hash. Depois de um reinício do servidor, ninguém usou um quadro ainda, então a primeira busca percorre uma vez os NPCs das cenas carregadas (Npc.AllOptions() inclui opções aninhadas em linhas de diálogo). Uma cena nova reinicia a busca.

#Conectar-se

// Cleared before anything subscribes, so listeners from other assemblies are never wiped.
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
static void ResetStatics()
{
    boards.Clear();
    scanned = false;
    ServerTurnedIn = null;
}

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
static void Hook()
{
    SceneManager.sceneLoaded -= OnSceneLoaded;
    SceneManager.sceneLoaded += OnSceneLoaded;
    Monster.ServerKilled -= OnKilled;
    Monster.ServerKilled += OnKilled;
    PlayerCharacter.LocalSpawned -= AskOnSpawn;
    PlayerCharacter.LocalSpawned += AskOnSpawn;
    KitNetworkManager manager = KitNetworkManager.Instance;
    if (manager == null) return;
    manager.ServerStarted += () => NetworkServer.ReplaceHandler<BountyAsk>(OnAsk);
    manager.ClientConnected += () => NetworkClient.ReplaceHandler<BountyState>(BountyTracker.Show);
}
  • ResetStatics limpa o estado estático (boards, scanned e o evento ServerTurnedIn) em SubsystemRegistration, no início de cada Play, porque o projeto dá Play sem recarga de domínio. Limpar ali, antes que qualquer coisa se inscreva, permite que BountyHunters em Game.Bounties.Server se inscreva em ServerTurnedIn depois sem ser apagado (veja Play sem recarga de domínio).
  • Hook se inscreve nos eventos estáticos com -= primeiro, e antes de verificar o network manager, então abates, spawns e carregamentos de cena ficam inscritos mesmo quando a primeira cena não tem KitNetworkManager.
  • Os handlers de mensagens são registrados a cada início de servidor e a cada conexão de cliente (veja Mensagens de rede).
  • Monster.ServerKilled conta os abates no servidor; PlayerCharacter.LocalSpawned pede o estado no cliente.

#Pegar uma recompensa

public static string Take(PlayerCharacter player, BountyBoardData board)
{
    IPlayerActor actor = player.Facts;
    if (actor.Flag(DayFlag) == Today && actor.Flag(IndexFlag) == 0) return "You already hunted today's bounty. Come back tomorrow.";
    int index = board.Pick(player.State.id, Today);
    BountyBoardData.Bounty bounty = board.At(index);
    if (bounty == null || bounty.monster == null) return "The board is empty.";
    actor.SetFlag(BoardFlag, Register(board));
    actor.SetFlag(IndexFlag, index + 1);
    actor.SetFlag(KillsFlag, 0);
    actor.SetFlag(DayFlag, Today);
    Send(player);
    return $"Today's bounty: slay {bounty.count} {bounty.monster.DisplayName}.";
}

Toda decisão usa o estado do servidor: as marcas do personagem e o id dele no banco de dados. Nada vem do cliente.

#Contar abates

static void OnKilled(Monster monster, PlayerCharacter killer)
{
    if (killer == null || killer.State == null || monster.Data == null) return;
    IPlayerActor actor = killer.Facts;
    BountyBoardData.Bounty bounty = Current(actor, out _);
    if (bounty == null || bounty.monster != monster.Data) return;
    int kills = actor.Flag(KillsFlag);
    if (kills >= bounty.count) return;
    actor.SetFlag(KillsFlag, kills + 1);
    if (kills + 1 == bounty.count) killer.ServerAnnounce("Bounty complete! Turn it in at the board.", new Color(1f, 0.85f, 0.3f));
    Send(killer);
}

ServerKilled entrega o jogador que ganhou o abate (pode ser null). A contagem para no alvo.

#Entregar

public static string TurnIn(PlayerCharacter player)
{
    IPlayerActor actor = player.Facts;
    BountyBoardData.Bounty bounty = Current(actor, out _);
    if (bounty == null) return "You have no bounty.";
    int kills = actor.Flag(KillsFlag);
    if (kills < bounty.count) return $"{kills} of {bounty.count} {bounty.monster.DisplayName} so far.";
    string why = GameAction.RunAll(bounty.rewards, actor);
    if (why != null) return why;
    actor.SetFlag(IndexFlag, 0);
    actor.SetFlag(DoneFlag, actor.Flag(DoneFlag) + 1);
    GameLog.Write(LogKind, player, itemId: bounty.monster.Id, amount: bounty.count);
    ServerTurnedIn?.Invoke(player, bounty.monster);
    Send(player);
    return "Bounty paid. Well hunted.";
}
  • GameAction.RunAll confere primeiro cada recompensa (uma bolsa cheia recusa Give Item) e depois paga todas.
  • GameLog.Write escreve uma linha bounty.done; os moderadores a encontram com /logs (veja Registro do jogo e reportes).
  • ServerTurnedIn é o evento próprio do exemplo, disparado em Game.Bounties e escutado por Game.Bounties.Server, que os clientes online não têm.

#Avisar o cliente

public static void Send(PlayerCharacter player)
{
    BountyBoardData.Bounty bounty = Current(player.Facts, out _);
    player.connectionToClient?.Send(bounty == null
        ? new BountyState()
        : new BountyState { monster = bounty.monster.DisplayName, kills = player.Facts.Flag(KillsFlag), required = bounty.count });
}

static void AskOnSpawn(PlayerCharacter _) => NetworkClient.Send(new BountyAsk());

// The connection says who asks; the message carries nothing to trust.
static void OnAsk(NetworkConnectionToClient conn, BountyAsk _)
{
    if (!CommandPacing.Allow(conn)) return;
    if (conn.identity != null && conn.identity.TryGetComponent(out PlayerCharacter player) && player.State != null) Send(player);
}

O pedido do cliente é vazio: o servidor sabe quem pediu pela conexão. Ele tem limite de ritmo com CommandPacing.

#BountyTracker.cs: a linha do HUD

public static void Show(BountyState state)
{
    if (label == null) Build();
    if (label == null) return;

GameInstance.Hud é a instância do HUD em execução. A linha é montada por código na primeira vez que chega um estado. #BountiesDoneCondition.cs: uma condição para designers

[Serializable]
public class BountiesDoneCondition : Condition
{
    public int atLeast = 5;

    protected override string DefaultText => $"Needs {atLeast} bounties done";

    public override bool Met(IPlayerFacts facts) => facts.Flag(Bounties.DoneFlag) >= atLeast;
}

Ela lê uma marca, que o cliente do dono também tem, então os marcadores de missão e as linhas bloqueadas aparecem corretamente. Os designers podem colocá-la em uma opção de loja que abre depois de cinco recompensas, em uma missão ou em uma saudação.

#Server/BountyCommands.cs: o comando de GM

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
static void Register()
{
    GmCommands.Register(new GmCommand
    {
        name = "bounty", rank = GmRank.Admin, usage = "bounty reset|done [player]", description = "Clears a player's bounty for today, or fills its kills.",
        run = c =>
        {
            PlayerCharacter target = c.Target(1);
            if (target == null) return "Nobody by that name here.";
            IPlayerActor actor = target.Facts;
            switch (c.Arg(0))
            {
                case "reset":
                    actor.SetFlag(Bounties.DayFlag, 0);
                    actor.SetFlag(Bounties.IndexFlag, 0);
                    break;
                case "done":
                    BountyBoardData.Bounty bounty = Bounties.Current(actor, out _);
                    if (bounty == null) return $"{target.characterName} has no bounty.";
                    actor.SetFlag(Bounties.KillsFlag, bounty.count);
                    break;
                default:
                    return "Usage: /bounty reset|done [player]";
            }
            Bounties.Send(target);
            return $"Bounty of {target.characterName}: {c.Arg(0)}.";
        },
    });
}

Ele fica em Game.Bounties.Server, então os builds de cliente o deixam de fora. Nível admin significa que todo uso é auditado. Veja Comandos de GM em código.

#Server/BountyHunters.cs: Central e histórico salvo

public const string HistoryKey = "bounties.history";

[Serializable]
public class History
{
    public List<string> monsters = new List<string>();
}

static void OnTurnedIn(PlayerCharacter player, MonsterData monster)
{
    History history = PlayerData.Get<History>(player, HistoryKey);
    history.monsters.Insert(0, monster.DisplayName);
    if (history.monsters.Count > HistorySize) history.monsters.RemoveRange(HistorySize, history.monsters.Count - HistorySize);
    PlayerData.Set(player, HistoryKey, history);
    // Offline the board just misses this one; the character's own history still has it.
    CentralMessages.Send(new BountyFinished { characterId = player.State.id, name = player.characterName, monster = monster.Id });
}
  • Cada personagem guarda as últimas dez caçadas com PlayerData, salvas com o personagem e nunca enviadas aos clientes.
  • Cada recompensa paga vai para o Central. Send devolve false em um jogador ou enquanto o Central está fora, e nada fica na fila: o ranking perde essa, o histórico não.
CentralMessages.On<BountyBoardList>(OnBoard);
GmCommands.Register(new GmCommand
{
    name = "hunters", rank = GmRank.Player, usage = "hunters", description = "The best bounty hunters on every map, and your last hunts.",
    run = c =>
    {
        string mine = Last(c.player);
        if (!CentralMessages.Online) return "The hunters board is kept online." + mine;
        CentralMessages.Send(new BountyBoardAsk { characterId = c.player.State.id });
        return "Asking the guild of hunters..." + mine;
    },
});

static void OnBoard(BountyBoardList board)
{
    var text = new StringBuilder("Best bounty hunters:");
    int rank = 1;
    foreach (BountyHunter hunter in board.top ?? new BountyHunter[0])
        text.Append($"\n{rank++}. {PlayerText.NoTags(hunter.name)}: {hunter.bounties}");
    if (rank == 1) text.Append("\nNobody yet.");
    text.Append($"\nYou: {board.mine}");
    SocialHub.Notice(board.characterId, text.ToString());
}
  • /hunters é um comando de nível jogador: um recurso de chat, não uma ferramenta da equipe, então não é auditado.
  • A resposta volta depois por CentralMessages.On e aparece no chat de quem pediu com SocialHub.Notice.
  • Os nomes que vieram de jogadores são mostrados com PlayerText.NoTags.

#Editor/BountySetup.cs: o menu de montagem

#O módulo do Central

Services/Examples/Bounties/ é o lado do Central:

Arquivo O que faz
Game.Bounties.Central.csproj Referencia o contrato de módulos sem copiá-lo, liga BountyBoardMessages.cs e copia o build para -p:KitModulesDir.
BountiesModule.cs ICentralModule chamado Bounties. Registra BountyContext, trata BountyFinished (valida o nome, de 1 a 32 caracteres, e m.Hosts(characterId), e então soma um à linha sob um SemaphoreSlim) e BountyBoardAsk (responde com os 10 melhores e a contagem de quem pediu).
BountyContext.cs A tabela bounty_hunters: character_id (chave), name, count (com índice).
Migrations/ Uma migração sem tipos de coluna, para rodar em SQLite e PostgreSQL.

Compile e instale:

cd Services
dotnet build Examples/Bounties -c Release -p:KitModulesDir=<launcher folder>/modules/central
dotnet build Examples/Bounties -c Release -p:KitModulesDir=../Deploy/modules/central   # Docker

#Faça do seu jeito

  • Adicione caçadas a Sample Bounty Board ou crie outros assets de quadro com Create > KitARPG > DevKit Example > Bounty Board. Cabe qualquer recompensa que as ações do kit podem dar.
  • Troque as marcas por um sistema do jogador quando precisar de estado sincronizado além de alguns números.
  • Adicione um objetivo de missão que conte recompensas, avançado a partir de Bounties.ServerTurnedIn.
  • Copie a estrutura de pastas (assembly do recurso, .Server, .Shared, .Editor) para os seus próprios recursos.
  • No seu próprio código, limpe os eventos estáticos em SubsystemRegistration e assine-os em AfterAssembliesLoaded ou depois, para que a ordem dos métodos de inicialização nunca importe.
  • Apague DevKit/Example/Bounties para remover o exemplo. Tire antes o quadro das suas cenas: elas referenciam BountyOption.
