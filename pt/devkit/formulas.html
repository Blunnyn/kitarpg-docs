Fórmulas

Como mudar a matemática do jogo sem mexer no kit: a CombatFormula para dano, cura, velocidade de ataque e experiência, e a StatFormula para como classe, nível, atributos e equipamento se somam nos stats.

#Como as fórmulas são instaladas

O kit guarda dois objetos de fórmula em GameInstance:

Propriedade Tipo Decide
GameInstance.Combat CombatFormula Dano, ticks de dano ao longo do tempo, curas, tempo entre ataques, experiência por abate
GameInstance.Formula StatFormula Fichas de stats, pontos de atributo e pontos de habilidade ganhos por nível

As duas são classes C# comuns em KitARPG.Data com métodos virtual. Para mudar uma regra, crie uma subclasse, sobrescreva o que precisar e atribua uma instância na inicialização:

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
static void Install() => GameInstance.Combat = new MyCombatFormula();

O kit recoloca as próprias fórmulas em SubsystemRegistration a cada Play (veja Play sem domain reload). BeforeSceneLoad roda depois disso e antes de qualquer cena, então nada luta antes de a sua fórmula estar no lugar.

Onde fica o arquivo: no assembly Game, para que todo build a instale. É o servidor que aplica as fórmulas, mas o cliente também usa Combat.Experience: o bestiário mostra a experiência que um monstro dá ao jogador local. Uma fórmula só em Game.Server faria o bestiário discordar do que os jogadores ganham.

#CombatFormula

Método Chamado quando O que devolve
Hit Attack(StatSheet attacker, IReadOnlyList<ElementDamage> rolls, StatSheet defender, float scale = 1) Ataques básicos de jogadores e monstros, e DamageEffect nas habilidades O golpe: total, crítico, elemento principal
float Element(StatSheet attacker, DamageElement element, float roll, StatSheet defender) Por Attack e Tick, para a parte de cada elemento O dano desse elemento depois das resistências
Hit Tick(StatSheet caster, DamageElement element, float amount, StatSheet holder) Cada tick de um estado de dano ao longo do tempo O golpe do tick, nunca crítico, no mínimo 1
int Heal(StatSheet healer, float amount) HealEffect e estados de cura A cura final
float AttackInterval(float attacksPerSecond, StatSheet attacker) Todo ataque básico de jogadores e monstros Segundos até o próximo ataque
long Experience(MonsterData monster, int playerLevel) Um abate, para quem matou e para cada membro do grupo que divide; o bestiário Experiência antes de bônus e taxas

#As regras do kit

  • Ataque: cada rolagem é calculada separadamente para o seu elemento. A rolagem (um valor aleatório entre o mínimo e o máximo dela, vezes scale) mais o dano do atacante para aquele elemento, aumentado pelo poder do atacante. Depois sai a resistência fixa do defensor àquele elemento, depois a resistência percentual, com teto no Max Resistance (maxResistance) do elemento (0,5 quando a rolagem não tem elemento). Os totais se somam. Um golpe crítico (chance critChance) multiplica o total por 1 + critDamage. O resultado é arredondado e no mínimo 1.
  • Tick: a mesma regra de elemento com os stats do lançador como estavam quando o estado foi aplicado; sem crítico.
  • Cura: (amount + healer.healing) * (1 + healer.healingBonus), arredondado.
  • Intervalo de ataque: 1 / (attacksPerSecond * (1 + attackSpeed)), com no mínimo 0,1 ataque por segundo.
  • Experiência: a experiência do monstro inteira até 3 níveis abaixo do jogador; depois 20% a menos para cada nível mais abaixo, até 10%.

Depois de Experience, o kit aplica o stat de ganho de experiência do jogador, as taxas do servidor (experienceRate e os eventos de /rates) e a divisão no grupo. A sua fórmula devolve a quantidade base.

#StatSheet

O que são attacker, defender e healer:

Membro O que é
CharacterStats stats maxHealth, maxMana, healthRegen, manaRegen, power, critChance, critDamage, healing, healingBonus, attackSpeed, moveSpeed, carryWeight, experienceGain, lootChance. As proporções são frações: critChance 0.05 é 5%.
ElementStats Element(DamageElement e) O damage, a resistance e a resistancePercent do elemento. Um elemento null lê o fallback.
int Attribute(AttributeData a) O total de um atributo.
DamageElement fallback O elemento padrão do jogo.

#Exemplo: diferença de nível mais dura

Monstros muito abaixo do jogador não dão nada depois de 8 níveis:

using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    public class MyCombatFormula : CombatFormula
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
        static void Install() => GameInstance.Combat = new MyCombatFormula();

        public override long Experience(MonsterData monster, int playerLevel)
        {
            int gap = playerLevel - monster.level;
            if (gap >= 8) return 0;
            return base.Experience(monster, playerLevel);
        }
    }
}

#Exemplo: armadura a partir de um atributo

Uma redução fixa a partir de um atributo do seu jogo (aqui um com id toughness), aplicada a todo elemento antes da resistência percentual:

public class ToughnessFormula : CombatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Combat = new ToughnessFormula();

    AttributeData toughness;

    public override float Element(StatSheet attacker, DamageElement element, float roll, StatSheet defender)
    {
        if (toughness == null) GameInstance.Database.TryGet("toughness", out toughness);
        float damage = base.Element(attacker, element, roll, defender);
        int points = toughness != null ? defender.Attribute(toughness) : 0;
        return Mathf.Max(0, damage - points * 0.5f);
    }
}

toughness é um campo de instância: Install cria uma fórmula nova a cada Play, então o asset em cache começa vazio toda vez, mesmo sem domain reload. Um cache static sobreviveria ao Play e manteria uma referência antiga se o banco de dados mudasse entre Plays; reinicie esses estáticos em SubsystemRegistration (veja Play sem domain reload).

#Exemplo: chance de crítico e velocidade de ataque com teto

using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using UnityEngine;

public class CappedFormula : CombatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Combat = new CappedFormula();

    public override Hit Attack(StatSheet attacker, IReadOnlyList<ElementDamage> rolls, StatSheet defender, float scale = 1)
    {
        // Capped for this attack only, then put back.
        float chance = attacker.stats.critChance;
        attacker.stats.critChance = Mathf.Min(chance, 0.5f);
        try { return base.Attack(attacker, rolls, defender, scale); }
        finally { attacker.stats.critChance = chance; }
    }

    public override float AttackInterval(float attacksPerSecond, StatSheet attacker) =>
        Mathf.Max(0.25f, base.AttackInterval(attacksPerSecond, attacker));
}

stats é um campo struct na ficha, então a mudança é feita e desfeita em volta da chamada à base.

#StatFormula

Método Chamado quando Devolve
StatSheet Sheet(CharacterClass characterClass, int level, IReadOnlyList<AttributeAmount> spent, GameDatabase database, IReadOnlyList<IStatSource> sources = null) Toda vez que os stats de um jogador são calculados (PlayerCharacter.RecalculateStats: nível, atributos, equipamento ou buffs mudaram), e para personagens novos no modo um jogador A ficha completa
int PointsEarned(CharacterClass characterClass, int level) Subidas de nível Pontos de atributo ganhos até aquele nível
int SkillPointsEarned(CharacterClass characterClass, int level) Totais de pontos de habilidade Pontos de habilidade ganhos até aquele nível

#A ordem do kit

  1. Os atributos da classe neste nível, depois os pontos gastos, depois os bônus de atributo de todas as fontes (equipamento, buffs, passivas).
  2. Os stats base da classe mais os stats por nível vezes level - 1.
  3. Os stats Per Point de cada atributo vezes o total dele.
  4. Os modificadores de stats de todas as fontes. Os bônus percentuais se aplicam por último.

Os padrões de pontos são Points Per Level (pointsPerLevel, 5) e Skill Points Per Level (skillPointsPerLevel, 1) da classe, vezes level - 1.

Os monstros não usam a fórmula de stats; os stats deles vêm dos seus dados.

#Exemplo: dois pontos de atributo por nível

public class MyStatFormula : StatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Formula = new MyStatFormula();

    // Two attribute points per level instead of the class's own number.
    public override int PointsEarned(CharacterClass characterClass, int level) => 2 * (level - 1);
}

#Exemplo: vida que cresce uma proporção por nível

using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Shared.Characters;
using UnityEngine;

public class GrowingHealthFormula : StatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Formula = new GrowingHealthFormula();

    public override StatSheet Sheet(CharacterClass characterClass, int level, IReadOnlyList<AttributeAmount> spent,
        GameDatabase database, IReadOnlyList<IStatSource> sources = null)
    {
        StatSheet sheet = base.Sheet(characterClass, level, spent, database, sources);
        // +2% max health per level after the first, kept whole.
        sheet.stats.maxHealth = Mathf.Round(sheet.stats.maxHealth * (1 + 0.02f * (level - 1)));
        return sheet;
    }
}

No kit, os stats são números inteiros e os bônus percentuais são pontos inteiros. Arredonde o que você soma, como acima, para que tooltips e fichas concordem.

#Exemplo: um ponto de habilidade a cada dois níveis

public override int SkillPointsEarned(CharacterClass characterClass, int level) => (level - 1) / 2;

#Mudar as regras em um jogo no ar

As fórmulas decidem números novos; elas não reescrevem os salvos. Mudar PointsEarned muda o que se ganha daqui em diante. Os personagens mantêm os pontos que têm: os pontos livres ficam guardados e só a diferença em cada subida de nível é somada. Se você diminuir os pontos por nível em um jogo no ar, dê aos jogadores um jeito de recomeçar (o ResetAttributesAction do kit ou o Scroll of Second Thoughts).

#Servidor e cliente

Servidor Cliente
Attack, Element, Tick, Heal, AttackInterval Sim Não
Experience Sim O bestiário
Sheet, PointsEarned, SkillPointsEarned Sim Não; o dono recebe a ficha pronta

Online, uma fórmula em um build de cliente diferente da do servidor de mapa só muda o que o bestiário desse cliente mostra. O modo um jogador roda as duas metades em um só processo.

#Erros comuns

  • Instalar em SubsystemRegistration. O kit reinicia as fórmulas ali; a ordem é indefinida.
  • Instalar só em Game.Server. O bestiário nos clientes passa a mostrar os números do kit.
  • Devolver decimais em Sheet. Arredonde o que você soma.
  • Guardar estado por lutador na fórmula. Uma só instância atende todos os lutadores do mapa.
  • Aplicar taxas dentro de Experience. O kit aplica o stat de experiência e as taxas do servidor depois dela, então contariam duas vezes.
