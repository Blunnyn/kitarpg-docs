DevKit

Extensões do editor

Como adicionar páginas suas à janela KitARPG, verificações suas ao Project Check e à verificação antes das builds, e como usar o visual de editor do kit nas suas ferramentas.

Onde os arquivos ficam: no assembly Game.Editor (veja Assemblies). Tudo nesta página usa KitARPG.Editor e UnityEditor, que nunca entram em uma build.

#Páginas na janela KitARPG

A janela KitARPG (KitARPG > Open KitARPG, Ctrl/Cmd+Shift+K) tem uma barra lateral de páginas: Overview, Play & Servers, Game Database, Game Settings, Shop, Modules e Project Check. Toda subclasse não abstrata de KitPage com um construtor sem parâmetros é encontrada pelo TypeCache do Unity e adicionada à barra lateral. Não há nada para registrar.

#KitPage

Membro O que faz Padrão
abstract string Name O nome da página na barra lateral.
virtual string Group O título da barra lateral sob o qual ela fica. O kit usa "" (topo), "Game" e "Project", nessa ordem; outros nomes vêm depois deles. "Game"
virtual int Order Ordem dentro do grupo, menor primeiro. Depois por nome. 100
virtual string IconName O nome de um ícone embutido do editor, como "Settings" ou "d_Favorite". "ScriptableObject Icon"
virtual string Badge Texto curto ao lado do nome, como uma contagem de problemas. Null não mostra nada. null
virtual KitGUI.State BadgeState A cor do selo. Off
virtual bool FullWidth True dá à página a área inteira em vez de uma coluna centralizada com rolagem, para páginas com colunas próprias. false
virtual void OnEnable(), OnDisable() Quando a página é mostrada e escondida.
virtual void Tick() Cerca de dez vezes por segundo enquanto a janela está aberta, para consultas periódicas.
abstract void OnGUI() Desenha a página, com IMGUI.
KitWindow Window A janela.
Rect Area A área onde a página desenha.
void Repaint() Pede à janela que redesenhe.

As páginas do kit usam estas ordens: Overview 0 e Play & Servers 1 (grupo ""); Game Database 10, Game Settings 20, Shop 25, Modules 30 (grupo "Game"); Project Check 10 (grupo "Project").

KitWindow.Show<T>() abre a janela em uma página: KitWindow.Show<GameDatabaseWindow>(), KitWindow.Show<MyGamePage>().

#Exemplo: uma página para o seu conteúdo

Lista todos os quadros de recompensas do projeto, com um botão para selecionar cada um e um selo de aviso quando algum está vazio. O tipo do quadro fica no assembly Game.Bounties do exemplo, então o assembly de editor que contém esta página o referencia.

using System.Linq;
using Blunnyn.KitARPG.Editor;
using Game.Bounties;
using UnityEditor;
using UnityEngine;

namespace Game
{
    public class BountyBoardsPage : KitPage
    {
        BountyBoardData[] boards = new BountyBoardData[0];

        public override string Name => "Bounty Boards";
        public override int Order => 500;
        public override string IconName => "d_Favorite";

        int Empty => boards.Count(b => b != null && b.bounties.Length == 0);

        public override string Badge => Empty > 0 ? Empty.ToString() : null;
        public override KitGUI.State BadgeState => KitGUI.State.Warning;

        public override void OnEnable() => Load();

        void Load() => boards = AssetDatabase.FindAssets("t:BountyBoardData")
            .Select(g => AssetDatabase.LoadAssetAtPath<BountyBoardData>(AssetDatabase.GUIDToAssetPath(g)))
            .Where(b => b != null).ToArray();

        public override void OnGUI()
        {
            KitGUI.Header("Bounty Boards", "Every board asset in the project and its hunts.");
            if (boards.Length == 0) KitGUI.Empty("No boards yet", "Create one with Create > KitARPG > DevKit Example > Bounty Board.");
            foreach (BountyBoardData board in boards)
            {
                KitGUI.State state = board.bounties.Length == 0 ? KitGUI.State.Warning : KitGUI.State.Done;
                string detail = board.bounties.Length == 0 ? "No hunts" : $"{board.bounties.Length} hunts";
                if (KitGUI.Status(state, board.name, detail, "Select")) Selection.activeObject = board;
            }
            KitGUI.Line();
            if (KitGUI.Secondary("Refresh", 120)) Load();
        }
    }
}

#O visual de editor do kit

KitGUI (namespace Blunnyn.KitARPG.Editor) desenha os cartões, títulos, linhas de estado e botões das janelas do kit, em IMGUI puro, para que as suas páginas combinem.

Membro O que desenha
Header(text, sub, icon) Um título de página com uma linha embaixo.
BeginCard(heading, sub, stripe) / EndCard(), ou using (new KitGUI.CardScope(heading)) Um cartão arredondado.
Status(state, heading, detail, button, primaryButton) Uma linha de checklist com uma luz colorida e um botão opcional; devolve true quando pressionado.
Primary(text, width, height), Secondary(...) Botões; devolvem true quando pressionados.
Segmented(value, options, height) Um controle segmentado; devolve o índice escolhido.
Switch(rect, on) Um interruptor liga/desliga.
Pill(text, color) Um pequeno rótulo colorido.
Tile(rect, value, caption, state) Um número com uma legenda.
Empty(heading, detail) Um espaço reservado para listas vazias.
Message(text, state) Uma linha de mensagem colorida.
Line(space) Um divisor.
Icon(name) Um ícone embutido do editor.
Accent, Good, Warn, Bad, Of(state) A paleta, para os temas claro e escuro do editor.

KitGUI.State é Done, Todo, Warning, Error, Off e Busy (uma luz pulsante).

#Inspetores para os seus dados

O inspetor do kit para dados do jogo (GameDataEditor) desenha todo asset GameData como cartões divididos pelos seus atributos [Header], e vale também para subclasses. Um tipo GameData seu ganha o mesmo visual sem um editor próprio. Use [Header], [Tooltip] e [Range] nos seus campos e ele fica com a cara dos dados do próprio kit.

#Verificações do projeto

KitARPG > Project Check (a página Project Check) roda todas as verificações de ProjectValidator.Checks e lista o que encontram como erros, avisos e notas, cada um com um botão para selecionar aquilo de que trata e, quando existe, um botão para corrigir. A mesma lista roda antes de cada build, sem abrir cenas, e para a build quando há erros (BuildCheck, que pode ser desligado na página Project Check).

#ProjectValidator

Membro O que é
static List<Action<List<ValidationIssue>>> Checks Todas as verificações, em ordem. Cada uma adiciona o que encontra à lista que recebe. Adicione as suas.
static List<ValidationIssue> Run(bool scenes = true) Roda todas. Com scenes false, as verificações que abrem cenas são puladas, como antes das builds.
static bool IncludeScenes Se a execução em andamento abre cenas. Leia-o em uma verificação que abriria cenas.

#ValidationIssue

Campo O que é
IssueLevel level Error (para as builds), Warning ou Info.
string area Um nome curto de grupo, como "My game".
string message Uma linha dizendo o que está errado.
Object context O asset ou objeto de que se trata; o botão Select o destaca.
string fixLabel Texto do botão de correção.
Action fix O que o botão de correção faz. Null não mostra botão.

#Registrando uma verificação

ProjectValidator.Checks é uma lista estática que vive enquanto durar o domínio do editor. Registre a partir de [InitializeOnLoadMethod], que roda depois de cada recarga de scripts, e remova antes de adicionar para que uma verificação nunca rode duas vezes:

[InitializeOnLoadMethod]
static void Register()
{
    ProjectValidator.Checks.Remove(Check);
    ProjectValidator.Checks.Add(Check);
}

#Exemplo: quadros de recompensas com prêmios vazios, com correção

using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Editor;
using Game.Bounties;
using UnityEditor;

namespace Game
{
    public static class BountyChecks
    {
        [InitializeOnLoadMethod]
        static void Register()
        {
            ProjectValidator.Checks.Remove(Check);
            ProjectValidator.Checks.Add(Check);
        }

        static void Check(List<ValidationIssue> issues)
        {
            foreach (string guid in AssetDatabase.FindAssets("t:BountyBoardData"))
            {
                var board = AssetDatabase.LoadAssetAtPath<BountyBoardData>(AssetDatabase.GUIDToAssetPath(guid));
                if (board == null) continue;
                for (int i = 0; i < board.bounties.Length; i++)
                {
                    BountyBoardData.Bounty bounty = board.bounties[i];
                    if (bounty.monster == null)
                        issues.Add(new ValidationIssue
                        {
                            level = IssueLevel.Error, area = "Bounties", context = board,
                            message = $"{board.name}: hunt {i + 1} has no monster.",
                        });
                    else if (bounty.rewards.Length == 0)
                    {
                        BountyBoardData.Bounty b = bounty;
                        issues.Add(new ValidationIssue
                        {
                            level = IssueLevel.Warning, area = "Bounties", context = board,
                            message = $"{board.name}: hunting {bounty.monster.DisplayName} pays nothing.",
                            fixLabel = "Add 100 gold",
                            fix = () =>
                            {
                                Undo.RecordObject(board, "Add bounty reward");
                                b.rewards = new GameAction[] { new GiveCurrencyAction { amount = 100 } };
                                EditorUtility.SetDirty(board);
                            },
                        });
                    }
                }
            }
        }
    }
}

#Diretrizes para verificações

  • Erros param as builds. Use Error só para coisas que vão quebrar no jogo. Use Warning para prováveis erros e Info para sugestões.
  • Seja rápido. As verificações rodam antes de cada build. Evite abrir cenas a menos que ProjectValidator.IncludeScenes seja true.
  • Aponte para o asset. Defina context para que o botão Select funcione.
  • Correções são seguras. Uma correção só deve adicionar o que falta ou corrigir uma coisa clara, com Undo e SetDirty.

#Encontrando as configurações e o banco de dados do jogo

ModulesWindow.Find() devolve o GameInstance do projeto (o do prefab KitNetwork), guardado em cache por alguns segundos. O campo database dele é o GameDatabase:

GameInstance game = ModulesWindow.Find();
GameDatabase database = game != null ? game.database : null;

GameDatabase.All<T>() lista todos os assets de um tipo e TryGet<T>(id, out T) encontra um pelo id.

#Itens de menu

[MenuItem]s comuns do Unity funcionam normalmente. Para colocar os seus ao lado dos do kit, use a raiz KitARPG/, como o exemplo faz com KitARPG > DevKit > Add Bounty Board to the Open Scene:

[MenuItem("KitARPG/My Game/Rebuild Recipes", priority = 200)]
static void Rebuild() { /* ... */ }

#Erros comuns

  • Código de editor em Game. Ele referencia UnityEditor e a build falha. Use Game.Editor.
  • Registrar uma verificação sem removê-la antes. Ela roda uma vez a mais depois de cada recarga de scripts.
  • Tick ou OnGUI lentos. Eles rodam com frequência; guarde em cache o que você carrega, como a página acima faz em OnEnable.
  • Uma página sem construtor sem parâmetros. Ela não é encontrada.
