Opções de NPC

Como adicionar seus próprios botões aos NPCs: a classe base NpcOption, o que o servidor verifica antes de executá-la, como responder ao jogador, como abrir uma janela sua e exemplos completos.

#O que é uma opção de NPC

Um componente Npc em uma cena tem uma lista de opções (Npc.options). Quando um jogador fala com o NPC, o servidor lista as opções que esse jogador pode ver, o cliente as mostra como botões e, quando o jogador escolhe uma, o servidor a executa. As opções do kit abrem lojas, teletransportam, ensinam habilidades, oferecem missões, executam falas de diálogo, abrem o banco, o mercado, o banco da guilda, a forja, o correio, os coletores, a fundação de guilda e as sedes de guilda, e disparam gatilhos do mundo.

Um tipo novo é uma classe. NpcOption é [Serializable] e a lista é [SerializeReference, PickType], então a sua aparece no menu + de Options de todo NPC e nas Options aninhadas de toda fala de diálogo.

Onde o arquivo fica: no assembly Game. As cenas guardam a opção no NPC, então os dois builds carregam a classe, embora só o servidor a execute.

#A classe base

NpcOption fica em Blunnyn.KitARPG.Net.

#Campos do Inspector

Campo O que faz Padrão
Label (label) Texto do botão. Vazio usa DefaultLabel. vazio
Required Level (requiredLevel) Fica oculta para personagens abaixo deste nível. 0
Conditions (conditions) Fica oculta enquanto uma delas não for cumprida. nenhuma
Show When Locked (showWhenLocked) Mostra a opção em cinza com o motivo em vez de ocultá-la. desligado

#Membros para sobrescrever

Membro O que faz Padrão
protected abstract string DefaultLabel { get; } Texto do botão quando Label está vazio. Obrigatório.
virtual string LabelFor(PlayerCharacter player) Servidor. O texto que este jogador vê, para rótulos que mudam por jogador. Label
virtual bool AvailableTo(PlayerCharacter player) Servidor. False oculta a opção deste jogador, mesmo com Show When Locked. true
virtual KitModule Module O módulo do kit a que pertence. Quando esse módulo está desligado em KitARPG > Modules, a opção desaparece. KitModule.None
abstract string Run(Npc npc, PlayerCharacter player) Servidor. Executa a opção. Retorna um código de erro para o jogador, ou null. Obrigatório.

#Auxiliares que você pode chamar

Membro O que retorna
string Label Label ou DefaultLabel.
string Locked(PlayerCharacter player) Por que o jogador não pode escolhê-la (nível, depois condições), ou null.
bool Offered(PlayerCharacter player) Módulo ligado, não bloqueada e AvailableTo.
bool Listed(PlayerCharacter player) Se o jogador a vê, podendo escolhê-la ou não.

#O que o servidor verifica antes de Run

O cliente do dono pede por meio de PlayerInteraction. Antes de o seu Run ser chamado, o servidor já:

  1. Confirmou que o jogador está vivo, carregado e falando com aquele NPC.
  2. Gastou do orçamento de pedidos por jogador (Max Requests Per Second, maxRequestsPerSecond, 10 em PlayerInteraction).
  3. Verificou que o jogador está dentro do Talk Range do NPC (talkRange, 3 m, mais meio metro). Longe demais responde too_far.
  4. Encontrou a opção pelo seu índice na lista mostrada na tela e verificou Offered(player): módulo, nível, condições e AvailableTo.

Então, dentro de Run, você sabe que o jogador está ao lado do NPC e tem permissão para escolher a opção. Qualquer custo ou requisito da sua opção além disso, verifique de novo em Run.

#Respondendo ao jogador

Run retorna uma string que é enviada ao cliente do dono como PlayerInteraction.ErrorReceived. Das janelas do kit, só a janela da loja mostra essas strings, enquanto está aberta, e ela transforma os códigos conhecidos (NpcErrors.NotEnoughMoney, NpcErrors.TooFar e os erros do inventário) em frases.

Para uma opção de diálogo comum, avise o jogador você mesmo e retorne null:

player.ServerAnnounce("Blessed!", new Color(1f, 0.85f, 0.4f));    // floating text over the player
if (player.TryGetComponent(out PlayerChat chat)) chat.Tell("The priest blesses you."); // a system line in the chat
return null;

DialogueOption faz o mesmo com os motivos de recusa das suas ações. A opção do exemplo de recompensas usa PlayerChat.Tell.

#Exemplo: o template

Create > KitARPG > Scripts > NPC Option cria uma bênção que cura em troca de ouro, e avisa o jogador no chat quando ele não pode pagar. Veja Templates.

#Exemplo: bênção, respondida no chat

O template com um rótulo que mostra o preço, um estado de bênção em vez de uma cura completa e uma linha no chat depois da bênção:

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class BlessingOption : NpcOption
    {
        public long price = 50;
        public StatusData blessing;
        public float seconds = 300;

        protected override string DefaultLabel => "Bless me";

        public override string LabelFor(PlayerCharacter player) =>
            $"{Label} ({price:N0} {GameInstance.Database.GoldName})";

        public override bool AvailableTo(PlayerCharacter player) => blessing != null;

        public override string Run(Npc npc, PlayerCharacter player)
        {
            var inventory = player.GetComponent<PlayerInventory>();
            if (inventory.gold < price)
            {
                Tell(player, $"That costs {price:N0} {GameInstance.Database.GoldName}.");
                return null;
            }
            inventory.AddGold(-price);
            player.AddStatus(blessing, 1, seconds);
            GameLog.Write("mygame.blessing", player, gold: price, detail: npc.Id);
            Tell(player, $"{npc.displayName} blesses you.");
            return null;
        }

        static void Tell(PlayerCharacter player, string text)
        {
            if (player.TryGetComponent(out PlayerChat chat)) chat.Tell(text);
        }
    }
}

PlayerCharacter.AddStatus é o método de IItemUser; o jogador o implementa.

#Exemplo: uma opção que abre uma janela sua

As opções rodam no servidor, então, para abrir uma janela no cliente, a opção envia uma mensagem ao dono. Esta abre uma janela de "baú" e informa à janela de qual NPC ela veio.

using System;
using Blunnyn.KitARPG.Net;
using Mirror;
using UnityEngine;

namespace Game
{
    public struct OpenStashMessage : NetworkMessage
    {
        public string npcId;
    }

    [Serializable]
    public class StashOption : NpcOption
    {
        protected override string DefaultLabel => "Open the stash";

        public override string Run(Npc npc, PlayerCharacter player)
        {
            player.connectionToClient?.Send(new OpenStashMessage { npcId = npc.Id });
            return null;
        }
    }

    public static class StashClient
    {
        public static event Action<Npc> Opened;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void ResetStatics() => Opened = null;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Hook()
        {
            KitNetworkManager manager = KitNetworkManager.Instance;
            if (manager == null) return;
            manager.ClientConnected += () => NetworkClient.ReplaceHandler<OpenStashMessage>(OnOpen);
        }

        static void OnOpen(OpenStashMessage message)
        {
            if (Npc.TryFind(message.npcId, out Npc npc)) Opened?.Invoke(npc);
        }
    }
}

Sua janela se inscreve em StashClient.Opened, abre e se fecha sozinha quando o jogador sai de npc.InReach(PlayerCharacter.Local.transform.position). Todo pedido que a janela envia de volta precisa verificar de novo no servidor que o jogador está perto daquele NPC (npc.InReach(player.transform.position)). Veja Mensagens de rede.

#Exemplo: um rótulo que muda por jogador

A opção do exemplo de recompensas diz "Today's bounty" ou "Turn in the bounty", dependendo do jogador:

public override string LabelFor(PlayerCharacter player) =>
    Bounties.Current(player.Facts, out _) != null ? "Turn in the bounty" : "Today's bounty";

#Exemplo: pertencer a um módulo

Uma opção que pertence a um dos módulos do kit desaparece quando esse módulo está desligado:

public override KitModule Module => KitModule.Guilds;

#Estado em uma opção

Uma instância de opção vive em um NPC em uma cena, e todos os jogadores que falam com aquele NPC a compartilham. Use campos de instância só para estado do NPC, nunca de um jogador. Marque os campos que só existem em tempo de execução com [NonSerialized] para que não acabem salvos na cena. O ShopOption do kit guarda assim seu estoque limitado por NPC:

[NonSerialized] int[] left;

Para estado por jogador, use flags, PlayerData ou um sistema do jogador (veja Salvando dados).

#Adicionando a opção a um NPC

  1. Selecione o NPC na cena dele (um GameObject com o componente Npc).
  2. Em Options, pressione + e escolha sua classe no menu.
  3. Preencha os campos dela, seu Label, Required Level e Conditions.
  4. Dentro de uma opção Dialogue, a lista aninhada Options também aceita sua classe, então ela pode aparecer depois de uma fala.

Opções com Label vazio usam seu DefaultLabel. Quando um NPC não tem saudação e tem só uma opção, falar com ele executa essa opção na hora.

#Servidor e cliente

Roda em
LabelFor, AvailableTo, Locked, Offered, Run Servidor
Rótulos e motivos de bloqueio Enviados como texto ao cliente
O componente Npc Ambos: os clientes o usam para nome, posição e alcance

No modo um jogador, o host roda a metade do servidor no mesmo processo.

#Erros comuns

  • Retornar uma frase de Run e esperar que o diálogo a mostre. Use ServerAnnounce ou PlayerChat.Tell.
  • Confiar na janela que vem depois. Uma janela aberta por uma opção envia seus próprios pedidos; cada um precisa verificar alcance e regras de novo.
  • Guardar dados por jogador na opção. Ela é compartilhada por todos que falam com aquele NPC.
  • Mudar a ordem das opções enquanto um jogador está conversando. O cliente escolhe pelo índice; reordene no editor, não em tempo de execução.
