Eventos

Todos os eventos que o kit dispara e que o seu código pode escutar, onde rodam, o que entregam, como se inscrever para que sobrevivam ao Play sem domain reload, e exemplos.

#Eventos estáticos

A maioria dos eventos do kit é static: você se inscreve uma vez, para todos os jogadores ou monstros, a partir de uma classe estática sua. Eles são de três tipos:

  • Eventos do servidor começam com Server e rodam no servidor de mapa (e no host em um jogador). Use-os para regras: recompensas, progresso, registro.
  • Eventos do cliente do dono rodam no cliente do jogador em questão. Use-os para a interface.
  • Eventos do cliente rodam em todo cliente que vê aquilo, como os efeitos de combate.

#Inscrevendo-se do jeito certo

O projeto do kit roda o Play sem domain reload, então toda classe limpa os seus eventos estáticos em um método SubsystemRegistration no início de cada Play. O Unity não define a ordem entre métodos SubsystemRegistration, então inscreva-se depois, em AfterAssembliesLoaded:

public static class LevelRewards
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
    static void Hook()
    {
        PlayerCharacter.ServerLeveledUp -= OnLevel;
        PlayerCharacter.ServerLeveledUp += OnLevel;
    }

    static void OnLevel(PlayerCharacter player) { /* ... */ }
}

O -= antes do += evita que você se inscreva duas vezes se o método rodar de novo. Inscreva-se com métodos nomeados, não com lambdas, para que o -= funcione. AfterSceneLoad também funciona; ele roda depois.

Veja Play sem domain reload para as regras completas.

PlayerTrade.ServerTraded PlayerCharacter a, PlayerCharacter b Uma troca foi concluída.
PlayerForge.ServerUpgraded PlayerCharacter, string itemId, bool success, int level Um aprimoramento deu certo (true) ou falhou (false); level é onde terminou, -1 quando a peça quebrou.

PlayerGuild.AllianceInvited string alliance, string guild Um convite de aliança.

#Eventos do cliente para efeitos

CombatEvents (namespace Blunnyn.KitARPG.Net) conta a todo cliente o que aconteceu em combate por perto, para animações, efeitos, números de dano e sons:

Evento Argumentos
CombatEvents.Damaged Transform who, int amount, bool critical, DamageElement element, GameData source
CombatEvents.Healed Transform who, int amount, GameData cause
CombatEvents.Announced Transform who, string text, Color color (texto curto sobre alguém, como "+12 XP")
CombatEvents.Shouted Transform boss, string text (uma fala de fase de chefe)
CombatEvents.SkillLanded Transform caster, SkillData skill, Vector3 point
CombatEvents.ActionStarted ActionEvent
CombatEvents.CastStarted, CastStopped Transform, SkillData, float seconds; Transform
CombatEvents.Bounced SkillData, Transform from, Transform to
CombatEvents.ZoneStarted SkillData, Vector3 where, float seconds
FighterStatus.AnyChanged FighterStatus (os estados de qualquer lutador mudaram)

Outros eventos gerais do cliente: GameRates.Changed (RatesState, um evento de experiência ou de saque começou ou terminou), ClientOptions.Changed (uma configuração mudou).

Eventos do cliente por objeto: Monster.Acted (CombatAction) e DeadChanged (bool) nos monstros, DeadChanged nos jogadores.

#Eventos do network manager

KitNetworkManager.Instance dispara ServerStarted, ServerStopping, ServerDisconnecting (NetworkConnectionToClient), ClientConnected e ClientDisconnected. São eventos de instância em um objeto que é criado de novo a cada Play, e o objeto antigo some com seus inscritos, então inscreva-se em AfterSceneLoad sem -=. Eventos estáticos continuam com -= primeiro: inscreva-se neles antes de verificar se Instance é null, para que fiquem inscritos mesmo numa cena sem network manager. Veja Mensagens de rede.

#Exemplos

#Recompensar a cada cinco níveis

Servidor, no assembly Game:

using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    public static class MilestoneRewards
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
        static void Hook()
        {
            PlayerCharacter.ServerLeveledUp -= OnLevel;
            PlayerCharacter.ServerLeveledUp += OnLevel;
        }

        static void OnLevel(PlayerCharacter player)
        {
            if (player.level % 5 != 0) return;
            // A flag per milestone, so leveling down and up again (death penalties) pays once.
            string key = $"mygame.milestone_{player.level}";
            IPlayerActor actor = player.Facts;
            if (actor.Flag(key) != 0) return;
            actor.SetFlag(key, 1);
            actor.AddCurrency(null, player.level * 100);
            player.ServerAnnounce($"Level {player.level} milestone!", new Color(1f, 0.85f, 0.3f));
        }
    }
}

#Mensagem de boas-vindas

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
static void Hook()
{
    PlayerCharacter.ServerSpawned -= OnSpawned;
    PlayerCharacter.ServerSpawned += OnSpawned;
}

static void OnSpawned(PlayerCharacter player)
{
    if (player.TryGetComponent(out PlayerChat chat)) chat.Tell($"Welcome back, {player.characterName}.");
}

ServerSpawned dispara em cada mapa em que um personagem entra, não só ao fazer login.

#Sequências de abates, guardadas na memória

static readonly Dictionary<PlayerCharacter, int> streaks = new Dictionary<PlayerCharacter, int>();

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
static void ResetStatics() => streaks.Clear();

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
static void Hook()
{
    Monster.ServerKilled -= OnKilled;
    Monster.ServerKilled += OnKilled;
    PlayerPvp.ServerDefeated -= OnDefeated;
    PlayerPvp.ServerDefeated += OnDefeated;
}

static void OnKilled(Monster monster, PlayerCharacter killer)
{
    if (killer == null) return;
    streaks.TryGetValue(killer, out int n);
    streaks[killer] = ++n;
    if (n % 10 == 0) killer.ServerAnnounce($"{n} kills!", Color.yellow);
}

static void OnDefeated(PlayerCharacter killer, PlayerCharacter victim, bool duel) => streaks.Remove(victim);

Dicionários com jogadores como chave crescem conforme os jogadores entram e saem. Remova as entradas quando eles saem (KitNetworkManager.ServerDisconnecting) ou ignore os destruídos (player == null).

#Um som nos acertos críticos

Cliente, no assembly Game. O clipe é carregado de uma pasta Resources sua:

static AudioClip clip;

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
static void Hook()
{
    clip = Resources.Load<AudioClip>("MyGame/CriticalHit");
    CombatEvents.Damaged -= OnDamaged;
    CombatEvents.Damaged += OnDamaged;
}

static void OnDamaged(Transform who, int amount, bool critical, DamageElement element, GameData source)
{
    if (critical && clip != null) GameAudio.PlayAt(clip, who.position, SoundChannel.Effects);
}

GameAudio.PlayAt respeita os controles de volume do jogador.

#Enviar saques raros para um webhook

GameLog.Written vê todas as linhas do registro, incluindo item.loot para drops notáveis. Veja o template Game Log Listener em Templates.

#Eventos seus

Dispare os seus próprios eventos estáticos do mesmo jeito e limpe-os em SubsystemRegistration:

public static event Action<PlayerCharacter, MonsterData> ServerTurnedIn;

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
static void ResetStatics() => ServerTurnedIn = null;

O código em Game.Server então se inscreve em eventos disparados em Game (veja Assemblies).

#Erros comuns

  • Inscrever-se em SubsystemRegistration. O kit pode limpar o evento depois que você se inscreveu.
  • Inscrever-se com uma lambda que você não consegue remover, em um método que pode rodar duas vezes.
  • Eventos do servidor em código do cliente. Eles nunca disparam em um cliente online.
  • Trabalho pesado em CombatEvents ou GameLog.Written. Eles disparam com frequência; mantenha os handlers curtos.
  • Lançar exceção em um handler. Outros inscritos depois de você podem não rodar. GameLog.Written captura exceções; a maioria dos outros eventos, não.
