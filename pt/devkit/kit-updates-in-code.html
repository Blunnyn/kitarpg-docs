Atualizações do kit em código

Como entregar mudanças para jogos que já foram feitos com o seu pacote ou template: a classe KitUpdate, como o Overview encontra e aplica atualizações e exemplos completos que adicionam um componente a todo prefab de jogador e uma configuração ao jogo.

#O que é uma atualização do kit

Quando uma nova versão do KitARPG adiciona algo de que um jogo precisa (uma moeda, um componente no jogador, uma janela no HUD), ela não pode reconstruir os prefabs e os dados do comprador: isso apagaria as mudanças dele. Em vez disso, ela traz uma atualização: uma classe pequena que verifica se aquilo está faltando e, quando pedido, adiciona só isso.

Você pode fazer o mesmo. Se você vende ou reutiliza um pacote feito sobre o KitARPG (um jogo template, um módulo que você compartilha entre seus projetos), cada versão sua pode trazer atualizações para os jogos já feitos com ele. Elas aparecem na mesma lista das atualizações do próprio kit.

Onde o arquivo fica: em um assembly Game.Editor (ou no assembly de editor do seu pacote).

#Onde as atualizações aparecem

  • Overview na janela KitARPG mostra quantas atualizações estão esperando, com Apply.
  • Project Check lista cada uma como um aviso com um botão Apply.
  • Play & Servers e a página Shop avisam quando há atualizações esperando.

Apply abre um diálogo que lista toda atualização pendente com seu Title e suas Changes, seguido de "Nothing else changes". Depois de confirmar, cada atualização que ainda é necessária roda na ordem de Order. Atualizações não podem ser aplicadas durante o Play.

#A classe KitUpdate

KitUpdate fica em Blunnyn.KitARPG.Editor. Toda subclasse não abstrata com um construtor sem parâmetros é encontrada pelo TypeCache da Unity.

Membro O que faz Padrão
abstract string Title Uma linha, como "Shop window in the HUD".
abstract string Changes Exatamente o que Apply vai mudar, mostrado antes de rodar. Nomeie os assets e os campos.
abstract bool Needed() True quando o projeto não tem aquilo. Chamado a cada poucos segundos pelas janelas (a resposta fica em cache por cerca de dois segundos), então mantenha-o barato.
abstract string Apply() Faz a mudança e retorna o que fez. Lance uma exceção para informar que não conseguiu.
virtual int Order Menor roda primeiro, para atualizações que dependem de outra. O kit usa de 10 a 80. 100

KitUpdates as executa:

Membro O que faz
KitUpdates.All Todas as atualizações, em ordem.
KitUpdates.Pending() As atualizações cujo Needed() é true agora.
KitUpdates.Run(update, out string result) Roda uma, salva os assets e registra o resultado no log. False quando lançou uma exceção.
KitUpdates.ApplyAll(updates) Pergunta uma vez com a lista e depois roda as que ainda são necessárias.

Uma exceção em Needed() é registrada como aviso e a atualização é tratada como não necessária.

#Regras para uma boa atualização

  • Adicione só o que falta. Verifique a coisa exata (um componente, o valor de um campo, um asset) e adicione só isso.
  • Nunca reconstrua. Não recrie um prefab, um HUD ou um asset de dados; carregue-o, mude uma coisa e salve.
  • Encontre as coisas do jeito que o jogo as tem. Os compradores renomeiam e movem assets. Procure-os por meio do GameInstance e do game database (ModulesWindow.Find()), não pelo caminho.
  • Seja idempotente. Depois de Apply, Needed() precisa retornar false. Rodar duas vezes não pode mudar nada na segunda vez.
  • Diga o que mudou. Changes antes, a string retornada depois.

#Exemplo: o template

Create > KitARPG > Scripts > Kit Update (Editor) adiciona uma palavra ao filtro do chat:

using System.Linq;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Editor;
using UnityEditor;

namespace Game
{
    /// <summary>
    /// Something your own package adds to games already made with it. It shows in Overview with Apply
    /// next to the kit's updates. Only add what is missing; never rebuild what the game changed.
    /// </summary>
    public class MyGameUpdate : KitUpdate
    {
        const string Word = "badword";

        public override string Title => "My game: chat filter word";
        public override string Changes => $"Game Settings > Chat: adds \"{Word}\" to the blocked words.";

        public override bool Needed()
        {
            GameInstance game = ModulesWindow.Find();
            return game != null && !game.blockedWords.Contains(Word);
        }

        public override string Apply()
        {
            GameInstance game = ModulesWindow.Find();
            game.blockedWords = game.blockedWords.Append(Word).ToArray();
            EditorUtility.SetDirty(game);
            AssetDatabase.SaveAssets();
            return $"Added \"{Word}\" to the blocked words.";
        }
    }
}

#Exemplo: adicionar um sistema do jogador a todo modelo de jogador

Um componente seu (veja Sistemas do jogador) precisa estar em todo prefab de modelo de jogador, incluindo modelos que o comprador fizer depois. Esta atualização encontra os modelos pelo game database e adiciona o componente onde ele falta:

using System.Collections.Generic;
using System.Linq;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Editor;
using UnityEditor;
using UnityEngine;

namespace Game
{
    public class AddReputationUpdate : KitUpdate
    {
        public override string Title => "Reputation on every player model";

        public override string Changes =>
            "Adds the Player Reputation component to each player model prefab that doesn't have it: "
            + string.Join(", ", Missing().Select(m => m.name)) + ". Nothing else on the prefabs changes.";

        public override int Order => 200;

        static IEnumerable<GameObject> Missing()
        {
            GameInstance game = ModulesWindow.Find();
            if (game == null || game.database == null) return Enumerable.Empty<GameObject>();
            return game.database.playerModels.Where(m => m != null && m.GetComponent<PlayerReputation>() == null);
        }

        public override bool Needed() => Missing().Any();

        public override string Apply()
        {
            var done = new List<string>();
            foreach (GameObject model in Missing().ToList())
            {
                string path = AssetDatabase.GetAssetPath(model);
                GameObject root = PrefabUtility.LoadPrefabContents(path);
                try
                {
                    if (root.GetComponent<PlayerReputation>() == null) root.AddComponent<PlayerReputation>();
                    PrefabUtility.SaveAsPrefabAsset(root, path);
                    done.Add(model.name);
                }
                finally { PrefabUtility.UnloadPrefabContents(root); }
            }
            return done.Count == 0 ? "Every model already had it." : "Added to " + string.Join(", ", done) + ".";
        }
    }
}

LoadPrefabContents e SaveAsPrefabAsset editam o próprio asset do prefab, do mesmo jeito que as atualizações do kit fazem. Como o Mirror precisa dos mesmos componentes no cliente e no servidor, refaça os dois builds depois de aplicar.

#Exemplo: adicionar uma janela no HUD

As atualizações do kit que adicionam janelas ao HUD carregam o prefab do HUD de GameInstance.hudPrefab, encontram o grupo a que pertencem, adicionam seu objeto e salvam. A mesma estrutura para uma janela sua:

using System.Linq;
using Blunnyn.KitARPG.Editor;
using UnityEditor;
using UnityEngine;

public class AddReputationWindowUpdate : KitUpdate
{
    public override string Title => "Reputation window in the HUD";

    public override string Changes => "Adds a Reputation Window object under Windows in the HUD prefab.";

    static GameObject Hud => ModulesWindow.Find()?.hudPrefab;

    public override bool Needed()
    {
        GameObject hud = Hud;
        return hud != null && hud.GetComponentInChildren<ReputationWindow>(true) == null;
    }

    public override string Apply()
    {
        GameObject hud = Hud ?? throw new System.InvalidOperationException("The GameInstance has no HUD prefab.");
        string path = AssetDatabase.GetAssetPath(hud);
        GameObject root = PrefabUtility.LoadPrefabContents(path);
        try
        {
            if (root.GetComponentInChildren<ReputationWindow>(true) != null) return "The HUD already had it.";
            Transform windows = root.GetComponentsInChildren<Transform>(true).FirstOrDefault(t => t.name == "Windows") ?? root.transform;
            var go = new GameObject("Reputation Window", typeof(RectTransform));
            go.transform.SetParent(windows, false);
            go.AddComponent<ReputationWindow>();
            PrefabUtility.SaveAsPrefabAsset(root, path);
            return $"Added the window to {hud.name}.";
        }
        finally { PrefabUtility.UnloadPrefabContents(root); }
    }
}

(ReputationWindow representa um componente de janela seu.) Procure os grupos do HUD pelo nome com uma alternativa, já que os compradores podem reorganizar o HUD. A estrutura do HUD está descrita em HUD e janelas.

#Exemplo: adicionar um asset de dados do jogo

Algumas atualizações adicionam conteúdo: uma moeda, um item de que o novo recurso precisa. Crie o asset ao lado do game database do jogo e liste-o lá:

using System.Linq;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Editor;
using UnityEditor;
using UnityEngine;

public class AddTokenCurrencyUpdate : KitUpdate
{
    public override string Title => "Arena Token currency";
    public override string Changes => "Creates the Arena Token currency next to the game database and lists it under Currencies.";

    static GameDatabase Database => ModulesWindow.Find()?.database;

    public override bool Needed()
    {
        GameDatabase db = Database;
        return db != null && !db.TryGet("arena_token", out CurrencyData _);
    }

    public override string Apply()
    {
        GameDatabase db = Database ?? throw new System.InvalidOperationException("No game database.");
        string folder = System.IO.Path.GetDirectoryName(AssetDatabase.GetAssetPath(db));
        var token = ScriptableObject.CreateInstance<CurrencyData>();
        token.name = "Arena Token";
        AssetDatabase.CreateAsset(token, AssetDatabase.GenerateUniqueAssetPath($"{folder}/Arena Token.asset"));
        // GameData ids are made from the name when empty.
        var so = new SerializedObject(token);
        so.FindProperty("id").stringValue = "arena_token";
        so.ApplyModifiedPropertiesWithoutUndo();
        db.currencies = db.currencies.Append(token).ToArray();
        EditorUtility.SetDirty(db);
        return "Created Arena Token and added it to the database.";
    }
}

O id é definido por meio de SerializedObject porque GameData.id é um campo serializado privado. Escolha o id uma vez só; os salvamentos o guardam.

#Atualizações e Start over

As atualizações são para jogos que mantêm seu conteúdo. Start over no Overview, em vez disso, monta a amostra inicial do zero, perdendo as mudanças feitas na amostra. Suas atualizações também devem funcionar em uma amostra nova: depois de Start over, Needed() decide de novo.

#Erros comuns

  • Needed() que carrega todo prefab do projeto. Ele roda a cada poucos segundos. Passe pelas listas do database.
  • Reconstruir em vez de adicionar. As mudanças do comprador se perdem.
  • Caminhos para assets. Os compradores os movem e renomeiam.
  • Needed() ainda true depois de Apply. A atualização aparece para sempre.
  • Código de editor em um assembly de runtime. As atualizações ficam em um assembly de editor.
