Comandos de GM em código

Como adicionar seus próprios comandos de barra: registrar um GmCommand, ler argumentos com GmContext, escolher um nível, como funciona a auditoria e exemplos completos.

#O que é um comando

Os jogadores digitam comandos no chat, começando com /. O chat envia a linha ao servidor de mapa, que procura o comando, compara o nível do jogador com o nível do comando, executa e mostra a resposta como uma linha de sistema no chat. O painel de GM (F8 ou /gm) executa os mesmos comandos. Os comandos do próprio kit estão listados em Comandos de GM.

Os comandos são registrados por código com GmCommands.Register. GmCommands fica em KitARPG.Server (namespace Blunnyn.KitARPG.Server), que os clientes online nunca levam.

Onde fica o arquivo: no assembly Game.Server (veja Assemblies). Assim os comandos existem nos servidores de mapa, no modo um jogador e no editor, e nunca em um build de cliente online.

#Registrar um comando

using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Server;
using UnityEngine;

namespace Game
{
    public static class MyCommands
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Register()
        {
            GmCommands.Register(new GmCommand
            {
                name = "refresh",
                aliases = new[] { "fill" },
                rank = GmRank.Moderator,
                usage = "refresh [player]",
                description = "Fills a player's health.",
                run = c =>
                {
                    PlayerCharacter target = c.Target(0);
                    if (target == null) return "Nobody by that name here.";
                    target.ServerHeal(target.maxHealth, null);
                    return $"Healed {target.characterName}.";
                },
            });
        }
    }
}

O kit limpa e registra os próprios comandos em SubsystemRegistration a cada Play, então registre os seus em AfterSceneLoad (ou AfterAssembliesLoaded). Registrar um nome que já existe substitui o comando antigo, incluindo os do kit. É assim que você altera um comando do kit; também é assim que você quebra um sem querer, então escolha nomes próprios.

#Campos de GmCommand

Campo O que é Padrão
name O que os jogadores digitam depois de /.
aliases Outros nomes para o mesmo comando. nenhum
rank O nível que ele pede por padrão (veja abaixo). GmRank.Admin
usage Mostrado por /help, como "item id [amount] [player]".
description Uma linha para /help.
run Func<GmContext, string>: executa a ação e devolve a resposta a mostrar, ou null para nenhuma.

#Níveis

GmRank Valor Significado
Player 1 Qualquer um.
Moderator 2 Moderação do chat e dos jogadores.
GameMaster 3 Mudanças no jogo: itens, teleportes, monstros.
Admin 4 Tudo, incluindo os papéis.

O nível que um comando pede é GmCommands.LevelOf(command): o nível definido para o nome dele em Game Settings > GM commands (GameInstance.gmCommandLevels) quando existe, senão o seu rank. Os designers podem subir ou descer qualquer comando, incluindo os seus, sem código. /role sempre pede Admin.

O nível de um jogador é GmCommands.RankOf(player): o papel da conta no banco de dados (accounts.Role), ou GmCommands.EveryoneRank se este for maior. No modo um jogador, Single Player Commands (singlePlayerCommands, ligado por padrão) torna EveryoneRank Admin, então todo comando funciona como trapaça. Online ele é Player.

Um jogador abaixo do nível do comando recebe "Unknown command", como se ele não existisse.

#GmContext

O que run recebe:

Membro O que é
PlayerCharacter player Quem digitou.
string[] args As palavras depois do nome, separadas por espaços.
string rest Tudo depois do nome, como foi digitado. Use para texto livre.
int level O nível que este comando pede. Passe-o para o Central nos comandos que o Central verifica de novo.
string Arg(int i) A palavra i, ou null.
int Int(int i, int fallback) A palavra i como inteiro, ou fallback.
long Long(int i, long fallback) O mesmo, como long.
float Float(int i, float fallback) O mesmo, como float. Recusa NaN e infinito.
PlayerCharacter Target(int i) O jogador nomeado pela palavra i neste mapa, ou quem digitou quando a palavra falta. Null quando o nome não está neste mapa.
T Data<T>(int i) O dado de jogo do tipo T cujo id é a palavra i, ou null.

Os números são lidos com a cultura invariante, então 1.5 funciona em qualquer máquina.

#Auditoria

Todo comando com nível acima de Player (2 ou mais) é trabalho da equipe e fica registrado:

  • Cada uso, permitido ou recusado pelo nível, vai para a auditoria de GM (tabela gm_audit online, o save no modo um jogador) com a conta, o personagem, o nível, o comando, a linha, o alvo e o resultado.
  • Cada uso que foi executado também escreve uma linha no registro do jogo do tipo gm.command com a resposta.
  • Quando a auditoria não pode ser registrada (Central inalcançável), os comandos da equipe ficam pausados e respondem "GM commands are paused". Nada de nível de equipe roda sem o seu registro.

Os comandos de nível Player não são auditados.

GmCommands.ServerUsed (PlayerCharacter, string line) é disparado para todo comando executado, antes de ele rodar. GmAudit.Recorded (GmAuditEntry) é disparado para cada linha da auditoria. Veja Eventos.

#Limites

GmCommands tem tetos que os comandos do kit respeitam, para que um erro de digitação ou uma conta da equipe roubada não inunde a economia. Respeite-os nos seus comandos que distribuem coisas:

Campo Padrão
MaxItems 9.999
MaxGold 1.000.000.000
MaxExperience 1.000.000.000
MaxPoints 1.000
MaxStatusSeconds 3.600
MaxKillRange 100
MaxMuteMinutes 525.600

São campos estáticos, reiniciados a cada Play. Altere-os no seu próprio método AfterSceneLoad se o seu jogo precisar de outros limites.

#Exemplos

#Dar pontos de atributo, com teto

GmCommands.Register(new GmCommand
{
    name = "points", rank = GmRank.GameMaster, usage = "points amount [player]", description = "Gives attribute points.",
    run = c =>
    {
        int amount = c.Int(0, 0);
        if (amount <= 0) return "Usage: /points amount [player]";
        amount = Mathf.Min(amount, GmCommands.MaxPoints);
        PlayerCharacter target = c.Target(1);
        if (target == null) return "Nobody by that name here.";
        target.GainPoints(amount, 0);
        return $"{target.characterName} got {amount} attribute points.";
    },
});

#Buscar dados de jogo por id

Data<T> encontra dados de jogo pelo id:

GmCommands.Register(new GmCommand
{
    name = "where", rank = GmRank.Player, usage = "where monster_id", description = "Maps where a monster lives.",
    run = c =>
    {
        MonsterData monster = c.Data<MonsterData>(0);
        if (monster == null) return "No monster with that id.";
        var maps = new System.Collections.Generic.List<string>();
        foreach (MapData map in GameInstance.Database.maps)
            if (map != null && System.Array.IndexOf(map.monsters, monster) >= 0) maps.Add(map.DisplayName);
        return maps.Count == 0 ? $"{monster.DisplayName} lives nowhere listed." : $"{monster.DisplayName}: {string.Join(", ", maps)}";
    },
});

#Um comando para jogadores

Comandos de nível Player são um jeito rápido de adicionar recursos ao chat. O /hunters do exemplo de recompensas pede um ranking ao Central:

GmCommands.Register(new GmCommand
{
    name = "hunters", rank = GmRank.Player, usage = "hunters", description = "The best bounty hunters on every map, and your last hunts.",
    run = c =>
    {
        string mine = Last(c.player);
        if (!CentralMessages.Online) return "The hunters board is kept online." + mine;
        CentralMessages.Send(new BountyBoardAsk { characterId = c.player.State.id });
        return "Asking the guild of hunters..." + mine;
    },
});

A resposta do Central chega depois e é mostrada com SocialHub.Notice. Veja Conversar com o Central.

#Texto livre

rest mantém os espaços:

GmCommands.Register(new GmCommand
{
    name = "notice", rank = GmRank.Moderator, usage = "notice text", description = "Sets the notice board.",
    run = c => string.IsNullOrWhiteSpace(c.rest) ? "Usage: /notice text" : SetNotice(c.rest),
});

Limpe qualquer texto que outros jogadores vão ver com PlayerText.Clean(text, maxLength).

#/help

/help lista os comandos do chat e depois todo comando que o nível do jogador permite, incluindo os de nível Player, cada um com o uso e a descrição. Os comandos acima do nível Player terminam com o nível entre colchetes, como [3]; os de nível Player aparecem sem ele.

#Erros

Uma exceção dentro de run é capturada: ela é registrada no log do servidor e o jogador vê "/name failed: message". Devolva uma frase em vez de lançar uma exceção para qualquer coisa que o jogador tenha feito errado.

#Servidor e cliente

Os comandos rodam só no servidor de mapa (ou no host do modo um jogador). O cliente envia a linha digitada; a linha é cortada em 300 caracteres e tem o mesmo ritmo do chat. Nada no seu run pode ser alcançado por um cliente a não ser por essa linha, e a verificação de nível acontece antes de ele rodar.

#Erros comuns

  • Colocar comandos no assembly Game. Ele não enxerga KitARPG.Server, e se enxergasse, os clientes levariam o código do comando.
  • Registrar em SubsystemRegistration. O kit limpa a lista ali; a ordem entre esses métodos é indefinida.
  • Reusar o nome de um comando do kit. O seu substitui o dele.
  • Quantidades sem teto. Use os campos Max....
  • Agir sobre um nome sem Target. Target só encontra jogadores neste mapa; para jogadores em outro lugar, passe pelo Central.
