Efeitos de habilidades

Como escrever os seus próprios efeitos de habilidade: a classe base SkillEffect, o que um lançamento entrega a você, como os alvos são escolhidos e exemplos completos que seguem as regras de dano do jogo.

#O que é um efeito de habilidade

Uma habilidade é um alvo, uma área e uma lista de efeitos (SkillData.effects). Quando a habilidade acerta, o servidor calcula quem ela alcançou e chama cada efeito uma vez por alvo. O kit traz efeitos de dano, cura, buffs de stats, estados, purificar e dissipar, empurrão, reviver e invocações. Qualquer outra coisa que uma habilidade deva fazer é uma nova classe de efeito.

Os efeitos são classes [Serializable] guardadas por referência ([SerializeReference, PickType]). Assim que a sua classe compila, ela aparece no menu de tipos + da lista Effects de toda habilidade em KitARPG > Game Database > Skills. Não há nada para registrar.

Onde fica o arquivo: no assembly Game. Os efeitos são dados que os dois builds carregam (o cliente os mostra nas dicas), embora só o servidor os aplique.

#A classe base

SkillEffect fica em Blunnyn.KitARPG.Data.

Membro O que faz Padrão
string Summary Texto curto mostrado na lista de efeitos do editor de habilidades e usado como linha padrão da dica. O nome da classe
bool Harmful true: o efeito cai nos inimigos que a habilidade alcança. false: no lançador e nos aliados que ela alcança. false
bool OnCaster true: o efeito roda uma vez por lançamento com o lançador como alvo, seja quem for que a habilidade alcance. Usado pelas invocações. false
void Apply(SkillCast cast, IFighter target) Só no servidor. Chamado uma vez por alvo. Obrigatório.
void Describe(ItemDescription description, int level, DamageElement fallback) Linhas para o cartão da habilidade em um rank. Roda no cliente. fallback é o elemento a nomear quando o seu está vazio. Adiciona Summary
void Visit(Action<GameData> visit) Entrega ao banco de dados do jogo todo asset para o qual o efeito aponta, para que sejam registrados. Nada

#Como os alvos são escolhidos

O SkillRunner do servidor reúne inimigos e aliados na área da habilidade e depois, para cada efeito em ordem:

  • Efeitos OnCaster rodam uma vez com target igual ao lançador.
  • Efeitos Harmful rodam em todo inimigo alcançado; os outros rodam em todo aliado alcançado (o lançador conta como aliado quando a área o inclui).
  • Em habilidades com Targets Dead marcado, só lutadores mortos são alcançados; caso contrário, só os vivos.

Uma habilidade pode acertar várias vezes em um lançamento:

  • Animações de vários golpes dividem um lançamento em vários momentos de golpe. Cada acerto leva uma fração do dano em cast.scale, e só o primeiro tem cast.firstHit verdadeiro.
  • Zonas deixadas no chão acertam de novo a cada tick, e cada tick é um lançamento novo com firstHit verdadeiro.
  • Linhas perfurantes acertam cada alvo à medida que o projétil passa.
  • Ricochetes pulam para o próximo alvo com cast.scale reduzido pelo Bounce Keep da habilidade.

Daí saem duas regras. Escale o dano e a cura por cast.scale. Coloque buffs, estados e outros efeitos de uma vez só atrás de if (!cast.firstHit) return; para que sejam aplicados uma vez por lançamento.

#O que um lançamento entrega a você

SkillCast:

Campo O que é
IFighter caster Quem lançou: um jogador ou um monstro.
SkillData skill A habilidade.
int level O rank em que foi lançada, com os bônus de equipamento. Use com LevelValue.At(level).
IReadOnlyList<ElementDamage> weapon Rolagens da arma do lançador, para efeitos que escalam com ela. Pode estar vazio ou ser null.
IFighter target O alvo mirado, se a habilidade tiver um.
Vector3 point Para onde foi mirada: a posição do alvo ou um ponto no chão.
float scale Fração do dano e da cura que este acerto leva. 1 para um acerto único.
bool firstHit Falso nos acertos seguintes de um mesmo lançamento.
float projectileSpeed Metros por segundo do projétil da habilidade, 0 se não houver.
SkillCast Copy() Uma cópia, para efeitos que acertam mais tarde.

IFighter é qualquer coisa que uma habilidade pode tocar, no servidor:

Membro O que faz
Transform transform, bool IsDead, int Level Posição, estado, nível.
int Team Jogadores são 0, monstros 1. Times diferentes são inimigos.
StatSheet CombatStats Stats e elementos para atacar e defender. Só no servidor.
void ServerDamage(Hit hit, IFighter source) Causa um golpe. Escudos, imunidades e morte são tratados dentro.
void ServerHeal(int amount, IFighter source, GameData cause = null) Cura. A quantia é final: os stats de quem cura não são somados de novo. cause escolhe o efeito que os clientes mostram.
bool ServerAddBuff(Buff buff) Adiciona um buff ou estado. False quando não pegou (imunidade, morto).
int ServerRemoveBuffs(Predicate<Buff> match, int max = 0) Remove os buffs que combinam, do mais novo ao mais antigo; 0 remove todos. Devolve quantos.
StatusFlags Status O que os seus estados o impedem de fazer agora (atordoado, enraizado, invisível).
bool ServerKnock(Vector3 to, float seconds) Empurra ou puxa. False quando ele não pode ser movido.
bool ServerRevive(float health, float mana, IFighter by) Traz de volta com uma fração da vida e da mana.

No servidor, os jogadores são PlayerCharacter e os monstros são Monster (os dois em Blunnyn.KitARPG.Net). Faça o cast para eles quando precisar de algo que IFighter não tem, como a vida.

#Números que crescem com o rank

LevelValue é um valor no rank 1 mais uma quantia por rank depois dele:

public LevelValue amount = new LevelValue(10, 2);   // 10 at rank 1, 12 at rank 2, 14 at rank 3
float value = amount.At(cast.level);
int whole = amount.AtInt(cast.level);               // rounded

O inspector o mostra como Base Value e Per Level.

#Golpes e a fórmula de dano

Um Hit é amount, critical, element (o elemento que causou a maior parte, pela sua cor) e source (a habilidade, o tipo de arma ou o monstro, que escolhe o efeito do golpe).

Para seguir as regras de dano do jogo (dano de elemento, poder, resistência fixa e percentual, críticos), deixe a fórmula de combate montar o golpe:

var rolls = new List<ElementDamage> { new ElementDamage(element, min.At(cast.level), max.At(cast.level)) };
Hit hit = GameInstance.Combat.Attack(cast.caster.CombatStats, rolls, target.CombatStats, cast.scale);
hit.source = cast.skill;
target.ServerDamage(hit, cast.caster);

Para curas, GameInstance.Combat.Heal(cast.caster.CombatStats, amount) soma o stat de curas e o bônus de cura do lançador. Um jogo que trocou a fórmula (veja Fórmulas) muda os seus efeitos também.

#Exemplo: o template

Create > KitARPG > Scripts > Skill Effect cria um efeito de dano fixo. Ele pula a fórmula de propósito para ficar curto. A página Templates o mostra.

#Exemplo: roubo de vida

Dano que cura o lançador com uma fração do que causou.

using System;
using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    /// <summary>Hits each enemy and heals the caster for a share of the damage.</summary>
    [Serializable]
    public class LifeStealEffect : SkillEffect
    {
        [Tooltip("Empty uses the database's default element.")]
        public DamageElement element;
        public LevelValue min = new LevelValue(8, 3);
        public LevelValue max = new LevelValue(12, 4);
        [Tooltip("Share of the damage dealt that heals the caster, from 0 to 1.")]
        public LevelValue steal = new LevelValue(0.2f, 0.02f);

        public override string Summary => $"Life steal {min.baseValue:0}-{max.baseValue:0}";

        public override bool Harmful => true;

        public override void Apply(SkillCast cast, IFighter target)
        {
            var rolls = new List<ElementDamage> { new ElementDamage(element, min.At(cast.level), max.At(cast.level)) };
            Hit hit = GameInstance.Combat.Attack(cast.caster.CombatStats, rolls, target.CombatStats, cast.scale);
            hit.source = cast.skill;
            target.ServerDamage(hit, cast.caster);

            int healed = Mathf.RoundToInt(hit.amount * Mathf.Clamp01(steal.At(cast.level)));
            if (healed > 0 && !cast.caster.IsDead) cast.caster.ServerHeal(healed, cast.caster, cast.skill);
        }

        public override void Describe(ItemDescription description, int level, DamageElement fallback)
        {
            DamageElement shown = element != null ? element : fallback;
            description.Add($"{min.At(level):0} to {max.At(level):0} {(shown != null ? shown.DisplayName : "Neutral")} damage",
                ItemDescription.Kind.Effect, shown != null ? shown.Icon : null);
            description.Add($"Heals you for {steal.At(level) * 100:0}% of the damage", ItemDescription.Kind.Effect);
        }

        // The element is an asset: hand it over so the database registers it.
        public override void Visit(Action<GameData> visit) => visit(element);
    }
}

A cura usa a quantia do golpe antes que os escudos absorvessem parte dela. Se isso importa no seu jogo, compare a vida do alvo antes e depois (veja o próximo exemplo para ler a vida).

#Exemplo: execução

Dano extra contra alvos abaixo de uma fração da vida.

using System;
using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    /// <summary>Hits harder when the target is low on health.</summary>
    [Serializable]
    public class ExecuteEffect : SkillEffect
    {
        public DamageElement element;
        public LevelValue min = new LevelValue(10, 3);
        public LevelValue max = new LevelValue(14, 4);
        [Tooltip("Below this share of health, from 0 to 1, the bonus applies.")]
        [Range(0, 1)] public float below = 0.3f;
        [Tooltip("Extra damage below the threshold: 1 doubles it.")]
        public LevelValue bonus = new LevelValue(1f, 0.25f);

        public override string Summary => $"Execute below {below * 100:0}%";

        public override bool Harmful => true;

        public override void Apply(SkillCast cast, IFighter target)
        {
            float scale = cast.scale;
            if (HealthShare(target) < below) scale *= 1 + bonus.At(cast.level);
            var rolls = new List<ElementDamage> { new ElementDamage(element, min.At(cast.level), max.At(cast.level)) };
            Hit hit = GameInstance.Combat.Attack(cast.caster.CombatStats, rolls, target.CombatStats, scale);
            hit.source = cast.skill;
            target.ServerDamage(hit, cast.caster);
        }

        static float HealthShare(IFighter fighter)
        {
            if (fighter is PlayerCharacter player) return player.maxHealth > 0 ? (float)player.health / player.maxHealth : 1f;
            if (fighter is Monster monster) return monster.maxHealth > 0 ? (float)monster.health / monster.maxHealth : 1f;
            return 1f;
        }

        public override void Describe(ItemDescription description, int level, DamageElement fallback)
        {
            description.Add($"{min.At(level):0} to {max.At(level):0} damage", ItemDescription.Kind.Effect);
            description.Add($"+{bonus.At(level) * 100:0}% against targets below {below * 100:0}% health", ItemDescription.Kind.Effect);
        }

        public override void Visit(Action<GameData> visit) => visit(element);
    }
}

#Exemplo: devolução de mana ao lançador

Um efeito OnCaster roda uma vez por lançamento, com o lançador como target. Este devolve mana a cada lançamento, a habilidade alcance alguém ou não. A verificação de firstHit limita a uma vez nas animações de vários golpes; uma zona paga de novo a cada tick, já que cada tick é um lançamento novo.

using System;
using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class ManaRefundEffect : SkillEffect
    {
        public LevelValue mana = new LevelValue(5, 1);

        public override string Summary => $"Refund {mana.baseValue:0} mana";

        public override bool OnCaster => true;

        public override void Apply(SkillCast cast, IFighter target)
        {
            if (!cast.firstHit) return;
            // Players are item users too, which is how mana is restored from data code.
            if (target is IItemUser user) user.RestoreMana(mana.AtInt(cast.level));
        }

        public override void Describe(ItemDescription description, int level, DamageElement fallback) =>
            description.Add($"Restores {mana.At(level):0} mana when cast", ItemDescription.Kind.Effect);
    }
}

#Exemplo: um estado a partir de um campo

Efeitos que apontam para assets (estados, monstros, itens) precisam entregá-los a Visit. Sem isso, um asset referenciado só pelo seu efeito pode ficar fora do banco de dados do jogo, e o servidor não consegue encontrá-lo pelo id.

[Serializable]
public class MarkForDeathEffect : SkillEffect
{
    public StatusData status;
    public LevelValue seconds = new LevelValue(6, 0.5f);

    public override string Summary => status != null ? $"Mark: {status.DisplayName}" : "Mark (none)";

    public override bool Harmful => true;

    public override void Apply(SkillCast cast, IFighter target)
    {
        if (status == null || !cast.firstHit) return;
        target.ServerAddBuff(Buff.Of(status, cast.level, seconds.At(cast.level), cast.caster));
    }

    public override void Visit(Action<GameData> visit) => visit(status);
}

Para a maioria dos estados, o ApplyStatusEffect do kit já faz isso, com chance e acúmulos. Escreva o seu só quando a regra for diferente.

#Servidor e cliente

Roda em
Apply Só no servidor: o servidor de mapa online, o host em um jogador.
Describe, Summary Onde quer que um cartão de habilidade seja mostrado: o cliente e o editor.
Valores dos campos Nos dois: o asset é o mesmo nos dois builds.

Os clientes veem o resultado pela sincronização do próprio kit: barras de vida, números de dano (CombatEvents.Damaged), ícones de buff e os efeitos da habilidade. O seu efeito não precisa enviar nada.

#Um jogador e MMO

Nada muda. Em um jogador, o host roda o mesmo Apply. Dano entre jogadores só acerta onde o PvP ou um duelo permite; essa verificação acontece antes de o seu efeito ser chamado, quando os alvos são reunidos.

#Erros comuns

  • Aplicar um buff a cada acerto. Animações de vários golpes e zonas chamam Apply muitas vezes. Proteja efeitos de uma vez só com cast.firstHit.
  • Ignorar cast.scale. Uma animação de três golpes passa a causar três golpes inteiros.
  • Usar UnityEngine.Random em Describe. As dicas precisam ser estáveis; role só em Apply.
  • Guardar estado por lançamento em campos. Uma instância do efeito é compartilhada por todo lançamento dessa habilidade, por todo jogador. Não guarde nada em campos durante a execução; use variáveis locais, ou um dicionário com o lutador como chave em um sistema do lado do servidor.
  • Esquecer Visit. Assets referenciados só pelo seu efeito podem faltar no banco de dados.
  • Renomear a classe. As habilidades guardam o seu efeito pelo nome do tipo. Renomear deixa entradas "missing type" que o validador lista. Mantenha o nome, ou adicione [UnityEngine.Scripting.APIUpdating.MovedFrom(...)] com o nome antigo.
  • Chamar ServerHeal com um número cru e depois a fórmula de novo. ServerHeal recebe uma quantia final.
