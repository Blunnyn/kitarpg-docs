Condições e ações em código

Como escrever as suas próprias condições (regras que um jogador precisa cumprir) e ações (coisas feitas a um jogador), o que elas podem ler e mudar, onde o kit as executa e como usá-las em dados seus.

#O que são

  • Uma condição responde sim ou não sobre um jogador: "nível 10 ou mais", "terminou a missão Old Mill", "é noite". Missões, opções de NPC, saudações de NPC e gatilhos do mundo têm listas delas.
  • Uma ação muda um jogador: pagar ouro, tirar um item, definir uma marca de história, iniciar uma missão. Falas de diálogo, missões (ao aceitar e ao concluir) e gatilhos do mundo têm listas delas.

O lado voltado para quem desenha o jogo está em Condições e ações. Esta página trata de escrever tipos novos.

As duas são classes [Serializable] guardadas com [SerializeReference, PickType]. A sua classe aparece no menu + de toda lista assim que compila.

Onde ficam os arquivos: no assembly Game. As condições também rodam no cliente, então precisam estar em todo build.

#Onde o kit as usa

Campo Tipo Verificado ou executado em
QuestData.conditions Condições Servidor ao pegar a missão; cliente do dono para os marcadores de missão e a janela de missões
QuestData.onAccept, QuestData.onComplete Ações Servidor
NpcOption.conditions Condições Servidor, ao listar as opções de um NPC
Npc.greetings[].conditions Condições Servidor, para escolher a saudação
DialogueOption.actions Ações Servidor, quando a fala é escolhida
WorldTrigger.conditions, WorldTrigger.actions Ambos Servidor, quando o gatilho dispara

#Condições

#Os fatos que uma condição lê

Met(IPlayerFacts facts) recebe o jogador por meio de IPlayerFacts (namespace Blunnyn.KitARPG.Data). Tudo nela funciona tanto no servidor quanto no cliente do dono.

Membro O que devolve
int Level O nível do personagem.
CharacterClass Class A sua classe.
MapData Map O mapa em que ele está, se o mapa estiver no banco de dados.
int CountItem(string itemId) Quantos de um item ele carrega na bolsa.
bool Wears(string itemId) Se ele veste o item (cosméticos não contam).
long Balance(CurrencyData currency) Ouro para uma moeda null, ou a quantia dessa moeda.
int SkillRank(SkillData skill) O rank de uma habilidade, 0 se não aprendida.
int Attribute(AttributeData attribute) O total do atributo: classe, pontos gastos e equipamento.
bool HasStatus(StatusData status) Se o estado está nele agora.
QuestState QuestStateOf(QuestData quest) Locked, Available, Active, Ready ou Done.
bool HasDone(QuestData quest) Entregue pelo menos uma vez.
bool HasDiscovered(string placeId) Um id de mapa ou de zona em que ele já esteve.
int Flag(string key) Uma marca de história; 0 se nunca definida.

O objeto por trás é um PlayerActor, que também implementa IPlayerActor. Quando você precisar de um componente do jogador, faça o cast e use Self:

if (facts is IPlayerActor actor && actor.Self.TryGetComponent(out PlayerCharacter player)) { ... }

#A classe base

Membro O que faz
string failText Campo do inspector Fail Text: mostrado quando a condição não é cumprida. Vazio usa DefaultText.
string Text failText ou DefaultText.
protected abstract string DefaultText { get; } O seu motivo padrão, como "Needs level 5". Obrigatório.
abstract bool Met(IPlayerFacts facts) A sua regra. Obrigatório.
virtual void Visit(Action<GameData> visit) Entrega todo asset para o qual a condição aponta.
static string Check(Condition[] conditions, IPlayerFacts facts) A primeira condição não cumprida, como texto, ou null quando todas são. Use nas suas próprias listas.

#Exemplo: o template

using System;
using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    /// <summary>A rule quests, dialog lines and NPC options can ask for. Lists of conditions show it on their own.</summary>
    [Serializable]
    public class NewCondition : Condition
    {
        public string flag = "my_game.mark";
        public int atLeast = 1;

        protected override string DefaultText => "Not yet";

        // Runs on the server and on the owner's client, so the client can show what is locked.
        public override bool Met(IPlayerFacts facts) => facts.Flag(flag) >= atLeast;
    }
}

#Exemplo: vida acima de uma fração

Usa Self para ler a vida do jogador, que é sincronizada para todos, então funciona dos dois lados.

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class HealthCondition : Condition
    {
        [Range(0, 1)] public float atLeast = 0.5f;

        protected override string DefaultText => $"Needs {atLeast * 100:0}% health";

        public override bool Met(IPlayerFacts facts)
        {
            if (!(facts is IPlayerActor actor) || !actor.Self.TryGetComponent(out PlayerCharacter player)) return false;
            return player.maxHealth > 0 && (float)player.health / player.maxHealth >= atLeast;
        }
    }
}

#Exemplo: veste um item de um conjunto

Lê assets, então os entrega a Visit.

[Serializable]
public class WearsAnyCondition : Condition
{
    public ItemData[] items = new ItemData[0];

    protected override string DefaultText => "Wear the right gear";

    public override bool Met(IPlayerFacts facts)
    {
        foreach (ItemData item in items)
            if (item != null && facts.Wears(item.Id)) return true;
        return false;
    }

    public override void Visit(Action<GameData> visit)
    {
        foreach (ItemData item in items) visit(item);
    }
}

#Condições incluídas

LevelCondition, ClassCondition, QuestCondition (com QuestCheck: NotStarted, Available, Taken, InProgress, Ready, Done, NotDone, NotTaken), ItemCondition, EquippedCondition, CurrencyCondition, DiscoveredCondition, MapCondition, SkillCondition, AttributeCondition, StatusCondition, FlagCondition (Equal, NotEqual, AtLeast, AtMost), TimeCondition (horas do jogo ou dias e horas reais em UTC), e os grupos AnyCondition, AllCondition e NotCondition. Combine essas antes de escrever uma nova: "nível 10 e sem a missão" são duas condições que já existem.

#As condições rodam no cliente

O cliente do dono avalia as condições de missão para mostrar os marcadores de missão sobre os NPCs e o estado na janela de missões. Isso tem duas consequências:

  • Leia só o que o cliente do dono tem. Marcas, missões, a bolsa, o equipamento, as habilidades, os estados e o nível são sincronizados para o dono. Os valores de PlayerData não são (eles nunca saem do servidor), então uma condição que os lê é sempre falsa no cliente.
  • Nunca confie na resposta do cliente. O servidor verifica de novo antes de qualquer coisa acontecer. Uma condição é um filtro, não uma tranca que o cliente segura.

#Ações

#O que uma ação pode fazer

Run(IPlayerActor actor) recebe o jogador por meio de IPlayerActor, que estende IPlayerFacts. Os membros próprios dela funcionam só no servidor.

Membro O que faz
GameObject Self O objeto do jogador, para componentes que a interface não cobre.
IItemUser User O jogador como os itens o veem: experiência, níveis, pontos, habilidades, estados, viagem. Veja Efeitos de itens.
string RoomFor(ItemData item, int amount) Por que estes não cabem na bolsa, ou null.
void GiveItem(ItemData item, int amount) Coloca itens na bolsa.
void TakeItem(ItemData item, int amount) Tira itens da bolsa.
void AddCurrency(CurrencyData currency, long amount) Negativo tira. Ouro para uma moeda null. Moedas premium vão para a conta pelo serviço da loja.
void SetFlag(string key, int value) Define uma marca de história; 0 a apaga. Salva com o personagem.
void Discover(string placeId, string placeName) Marca um lugar como encontrado.
string StartQuest(QuestData quest) Inicia uma missão. Devolve o motivo da recusa, ou null.
void DropQuest(QuestData quest) Abandona a missão.
void RemoveStatus(StatusData status) Tira um estado.
void Say(string text, Color color) Texto flutuante sobre o jogador, que só ele vê.
string FireTrigger(string triggerId) Dispara um gatilho do mundo no mapa do jogador. Devolve o motivo da recusa, ou null.

#A classe base

Membro O que faz Padrão
virtual string Check(IPlayerActor actor) Por que ela não pode rodar agora, ou null. null
abstract void Run(IPlayerActor actor) Executa a ação. Obrigatório.
virtual string Cost Um preço para mostrar ao lado da fala de diálogo que a executa, como "50 Gold". null
virtual void Visit(Action<GameData> visit) Entrega todo asset para o qual ela aponta. Nada
static string RunAll(GameAction[] actions, IPlayerActor actor) Verifica todas as ações e depois executa todas. Devolve o primeiro motivo pelo qual não pode, ou null.
static string Costs(GameAction[] actions) Os custos de uma lista juntos, ou null.

Uma lista é tudo ou nada: RunAll chama todo Check primeiro e só depois todo Run. Coloque todo motivo de recusa em Check e nunca falhe dentro de Run.

#Exemplo: o template

using System;
using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    /// <summary>Something done to a player from a dialog line or a quest reward. Server only.</summary>
    [Serializable]
    public class NewAction : GameAction
    {
        public string flag = "my_game.mark";
        public int add = 1;

        // Every action of a list is checked before any runs; return why not, or null.
        public override string Check(IPlayerActor actor) => null;

        public override void Run(IPlayerActor actor) => actor.SetFlag(flag, actor.Flag(flag) + add);
    }
}

#Exemplo: dar itens, sem nunca perdê-los

O GiveItemAction do kit recusa quando a bolsa está cheia. Este dá de qualquer jeito: na bolsa, depois no banco, depois retido até haver espaço.

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class GiveOrBankAction : GameAction
    {
        public ItemData item;
        public int amount = 1;

        public override string Check(IPlayerActor actor) => item == null ? "Nothing to give" : null;

        public override void Run(IPlayerActor actor)
        {
            if (!actor.Self.TryGetComponent(out PlayerInventory inventory)) return;
            int banked = inventory.GiveOrBank(item, Mathf.Max(1, amount));
            if (banked > 0) actor.Say($"{banked} {item.DisplayName} went to your bank", new Color(1f, 0.85f, 0.4f));
        }

        public override void Visit(Action<GameData> visit) => visit(item);
    }
}

#Exemplo: um serviço pago com uma linha de registro

Mostra Cost, então uma fala de diálogo com o rótulo "Heal me" aparece como "Heal me (200 Gold)", e escreve uma linha no registro do jogo que os moderadores podem pesquisar.

[Serializable]
public class PaidHealAction : GameAction
{
    public long price = 200;

    public override string Cost => $"{price:N0} {GameInstance.Database?.GoldName ?? "Gold"}";

    public override string Check(IPlayerActor actor) =>
        actor.Balance(null) < price ? $"You need {price:N0} {GameInstance.Database.GoldName}" : null;

    public override void Run(IPlayerActor actor)
    {
        actor.AddCurrency(null, -price);
        if (actor.Self.TryGetComponent(out PlayerCharacter player))
        {
            player.ServerHeal(player.maxHealth, null);
            GameLog.Write("mygame.paid_heal", player, gold: price);
        }
    }
}

#Ações incluídas

GiveItemAction, TakeItemAction, GiveCurrencyAction, ChargeCurrencyAction, ExperienceAction, PointsAction, ResetAttributesAction, TeachSkillAction, AddStatusAction, RemoveStatusAction, RestoreAction, TravelAction, SetFlagAction, StartQuestAction, DropQuestAction, DiscoverAction, MessageAction e FireTriggerAction.

#Usar listas nos seus próprios dados

Qualquer ScriptableObject ou classe serializável sua pode ter listas que os designers preenchem pelos mesmos menus:

using Blunnyn.KitARPG.Data;
using UnityEngine;

[CreateAssetMenu(menuName = "My Game/Reward Chest")]
public class RewardChestData : ScriptableObject
{
    [SerializeReference, PickType] public Condition[] conditions = new Condition[0];
    [SerializeReference, PickType] public GameAction[] rewards = new GameAction[0];
}

No servidor:

IPlayerActor actor = player.Facts;
string why = Condition.Check(chest.conditions, actor) ?? GameAction.RunAll(chest.rewards, actor);
if (why != null) player.ServerAnnounce(why, new Color(1f, 0.5f, 0.45f));

Sem [PickType], o inspector mostra uma lista [SerializeReference] sem como escolher um tipo. O BountyBoardData.rewards do exemplo de recompensas é uma lista assim.

#Servidor e cliente

Servidor Cliente do dono
Condition.Met Sim, e a resposta é final Sim, para mostrar conteúdo bloqueado
GameAction.Check, Run Sim Nunca
DefaultText, Cost Sim (enviado como texto) Sim

Em um jogador, os dois rodam na mesma máquina, com as mesmas respostas.

#Erros comuns

  • Ler dados só de servidor em uma condição (PlayerData, campos privados do servidor). O cliente mostra o estado errado.
  • Falhar dentro de Run. A lista já passou pelas verificações, então as outras ações rodaram. Verifique em Check.
  • Dar itens pelo inventário cru. Use GiveItem, TakeItem ou PlayerInventory para que a bolsa sincronize e o salvamento fique certo.
  • Guardar estado por jogador em campos. Uma instância atende todos os jogadores. Use marcas ou PlayerData.
  • Esquecer Visit. Assets referenciados só pela sua classe podem ficar fora do banco de dados do jogo.
