Conditions and actions in code

Esta página ainda não foi traduzida. Ela aparece em inglês.

How to write your own conditions (rules a player must meet) and actions (things done to a player), what they can read and change, where the kit runs them, and how to use them in data of your own.

#What they are

  • A condition answers yes or no about a player: "level 10 or more", "has finished the Old Mill quest", "it is night". Quests, NPC options, NPC greetings and world triggers have lists of them.
  • An action changes a player: pay gold, take an item, set a story flag, start a quest. Dialogue lines, quests (on accept and on complete) and world triggers have lists of them.

The designer-facing side is on Conditions and actions. This page is about writing new kinds.

Both are [Serializable] classes held with [SerializeReference, PickType]. Your class shows in every list's + menu once it compiles.

Where the files go: the Game assembly. Conditions run on the client too, so they must be in every build.

#Where the kit uses them

Field Kind Checked or run on
QuestData.conditions Conditions Server when taking the quest; owner's client for quest markers and the quest window
QuestData.onAccept, QuestData.onComplete Actions Server
NpcOption.conditions Conditions Server, when listing an NPC's options
Npc.greetings[].conditions Conditions Server, to pick the greeting
DialogueOption.actions Actions Server, when the line is picked
WorldTrigger.conditions, WorldTrigger.actions Both Server, when the trigger fires

#Conditions

#The facts a condition reads

Met(IPlayerFacts facts) gets the player through IPlayerFacts (namespace Blunnyn.KitARPG.Data). Everything on it works both on the server and on the owner's client.

Member What it returns
int Level The character's level.
CharacterClass Class Its class.
MapData Map The map it is on, if the map is in the database.
int CountItem(string itemId) How many of an item it carries in the bag.
bool Wears(string itemId) Whether it wears the item (cosmetics not counted).
long Balance(CurrencyData currency) Gold for a null currency, or that currency's amount.
int SkillRank(SkillData skill) Rank of a skill, 0 when not learned.
int Attribute(AttributeData attribute) The attribute's total: class, spent points and gear.
bool HasStatus(StatusData status) Whether the status is on it now.
QuestState QuestStateOf(QuestData quest) Locked, Available, Active, Ready or Done.
bool HasDone(QuestData quest) Turned in at least once.
bool HasDiscovered(string placeId) A map or zone id it has been to.
int Flag(string key) A story flag; 0 when never set.

The object behind it is a PlayerActor, which also implements IPlayerActor. When you need a component of the player, cast and use Self:

if (facts is IPlayerActor actor && actor.Self.TryGetComponent(out PlayerCharacter player)) { ... }

#The base class

Member What it does
string failText Inspector field Fail Text: shown when the condition isn't met. Empty uses DefaultText.
string Text failText or DefaultText.
abstract string DefaultText { get; } Your default reason, like "Needs level 5". Required.
abstract bool Met(IPlayerFacts facts) Your rule. Required.
virtual void Visit(Action<GameData> visit) Hand over every asset the condition points at.
static string Check(Condition[] conditions, IPlayerFacts facts) The first condition not met, as text, or null when all are. Use it on your own lists.

#Example: the template

[Serializable]
public class NewCondition : Condition
{
    public string flag = "my_game.mark";
    public int atLeast = 1;

    protected override string DefaultText => "Not yet";

    public override bool Met(IPlayerFacts facts) => facts.Flag(flag) >= atLeast;
}

#Example: health above a share

Uses Self to read the player's health, which is synced to everyone, so it works on both sides.

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class HealthCondition : Condition
    {
        [Range(0, 1)] public float atLeast = 0.5f;

        protected override string DefaultText => $"Needs {atLeast * 100:0}% health";

        public override bool Met(IPlayerFacts facts)
        {
            if (!(facts is IPlayerActor actor) || !actor.Self.TryGetComponent(out PlayerCharacter player)) return false;
            return player.maxHealth > 0 && (float)player.health / player.maxHealth >= atLeast;
        }
    }
}

#Example: wears an item from a set

Reads assets, so it hands them to Visit.

[Serializable]
public class WearsAnyCondition : Condition
{
    public ItemData[] items = new ItemData[0];

    protected override string DefaultText => "Wear the right gear";

    public override bool Met(IPlayerFacts facts)
    {
        foreach (ItemData item in items)
            if (item != null && facts.Wears(item.Id)) return true;
        return false;
    }

    public override void Visit(Action<GameData> visit)
    {
        foreach (ItemData item in items) visit(item);
    }
}

#Built-in conditions

LevelCondition, ClassCondition, QuestCondition (with QuestCheck: NotStarted, Available, Taken, InProgress, Ready, Done, NotDone, NotTaken), ItemCondition, EquippedCondition, CurrencyCondition, DiscoveredCondition, MapCondition, SkillCondition, AttributeCondition, StatusCondition, FlagCondition (Equal, NotEqual, AtLeast, AtMost), TimeCondition (game hours or real UTC days and hours), and the groups AnyCondition, AllCondition and NotCondition. Combine those before writing a new one: "level 10 and not on the quest" is two existing conditions.

#Conditions run on the client

The owner's client evaluates quest conditions to show quest markers over NPCs and the state in the quest window. That has two consequences:

  • Read only what the owner's client has. Flags, quests, the bag, gear, skills, statuses and level are synced to the owner. PlayerData values are not (they never leave the server), so a condition that reads them is always false on the client.
  • Never trust the client's answer. The server checks again before anything happens. A condition is a filter, not a lock the client holds.

#Actions

#What an action can do

Run(IPlayerActor actor) gets the player through IPlayerActor, which extends IPlayerFacts. Its own members work on the server only.

Member What it does
GameObject Self The player object, for components the interface doesn't cover.
IItemUser User The player as items see it: experience, levels, points, skills, statuses, travel. See Item effects.
string RoomFor(ItemData item, int amount) Why these won't fit in the bag, or null.
void GiveItem(ItemData item, int amount) Puts items in the bag.
void TakeItem(ItemData item, int amount) Takes items from the bag.
void AddCurrency(CurrencyData currency, long amount) Negative takes. Gold for a null currency. Premium currencies go to the account through the shop service.
void SetFlag(string key, int value) Sets a story flag; 0 clears it. Saved with the character.
void Discover(string placeId, string placeName) Marks a place as found.
string StartQuest(QuestData quest) Starts a quest. Returns why not, or null.
void DropQuest(QuestData quest) Abandons it.
void RemoveStatus(StatusData status) Takes a status off.
void Say(string text, Color color) Floating text over the player, only they see it.
string FireTrigger(string triggerId) Sets off a world trigger on the player's map. Returns why not, or null.

#The base class

Member What it does Default
virtual string Check(IPlayerActor actor) Why it can't run now, or null. null
abstract void Run(IPlayerActor actor) Does it. Required.
virtual string Cost A price to show next to the dialogue line that runs it, like "50 Gold". null
virtual void Visit(Action<GameData> visit) Hand over every asset it points at. Nothing
static string RunAll(GameAction[] actions, IPlayerActor actor) Checks every action, then runs them all. Returns the first reason it can't, or null.
static string Costs(GameAction[] actions) The costs of a list joined, or null.

A list is all or nothing: RunAll calls every Check first and only then every Run. Put every reason to refuse in Check and never fail inside Run.

#Example: the template

[Serializable]
public class NewAction : GameAction
{
    public string flag = "my_game.mark";
    public int add = 1;

    public override string Check(IPlayerActor actor) => null;

    public override void Run(IPlayerActor actor) => actor.SetFlag(flag, actor.Flag(flag) + add);
}

#Example: give items, never lose them

The kit's GiveItemAction refuses when the bag is full. This one gives anyway: the bag, then the bank, then held until there is room.

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class GiveOrBankAction : GameAction
    {
        public ItemData item;
        public int amount = 1;

        public override string Check(IPlayerActor actor) => item == null ? "Nothing to give" : null;

        public override void Run(IPlayerActor actor)
        {
            if (!actor.Self.TryGetComponent(out PlayerInventory inventory)) return;
            int banked = inventory.GiveOrBank(item, Mathf.Max(1, amount));
            if (banked > 0) actor.Say($"{banked} {item.DisplayName} went to your bank", new Color(1f, 0.85f, 0.4f));
        }

        public override void Visit(Action<GameData> visit) => visit(item);
    }
}

#Example: a priced service with a log line

Shows Cost, so the dialogue line reads "Repair my armor (200 Gold)", and writes a game log line moderators can search.

[Serializable]
public class PaidHealAction : GameAction
{
    public long price = 200;

    public override string Cost => $"{price:N0} {GameInstance.Database?.GoldName ?? "Gold"}";

    public override string Check(IPlayerActor actor) =>
        actor.Balance(null) < price ? $"You need {price:N0} {GameInstance.Database.GoldName}" : null;

    public override void Run(IPlayerActor actor)
    {
        actor.AddCurrency(null, -price);
        if (actor.Self.TryGetComponent(out PlayerCharacter player))
        {
            player.ServerHeal(player.maxHealth, null);
            GameLog.Write("mygame.paid_heal", player, gold: price);
        }
    }
}

#Built-in actions

GiveItemAction, TakeItemAction, GiveCurrencyAction, ChargeCurrencyAction, ExperienceAction, PointsAction, ResetAttributesAction, TeachSkillAction, AddStatusAction, RemoveStatusAction, RestoreAction, TravelAction, SetFlagAction, StartQuestAction, DropQuestAction, DiscoverAction, MessageAction and FireTriggerAction.

#Using lists in your own data

Any ScriptableObject or serializable class of yours can hold lists that designers fill from the same menus:

using Blunnyn.KitARPG.Data;
using UnityEngine;

[CreateAssetMenu(menuName = "My Game/Reward Chest")]
public class RewardChestData : ScriptableObject
{
    [SerializeReference, PickType] public Condition[] conditions = new Condition[0];
    [SerializeReference, PickType] public GameAction[] rewards = new GameAction[0];
}

On the server:

IPlayerActor actor = player.Facts;
string why = Condition.Check(chest.conditions, actor) ?? GameAction.RunAll(chest.rewards, actor);
if (why != null) player.ServerAnnounce(why, new Color(1f, 0.5f, 0.45f));

Without [PickType] the inspector shows a [SerializeReference] list with no way to pick a type. The bounty example's BountyBoardData.rewards is a list like this.

#Server and client

Server Owner's client
Condition.Met Yes, and its answer is final Yes, to show locked content
GameAction.Check, Run Yes Never
DefaultText, Cost Yes (sent as text) Yes

Single player runs both on the same machine, with the same answers.

#Common mistakes

  • Reading server-only data in a condition (PlayerData, private server fields). The client shows the wrong state.
  • Failing inside Run. The list has already passed its checks, so the other actions ran. Check in Check.
  • Giving items through the raw inventory. Use GiveItem, TakeItem or PlayerInventory so the bag syncs and the save stays right.
  • Keeping per-player state in fields. One instance serves every player. Use flags or PlayerData.
  • Forgetting Visit. Assets only your class references may be left out of the game database.
