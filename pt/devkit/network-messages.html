Mensagens de rede

Como fazer o cliente e o servidor conversarem com mensagens de rede do Mirror, sem adicionar um componente ao prefab do jogador: definir mensagens, registrar handlers no momento certo, validar no servidor e enviar para um jogador, para os jogadores próximos ou para todos.

#Mensagens ou um sistema do jogador

Mensagens de rede Um sistema do jogador (NetworkBehaviour)
Mudança no prefab Nenhuma Adicionado a cada prefab de modelo de jogador
Estado sincronizado Nenhum; você envia o que muda [SyncVar] e coleções sincronizadas
Quem enviou conn.identity no servidor O próprio jogador do componente
Bom para Pedidos e respostas, avisos, recursos que você quer apagar removendo uma pasta Estado que a interface lê o tempo todo

O exemplo de recompensas usa mensagens: o cliente pede a sua recompensa quando aparece, e o servidor envia a recompensa sempre que ela muda. Veja Sistemas do jogador para a outra opção.

Onde o arquivo fica: no assembly Game. Os dois lados precisam dos tipos de mensagem e dos seus handlers.

#Definindo uma mensagem

Uma mensagem é uma struct que implementa Mirror.NetworkMessage, com campos públicos de tipos que o Mirror sabe escrever: números, bool, string, Vector3, enums, arrays e listas desses, e outras structs feitas deles.

using Mirror;

public struct CraftRequest : NetworkMessage
{
    public string recipeId;
    public int amount;
}

public struct CraftResult : NetworkMessage
{
    public bool ok;
    public string text;
}

O weaver do Mirror gera o código que as lê e escreve, no seu assembly, em tempo de compilação.

#Registrando handlers

Os handlers são registrados no servidor quando ele inicia e no cliente quando ele se conecta. KitNetworkManager dispara eventos para os dois:

Evento Quando
ServerStarted Um servidor ou host inicia. Em um jogador o host reinicia a cada troca de mapa, então isto dispara de novo a cada vez.
ServerStopping Antes de o servidor parar.
ServerDisconnecting (NetworkConnectionToClient) Antes de o jogador de uma conexão ser destruído.
ClientConnected O cliente se conectou a um mapa.
ClientDisconnected O cliente saiu de um mapa.

KitNetworkManager.Instance é o manager, no objeto KitNetwork da cena Title (clientes e um jogador) e da cena Server (servidores de mapa), as cenas em que um jogo começa. Ele sobrevive às trocas de cena, então conecte-se em AfterSceneLoad, quando a primeira cena já o carregou:

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
static void Hook()
{
    KitNetworkManager manager = KitNetworkManager.Instance;
    if (manager == null) return;
    manager.ServerStarted += () => NetworkServer.ReplaceHandler<CraftRequest>(OnCraft);
    manager.ClientConnected += () => NetworkClient.ReplaceHandler<CraftResult>(OnResult);
}

static void OnResult(CraftResult result) => Debug.Log(result.text);

Use ReplaceHandler, não RegisterHandler: ele não reclama quando o mesmo handler é registrado de novo no próximo início. Os handlers do servidor só aceitam mensagens de conexões autenticadas (jogadores que apresentaram um ticket válido).

#Tratando um pedido no servidor

static void OnCraft(NetworkConnectionToClient conn, CraftRequest message)
{
    // 1. Spend from this connection's budget; floods get disconnected.
    if (!CommandPacing.Allow(conn)) return;

    // 2. Who sent it comes from the connection, never from the message.
    if (conn.identity == null || !conn.identity.TryGetComponent(out PlayerCharacter player)) return;
    if (player.State == null || player.IsDead) return;

    // 3. Validate every field.
    if (string.IsNullOrEmpty(message.recipeId) || message.recipeId.Length > 64) return;
    if (message.amount < 1 || message.amount > 99) return;
    if (!GameInstance.Database.TryGet(message.recipeId, out RecipeData recipe)) return;

    // 4. Do it through the kit's systems, then answer.
    string why = Crafting.ServerCraft(player, recipe, message.amount);
    conn.Send(new CraftResult { ok = why == null, text = why ?? $"Crafted {recipe.DisplayName}." });
}

(RecipeData e Crafting representam o seu próprio tipo de dados e as suas regras.)

Os quatro passos valem para todo handler:

  1. Ritmo. CommandPacing.Allow(conn) divide um orçamento por conexão com todo [Command] do jogo (30 por segundo, rajada de 60). Muito acima disso, a conexão é expulsa com KickReasons.Flooding. Use CommandPacing.AllowCentral(conn) para pedidos que geram trabalho para o Central (2 por segundo, rajada de 10).
  2. Identidade. conn.identity é o objeto do jogador da conexão que enviou. Nunca coloque um id de personagem, id de conta ou nome de jogador em um pedido para agir com base nele.
  3. Validação. Strings têm comprimento, números têm intervalos e devem ser finitos (float.IsFinite), ids devem existir no banco de dados, e referências a coisas do mundo (um NPC, um monstro, um drop) devem estar perto e visíveis para aquele jogador.
  4. Sistemas do kit. Mude itens, ouro e progresso por PlayerInventory, IPlayerActor, PlayerQuests e PlayerProgress.

#Nomeando coisas do mundo

Para nomear um monstro ou jogador, envie o netId dele e resolva-o no servidor com Fighters.TargetFor, que devolve null para tudo o que aquela conexão não deveria ver (fora da visão dela, um inimigo invisível, um monstro de evento criado para outra pessoa):

ICombatant target = Fighters.TargetFor(conn, player, message.targetNetId);
if (target == null) return;

Para nomear um NPC, envie o id dele e verifique o alcance:

if (!Npc.TryFind(message.npcId, out Npc npc) || !npc.InReach(player.transform.position)) return;

#Enviando do servidor

Para Como
Um jogador player.connectionToClient.Send(message) (ou conn.Send em um handler)
Todos que veem um jogador NetworkServer.SendToReadyObservers(player.netIdentity, message)
Todos neste servidor de mapa NetworkServer.SendToAll(message)
Todos em todos os mapas Pelo Central: veja Conversando com o Central

connectionToClient é null em objetos sem dono e pode ser null enquanto um jogador está saindo; use ?.Send. Os mapas instanciados (masmorras, casas de guilda) rodam suas cópias dentro do mesmo processo do servidor de mapa, então SendToAll chega a todas as cópias. Para limitar um aviso a uma cópia, percorra PlayerCharacter.ServerAll() e compare gameObject.scene.

#Enviando do cliente

public static void Craft(string recipeId, int amount) =>
    NetworkClient.Send(new CraftRequest { recipeId = recipeId, amount = amount });

Só envie enquanto estiver conectado (NetworkClient.isConnected). Mensagens enviadas antes de o jogador aparecer chegam com conn.identity null, o que o handler acima ignora.

#Pedindo quando o jogador aparece

O cliente sabe que o seu jogador existe quando PlayerCharacter.LocalSpawned dispara. O exemplo de recompensas pede o seu estado ali:

PlayerCharacter.LocalSpawned -= AskOnSpawn;
PlayerCharacter.LocalSpawned += AskOnSpawn;

static void AskOnSpawn(PlayerCharacter _) => NetworkClient.Send(new BountyAsk());

#Um exemplo completo: um quadro de avisos do mundo

Os jogadores leem uma mensagem do dia para todo o servidor, e os moderadores a mudam com um comando de GM. O aviso fica guardado no servidor de mapa.

using Blunnyn.KitARPG.Net;
using Mirror;
using UnityEngine;

namespace Game
{
    public struct NoticeAsk : NetworkMessage { }

    public struct NoticeText : NetworkMessage
    {
        public string text;
    }

    public static class NoticeBoard
    {
        public const int MaxLength = 300;

        /// <summary>Server: the current notice.</summary>
        public static string Current { get; private set; } = "";

        /// <summary>Client: the notice arrived.</summary>
        public static event System.Action<string> Received;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void ResetStatics()
        {
            Current = "";
            Received = null;
        }

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Hook()
        {
            PlayerCharacter.LocalSpawned -= AskOnSpawn;
            PlayerCharacter.LocalSpawned += AskOnSpawn;
            KitNetworkManager manager = KitNetworkManager.Instance;
            if (manager == null) return;
            manager.ServerStarted += () => NetworkServer.ReplaceHandler<NoticeAsk>(OnAsk);
            manager.ClientConnected += () => NetworkClient.ReplaceHandler<NoticeText>(OnText);
        }

        static void OnText(NoticeText message) => Received?.Invoke(message.text);

        static void AskOnSpawn(PlayerCharacter _) => NetworkClient.Send(new NoticeAsk());

        static void OnAsk(NetworkConnectionToClient conn, NoticeAsk _)
        {
            if (!CommandPacing.Allow(conn) || conn.identity == null) return;
            conn.Send(new NoticeText { text = Current });
        }

        /// <summary>Server only. Sets the notice and shows it to everyone on this map server.</summary>
        public static void ServerSet(string text)
        {
            Current = PlayerText.Clean(text ?? "", MaxLength);
            NetworkServer.SendToAll(new NoticeText { text = Current });
        }
    }
}

Hook segue Play sem domain reload: o evento estático PlayerCharacter.LocalSpawned recebe -= antes de +=, e vem antes da verificação do manager, então fica inscrito mesmo numa cena sem network manager. Os eventos do próprio manager não precisam de -=: o manager é criado de novo a cada Play, e o antigo some com seus inscritos.

O comando de GM, no assembly Game.Server:

GmCommands.Register(new GmCommand
{
    name = "notice", rank = GmRank.Moderator, usage = "notice text", description = "Sets the notice board.",
    run = c =>
    {
        NoticeBoard.ServerSet(c.rest);
        return "Notice set.";
    },
});

PlayerText.Clean apara o texto, remove caracteres de controle, corta-o em um comprimento e quebra as tags de rich text, para que um aviso não consiga injetar marcação do TextMeshPro nas telas de outros jogadores. Para defini-lo em todos os mapas de uma vez, envie-o pelo Central (veja Conversando com o Central).

#Versão de rede

O kit calcula um hash de toda mensagem de rede e de todo campo sincronizado do projeto, inclusive os seus (NetworkVersion). O cliente envia o hash com o seu ticket, e um servidor de mapa compilado com código diferente o recusa com version_mismatch. Depois de adicionar ou mudar uma mensagem, recompile tanto o cliente quanto o servidor de mapa. No editor o valor é calculado a partir do código atual, então o Play sempre combina consigo mesmo.

#Um jogador e MMO

As mensagens funcionam igual nos dois. Em um jogador o cliente e o host rodam em um só processo: NetworkClient.Send chega ao handler do host por uma conexão local, que o CommandPacing nunca limita. Como o host reinicia a cada troca de mapa, os handlers registrados a partir de ServerStarted são registrados de novo a cada vez, e é por isso que se usa ReplaceHandler.

#Erros comuns

  • Confiar em um id da mensagem. Um jogador envia o próprio nome ou id e o servidor age por outra pessoa. Use conn.identity.
  • Sem ritmo. Todo handler que um cliente pode acionar deve chamar CommandPacing.Allow.
  • Registrar só uma vez na inicialização. O host em um jogador reinicia; registre em ServerStarted e ClientConnected.
  • Enviar dados privados aos observadores. SendToReadyObservers chega a todos por perto.
  • Strings e arrays sem limite. Verifique os comprimentos antes de usá-los, e antes de guardá-los ou repassá-los.
  • Esquecer de recompilar o servidor de mapa depois de mudar uma mensagem.
