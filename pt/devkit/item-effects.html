Efeitos de itens

Como escrever seus próprios efeitos para itens consumíveis: a classe base ItemEffect, a interface IItemUser com que ela trabalha, como o uso de um item flui no servidor e exemplos completos.

#O que é um efeito de item

Um consumível (ConsumableData: poções, pergaminhos, comida) restaura vida e mana com seus próprios campos e depois executa uma lista de efeitos (ConsumableData.effects). O kit traz efeitos de experiência, níveis, aprender habilidades, pontos de atributo e de habilidade, reiniciar atributos, lançar uma habilidade, adicionar um estado e viajar. Qualquer outra coisa que um item deva fazer é uma nova classe de efeito.

Os efeitos são classes [Serializable] guardadas por referência com [SerializeReference, PickType]. Assim que a sua compila, ela aparece no menu de tipos + de Effects em todo Consumable em KitARPG > Game Database > Items.

Onde o arquivo fica: no assembly Game. Os tooltips no cliente também leem o efeito.

#A classe base

ItemEffect fica em Blunnyn.KitARPG.Data.

Membro O que faz Padrão
string Summary Texto curto no editor de itens e a linha padrão do tooltip. O nome da classe
string Check(IItemUser user) Servidor. Por que este usuário não pode usá-lo agora, ou null. Todo efeito do item é verificado antes de qualquer um rodar. null
void Use(IItemUser user, ItemData item) Servidor. Aplica o efeito. item é o que foi usado, para devolvê-lo se algo falhar depois. Obrigatório.
void Describe(ItemDescription description, IItemUser viewer) Linhas para o tooltip do item. viewer pode ser null (um tooltip no editor, ou do item de outro jogador). Adiciona Summary
void Visit(Action<GameData> visit) Entrega ao game database todo asset para o qual o efeito aponta. Nada

#O que acontece quando um jogador usa um item

  1. O cliente do dono pede (PlayerInventory.Use(slot), pela bolsa, pelo menu do item ou por um espaço da barra rápida).
  2. No servidor, PlayerInventory verifica seu próprio ritmo, que o espaço contém um item e que o item é usável (IUsable).
  3. Verifica a recarga do Cooldown Group do item (cooldownGroup, padrão potion).
  4. Chama ConsumableData.CheckUse(player): jogadores mortos não podem usar itens; depois o Check de cada efeito roda em ordem, e a primeira resposta que não for null para tudo. Essa resposta é mostrada sobre a cabeça do jogador.
  5. Um consumível sem efeitos só é usável enquanto restauraria alguma coisa.
  6. ConsumableData.Use restaura vida e mana e depois chama o Use de cada efeito em ordem.
  7. A recarga começa e um item é tirado da pilha.

Como todo Check roda antes de qualquer Use, um item com três efeitos faz os três ou nenhum. Coloque todo motivo de recusa em Check. Depois que Use roda, o item foi gasto.

#IItemUser

O jogador como os itens o veem. No servidor é o PlayerCharacter; no cliente, os tooltips recebem o jogador local.

Membro O que faz Onde
CharacterClass Class, int Level Classe e nível. Ambos
IReadOnlyList<string> WornItemIds Id do item em cada posição de equipamento, vazio onde nada está equipado. Ambos
bool IsDead, int Health, int MaxHealth, int Mana, int MaxMana Estado atual. Ambos
void RestoreHealth(int), void RestoreMana(int) Restaura. Servidor
long ExperienceToNext Experiência que ainda falta, 0 no nível máximo. Ambos
void GainExperience(long) Adiciona experiência, com subidas de nível. Servidor
void GainLevel() Sobe um nível, como se a experiência tivesse sido ganha. Servidor
void GainPoints(int attributePoints, int skillPoints) Adiciona pontos para gastar. Servidor
int SpentAttributePoints Pontos gastos até agora. Ambos
void ResetAttributes() Devolve todo ponto de atributo gasto. Servidor
string CanLearnSkill(SkillData, int rank), void LearnSkill(SkillData, int rank) Aprendizado de habilidade dentro das regras da habilidade. Verificar em ambos, aprender no servidor
string CanCastFromItem(SkillData), void CastFromItem(SkillData, int rank) Lança uma habilidade sem conhecê-la, sem custo de mana nem recarga. Verificar em ambos, lançar no servidor
void AddStatus(StatusData, int level, float seconds) Adiciona um estado. Servidor
void TravelTo(MapData, Vector3, ItemData refund) Leva o jogador a um mapa; devolve refund se a viagem falhar. Servidor

Para qualquer coisa que não esteja na interface, faça o cast para PlayerCharacter (namespace Blunnyn.KitARPG.Net) e use os componentes dele. O assembly Game referencia KitARPG.Net, então isto funciona:

if (!(user is PlayerCharacter player)) return;
var inventory = player.GetComponent<PlayerInventory>();

#Exemplo: o template

Create > KitARPG > Scripts > Item Effect cria um efeito de experiência. Veja Templates.

#Exemplo: bolsinha de ouro

Abre e dá uma quantia aleatória de ouro. Não pode ser aberto com a carteira cheia (Check recusa com "Your purse is full"); quando a carteira tem espaço mas não para tudo, ServerReceiveGold manda o resto para o banco.

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class GoldPouchEffect : ItemEffect
    {
        public int min = 50;
        public int max = 200;

        public override string Summary => $"{min}-{max} gold";

        public override string Check(IItemUser user)
        {
            if (!(user is PlayerCharacter player) || !player.TryGetComponent(out PlayerInventory inventory)) return "Nothing happens";
            return inventory.GoldRoom <= 0 ? "Your purse is full" : null;
        }

        public override void Use(IItemUser user, ItemData item)
        {
            var player = (PlayerCharacter)user;
            int amount = UnityEngine.Random.Range(min, max + 1);
            player.GetComponent<PlayerInventory>().ServerReceiveGold(amount);
            player.ServerAnnounce($"+{amount:N0} {GameInstance.Database.GoldName}", new Color(1f, 0.85f, 0.3f));
            GameLog.Write("mygame.gold_pouch", player, itemId: item.Id, gold: amount);
        }

        public override void Describe(ItemDescription description, IItemUser viewer) =>
            description.Add($"Holds {min:N0} to {max:N0} {GameInstance.Database?.GoldName ?? "Gold"}", ItemDescription.Kind.Effect);
    }
}

Check e Use rodam no servidor, então o cast é seguro ali. Describe nunca faz cast do viewer: ele pode ser null.

#Exemplo: voltar para a cidade

Manda o jogador para o mapa inicial do jogo. Se a viagem falhar, o pergaminho volta.

[Serializable]
public class RecallEffect : ItemEffect
{
    public override string Summary => "Recall to town";

    public override string Check(IItemUser user)
    {
        MapData town = GameInstance.Database != null ? GameInstance.Database.startMap : null;
        return town == null ? "Leads nowhere" : null;
    }

    public override void Use(IItemUser user, ItemData item)
    {
        MapData town = GameInstance.Database.startMap;
        user.TravelTo(town, town.startPosition, item);
    }

    public override void Describe(ItemDescription description, IItemUser viewer) =>
        description.Add("Takes you back to town", ItemDescription.Kind.Effect);
}

O TravelItemEffect do kit faz o mesmo para um mapa e uma posição fixos definidos no inspector.

#Exemplo: uma caixa de itens

Abre e dá cada item da sua lista, e não pode ser usado se alguma entrada não couber na bolsa. IPlayerActor (o jogador como as ações o veem) tem RoomFor e GiveItem; obtenha-o de PlayerCharacter.Facts.

[Serializable]
public class BoxEffect : ItemEffect
{
    [Serializable]
    public struct Entry
    {
        public ItemData item;
        public int amount;
    }

    public Entry[] contents = new Entry[0];

    public override string Summary => $"Box of {contents.Length}";

    public override string Check(IItemUser user)
    {
        if (!(user is PlayerCharacter player)) return "Nothing happens";
        foreach (Entry e in contents)
        {
            if (e.item == null) continue;
            string why = player.Facts.RoomFor(e.item, Mathf.Max(1, e.amount));
            if (why != null) return why;
        }
        return null;
    }

    public override void Use(IItemUser user, ItemData item)
    {
        IPlayerActor actor = ((PlayerCharacter)user).Facts;
        foreach (Entry e in contents)
            if (e.item != null) actor.GiveItem(e.item, Mathf.Max(1, e.amount));
    }

    public override void Describe(ItemDescription description, IItemUser viewer)
    {
        foreach (Entry e in contents)
            if (e.item != null) description.Add($"{e.item.DisplayName} x{Mathf.Max(1, e.amount)}", ItemDescription.Kind.Effect, e.item.Icon);
    }

    public override void Visit(Action<GameData> visit)
    {
        foreach (Entry e in contents) visit(e.item);
    }
}

RoomFor verifica cada entrada sozinha contra a bolsa atual. Várias entradas que cabem uma de cada vez podem não caber juntas; para uma verificação exata, teste a lista inteira com PlayerInventory.ServerRoomFor, ou dê os itens com GiveOrBank para que nada se perca nunca (veja Inventário e banco).

#Tooltips

Describe monta as linhas do tooltip. ItemDescription.Add(text, kind, icon) adiciona uma linha; os tipos são:

Tipo Usado para
Normal Texto comum.
Heading Um título de seção.
Effect O que o item faz.
Muted Detalhes secundários, como requisitos que o viewer cumpre.
Warning Requisitos que o viewer não cumpre.

Use o viewer para colorir os requisitos: Warning quando o jogador local não pode usar o item, Muted quando pode. Sempre trate viewer == null.

#Servidor e cliente

Roda em
Check, Use Servidor. O cliente nunca decide se um item funciona.
Describe, Summary Cliente (tooltips) e editor.

No modo um jogador, os dois lados rodam na mesma máquina, com o mesmo código.

#Outros tipos de itens usáveis

Os efeitos cobrem os consumíveis. Para um tipo de item totalmente novo, crie uma subclasse de ItemData (ou ConsumableData) e implemente as interfaces que se aplicam (IUsable, IConsumable, IEquippable). ConsumableData.CheckUse e Use são virtual. Para interferir em todo uso de item, sobrescreva PlayerInventory.UseItem em uma subclasse de PlayerInventory (veja Sobrescrevendo o comportamento do kit).

#Erros comuns

  • Recusar dentro de Use. A essa altura o item já foi gasto. Recuse em Check.
  • Ler viewer sem verificar null em Describe.
  • Dar itens com Inventory.Add direto no inventário. Passe por PlayerInventory (Give, GiveOrBank, ServerReceive) ou por IPlayerActor.GiveItem, para que a bolsa sincronize, o peso se atualize e o salvamento fique correto.
  • Esquecer Visit para itens, estados, mapas ou habilidades para os quais o efeito aponta.
  • Guardar estado em campos em tempo de execução. Uma instância de efeito serve todas as cópias do item para todos os jogadores.
