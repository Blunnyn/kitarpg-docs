Primeiros passos

Requisitos

O que você precisa no seu computador para usar o KitARPG, o que é opcional e para que serve cada peça. Leia antes de instalar para que nada pare você no meio do caminho.

#A versão curta

  • Para jogar a amostra no modo de um jogador: Unity 6.6 (6000.6.0f1) ou mais nova. Nada mais.
  • Para jogar a amostra como MMO no seu computador: o item acima mais o SDK do .NET 10.
  • Para implantar um MMO: os itens acima mais o suporte de build Linux Dedicated Server na Unity e uma máquina com Docker.

#Unity

Requisito Valor Observações
Versão da Unity 6000.6.0f1 (Unity 6.6) ou mais nova A versão mais baixa que o kit suporta. Versões mais antigas não o compilam
Pipeline de renderização Universal Render Pipeline 17.6 O Setup Wizard o ativa. Os materiais do kit são materiais URP e aparecem rosa sem ele
Espaço de cor Linear O Setup Wizard o define
TextMesh Pro essentials Importados no projeto O Setup Wizard os importa. Sem eles nenhum texto da interface do kit tem fonte
Active Input Handling Input System, Input Manager ou os dois O kit lê a entrada pela sua própria camada KitInput e funciona com qualquer um
Plataforma do editor macOS ou Windows As builds locais do servidor de mapa e os padrões do launcher são para Mac e Windows. A biblioteca SQLite do editor também vem para Linux

#Pacotes da Unity

O pacote do KitARPG declara os pacotes da Unity de que precisa. Quando você o importa, a Unity os instala para você, então um projeto vazio funciona.

Pacote Id Versão Usado para
Universal RP com.unity.render-pipelines.universal 17.6.0 Renderização
AI Navigation com.unity.ai.navigation 2.0.14 NavMesh para jogadores e monstros no servidor
uGUI com.unity.ugui 2.6.0 Toda a interface, com TextMesh Pro
Input System com.unity.inputsystem 1.20.0 Teclado, mouse e toque quando o projeto o usa
Test Framework com.unity.test-framework 1.8.0 Os testes de Play Mode do kit. Opcional: o kit ainda compila se você o remover

A rede é Mirror com o transporte KCP (UDP). O Mirror vem dentro do pacote, em Assets/Mirror; você não o instala separadamente.

#Pacotes e módulos opcionais da Unity

Item Necessário para Como obter
Multiplayer Play Mode 3.0 (com.unity.multiplayer.playmode) Play with two players (jogar com dois jogadores), que abre um segundo editor O botão oferece instalá-lo na primeira vez
Mac Build Support (IL2CPP) Clientes para Mac e jogos de um jogador para Mac Unity Hub > Installs > Add modules
Windows Build Support (IL2CPP) Clientes para Windows e jogos de um jogador para Windows Unity Hub > Installs > Add modules
Linux Dedicated Server Build Support (IL2CPP) Servidores de mapa Linux para Docker (KitARPG > Starter > Build Linux Server) Unity Hub > Installs > Add modules
com.unity.toolchain.macos-arm64-linux Gerar a build do servidor de mapa Linux a partir de um Mac Package Manager > Add package by name
Nota

Os clientes entregues aos jogadores são sempre gerados com IL2CPP. A verificação de build para um cliente MMO gerado com Mono, porque o código dele seria distribuído como DLLs legíveis. As builds IL2CPP para Windows são feitas no Windows, e as para Mac em um Mac. Veja Builds.

#Para MMO: o SDK do .NET 10

Login, Central, o Shop e o launcher são programas .NET 10. O editor os compila e roda para você, mas precisa do SDK.

Requisito Valor Observações
SDK do .NET 10.x Gratuito, em https://dotnet.microsoft.com/download/dotnet/10.0. Só o runtime não basta: o editor gera os serviços a partir do código-fonte

Onde o editor procura o dotnet, já que a Unity nem sempre recebe o PATH do seu shell:

  • Cada pasta do PATH.
  • Windows: C:\Program Files\dotnet\dotnet.exe.
  • Mac e Linux: /usr/local/share/dotnet/dotnet, /usr/local/bin/dotnet, /opt/homebrew/bin/dotnet, /usr/share/dotnet/dotnet e ~/.dotnet/dotnet.

Depois de instalar, pressione Check again abaixo da linha do SDK do .NET 10 em Play & Servers. Play & Servers mostra as versões que encontrou ("Installed: ...").

#Opcional: Docker

Item Necessário para
Docker Desktop (Mac, Windows) ou Docker Engine (Linux) Rodar o PostgreSQL no seu computador com um clique (Set up PostgreSQL... > Docker on this computer) e implantar com Docker Compose

Você não precisa do Docker para fazer seu jogo nem para jogar o MMO localmente: o SQLite funciona sem nada instalado.

#Opcional: PostgreSQL

O SQLite basta para desenvolver e para servidores pequenos. Para produção, use PostgreSQL. Qualquer servidor PostgreSQL funciona: um no seu computador, em um VPS ou um hospedado como RDS, Supabase ou Neon. Com Docker, o kit roda o PostgreSQL 17 para você. Veja Banco de dados.

#Portas usadas no seu computador

Quando você roda o MMO localmente, estas portas precisam estar livres. Play & Servers avisa quando outra coisa as ocupa.

Porta Protocolo Usada por
5100 TCP (HTTP) Login
5200 TCP (HTTP) Central
5300 TCP (HTTP) Shop (só quando ele roda)
7700 UDP O link de mapas do Central, ao qual os servidores de mapa se conectam
7777 UDP Servidor de mapa de town
7778 UDP Servidor de mapa de forest
7779 UDP Servidor de mapa de crypt
5432 em diante TCP PostgreSQL no Docker, na primeira porta livre a partir de 5432

#Hardware

O kit não tem necessidades especiais de hardware além do que a Unity 6.6 pede. Tenha em mente:

  • A primeira build do servidor de mapa leva alguns minutos; as seguintes são mais rápidas.
  • Play with two players roda um segundo editor da Unity, que usa mais ou menos tanta memória quanto o primeiro. Na primeira vez que abre, ele importa o projeto.
  • No MMO cada mapa em execução é um processo próprio. A amostra inicia town com os serviços, e forest e crypt quando um jogador entra neles pela primeira vez.

#Para os jogadores do seu jogo

Build Os jogadores precisam de
Um jogador Nada mais. O salvamento é um arquivo SQLite na pasta de dados do jogador
Cliente MMO Uma conexão de rede com os endereços do seu Login e do seu Central (HTTPS) e com as portas UDP dos servidores de mapa
