Primeiros passos

Estrutura do projeto

Onde fica cada parte do KitARPG no seu projeto e no disco, quais pastas você pode editar, quais pertencem ao kit e quais nunca saem do seu computador. Leia antes de começar a adicionar seu próprio conteúdo, para que as atualizações nunca sobrescrevam seu trabalho.

#A visão geral

YourWorkspace/
├── YourUnityProject/
│   ├── Assets/
│   │   ├── Blunnyn/
│   │   │   ├── KitARPG/          The kit (read-only for you)
│   │   │   └── Art/              The kit's voxel art
│   │   ├── Mirror/               Networking library
│   │   ├── ScriptTemplates/      Mirror's script templates
│   │   ├── Settings/             URP assets and KitARPGSettings
│   │   └── Game/                 Your game (you make this folder)
│   └── UserSettings/
│       └── KitARPG/              This computer only: keys, local database, logs
└── Builds/
    ├── Starter/                  Builds made from the KitARPG menus
    └── ...

A pasta Builds fica ao lado da pasta do seu projeto da Unity, não dentro dela.

#O kit: Assets/Blunnyn/KitARPG/

Pasta O que tem dentro
Runtime/Shared/ C# puro sem Unity, compartilhado com os serviços .NET: regras de conta e de personagem, regras de inventário, mensagens para o Central, códigos de erro. Assembly KitARPG.Shared
Runtime/Data/ Assets de dados e suas regras: classes, atributos, itens, habilidades, estados, monstros, missões, condições, ações, mapas, GameDatabase, GameInstance. Assembly KitARPG.Data
Runtime/Net/ Tudo o que está na rede com Mirror: jogadores, monstros, NPCs, combate, chat, guildas, o registro do jogo, o network manager. Assembly KitARPG.Net
Runtime/Server/ Só do servidor de mapa: o link com o Central, comandos de GM, instâncias, recompensas, o cliente do Shop. Assembly KitARPG.Server, deixado de fora das builds de cliente MMO
Runtime/Local/ O salvamento de um jogador em SQLite. Assembly KitARPG.Local, só nas builds de um jogador
Runtime/Client/ Interface, janelas, HUD, tela de título, sessão, entrada (KitInput), controles de toque, opções. Assembly KitARPG.Client
Runtime/Resources/KitARPG/ Recursos que o kit carrega pelo nome, como o Animator controller do personagem KitCharacter.controller
Modes/TopDown/ O modo top-down: Runtime (câmera e entrada) e Server (movimento e ações no servidor)
Modes/ThirdPerson/ Os modos de terceira pessoa e câmera livre, divididos do mesmo jeito
Editor/ A janela KitARPG e suas páginas, o Setup Wizard, Game Database, Project Check, ferramentas de build, o gerador da amostra inicial e as atualizações do kit. Assembly KitARPG.Editor
DevKit/Example/Bounties/ O exemplo do quadro de recompensas, feito como um jogo seria feito, com seus próprios assemblies
Samples/Starter/ A amostra inicial (veja abaixo)
Tests/PlayMode/ Os testes de Play Mode do kit. Assembly KitARPG.Tests.PlayMode, nunca nas builds
Plugins/LiteNetLib/ A biblioteca que os servidores de mapa usam para falar com o Central
Plugins/SQLite/ A biblioteca nativa do SQLite para macOS, Windows e Linux, usada pelo salvamento de um jogador
Documentation/ Esta documentação como site em Web/ (aberto por KitARPG > Documentation), GettingStarted.md, DevKit.md, CHANGELOG.md, a referência da API em API/ e o manual em PDF
Services.zip Os serviços .NET como código-fonte, como vêm no pacote
Services~/ O Services.zip descompactado pelo editor. A Unity não o importa

#Assemblies

Assembly Vai para
KitARPG.Shared, KitARPG.Data, KitARPG.Net, KitARPG.Client Todas as builds
KitARPG.Modes.TopDown, KitARPG.Modes.ThirdPerson Todas as builds
KitARPG.Server, KitARPG.Modes.TopDown.Server, KitARPG.Modes.ThirdPerson.Server Só servidores de mapa e jogos de um jogador
KitARPG.Local Só jogos de um jogador
KitARPG.Editor Só o editor
KitARPG.Tests.PlayMode Só o editor, com os testes ativos

KitARPG > Check Build Separation mostra qual código vai para cada tipo de build. Veja Assemblies.

#A amostra inicial: Samples/Starter/

Pasta ou arquivo O que tem dentro
Scenes/ Title.unity, Server.unity, Town.unity, Forest.unity, Crypt.unity, mais uma pasta por cena de mapa com seus dados de iluminação e NavMesh
Prefabs/ KitNetwork.prefab (o network manager com o GameInstance que guarda o Game Settings), GameHud.prefab, TouchControls.prefab, os prefabs de jogador PlayerMale, PlayerFemale e PlayerPanda, os prefabs de monstros e UI/ com as peças de UI reutilizáveis
Data/ Todos os assets de dados do jogo: StarterDatabase.asset, Attributes/, Classes/, Currencies/, Elements/, Items/, Skills/, Statuses/, WeaponTypes/, Monsters/, Quests/, Shops/, Maps/, Guilds/, as configurações de câmera, a tabela de experiência, os emblemas de guilda, a arte da loja e a máscara da parte superior do corpo
Effects/ Efeitos de partículas para golpes, lançamentos, projéteis, áreas e estados
Materials/ Materiais dos mapas da amostra
StarterAppearance.asset O catálogo de malhas de corpos, cabelos e equipamentos para os personagens modulares
Cena Papel
Title Login, lista e criação de personagens. Precisa ser a primeira em Build Settings
Server A cena vazia em que um servidor de mapa começa antes de carregar seu mapa. Necessária no MMO
Town O mapa inicial: lojas, quem dá missões, banqueiro, serviços de guilda
Forest Monstros, um chefe, aparições de dia e de noite
Crypt A Sunken Crypt, uma masmorra instanciada
Atenção

Start over em Overview e KitARPG > Starter > Build Scenes and Prefabs geram a amostra de novo a partir do código do kit e perdem toda mudança feita dentro de Samples/Starter/. Importar um kit mais novo também pode substituir arquivos ali. Copie antes para a sua própria pasta o que você quer mudar. Veja Atualizar o kit.

#Configurações do projeto que o kit usa

Caminho O que é
Assets/Settings/Resources/KitARPGSettings.asset Como o jogo roda: mode (MMO ou um jogador), loginUrl e centralUrl para as builds, saveFile para um jogador. Criado se não existir
Assets/Settings/KitARPG_URP.asset O asset URP que o Setup Wizard cria quando o projeto não tem nenhum

Campos de KitARPGSettings:

Campo O que faz Padrão
Mode (mode) Online (MMO) ou SinglePlayer. Play & Servers e o Setup Wizard o definem; as builds o definem conforme o tipo de build Online
Login Url (loginUrl) O endereço do Login que os clientes MMO usam http://127.0.0.1:5100
Central Url (centralUrl) O endereço do Central que os clientes MMO usam http://127.0.0.1:5200
Save File (saveFile) O salvamento de um jogador, na pasta de dados persistentes do jogador savegame.db
Importante

Antes de gerar a build de um cliente MMO para os jogadores, defina Login Url e Central Url com os endereços https:// dos seus servidores. Um cliente de release recusa HTTP simples, exceto para este computador, e a build para se eles não forem HTTPS.

#Só deste computador: UserSettings/KitARPG/

A Unity nunca coloca UserSettings nas builds, e o controle de versão normalmente o ignora. Tudo aqui é específico do seu computador.

Arquivo ou pasta O que é
setup-done O Setup Wizard rodou
seen-version A última versão do kit que este projeto abriu, para o What's New
launcher.json As configurações do launcher que Play & Servers usa: portas, banco de dados, mapas, chaves
launcher.pid O launcher em execução, para o editor encontrá-lo depois de reiniciar
services.log Saída dos serviços iniciados pelo editor
data/kitarpg.db O banco de dados SQLite local do MMO: contas, personagens, itens, guildas, correio
data/logs/map-<id>.log O log de cada servidor de mapa
quickplay.json Contas de teste para Play with two players
shop-conf.json O catálogo local da loja
shop.log, shop.pid O serviço Shop iniciado pelo editor
modules/ Módulos para Login (login/) e Central (central/) carregados pelo launcher local
Importante

launcher.json guarda a chave de assinatura e a chave de mapas. Não faça commit dele nem o compartilhe.

#Onde fica o seu jogo

Mantenha tudo o que você faz fora de Assets/Blunnyn:

Assets/Game/
├── Game.asmdef           Create > KitARPG > Scripts > Game Assembly
├── Data/                 Your items, skills, monsters, quests, maps
├── Prefabs/              Your player models, monsters, HUD copy
├── Scenes/               Your maps
├── Scripts/              Your code
└── Editor/               Game Editor Assembly and your tools

Passos:

  1. Crie uma pasta como Assets/Game.
  2. Para escrever código, clique nela com o botão direito e escolha Create > KitARPG > Scripts > Game Assembly. Os scripts ali enxergam o kit.
  3. Crie dados novos com os botões New do Game Database e depois mova os assets para a sua pasta, ou duplique assets da amostra e mova as cópias.
  4. Para seus próprios mapas, duplique Forest.unity na sua pasta e adicione uma entrada de mapa. Veja Mapas.

Os ids não dependem de nomes de arquivo nem de pastas depois de criados, então mover assets é seguro.
