Project structure

Esta página ainda não foi traduzida. Ela aparece em inglês.

Where every part of KitARPG lives in your project and on disk, which folders you may edit, which belong to the kit, and which never leave your computer. Read it before you start adding your own content, so updates never overwrite your work.

#The big picture

YourWorkspace/
├── YourUnityProject/
│   ├── Assets/
│   │   ├── Blunnyn/
│   │   │   ├── KitARPG/          The kit (read-only for you)
│   │   │   └── Art/              The kit's voxel art
│   │   ├── Mirror/               Networking library
│   │   ├── ScriptTemplates/      Mirror's script templates
│   │   ├── Settings/             URP assets and KitARPGSettings
│   │   └── Game/                 Your game (you make this folder)
│   └── UserSettings/
│       └── KitARPG/              This computer only: keys, local database, logs
└── Builds/
    ├── Starter/                  Builds made from the KitARPG menus
    └── ...

The Builds folder sits next to your Unity project folder, not inside it.

#The kit: Assets/Blunnyn/KitARPG/

Folder What is in it
Runtime/Shared/ Plain C# without Unity, shared with the .NET services: account and character rules, inventory rules, messages to Central, error codes. Assembly KitARPG.Shared
Runtime/Data/ Data assets and their rules: classes, attributes, items, skills, statuses, monsters, quests, conditions, actions, maps, GameDatabase, GameInstance. Assembly KitARPG.Data
Runtime/Net/ Everything on the network with Mirror: players, monsters, NPCs, combat, chat, guilds, the game log, the network manager. Assembly KitARPG.Net
Runtime/Server/ Map server only: the link to Central, GM commands, instances, rewards, the Shop client. Assembly KitARPG.Server, left out of MMO client builds
Runtime/Local/ The single player save in SQLite. Assembly KitARPG.Local, only in single player builds
Runtime/Client/ Interface, windows, HUD, title screen, session, input (KitInput), touch controls, options. Assembly KitARPG.Client
Runtime/Resources/KitARPG/ Resources the kit loads by name, such as the character Animator controller KitCharacter.controller
Modes/TopDown/ The top-down mode: Runtime (camera and input) and Server (movement and actions on the server)
Modes/ThirdPerson/ The third person and free camera modes, split the same way
Editor/ The KitARPG window and its pages, the Setup Wizard, Game Database, Project Check, build tools, the starter sample builder and the kit updates. Assembly KitARPG.Editor
DevKit/Example/Bounties/ The bounty board example, built as a game would be, with its own assemblies
Samples/Starter/ The starter sample (see below)
Tests/PlayMode/ The kit's Play mode tests. Assembly KitARPG.Tests.PlayMode, never in builds
Plugins/LiteNetLib/ The library map servers use to talk to Central
Plugins/SQLite/ The native SQLite library for macOS, Windows and Linux, used by the single player save
Documentation/ GettingStarted.md, DevKit.md, CHANGELOG.md, the API reference in API/ and the PDF manual
Services.zip The .NET services as source, as shipped in the package
Services~/ Services.zip unpacked by the editor. Unity doesn't import it

#Assemblies

Assembly Goes into
KitARPG.Shared, KitARPG.Data, KitARPG.Net, KitARPG.Client Every build
KitARPG.Modes.TopDown, KitARPG.Modes.ThirdPerson Every build
KitARPG.Server, KitARPG.Modes.TopDown.Server, KitARPG.Modes.ThirdPerson.Server Map servers and single player games only
KitARPG.Local Single player games only
KitARPG.Editor The editor only
KitARPG.Tests.PlayMode The editor only, with tests on

KitARPG > Check Build Separation shows which code goes into each kind of build. See Assemblies.

#The starter sample: Samples/Starter/

Folder or file What is in it
Scenes/ Title.unity, Server.unity, Town.unity, Forest.unity, Crypt.unity, plus a folder per map scene with its lighting and NavMesh data
Prefabs/ KitNetwork.prefab (the network manager with the GameInstance that holds Game Settings), GameHud.prefab, TouchControls.prefab, the player prefabs PlayerMale, PlayerFemale and PlayerPanda, the monster prefabs and UI/ with the reusable UI pieces
Data/ Every game data asset: StarterDatabase.asset, Attributes/, Classes/, Currencies/, Elements/, Items/, Skills/, Statuses/, WeaponTypes/, Monsters/, Quests/, Shops/, Maps/, Guilds/, the camera settings, the experience table, guild emblems, shop art and the upper body mask
Effects/ Particle effects for hits, casts, projectiles, areas and statuses
Materials/ Materials of the sample maps
StarterAppearance.asset The catalog of bodies, hair and gear meshes for the modular characters
Scene Role
Title Login, character list and creation. Must be first in Build Settings
Server The empty scene a map server starts in before it loads its map. Needed in MMO
Town The start map: shops, quest givers, banker, guild services
Forest Monsters, a boss, day and night spawns
Crypt The Sunken Crypt, an instanced dungeon
Atenção

Start over in Overview and KitARPG > Starter > Build Scenes and Prefabs build the sample again from the kit's code and lose every change made inside Samples/Starter/. Importing a newer kit can also replace files there. Copy what you want to change into your own folder first. See Updating the kit.

#The art: Assets/Blunnyn/Art/

Folder What is in it
3D/VoxelHero/ Voxel bodies (VoxelMale, VoxelFemale, VoxelPanda), Gear/ (hair, hats, chests, backs, gloves, legs, boots, weapons), Monsters/, and the shared VoxelHero.mat with its palette textures
3D/HumanModel/ A second, non-voxel human model with its own gear
Anims/ The humanoid character animations (Little Heroes Mega Pack) and Humanoid.controller
Sprites/ Icons/ for items, skills, elements, stats and categories, guild Emblems/, Shop/ art and UI sprites

#Project settings the kit uses

Path What it is
Assets/Settings/Resources/KitARPGSettings.asset How the game runs: mode (MMO or single player), loginUrl and centralUrl for builds, saveFile for single player. Created if missing
Assets/Settings/KitARPG_URP.asset The URP asset the Setup Wizard creates when the project has none

KitARPGSettings fields:

Field What it does Default
Mode (mode) Online (MMO) or SinglePlayer. Play & Servers and the Setup Wizard set it; builds set it for the kind of build Online
Login Url (loginUrl) The Login address MMO clients use http://127.0.0.1:5100
Central Url (centralUrl) The Central address MMO clients use http://127.0.0.1:5200
Save File (saveFile) The single player save, in the player's persistent data folder savegame.db
Importante

Before building an MMO client for players, set Login Url and Central Url to your servers' https:// addresses. A release client refuses plain HTTP except to this computer, and the build stops if they aren't HTTPS.

#This computer only: UserSettings/KitARPG/

Unity never puts UserSettings in builds, and version control usually ignores it. Everything here is specific to your computer.

File or folder What it is
setup-done The Setup Wizard ran
seen-version The last kit version this project opened, for What's New
launcher.json The launcher settings Play & Servers uses: ports, database, maps, keys
launcher.pid The running launcher, so the editor finds it after a restart
services.log Output of the services started from the editor
data/kitarpg.db The local SQLite database of the MMO: accounts, characters, items, guilds, mail
data/logs/map-<id>.log Each map server's log
quickplay.json Test accounts for Play with two players
shop-conf.json The local shop catalog
shop.log, shop.pid The Shop service started from the editor
modules/ Modules for Login (login/) and Central (central/) loaded by the local launcher
Importante

launcher.json holds the signing key and the map key. Don't commit it or share it.

#The services: Services~/

Folder What is in it
Shared/ Compiles Runtime/Shared so the rules exist once
Data/ Database entities, one context per provider (SQLite and PostgreSQL) and their migrations
Hosting/ Settings shared by the services: tokens, bans, game log writer
Modules/ The contract for Login and Central modules
Login/ Accounts and characters
Central/ Sessions, tickets, maps, social systems
Shop/ The optional premium shop service
Launcher/ Starts everything, with a window or headless
Examples/Bounties/ The Central side of the bounty board example
Tests/ Tests of rules, Login and Central
KitARPG.Services.slnx The solution
README.md Endpoints, settings and production security

See Services.

#Where your game goes

Keep everything you make outside Assets/Blunnyn:

Assets/Game/
├── Game.asmdef           Create > KitARPG > Scripts > Game Assembly
├── Data/                 Your items, skills, monsters, quests, maps
├── Prefabs/              Your player models, monsters, HUD copy
├── Scenes/               Your maps
├── Scripts/              Your code
└── Editor/               Game Editor Assembly and your tools

Steps:

  1. Create a folder such as Assets/Game.
  2. To write code, right click it and pick Create > KitARPG > Scripts > Game Assembly. Scripts there see the kit.
  3. Make new data with the Game Database's New buttons, then move the assets into your folder, or duplicate sample assets and move the copies.
  4. For your own maps, duplicate Forest.unity into your folder and add a map entry. See Maps.

Ids don't depend on file names or folders once made, so moving assets is safe.
