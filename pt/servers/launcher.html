Servidores e implantação

Lançador

O KitARPG Launcher inicia o Login, a Central, os servidores de mapa e, se você quiser, o Shop com um botão ou um comando. Esta página cobre a janela, a linha de comando, cada campo do launcher.json e como rodá-lo em um servidor.

#O que é

O lançador é um pequeno programa .NET 10 em Services/Launcher (dentro de Assets/Blunnyn/KitARPG/Services~ no pacote da Asset Store), feito com Avalonia para que a janela funcione no Windows, no macOS e no Linux. Ele:

  • encontra os serviços compilados e a build do seu servidor de mapa;
  • cria chaves secretas novas para esta instalação na primeira execução;
  • inicia o Login, depois a Central (que inicia os servidores de mapa) e o Shop quando pedido;
  • mostra a saída deles e os jogadores em cada mapa;
  • para tudo junto.

KitARPG > Play and Servers usa o mesmo lançador sem janela: Start services o executa com --headless --config UserSettings/KitARPG/launcher.json. Na maior parte do tempo você nunca abre o lançador por conta própria. Veja Play & Servers.

#Antes da primeira execução

  1. Compile os serviços: dotnet build na pasta Services, ou Build services em Play & Servers.
  2. Gere um servidor de mapa para o seu computador: KitARPG > Starter > Build Mac Server ou Build Windows Server. Veja Builds.
  3. Exporte os dados do jogo para que o Login possa criar personagens. Play & Servers faz isso cada vez que inicia os serviços. Se você rodar o lançador por conta própria, defina GameDataFile ou use KitARPG > Export Game Data for Services.

#A janela

cd Services
dotnet run --project Launcher

A janela mostra KitARPG, um botão Start, uma linha de status, os mapas com seus jogadores, uma caixa de seleção Premium shop e o log de cada serviço.

  • Start inicia o conjunto; o botão vira Stop.
  • A linha de status diz Running. Open the Title scene or the client build to play. enquanto ele roda.
  • Premium shop liga ShopEnabled e ShopAutoStart juntos: o Shop inicia e para com o resto, e os mapas que a Central inicia recebem o endereço e a chave dele.

Fechar a janela para tudo.

#Linha de comando

Argumentos O que faz
(nenhum) Abre a janela
--headless Roda o mesmo conjunto no terminal, com a saída de cada serviço na saída padrão. Ctrl+C ou SIGTERM para tudo
--config <file> Usa outro launcher.json em vez do que está ao lado do lançador. Funciona com ou sem --headless
--headless --shop-only Roda só o Shop. A página Shop do editor o inicia e para assim, separado do resto
--postgres Verifica ou cria um banco de dados PostgreSQL. Lê uma requisição JSON na entrada padrão e imprime uma resposta JSON. Veja Verificar o PostgreSQL 
dotnet run --project Launcher                                    # window
dotnet run --project Launcher -- --headless                      # terminal
dotnet run --project Launcher -- --headless --config my.json     # another settings file
dotnet run --project Launcher -- --headless --shop-only --config my.json

Com --headless, o lançador primeiro imprime cada problema que encontra, cada linha começando com !, depois inicia o que puder e imprime os endereços do Login e da Central. Com --shop-only, um problema o faz parar com código de saída 1.

#launcher.json

O lançador lê o launcher.json ao lado dele, ou o arquivo passado com --config. Um arquivo que não existe é criado. Os campos vazios são preenchidos e o arquivo é salvo de novo a cada início, então você só escreve o que quer mudar.

Campo O que faz Padrão
LoginDll Caminho para KitARPG.Services.Login.dll Encontrado: uma pasta Login ao lado do lançador, ou Login/bin/Debug/net10.0 em uma pasta acima
CentralDll Caminho para KitARPG.Services.Central.dll Encontrado do mesmo jeito
ShopDll Caminho para KitARPG.Services.Shop.dll Encontrado do mesmo jeito
MapServerExecutable A build do seu servidor de mapa Encontrada em uma pasta acima: Builds/Starter/MacServer/KitARPGServer.app/Contents/MacOS/Unity no macOS, Builds/Starter/WindowsServer/KitARPGServer.exe no Windows
DataFolder Onde ficam o banco de dados SQLite e os logs dos mapas data ao lado do launcher.json
ModulesFolder Módulos do jogo: o Login carrega login/, a Central carrega central/ modules ao lado do launcher.json (as duas subpastas são criadas vazias)
DatabaseProvider Sqlite ou Postgres Sqlite
ConnectionString Conexão do PostgreSQL, usada só com Postgres. Com Sqlite, o arquivo é DataFolder/kitarpg.db Vazio
Maps Os mapas que a Central conhece: Id, Port, AutoStart town 7777 (inicia com a Central), forest 7778, crypt 7779, guild_hall 7780; Play & Servers adiciona todos os outros mapas do banco de dados do jogo na próxima porta livre
ExternalMaps Ids de mapas que outra coisa roda, como o editor em Play. A Central espera que eles se registrem em vez de iniciá-los Vazio
GameDataFile O gamedata.json que o Login lê Vazio: o que está ao lado do serviço Login
LoginPort Porta HTTP do Login 5100
CentralPort Porta HTTP da Central 5200
MapLinkPort Porta UDP da Central para os servidores de mapa 7700
SigningKey Chave de assinatura de tokens do Login e da Central 64 caracteres hexadecimais aleatórios, criados na primeira execução
MapKey Chave que os servidores de mapa apresentam à Central 32 caracteres hexadecimais aleatórios, criados na primeira execução
ShopPort Porta HTTP do Shop 5300
ShopMapKey Chave que os servidores de mapa enviam ao Shop como X-Shop-Key 32 caracteres hexadecimais aleatórios, criados na primeira execução
ShopAdminKey Chave da API de administração do Shop (X-Admin-Key), com a qual o editor publica o catálogo 32 caracteres hexadecimais aleatórios, criados na primeira execução
ShopCatalogFile O arquivo de catálogo do Shop. Se não existir, o exemplo ao lado do serviço Shop é copiado para lá shop-conf.json ao lado do launcher.json
ShopEnabled A Central recebe KITARPG_SHOP_URL e KITARPG_SHOP_KEY, e os servidores de mapa que ela inicia os herdam false
ShopAutoStart O Shop inicia e para com o Login e a Central false

Um mapa que o exemplo ganhou em uma atualização do kit (por exemplo crypt) é adicionado a um arquivo mais antigo, a menos que o id ou a porta dele já estejam em uso.

Exemplo:

{
  "DatabaseProvider": "Postgres",
  "ConnectionString": "Host=localhost;Port=5432;Database=kitarpg;Username=kitarpg;Password=...",
  "Maps": [
    { "Id": "town", "Port": 7777, "AutoStart": true },
    { "Id": "forest", "Port": 7778, "AutoStart": false },
    { "Id": "crypt", "Port": 7779, "AutoStart": false },
    { "Id": "guild_hall", "Port": 7780, "AutoStart": false }
  ],
  "ExternalMaps": [ "forest" ],
  "ShopEnabled": true,
  "ShopAutoStart": true
}
Importante

O launcher.json guarda a chave de assinatura, a chave dos mapas e as chaves do Shop em texto puro. Mantenha-o fora do controle de versão e fora das builds. O editor guarda a cópia dele em UserSettings/KitARPG/, que o Unity nunca inclui nas builds.

#O que ele inicia, e como

O lançador inicia cada serviço com dotnet <dll>, a partir da pasta da dll, e passa as configurações como variáveis de ambiente.

  1. Login com ASPNETCORE_URLS=http://127.0.0.1:<LoginPort>, as configurações do banco de dados, Auth__SigningKey, Modules__Path=<ModulesFolder>/login e, quando definido, Characters__GameDataFile.
  2. Uma pausa de 1,5 segundo, para que o Login rode as migrações do banco de dados primeiro.
  3. Shop, com ShopAutoStart: ASPNETCORE_URLS=http://127.0.0.1:<ShopPort>, ASPNETCORE_ENVIRONMENT=Production, as configurações do banco de dados, Shop__CatalogPath, Shop__MapKeys__0=<ShopMapKey>, Shop__AdminKey.
  4. Central com ASPNETCORE_URLS=http://127.0.0.1:<CentralPort>, as configurações do banco de dados, Auth__SigningKey, Central__MapLinkPort, Central__MapKey, Modules__Path=<ModulesFolder>/central e um grupo Central__Maps__N__* por mapa:
    • Executable: MapServerExecutable, ou vazio para um mapa externo;
    • Port e AutoStart (sempre desligado para um mapa externo);
    • Arguments: -batchmode -nographics -map {map} -port {port} -central {central} -logFile <DataFolder>/logs/map-{map}.log. Com ShopEnabled, a Central também recebe KITARPG_SHOP_URL e KITARPG_SHOP_KEY, que chegam a todos os mapas que ela inicia.

A Central inicia os mapas com AutoStart na hora e os outros quando o primeiro jogador precisa deles. Os serviços escutam só em 127.0.0.1, então nada do que o lançador inicia é acessível de outros computadores.

Cada linha de saída aparece com o nome do serviço entre colchetes, como [Login] ou [Central]. Os servidores de mapa escrevem em <DataFolder>/logs/map-<id>.log.

#Rodar um mapa no editor

Para depurar um mapa no editor do Unity enquanto o resto roda pelo lançador:

  1. Adicione o id do mapa a ExternalMaps (Play & Servers faz isso com Map in the editor).
  2. Inicie os serviços. A Central espera esse mapa se registrar em vez de iniciar a build.
  3. Dê Play no servidor de mapa no editor. Ele se registra na Central como uma build faria.

#Verificar o PostgreSQL

--postgres é como a janela Set up PostgreSQL do editor conversa com o PostgreSQL. Ele lê uma requisição JSON da entrada padrão:

Campo O que é Padrão
action check testa o login do jogo; create cria o banco de dados e o usuário com um login de administrador check
host Endereço do servidor localhost
port Porta do servidor 5432
ssl Prefer, Require ou Disable Prefer
database O banco de dados do jogo kitarpg
user O usuário do jogo kitarpg
password A senha do usuário do jogo Vazio
adminUser Login de administrador, só para create postgres
adminPassword Senha de administrador, só para create. Nunca é salva Vazio
adminDatabase Banco de dados ao qual o administrador se conecta primeiro postgres 
echo '{"action":"check","host":"localhost","port":5432,"database":"kitarpg","user":"kitarpg","password":"..."}' \
  | dotnet run --project Launcher -- --postgres

Ele imprime { "Ok": true|false, "Message": "...", "ConnectionString": "..." }. check também confirma que o usuário pode criar tabelas. create cria o papel e o banco de dados (de propriedade desse papel), concede a ele tudo o que precisa e funciona em servidores hospedados onde o administrador não é superusuário. Veja Banco de dados.

#Só um computador

O lançador foi feito para rodar tudo em um computador:

  • Login, Central e Shop escutam só em 127.0.0.1.
  • Os servidores de mapa que ele inicia não recebem -address, então anunciam o endereço em que a Central os vê, que é 127.0.0.1. Um jogador em outro computador seria mandado para lá.
  • Nada coloca HTTPS na frente dos serviços.

Para um servidor que os jogadores acessam pela internet, use o Docker Compose, que adiciona o Caddy para HTTPS e dá a cada mapa seu endereço público. Veja Docker.

#Dicas

  • Use um launcher.json por configuração (SQLite para testes rápidos, PostgreSQL para homologação) e troque com --config.
  • Depois de recompilar um serviço ou o servidor de mapa, reinicie o lançador. Play & Servers avisa quando os serviços em execução são mais antigos que as builds deles.
  • Se as portas estiverem em uso, provavelmente outro lançador ainda está rodando. Pare-o, ou mude as portas no launcher.json.

#Erros comuns

  • "Login service not found." Os serviços não estão compilados, ou LoginDll aponta para um caminho antigo. Compile-os, ou limpe o campo para que ele seja encontrado de novo.
  • "Map server not found." Gere o servidor de mapa para este computador, ou defina MapServerExecutable.
  • "DatabaseProvider is Postgres but ConnectionString is empty." Preencha a string de conexão ou volte para Sqlite.
  • Mudar as chaves à mão com os mapas rodando. Os servidores de mapa mantêm a chave com que iniciaram. Reinicie o conjunto inteiro depois de mudar as chaves.
