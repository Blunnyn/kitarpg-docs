Servidores e implantação

Docker

Rode o jogo online inteiro em uma máquina com Docker Compose: PostgreSQL, Caddy para HTTPS, Login, Central, um contêiner por mapa e o Shop opcional. Esta página cobre cada serviço do arquivo compose, o arquivo .env, a implantação em uma VPS passo a passo, como adicionar mapas e servidores de mapa em outras máquinas, atualizações e comandos do dia a dia.

#O que há na pasta Deploy

A pasta Deploy fica ao lado da pasta do seu projeto Unity e da pasta Services. O arquivo compose gera as imagens dos serviços a partir da pasta acima de Deploy, então ele espera esta estrutura:

<your folder>/
  Deploy/            docker-compose.yml, .env, Caddyfile, Dockerfiles
    builds/starter/  the Linux map server build
    modules/login/   Login modules (optional)
    modules/central/ Central modules (optional)
    shop/            the Shop's catalog file (with the shop profile)
  Services/          the .NET services
  Unity/             your Unity project (the shared code in Assets/Blunnyn/KitARPG/Runtime/Shared)
Arquivo O que é
docker-compose.yml A stack
.env.example Todas as variáveis de que a stack precisa, com valores de exemplo. Copie-o para .env
Caddyfile As rotas do Caddy: HTTPS para o Login, a Central e os webhooks do Shop
Services.Dockerfile Gera o Login, a Central ou o Shop (--build-arg SERVICE=Login) a partir da imagem do SDK do .NET 10 para a imagem de runtime do ASP.NET 10, rodando como usuário não root na porta 8080
MapServer.Dockerfile Empacota uma build Linux do servidor de mapa em uma imagem Ubuntu 24.04, rodando como o usuário kit (uid 1001), com -batchmode -nographics -logFile -
Nota

O Services.Dockerfile copia Services/ e Unity/Assets/Blunnyn/KitARPG/Runtime/Shared/ da pasta acima de Deploy. Se a pasta do seu projeto Unity tiver outro nome, altere essa linha COPY para corresponder.

#Os serviços do arquivo compose

Serviço Imagem Portas no host Volumes Observações
caddy caddy:2.10-alpine 80/tcp, 443/tcp, 443/udp Caddyfile (somente leitura), caddy-data, caddy-config Obtém e renova os certificados TLS. Endereço fixo KITARPG_PROXY_ADDRESS na rede do compose
postgres postgres:17-alpine Nenhuma pgdata Banco de dados kitarpg, usuário kitarpg, senha POSTGRES_PASSWORD. Saúde verificada com pg_isready
login kitarpg/login 127.0.0.1:5100 → 8080 modules/login (somente leitura) Espera o PostgreSQL ficar saudável
central kitarpg/central 127.0.0.1:5200 → 8080 modules/central (somente leitura) O link do mapa (UDP 7700) fica na rede do compose
shop kitarpg/shop 127.0.0.1:5300 → 5300 Pasta shop Somente com --profile shop
map-town kitarpg/map-server 7777/udp Nenhum -map town -port 7777 -central central:7700
map-forest kitarpg/map-server 7778/udp Nenhum -map forest -port 7778
map-crypt kitarpg/map-server 7779/udp Nenhum -map crypt -port 7779
map-guild-hall kitarpg/map-server 7780/udp Nenhum -map guild_hall -port 7780

As imagens de mapa são geradas para linux/amd64. Os quatro serviços de mapa compartilham uma imagem gerada a partir de builds/starter; só o comando deles muda.

O que o arquivo compose define nos serviços:

  • Login e Central: Database__Provider=Postgres, a connection string com POSTGRES_PASSWORD, Auth__SigningKey=KITARPG_SIGNING_KEY, Proxy__Enabled=true e Proxy__KnownProxies__0 com o endereço do Caddy.
  • Somente a Central: Central__MapKey=KITARPG_MAP_KEY, Central__MapNetworks__0 com a rede do compose, e os mapas town 7777, forest 7778, crypt 7779 e guild_hall 7780 sem executáveis (cada mapa é o próprio contêiner, então a Central só espera que eles se registrem).
  • Mapas: KITARPG_CENTRAL_KEY=KITARPG_MAP_KEY, KITARPG_SHOP_URL=http://shop:5300, KITARPG_SHOP_KEY e -address KITARPG_PUBLIC_ADDRESS.
  • Shop: o banco de dados, as configurações de proxy, ASPNETCORE_URLS=http://+:5300, Shop__CatalogPath=/app/shop/shop-conf.json, KITARPG_SHOP_KEY, Shop__AdminKey e os segredos dos webhooks do Stripe e assinados.

Todos os serviços reiniciam sozinhos (unless-stopped).

#O arquivo .env

Copie .env.example para .env e altere todos os valores. O arquivo compose se recusa a iniciar enquanto faltar uma variável obrigatória, e os serviços recusam valores de exemplo.

Variável O que é Obrigatória
POSTGRES_PASSWORD A senha do banco de dados Sim
KITARPG_SIGNING_KEY Chave de assinatura de tokens do Login e da Central, com pelo menos 32 caracteres aleatórios Sim
KITARPG_MAP_KEY Chave que os servidores de mapa apresentam à Central, com pelo menos 16 caracteres aleatórios Sim
KITARPG_PUBLIC_ADDRESS O endereço que os jogadores usam para alcançar os servidores de mapa: o IP público do seu servidor ou um domínio Padrão 127.0.0.1 (somente esta máquina)
KITARPG_LOGIN_DOMAIN Nome público do Login, como login.mygame.com Padrão login.localhost
KITARPG_CENTRAL_DOMAIN Nome público da Central, como central.mygame.com Padrão central.localhost
KITARPG_NETWORK A rede do compose. Altere somente se a sub-rede já estiver em uso no host Padrão 172.28.0.0/24
KITARPG_PROXY_ADDRESS O endereço fixo do Caddy nessa rede Padrão 172.28.0.10
KITARPG_SHOP_KEY Chave que os servidores de mapa enviam ao Shop, com pelo menos 16 caracteres aleatórios Com o perfil shop
KITARPG_SHOP_ADMIN_KEY Chave da API de administração do Shop, com pelo menos 16 caracteres aleatórios Com o perfil shop
KITARPG_STRIPE_WEBHOOK_SECRET O segredo de assinatura de webhooks do Stripe (whsec_...). Vazio desliga o Stripe Não
KITARPG_SHOP_SIGNED_SECRET Segredo compartilhado com a sua própria loja web. Vazio a desliga Não

Crie cada segredo com openssl rand -hex 32. Mantenha o .env fora do controle de versão.

#Experimente no seu computador

Você pode rodar a stack na sua própria máquina antes de alugar um servidor. Com os nomes padrão *.localhost, o Caddy usa a própria autoridade certificadora local.

  1. Instale o Docker Desktop.
  2. Na Unity: KitARPG > Export Game Data for Services e depois KitARPG > Starter > Build Linux Server.
  3. Em Deploy: cp .env.example .env e depois substitua os três segredos obrigatórios.
  4. docker compose up --build.
  5. Jogue no editor. O arquivo compose publica o Login e a Central em 127.0.0.1:5100 e 127.0.0.1:5200, os endereços padrão do cliente, então um cliente no editor os alcança. Pare os serviços no Play & Servers antes, ou as portas estarão ocupadas.

Em um Mac com Apple silicon, os contêineres de mapa rodam como x86 sob emulação: serve para experimentar, não para medir desempenho.

#Implantar em uma VPS

Um passo a passo para uma VPS Linux (Ubuntu 24.04 ou similar) com IP público.

#1. Preparar o servidor

  1. Alugue uma VPS com CPU x86-64 (a imagem de mapa é gerada para linux/amd64). Dimensione-a pelas suas próprias medições; veja Desempenho.

  2. Instale o Docker Engine com o plugin Compose, seguindo o guia do Docker para a sua distribuição.

  3. Abra no firewall exatamente estas portas:

    Porta Protocolo Para
    22 TCP SSH
    80 TCP Caddy (certificados e o redirecionamento para HTTPS)
    443 TCP e UDP Caddy (HTTPS e HTTP/3)
    7777 a 7780 UDP Os servidores de mapa (uma porta por mapa)

    Não abra 5100, 5200, 5300, 5432 nem 7700.

#2. Apontar os seus domínios

Crie dois registros DNS A apontando para o IP da VPS, por exemplo login.mygame.com e central.mygame.com. O Caddy só consegue obter certificados depois que eles resolvem.

#3. Gerar e copiar

No seu computador:

  1. KitARPG > Export Game Data for Services.

  2. KitARPG > Starter > Build Linux Server.

  3. Copie a pasta com Deploy, Services e o código compartilhado para o servidor, por exemplo com rsync:

    rsync -av --exclude 'bin' --exclude 'obj' --exclude '*.db' \
  Deploy Services Unity/Assets/Blunnyn/KitARPG/Runtime/Shared \
  user@server:/opt/mygame/ --relative

    A flag --relative mantém os caminhos, então o servidor recebe /opt/mygame/Unity/Assets/Blunnyn/KitARPG/Runtime/Shared.

#4. Configurar

No servidor, em /opt/mygame/Deploy:

cp .env.example .env
nano .env

Defina os segredos, KITARPG_PUBLIC_ADDRESS com o IP público da VPS (ou um domínio que aponte para ela) e os dois domínios.

#5. Iniciar

docker compose up --build -d
docker compose ps
docker compose logs -f central

A Central registra Map link listening on UDP 7700 e depois Map town (...) registered at <address>:7777 para cada mapa. Verifique os serviços a partir do próprio servidor:

curl http://127.0.0.1:5100/health
curl http://127.0.0.1:5200/api/maps
curl https://login.mygame.com/health

#6. Gerar o cliente

Defina Login Url como https://login.mygame.com e Central Url como https://central.mygame.com em KitARPGSettings e depois use Build Mac Client ou Build Windows Client. Veja Builds.

#7. Definir o seu administrador

Crie a sua conta no jogo e depois:

docker compose exec postgres psql -U kitarpg -d kitarpg \
  -c "UPDATE accounts SET \"Role\" = 4 WHERE \"Username\" = 'yourname';"

#8. Fazer backup

Agende um pg_dump toda noite e copie os arquivos para fora do servidor. Veja Banco de dados.

#O Shop

docker compose --profile shop up --build -d
  • Defina KITARPG_SHOP_KEY e KITARPG_SHOP_ADMIN_KEY no .env antes; o Shop se recusa a iniciar sem chaves reais.
  • O catálogo é Deploy/shop/shop-conf.json. O primeiro início copia o exemplo para lá se ele não existir. As edições são aplicadas sem reiniciar.
  • Para que a API de administração salve ofertas, o usuário do contêiner (uid 1654) precisa poder escrever na pasta: sudo chown 1654 shop. A pasta é montada, não o arquivo, porque salvar substitui o arquivo renomeando-o.
  • O Caddy encaminha ao Shop somente /api/shop/webhooks/* no domínio do Login. A API de administração é acessível em 127.0.0.1:5300 a partir do próprio servidor. Para publicar o catálogo pelo editor, abra um túnel SSH (ssh -L 5300:127.0.0.1:5300 user@server) e use http://127.0.0.1:5300 como endereço do servidor online.

Veja Serviço Shop.

#Módulos

Coloque cada módulo do Login na própria pasta dentro de Deploy/modules/login e cada módulo da Central dentro de Deploy/modules/central, e depois rode docker compose restart login ou central. As pastas são montadas como somente leitura. Para recusar qualquer módulo que não seja o seu, adicione Modules__Allow__0: MyGame.Central.dll ao ambiente do serviço. Veja Módulos de serviço.

#Adicionar um mapa

  1. Adicione o mapa na Unity (Game Database e a cena dele) e gere de novo o servidor Linux.

  2. Em docker-compose.yml, copie um bloco de mapa e altere o nome, o id do mapa e a porta:

    map-desert:
  <<: *map
  command: ["-map", "desert", "-port", "7781", "-central", "central:7700", "-address", "${KITARPG_PUBLIC_ADDRESS:-127.0.0.1}"]
  ports:
    - "7781:7781/udp"

  3. Informe a Central sobre ele, no ambiente do serviço central:

    Central__Maps__4__Id: desert
Central__Maps__4__Port: "7781"

  4. Abra a UDP 7781 no firewall.

  5. docker compose up --build -d.

Cada id de mapa pode rodar em um único contêiner; a Central recusa um segundo registro do mesmo id.

#Adicionar servidores de mapa

Um mapa movimentado pode ir para uma máquina própria. O link do mapa (UDP 7700) não é criptografado, então as máquinas precisam compartilhar uma rede privada ou um túnel WireGuard. Nunca publique a 7700 na internet.

Na máquina principal (onde a Central roda):

  1. Configure a rede privada ou o túnel. Digamos que a máquina principal seja 10.8.0.1 e a máquina do mapa seja 10.8.0.2.

  2. Publique o link do mapa somente no endereço do túnel, no serviço central:

    ports:
  - "127.0.0.1:5200:8080"
  - "10.8.0.1:7700:7700/udp"

  3. Permita a rede do túnel, ao lado da rede do compose:

    Central__MapNetworks__1: 10.8.0.0/24

  4. Remova o contêiner desse mapa desta máquina e mantenha a entrada Central__Maps__N dele.

  5. docker compose up -d.

Na máquina do mapa:

  1. Instale o Docker e copie Deploy/MapServer.Dockerfile e Deploy/builds/starter.

  2. Gere e rode o mapa:

    docker build -f MapServer.Dockerfile --build-arg BUILD_DIR=builds/starter -t kitarpg/map-server .
docker run -d --restart unless-stopped --name map-forest \
  -e KITARPG_CENTRAL_KEY=<map key> \
  -p 7778:7778/udp kitarpg/map-server \
  -map forest -port 7778 -central 10.8.0.1:7700 -address <this machine's public IP>

  3. Abra a UDP 7778 no firewall desta máquina.

A Central registra o cadastro do mapa. Se ela registrar Refused a map link from ...: not in Central:MapNetworks, a rede do túnel ainda não está permitida.

#Atualizar

Quando você mudar o jogo ou aplicar uma atualização do kit:

  1. Faça backup do banco de dados.
  2. Gere de novo o que mudou: Export Game Data for Services e Build Linux Server na Unity, e o cliente.
  3. Copie os arquivos novos para o servidor.
  4. docker compose up --build -d. Os serviços com imagens novas reiniciam; as migrações rodam no início.
  5. Lance o cliente novo ao mesmo tempo: um cliente e um servidor de mapa gerados a partir de códigos de rede diferentes recusam um ao outro.

Reiniciar a Central encerra todas as sessões, e os jogadores que continuam em um mapa não conseguem salvar até fazer login de novo. Atualize em uma janela de manutenção, com os jogadores fora.

#Comandos do dia a dia

Tarefa Comando (em Deploy)
Status docker compose ps
Acompanhar o log de um serviço docker compose logs -f central
O log de um mapa docker compose logs -f map-town
Reiniciar um serviço docker compose restart login
Parar tudo docker compose down (mantém os volumes)
Jogadores por mapa curl http://127.0.0.1:5200/api/maps
CPU, memória e rede por contêiner docker stats
Shell do banco de dados docker compose exec postgres psql -U kitarpg -d kitarpg
Importante

docker compose down -v apaga os volumes, incluindo pgdata: todas as contas e personagens somem. Nunca adicione -v em um servidor ativo.

#Erros comuns

  • O Caddy não consegue obter um certificado. Os domínios ainda não apontam para o servidor, ou as portas 80 e 443 estão fechadas.
  • Os jogadores se conectam a 127.0.0.1. KITARPG_PUBLIC_ADDRESS ainda está no padrão. Defina-o com o IP público e reinicie os mapas.
  • "Set POSTGRES_PASSWORD in Deploy/.env." O arquivo .env não existe ou está incompleto.
  • Um serviço sai com "... is empty, too short or a sample value." Um segredo no .env ainda tem o valor de exemplo.
  • Os contêineres de mapa iniciam, mas a Central não mostra nenhum mapa. Verifique os logs dos mapas: uma KITARPG_MAP_KEY errada, ou falta a cena do mapa na build (Unknown map).
  • Ninguém consegue criar personagens. O Login foi gerado sem o gamedata.json. Exporte os dados do jogo e gere de novo com docker compose up --build -d login.
