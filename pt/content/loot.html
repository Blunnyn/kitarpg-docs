Saque

Uma tabela de saque diz o que um monstro deixa cair quando morre: uma quantidade de ouro e uma lista de itens, cada um com sua chance. Esta página cobre todos os campos de uma tabela de saque, como os drops são sorteados, os drops de missão, como o saque chega ao jogador e as configurações e stats que mudam as chances.

#O que é uma tabela de saque

Uma tabela de saque é um asset LootTable no Game Database. Um monstro aponta para uma no campo Loot (loot). Vários monstros podem compartilhar uma tabela: o Slime e o Giant Slime do exemplo usam Slime Loot.

Quando um monstro morre, o servidor sorteia a tabela dele uma vez para o jogador que ganhou a morte. O saque é só desse jogador: ninguém mais o vê nem pode pegá-lo.

#Onde fica no editor

Game Database > Items > Loot. A lista mostra todas as tabelas; + New loot table cria uma em uma pasta Loot ao lado do banco de dados e a adiciona à lista lootTables do banco de dados. Você também pode usar Create > KitARPG > Loot Table na janela Project.

No cartão de uma tabela, cada drop é uma linha com o ícone do item. A coluna de chance mostra Chance %: os dados guardam de 0 a 1, o editor mostra e recebe porcentagem.

#Campos

#A tabela

Campo O que faz Padrão
Id, Display Name, Description, Icon Comuns a todo asset do banco de dados. Nas tabelas de saque, só o id importa. Do nome do arquivo
Gold (gold) Ouro mínimo e máximo que cai (x e y, ambos incluídos). 1 a 5
Drops (drops) Os itens que ela pode deixar cair, em ordem. Vazio
Max Drops (maxDrops) O máximo de itens que uma morte pode deixar cair. 0 significa sem limite. 3

#Cada drop

Campo O que faz Padrão
Item (item) O item. Project Check avisa sobre um drop sem item. Nenhum
Chance (chance) Chance de cair, mostrada como porcentagem (0 a 100). 0
Min Amount (minAmount) O mínimo do item quando ele cai. 0
Max Amount (maxAmount) O máximo do item quando ele cai. 0
Quest (quest) Cai só para quem matou e está nesta missão e ainda precisa do item. Vazio: cai para qualquer um. Nenhum

A quantidade é um número inteiro aleatório de Min Amount a Max Amount, ambos incluídos, e nunca menor que 1. Um drop com os dois em 0 deixa cair um.

#Como uma morte é sorteada

Quando um monstro morre, o componente Rewards do servidor paga o jogador que causou mais dano:

  1. A experiência vai para quem matou, ou é dividida com os membros do grupo por perto. Veja Monstros.
  2. Ouro: uma quantidade aleatória de Gold, vezes a taxa de ouro do servidor. Um coletor de guilda por perto tira a parte dele primeiro. Veja Coletores.
  3. Itens: cada drop é conferido na ordem da lista:
    1. Um drop com Quest é ignorado, a menos que quem matou tenha essa missão aberta e carregue menos do item do que o objetivo de coleta pede.
    2. Um sorteio aleatório contra a chance do drop (veja Chances). Se acertar, o item e sua quantidade são adicionados.
    3. Quando o número de itens adicionados chega a Max Drops, o resto da lista não é sorteado.
  4. Entrega: o ouro e os itens chegam ao jogador do jeito que Game Settings > Loot diz (veja Como o saque chega ao jogador).

Como a lista para em Max Drops, a ordem importa. Coloque primeiro os drops que você nunca quer cortar. O exemplo coloca os drops de missão no topo de Slime Loot e Mushroom Loot por esse motivo.

#Chances

Para cada item que não é um drop de missão, a chance usada é:

chance x (1 + the killer's Loot Chance stat) x the server's loot rate, limitada a 100 %.

  • Loot Chance (lootChance) é um stat. 0,1 é +10 % de cada chance, não +10 pontos: um drop de 5 % vira 5,5 %. No exemplo, cada ponto de Luck dá +0,5 %.
  • A taxa de saque é Game Settings > Rates > Loot Rate (lootRate, padrão 1) vezes um evento de taxas que um GM pode ter iniciado com /rates loot 2 60.
  • Os drops de missão mantêm a própria chance. Sorte e taxas nunca deixam uma missão mais fácil.

O ouro usa Gold Rate (goldRate, padrão 1) do mesmo jeito. Veja Configurações do jogo e Comandos de GM.

#Como o saque chega ao jogador

Game Settings > Loot tem duas configurações (GameInstance, no prefab KitNetwork):

Campo O que faz Padrão
Loot Mode (lootMode) Como os jogadores recebem o que os monstros deixam cair. Só o jogador que ganhou a morte o vê. Ground
Auto Gold (autoGold) O ouro vai direto para o jogador. Desligado: ele cai como os itens, no chão ou no corpo. Ligado

Os modos de saque:

Modo O que o jogador vê
Ground Cada item cai no chão ao lado do monstro, espalhado em cerca de 1,2 m, como seu ícone com o nome na cor da raridade. Clicar em um faz o personagem ir até lá e pegá-lo. O ouro (quando Auto Gold está desligado) cai como uma pilha.
Corpse Os itens ficam no corpo do monstro, que fica cinza onde morreu. Clicar nele abre a janela de saque, para pegar os itens um por um ou todos.
Automatic Os itens vão direto para a bolsa. O que não cabe cai no chão.

Detalhes que valem em todos os modos:

  • O saque espera 90 segundos e depois desaparece. Também desaparece quando o dono sai do mapa.
  • O jogador o pega a até 2 m (um pouco mais enquanto a janela de saque está aberta).
  • O saque pode deixar a bolsa acima do limite de peso. Então o personagem não consegue andar até largar, vender ou guardar algo. Veja Inventário e banco.
  • O ouro que não cabe na carteira vai para o banco.
  • Os itens da raridade de Game Settings > Logs > Log Loot From ou melhor (Rare por padrão) são escritos no registro do jogo. Veja Registro do jogo e denúncias.

O saque nunca existe como objeto de rede. O servidor o guarda na memória e diz só ao dono onde ele está. Outro cliente, mesmo modificado, não consegue vê-lo nem pegá-lo.

#Montar uma tabela de saque

Isto monta uma tabela para um lobo, com um drop de missão.

  1. Game Database > Items > Loot > + New loot table. Renomeie para Wolf Loot.
  2. Defina Gold como 2 e 7.
  3. Defina Max Drops como 2.
  4. Adicione primeiro o drop de missão: Item Wolf Pelt, Chance % 60, Min Amount 1, Max Amount 1, Quest "Pelts for the Tanner".
  5. Adicione os drops normais: Health Potion a 25 %, 1 a 1; uma runa a 15 %, 1 a 2; uma capa rara a 2 %, 1 a 1.
  6. Abra World > Monsters > Wolf e escolha Wolf Loot em Loot.
  7. Crie a missão: um CollectObjective de 5 Wolf Pelts. Marque a pele como item de missão (Items > Quest items faz isso). Veja Missões.
  8. Teste: /spawn wolf 5, mate-os com a missão aberta e sem ela. Sem a missão, nenhuma pele cai.
Dica

Um chefe com drops garantidos: dê 100 % a esses itens e aumente Max Drops para que os outros drops ainda tenham espaço. O Mushroom King do exemplo sempre deixa cair Holy Water e tem Max Drops 5.

#O bestiário

O bestiário (B) lista os drops de cada monstro com a chance que o jogador tem, incluindo o stat de saque dele. Desligue In Bestiary de um monstro para escondê-lo ali.

#Um jogador e MMO

Os sorteios são os mesmos nos dois. No MMO, eles acontecem no servidor de mapa onde o monstro morreu, e só o cliente do dono fica sabendo do saque. Em um jogo de um jogador, eles acontecem no host. No MMO, cada item na bolsa do jogador é uma linha no banco de dados com um único dono; o saque vira uma linha dessas quando é pego.

#Para programadores

Rewards.OnKilled, Rewards.DropChance e Rewards.ShareExperience são virtuais. Sobrescreva DropChance para mudar a regra das chances, ou OnKilled para dividir o saque com um grupo. Rewards.Instance.Pay(...) entrega itens e ouro a um jogador seguindo o modo de saque, para um saque próprio. Veja Sobrescrever o comportamento do kit.

#Erros comuns

  • Um drop nunca cai. A chance dele é 0, Max Drops é alcançado pelos drops acima dele, ou ele tem uma Quest que quem matou não tem aberta.
  • Um item de missão para de cair. O jogador já carrega tantos quanto o objetivo pede. Isso é proposital.
  • Os drops parecem generosos demais. A taxa de saque em Game Settings, um evento de taxas de GM ou um stat Loot Chance alto. Confira /rates.
  • O grupo não entende por que só um ganhou o saque. O saque vai para quem causou mais dano. A experiência e as contagens de mortes das missões são compartilhadas; os itens não.
