O editor

Play & Servers

Play & Servers é onde você escolhe como o seu jogo roda, um jogador ou MMO, e segue passos numerados para jogá-lo a partir do editor. No MMO, a página compila e inicia os serviços (Login, Central e os servidores de mapa), configura o banco de dados, mostra o estado e o log de cada serviço e joga com um ou dois jogadores.

#Onde fica

  • KitARPG > Play and Servers, ou
  • a página Play & Servers na janela KitARPG (Ctrl/Cmd+Shift+K), a segunda da barra lateral.

No MMO, a barra lateral mostra On ao lado da página quando Login e Central respondem, e ... enquanto eles iniciam.

#Escolher um jogador ou MMO

A página abre com dois cartões grandes. Clique em um para escolhê-lo:

Cartão Descrição exibida O que significa
Single player "The game hosts its own world and saves on the player's computer. No servers to run." O jogo é cliente e servidor ao mesmo tempo e salva em um arquivo SQLite local. Veja Início rápido: um jogador
MMO "Players log in to your servers: Login, Central and one server per map." Os jogadores entram nos seus serviços e se encontram em mapas compartilhados. Veja Início rápido: MMO

A escolha fica salva no asset de configurações Assets/Settings/Resources/KitARPGSettings.asset (o campo mode de KitSettings). As builds feitas pelos menus de build do kit definem o modo de que a build precisa e depois devolvem o seu.

Se o projeto ainda não tem asset de configurações, a página mostra um cartão No settings yet com Create settings. Pressione-o para criar o asset.

O asset de configurações também guarda estes campos, que você pode editar no Inspector:

Campo O que faz Padrão
Mode (mode) Online (MMO) ou Single Player Online
Login Url (loginUrl) Onde os clientes acessam o serviço Login http://127.0.0.1:5100
Central Url (centralUrl) Onde os clientes acessam o Central http://127.0.0.1:5200
Save File (saveFile) O salvamento do modo de um jogador, um arquivo SQLite na pasta de dados persistentes do jogador savegame.db

#Como os passos funcionam

Abaixo dos cartões vêm os passos numerados. Cada passo é um cartão com um número, um título, uma linha de resumo e uma etiqueta:

Etiqueta Significa
Done O passo está completo. O cartão se recolhe e o número vira uma marca de verificação
To do Ainda não foi feito. O primeiro passo não feito tem contorno dourado e abre sozinho
Locked Um passo anterior precisa ser feito primeiro. Passos bloqueados não abrem

Clique no cabeçalho de um passo para abri-lo ou recolhê-lo. A seta à direita (▸ ou ▾) mostra qual dos dois.

#Passos de um jogador

#1. Verificar o projeto

Resumo: "Scenes and the SQLite library are in place." ou "Something the game needs is missing."

Linha Concluída quando Correção
Scenes in Build Settings A primeira cena ativada em Build Settings é Title. O detalhe lista as cenas Use starter scenes coloca as cenas da amostra em Build Settings na ordem certa
SQLite library for this platform A biblioteca nativa do SQLite para o seu editor está em Plugins/SQLite (macOS/libe_sqlite3.dylib, Windows/e_sqlite3.dll ou Linux/libe_sqlite3.so) Importe o pacote do KitARPG de novo

#2. Jogar

Resumo: "The editor is the client and the server at once." Bloqueado até o passo 1 estar feito.

  • ▶ Play single player abre a cena Title e entra no Play Mode com o argumento -mode single. Se a cena aberta tem alterações não salvas, o Unity pede para salvá-las antes. Fica desativado enquanto você já está jogando.
  • Save data mostra o caminho do arquivo de salvamento que o editor usa.
  • Show folder abre a pasta de dados persistentes no Finder ou no Explorer.
  • Delete save data pergunta "Delete every single player character saved by the editor?" e apaga o arquivo de salvamento junto com os arquivos -wal e -shm. Fica desativado no Play Mode ou quando não há salvamento.

#3. Compilar o jogo

Resumo: "Builds go to Builds/Starter and carry the server code, so the game hosts itself."

Botão Saída
Build for Mac Builds/Starter/MacSinglePlayer/KitARPG.app
Build for Windows Builds/Starter/WindowsSinglePlayer/KitARPG.exe

A pasta Builds é criada ao lado da pasta do seu projeto Unity, na pasta que a contém. Veja Builds.

#Passos do MMO

#1. Verificar o projeto

O resumo conta o que está pronto, por exemplo "3 of 5 ready", e mostra "Scenes, .NET, the services and the map server build are ready." quando os cinco estão.

Linha Concluída quando Botão
Scenes in Build Settings Title é a primeira cena ativada e Server está na lista Use starter scenes
.NET 10 SDK dotnet --list-sdks informa um SDK 10.x. O detalhe lista o que está instalado, ou "dotnet was not found" Get .NET abre a página de download do .NET 10. Check again procura o dotnet de novo depois que você o instala, sem reiniciar o Unity
Services source A pasta com KitARPG.Services.slnx foi encontrada. O detalhe mostra o caminho Browse permite escolhê-la manualmente
Services built Login, Central e o launcher estão compilados. "Building..." enquanto compila Build services, ou Rebuild depois de compilado. Desativado sem o código-fonte ou o SDK
Map server build A build local do servidor de mapa existe e tem a cena de cada mapa. Cinza quando todos os mapas rodam no editor e a build não é necessária Build, ou Rebuild depois de compilada

Quando a compilação dos serviços falha, uma caixa vermelha abaixo da linha mostra até oito linhas de erro. Se nenhuma pôde ser lida, ela diz "dotnet build failed. Run it in a terminal to see why."

O editor procura o código-fonte dos serviços nesta ordem: uma pasta que você escolheu com Browse (lembrada por projeto), Services ao lado do projeto Unity, Services dentro dele e Assets/Blunnyn/KitARPG/Services~, onde o kit descompacta os serviços que vêm no pacote.

Mais duas linhas podem aparecer:

  • N kit updates (aviso): "Things this kit adds that the game doesn't have yet. Apply them before building the map server, so both have them." Review abre a Overview.
  • In-game shop, quando o serviço Shop está no projeto: desligado ("Off. The Shop service is optional."), rodando, ou ligado mas sem rodar. Open Shop abre a página Shop.

A build do servidor de mapa vai para Builds/Starter/MacServer/KitARPGServer.app no Mac e para Builds/Starter/WindowsServer/KitARPGServer.exe no Windows. É uma build de player normal com o código do servidor compilado dentro, que o launcher roda em modo batch sem gráficos; ela não precisa do módulo Dedicated Server do Unity. Depois de cada build, um arquivo KitARPGScenes.txt ao lado dela lista suas cenas, e é assim que a página sabe que um mapa adicionado depois está faltando nela.

Nota

A linha diz "Missing the scene of a map: ..." quando um mapa foi adicionado depois da última build. Os jogadores que viajarem até ele voltariam para o login. Compile o servidor de mapa de novo.

#2. Escolher o banco de dados

Bloqueado até o passo 1 estar feito. O resumo mostra a escolha atual.

Um seletor de duas opções escolhe onde os serviços guardam contas, personagens e itens:

Escolha Use para
SQLite: a local file Desenvolvimento e servidores pequenos. Nada para instalar. A página mostra o caminho do arquivo, UserSettings/KitARPG/data/kitarpg.db por padrão
PostgreSQL: for production Servidores reais, ou para desenvolver com o mesmo banco de dados que você vai publicar

Com PostgreSQL escolhido, uma linha de estado mostra Connection ready com a string de conexão (senha oculta) ou No connection yet. Depois:

  • Set up PostgreSQL... abre a janela de configuração do PostgreSQL. Veja Configurar o PostgreSQL.
  • Write the connection string by hand, uma seção recolhível com um campo de texto. O formato esperado aparece abaixo dele: Host=localhost;Port=5432;Database=kitarpg;Username=kitarpg;Password=...

O banco de dados não pode ser trocado enquanto os serviços rodam ("Stop the services to change the database.").

Keys (chaves): "Signing and map keys are made for this machine and kept in UserSettings/KitARPG." New keys cria uma nova chave de assinatura (32 bytes aleatórios, usada para assinar os tokens de login) e uma nova chave de mapa (16 bytes aleatórios, o que os servidores de mapa mostram ao Central) e as salva. Fica desativado enquanto os serviços rodam.

Veja Banco de dados para saber do que cada banco de dados precisa em produção.

#3. Iniciar os serviços

Bloqueado até os passos 1 e 2 estarem feitos. O resumo mostra "Login, Central and the maps, on this computer.", "Starting..." ou "Running. Maps: town (1 player), ...".

Três linhas mostram cada parte com uma luz (cinza desligado, dourado iniciando, verde no ar):

Serviço Detalhe Porta
Login Contas e personagens 5100
Central Sessões, chat, guildas e mapas 5200
Maps "Started by Central when someone enters", ou os mapas rodando com a contagem de jogadores Uma porta por mapa, 7777 para town, 7778 para forest, 7779 para crypt

Map in the editor escolhe onde os mapas rodam:

Escolha Significado
None, every map runs from the map server build O Central inicia todos os mapas a partir da build. É o padrão
town: runs in this editor, to debug it (uma linha por mapa) O Central espera que esse mapa venha do editor. Você o joga com Play map server no passo 4. Use isso para depurar o código do servidor com breakpoints

A escolha não pode mudar enquanto os serviços rodam.

Botões:

  • Start services inicia o launcher em modo headless com UserSettings/KitARPG/launcher.json. Antes de iniciar, a página grava os dados do jogo do seu banco de dados do jogo em UserSettings/KitARPG/gamedata.json, para que o Login crie personagens com os seus dados como estão agora.
  • Restart para os serviços e os inicia de novo assim que as portas ficam livres (no máximo dez segundos). Um botão Restart também fica no cabeçalho do passo enquanto ele está recolhido.
  • Stop para o launcher, que fecha o Login, o Central e todos os mapas que ele iniciou.

Os serviços param sozinhos quando você fecha o Unity. Eles continuam rodando entre recargas de scripts e o Play Mode.

Avisos que este passo pode mostrar:

Aviso Significado Correção
"Services from an earlier editor session are still running (process ...)" Um launcher iniciado por um editor que fechou sem pará-lo ocupa as portas. Só no Mac e no Linux Stop the old services
"The services or the map server were rebuilt after they started, so they still run the old code. Restart them." Você compilou de novo depois de iniciar Restart
"Something else is using port ..." Outro programa escuta na porta do Login ou do Central, muitas vezes serviços iniciados por um terminal Pare esse programa primeiro

#4. Jogar

Bloqueado até os serviços estarem rodando.

  • ▶ Play client abre a cena Title e joga como cliente dos serviços locais (-mode online -login http://127.0.0.1:5100 -centralUrl http://127.0.0.1:5200).
  • Play map server: town aparece quando um mapa roda no editor. Ele abre a cena Server e joga como servidor desse mapa, conectado ao Central com a chave de mapa.
  • Two players: Play with two abre um segundo editor e faz login nos dois. Veja Jogar com dois jogadores.
  • Built client: Open inicia a build do cliente ao lado do editor, quantas vezes você quiser, para ter mais jogadores ao mesmo tempo. Build ou Rebuild a cria (Builds/Starter/MacClient/KitARPG.app ou Builds/Starter/WindowsClient/KitARPG.exe). Os clientes de release são compilados com IL2CPP, então essa build demora mais que uma Mono.

#O log

O cartão Log na parte de baixo se abre para mostrar as últimas 120 linhas da saída dos serviços. Open log file abre UserSettings/KitARPG/services.log no seu editor de texto. O log começa vazio cada vez que os serviços iniciam.

#Passo a passo: iniciar os serviços do MMO

  1. Abra Play & Servers e clique no cartão MMO.
  2. No passo 1, corrija todas as linhas vermelhas. Normalmente: pressione Use starter scenes, instale o SDK do .NET 10 se for pedido (depois Check again), pressione Build services e espere, depois pressione Build em Map server build e espere a build do Unity terminar.
  3. No passo 2, mantenha SQLite: a local file por enquanto.
  4. No passo 3, deixe Map in the editor em None e pressione Start services. As luzes do Login e do Central ficam verdes depois de alguns segundos.
  5. No passo 4, pressione ▶ Play client. Na tela de título, registre uma conta, crie um personagem e entre no mundo. O Central inicia o servidor do mapa town na primeira vez que alguém vai até lá.
  6. Quando você mudar scripts ou cenas, compile o servidor de mapa de novo e pressione Restart. A lista To do da Overview avisa quando.

#Configurar o PostgreSQL

Set up PostgreSQL... no passo 2 abre a janela PostgreSQL Setup. Ela funciona com o launcher (KitARPG.Launcher --postgres), então compile os serviços antes; sem eles, a janela diz "The services aren't built yet; they do the talking to PostgreSQL. Build them in Play & Servers first."

O seletor no topo escolhe onde o PostgreSQL roda: A server I run ou Docker on this computer.

#A server I run

Where is PostgreSQL?

Campo O que faz Padrão
Host Endereço do servidor. localhost para este computador localhost
Port A porta dele 5432
SSL Prefer, Require ou Disable. Servidores hospedados (uma VPS, RDS, Supabase, Neon) normalmente precisam de Require Prefer

Depois escolha Create the database for me ou Use a database I have.

Com Create the database for me:

  1. Preencha Admin login (User, Password): uma conta com permissão para criar bancos de dados e usuários. Ela é usada uma vez e nunca é salva. No Mac com Homebrew ou Postgres.app, o admin costuma ser o seu próprio usuário, sem senha. Usuário padrão: postgres.
  2. Preencha For the game: Database (kitarpg), User (kitarpg) e Password. A senha começa aleatória; Show a revela e New cria outra.
  3. Pressione Create and use. A janela cria o banco de dados e o usuário, testa o login e, quando funciona, preenche a string de conexão em Play & Servers e troca para PostgreSQL.

Com Use a database I have, preencha Login (Database, User, Password) e pressione Test and use.

A mensagem abaixo do botão diz o que aconteceu, ou por que falhou. A janela desiste depois de um minuto sem resposta ("PostgreSQL didn't answer in a minute.").

#Docker on this computer

Precisa do Docker Desktop (o OrbStack também funciona). Create and use roda o PostgreSQL 17 (postgres:17-alpine) em um contêiner chamado kitarpg-postgres, com os dados no volume kitarpg-pgdata, escutando em 127.0.0.1 na primeira porta livre a partir de 5432. Ele define uma nova senha aleatória para o usuário kitarpg e preenche a string de conexão em Play & Servers.

O contêiner continua rodando depois que você fecha o Unity e reinicia junto com o Docker. Pressionar Create and use de novo reaproveita o contêiner e dá a ele uma senha nova. Na primeira vez, baixar a imagem pode levar um minuto.

Mensagens que você pode ver:

Mensagem Correção
"Docker was not found. Install Docker Desktop, or write the connection string of your own server." Instale o Docker Desktop, ou use A server I run
"Docker is installed but not running. Open Docker Desktop and try again." Inicie o Docker Desktop
"The container kitarpg-postgres doesn't publish port 5432. Remove it in Docker Desktop and try again." Apague o contêiner antigo no Docker Desktop
"PostgreSQL didn't start. Its log is in Docker Desktop, container kitarpg-postgres." Leia o log do contêiner no Docker Desktop

A string de conexão, com a senha, fica salva em UserSettings/KitARPG/launcher.json, fora dos assets do projeto e fora do controle de versão por padrão.

#Jogar com dois jogadores

Play with two (passo 4), Play with two players (Overview) e KitARPG > Play With Two Players fazem a mesma coisa:

  1. Se o modo não é MMO, uma caixa de diálogo diz "Two players need the MMO mode, where players meet on servers." e abre Play & Servers.
  2. Se falta o pacote Multiplayer Play Mode do Unity (com.unity.multiplayer.playmode), uma caixa de diálogo oferece Install. Pressione o botão de novo depois que ele estiver instalado.
  3. Se os serviços não estão rodando, ele os inicia. Se não estão compilados, ele pede que você os compile antes.
  4. Ele abre o Player 2, um segundo editor do mesmo projeto, pelo Multiplayer Play Mode. Na primeira vez, esse editor importa o projeto, o que demora um pouco.
  5. Quando o Login responde e o Player 2 está aberto, os dois editores entram em Play. Cada um entra com a sua própria conta de teste, cria o personagem se ele não existe e entra no mundo sem passar pela tela de título.

As contas de teste são kitplayer1 e kitplayer2, com os personagens Aria e Bram, uma senha aleatória criada para esta máquina, o primeiro modelo de jogador e a primeira classe dele. Elas ficam em UserSettings/KitARPG/quickplay.json; edite esse arquivo para usar outros nomes. Elas são criadas só nos seus serviços locais.

Se o Player 2 não consegue iniciar sozinho, o Console avisa e o Unity abre Window > Multiplayer > Multiplayer Play Mode: ative o Player 2 ali e pressione o botão de novo. Se nada estiver pronto depois de 15 minutos, o Console informa.

Os mapas rodam a partir da build do servidor de mapa, ou neste editor quando um está escolhido em Map in the editor.

#Arquivos que esta página usa

Todos ficam em UserSettings/KitARPG/, por usuário e fora do controle de versão:

Arquivo Guarda
launcher.json Portas, chaves, banco de dados, mapas e caminhos que o launcher lê
data/kitarpg.db O banco de dados SQLite dos serviços locais
gamedata.json Os dados do jogo que o Login e o Central leem, gravados a cada início
services.log A saída dos serviços
launcher.pid O launcher em execução, para que o editor o encontre depois de reiniciar
quickplay.json As contas de teste para dois jogadores

As configurações do launcher listam os mapas e suas portas. O editor começa com town na 7777 (iniciado com os serviços), forest na 7778 e crypt na 7779, e o launcher adiciona guild_hall na 7780. Todos os outros mapas do banco de dados do jogo recebem a próxima porta livre quando você inicia os serviços, então um mapa novo não precisa de configuração. Para mudar as portas, edite launcher.json com os serviços parados. Veja Launcher e Configuração.

#Dicas

  • Mantenha Map in the editor em None, a menos que esteja depurando o código do servidor. Jogar um servidor de mapa no editor significa que o editor não pode ser também um cliente; use Built client ou dois jogadores para isso.
  • Depois de mudar classes, itens ou outros dados que o Login usa para criar personagens, reinicie os serviços para que eles leiam os novos dados do jogo.
  • O Play da barra de ferramentas normal do Unity não passa os argumentos da janela. Use os botões desta página ou da Overview, ou comece pela cena Title.

#Erros comuns

  • Iniciar os serviços sem uma build do servidor de mapa. O Login e o Central iniciam, mas nenhum mapa se registra e os jogadores ficam na tela de título. Compile o servidor de mapa.
  • Esquecer de reiniciar depois de compilar de novo. Os serviços continuam rodando o código antigo. O passo mostra um aviso e a Overview lista Restart the services.
  • Portas ocupadas por serviços iniciados em um terminal. Pare esses primeiro; dois launchers não podem dividir as portas.
