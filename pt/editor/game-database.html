O editor

Game Database

A página Game Database mostra todos os dados do jogo em um só lugar: modelos de jogador, classes, atributos, habilidades, itens, monstros, saque, lojas, missões, mapas e as configurações do próprio banco de dados. Você navega por tipo à esquerda, escolhe uma entrada no meio e a edita à direita. Ela também tem dois assistentes que criam um novo modelo de jogador ou um novo monstro a partir de um modelo 3D.

#Onde fica

  • KitARPG > Game Database, ou
  • a página Game Database na janela KitARPG (Ctrl/Cmd+Shift+K).

Quando os dados têm problemas, a barra lateral mostra a quantidade ao lado da página.

#O que é o banco de dados do jogo

O banco de dados do jogo é um asset GameDatabase. O jogo lê todos os seus dados por meio dele, por id. Você lista nele as entradas principais (modelos de jogador, mapas, monstros, itens e assim por diante); tudo aquilo a que essas entradas apontam (as habilidades de uma classe, a tabela de saque de um monstro, os itens de uma tabela de saque) é reunido sozinho. Assim, uma habilidade adicionada a uma classe está no jogo sem precisar listá-la duas vezes.

O banco de dados é definido na Game Instance do prefab de rede. A amostra inicial cria um em Assets/Blunnyn/KitARPG/Samples/Starter/Data/StarterDatabase.asset. O Login e o Central recebem uma cópia dele como gamedata.json cada vez que o Play & Servers inicia os serviços.

#O layout

A página usa toda a largura da janela, em três colunas abaixo de uma barra de ferramentas.

#Barra de ferramentas

Elemento O que faz
Campo Game Database O banco de dados sendo editado. Escolha outro para trocar; a escolha fica lembrada
Etiqueta N problems Aparece quando os dados têm problemas. A página Settings os lista
Collect referenced Grava nas próprias listas do banco de dados cada entrada que ele só alcança por referências, para que cada lista mostre tudo. Os modelos de jogador não são tocados
Export for services Grava gamedata.json na pasta Login do código-fonte dos serviços, para serviços que você roda manualmente. O mesmo que KitARPG > Export Game Data for Services

Quando o projeto não tem banco de dados do jogo, a página mostra No game database yet com Create game database. Escolha onde salvá-lo; os dados que você criar depois vão para pastas ao lado dele.

Os tipos de dados, em grupos, cada um com a sua quantidade. A quantidade inclui as entradas alcançadas por referências.

Characters Classes O que um personagem é: atributos por nível, habilidades e com o que ele começa
Characters Attributes Força, inteligência e os demais, e os stats que cada ponto dá
Characters Elements Tipos de dano, cada um com a sua resistência
Combat Skills O que jogadores e monstros lançam, feito de efeitos
Combat Statuses Buffs e debuffs: veneno, atordoamento, escudos e afins
Combat Weapon Types Espada, arco, cajado: como cada tipo ataca e se anima
Items Items Armas, equipamento, poções, pergaminhos e tudo o mais que cabe em uma bolsa
Items Sets Peças que somam bônus quando usadas juntas. Uma peça entra em um conjunto pela própria página
Items Currencies O ouro e qualquer outro dinheiro que o jogo usa
Items Loot O que os monstros deixam cair e com que frequência
Items Shops O que as lojas de NPC vendem e compram
World Monsters Stats, habilidades, saque e comportamento de cada monstro
World Quests Objetivos, recompensas e quem pode aceitá-las

#Entradas (meio)

O título e a dica da categoria, um campo de busca e a lista. Cada linha mostra o ícone da entrada (ou a primeira letra, quando não tem), o nome e uma segunda linha: o id, ou para itens a categoria e o id, ou para modelos o id do modelo e quantas classes ele tem.

  • Digite no campo de busca para filtrar por nome ou id.
  • Clique em uma linha para editá-la. Um clique duplo também seleciona o asset na janela Project.
  • As setas Up e Down percorrem a lista.
  • O botão na parte de baixo cria uma nova entrada: + New class, + New skill, + New weapon e assim por diante. Quando uma categoria pode criar mais de um tipo (Items pode criar uma arma, um equipamento, um consumível ou um item simples), um menu pergunta qual.

As novas entradas recebem o nome "New ..." com um id feito a partir do nome, são salvas em uma pasta com o nome da categoria ao lado do asset do banco de dados (por exemplo Data/Skills), adicionadas à lista do banco de dados e abertas. Renomeie-as nos seus campos.

As categorias Models e Monsters têm botões próprios, descritos em Novo modelo de jogador e Novo monstro.

#Página da entrada (direita)

O topo da página mostra o ícone, o nome, uma etiqueta com o tipo (Weapon, Skill, Monster...) e uma etiqueta com o id, além de três botões:

Botão O que faz
Show file Seleciona o asset na janela Project
Duplicate Copia o asset ao lado dele, com um id feito a partir do nome da cópia, adiciona-o à mesma lista e o abre. Não existe em modelos
Delete Pergunta "Move ... to the trash? Characters that saved its id lose it." e move o asset para a lixeira. Em modelos, o botão é Remove: tira o modelo do banco de dados e mantém o prefab

Abaixo disso, o caminho do asset e depois os campos em cartões, um cartão por grupo de campos. Os campos são os mesmos que você vê no Inspector.

Alguns tipos têm cartões extras acima dos campos:

  • Itens: um cartão In game com o tooltip que os jogadores veem, raridade e categoria, descrição, todos os bônus (bônus sorteados como intervalos), o nível e as classes para equipamento, os preços de venda e de compra, o empilhamento, o peso e se ele é vinculado, e o ícone do item.
  • Equipamento com bônus fixos: "N fixed bonuses that never roll. Turn them into min and max ranges, 25% up and down?" com Make them roll, que passa os bônus fixos para intervalos aleatórios. Veja Equipamento.
  • Modelos: um cartão Look com uma prévia do prefab (clique duas vezes para abrir o prefab), as classes dele (a primeira marcada como "(default)") e quantas animações estão definidas. Abaixo dos campos, uma seção Animations edita o Character Animations do modelo: clips para mover, receber golpe, morrer, atacar com cada tipo de arma e lançar cada habilidade. Um prefab sem esse componente mostra Add Character Animations.
  • Mapas: um cartão Adding a map com o que um mapa precisa e em que pé está cada parte. Veja Mapas.

#Novo modelo de jogador

Em Models, a parte de baixo da lista tem:

  • + New player model, que abre o assistente na coluna da direita.
  • "Or add a player prefab you already made": um campo de prefab e Add prefab. Ele adiciona um componente Player Model quando o prefab não tem e o lista no banco de dados. Arraste um prefab da janela Project; um objeto de cena é recusado.

O assistente tem quatro passos mostrados como uma barra no topo. Os passos pelos quais você passou podem ser clicados para voltar. Cancel o fecha sem criar nada, Back volta um passo e Next avança; Next fica desativado enquanto o passo tem um problema, mostrado em uma linha laranja.

#Passo 1: Model

  1. Arraste um FBX ou um prefab para o campo de The 3D model. Uma prévia aparece ao lado.
  2. Leia o estado abaixo dele:
    • Humanoid rig: as armas vão nas mãos e ele pode compartilhar as animações do kit.
    • Generic rig: use animações feitas para esse rig e defina os ossos das mãos no modelo depois.
    • No Animator: ele não vai se animar. Adicione um Animator ao modelo, ou defina o rig como Humanoid nas configurações de importação.
    • No skinned meshes: o equipamento troca partes do corpo por skinned mesh, então este modelo aparece sem mudanças de equipamento.
  3. Em Name, confira Display name (preenchido com o nome do modelo) e Id (feito a partir do nome até você digitar o seu). O id é salvo com os personagens; mudá-lo depois quebra os personagens criados com ele.
  4. Marque Own hair only para manter o cabelo, as orelhas ou os chifres do próprio corpo: nenhum penteado é oferecido para ele.

#Passo 2: Classes

  1. Em Classes it can be, marque as classes que um personagem com essa aparência pode escolher. A primeira marcada é a padrão.
  2. Para criar classes junto com o modelo, pressione + New class em New classes, digite um nome e, se quiser, escolha uma classe em copy of para partir dos atributos, das habilidades e do equipamento dela. x remove uma linha.

É preciso pelo menos uma classe. Os nomes das novas classes não podem coincidir com o id de uma classe existente.

#Passo 3: Animations

  1. Start from a model: escolha um modelo existente para copiar as animações dele (clips, momentos de golpe, por arma e por habilidade) e o catálogo de aparência, ou Nothing, start empty. Com um modelo escolhido:
    • Copy its animations (ligado por padrão).
    • Copy the game's own components on it (not the kit's) (ligado por padrão): os componentes que você adicionou a esse modelo vêm junto com os seus valores.
    • Um aviso aparece quando um modelo é humanoide e o outro não, já que os clips copiados podem não tocar neste rig.
  2. Upper body (só humanoide): Use an upper body mask (ligado por padrão) permite que os personagens ataquem e lancem habilidades enquanto andam, com as pernas ainda se movendo. Deixe Mask vazio para usar a máscara do kit, ou escolha o seu próprio Avatar Mask.

Com as animações vazias, solte os clips no cartão Animations do modelo depois. Os golpes continuam acertando no tempo certo.

#Passo 4: Create

  1. Confira Prefab folder. O padrão é uma pasta Prefabs ao lado da pasta do banco de dados. O caminho completo do prefab aparece abaixo. A pasta precisa estar dentro de Assets, e não pode existir um prefab com esse nome.
  2. Leia What will be made: o prefab com o Player Model, rede, movimento, inventário, stats, habilidades, missões, chat, amigos, grupo, troca, guilda, banco, forja, correio, mercado, loja, PvP, equipamento, aparência, animações e o nome sobre a cabeça; as classes; as animações; a máscara; e que ele entra no banco de dados.
  3. Pressione Create player.

O assistente cria as novas classes (em Classes, ao lado do banco de dados) e o prefab, adiciona os dois ao banco de dados e abre o novo modelo, pronto para editar. Veja Modelos de jogador.

#Novo monstro

Em Monsters, a parte de baixo da lista tem:

  • + New monster, que abre o assistente.
  • Blank monster data, que cria só um asset de dados de Monster, sem prefab.

#Passo 1: Model

  1. Arraste um FBX ou um prefab para The 3D model.
  2. O estado diz Animated (você escolhe os clips no passo 3) ou No Animator (ele dá saltinhos ao se mover e pisca quando é atingido, como os slimes da amostra; os ataques dele continuam acertando no tempo certo).
  3. Confira Display name. O id feito a partir dele aparece abaixo do campo. Nenhum outro monstro pode ter esse id.

#Passo 2: Combat

Start from a monster copia tudo o que outro monstro tem: stats, habilidades, resistências, fases e saque. Escolha Nothing, start from the defaults para partir dos valores de um monstro novo. Escolher um monstro preenche os campos abaixo com os valores dele; mude o que este faz de diferente.

How it fights

Campo O que faz Padrão
Level O nível do monstro, no mínimo 1 1
Rank Normal, Elite ou Boss. Elites e chefes ganham uma moldura na placa; os chefes, uma barra no topo da tela Normal
Health A vida máxima, no mínimo 1 50
Damage O dano mínimo e máximo do ataque, e o elemento (vazio usa o elemento padrão) 1 a 3
Attack range (m) Cerca de 1,4 para corpo a corpo; mais longe para monstros que atiram. No mínimo 0,5 1,4
Attacks per second No mínimo 0,1 0,8
Move speed 3
Aggression Passive, Aggressive, ou Pack (entra na luta quando um monstro próximo é atacado) Aggressive

Rewards

Campo O que faz Padrão
Experience A experiência pela morte 10
Loot table Vazio: não deixa cair nada. Crie tabelas na categoria Loot None
Respawn seconds O tempo até ele voltar 30

#Passo 3: Animations

Sem um Animator, este passo só diz que não há nada para escolher.

Com um:

  1. Start from a monster copia os clips e os momentos de golpe de um monstro animado. Nothing começa vazio.
  2. Clips: Idle, Walk, Hit, Death e Attack. Os clips que você escolhe substituem os copiados. Os vazios são ignorados: sem Hit ele não recua, sem Death ele não cai.
  3. Hit lands at (aparece quando há um clip de ataque): de 0 (início) a 1 (fim) do ataque, quando o dano acerta. Padrão 0,5.

#Passo 4: Create

  1. Confira Prefab folder (uma pasta Prefabs ao lado da pasta do banco de dados, por padrão).
  2. Render its bestiary icon (ligado por padrão) desenha o retrato do monstro depois que ele é criado.
  3. Leia What will be made: os dados do monstro, o prefab (rede, movimento, uma área de clique, o componente Monster, as animações e a placa sobre a cabeça, mais o corpo saltitante sem Animator) e que ele entra no banco de dados.
  4. Pressione Create monster.

Os dados vão para Monsters, ao lado do banco de dados. Um monstro copiado recebe um retrato novo em vez do retrato do original. O novo monstro se abre na lista. Para colocá-lo no mundo, adicione um Monster Spawner a uma cena de mapa e escolha-o. Veja Monstros.

#Um jogador e MMO

Os dados são os mesmos nos dois. No MMO, o Login e o Central leem uma cópia (gamedata.json) gravada quando o Play & Servers inicia os serviços, então reinicie-os depois de mudar dados que o Login usa para criar personagens, como classes, itens iniciais ou o mapa inicial. Os servidores de mapa leem o banco de dados da sua build, então compile o servidor de mapa de novo depois de mudar dados. Veja Play & Servers.

#Dicas

  • Mantenha os ids curtos, em minúsculas, com letras, dígitos, - e _. O Project Check avisa sobre outros caracteres.
  • Nunca mude o id de algo que os jogadores já têm. Os salvamentos apontam para ids.
  • Use Duplicate para criar variantes, como uma cópia mais forte de um monstro ou um item com outras cores.
  • Collect referenced é útil depois de importar dados feitos em outro lugar, para que cada lista mostre o que o jogo realmente contém.

#Erros comuns

  • Criar assets com Create > KitARPG na janela Project e esquecer de listá-los. O jogo só conhece o que o banco de dados alcança. O Project Check lista os assets inalcançáveis como notas. Criar entradas por esta página as lista sozinho.
  • Um modelo sem classes. Ninguém pode escolhê-lo. O banco de dados informa "Player model '...' has no classes".
  • Duas entradas do mesmo tipo com o mesmo id. Só uma é encontrada. O Project Check informa isso como erro.
