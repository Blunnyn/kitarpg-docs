Servidores y despliegue

Docker

Corre todo el juego en línea en una máquina con Docker Compose: PostgreSQL, Caddy para HTTPS, Login, Central, un contenedor por mapa y Shop opcional. Esta página cubre cada servicio del archivo compose, el archivo .env, el despliegue en un VPS paso a paso, cómo agregar mapas y servidores de mapa en otras máquinas, las actualizaciones y los comandos del día a día.

#Qué hay en la carpeta Deploy

La carpeta Deploy está junto a la carpeta de tu proyecto de Unity y la carpeta Services. El archivo compose compila las imágenes de los servicios desde la carpeta que está encima de Deploy, así que espera esta estructura:

<your folder>/
  Deploy/            docker-compose.yml, .env, Caddyfile, Dockerfiles
    builds/starter/  the Linux map server build
    modules/login/   Login modules (optional)
    modules/central/ Central modules (optional)
    shop/            the Shop's catalog file (with the shop profile)
  Services/          the .NET services
  Unity/             your Unity project (the shared code in Assets/Blunnyn/KitARPG/Runtime/Shared)
Archivo Qué es
docker-compose.yml La pila
.env.example Cada variable que necesita la pila, con valores de ejemplo. Cópialo a .env
Caddyfile Las rutas de Caddy: HTTPS para Login, Central y los webhooks de Shop
Services.Dockerfile Compila Login, Central o Shop (--build-arg SERVICE=Login) desde la imagen del SDK de .NET 10 hacia la imagen del runtime de ASP.NET 10, corriendo como usuario no root en el puerto 8080
MapServer.Dockerfile Empaqueta una build de servidor de mapa Linux en una imagen Ubuntu 24.04, corriendo como usuario kit (uid 1001), con -batchmode -nographics -logFile -
Nota

Services.Dockerfile copia Services/ y Unity/Assets/Blunnyn/KitARPG/Runtime/Shared/ desde la carpeta que está encima de Deploy. Si la carpeta de tu proyecto de Unity tiene otro nombre, cambia esa línea COPY para que coincida.

#Los servicios del archivo compose

Servicio Imagen Puertos en el host Volúmenes Notas
caddy caddy:2.10-alpine 80/tcp, 443/tcp, 443/udp Caddyfile (solo lectura), caddy-data, caddy-config Obtiene y renueva los certificados TLS. Dirección fija KITARPG_PROXY_ADDRESS en la red de compose
postgres postgres:17-alpine Ninguno pgdata Base de datos kitarpg, usuario kitarpg, contraseña POSTGRES_PASSWORD. Salud revisada con pg_isready
login kitarpg/login 127.0.0.1:5100 → 8080 modules/login (solo lectura) Espera a que PostgreSQL esté sano
central kitarpg/central 127.0.0.1:5200 → 8080 modules/central (solo lectura) El enlace de mapa (UDP 7700) queda en la red de compose
shop kitarpg/shop 127.0.0.1:5300 → 5300 Carpeta shop Solo con --profile shop
map-town kitarpg/map-server 7777/udp Ninguno -map town -port 7777 -central central:7700
map-forest kitarpg/map-server 7778/udp Ninguno -map forest -port 7778
map-crypt kitarpg/map-server 7779/udp Ninguno -map crypt -port 7779
map-guild-hall kitarpg/map-server 7780/udp Ninguno -map guild_hall -port 7780

Las imágenes de mapa se compilan para linux/amd64. Los cuatro servicios de mapa comparten una imagen compilada desde builds/starter; solo cambia su comando.

Lo que el archivo compose define en los servicios:

  • Login y Central: Database__Provider=Postgres, la cadena de conexión con POSTGRES_PASSWORD, Auth__SigningKey=KITARPG_SIGNING_KEY, Proxy__Enabled=true y Proxy__KnownProxies__0 con la dirección de Caddy.
  • Solo Central: Central__MapKey=KITARPG_MAP_KEY, Central__MapNetworks__0 con la red de compose, y los mapas town 7777, forest 7778, crypt 7779 y guild_hall 7780 sin ejecutables (cada mapa es su propio contenedor, así que Central solo espera a que se registren).
  • Mapas: KITARPG_CENTRAL_KEY=KITARPG_MAP_KEY, KITARPG_SHOP_URL=http://shop:5300, KITARPG_SHOP_KEY, y -address KITARPG_PUBLIC_ADDRESS.
  • Shop: la base de datos, las opciones del proxy, ASPNETCORE_URLS=http://+:5300, Shop__CatalogPath=/app/shop/shop-conf.json, KITARPG_SHOP_KEY, Shop__AdminKey, y los secretos de los webhooks de Stripe y firmados.

Cada servicio se reinicia solo (unless-stopped).

#El archivo .env

Copia .env.example a .env y cambia cada valor. El archivo compose se niega a arrancar mientras falte una variable obligatoria, y los servicios rechazan los valores de ejemplo.

Variable Qué es Obligatoria
POSTGRES_PASSWORD La contraseña de la base de datos Sí
KITARPG_SIGNING_KEY Clave de firma de tokens para Login y Central, de al menos 32 caracteres aleatorios Sí
KITARPG_MAP_KEY Clave que presentan los servidores de mapa a Central, de al menos 16 caracteres aleatorios Sí
KITARPG_PUBLIC_ADDRESS La dirección que usan los jugadores para alcanzar los servidores de mapa: la IP pública de tu servidor o un dominio Predeterminado 127.0.0.1 (solo esta máquina)
KITARPG_LOGIN_DOMAIN Nombre público para Login, como login.mygame.com Predeterminado login.localhost
KITARPG_CENTRAL_DOMAIN Nombre público para Central, como central.mygame.com Predeterminado central.localhost
KITARPG_NETWORK La red de compose. Cámbiala solo si la subred está ocupada en el host Predeterminado 172.28.0.0/24
KITARPG_PROXY_ADDRESS La dirección fija de Caddy en esa red Predeterminado 172.28.0.10
KITARPG_SHOP_KEY Clave que envían los servidores de mapa a Shop, de al menos 16 caracteres aleatorios Con el perfil shop
KITARPG_SHOP_ADMIN_KEY Clave para la API de administración de Shop, de al menos 16 caracteres aleatorios Con el perfil shop
KITARPG_STRIPE_WEBHOOK_SECRET El secreto de firma de webhooks de Stripe (whsec_...). Vacío desactiva Stripe No
KITARPG_SHOP_SIGNED_SECRET Secreto compartido con tu propia tienda web. Vacío lo desactiva No

Crea cada secreto con openssl rand -hex 32. Mantén .env fuera del control de versiones.

#Pruébalo en tu computadora

Puedes correr la pila en tu propia máquina antes de alquilar un servidor. Con los nombres *.localhost predeterminados Caddy usa su propia autoridad de certificación local.

  1. Instala Docker Desktop.
  2. En Unity: KitARPG > Export Game Data for Services, luego KitARPG > Starter > Build Linux Server.
  3. En Deploy: cp .env.example .env, luego reemplaza los tres secretos obligatorios.
  4. docker compose up --build.
  5. Juega en el editor. El archivo compose publica Login y Central en 127.0.0.1:5100 y 127.0.0.1:5200, las direcciones predeterminadas del cliente, así que un cliente en el editor los alcanza. Detén primero los servicios en Play & Servers, o los puertos estarán ocupados.

En una Mac con Apple silicon los contenedores de mapa corren como x86 bajo emulación: sirve para probar, no para medir el rendimiento.

#Desplegar en un VPS

Un paso a paso para un VPS Linux (Ubuntu 24.04 o similar) con una IP pública.

#1. Preparar el servidor

  1. Alquila un VPS con CPU x86-64 (la imagen de mapa se compila para linux/amd64). Dimensiónalo según tus propias mediciones; consulta Rendimiento.

  2. Instala Docker Engine con el plugin Compose, siguiendo la guía de Docker para tu distribución.

  3. Abre el firewall exactamente para estos puertos:

    Puerto Protocolo Para
    22 TCP SSH
    80 TCP Caddy (certificados y la redirección a HTTPS)
    443 TCP y UDP Caddy (HTTPS y HTTP/3)
    7777 a 7780 UDP Los servidores de mapa (un puerto por mapa)

    No abras 5100, 5200, 5300, 5432 ni 7700.

#2. Apuntar tus dominios

Crea dos registros DNS A que apunten a la IP del VPS, por ejemplo login.mygame.com y central.mygame.com. Caddy solo puede obtener certificados una vez que resuelven.

#3. Compilar y copiar

En tu computadora:

  1. KitARPG > Export Game Data for Services.

  2. KitARPG > Starter > Build Linux Server.

  3. Copia la carpeta con Deploy, Services y el código compartido al servidor, por ejemplo con rsync:

    rsync -av --exclude 'bin' --exclude 'obj' --exclude '*.db' \
  Deploy Services Unity/Assets/Blunnyn/KitARPG/Runtime/Shared \
  user@server:/opt/mygame/ --relative

    La opción --relative conserva las rutas, así el servidor recibe /opt/mygame/Unity/Assets/Blunnyn/KitARPG/Runtime/Shared.

#4. Configurar

En el servidor, en /opt/mygame/Deploy:

cp .env.example .env
nano .env

Pon los secretos, KITARPG_PUBLIC_ADDRESS con la IP pública del VPS (o un dominio que apunte a ella) y los dos dominios.

#5. Arrancar

docker compose up --build -d
docker compose ps
docker compose logs -f central

Central registra Map link listening on UDP 7700, luego Map town (...) registered at <address>:7777 para cada mapa. Revisa los servicios desde el servidor mismo:

curl http://127.0.0.1:5100/health
curl http://127.0.0.1:5200/api/maps
curl https://login.mygame.com/health

#6. Compilar el cliente

Pon Login Url en https://login.mygame.com y Central Url en https://central.mygame.com en KitARPGSettings, luego Build Mac Client o Build Windows Client. Consulta Builds.

#7. Nombrar a tu admin

Crea tu cuenta en el juego, luego:

docker compose exec postgres psql -U kitarpg -d kitarpg \
  -c "UPDATE accounts SET \"Role\" = 4 WHERE \"Username\" = 'yourname';"

#8. Hacer copias de seguridad

Programa un pg_dump cada noche y copia los archivos fuera del servidor. Consulta Base de datos.

#Shop

docker compose --profile shop up --build -d
  • Pon KITARPG_SHOP_KEY y KITARPG_SHOP_ADMIN_KEY en .env primero; Shop se niega a arrancar sin claves reales.
  • El catálogo es Deploy/shop/shop-conf.json. El primer arranque copia la muestra ahí si falta. Los cambios se toman sin reiniciar.
  • Para que la API de administración guarde ofertas, el usuario del contenedor (uid 1654) debe poder escribir la carpeta: sudo chown 1654 shop. Se monta la carpeta, no el archivo, porque guardar reemplaza el archivo renombrándolo.
  • Caddy reenvía a Shop solo /api/shop/webhooks/* en el dominio de Login. La API de administración se alcanza en 127.0.0.1:5300 desde el servidor mismo. Para publicar el catálogo desde el editor, abre un túnel SSH (ssh -L 5300:127.0.0.1:5300 user@server) y usa http://127.0.0.1:5300 como dirección del servidor en línea.

Consulta Servicio Shop.

#Módulos

Pon cada módulo de Login en su propia carpeta bajo Deploy/modules/login y cada módulo de Central bajo Deploy/modules/central, luego docker compose restart login o central. Las carpetas se montan en solo lectura. Para rechazar cualquier módulo que no sea el tuyo, agrega Modules__Allow__0: MyGame.Central.dll al entorno del servicio. Consulta Módulos de servicio.

#Agregar un mapa

  1. Agrega el mapa en Unity (Game Database y su escena) y compila otra vez el servidor Linux.

  2. En docker-compose.yml, copia un bloque de mapa y cambia el nombre, el id del mapa y el puerto:

    map-desert:
  <<: *map
  command: ["-map", "desert", "-port", "7781", "-central", "central:7700", "-address", "${KITARPG_PUBLIC_ADDRESS:-127.0.0.1}"]
  ports:
    - "7781:7781/udp"

  3. Avísale a Central, en el entorno del servicio central:

    Central__Maps__4__Id: desert
Central__Maps__4__Port: "7781"

  4. Abre UDP 7781 en el firewall.

  5. docker compose up --build -d.

Cada id de mapa puede correr en un solo contenedor; Central rechaza un segundo registro del mismo id.

#Agregar servidores de mapa

Un mapa concurrido puede pasar a su propia máquina. El enlace de mapa (UDP 7700) no está cifrado, así que las máquinas deben compartir una red privada o un túnel WireGuard. Nunca publiques 7700 en internet.

En la máquina principal (donde corre Central):

  1. Configura la red privada o el túnel. Digamos que la máquina principal es 10.8.0.1 y la máquina del mapa es 10.8.0.2.

  2. Publica el enlace de mapa solo en la dirección del túnel, en el servicio central:

    ports:
  - "127.0.0.1:5200:8080"
  - "10.8.0.1:7700:7700/udp"

  3. Permite la red del túnel, junto a la red de compose:

    Central__MapNetworks__1: 10.8.0.0/24

  4. Quita el contenedor de ese mapa de esta máquina y conserva su entrada Central__Maps__N.

  5. docker compose up -d.

En la máquina del mapa:

  1. Instala Docker y copia Deploy/MapServer.Dockerfile y Deploy/builds/starter.

  2. Compila y corre el mapa:

    docker build -f MapServer.Dockerfile --build-arg BUILD_DIR=builds/starter -t kitarpg/map-server .
docker run -d --restart unless-stopped --name map-forest \
  -e KITARPG_CENTRAL_KEY=<map key> \
  -p 7778:7778/udp kitarpg/map-server \
  -map forest -port 7778 -central 10.8.0.1:7700 -address <this machine's public IP>

  3. Abre UDP 7778 en el firewall de esta máquina.

Central registra el registro del mapa. Si registra Refused a map link from ...: not in Central:MapNetworks, la red del túnel todavía no está permitida.

#Actualizar

Cuando cambias el juego o aplicas una actualización del kit:

  1. Haz una copia de seguridad de la base de datos.
  2. Vuelve a compilar lo que cambió: Export Game Data for Services y Build Linux Server en Unity, y el cliente.
  3. Copia los archivos nuevos al servidor.
  4. docker compose up --build -d. Los servicios con imágenes nuevas se reinician; las migraciones corren al arrancar.
  5. Publica el cliente nuevo al mismo tiempo: un cliente y un servidor de mapa compilados con código de red distinto se rechazan entre sí.

Reiniciar Central termina todas las sesiones, y los jugadores que se quedan en un mapa no pueden guardar hasta que vuelven a iniciar sesión. Actualiza en una ventana de mantenimiento, sin jugadores dentro.

#Comandos del día a día

Tarea Comando (en Deploy)
Estado docker compose ps
Seguir el registro de un servicio docker compose logs -f central
El registro de un mapa docker compose logs -f map-town
Reiniciar un servicio docker compose restart login
Detener todo docker compose down (conserva los volúmenes)
Jugadores por mapa curl http://127.0.0.1:5200/api/maps
CPU, memoria y red por contenedor docker stats
Shell de la base de datos docker compose exec postgres psql -U kitarpg -d kitarpg
Importante

docker compose down -v borra los volúmenes, incluido pgdata: desaparecen todas las cuentas y personajes. Nunca agregues -v en un servidor en vivo.

#Errores comunes

  • Caddy no puede obtener un certificado. Los dominios todavía no apuntan al servidor, o los puertos 80 y 443 están cerrados.
  • Los jugadores se conectan a 127.0.0.1. KITARPG_PUBLIC_ADDRESS sigue en el valor predeterminado. Ponlo en la IP pública y reinicia los mapas.
  • "Set POSTGRES_PASSWORD in Deploy/.env." El archivo .env falta o está incompleto.
  • Un servicio sale con "... is empty, too short or a sample value." Un secreto en .env todavía tiene su valor de ejemplo.
  • Los contenedores de mapa arrancan, pero Central no muestra mapas. Revisa los registros de los mapas: un KITARPG_MAP_KEY incorrecto, o a la build le falta la escena del mapa (Unknown map).
  • Nadie puede crear personajes. Login se compiló sin gamedata.json. Exporta los datos del juego y vuelve a compilar con docker compose up --build -d login.
