Servidores y despliegue

Launcher

Esta página aún no está traducida. Se muestra en inglés.

The KitARPG Launcher starts Login, Central, the map servers and, if you want, the Shop with one button or one command. This page covers its window, its command line, every field of launcher.json and how to run it on a server.

#What it is

The launcher is a small .NET 10 program in Services/Launcher (inside Assets/Blunnyn/KitARPG/Services~ in the Asset Store package), made with Avalonia so its window works on Windows, macOS and Linux. It:

  • finds the built services and your map server build;
  • makes fresh secret keys for this install on the first run;
  • starts Login, then Central (which starts the map servers), and the Shop when asked;
  • shows their output and the players on each map;
  • stops everything together.

KitARPG > Play and Servers uses the same launcher without a window: Start services runs it with --headless --config UserSettings/KitARPG/launcher.json. Most of the time you never open the launcher yourself. See Play & Servers.

#Before the first run

  1. Build the services: dotnet build in the Services folder, or Build services in Play & Servers.
  2. Build a map server for your computer: KitARPG > Starter > Build Mac Server or Build Windows Server. See Builds.
  3. Export the game data so Login can create characters. Play & Servers does it each time it starts the services. Running the launcher yourself, set GameDataFile or use KitARPG > Export Game Data for Services.

#The window

cd Services
dotnet run --project Launcher

The window shows KitARPG, a Start button, a status line, the maps with their players, a Premium shop check box and the log of every service.

  • Start starts the stack; the button becomes Stop.
  • The status line says Running. Open the Title scene or the client build to play. while it runs.
  • Premium shop turns on ShopEnabled and ShopAutoStart together: the Shop starts and stops with the rest, and the maps Central starts get its address and key.

Closing the window stops everything.

#Command line

Arguments What it does
(none) Opens the window
--headless Runs the same stack in the terminal, with every service's output on standard output. Ctrl+C or SIGTERM stops everything
--config <file> Uses another launcher.json instead of the one next to the launcher. Works with or without --headless
--headless --shop-only Runs only the Shop. The editor's Shop page starts and stops it this way, apart from the rest
--postgres Checks or creates a PostgreSQL database. Reads one JSON request on standard input and prints one JSON answer. See Checking PostgreSQL 
dotnet run --project Launcher                                    # window
dotnet run --project Launcher -- --headless                      # terminal
dotnet run --project Launcher -- --headless --config my.json     # another settings file
dotnet run --project Launcher -- --headless --shop-only --config my.json

With --headless the launcher first prints every problem it finds, each line starting with !, then starts what it can and prints the Login and Central addresses. With --shop-only a problem stops it with exit code 1.

#launcher.json

The launcher reads launcher.json next to itself, or the file given with --config. A missing file is created. Empty fields are filled in and the file is saved again on every start, so you only write what you want to change.

Field What it does Default
LoginDll Path to KitARPG.Services.Login.dll Found: a Login folder next to the launcher, or Login/bin/Debug/net10.0 in a parent folder
CentralDll Path to KitARPG.Services.Central.dll Found the same way
ShopDll Path to KitARPG.Services.Shop.dll Found the same way
MapServerExecutable Your map server build Found in a parent folder: Builds/Starter/MacServer/KitARPGServer.app/Contents/MacOS/Unity on macOS, Builds/Starter/WindowsServer/KitARPGServer.exe on Windows
DataFolder Where the SQLite database and the map logs go data next to launcher.json
ModulesFolder Game modules: Login loads login/, Central loads central/ modules next to launcher.json (both subfolders are created empty)
DatabaseProvider Sqlite or Postgres Sqlite
ConnectionString PostgreSQL connection, used only with Postgres. With Sqlite the file is DataFolder/kitarpg.db Empty
Maps The maps Central knows: Id, Port, AutoStart town 7777 (starts with Central), forest 7778, crypt 7779
ExternalMaps Map ids run by something else, such as the editor in Play. Central waits for them to register instead of starting them Empty
GameDataFile The gamedata.json Login reads Empty: the one next to the Login service
LoginPort Login's HTTP port 5100
CentralPort Central's HTTP port 5200
MapLinkPort Central's UDP port for map servers 7700
SigningKey Token signing key for Login and Central 64 random hex characters, made on first run
MapKey Key map servers present to Central 32 random hex characters, made on first run
ShopPort The Shop's HTTP port 5300
ShopMapKey Key map servers send the Shop as X-Shop-Key 32 random hex characters, made on first run
ShopAdminKey Key for the Shop's admin API (X-Admin-Key), which the editor publishes the catalog with 32 random hex characters, made on first run
ShopCatalogFile The Shop's catalog file. If missing, the sample next to the Shop service is copied there shop-conf.json next to launcher.json
ShopEnabled Central gets KITARPG_SHOP_URL and KITARPG_SHOP_KEY, and the map servers it starts inherit them false
ShopAutoStart The Shop starts and stops with Login and Central false

A map the sample gained in a kit update (for example crypt) is added to an older file, unless its id or port is already taken.

Example:

{
  "DatabaseProvider": "Postgres",
  "ConnectionString": "Host=localhost;Port=5432;Database=kitarpg;Username=kitarpg;Password=...",
  "Maps": [
    { "Id": "town", "Port": 7777, "AutoStart": true },
    { "Id": "forest", "Port": 7778, "AutoStart": false },
    { "Id": "crypt", "Port": 7779, "AutoStart": false }
  ],
  "ExternalMaps": [ "forest" ],
  "ShopEnabled": true,
  "ShopAutoStart": true
}
Importante

launcher.json holds the signing key, the map key and the Shop keys in plain text. Keep it out of version control and out of builds. The editor keeps its copy in UserSettings/KitARPG/, which Unity never ships.

#What it starts, and how

The launcher starts each service with dotnet <dll>, from the dll's folder, and passes settings as environment variables.

  1. Login with ASPNETCORE_URLS=http://127.0.0.1:<LoginPort>, the database settings, Auth__SigningKey, Modules__Path=<ModulesFolder>/login and, when set, Characters__GameDataFile.
  2. A pause of 1.5 seconds, so Login runs the database migrations first.
  3. Shop, with ShopAutoStart: ASPNETCORE_URLS=http://127.0.0.1:<ShopPort>, ASPNETCORE_ENVIRONMENT=Production, the database settings, Shop__CatalogPath, Shop__MapKeys__0=<ShopMapKey>, Shop__AdminKey.
  4. Central with ASPNETCORE_URLS=http://127.0.0.1:<CentralPort>, the database settings, Auth__SigningKey, Central__MapLinkPort, Central__MapKey, Modules__Path=<ModulesFolder>/central and one Central__Maps__N__* group per map:
    • Executable: MapServerExecutable, or empty for an external map;
    • Port and AutoStart (always off for an external map);
    • Arguments: -batchmode -nographics -map {map} -port {port} -central {central} -logFile <DataFolder>/logs/map-{map}.log. With ShopEnabled, Central also gets KITARPG_SHOP_URL and KITARPG_SHOP_KEY, which reach every map it starts.

Central starts the AutoStart maps right away and the others when the first player needs them. The services listen on 127.0.0.1 only, so nothing the launcher starts is reachable from other computers.

Every line of output is shown with the service name in brackets, such as [Login] or [Central]. Map servers write to <DataFolder>/logs/map-<id>.log.

#Running a map in the editor

To debug a map in the Unity editor while the rest runs from the launcher:

  1. Add the map id to ExternalMaps (Play & Servers does it with Map in the editor).
  2. Start the services. Central waits for that map to register instead of starting the build.
  3. Play the map server in the editor. It registers with Central like a build would.

#Checking PostgreSQL

--postgres is how the editor's Set up PostgreSQL window talks to PostgreSQL. It reads one JSON request from standard input:

Field What it is Default
action check tests the game's login; create makes the database and user with an admin login check
host Server address localhost
port Server port 5432
ssl Prefer, Require or Disable Prefer
database The game's database kitarpg
user The game's user kitarpg
password The game user's password Empty
adminUser Admin login, only for create postgres
adminPassword Admin password, only for create. Never saved Empty
adminDatabase Database the admin connects to first postgres 
echo '{"action":"check","host":"localhost","port":5432,"database":"kitarpg","user":"kitarpg","password":"..."}' \
  | dotnet run --project Launcher -- --postgres

It prints { "Ok": true|false, "Message": "...", "ConnectionString": "..." }. check also confirms that the user can create tables. create makes the role and the database (owned by that role), grants it everything it needs and works on hosted servers where the admin isn't a superuser. See Database.

#One computer only

The launcher is made for running everything on one computer:

  • Login, Central and the Shop listen on 127.0.0.1 only.
  • The map servers it starts get no -address, so they announce the address Central sees them at, which is 127.0.0.1. A player on another computer would be sent there.
  • Nothing puts HTTPS in front of the services.

For a server that players reach over the internet, use Docker Compose, which adds Caddy for HTTPS and gives each map its public address. See Docker.

#Tips

  • Use one launcher.json per setup (SQLite for quick tests, PostgreSQL for staging) and switch with --config.
  • After you rebuild a service or the map server, restart the launcher. Play & Servers tells you when the running services are older than their builds.
  • If ports are taken, another launcher is probably still running. Stop it, or change the ports in launcher.json.

#Common mistakes

  • "Login service not found." The services aren't built, or LoginDll points to an old path. Build them, or clear the field so it is found again.
  • "Map server not found." Build the map server for this computer, or set MapServerExecutable.
  • "DatabaseProvider is Postgres but ConnectionString is empty." Fill in the connection string or switch back to Sqlite.
  • Changing the keys by hand while maps run. Map servers keep the key they started with. Restart the whole stack after changing keys.
