Servidores y despliegue

Lanzador

El KitARPG Launcher arranca Login, Central, los servidores de mapa y, si quieres, Shop con un botón o un comando. Esta página cubre su ventana, su línea de comandos, cada campo de launcher.json y cómo correrlo en un servidor.

#Qué es

El lanzador es un pequeño programa .NET 10 en Services/Launcher (dentro de Assets/Blunnyn/KitARPG/Services~ en el paquete de la Asset Store), hecho con Avalonia para que su ventana funcione en Windows, macOS y Linux. Hace esto:

  • encuentra los servicios compilados y tu build del servidor de mapa;
  • crea claves secretas nuevas para esta instalación en la primera ejecución;
  • arranca Login, luego Central (que arranca los servidores de mapa), y Shop cuando se pide;
  • muestra su salida y los jugadores en cada mapa;
  • detiene todo junto.

KitARPG > Play and Servers usa el mismo lanzador sin ventana: Start services lo corre con --headless --config UserSettings/KitARPG/launcher.json. La mayor parte del tiempo nunca abres el lanzador tú mismo. Consulta Play & Servers.

#Antes de la primera ejecución

  1. Compila los servicios: dotnet build en la carpeta Services, o Build services en Play & Servers.
  2. Compila un servidor de mapa para tu computadora: KitARPG > Starter > Build Mac Server o Build Windows Server. Consulta Builds.
  3. Exporta los datos del juego para que Login pueda crear personajes. Play & Servers lo hace cada vez que arranca los servicios. Si corres el lanzador tú mismo, pon GameDataFile o usa KitARPG > Export Game Data for Services.

#La ventana

cd Services
dotnet run --project Launcher

La ventana muestra KitARPG, un botón Start, una línea de estado, los mapas con sus jugadores, una casilla Premium shop y el registro de cada servicio.

  • Start arranca la pila; el botón pasa a ser Stop.
  • La línea de estado dice Running. Open the Title scene or the client build to play. mientras corre.
  • Premium shop activa ShopEnabled y ShopAutoStart juntos: Shop arranca y se detiene con el resto, y los mapas que arranca Central reciben su dirección y su clave.

Cerrar la ventana detiene todo.

#Línea de comandos

Argumentos Qué hace
(ninguno) Abre la ventana
--headless Corre la misma pila en la terminal, con la salida de cada servicio en la salida estándar. Ctrl+C o SIGTERM detienen todo
--config <file> Usa otro launcher.json en vez del que está junto al lanzador. Funciona con o sin --headless
--headless --shop-only Corre solo Shop. La página Shop del editor lo arranca y lo detiene así, aparte del resto
--postgres Revisa o crea una base de datos PostgreSQL. Lee una petición JSON en la entrada estándar e imprime una respuesta JSON. Consulta Revisar PostgreSQL 
dotnet run --project Launcher                                    # window
dotnet run --project Launcher -- --headless                      # terminal
dotnet run --project Launcher -- --headless --config my.json     # another settings file
dotnet run --project Launcher -- --headless --shop-only --config my.json

Con --headless el lanzador primero imprime cada problema que encuentra, cada línea empezando con !, luego arranca lo que puede e imprime las direcciones de Login y Central. Con --shop-only un problema lo detiene con código de salida 1.

#launcher.json

El lanzador lee launcher.json junto a sí mismo, o el archivo dado con --config. Un archivo que falta se crea. Los campos vacíos se completan y el archivo se vuelve a guardar en cada arranque, así que solo escribes lo que quieres cambiar.

Campo Qué hace Predeterminado
LoginDll Ruta a KitARPG.Services.Login.dll Se encuentra: una carpeta Login junto al lanzador, o Login/bin/Debug/net10.0 en una carpeta superior
CentralDll Ruta a KitARPG.Services.Central.dll Se encuentra de la misma forma
ShopDll Ruta a KitARPG.Services.Shop.dll Se encuentra de la misma forma
MapServerExecutable Tu build del servidor de mapa Se encuentra en una carpeta superior: Builds/Starter/MacServer/KitARPGServer.app/Contents/MacOS/Unity en macOS, Builds/Starter/WindowsServer/KitARPGServer.exe en Windows
DataFolder Dónde van la base de datos SQLite y los registros de los mapas data junto a launcher.json
ModulesFolder Módulos del juego: Login carga login/, Central carga central/ modules junto a launcher.json (ambas subcarpetas se crean vacías)
DatabaseProvider Sqlite o Postgres Sqlite
ConnectionString Conexión de PostgreSQL, usada solo con Postgres. Con Sqlite el archivo es DataFolder/kitarpg.db Vacío
Maps Los mapas que conoce Central: Id, Port, AutoStart town 7777 (arranca con Central), forest 7778, crypt 7779, guild_hall 7780; Play & Servers agrega cada otro mapa de la base de datos del juego en el siguiente puerto libre
ExternalMaps Ids de mapas que corre otra cosa, como el editor en Play. Central espera a que se registren en vez de arrancarlos Vacío
GameDataFile El gamedata.json que lee Login Vacío: el que está junto al servicio Login
LoginPort Puerto HTTP de Login 5100
CentralPort Puerto HTTP de Central 5200
MapLinkPort Puerto UDP de Central para los servidores de mapa 7700
SigningKey Clave de firma de tokens para Login y Central 64 caracteres hexadecimales aleatorios, creados en la primera ejecución
MapKey Clave que presentan los servidores de mapa a Central 32 caracteres hexadecimales aleatorios, creados en la primera ejecución
ShopPort Puerto HTTP de Shop 5300
ShopMapKey Clave que envían los servidores de mapa a Shop como X-Shop-Key 32 caracteres hexadecimales aleatorios, creados en la primera ejecución
ShopAdminKey Clave para la API de administración de Shop (X-Admin-Key), con la que el editor publica el catálogo 32 caracteres hexadecimales aleatorios, creados en la primera ejecución
ShopCatalogFile El archivo de catálogo de Shop. Si falta, se copia ahí la muestra que está junto al servicio Shop shop-conf.json junto a launcher.json
ShopEnabled Central recibe KITARPG_SHOP_URL y KITARPG_SHOP_KEY, y los servidores de mapa que arranca los heredan false
ShopAutoStart Shop arranca y se detiene con Login y Central false

Un mapa que la muestra ganó en una actualización del kit (por ejemplo crypt) se agrega a un archivo más viejo, salvo que su id o su puerto ya estén ocupados.

Ejemplo:

{
  "DatabaseProvider": "Postgres",
  "ConnectionString": "Host=localhost;Port=5432;Database=kitarpg;Username=kitarpg;Password=...",
  "Maps": [
    { "Id": "town", "Port": 7777, "AutoStart": true },
    { "Id": "forest", "Port": 7778, "AutoStart": false },
    { "Id": "crypt", "Port": 7779, "AutoStart": false },
    { "Id": "guild_hall", "Port": 7780, "AutoStart": false }
  ],
  "ExternalMaps": [ "forest" ],
  "ShopEnabled": true,
  "ShopAutoStart": true
}
Importante

launcher.json guarda la clave de firma, la clave del mapa y las claves de Shop en texto plano. Mantenlo fuera del control de versiones y fuera de las builds. El editor guarda su copia en UserSettings/KitARPG/, que Unity nunca incluye.

#Qué arranca, y cómo

El lanzador arranca cada servicio con dotnet <dll>, desde la carpeta de la dll, y le pasa las opciones como variables de entorno.

  1. Login con ASPNETCORE_URLS=http://127.0.0.1:<LoginPort>, las opciones de la base de datos, Auth__SigningKey, Modules__Path=<ModulesFolder>/login y, cuando está definido, Characters__GameDataFile.
  2. Una pausa de 1,5 segundos, para que Login corra primero las migraciones de la base de datos.
  3. Shop, con ShopAutoStart: ASPNETCORE_URLS=http://127.0.0.1:<ShopPort>, ASPNETCORE_ENVIRONMENT=Production, las opciones de la base de datos, Shop__CatalogPath, Shop__MapKeys__0=<ShopMapKey>, Shop__AdminKey.
  4. Central con ASPNETCORE_URLS=http://127.0.0.1:<CentralPort>, las opciones de la base de datos, Auth__SigningKey, Central__MapLinkPort, Central__MapKey, Modules__Path=<ModulesFolder>/central y un grupo Central__Maps__N__* por mapa:
    • Executable: MapServerExecutable, o vacío para un mapa externo;
    • Port y AutoStart (siempre desactivado para un mapa externo);
    • Arguments: -batchmode -nographics -map {map} -port {port} -central {central} -logFile <DataFolder>/logs/map-{map}.log. Con ShopEnabled, Central también recibe KITARPG_SHOP_URL y KITARPG_SHOP_KEY, que llegan a cada mapa que arranca.

Central arranca los mapas con AutoStart de inmediato y los demás cuando el primer jugador los necesita. Los servicios escuchan solo en 127.0.0.1, así que nada de lo que arranca el lanzador se puede alcanzar desde otras computadoras.

Cada línea de salida se muestra con el nombre del servicio entre corchetes, como [Login] o [Central]. Los servidores de mapa escriben en <DataFolder>/logs/map-<id>.log.

#Correr un mapa en el editor

Para depurar un mapa en el editor de Unity mientras el resto corre desde el lanzador:

  1. Agrega el id del mapa a ExternalMaps (Play & Servers lo hace con Map in the editor).
  2. Arranca los servicios. Central espera a que ese mapa se registre en vez de arrancar la build.
  3. Juega el servidor de mapa en el editor. Se registra en Central como lo haría una build.

#Revisar PostgreSQL

--postgres es la forma en que la ventana Set up PostgreSQL del editor habla con PostgreSQL. Lee una petición JSON de la entrada estándar:

Campo Qué es Predeterminado
action check prueba el usuario del juego; create crea la base de datos y el usuario con un usuario administrador check
host Dirección del servidor localhost
port Puerto del servidor 5432
ssl Prefer, Require o Disable Prefer
database La base de datos del juego kitarpg
user El usuario del juego kitarpg
password La contraseña del usuario del juego Vacío
adminUser Usuario administrador, solo para create postgres
adminPassword Contraseña del administrador, solo para create. Nunca se guarda Vacío
adminDatabase Base de datos a la que se conecta primero el administrador postgres 
echo '{"action":"check","host":"localhost","port":5432,"database":"kitarpg","user":"kitarpg","password":"..."}' \
  | dotnet run --project Launcher -- --postgres

Imprime { "Ok": true|false, "Message": "...", "ConnectionString": "..." }. check también confirma que el usuario puede crear tablas. create crea el rol y la base de datos (con ese rol como dueño), le da todo lo que necesita y funciona en servidores alojados donde el administrador no es superusuario. Consulta Base de datos.

#Solo una computadora

El lanzador está hecho para correr todo en una computadora:

  • Login, Central y Shop escuchan solo en 127.0.0.1.
  • Los servidores de mapa que arranca no reciben -address, así que anuncian la dirección con la que los ve Central, que es 127.0.0.1. Un jugador en otra computadora sería enviado ahí.
  • Nada pone HTTPS delante de los servicios.

Para un servidor al que los jugadores llegan por internet, usa Docker Compose, que agrega Caddy para HTTPS y le da a cada mapa su dirección pública. Consulta Docker.

#Consejos

  • Usa un launcher.json por configuración (SQLite para pruebas rápidas, PostgreSQL para staging) y cambia con --config.
  • Después de volver a compilar un servicio o el servidor de mapa, reinicia el lanzador. Play & Servers te avisa cuando los servicios en marcha son más viejos que sus builds.
  • Si los puertos están ocupados, probablemente otro lanzador sigue corriendo. Detenlo, o cambia los puertos en launcher.json.

#Errores comunes

  • "Login service not found." Los servicios no están compilados, o LoginDll apunta a una ruta vieja. Compílalos, o vacía el campo para que se encuentre de nuevo.
  • "Map server not found." Compila el servidor de mapa para esta computadora, o pon MapServerExecutable.
  • "DatabaseProvider is Postgres but ConnectionString is empty." Completa la cadena de conexión o vuelve a Sqlite.
  • Cambiar las claves a mano mientras corren los mapas. Los servidores de mapa conservan la clave con la que arrancaron. Reinicia toda la pila después de cambiar las claves.
