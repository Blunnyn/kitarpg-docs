Servidores y despliegue

Configuration

Esta página aún no está traducida. Se muestra en inglés.

Every setting of Login, Central, the Shop and the map servers, with its default, the environment variable that sets it, and the client settings that point players at your servers.

#How the services read settings

Login, Central and the Shop are ASP.NET Core services. Each reads, in this order (later wins):

  1. appsettings.json next to the service.
  2. appsettings.<Environment>.json, for example appsettings.Development.json.
  3. Environment variables.
  4. Command line arguments (--Section:Key=value).

A setting written Section:Key in this manual is the variable Section__Key (two underscores). List entries take an index: Auth:SigningKeys item 0 is Auth__SigningKeys__0.

The environment is set with ASPNETCORE_ENVIRONMENT. Anything other than Development counts as production: the services then refuse to start with an empty, short or sample secret. The launcher runs Login and Central without setting it (production) and the Shop as Production.

ASPNETCORE_URLS sets the address a service listens on, for example http://127.0.0.1:5100. The Docker images listen on http://+:8080 (the Shop on http://+:5300).

Consejo

Keep appsettings.json as shipped and put your values in environment variables (the launcher and Docker Compose both do). A kit update can then replace the services without touching your settings.

Auth:SigningKeys Extra keys for rotation. The first one signs; every key, plus SigningKey, is accepted Empty
Auth:Issuer Issuer and audience of the tokens kitarpg
Auth:TokenMinutes Access token lifetime 30
Auth:RememberDays Days a "Remember me" token lasts 30
Auth:AttemptsPerMinute Requests to /api/auth/* per client address and minute 10
Auth:FailedLoginsPerAccount Wrong passwords per username before it locks 5
Auth:FailedLoginMinutes Minutes a username stays locked, and the window failures are counted in 15
Auth:BanCheckSeconds How long a ban check is cached. A banned account's token stops working within this 5

#Central:Maps

Each entry describes one map.

Field What it does Default
Id The map id from your Game Database Empty
Executable Map server build to launch. Empty means something else starts the map and Central only waits 3 seconds for it to register Empty
Arguments Command line for the launched map. {map}, {port}, {central} (CentralHost:MapLinkPort) and {key} are replaced -batchmode -nographics -map {map} -port {port} -central {central}
Port The map's game port 7777
AutoStart Launch the map when Central starts instead of with the first player false

Central passes the map key to the processes it launches in KITARPG_CENTRAL_KEY, which other users of the machine can't read the way they can read a command line. Use {key} with -centralKey only for map builds older than that variable.

As environment variables:

Central__Maps__0__Id=town
Central__Maps__0__Port=7777
Central__Maps__0__Executable=/opt/kitarpg/map/KitARPGServer.x86_64
Central__Maps__0__AutoStart=true

#Shop

The Shop's settings (Shop:CatalogPath, Shop:MapKeys, Shop:AdminKey, the payment providers and its rate limits) are in Shop service.

#Environment variables by name

Besides the Section__Key forms above, the kit reads these variables directly:

Variable Read by What it is
KITARPG_CENTRAL_KEY Map server The map key for Central. -centralKey on the command line wins over it
KITARPG_SHOP_URL Map server The Shop's address, such as http://shop:5300. -shop wins over it
KITARPG_SHOP_KEY Map server, Shop The map key for the Shop. On the Shop it adds one more accepted key to Shop:MapKeys. -shopKey wins on the map
ASPNETCORE_ENVIRONMENT Services Development or anything else (production)
ASPNETCORE_URLS Services Listen addresses

The Docker Compose .env file has its own variables (POSTGRES_PASSWORD, KITARPG_SIGNING_KEY, KITARPG_MAP_KEY, KITARPG_PUBLIC_ADDRESS, the domains and the Shop secrets) that the compose file turns into the settings above. See Docker.

#Map server command line

A map server is your game built as a server (see Builds). It reads:

Argument What it does Default
-batchmode -nographics Unity's flags for running without a window. A map server only starts by itself in batch mode
-map <id> Which map from the Game Database to run MapServer.mapId in the scene (town)
-port <port> UDP port players connect to The transport's port in KitNetwork (7777)
-central <host:port> Central's map link CentralLink.host and port (127.0.0.1:7700)
-centralKey <key> Map key. Prefer KITARPG_CENTRAL_KEY: a command line is visible to every user of the machine KITARPG_CENTRAL_KEY
-address <host> Address players are told to connect to. Empty uses the address Central sees the map at MapServer.publicAddress (empty)
-shop <url> The Shop's address KITARPG_SHOP_URL
-shopKey <key> Key for the Shop KITARPG_SHOP_KEY
-logFile <file> Unity's log file. - writes to standard output (the Docker image does) Unity's default

Example:

KITARPG_CENTRAL_KEY=<map key> ./KitARPGServer.x86_64 -batchmode -nographics \
  -map forest -port 7778 -central 10.8.0.1:7700 -address play.mygame.com -logFile -

Without a Shop address and key the in-game shop stays closed. A Shop address that is plain http:// on a public address is refused, since the key would cross the internet readable; use https:// or a private address (10.x, 172.16-31.x, 192.168.x, loopback, or a name without dots like shop).

The map server logs Map server '<id>' starting on port <port>, Central at <host>:<port>., then Registered with Central as <id>. once Central accepts it.

#Client settings

The client finds Login and Central through Assets/Settings/Resources/KitARPGSettings.asset, which KitARPG > Play and Servers edits.

Field What it does Default
Mode (mode) Online or SinglePlayer. The kit's build menus set it for each build Online
Login Url (loginUrl) Login's address http://127.0.0.1:5100
Central Url (centralUrl) Central's address http://127.0.0.1:5200
Save File (saveFile) Single player save, in the player's persistent data folder savegame.db

Before you build a client for players, set Login Url and Central Url to your HTTPS addresses, for example https://login.mygame.com and https://central.mygame.com. A release client build stops if either is plain HTTP on anything but this computer.

In the editor and in builds with KITARPG_DEV only, the client also reads:

Argument What it does
-mode online or -mode single Overrides Mode
-login <url> Overrides Login Url
-centralUrl <url> Overrides Central Url
-save <file> Overrides Save File
-autoplay Signs in by itself with a test account
-smoketest <mode> Runs an automatic test (enter, portal, systems)

Release clients ignore all of them, so a shortcut can't send a player's password to another server.

#Development and production values

Secret Development value What production needs
Auth:SigningKey development-only-key-change-me-... 32 or more random characters, same on Login and Central
Central:MapKey development-map-key 16 or more random characters, same on Central and every map
Shop:MapKeys dev-shop-key 16 or more random characters, same on the Shop and every map
Shop:AdminKey dev-shop-admin-key 16 or more random characters, or empty to turn the admin API off
Database password None (SQLite) Long and random. kitarpg, postgres, password, admin, root, secret and sample values are refused

The launcher and Play & Servers make random keys per computer. To make your own:

openssl rand -hex 32
