Servidores y despliegue

Configuración

Cada opción de Login, Central, Shop y los servidores de mapa, con su valor predeterminado, la variable de entorno que la define, y las opciones del cliente que dirigen a los jugadores a tus servidores.

#Cómo leen las opciones los servicios

Login, Central y Shop son servicios ASP.NET Core. Cada uno lee, en este orden (lo último gana):

  1. appsettings.json junto al servicio.
  2. appsettings.<Environment>.json, por ejemplo appsettings.Development.json.
  3. Variables de entorno.
  4. Argumentos de línea de comandos (--Section:Key=value).

Una opción escrita Section:Key en este manual es la variable Section__Key (dos guiones bajos). Las entradas de listas llevan un índice: el elemento 0 de Auth:SigningKeys es Auth__SigningKeys__0.

El entorno se define con ASPNETCORE_ENVIRONMENT. Cualquier cosa que no sea Development cuenta como producción: entonces los servicios se niegan a arrancar con un secreto vacío, corto o de ejemplo. El lanzador corre Login y Central sin definirlo (producción) y Shop como Production.

ASPNETCORE_URLS define la dirección en la que escucha un servicio, por ejemplo http://127.0.0.1:5100. Las imágenes de Docker escuchan en http://+:8080 (Shop en http://+:5300).

Consejo

Deja appsettings.json como viene y pon tus valores en variables de entorno (el lanzador y Docker Compose lo hacen así). Así una actualización del kit puede reemplazar los servicios sin tocar tus opciones.

#Auth (Login y Central)

Login firma los tokens y Central los revisa, así que ambos necesitan el mismo SigningKey, SigningKeys e Issuer.

Opción Qué hace Predeterminado
Auth:SigningKey Clave HMAC para los tokens de acceso, de al menos 32 bytes. Obligatoria Vacío (development-only-key-... en Development)
Auth:SigningKeys Claves extra para rotación. La primera firma; se acepta cada clave, más SigningKey Vacío
Auth:Issuer Emisor y audiencia de los tokens kitarpg
Auth:TokenMinutes Vida del token de acceso 30
Auth:RememberDays Días que dura un token de "Remember me" 30
Auth:AttemptsPerMinute Peticiones a /api/auth/* por dirección de cliente y minuto 10
Auth:FailedLoginsPerAccount Contraseñas incorrectas por nombre de usuario antes de que se bloquee 5
Auth:FailedLoginMinutes Minutos que un nombre de usuario queda bloqueado, y la ventana en la que se cuentan las fallas 15
Auth:BanCheckSeconds Cuánto tiempo se guarda en caché una revisión de baneo. El token de una cuenta baneada deja de funcionar dentro de este tiempo 5

#Central:Maps

Cada entrada describe un mapa.

Campo Qué hace Predeterminado
Id El id del mapa de tu Game Database Vacío
Executable Build del servidor de mapa a lanzar. Vacío significa que otra cosa arranca el mapa y Central solo espera 3 segundos a que se registre Vacío
Arguments Línea de comandos para el mapa lanzado. Se reemplazan {map}, {port}, {central} (CentralHost:MapLinkPort) y {key} -batchmode -nographics -map {map} -port {port} -central {central}
Port El puerto de juego del mapa 7777
AutoStart Lanza el mapa cuando arranca Central en vez de con el primer jugador false

Central les pasa la clave del mapa a los procesos que lanza en KITARPG_CENTRAL_KEY, que los demás usuarios de la máquina no pueden leer como sí pueden leer una línea de comandos. Usa {key} con -centralKey solo para builds de mapa más viejas que esa variable.

Como variables de entorno:

Central__Maps__0__Id=town
Central__Maps__0__Port=7777
Central__Maps__0__Executable=/opt/kitarpg/map/KitARPGServer.x86_64
Central__Maps__0__AutoStart=true

#Shop

Las opciones de Shop (Shop:CatalogPath, Shop:MapKeys, Shop:AdminKey, los proveedores de pago y sus límites de ritmo) están en Servicio Shop.

#Variables de entorno por nombre

Además de las formas Section__Key de arriba, el kit lee estas variables directamente:

Variable La lee Qué es
KITARPG_CENTRAL_KEY Servidor de mapa La clave del mapa para Central. -centralKey en la línea de comandos le gana
KITARPG_SHOP_URL Servidor de mapa La dirección de Shop, como http://shop:5300. -shop le gana
KITARPG_SHOP_KEY Servidor de mapa, Shop La clave del mapa para Shop. En Shop agrega una clave aceptada más a Shop:MapKeys. -shopKey le gana en el mapa
ASPNETCORE_ENVIRONMENT Servicios Development o cualquier otra cosa (producción)
ASPNETCORE_URLS Servicios Direcciones de escucha

El archivo .env de Docker Compose tiene sus propias variables (POSTGRES_PASSWORD, KITARPG_SIGNING_KEY, KITARPG_MAP_KEY, KITARPG_PUBLIC_ADDRESS, los dominios y los secretos de Shop) que el archivo compose convierte en las opciones de arriba. Consulta Docker.

#Línea de comandos del servidor de mapa

Un servidor de mapa es tu juego compilado como servidor (consulta Builds). Lee:

Argumento Qué hace Predeterminado
-batchmode -nographics Las opciones de Unity para correr sin ventana. Un servidor de mapa solo arranca solo en modo batch
-map <id> Qué mapa de la Game Database correr MapServer.mapId en la escena (town)
-port <port> Puerto UDP al que se conectan los jugadores El puerto del transporte en KitNetwork (7777)
-central <host:port> El enlace de mapa de Central CentralLink.host y port (127.0.0.1:7700)
-centralKey <key> Clave del mapa. Prefiere KITARPG_CENTRAL_KEY: una línea de comandos es visible para todos los usuarios de la máquina KITARPG_CENTRAL_KEY
-address <host> Dirección a la que se les dice a los jugadores que se conecten. Vacío usa la dirección con la que Central ve al mapa MapServer.publicAddress (vacío)
-shop <url> La dirección de Shop KITARPG_SHOP_URL
-shopKey <key> Clave para Shop KITARPG_SHOP_KEY
-logFile <file> El archivo de registro de Unity. - escribe en la salida estándar (la imagen de Docker lo hace) El predeterminado de Unity

Ejemplo:

KITARPG_CENTRAL_KEY=<map key> ./KitARPGServer.x86_64 -batchmode -nographics \
  -map forest -port 7778 -central 10.8.0.1:7700 -address play.mygame.com -logFile -

Sin una dirección y clave de Shop la tienda del juego queda cerrada. Una dirección de Shop con http:// simple en una dirección pública se rechaza, porque la clave cruzaría internet legible; usa https:// o una dirección privada (10.x, 172.16-31.x, 192.168.x, loopback, o un nombre sin puntos como shop).

El servidor de mapa registra Map server '<id>' starting on port <port>, Central at <host>:<port>., luego Registered with Central as <id>. una vez que Central lo acepta.

#Componentes del servidor de mapa

Viven en el prefab KitNetwork (Assets/Blunnyn/KitARPG/Samples/Starter/Prefabs/KitNetwork.prefab en la muestra) y en el objeto del servidor de mapa de la escena. Cambiarlos cambia cada build que hagas después.

#Map Server (MapServer)

Campo Qué hace Predeterminado
Map Id (mapId) Mapa a correr cuando se arranca sin -map town
Public Address (publicAddress) Dirección a la que se conectan los clientes. Vacío deja que Central use la dirección que ve Vacío
Save Interval Seconds (saveIntervalSeconds) Cada cuánto se guarda cada jugador 60
Start In Editor (startInEditor) Arranca el servidor al entrar en modo Play en el editor Activado

#Central Link (CentralLink)

Campo Qué hace Predeterminado
host, port El enlace de mapa de Central, cuando no se da -central 127.0.0.1, 7700
key Clave del mapa cuando no están definidos ni -centralKey ni KITARPG_CENTRAL_KEY development-map-key
heartbeatSeconds Cada cuánto informa el mapa su cantidad de jugadores 5
retrySeconds Cada cuánto intenta alcanzar Central de nuevo 3
logSeconds Cada cuánto se envían las líneas del registro del juego 2
maxUnconfirmedAudit Líneas de auditoría de GM esperando a Central antes de que los comandos de GM dejen de correr 500

#Network manager y transporte

El KitNetworkManager y el KcpTransport de KitNetwork son componentes propios de Mirror. El kit pone estos valores; consulta Rendimiento antes de cambiarlos.

Componente Campo Valor del kit
KitNetworkManager Send Rate (sendRate): ticks del servidor por segundo 30
KitNetworkManager Max Connections (maxConnections): jugadores que acepta un servidor de mapa 100
KcpTransport port 7777
KcpTransport Timeout (ms) 10.000
TicketAuthenticator timeout: segundos que tiene un cliente para presentar un ticket válido 10
KitInterestManagement visRange: metros que ve un jugador 40
KitInterestManagement rebuildInterval: segundos entre reconstrucciones de la visibilidad 1

#Opciones del cliente

El cliente encuentra a Login y Central a través de Assets/Settings/Resources/KitARPGSettings.asset, que edita KitARPG > Play and Servers.

Campo Qué hace Predeterminado
Mode (mode) Online o SinglePlayer. Los menús de build del kit lo ponen para cada build Online
Login Url (loginUrl) La dirección de Login http://127.0.0.1:5100
Central Url (centralUrl) La dirección de Central http://127.0.0.1:5200
Save File (saveFile) Guardado de un jugador, en la carpeta de datos persistentes del jugador savegame.db

Antes de compilar un cliente para los jugadores, pon Login Url y Central Url con tus direcciones HTTPS, por ejemplo https://login.mygame.com y https://central.mygame.com. Una build de cliente de release se detiene si alguna es HTTP simple en algo que no sea esta computadora.

Solo en el editor y en builds con KITARPG_DEV, el cliente también lee:

Argumento Qué hace
-mode online o -mode single Reemplaza Mode
-login <url> Reemplaza Login Url
-centralUrl <url> Reemplaza Central Url
-save <file> Reemplaza Save File
-autoplay Inicia sesión solo con una cuenta de prueba
-smoketest <mode> Corre una prueba automática (enter, portal, systems)

Los clientes de release los ignoran todos, así un acceso directo no puede enviar la contraseña de un jugador a otro servidor.

#Valores de desarrollo y de producción

Secreto Valor en Development Lo que necesita producción
Auth:SigningKey development-only-key-change-me-... 32 o más caracteres aleatorios, iguales en Login y Central
Central:MapKey development-map-key 16 o más caracteres aleatorios, iguales en Central y en cada mapa
Shop:MapKeys dev-shop-key 16 o más caracteres aleatorios, iguales en Shop y en cada mapa
Shop:AdminKey dev-shop-admin-key 16 o más caracteres aleatorios, o vacío para desactivar la API de administración
Contraseña de la base de datos Ninguna (SQLite) Larga y aleatoria. Se rechazan kitarpg, postgres, password, admin, root, secret y los valores de ejemplo

El lanzador y Play & Servers crean claves aleatorias por computadora. Para crear las tuyas:

openssl rand -hex 32
