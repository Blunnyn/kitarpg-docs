El editor

Game Database

La página Game Database muestra todos los datos del juego en un solo lugar: modelos de jugador, clases, atributos, skills, ítems, monstruos, botín, tiendas, misiones, mapas y los ajustes propios de la base de datos. Navegas por tipo a la izquierda, eliges una entrada en el medio y la editas a la derecha. También tiene dos asistentes que crean un modelo de jugador nuevo o un monstruo nuevo a partir de un modelo 3D.

#Dónde está

  • KitARPG > Game Database, o
  • la página Game Database de la ventana KitARPG (Ctrl/Cmd+Shift+K).

Cuando los datos tienen problemas, la barra lateral muestra cuántos son junto a la página.

#Qué es la base de datos del juego

La base de datos del juego es un asset GameDatabase. El juego lee todos sus datos a través de él, por id. En ella listas las entradas principales (modelos de jugador, mapas, monstruos, ítems, etc.); todo aquello a lo que apuntan esas entradas (las skills de una clase, la tabla de botín de un monstruo, los ítems de una tabla de botín) se reúne solo. Así, una skill agregada a una clase está en el juego sin listarla dos veces.

La base de datos se pone en el Game Instance del prefab de red. La muestra Starter crea una en Assets/Blunnyn/KitARPG/Samples/Starter/Data/StarterDatabase.asset. Login y Central reciben una copia como gamedata.json cada vez que Play & Servers inicia los servicios.

#La disposición

La página usa todo el ancho de la ventana, en tres columnas bajo una barra de herramientas.

#Barra de herramientas

Elemento Qué hace
Campo Game Database La base de datos que se edita. Elige otra para cambiar; la elección se recuerda
Etiqueta N problems Aparece cuando los datos tienen problemas. La página Settings los lista
Collect referenced Escribe en sus propias listas cada entrada a la que la base de datos solo llega por referencias, para que cada lista muestre todo. No toca los modelos de jugador
Export for services Escribe gamedata.json en la carpeta Login del código de los servicios, para servicios que corres a mano. Igual que KitARPG > Export Game Data for Services

Cuando el proyecto no tiene base de datos del juego, la página muestra No game database yet con Create game database. Elige dónde guardarla; los datos que crees después van a carpetas junto a ella.

#Categorías (izquierda)

Los tipos de datos, en grupos, cada uno con su conteo. El conteo incluye las entradas alcanzadas por referencias.

Grupo Categoría Contiene
Characters Models Prefabs de jugador. Las clases de un modelo son las que puede elegir un personaje nuevo con ese aspecto
Characters Classes Lo que es un personaje: atributos por nivel, skills y con qué empieza
Characters Attributes Fuerza, inteligencia y los demás, y las stats que da cada punto
Characters Elements Tipos de daño, cada uno con su propia resistencia
Combat Skills Lo que lanzan jugadores y monstruos, armado con efectos
Combat Statuses Buffs y debuffs: veneno, aturdimiento, escudos y similares
Combat Weapon Types Espada, arco, bastón: cómo ataca y se anima cada tipo
Items Items Armas, equipo, pociones, pergaminos y todo lo demás que cabe en una bolsa
Items Sets Piezas que suman bonificaciones cuando se llevan juntas. Una pieza se une a un set desde su propia página
Items Currencies El oro y cualquier otro dinero que use el juego
Items Loot Lo que sueltan los monstruos y con qué frecuencia
Items Shops Lo que venden y compran las tiendas de NPC
World Monsters Stats, skills, botín y comportamiento de cada monstruo
World Quests Objetivos, recompensas y quién puede tomarlas
World Maps Escenas entre las que viajan los jugadores, con sus reglas
Database Settings Mapa inicial, tabla de experiencia, oro y las reglas que comparten todas las entradas

Cuando eliges Items (o una de sus subcategorías), las subcategorías de ítems se abren debajo:

Subcategoría Muestra Una nueva es

Shields Equipo para la mano secundaria Equipo en la posición Off Hand
Hats Equipo de cabeza Equipo en la posición Head
Cloaks Equipo de espalda: capas, mochilas, alas Equipo en la posición Back

Rings Anillos; un personaje lleva dos Equipo en la posición Ring
Chest Armaduras, túnicas y camisas Equipo en la posición Chest
Gloves Guantes, guanteletes y brazales Equipo en la posición Hands
Legs Pantalones, faldas y grebas Equipo en la posición Legs
Boots Botas y zapatos Equipo en la posición Feet
Cosmetics Equipo que solo cambia el aspecto Equipo cosmético, posición Head, sin mejoras

Las subcategorías de equipo no muestran armas, munición ni cosméticos. Consulta Ítems y Equipo.

#Entradas (medio)

El título y la pista de la categoría, un campo de búsqueda y la lista. Cada fila muestra el ícono de la entrada (o su primera letra cuando no tiene), su nombre y una segunda línea: el id, o para los ítems la categoría y el id, o para los modelos el id del modelo y cuántas clases tiene.

  • Escribe en el campo de búsqueda para filtrar por nombre o id.
  • Haz clic en una fila para editarla. El doble clic además selecciona el asset en la ventana Project.
  • Las flechas Up y Down recorren la lista.
  • El botón de abajo crea una entrada nueva: + New class, + New skill, + New weapon, etc. Cuando una categoría puede crear más de un tipo (Items puede crear un arma, equipo, un consumible o un ítem simple), un menú pregunta cuál.

Las entradas nuevas se llaman "New ..." con un id hecho a partir del nombre, se guardan en una carpeta con el nombre de la categoría junto al asset de la base de datos (por ejemplo Data/Skills), se agregan a la lista de la base de datos y se abren. Cámbiales el nombre en sus campos.

Las categorías Models y Monsters tienen sus propios botones, descritos en Modelo de jugador nuevo y Monstruo nuevo.

#Página de la entrada (derecha)

Arriba de la página se ven el ícono, el nombre, una etiqueta con el tipo (Weapon, Skill, Monster...) y una etiqueta con el id, más tres botones:

Botón Qué hace
Show file Selecciona el asset en la ventana Project
Duplicate Copia el asset junto a él, con un id hecho a partir del nombre de la copia, lo agrega a la misma lista y lo abre. No está en los modelos
Delete Pregunta "Move ... to the trash? Characters that saved its id lose it." y mueve el asset a la papelera. En los modelos el botón es Remove: saca el modelo de la base de datos y conserva el prefab

Debajo, la ruta del asset, y luego los campos en tarjetas, una tarjeta por grupo de campos. Los campos son los mismos que ves en el Inspector.

Algunos tipos tienen tarjetas extra sobre los campos:

  • Ítems: una tarjeta In game con el tooltip que ven los jugadores, rareza y categoría, descripción, cada bonificación (las tiradas como rangos), el nivel y las clases del equipo, el precio de venta y de compra, la pila, el peso y si está ligado, y el ícono del ítem.
  • Equipo con bonificaciones fijas: "N fixed bonuses that never roll. Turn them into min and max ranges, 25% up and down?" con Make them roll, que pasa las bonificaciones fijas a rangos aleatorios. Consulta Equipo.
  • Modelos: una tarjeta Look con una vista previa del prefab (doble clic para abrir el prefab), sus clases (la primera marcada "(default)") y cuántas animaciones están puestas. Bajo los campos, una sección Animations edita el Character Animations del modelo: clips para moverse, recibir golpes, morir, atacar con cada tipo de arma y lanzar cada skill. Un prefab sin ese componente muestra Add Character Animations.
  • Mapas: una tarjeta Adding a map con lo que necesita un mapa y en qué estado está cada parte. Consulta Mapas.

#Modelo de jugador nuevo

En Models, al pie de la lista hay:

  • + New player model, que abre el asistente en la columna derecha.
  • "Or add a player prefab you already made" (o agrega un prefab de jugador que ya hiciste): un campo de prefab y Add prefab. Agrega un componente Player Model cuando el prefab no lo tiene y lo lista en la base de datos. Arrastra un prefab desde la ventana Project; un objeto de escena se rechaza.

El asistente tiene cuatro pasos que se muestran como una barra arriba. Los pasos que ya pasaste se pueden pulsar para volver. Cancel lo cierra sin crear nada, Back vuelve un paso y Next avanza; Next aparece en gris mientras el paso tiene un problema, que se muestra en una línea naranja.

#Paso 1: Model

  1. Arrastra un FBX o un prefab al campo de The 3D model. Al lado se muestra una vista previa.
  2. Lee el estado que aparece debajo:
    • Humanoid rig: las armas van en sus manos y puede compartir las animaciones del kit.
    • Generic rig: usa animaciones hechas para este rig, y pon después los huesos de las manos en el modelo.
    • No Animator: no se va a animar. Agrega un Animator al modelo, o pon su rig en Humanoid en los ajustes de importación.
    • No skinned meshes: el equipo cambia partes del cuerpo por skinned mesh, así que este modelo se muestra sin cambios de equipo.
  3. En Name, revisa Display name (completado con el nombre del modelo) e Id (hecho a partir del nombre hasta que escribas el tuyo). El id se guarda con los personajes; cambiarlo después rompe los personajes creados con él.
  4. Marca Own hair only para conservar el pelo, las orejas o los cuernos propios del cuerpo: no se le ofrecen peinados.

#Paso 2: Classes

  1. En Classes it can be, marca las clases que puede elegir un personaje con este aspecto. La primera marcada es la predeterminada.
  2. Para crear clases junto con el modelo, presiona + New class en New classes, escribe un nombre y, si quieres, elige una clase en copy of para empezar con sus atributos, skills y equipo. x quita una fila.

Hace falta al menos una clase. Los nombres de las clases nuevas no deben coincidir con el id de una clase existente.

#Paso 3: Animations

  1. Start from a model: elige un modelo existente para copiar sus animaciones (clips, momentos de golpe, por arma y por skill) y su catálogo de apariencia, o Nothing, start empty. Con un modelo elegido:
    • Copy its animations (prendido por defecto).
    • Copy the game's own components on it (not the kit's) (prendido por defecto): los componentes que agregaste a ese modelo vienen con sus valores.
    • Aparece una advertencia cuando un modelo es humanoide y el otro no, porque los clips copiados pueden no reproducirse en este rig.
  2. Upper body (solo humanoide): Use an upper body mask (prendido por defecto) deja que los personajes ataquen y lancen skills mientras caminan, con las piernas todavía en movimiento. Deja Mask vacío para usar la máscara del kit, o elige tu propia Avatar Mask.

Con las animaciones vacías, pon los clips después en la tarjeta Animations del modelo. Los golpes igual llegan a tiempo.

#Paso 4: Create

  1. Revisa Prefab folder. Por defecto es una carpeta Prefabs junto a la carpeta de la base de datos. Debajo se muestra la ruta completa del prefab. La carpeta debe estar dentro de Assets, y no debe existir un prefab con ese nombre.
  2. Lee What will be made: el prefab con el Player Model, red, movimiento, inventario, stats, skills, misiones, chat, amigos, grupo, intercambio, gremio, banco, forja, correo, mercado, tienda, PvP, equipo, apariencia, animaciones y el nombre sobre la cabeza; las clases; las animaciones; la máscara; y que se une a la base de datos.
  3. Presiona Create player.

El asistente crea las clases nuevas (en Classes junto a la base de datos) y el prefab, agrega los dos a la base de datos y abre el modelo nuevo, listo para editar. Consulta Modelos de jugador.

#Monstruo nuevo

En Monsters, al pie de la lista hay:

  • + New monster, que abre el asistente.
  • Blank monster data, que crea solo un asset de datos Monster, sin prefab.

#Paso 1: Model

  1. Arrastra un FBX o un prefab a The 3D model.
  2. El estado dice Animated (eliges sus clips en el paso 3) o No Animator (salta al moverse y destella al recibir golpes, como los slimes de la muestra; sus ataques igual llegan a tiempo).
  3. Revisa Display name. Bajo el campo se muestra el id hecho a partir de él. Ningún otro monstruo puede tener ese id.

#Paso 2: Combat

Start from a monster copia todo lo que tiene otro monstruo: stats, skills, resistencias, fases y botín. Elige Nothing, start from the defaults para empezar con los valores de un monstruo nuevo. Elegir un monstruo completa los campos de abajo con sus valores; cambia lo que este hace distinto.

How it fights

Campo Qué hace Por defecto

Attacks per second Al menos 0,1 0,8
Move speed 3

Campo Qué hace Por defecto

#Paso 3: Animations

Sin Animator, este paso solo dice que no hay nada que elegir.

Con uno:

  1. Start from a monster copia los clips y los momentos de golpe de un monstruo animado. Nothing empieza vacío.
  2. Clips: Idle, Walk, Hit, Death y Attack. Los clips que eliges reemplazan a los copiados. Los vacíos se saltean: sin Hit no reacciona al golpe, sin Death no cae.
  3. Hit lands at (se muestra cuando hay un clip de ataque): de 0 (inicio) a 1 (final) del ataque, cuándo llega el daño. Por defecto 0,5.

#Paso 4: Create

  1. Revisa Prefab folder (una carpeta Prefabs junto a la carpeta de la base de datos por defecto).
  2. Render its bestiary icon (prendido por defecto) dibuja el retrato del monstruo después de crearlo.
  3. Lee What will be made: los datos del monstruo, el prefab (red, movimiento, un área de clic, el componente Monster, sus animaciones y la placa sobre su cabeza, más el cuerpo que salta cuando no hay Animator) y que se une a la base de datos.
  4. Presiona Create monster.

Los datos van en Monsters junto a la base de datos. Un monstruo copiado recibe un retrato nuevo en lugar del original. El monstruo nuevo se abre en la lista. Para ponerlo en el mundo, agrega un Monster Spawner a una escena de mapa y elígelo. Consulta Monstruos.

#Un jugador y MMO

Los datos son los mismos en los dos. En MMO, Login y Central leen una copia (gamedata.json) que se escribe cuando Play & Servers inicia los servicios, así que reinícialos después de cambiar datos que Login usa para crear personajes, como clases, ítems iniciales o el mapa inicial. Los servidores de mapa leen la base de datos de su build, así que vuelve a compilar el servidor de mapa después de cambiar datos. Consulta Play & Servers.

#Consejos

  • Mantén los ids cortos, en minúsculas, con letras, dígitos, - y _. Project Check avisa sobre otros caracteres.
  • Nunca cambies el id de algo que los jugadores ya tienen. Los guardados apuntan a ids.
  • Usa Duplicate para crear variantes, como una copia más fuerte de un monstruo o un ítem de otro color.
  • Collect referenced sirve después de importar datos hechos en otro lugar, para que cada lista muestre lo que el juego realmente contiene.

#Errores comunes

  • Crear assets con Create > KitARPG en la ventana Project y olvidar listarlos. El juego solo conoce lo que alcanza la base de datos. Project Check lista los assets inalcanzables como notas. Crear las entradas desde esta página las lista solas.
  • Un modelo sin clases. Nadie puede elegirlo. La base de datos informa "Player model '...' has no classes".
  • Dos entradas del mismo tipo con el mismo id. Solo se encuentra una. Project Check lo informa como error.
