Referencia

Solución de problemas

Problemas con los que te puedes encontrar en KitARPG, qué significa cada mensaje, por qué pasa y cómo corregirlo. Busca tu síntoma por sección: configuración, jugar, servicios MMO, inicio de sesión, builds, bases de datos, servidores y herramientas de GM.

#Primeras revisiones

Antes de buscar un problema concreto, estas cuatro revisiones resuelven la mayoría:

  1. Detén Play. Muchos ajustes están bloqueados durante Play.
  2. Abre Project Check (KitARPG > Project Check) y corrige cada error. La mayoría tienen un botón de corrección.
  3. Aplica las actualizaciones del kit pendientes en Overview.
  4. En MMO, vuelve a compilar y reinicia: Play & Servers > Rebuild de los servicios, Rebuild del servidor de mapa, y luego Restart.

Registros para leer:

Registro Dónde
Console de Unity Window > General > Console
Servicios iniciados desde el editor Play & Servers > tarjeta Log, o UserSettings/KitARPG/services.log
Cada servidor de mapa UserSettings/KitARPG/data/logs/map-<id>.log
Shop iniciado desde el editor UserSettings/KitARPG/shop.log
Pruebas de modo Play Logs/KitARPG-PlayMode-Tests.xml

#Configuración e importación

#Los materiales se ven rosados

URP no es el render pipeline activo, o un nivel de calidad todavía usa otro pipeline. Los materiales del kit son materiales de URP.

Solución: abre KitARPG > Setup Wizard y presiona Set everything up. Pone URP como pipeline predeterminado y en cada nivel de calidad, y pone el color Linear. Para revisarlo a mano: Project Settings > Graphics > Default Render Pipeline y Project Settings > Quality, cada nivel.

#Las etiquetas no tienen texto ni fuente

Los recursos esenciales de TextMesh Pro no están en el proyecto. Project Check muestra el error "TextMesh Pro's essential resources aren't in the project, so every label in the kit's UI and sample has no font."

Solución: presiona Set everything up en el Setup Wizard, o el botón de importar del error de Project Check, o Window > TextMeshPro > Import TMP Essential Resources. En modo batch la importación queda en cola y no termina antes de que Unity salga; córrela una vez en el editor normal.

#Los menús no reciben clics

El EventSystem de una escena tiene el módulo de UI del otro sistema de input. Project Check avisa: "<scene>'s EventSystem has the UI module of the other input system, so menus may not take clicks."

Solución: presiona Fix scenes en la advertencia, o Set everything up en el Setup Wizard. El kit también cambia el módulo cuando una escena se carga con el Input System, como respaldo.

#InvalidOperationException sobre la clase Input al presionar Play

El proyecto usa solo el Input System (las plantillas nuevas de Unity lo hacen) y algún script lee UnityEngine.Input directamente. El código propio del kit nunca lo hace.

Solución: en tus scripts, llama a KitInput.GetKey, KitInput.GetKeyDown, KitInput.GetMouseButton, KitInput.mousePosition y los demás en lugar de Input. Funcionan en los dos tipos de proyecto. O pon Project Settings > Player > Active Input Handling en Both.

#Los cambios en Game Settings no llegan a una escena

La escena cambia campos del prefab Game Instance, así que Game Settings (que edita el prefab) no le llega. Un caso común: los controles táctiles aparecen con Input Layout en Mouse And Keys. Project Check avisa: "<scene> overrides Game Settings on its Game Instance (...), so changes in Game Settings don't reach that scene."

Solución: presiona Fix scenes en Project Check. Revierte esos cambios para que la escena siga al prefab.

#"Scenes in Build Settings" está en rojo

Title no es la primera escena activa, o, en MMO, Server no está en la lista. El detalle dice "The first scene must be Title, and Server must be listed."

Solución: presiona Use starter scenes. Pone Title, Server, Town, Forest y Crypt en Build Settings, Title primero. Si la muestra todavía no existe, ofrece armarla.

#Falta "SQLite library for this platform"

El guardado de un jugador necesita la biblioteca nativa de SQLite en Assets/Blunnyn/KitARPG/Plugins/SQLite/ (macOS/libe_sqlite3.dylib, Windows/e_sqlite3.dll o Linux/libe_sqlite3.so).

Solución: vuelve a importar el paquete de KitARPG con la carpeta Plugins/SQLite marcada.

#"Stop Play before building the starter sample."

Armar la muestra durante Play guardaría objetos rotos en sus prefabs.

Solución: detén Play y vuelve a armarla.

#El Setup Wizard no se abre

Se abre solo una vez por proyecto. Después, UserSettings/KitARPG/setup-done lo mantiene cerrado.

Solución: abre KitARPG > Setup Wizard.

#Jugar en el editor

#No puedo cambiar Game Settings ni Modules

Sus campos están bloqueados durante Play, porque se guardan en el prefab de red.

Solución: detén Play primero.

#"Add the Title scene to Build Settings first."

Play & Servers abre Title desde Build Settings.

Solución: presiona Use starter scenes, o agrega tu escena Title como primera escena.

#El juego empieza sin pantalla de título

El botón Play de Unity juega la escena abierta. Una escena de mapa sola no tiene sesión.

Solución: abre Title, o usa Play en Overview o en Play & Servers, que abren Title por ti.

#Los jugadores o los monstruos no se mueven en un mapa nuevo

La escena del mapa no tiene un NavMesh horneado. El movimiento y los monstruos usan el NavMesh en el servidor.

Solución: agrega un NavMeshSurface a la escena y hornéalo. Duplicar el Forest de la muestra te da uno ya configurado. Consulta Mapas.

#Los jugadores que llegan a un mapa no tienen dónde pararse

Project Check: "<scene> has no SpawnPoint; players arriving at '<map>' have nowhere to stand."

Solución: agrega un SpawnPoint a la escena.

#Funciones en un jugador responden "Only on an online server."

Amigos, grupos, gremios, correo, el mercado, los recaudadores, la tienda del juego y algunos comandos de moderación necesitan un servidor.

Solución: cambia a MMO en Play & Servers, o apaga esos sistemas en Modules para que no aparezcan.

#Servicios MMO

#No se encuentra el SDK de .NET 10

La fila dice "dotnet was not found. Install the .NET 10 SDK, then check again." o "Found ...; the services need 10." Unity no siempre recibe el PATH de tu shell.

Solución: instala el SDK de .NET 10 (no solo el runtime) desde https://dotnet.microsoft.com/download/dotnet/10.0, y luego presiona Check again. Si está instalado en un lugar poco común, pon un enlace a dotnet en una de las carpetas que revisa el kit: /usr/local/share/dotnet, /usr/local/bin, /opt/homebrew/bin, ~/.dotnet en Mac y Linux, C:\Program Files\dotnet en Windows. Reiniciar Unity Hub y Unity después de instalar también refresca el PATH.

#"Services source: Not found."

El kit no encontró una carpeta con KitARPG.Services.slnx. Busca junto a la carpeta de tu proyecto de Unity (../Services), dentro de ella (Services) y en Assets/Blunnyn/KitARPG/Services~.

Solución: espera a que el editor termine de cargar (desempaqueta Services.zip al cargar), o presiona Browse y elige la carpeta. Si Services~ no existe, revisa que Assets/Blunnyn/KitARPG/Services.zip se haya importado.

#"dotnet build failed."

Los servicios no compilaron. Play & Servers muestra las primeras líneas del error. "dotnet build failed. Run it in a terminal to see why." significa que no había ninguna para mostrar.

Solución: abre una terminal en la carpeta de los servicios y corre dotnet build. Causas comunes: sin internet la primera vez (se descargan los paquetes NuGet), un SDK más viejo que el 10, o archivos cambiados a mano en Services~. Volver a importar el kit restaura los servicios.

#"Something else is using port ..."

Servicios iniciados desde una terminal o desde una sesión anterior ocupan los puertos 5100, 5200 o 7700. Pueden estar corriendo código más viejo.

Solución: detenlos. Si Play & Servers muestra "Services from an earlier editor session are still running (process ...)", presiona Stop the old services. Si no, busca el proceso (en Mac y Linux lsof -i :5100, en Windows netstat -ano | findstr 5100) y termínalo.

#"The services or the map server were rebuilt after they started, so they still run the old code. Restart them."

Compilaste mientras corrían.

Solución: presiona Restart.

#"No map reached Central"

Overview lo muestra cuando los servicios corren pero ningún servidor de mapa se registró. Por lo general falta la build del servidor de mapa o está desactualizada.

Solución: compila el servidor de mapa (Play & Servers, paso 1) y reinicia los servicios. Si sigue, lee UserSettings/KitARPG/data/logs/map-town.log.

#La build del servidor de mapa: "Missing the scene of a map"

A la build le falta la escena de un mapa, así que los jugadores que viajan ahí terminan de vuelta en el inicio de sesión.

Solución: presiona Rebuild. Las builds toman sus escenas de los mapas de la Game Database. Si la build misma dice "No scene file named ...", el mapa nombra una escena que no existe: corrige el nombre en la página del mapa.

#"Two players need the MMO mode"

Play with two players solo funciona en MMO.

Solución: cambia a MMO en Play & Servers.

#Play with two players no inicia Player 2

Multiplayer Play Mode de Unity no pudo activar solo al segundo jugador. La Console dice que prendas Player 2.

Solución: en Window > Multiplayer > Multiplayer Play Mode, prende Player 2, y luego presiona Play with two otra vez. El primer arranque importa el proyecto en el segundo editor, lo que tarda un rato. Si el diálogo dice "Build the services first", haz el paso 1 de Play & Servers.

#No puedo cambiar la base de datos

"Stop the services to change the database."

Solución: presiona Stop en el paso 3, cámbiala e inicia otra vez.

#version_mismatch: "The game and the server are different versions"

El cliente envía un hash corto de todo lo que viaja por la red (campos sincronizados, listas y mensajes). El servidor de mapa lo compara con el suyo y rechaza a un cliente compilado con código distinto, en lugar de fallar después al leer los datos.

Solución: vuelve a compilar el servidor de mapa (o el cliente) para que los dos salgan del mismo código, y luego reinicia los servicios. Pasa seguido después de cambiar código, actualizar el kit o dejar corriendo un servidor de mapa viejo.

#mode_mismatch: "The server plays a different game mode"

El cliente y el servidor de mapa se compilaron con distinto Game Settings > Control Mode (controlMode).

Solución: compila los dos con el mismo modo. Después de cambiar el modo, vuelve a compilar el servidor de mapa y cada cliente.

#session_busy: "Your character is still being saved"

Volviste a iniciar sesión mientras tu personaje todavía estaba en un mapa. Central le pide a ese mapa que guarde y saque al personaje y espera hasta 5 segundos (Central:KickWaitSeconds). Si el guardado no llegó, responde session_busy en lugar de arriesgar que un guardado viejo sobrescriba ítems más nuevos.

Solución: espera unos segundos y presiona Play otra vez. Si nunca se resuelve, el servidor de mapa viejo está trabado: revisa su registro o reinicia los servicios.

#map_unavailable: "That map is not running right now"

Central no pudo iniciar el servidor de mapa a tiempo (Central:LaunchTimeoutSeconds, 60), o el mapa no está en su lista.

Solución: revisa que la build del servidor de mapa exista y corra, que el puerto del mapa esté libre, y el registro del mapa. En Docker, revisa que el mapa tenga su propio servicio en docker-compose.yml y una entrada Central__Maps__N.

#Los jugadores que viajan a un mapa nuevo terminan de vuelta en el inicio de sesión

A la build del servidor de mapa le falta la escena de ese mapa, o Central no conoce el mapa.

Solución: vuelve a compilar el servidor de mapa; Play & Servers nombra la escena que falta. Para Docker, agrega el servicio del mapa y su entrada en la lista de mapas de Central.

#"Kicked" por saturación

Un cliente que envía muchos más comandos de los que podría una persona (bastante más de 30 por segundo) se desconecta con el motivo flooding. Pasa con clientes modificados o bots.

Solución: nada para los jugadores normales. Si tu propio código envía un comando en cada frame, envíalo con menos frecuencia.

#Builds

#"KitARPG found N problem(s)"

Project Check corre antes de cada build y la detiene si hay errores.

Solución: abre Project Check, corrige los errores y vuelve a compilar. Puedes apagar la detención en Project Check con Stop builds on errors, pero los problemas siguen ahí.

#"The client talks to ... without HTTPS"

Un cliente MMO de release debe llegar a Login y Central por HTTPS, salvo en esta computadora. La build se detiene: "... so passwords and tokens would cross the internet readable."

Solución: pon Login Url y Central Url en Assets/Settings/Resources/KitARPGSettings.asset con tus direcciones https://. Para probar contra un servidor sin HTTPS, usa el cliente de prueba, nunca para jugadores.

#"The client is built with Mono"

Un cliente MMO de release debe compilarse con IL2CPP, o su código se publica como DLLs legibles.

Solución: pon Player Settings > Scripting Backend en IL2CPP. Compila los clientes de Windows en Windows y los de Mac en una Mac; IL2CPP no hace compilación cruzada entre ellos.

#"... goes into the online client but uses ..., which is server code."

Un ensamblado que va al cliente referencia código de servidor.

Solución: mueve el código que necesita el servidor a un ensamblado cuyo nombre termine en .Server (Create > KitARPG > Scripts > Game Server Assembly). KitARPG > Check Build Separation muestra qué va dónde.

#"Single player hosts its own world and needs ..."

A una build de un jugador hecha fuera de los menús del kit le falta el código de servidor o el guardado local.

Solución: compila con KitARPG > Starter > Build Mac Single Player o Build Windows Single Player, que agregan los símbolos KITARPG_SERVER y KITARPG_SINGLEPLAYER.

#Una build falla dentro de URP después de Play

Si una sesión de Play terminó sin devolver el render pipeline del proyecto, un nivel de calidad puede apuntar a una copia destruida. El kit lo repara solo cuando termina Play y antes de cada build.

Solución: si igual pasa, abre Project Settings > Quality y pon el asset de URP en cada nivel, o corre Set everything up otra vez.

#La build del servidor Linux falla en una Mac

Compilar un servidor Linux desde una Mac necesita Linux Dedicated Server Build Support y el paquete com.unity.toolchain.macos-arm64-linux.

Solución: agrega el módulo en Unity Hub y el paquete en el Package Manager.

#Bases de datos

#Mensajes de la configuración de PostgreSQL

Set up PostgreSQL... informa cada problema común en palabras simples:

Mensaje Solución
"Wrong user or password." Revisa los datos de inicio de sesión
"That database doesn't exist. Create it from here with an admin login." Usa Create the database for me
"The server doesn't take this login from this computer (pg_hba.conf): ..." Permite tu dirección en el pg_hba.conf del servidor, o usa el host que permite
"That login isn't allowed to do this: ..." Usa un usuario administrador para crear, o un usuario dueño de la base de datos
"No server answered there. Check the host and port, and that PostgreSQL is running." Inicia PostgreSQL, revisa el host y el puerto
"The server didn't answer in time. Check the host, the port and the firewall." Abre el puerto en el firewall
"Connected to PostgreSQL ..., but ... can't create tables in ..." Haz al usuario dueño de la base de datos, o crea la base de datos desde la ventana
"Use a password of 8 characters or more." Una contraseña más larga

Los servidores alojados (RDS, Supabase, Neon) suelen necesitar SSL: Require.

#Docker en esta computadora no inicia

La opción Docker necesita Docker Desktop corriendo. Inicia un contenedor llamado kitarpg-postgres en el primer puerto libre desde 5432.

Solución: inicia Docker Desktop y vuelve a intentar. Si existe un contenedor de antes, el kit reutiliza su volumen y pone una contraseña nueva.

#¿Dónde está la base de datos local?

UserSettings/KitARPG/data/kitarpg.db para el MMO en tu computadora. El guardado de un jugador es savegame.db en la carpeta de datos persistentes; Play & Servers muestra su ruta.

#Servidores en producción

#Un servicio se niega a iniciar: "... is empty, too short or a sample value"

Fuera de Development, Login, Central y Shop rechazan secretos de muestra o vacíos: la clave de firma, la clave de mapas, la contraseña de la base de datos, las claves de la tienda.

Solución: pon valores largos y aleatorios en Deploy/.env (la clave de firma necesita al menos 32 caracteres). Consulta Seguridad.

#Los clientes no pueden conectarse a los mapas del servidor

Los servidores de mapa usan UDP. Los jugadores necesitan los puertos de los mapas abiertos.

Solución: abre UDP 7777 a 7779 (uno por mapa) en el firewall del servidor, y TCP 80 y 443 para Caddy. Nunca publiques el enlace de los mapas (UDP 7700) en internet.

#Los límites de Login cuentan a todos como un solo jugador

Detrás de un proxy, cada pedido parece venir de la dirección del proxy.

Solución: prende los ajustes Proxy con la dirección de tu proxy. El archivo Docker Compose ya confía en su propio Caddy. Consulta Configuración.

#Herramientas de GM

#Los comandos de GM dicen "Unknown command"

El nivel de tu cuenta está por debajo del del comando. Los comandos por encima de tu nivel responden como si no existieran.

Solución: nombra al primer admin en la base de datos (consulta Comandos de GM), y luego usa /role para los demás. Un nivel subido se aplica la próxima vez que el jugador entra a un mapa. Revisa también Game Settings > Gm Command Levels.

#"GM commands are paused: they can't be recorded right now."

Los comandos del equipo solo corren cuando se pueden registrar en la auditoría, y el mapa no puede llegar a Central en este momento.

Solución: espera y vuelve a intentar. Si sigue, revisa que Central esté corriendo y que el mapa esté enlazado a él.

#El panel de GM no se abre

F8 y /gm lo abren solo para el nivel 2 o más (si no, "Unknown command /gm. Try /help.").

Solución: sube el nivel de la cuenta.

#La tienda del juego

#El botón de la tienda no aparece

La tienda funciona solo en línea, con el módulo In-game shop prendido y el servicio Shop corriendo. Un jugador no tiene tienda.

Solución: revisa Modules, prende la tienda en la página Shop e inicia el servicio Shop. La ventana de la tienda dice cuando está cargando o no puede llegar al servicio.

#"This map has no Shop service." después de /currency gems

Al servidor de mapa no se le dieron la dirección y la clave de Shop.

Solución: inicia Shop con The game has an in-game shop prendido, para que Central les pase KITARPG_SHOP_URL y KITARPG_SHOP_KEY a los mapas que inicia. Un mapa que corre en el editor no los recibe.

#Pruebas

#Correr las pruebas del kit

KitARPG > Run Play Mode Tests corre las pruebas de modo Play del kit en un jugador, sobre un guardado descartable, así que tus personajes quedan intactos. La Console muestra cuántas pasaron y los resultados van a Logs/KitARPG-PlayMode-Tests.xml. Desde la línea de comandos:

Unity -projectPath . -batchmode -executeMethod Blunnyn.KitARPG.Editor.KitTests.RunPlayMode

En modo batch, Unity sale con código 1 cuando falla una prueba. El menú necesita el paquete Test Framework; sin él, el menú no está.
