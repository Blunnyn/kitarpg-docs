Primeros pasos

Requisitos

Qué necesitas en tu computadora para usar KitARPG, qué es opcional y para qué sirve cada pieza. Léela antes de instalar para que nada te detenga a mitad de camino.

#La versión corta

  • Para jugar la muestra en un jugador: Unity 6.6 (6000.6.0f1) o más nuevo. Nada más.
  • Para jugar la muestra como MMO en tu computadora: lo anterior más el SDK de .NET 10.
  • Para desplegar un MMO: lo anterior más el soporte de build Linux Dedicated Server en Unity y una máquina con Docker.

#Unity

Requisito Valor Notas
Versión de Unity 6000.6.0f1 (Unity 6.6) o más nuevo La versión mínima que soporta el kit. Las versiones anteriores no lo compilan
Pipeline de render Universal Render Pipeline 17.6 El Setup Wizard lo activa. Los materiales del kit son materiales de URP y se ven rosados sin él
Espacio de color Linear Lo pone el Setup Wizard
TextMesh Pro essentials Importados en el proyecto Los importa el Setup Wizard. Sin ellos, ninguna etiqueta de la UI del kit tiene fuente
Active Input Handling Input System, Input Manager o ambos El kit lee la entrada mediante su propia capa KitInput y funciona con cualquiera
Plataforma del editor macOS o Windows Las builds locales del servidor de mapa y los valores por defecto del lanzador son para Mac y Windows. La biblioteca SQLite del editor también viene para Linux

#Paquetes de Unity

El paquete de KitARPG declara los paquetes de Unity que necesita. Cuando lo importas, Unity los instala por ti, así que un proyecto vacío funciona.

Paquete Id Versión Se usa para
Universal RP com.unity.render-pipelines.universal 17.6.0 Render
AI Navigation com.unity.ai.navigation 2.0.14 NavMesh para jugadores y monstruos en el servidor
uGUI com.unity.ugui 2.6.0 Toda la interfaz, con TextMesh Pro
Input System com.unity.inputsystem 1.20.0 Teclado, mouse y táctil cuando el proyecto lo usa
Test Framework com.unity.test-framework 1.8.0 Las pruebas en Play del kit. Opcional: el kit compila igual si lo quitas

La red es Mirror con el transporte KCP (UDP). Mirror viene dentro del paquete, en Assets/Mirror; no lo instalas por separado.

#Paquetes y módulos de Unity opcionales

Elemento Se necesita para Cómo conseguirlo
Multiplayer Play Mode 3.0 (com.unity.multiplayer.playmode) Play with two players, que abre un segundo editor El botón ofrece instalarlo la primera vez
Mac Build Support (IL2CPP) Clientes de Mac y juegos de un jugador para Mac Unity Hub > Installs > Add modules
Windows Build Support (IL2CPP) Clientes de Windows y juegos de un jugador para Windows Unity Hub > Installs > Add modules
Linux Dedicated Server Build Support (IL2CPP) Servidores de mapa Linux para Docker (KitARPG > Starter > Build Linux Server) Unity Hub > Installs > Add modules
com.unity.toolchain.macos-arm64-linux Compilar el servidor de mapa Linux desde una Mac Package Manager > Add package by name
Nota

Los clientes que se entregan a los jugadores siempre se compilan con IL2CPP. La revisión de build detiene un cliente MMO compilado con Mono, porque su código viajaría como DLLs legibles. Las builds IL2CPP para Windows se hacen en Windows, y las de Mac en una Mac. Consulta Builds.

#Para MMO: el SDK de .NET 10

Login, Central, el Shop y el lanzador son programas de .NET 10. El editor los compila y los corre por ti, pero necesita el SDK.

Requisito Valor Notas
SDK de .NET 10.x Gratis, desde https://dotnet.microsoft.com/download/dotnet/10.0. El runtime solo no alcanza: el editor compila los servicios desde el código fuente

Dónde busca el editor dotnet, ya que Unity no siempre recibe el PATH de tu shell:

  • Cada carpeta del PATH.
  • Windows: C:\Program Files\dotnet\dotnet.exe.
  • Mac y Linux: /usr/local/share/dotnet/dotnet, /usr/local/bin/dotnet, /opt/homebrew/bin/dotnet, /usr/share/dotnet/dotnet y ~/.dotnet/dotnet.

Después de instalar, presiona Check again bajo la línea del .NET 10 SDK en Play & Servers. Play & Servers muestra las versiones que encontró ("Installed: ...").

#Opcional: Docker

Elemento Se necesita para
Docker Desktop (Mac, Windows) o Docker Engine (Linux) Correr PostgreSQL en tu computadora con un clic (Set up PostgreSQL... > Docker on this computer), y desplegar con Docker Compose

No necesitas Docker para hacer tu juego ni para jugar el MMO en local: SQLite funciona sin instalar nada.

#Opcional: PostgreSQL

SQLite alcanza para desarrollar y para servidores pequeños. Para producción, usa PostgreSQL. Sirve cualquier servidor PostgreSQL: uno en tu computadora, en un VPS, o uno administrado como RDS, Supabase o Neon. Con Docker, el kit corre PostgreSQL 17 por ti. Consulta Base de datos.

#Puertos que se usan en tu computadora

Cuando corres el MMO en local, estos puertos deben estar libres. Play & Servers avisa cuando algo más los ocupa.

Puerto Protocolo Lo usa
5100 TCP (HTTP) Login
5200 TCP (HTTP) Central
5300 TCP (HTTP) Shop (solo cuando corre)
7700 UDP El enlace de Central con los mapas, al que se conectan los servidores de mapa
7777 UDP Servidor de mapa de town
7778 UDP Servidor de mapa de forest
7779 UDP Servidor de mapa de crypt
5432 y siguientes TCP PostgreSQL en Docker, en el primer puerto libre desde el 5432

#Hardware

El kit no tiene necesidades especiales de hardware más allá de lo que pide Unity 6.6. Ten en cuenta:

  • La primera build del servidor de mapa tarda unos minutos; las siguientes son más rápidas.
  • Play with two players corre un segundo editor de Unity, que usa más o menos tanta memoria como el primero. La primera vez que se abre, importa el proyecto.
  • En MMO cada mapa en ejecución es su propio proceso. La muestra levanta town con los servicios, y forest y crypt cuando un jugador entra a ellos por primera vez.

#Para los jugadores de tu juego

Build Los jugadores necesitan
Un jugador Nada más. El guardado es un archivo SQLite en la carpeta de datos del jugador
Cliente MMO Una conexión de red a tus direcciones de Login y Central (HTTPS) y a los puertos UDP de los servidores de mapa
