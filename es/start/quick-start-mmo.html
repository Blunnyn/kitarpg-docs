Primeros pasos

Inicio rápido: MMO

Corre la muestra como MMO en tu propia computadora: compila los servicios y el servidor de mapa, levántalos, crea una cuenta, juega y mira cómo se encuentran dos jugadores. Todo se maneja desde la página Play & Servers de la ventana KitARPG.

#Lo que vas a correr

Pieza Qué hace Puerto en tu computadora
Login Cuentas, inicio de sesión, lista y creación de personajes 5100 (HTTP)
Central Sesiones, tickets de un solo uso para entrar a los mapas, chat, amigos, grupos, gremios, correo, mercado; levanta los servidores de mapa 5200 (HTTP), 7700 (UDP, enlace con los mapas)
Servidores de mapa Un servidor de Unity por mapa, que corre el juego 7777 town, 7778 forest, 7779 crypt (UDP)
Shop (opcional) Moneda premium, ofertas, compras, pagos 5300 (HTTP)
Base de datos Archivo SQLite o PostgreSQL

El editor corre todo esto mediante el lanzador, sin ventana. Central levanta cada servidor de mapa desde tu build del servidor de mapa cuando el primer jugador lo necesita; town arranca con los servicios.

#Antes de empezar

  • Termina el Setup Wizard.
  • Instala el SDK de .NET 10 desde https://dotnet.microsoft.com/download/dotnet/10.0. Consulta Requisitos.
  • Asegúrate de que los puertos 5100, 5200, 7700 y del 7777 al 7779 estén libres.

#Paso a paso

#1. Abre Play & Servers y elige MMO

  1. Abre la ventana KitARPG: KitARPG > Open KitARPG o Ctrl/Cmd+Shift+K.
  2. Ve a Play & Servers.
  3. Haz clic en la tarjeta MMO de arriba.

Debajo de las tarjetas aparecen cuatro pasos numerados. Se desbloquean en orden: los pasos terminados se pliegan con una marca de verificación, el paso actual se abre y los pasos bloqueados todavía no se pueden abrir. El encabezado de cada paso resume en qué estado está.

#2. Paso 1: Revisa el proyecto

El encabezado del paso muestra cuántas revisiones están listas ("3 of 5 ready."). Recorre las filas de arriba abajo:

Fila Está bien cuando Qué presionar
Scenes in Build Settings Title es la primera escena y Server está en la lista Use starter scenes
.NET 10 SDK "Installed: 10.x..." Get .NET abre la página de descarga. Después de instalar, presiona Check again
Services source Muestra la carpeta con KitARPG.Services.slnx, normalmente Assets/Blunnyn/KitARPG/Services~ Browse para elegir otra carpeta
Services built "Login, Central and the launcher are compiled." Build services. Corre dotnet build sobre los servicios, una vez. Después dice Rebuild
Map server build "Ready. Rebuild after changing scenes or server code." Build. En una Mac corre KitARPG > Starter > Build Mac Server, en Windows Build Windows Server. La primera build tarda unos minutos

Pueden aparecer dos filas más:

  • N kit updates, cuando el kit tiene actualizaciones que le faltan a tu juego. Presiona Review y aplícalas antes de compilar el servidor de mapa, para que los dos las tengan.
  • In-game shop, cuando el servicio Shop está disponible. Dice si la tienda está apagada, corriendo, o prendida pero sin correr, con Open Shop. La tienda es opcional; consulta Página Shop.

La build del servidor de mapa va a Builds/Starter/MacServer/KitARPGServer.app o Builds/Starter/WindowsServer/KitARPGServer.exe, en una carpeta Builds junto a la carpeta de tu proyecto de Unity. Cada build anota las escenas que lleva, así Play & Servers sabe cuándo le falta la escena de un mapa.

Atención

Vuelve a compilar el servidor de mapa después de cambiar una escena, agregar un mapa o cambiar código del servidor. Un servidor de mapa más viejo que tu código puede rechazar clientes con "The game and the server are different versions", y uno al que le falta la escena de un mapa manda de vuelta al inicio de sesión a los jugadores que viajan ahí.

Si Build services falla, el paso muestra las primeras líneas del error. Si no hay ninguna: "dotnet build failed. Run it in a terminal to see why." Abre una terminal en la carpeta de los servicios y corre dotnet build para ver la salida completa.

#3. Paso 2: Elige la base de datos

Opción Cuándo usarla
SQLite: a local file (por defecto) Desarrollo y servidores pequeños. No hay que instalar nada
PostgreSQL: for production Producción, o para desarrollar contra la misma base de datos que despliegas

Deja SQLite para este inicio rápido. El archivo es UserSettings/KitARPG/data/kitarpg.db.

PostgreSQL necesita una conexión: Set up PostgreSQL... se conecta a un servidor que tú corres, puede crear la base de datos y el usuario por ti, o corre PostgreSQL 17 en Docker. También puedes escribir la cadena de conexión a mano. Consulta Base de datos.

La línea Keys explica que la clave de firma y la clave de los mapas se crean para esta computadora y se guardan en UserSettings/KitARPG. New keys crea una nueva clave de firma y una nueva clave de mapas. Está desactivado mientras corren los servicios. Los tokens firmados con la clave anterior dejan de aceptarse, así que los clientes que tenían la sesión iniciada tienen que volver a iniciarla.

No puedes cambiar la base de datos mientras corren los servicios: "Stop the services to change the database."

#4. Paso 3: Levanta los servicios

  1. Presiona Start services.

  2. Aparecen tres luces:

    Luz Detalle
    Login Cuentas y personajes, puerto 5100
    Central Sesiones, chat, gremios y mapas, puerto 5200
    Maps "Started by Central when someone enters", y luego los mapas que se registraron

    Cada luz dice off, starting o up.

  3. Espera a que Login y Central estén en up. El encabezado del paso dice entonces "Running. Maps: ..." y se pliega.

Mientras corren los servicios, el paso ofrece Restart y Stop. Antes de que arranquen, corre la exportación de los datos del juego: Play & Servers escribe el gamedata.json que Login lee para crear personajes.

Map in the editor elige un mapa para correrlo dentro de este editor en lugar de desde la build, para que puedas depurarlo. Por ahora déjalo en "None, every map runs from the map server build". Solo se puede cambiar mientras los servicios están detenidos.

Avisos que puede mostrar este paso:

Mensaje Significado Solución
"Services from an earlier editor session are still running (process ...)" Un lanzador que arrancó antes de que se reiniciara el editor todavía ocupa los puertos Stop the old services
"Something else is using port ..." Servicios levantados desde una terminal o desde otra sesión ocupan los puertos Detenlos y luego levanta estos
"The services or the map server were rebuilt after they started, so they still run the old code. Restart them." Compilaste mientras corrían Restart

#5. Paso 4: Juega

  1. Presiona Play client. El editor abre Title y se une a los servicios en ejecución como cliente en http://127.0.0.1:5100 (Login) y http://127.0.0.1:5200 (Central).
  2. Aparece la pantalla de inicio de sesión con Username, Password, Remember me, Sign in automatically, Sign in y Create account.
  3. Escribe un nombre de usuario (de 3 a 16 letras, dígitos o _) y una contraseña (8 caracteres o más), y presiona Create account. El estado dice "Creating account...", y luego "Account created, signing in...".
  4. Se abre la lista de personajes. Presiona New, completa Name, Look, Class y Hair, y presiona Create. Consulta Inicio rápido: un jugador para las reglas de cada campo.
  5. Selecciona el personaje y presiona Play. Central le da al cliente un ticket para town, y apareces en la ciudad.

Remember me guarda un token de un solo uso en esta computadora para que no tengas que escribir la contraseña la próxima vez; la contraseña en sí nunca se guarda. Sign in automatically (solo con Remember me) inicia sesión al arrancar. Para iniciar sesión como otra persona, presiona Sign out en la lista de personajes.

#Dos jugadores a la vez

Play with two en el paso 4 (también en Overview y en KitARPG > Play With Two Players) muestra a dos jugadores encontrándose:

  1. Levanta los servicios si están detenidos.
  2. Abre un segundo editor con el Multiplayer Play Mode de Unity. Si falta el paquete, ofrece instalarlo ("Install").
  3. Cuando Login responde y el segundo editor está abierto, presiona Play en los dos. Cada uno inicia sesión solo con una cuenta y un personaje de prueba creados para esta computadora: kitplayer1 jugando con Aria y kitplayer2 jugando con Bram. Se guardan en UserSettings/KitARPG/quickplay.json.

La primera vez, el segundo editor importa el proyecto, lo que tarda un rato. Si Player 2 no se puede levantar automáticamente, se abre la ventana Multiplayer Play Mode: activa ahí Player 2 y vuelve a presionar el botón.

Para más de dos jugadores, Built client en el paso 4 tiene Build (un cliente MMO para tu plataforma) y Open: abre todos los clientes compilados que quieras. Cada uno se abre conectado a los servicios locales.

#Correr un mapa en el editor

Para depurar código del servidor de un mapa:

  1. Detén los servicios.
  2. En el paso 3, pon en Map in the editor el mapa, por ejemplo forest: runs in this editor, to debug it.
  3. Levanta los servicios. Ahora Central espera a que ese mapa se registre en lugar de levantarlo.
  4. En el paso 4, presiona Play map server: forest. El editor juega la escena Server como ese servidor de mapa.
  5. Únete con un cliente compilado o con Play with two: un jugador que entra caminando al bosque llega a tu editor.

#Hacerte administrador

Las cuentas nuevas empiezan en el nivel de GM 1 (Player). Para usar comandos de GM online, pon al primer administrador en la base de datos. Con la base de datos SQLite por defecto, detén los servicios y corre:

sqlite3 UserSettings/KitARPG/data/kitarpg.db "UPDATE accounts SET \"Role\" = 4 WHERE \"Username\" = 'yourname';"

Con PostgreSQL:

UPDATE accounts SET "Role" = 4 WHERE "Username" = 'yourname';

Después de eso, los administradores cambian niveles dentro del juego con /role player level. Consulta Comandos de GM.

#El registro

La tarjeta Log al final de Play & Servers muestra las últimas líneas de la salida de los servicios. Open log file abre UserSettings/KitARPG/services.log. Cada servidor de mapa escribe su propio registro en UserSettings/KitARPG/data/logs/map-<id>.log.

#Detener

Presiona Stop en el paso 3. El lanzador detiene Login, Central y cada servidor de mapa que levantó. Cerrar el editor no siempre los detiene: si la próxima vez siguen corriendo, Play & Servers ofrece Stop the old services.

#Lo que sale mal más a menudo

Síntoma Solución
"Can't reach the server." en la pantalla de inicio de sesión Los servicios no están corriendo, o Login todavía no está en up. Revisa el paso 3
"That map is not running right now. Try again in a moment." Central no pudo levantar el mapa. La build del servidor de mapa falta o está rota; revisa el registro del mapa en UserSettings/KitARPG/data/logs
"The game and the server are different versions. Update the game." El servidor de mapa se compiló con código más viejo. Vuelve a compilarlo y presiona Restart
"No map reached Central" en Overview La build del servidor de mapa falta o está desactualizada. Compílala y reinicia
Viajar a un mapa te manda de vuelta al inicio de sesión A la build del servidor de mapa le falta la escena de ese mapa. Vuelve a compilarla
"Your character is still being saved. Try again in a moment." Volviste a iniciar sesión mientras la sesión anterior se estaba guardando. Espera unos segundos
