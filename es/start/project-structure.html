Primeros pasos

Estructura del proyecto

Dónde vive cada parte de KitARPG en tu proyecto y en el disco, qué carpetas puedes editar, cuáles pertenecen al kit y cuáles nunca salen de tu computadora. Léela antes de empezar a agregar tu propio contenido, para que las actualizaciones nunca sobrescriban tu trabajo.

#El panorama general

YourWorkspace/
├── YourUnityProject/
│   ├── Assets/
│   │   ├── Blunnyn/
│   │   │   ├── KitARPG/          The kit (read-only for you)
│   │   │   └── Art/              The kit's voxel art
│   │   ├── Mirror/               Networking library
│   │   ├── ScriptTemplates/      Mirror's script templates
│   │   ├── Settings/             URP assets and KitARPGSettings
│   │   └── Game/                 Your game (you make this folder)
│   └── UserSettings/
│       └── KitARPG/              This computer only: keys, local database, logs
└── Builds/
    ├── Starter/                  Builds made from the KitARPG menus
    └── ...

La carpeta Builds está junto a la carpeta de tu proyecto de Unity, no dentro.

#El kit: Assets/Blunnyn/KitARPG/

Carpeta Qué contiene
Runtime/Shared/ C# puro sin Unity, compartido con los servicios .NET: reglas de cuentas y personajes, reglas del inventario, mensajes a Central, códigos de error. Ensamblado KitARPG.Shared
Runtime/Data/ Los assets de datos y sus reglas: clases, atributos, ítems, skills, estados, monstruos, misiones, condiciones, acciones, mapas, GameDatabase, GameInstance. Ensamblado KitARPG.Data
Runtime/Net/ Todo lo que va en red con Mirror: jugadores, monstruos, NPCs, combate, chat, gremios, el registro del juego, el network manager. Ensamblado KitARPG.Net
Runtime/Server/ Solo del servidor de mapa: el enlace con Central, comandos de GM, instancias, recompensas, el cliente de Shop. Ensamblado KitARPG.Server, que queda fuera de las builds de cliente MMO
Runtime/Local/ El guardado de un jugador en SQLite. Ensamblado KitARPG.Local, solo en builds de un jugador
Runtime/Client/ Interfaz, ventanas, HUD, pantalla de título, sesión, entrada (KitInput), controles táctiles, opciones. Ensamblado KitARPG.Client
Runtime/Resources/KitARPG/ Recursos que el kit carga por nombre, como el Animator controller del personaje KitCharacter.controller
Modes/TopDown/ El modo top-down: Runtime (cámara y entrada) y Server (movimiento y acciones en el servidor)
Modes/ThirdPerson/ Los modos tercera persona y cámara libre, divididos de la misma forma
Editor/ La ventana KitARPG y sus páginas, el Setup Wizard, Game Database, Project Check, herramientas de build, el generador de la muestra Starter y las actualizaciones del kit. Ensamblado KitARPG.Editor
DevKit/Example/Bounties/ El ejemplo del tablón de recompensas, hecho como lo haría un juego, con sus propios ensamblados
Samples/Starter/ La muestra Starter (ver más abajo)
Tests/PlayMode/ Las pruebas en Play del kit. Ensamblado KitARPG.Tests.PlayMode, nunca en builds
Plugins/LiteNetLib/ La biblioteca que usan los servidores de mapa para hablar con Central
Plugins/SQLite/ La biblioteca nativa de SQLite para macOS, Windows y Linux, que usa el guardado de un jugador
Documentation/ Esta documentación como sitio web en Web/ (se abre con KitARPG > Documentation), GettingStarted.md, DevKit.md, CHANGELOG.md, la referencia de la API en API/ y el manual en PDF
Services.zip Los servicios .NET como código fuente, tal como vienen en el paquete
Services~/ Services.zip desempaquetado por el editor. Unity no lo importa

#Ensamblados

Ensamblado Va en
KitARPG.Shared, KitARPG.Data, KitARPG.Net, KitARPG.Client Todas las builds
KitARPG.Modes.TopDown, KitARPG.Modes.ThirdPerson Todas las builds
KitARPG.Server, KitARPG.Modes.TopDown.Server, KitARPG.Modes.ThirdPerson.Server Solo servidores de mapa y juegos de un jugador
KitARPG.Local Solo juegos de un jugador
KitARPG.Editor Solo el editor
KitARPG.Tests.PlayMode Solo el editor, con las pruebas activadas

KitARPG > Check Build Separation muestra qué código va en cada tipo de build. Consulta Ensamblados.

#La muestra Starter: Samples/Starter/

Carpeta o archivo Qué contiene
Scenes/ Title.unity, Server.unity, Town.unity, Forest.unity, Crypt.unity, más una carpeta por escena de mapa con sus datos de iluminación y de NavMesh
Prefabs/ KitNetwork.prefab (el network manager con el GameInstance que guarda Game Settings), GameHud.prefab, TouchControls.prefab, los prefabs de jugador PlayerMale, PlayerFemale y PlayerPanda, los prefabs de monstruos y UI/ con las piezas de UI reutilizables
Data/ Todos los assets de datos del juego: StarterDatabase.asset, Attributes/, Classes/, Currencies/, Elements/, Items/, Skills/, Statuses/, WeaponTypes/, Monsters/, Quests/, Shops/, Maps/, Guilds/, los ajustes de cámara, la tabla de experiencia, los emblemas de gremio, el arte de la tienda y la máscara de torso
Effects/ Efectos de partículas para golpes, lanzamientos, proyectiles, áreas y estados
Materials/ Materiales de los mapas de la muestra
StarterAppearance.asset El catálogo de mallas de cuerpos, pelo y equipo para los personajes modulares
Escena Función
Title Inicio de sesión, lista de personajes y creación. Debe ser la primera en Build Settings
Server La escena vacía en la que arranca un servidor de mapa antes de cargar su mapa. Necesaria en MMO
Town El mapa inicial: tiendas, NPCs que dan misiones, banquero, servicios del gremio
Forest Monstruos, un jefe, apariciones de día y de noche
Crypt La Sunken Crypt, una mazmorra instanciada
Atención

Start over en Overview y KitARPG > Starter > Build Scenes and Prefabs vuelven a generar la muestra desde el código del kit y pierden todos los cambios hechos dentro de Samples/Starter/. Importar un kit más nuevo también puede reemplazar archivos ahí. Copia primero a tu propia carpeta lo que quieras cambiar. Consulta Actualizar el kit.

#Ajustes del proyecto que usa el kit

Ruta Qué es
Assets/Settings/Resources/KitARPGSettings.asset Cómo corre el juego: mode (MMO o un jugador), loginUrl y centralUrl para las builds, saveFile para un jugador. Se crea si falta
Assets/Settings/KitARPG_URP.asset El asset de URP que crea el Setup Wizard cuando el proyecto no tiene ninguno

Campos de KitARPGSettings:

Campo Qué hace Por defecto
Mode (mode) Online (MMO) o SinglePlayer. Lo ponen Play & Servers y el Setup Wizard; las builds lo ponen según el tipo de build Online
Login Url (loginUrl) La dirección de Login que usan los clientes MMO http://127.0.0.1:5100
Central Url (centralUrl) La dirección de Central que usan los clientes MMO http://127.0.0.1:5200
Save File (saveFile) El guardado de un jugador, en la carpeta de datos persistentes del jugador savegame.db
Importante

Antes de compilar un cliente MMO para jugadores, pon en Login Url y Central Url las direcciones https:// de tus servidores. Un cliente de release rechaza HTTP sin cifrar salvo hacia esta computadora, y la build se detiene si no son HTTPS.

#Solo de esta computadora: UserSettings/KitARPG/

Unity nunca pone UserSettings en las builds, y el control de versiones normalmente lo ignora. Todo lo que hay aquí es específico de tu computadora.

Archivo o carpeta Qué es
setup-done El Setup Wizard ya corrió
seen-version La última versión del kit que abrió este proyecto, para What's New
launcher.json Los ajustes del lanzador que usa Play & Servers: puertos, base de datos, mapas, claves
launcher.pid El lanzador en ejecución, para que el editor lo encuentre después de reiniciar
services.log La salida de los servicios levantados desde el editor
data/kitarpg.db La base de datos SQLite local del MMO: cuentas, personajes, ítems, gremios, correo
data/logs/map-<id>.log El registro de cada servidor de mapa
quickplay.json Las cuentas de prueba para Play con dos jugadores
shop-conf.json El catálogo local de la tienda
shop.log, shop.pid El servicio Shop levantado desde el editor
modules/ Módulos para Login (login/) y Central (central/) que carga el lanzador local
Importante

launcher.json guarda la clave de firma y la clave de los mapas. No lo subas al repositorio ni lo compartas.

#Dónde va tu juego

Deja todo lo que hagas fuera de Assets/Blunnyn:

Assets/Game/
├── Game.asmdef           Create > KitARPG > Scripts > Game Assembly
├── Data/                 Your items, skills, monsters, quests, maps
├── Prefabs/              Your player models, monsters, HUD copy
├── Scenes/               Your maps
├── Scripts/              Your code
└── Editor/               Game Editor Assembly and your tools

Pasos:

  1. Crea una carpeta como Assets/Game.
  2. Para escribir código, haz clic derecho sobre ella y elige Create > KitARPG > Scripts > Game Assembly. Los scripts que pongas ahí ven el kit.
  3. Crea datos nuevos con los botones New de la Game Database y luego mueve los assets a tu carpeta, o duplica assets de la muestra y mueve las copias.
  4. Para tus propios mapas, duplica Forest.unity en tu carpeta y agrega una entrada de mapa. Consulta Mapas.

Una vez creados, los ids no dependen de los nombres de archivo ni de las carpetas, así que mover assets es seguro.
