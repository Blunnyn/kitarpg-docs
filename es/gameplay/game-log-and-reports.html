Game log and reports

Esta página aún no está traducida. Se muestra en inglés.

Three tools help you run a game and keep it fair: the game log, which records what happens to accounts, characters, items and gold; player reports, which bring a problem to the moderators with the chat around it; and the chat filter, which masks or blocks words you choose. This page covers each one, every setting, and how they work in single player and MMO.

#The game log

The game log is one table, game_logs, with a line per event: when, kind, map, account, character, the other party, item, amount, gold and a detail. It has no foreign keys, so lines survive deleted characters.

#What it records

Kind When
account.created, account.login, account.login_failed, account.resumed Accounts created, logins and failed logins with the IP, "Remember me" logins
character.created, character.deleted Characters made and deleted
session.enter, session.leave Entering and leaving the world
item.trade Trades, with what each side gave
item.shop_buy, item.shop_sell Buying and selling at NPC shops
item.loot Loot of Log Loot From rarity or better
item.destroy Items destroyed
item.forge Forge upgrades, sockets and salvage
bank.deposit, bank.withdraw The account bank
guild.bank, guild.created, guild.collector The guild bank, new guilds, tax collectors
mail.sent, mail.taken Letters sent and items or gold taken from them
market.listed, market.sold, market.cancelled, market.expired The market
shop.premium_buy, shop.premium_gift, shop.premium_grant, shop.premium_topup, shop.premium_refund The cash shop and premium currency
combat.death, combat.pvp_kill Deaths and PvP kills
character.level, character.experience_lost Levels and experience lost on death
quest.done Quests completed
chat.line Every chat line, only with Log Chat on
gm.command, gm.ban GM commands with their answer, bans
report.sent, report.closed Player reports

The kind is free text, so your game adds its own (see In code).

#Settings

In KitARPG > Game Settings, section Logs:

Field What it does Default
Log Loot From (logLootFrom) Loot of this rarity or better goes to the game log Rare
Log Chat (logChat) Every chat line goes to the game log too. Reports always carry the lines around them Off

On Login and Central (appsettings.json or environment variables):

Setting What it does Default
Logs:Days Lines older than this are deleted, once an hour. 0 keeps them forever 180

#How lines get there

  • The map server collects its lines and sends them to Central every 2 seconds. If Central is down, up to 5.000 lines wait. Central stamps each line with the map that sent it.
  • Login and Central write their own lines directly.
  • Writing happens in batches from a queue, away from each request, so logging never slows a login or a trade.

#Reading the log

  • In game, a moderator types /logs player [kind] for that player's last 15 lines, optionally of one kind. item covers every item.* kind. The GM panel's Moderation tab and each player's logs button in Players do the same.
  • Outside the game, query the game_logs table with any SQL tool. See Database.
SELECT "At", "Kind", "Character", "Other", "ItemId", "Amount", "Gold", "Detail"
FROM game_logs WHERE "Kind" LIKE 'item.%' ORDER BY "At" DESC LIMIT 50;

The columns are Id, At (UTC), Kind, MapId, AccountId, CharacterId, Character, OtherId, Other, ItemId, Amount, Gold and Detail. On PostgreSQL the names need the double quotes, as above.

#Player reports

#For the player

  • Right click a player (or their name in chat) and pick Report. A dialog asks "Report name to the moderators?" with a text box for what happened (up to 200 characters).
  • Or type /report name reason.

A player waits 60 seconds between reports, and Central accepts at most 10 per day from one account.

#What a report carries

The map adds the last 30 chat lines the reporter saw, so moderators read the context without logging all chat. The report goes to the reports table and to the game log as report.sent.

#For moderators

  • Online moderators get a notice when a report arrives.
  • /reports lists the open reports.
  • /closereport id marks one as handled (report.closed in the log).
  • /logs player [kind] shows what the player did.

The GM panel's Moderation tab has the same. See GM tools.

#Chat filter

The chat filter hides or blocks words you list. It runs on the server.

#Settings

In KitARPG > Game Settings, section Chat filter:

Field What it does Default
Blocked Words (blockedWords) Words nobody may say, one per entry. End one with * to also catch what starts with it Empty
Blocked Words File (blockedWordsFile) A text asset with more words, one per line, for long lists. Lines starting with # are comments Empty
Chat Filter Mode (chatFilterMode) Mask hides blocked words with asterisks; Block drops the whole line and tells the player Mask

#How it matches

  • Whole words only, so "class" is safe from "ass".
  • An entry ending in * also catches longer words: dumb* catches "dumbest".
  • Digits and symbols standing in for letters are read as the letters, so d4rn and @ss are caught.
  • Case doesn't matter.

#Where it applies

  • Chat lines on every channel.
  • Mail subjects and bodies.
  • The guild notice.
  • Guild names: a name with a blocked word is refused.

#Step by step: add a word list

  1. Create a text file in your project, for example Assets/Game/BlockedWords.txt, with one word per line and # lines for notes.
  2. In Game Settings > Chat filter, drag it into Blocked Words File.
  3. Pick Chat Filter Mode.
  4. Rebuild the map server: the filter runs there.

#Single player and MMO

Single player MMO
Game log In the save file's game_logs table, kept 90 days Central's database, kept Logs:Days
Reports, /reports, /logs Not available Yes
Chat filter Yes Yes, on the map server

#In code

  • GameLog.Write(kind, player, other, itemId, amount, gold, detail) adds a line from server code. Use your own kinds, like bounty.claimed.
  • GameLog.Written fires for every line, to send them somewhere else as well.
  • ChatFilter.Mask, ChatFilter.Blocks and ChatFilter.Apply check any text you let players write. SocialHub.Filter runs your own chat rules after the filter.

See Events and Security rules.

#Common mistakes

  • The filter misses a word with a suffix. Add * to the entry.
  • The filter catches an innocent word. Remove a * entry that is too short.
  • Loot never shows in the log. Log Loot From is higher than the items' rarity.
  • The table grows too big. Lower Logs:Days, or leave Log Chat off.
