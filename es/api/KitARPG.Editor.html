#BuildSeparation (class)

Keeps each build to the code it should carry. Which assemblies go in comes from their define constraints and the build's scripting defines: KITARPG_SERVER: server code (KitARPG.Server, every *.Server assembly), for map servers and single player. KITARPG_SINGLEPLAYER: the local save (KitARPG.Local), for single player only. KITARPG_DEV or a development build: test tools (auto login, smoke test, Sandbox). Every build is checked before it starts, from any menu or build profile, and stops when an assembly is where it shouldn't be. The check can't be turned off.

Member Description
public static readonly string[] ServerAssemblies = Server-only assemblies of the kit. Any assembly whose name ends in ".Server" counts too.
public static readonly string[] DevAssemblies = Test tools that only development builds may carry.
public static void Expect(BuildKind kind, string[] extraDefines) Called by the kit's own build menus, which know what they build and the extra defines they pass. Builds started elsewhere are worked out from the game mode and the defines.
public static HashSet<string> Defines(BuildTarget target, bool serverSubtarget, bool development, IEnumerable<string> extra = null) The defines a player build compiles with: the project's, the active build profile's and the extra ones.
public static List<string> Check(BuildTarget target, BuildKind kind, HashSet<string> defines, out List<string> warnings) What's wrong with a build of this kind; empty when it may go ahead.
public static List<string> Included(BuildTarget target, HashSet<string> defines) The project's assemblies a player build for this target would compile, judged by their platforms and define constraints.
public static bool Holds(string constraint, HashSet<string> defines) One define constraint, like "UNITY_SERVER || !UNITY_EDITOR".

#KitUpdate (class)

Something a newer kit adds to a game made with an older one: a currency, a component on the player, a window in the HUD. An update only adds what is missing and never rebuilds what the game already has, so changes made by hand stay. Subclass it to ship your own.

Member Description
public abstract string Title One line, like "Shop window in the HUD".
public abstract string Changes What Apply will change, named precisely, shown before it runs.
public abstract bool Needed() The project lacks it. Called every few seconds, so keep it cheap.
public abstract string Apply() Makes the change and says what it did. Throw to report that it couldn't.
public virtual int Order Lower runs first, for updates that rely on another.
public virtual string Addon Id of the add-on that ships it. While that add-on is off the update isn't offered.

#ShopRunner (class)

Runs the Shop service on this computer through the launcher's shop-only mode, apart from Login and Central, and talks to any Shop service's admin API.

Member Description
public static int RunningPid The shop this project started, from this session or an earlier one, or 0.
public static void SeedCatalog(ServiceRunner.LauncherConfig config) A first catalog for this computer: the sample that comes with the service.
public static void WriteFile(string path, ShopConfig conf) Writes through a temporary file, so a running shop never reads half a catalog.
public static async Task<ShopPublishResult> Publish(string url, string adminKey, ShopConfig conf) Replaces the service's whole catalog. Nothing changes there unless every offer passes.

#StarterBuilder (class)

Generates the starter sample: player prefabs, the network prefab, the title screen and two maps joined by portals. Everything it makes is a normal asset you can edit afterwards; running it again overwrites them.

Member Description
public static string MapServerExecutable Executable of the local map server build for this editor's platform.
public static string MapServerProblem() Why the local map server build can't be trusted, or null when it's fine: missing, missing a map's scene, or older than the game code or scenes it was built from.
public static void BuildMapServer() Builds the map server for this editor's platform.
public static List<string> MapServerMissingScenes() Map scenes the local map server build doesn't have, or null when it can't tell (no build, or an older one).
public static string ClientPath The client build for this editor's platform, to run next to the editor.
public static void BuildMacServer() Local map server for the launcher: a normal player build with the server code compiled in, run with -batchmode -nographics. Needs no Dedicated Server module.
public static void BuildMacTestClient() Client with the test tools (smoke test, auto login) for local checks, never for players: Mono for a fast build, in its own folder so it can't be mistaken for the release client.
public static void BuildMacSinglePlayer() Single player game: the client hosts its own maps, so the server code goes in.

#StarterData (class)

Game data of the starter sample: four attributes, three classes with their skills, the voxel weapons and armor sets, potions and the two maps. Running it again updates the assets in place, keeping their ids.

Member Description
public static Sprite Icon(string name) One of the pixel icons made by Art/Tools/make_ui_icons.py, imported as a crisp sprite.
public static GameObject SharedMaterialModel(string path) Loads a voxel model, pointing its material at the shared palette one first.
public static void Animate(CharacterAnimations animations, Content c) The sample animations of a humanoid player: moving, reactions, each weapon type and the skills that need their own.

#StarterEffects (class)

The sample's combat visuals: particle effects made from code (hit spark, cast aura, launch flash, orb, arrow, area burst, heal sparkle) that tint to the element, and access to the animation pack the sample characters use.

Member Description
public static AnimationClip Clip(string name) A clip from the sample's animation pack, like "Melee Right Attack 01".

#StarterGuilds (class)

The kit's guild emblem pieces, drawn by Art/Tools/make_guild_emblems.py, as a Guild Emblems asset.

Member Description
public static GuildEmblemData MakeEmblems(string path) Loads the asset at path, or makes it, and fills any empty list with the kit's pieces.

#StarterMasks (class)

Avatar masks the sample characters use.

Member Description
public static AvatarMask UpperBody(string path = UpperBodyPath) A humanoid mask with the spine, head and arms, so actions leave the legs walking. Loaded when it exists.

#StarterShopArt (class)

The sample's shop pictures, drawn by Art/Tools/make_shop_art.py, gathered in a ShopArt asset.

#StatRollDrawer (class)

A random bonus on one line: what it raises, then min and max. Only the fields that apply are shown.

#State (enum)

#TmpEssentials (class)

TextMesh Pro's essential resources (its default font and settings), which the kit's UI and sample use.

#TouchLayoutUpdate (class)

Puts the touch hotbar in its current order, skills 1 to 4 around Attack and the potion on 5, without the Dodge button.

#TouchUi (class)

Makes the sample on-screen controls: a stick, Attack, Activate (only near loot or an NPC), four skills and a consumable around Attack, a cancel button above them, the Chat button and the picker that fills the skill buttons. The pieces are prefabs of their own, so a change to one skill button reaches all five. An existing prefab is kept, edits and all.

Member Description
public static GameObject Build(string folder, bool replace = false) The prefab at folder/TouchControls.prefab, made if missing or when replace.
public static readonly (string name, int slot, Vector2 offset)[] Places = Where each hotbar button sits from Attack's center: skills 1 to 4 in an arc from low on the left up to the top, and slot 5, the potion, at the top left.

#UpperBodyMaskUpdate (class)

Gives humanoid player models an upper body mask, so they attack and cast while their legs keep walking.

#ValidationIssue (class)

Something the validator found, with what it is about and maybe a fix.

#ValidatorWindow (class)

The validator's findings, with a way to jump to each one and fix the simple ones.

Member Description
public void Queue() Runs the check on the next editor update, so opening the window stays quick.
public void Run(bool scenes = true) Checks the project. Scenes are opened to check them only when asked.
