DevKit

Condiciones y acciones en código

Cómo escribir tus propias condiciones (reglas que un jugador debe cumplir) y acciones (cosas que se le hacen a un jugador), qué pueden leer y cambiar, dónde las ejecuta el kit y cómo usarlas en datos propios.

#Qué son

  • Una condición responde sí o no sobre un jugador: "nivel 10 o más", "terminó la misión Old Mill", "es de noche". Las misiones, las opciones de NPC, los saludos de NPC y los disparadores del mundo tienen listas de condiciones.
  • Una acción cambia algo de un jugador: pagar oro, quitar un ítem, poner una marca de historia, empezar una misión. Las líneas de diálogo, las misiones (al aceptar y al completar) y los disparadores del mundo tienen listas de acciones.

El lado para diseñadores está en Condiciones y acciones. Esta página trata de escribir tipos nuevos.

Las dos son clases [Serializable] que se guardan con [SerializeReference, PickType]. Tu clase aparece en el menú + de cada lista en cuanto compila.

Dónde van los archivos: en el ensamblado Game. Las condiciones también corren en el cliente, así que deben estar en todas las builds.

#Dónde las usa el kit

Campo Tipo Se revisa o se ejecuta en
QuestData.conditions Condiciones Servidor al tomar la misión; cliente del dueño para las marcas de misión y la ventana de misiones
QuestData.onAccept, QuestData.onComplete Acciones Servidor
NpcOption.conditions Condiciones Servidor, al listar las opciones de un NPC
Npc.greetings[].conditions Condiciones Servidor, para elegir el saludo
DialogueOption.actions Acciones Servidor, cuando se elige la línea
WorldTrigger.conditions, WorldTrigger.actions Las dos Servidor, cuando se activa el disparador

#Condiciones

#Los datos que lee una condición

Met(IPlayerFacts facts) recibe al jugador mediante IPlayerFacts (namespace Blunnyn.KitARPG.Data). Todo lo que tiene funciona tanto en el servidor como en el cliente del dueño.

Miembro Qué devuelve
int Level El nivel del personaje.
CharacterClass Class Su clase.
MapData Map El mapa en el que está, si el mapa está en la base de datos.
int CountItem(string itemId) Cuántas copias de un ítem lleva en la bolsa.
bool Wears(string itemId) Si lleva puesto el ítem (sin contar cosméticos).
long Balance(CurrencyData currency) El oro si la moneda es null, o la cantidad de esa moneda.
int SkillRank(SkillData skill) El rango de un skill, 0 si no lo aprendió.
int Attribute(AttributeData attribute) El total del atributo: clase, puntos gastados y equipo.
bool HasStatus(StatusData status) Si tiene el estado ahora.
QuestState QuestStateOf(QuestData quest) Locked, Available, Active, Ready o Done.
bool HasDone(QuestData quest) Si la entregó al menos una vez.
bool HasDiscovered(string placeId) Un id de mapa o zona donde estuvo.
int Flag(string key) Una marca de historia; 0 si nunca se puso.

El objeto que hay detrás es un PlayerActor, que también implementa IPlayerActor. Cuando necesites un componente del jugador, convierte el tipo y usa Self:

if (facts is IPlayerActor actor && actor.Self.TryGetComponent(out PlayerCharacter player)) { ... }

#La clase base

Miembro Qué hace
string failText Campo del inspector Fail Text: se muestra cuando no se cumple la condición. Vacío usa DefaultText.
string Text failText o DefaultText.
protected abstract string DefaultText { get; } Tu motivo por defecto, como "Needs level 5". Obligatorio.
abstract bool Met(IPlayerFacts facts) Tu regla. Obligatorio.
virtual void Visit(Action<GameData> visit) Entrega cada asset al que apunta la condición.
static string Check(Condition[] conditions, IPlayerFacts facts) La primera condición que no se cumple, como texto, o null si se cumplen todas. Úsalo en tus propias listas.

#Ejemplo: la plantilla

using System;
using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    /// <summary>A rule quests, dialog lines and NPC options can ask for. Lists of conditions show it on their own.</summary>
    [Serializable]
    public class NewCondition : Condition
    {
        public string flag = "my_game.mark";
        public int atLeast = 1;

        protected override string DefaultText => "Not yet";

        // Runs on the server and on the owner's client, so the client can show what is locked.
        public override bool Met(IPlayerFacts facts) => facts.Flag(flag) >= atLeast;
    }
}

#Ejemplo: vida por encima de una proporción

Usa Self para leer la vida del jugador, que se sincroniza con todos, así que funciona en los dos lados.

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class HealthCondition : Condition
    {
        [Range(0, 1)] public float atLeast = 0.5f;

        protected override string DefaultText => $"Needs {atLeast * 100:0}% health";

        public override bool Met(IPlayerFacts facts)
        {
            if (!(facts is IPlayerActor actor) || !actor.Self.TryGetComponent(out PlayerCharacter player)) return false;
            return player.maxHealth > 0 && (float)player.health / player.maxHealth >= atLeast;
        }
    }
}

#Ejemplo: lleva puesto un ítem de un grupo

Lee assets, así que los entrega a Visit.

[Serializable]
public class WearsAnyCondition : Condition
{
    public ItemData[] items = new ItemData[0];

    protected override string DefaultText => "Wear the right gear";

    public override bool Met(IPlayerFacts facts)
    {
        foreach (ItemData item in items)
            if (item != null && facts.Wears(item.Id)) return true;
        return false;
    }

    public override void Visit(Action<GameData> visit)
    {
        foreach (ItemData item in items) visit(item);
    }
}

#Condiciones incluidas

LevelCondition, ClassCondition, QuestCondition (con QuestCheck: NotStarted, Available, Taken, InProgress, Ready, Done, NotDone, NotTaken), ItemCondition, EquippedCondition, CurrencyCondition, DiscoveredCondition, MapCondition, SkillCondition, AttributeCondition, StatusCondition, FlagCondition (Equal, NotEqual, AtLeast, AtMost), TimeCondition (horas del juego o días y horas reales en UTC), y los grupos AnyCondition, AllCondition y NotCondition. Combínalas antes de escribir una nueva: "nivel 10 y sin la misión" son dos condiciones que ya existen.

#Las condiciones corren en el cliente

El cliente del dueño evalúa las condiciones de misión para mostrar las marcas de misión sobre los NPCs y el estado en la ventana de misiones. Eso tiene dos consecuencias:

  • Lee solo lo que tiene el cliente del dueño. Las marcas, las misiones, la bolsa, el equipo, los skills, los estados y el nivel se sincronizan con el dueño. Los valores de PlayerData no (nunca salen del servidor), así que una condición que los lee siempre da false en el cliente.
  • Nunca confíes en la respuesta del cliente. El servidor vuelve a revisar antes de que pase algo. Una condición es un filtro, no un candado que tiene el cliente.

#Acciones

#Qué puede hacer una acción

Run(IPlayerActor actor) recibe al jugador mediante IPlayerActor, que extiende IPlayerFacts. Sus miembros propios funcionan solo en el servidor.

Miembro Qué hace
GameObject Self El objeto del jugador, para componentes que la interfaz no cubre.
IItemUser User El jugador como lo ven los ítems: experiencia, niveles, puntos, skills, estados, viajes. Consulta Efectos de ítems.
string RoomFor(ItemData item, int amount) Por qué no caben en la bolsa, o null.
void GiveItem(ItemData item, int amount) Pone ítems en la bolsa.
void TakeItem(ItemData item, int amount) Quita ítems de la bolsa.
void AddCurrency(CurrencyData currency, long amount) Un valor negativo quita. Oro si la moneda es null. Las monedas premium van a la cuenta mediante el servicio de tienda.
void SetFlag(string key, int value) Pone una marca de historia; 0 la borra. Se guarda con el personaje.
void Discover(string placeId, string placeName) Marca un lugar como descubierto.
string StartQuest(QuestData quest) Empieza una misión. Devuelve por qué no, o null.
void DropQuest(QuestData quest) La abandona.
void RemoveStatus(StatusData status) Quita un estado.
void Say(string text, Color color) Texto flotante sobre el jugador; solo lo ve él.
string FireTrigger(string triggerId) Activa un disparador del mundo en el mapa del jugador. Devuelve por qué no, o null.

#La clase base

Miembro Qué hace Por defecto
virtual string Check(IPlayerActor actor) Por qué no puede ejecutarse ahora, o null. null
abstract void Run(IPlayerActor actor) La ejecuta. Obligatorio.
virtual string Cost Un precio que se muestra junto a la línea de diálogo que la ejecuta, como "50 Gold". null
virtual void Visit(Action<GameData> visit) Entrega cada asset al que apunta. Nada
static string RunAll(GameAction[] actions, IPlayerActor actor) Revisa todas las acciones y después las ejecuta todas. Devuelve el primer motivo por el que no puede, o null.
static string Costs(GameAction[] actions) Los costos de una lista unidos, o null.

Una lista es todo o nada: RunAll llama primero a cada Check y solo después a cada Run. Pon todos los motivos para rechazar en Check y nunca falles dentro de Run.

#Ejemplo: la plantilla

using System;
using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    /// <summary>Something done to a player from a dialog line or a quest reward. Server only.</summary>
    [Serializable]
    public class NewAction : GameAction
    {
        public string flag = "my_game.mark";
        public int add = 1;

        // Every action of a list is checked before any runs; return why not, or null.
        public override string Check(IPlayerActor actor) => null;

        public override void Run(IPlayerActor actor) => actor.SetFlag(flag, actor.Flag(flag) + add);
    }
}

#Ejemplo: dar ítems sin perderlos nunca

El GiveItemAction del kit rechaza cuando la bolsa está llena. Este los da igual: a la bolsa, luego al banco, y si no, quedan retenidos hasta que haya lugar.

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class GiveOrBankAction : GameAction
    {
        public ItemData item;
        public int amount = 1;

        public override string Check(IPlayerActor actor) => item == null ? "Nothing to give" : null;

        public override void Run(IPlayerActor actor)
        {
            if (!actor.Self.TryGetComponent(out PlayerInventory inventory)) return;
            int banked = inventory.GiveOrBank(item, Mathf.Max(1, amount));
            if (banked > 0) actor.Say($"{banked} {item.DisplayName} went to your bank", new Color(1f, 0.85f, 0.4f));
        }

        public override void Visit(Action<GameData> visit) => visit(item);
    }
}

#Ejemplo: un servicio con precio y una línea de registro

Muestra Cost, así que una línea de diálogo con la etiqueta "Heal me" dice "Heal me (200 Gold)", y escribe una línea en el registro del juego que los moderadores pueden buscar.

[Serializable]
public class PaidHealAction : GameAction
{
    public long price = 200;

    public override string Cost => $"{price:N0} {GameInstance.Database?.GoldName ?? "Gold"}";

    public override string Check(IPlayerActor actor) =>
        actor.Balance(null) < price ? $"You need {price:N0} {GameInstance.Database.GoldName}" : null;

    public override void Run(IPlayerActor actor)
    {
        actor.AddCurrency(null, -price);
        if (actor.Self.TryGetComponent(out PlayerCharacter player))
        {
            player.ServerHeal(player.maxHealth, null);
            GameLog.Write("mygame.paid_heal", player, gold: price);
        }
    }
}

#Acciones incluidas

GiveItemAction, TakeItemAction, GiveCurrencyAction, ChargeCurrencyAction, ExperienceAction, PointsAction, ResetAttributesAction, TeachSkillAction, AddStatusAction, RemoveStatusAction, RestoreAction, TravelAction, SetFlagAction, StartQuestAction, DropQuestAction, DiscoverAction, MessageAction y FireTriggerAction.

#Usar listas en tus propios datos

Cualquier ScriptableObject o clase serializable tuya puede tener listas que los diseñadores llenan desde los mismos menús:

using Blunnyn.KitARPG.Data;
using UnityEngine;

[CreateAssetMenu(menuName = "My Game/Reward Chest")]
public class RewardChestData : ScriptableObject
{
    [SerializeReference, PickType] public Condition[] conditions = new Condition[0];
    [SerializeReference, PickType] public GameAction[] rewards = new GameAction[0];
}

En el servidor:

IPlayerActor actor = player.Facts;
string why = Condition.Check(chest.conditions, actor) ?? GameAction.RunAll(chest.rewards, actor);
if (why != null) player.ServerAnnounce(why, new Color(1f, 0.5f, 0.45f));

Sin [PickType] el inspector muestra una lista [SerializeReference] sin forma de elegir un tipo. BountyBoardData.rewards del ejemplo de recompensas es una lista así.

#Servidor y cliente

Servidor Cliente del dueño
Condition.Met Sí, y su respuesta es la definitiva Sí, para mostrar contenido bloqueado
GameAction.Check, Run Sí Nunca
DefaultText, Cost Sí (se manda como texto) Sí

En un jugador las dos corren en la misma máquina, con las mismas respuestas.

#Errores comunes

  • Leer datos solo del servidor en una condición (PlayerData, campos privados del servidor). El cliente muestra el estado equivocado.
  • Fallar dentro de Run. La lista ya pasó sus revisiones, así que las otras acciones se ejecutaron. Revisa en Check.
  • Dar ítems tocando el inventario directamente. Usa GiveItem, TakeItem o PlayerInventory para que la bolsa se sincronice y el guardado quede bien.
  • Guardar estado por jugador en campos. Una sola instancia atiende a todos los jugadores. Usa marcas o PlayerData.
  • Olvidar Visit. Los assets a los que solo tu clase hace referencia pueden quedar fuera de la base de datos del juego.
