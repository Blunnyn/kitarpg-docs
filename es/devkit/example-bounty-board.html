DevKit

Ejemplo: tablero de recompensas

Un recorrido por el ejemplo del DevKit, archivo por archivo: un tablero de recompensas que da una cacería por día, cuenta las muertes, muestra el avance en el HUD, paga recompensas y lleva en Central un ranking de los mejores cazadores. Está hecho solo con los puntos de extensión de esta sección, sin cambiar el kit.

#Qué hace

  1. Un tablero en el pueblo es un NPC con un botón Bounties.
  2. Cada personaje recibe una cacería por día de la lista del tablero: matar cierta cantidad de un monstruo. La cacería es la misma todo el día para ese personaje y distinta entre personajes.
  3. Las muertes se cuentan en el servidor y una línea bajo el reloj muestra "Bounty: Slime 3/8".
  4. De vuelta en el tablero, el botón entrega la cacería y paga las recompensas que tiene el tablero (oro, experiencia, cualquier cosa que puedan hacer las acciones del kit).
  5. En línea, cada recompensa pagada va a un módulo en Central, y /hunters muestra los diez mejores cazadores de todos los mapas.

#Pruébalo

  1. Abre la escena Town o Forest.
  2. Elige KitARPG > DevKit > Add Bounty Board to the Open Scene. Aparece un tablero de madera en el pivote de la vista Scene y, la primera vez, se crea un asset Sample Bounty Board con los dos primeros monstruos normales de tu base de datos. Guarda la escena.
  3. Dale Play, camina hasta el tablero y presiona Today's bounty. Caza; la línea bajo el reloj va contando.
  4. De vuelta en el tablero, presiona Turn in the bounty.
  5. Para probar rápido: /bounty done completa las muertes y /bounty reset borra la cacería de hoy (nivel admin; en un jugador funcionan todos los comandos).
  6. En línea: compila el módulo de Central e instálalo (consulta El módulo de Central más abajo), reinicia los servicios y escribe /hunters.

#BountyBoardData.cs: los datos

[CreateAssetMenu(menuName = "KitARPG/DevKit Example/Bounty Board", order = 900)]
public class BountyBoardData : ScriptableObject
{
    [Serializable]
    public class Bounty
    {
        public MonsterData monster;
        public int count = 10;
        [Tooltip("Paid on turning it in.")]
        [SerializeReference, PickType] public GameAction[] rewards = new GameAction[0];
    }

    public Bounty[] bounties = new Bounty[0];

    /// <summary>Today's bounty for a character. The same all day, different between characters.</summary>
    public int Pick(long characterId, int day) =>
        bounties.Length == 0 ? -1 : (int)((characterId * 31 + day) % bounties.Length);

    public Bounty At(int index) => index >= 0 && index < bounties.Length ? bounties[index] : null;
}
  • Un ScriptableObject común: solo el código del ejemplo apunta a él, así que no necesita ser un GameData con id.
  • rewards es una lista de acciones del kit con [SerializeReference, PickType], así los diseñadores eligen Give Currency, Experience, Give Item o cualquier acción tuya del mismo menú que usan las misiones. Consulta Condiciones y acciones en código.
  • Pick saca la cacería del día del id del personaje y del número de día, así no hay que guardar nada para recordar qué cacería se ofreció.

#BountyOption.cs: el botón

[Serializable]
public class BountyOption : NpcOption
{
    public BountyBoardData board;

    protected override string DefaultLabel => "Bounties";

    public override string LabelFor(PlayerCharacter player) =>
        Bounties.Current(player.Facts, out _) != null ? "Turn in the bounty" : "Today's bounty";

    public override bool AvailableTo(PlayerCharacter player) => board != null;

    public override string Run(Npc npc, PlayerCharacter player)
    {
        Bounties.Register(board);
        string answer = Bounties.Current(player.Facts, out _) != null ? Bounties.TurnIn(player) : Bounties.Take(player, board);
        if (player.TryGetComponent(out PlayerChat chat)) chat.Tell(answer);
        return null;
    }
}
  • LabelFor le da a cada jugador su propio texto.
  • AvailableTo oculta el botón en un tablero sin datos.
  • Run ya sabe que el jugador está junto al tablero: el kit revisó el alcance antes de llamarlo. Responde en el chat con PlayerChat.Tell y devuelve null. Consulta Opciones de NPC.

#Bounties.cs: las reglas del servidor

#El avance en marcas

public const string BoardFlag = "bounty.board";
public const string IndexFlag = "bounty.index";
public const string KillsFlag = "bounty.kills";
public const string DayFlag = "bounty.day";
public const string DoneFlag = "bounty.done";
public const string LogKind = "bounty.done";

Todo el avance son marcas del personaje, con IPlayerActor.SetFlag y Flag. Se guardan con el personaje en un jugador y en línea, y se sincronizan con el dueño, sin código de guardado. El tablero se guarda como un hash del nombre de su asset (Animator.StringToHash(board.name)), la cacería como su índice más uno (0 significa ninguna) y el día como días desde el 2020-01-01 UTC. Consulta Guardar datos.

#Encontrar los tableros tras un reinicio

static readonly Dictionary<int, BountyBoardData> boards = ...;
static bool scanned;

static BountyBoardData Board(int key)
{
    if (boards.TryGetValue(key, out BountyBoardData board) || scanned) return board;
    scanned = true;
    foreach (Npc npc in UnityEngine.Object.FindObjectsByType<Npc>(FindObjectsSortMode.None))
        foreach (NpcOption option in npc.AllOptions())
            if (option is BountyOption b && b.board != null) Register(b.board);
    boards.TryGetValue(key, out board);
    return board;
}

Las marcas de un personaje apuntan a un tablero por su hash. Después de reiniciar el servidor nadie usó todavía un tablero, así que la primera búsqueda revisa una vez los NPCs de las escenas cargadas (Npc.AllOptions() incluye las opciones anidadas en las líneas de diálogo). Una escena nueva reinicia la búsqueda.

#Engancharse

// Cleared before anything subscribes, so listeners from other assemblies are never wiped.
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
static void ResetStatics()
{
    boards.Clear();
    scanned = false;
    ServerTurnedIn = null;
}

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
static void Hook()
{
    SceneManager.sceneLoaded -= OnSceneLoaded;
    SceneManager.sceneLoaded += OnSceneLoaded;
    Monster.ServerKilled -= OnKilled;
    Monster.ServerKilled += OnKilled;
    PlayerCharacter.LocalSpawned -= AskOnSpawn;
    PlayerCharacter.LocalSpawned += AskOnSpawn;
    KitNetworkManager manager = KitNetworkManager.Instance;
    if (manager == null) return;
    manager.ServerStarted += () => NetworkServer.ReplaceHandler<BountyAsk>(OnAsk);
    manager.ClientConnected += () => NetworkClient.ReplaceHandler<BountyState>(BountyTracker.Show);
}
  • ResetStatics limpia el estado estático (boards, scanned y el evento ServerTurnedIn) en SubsystemRegistration, al comienzo de cada Play, porque el proyecto juega sin recarga de dominio. Limpiarlo ahí, antes de que nada se suscriba, permite que BountyHunters en Game.Bounties.Server se suscriba a ServerTurnedIn después sin que se borre (consulta Play sin recarga de dominio).
  • Hook se suscribe a los eventos estáticos con -= primero, y antes de revisar el network manager, así que las muertes, las apariciones y las cargas de escena quedan enganchadas aunque la primera escena no tenga KitNetworkManager.
  • Los manejadores de mensajes se registran en cada arranque del servidor y en cada conexión del cliente (consulta Mensajes de red).
  • Monster.ServerKilled cuenta las muertes en el servidor; PlayerCharacter.LocalSpawned pide el estado en el cliente.

#Tomar una recompensa

public static string Take(PlayerCharacter player, BountyBoardData board)
{
    IPlayerActor actor = player.Facts;
    if (actor.Flag(DayFlag) == Today && actor.Flag(IndexFlag) == 0) return "You already hunted today's bounty. Come back tomorrow.";
    int index = board.Pick(player.State.id, Today);
    BountyBoardData.Bounty bounty = board.At(index);
    if (bounty == null || bounty.monster == null) return "The board is empty.";
    actor.SetFlag(BoardFlag, Register(board));
    actor.SetFlag(IndexFlag, index + 1);
    actor.SetFlag(KillsFlag, 0);
    actor.SetFlag(DayFlag, Today);
    Send(player);
    return $"Today's bounty: slay {bounty.count} {bounty.monster.DisplayName}.";
}

Cada decisión usa el estado del servidor: las marcas del personaje y su id en la base de datos. Nada viene del cliente.

#Contar las muertes

static void OnKilled(Monster monster, PlayerCharacter killer)
{
    if (killer == null || killer.State == null || monster.Data == null) return;
    IPlayerActor actor = killer.Facts;
    BountyBoardData.Bounty bounty = Current(actor, out _);
    if (bounty == null || bounty.monster != monster.Data) return;
    int kills = actor.Flag(KillsFlag);
    if (kills >= bounty.count) return;
    actor.SetFlag(KillsFlag, kills + 1);
    if (kills + 1 == bounty.count) killer.ServerAnnounce("Bounty complete! Turn it in at the board.", new Color(1f, 0.85f, 0.3f));
    Send(killer);
}

ServerKilled da el jugador que se ganó la muerte (puede ser null). La cuenta se detiene en el objetivo.

#Entregar

public static string TurnIn(PlayerCharacter player)
{
    IPlayerActor actor = player.Facts;
    BountyBoardData.Bounty bounty = Current(actor, out _);
    if (bounty == null) return "You have no bounty.";
    int kills = actor.Flag(KillsFlag);
    if (kills < bounty.count) return $"{kills} of {bounty.count} {bounty.monster.DisplayName} so far.";
    string why = GameAction.RunAll(bounty.rewards, actor);
    if (why != null) return why;
    actor.SetFlag(IndexFlag, 0);
    actor.SetFlag(DoneFlag, actor.Flag(DoneFlag) + 1);
    GameLog.Write(LogKind, player, itemId: bounty.monster.Id, amount: bounty.count);
    ServerTurnedIn?.Invoke(player, bounty.monster);
    Send(player);
    return "Bounty paid. Well hunted.";
}
  • GameAction.RunAll revisa primero cada recompensa (una bolsa llena rechaza Give Item) y luego las paga todas.
  • GameLog.Write escribe una línea bounty.done; los moderadores la encuentran con /logs (consulta Registro del juego y reportes).
  • ServerTurnedIn es el evento propio del ejemplo, que se lanza en Game.Bounties y escucha Game.Bounties.Server, que los clientes en línea no tienen.

#Avisarle al cliente

public static void Send(PlayerCharacter player)
{
    BountyBoardData.Bounty bounty = Current(player.Facts, out _);
    player.connectionToClient?.Send(bounty == null
        ? new BountyState()
        : new BountyState { monster = bounty.monster.DisplayName, kills = player.Facts.Flag(KillsFlag), required = bounty.count });
}

static void AskOnSpawn(PlayerCharacter _) => NetworkClient.Send(new BountyAsk());

// The connection says who asks; the message carries nothing to trust.
static void OnAsk(NetworkConnectionToClient conn, BountyAsk _)
{
    if (!CommandPacing.Allow(conn)) return;
    if (conn.identity != null && conn.identity.TryGetComponent(out PlayerCharacter player) && player.State != null) Send(player);
}

La petición del cliente está vacía: el servidor sabe quién preguntó por la conexión. Se limita con CommandPacing.

#BountyTracker.cs: la línea del HUD

public static void Show(BountyState state)
{
    if (label == null) Build();
    if (label == null) return;
    bool has = !string.IsNullOrEmpty(state.monster);
    label.gameObject.SetActive(has);
    if (!has) return;
    bool done = state.kills >= state.required;
    label.text = done
        ? $"<color=#F5D67F>Bounty: {state.monster} {state.kills}/{state.required}, turn it in</color>"
        : $"Bounty: {state.monster} {state.kills}/{state.required}";
}

    GameObject hud = GameInstance.Hud;

    var go = new GameObject("Bounty Tracker", typeof(RectTransform));
    go.transform.SetParent(canvas.transform, false);
    // anchored to the top right, under the clock
    ...
}

GameInstance.Hud es la instancia del HUD en ejecución. La línea se arma desde código la primera vez que llega un estado. En un juego real, pon tu interfaz en el prefab del HUD, para que los diseñadores puedan moverla y darle estilo (y llevarla a juegos existentes con una actualización del kit). #BountiesDoneCondition.cs: una condición para diseñadores

[Serializable]
public class BountiesDoneCondition : Condition
{
    public int atLeast = 5;

    protected override string DefaultText => $"Needs {atLeast} bounties done";

    public override bool Met(IPlayerFacts facts) => facts.Flag(Bounties.DoneFlag) >= atLeast;
}

Lee una marca, que el cliente del dueño también tiene, así las marcas de misión y las líneas bloqueadas se muestran bien. Los diseñadores pueden ponerla en una opción de tienda que se abre después de cinco recompensas, en una misión o en un saludo.

#Server/BountyCommands.cs: el comando de GM

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
static void Register()
{
    GmCommands.Register(new GmCommand
    {
        name = "bounty", rank = GmRank.Admin, usage = "bounty reset|done [player]", description = "Clears a player's bounty for today, or fills its kills.",
        run = c =>
        {
            PlayerCharacter target = c.Target(1);
            if (target == null) return "Nobody by that name here.";
            IPlayerActor actor = target.Facts;
            switch (c.Arg(0))
            {
                case "reset":
                    actor.SetFlag(Bounties.DayFlag, 0);
                    actor.SetFlag(Bounties.IndexFlag, 0);
                    break;
                case "done":
                    BountyBoardData.Bounty bounty = Bounties.Current(actor, out _);
                    if (bounty == null) return $"{target.characterName} has no bounty.";
                    actor.SetFlag(Bounties.KillsFlag, bounty.count);
                    break;
                default:
                    return "Usage: /bounty reset|done [player]";
            }
            Bounties.Send(target);
            return $"Bounty of {target.characterName}: {c.Arg(0)}.";
        },
    });
}

Vive en Game.Bounties.Server, así que las builds de cliente lo dejan fuera. El nivel admin significa que cada uso queda auditado. Consulta Comandos de GM en código.

#Server/BountyHunters.cs: Central y el historial guardado

public const string HistoryKey = "bounties.history";

[Serializable]
public class History
{
    public List<string> monsters = new List<string>();
}

static void OnTurnedIn(PlayerCharacter player, MonsterData monster)
{
    History history = PlayerData.Get<History>(player, HistoryKey);
    history.monsters.Insert(0, monster.DisplayName);
    if (history.monsters.Count > HistorySize) history.monsters.RemoveRange(HistorySize, history.monsters.Count - HistorySize);
    PlayerData.Set(player, HistoryKey, history);
    // Offline the board just misses this one; the character's own history still has it.
    CentralMessages.Send(new BountyFinished { characterId = player.State.id, name = player.characterName, monster = monster.Id });
}
  • Cada personaje guarda sus diez últimas cacerías con PlayerData, que se guarda con el personaje y nunca se envía a los clientes.
  • Cada recompensa pagada va a Central. Send devuelve false en un jugador o mientras Central no está, y no se pone nada en cola: al ranking le falta esa, al historial no.
CentralMessages.On<BountyBoardList>(OnBoard);
GmCommands.Register(new GmCommand
{
    name = "hunters", rank = GmRank.Player, usage = "hunters", description = "The best bounty hunters on every map, and your last hunts.",
    run = c =>
    {
        string mine = Last(c.player);
        if (!CentralMessages.Online) return "The hunters board is kept online." + mine;
        CentralMessages.Send(new BountyBoardAsk { characterId = c.player.State.id });
        return "Asking the guild of hunters..." + mine;
    },
});

static void OnBoard(BountyBoardList board)
{
    var text = new StringBuilder("Best bounty hunters:");
    int rank = 1;
    foreach (BountyHunter hunter in board.top ?? new BountyHunter[0])
        text.Append($"\n{rank++}. {PlayerText.NoTags(hunter.name)}: {hunter.bounties}");
    if (rank == 1) text.Append("\nNobody yet.");
    text.Append($"\nYou: {board.mine}");
    SocialHub.Notice(board.characterId, text.ToString());
}
  • /hunters es un comando de nivel jugador: una función del chat, no una herramienta del equipo, así que no se audita.
  • La respuesta llega después por CentralMessages.On y se muestra en el chat de quien preguntó con SocialHub.Notice.
  • Los nombres que vienen de jugadores se muestran con PlayerText.NoTags.

// Messages between the map servers and the Bounties module in Central. Plain C# with public fields,

Está en Game.Bounties.Shared, un ensamblado sin referencias al motor. Unity lo compila y el módulo de Central enlaza el mismo archivo, así los dos lados siempre coinciden.

#Editor/BountySetup.cs: el menú de preparación

KitARPG > DevKit > Add Bounty Board to the Open Scene:

  • arma un tablero con tres cubos en el pivote de la vista Scene, con un Npc (id bounty_board, nombre Bounty Board), un BoxCollider para los clics y una Nameplate,
  • agrega una BountyOption que apunta a Sample Bounty Board,
  • crea Sample Bounty Board la primera vez, junto al script, con los dos primeros monstruos normales que tienen prefab en la base de datos del juego: 8 y 10 muertes, que pagan 150 y 200 de oro y 200 y 300 de experiencia,
  • registra el Undo y marca la escena como modificada.

Usa ModulesWindow.Find() para llegar a la base de datos del juego. Consulta Extensiones del editor.

#El módulo de Central

Services/Examples/Bounties/ es el lado de Central:

Archivo Qué hace
Game.Bounties.Central.csproj Referencia el contrato de módulos sin copiarlo, enlaza BountyBoardMessages.cs y copia la compilación a -p:KitModulesDir.
BountiesModule.cs ICentralModule llamado Bounties. Registra BountyContext, atiende BountyFinished (valida el nombre, de 1 a 32 caracteres, y m.Hosts(characterId), y luego suma uno a la fila bajo un SemaphoreSlim) y BountyBoardAsk (responde los 10 primeros y la cuenta propia de quien pregunta).
