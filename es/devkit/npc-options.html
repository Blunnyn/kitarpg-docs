Opciones de NPC

Cómo agregar tus propios botones a los NPCs: la clase base NpcOption, qué revisa el servidor antes de correrla, cómo responderle al jugador, cómo abrir una ventana propia, y ejemplos completos.

#Qué es una opción de NPC

Un componente Npc en una escena tiene una lista de opciones (Npc.options). Cuando un jugador habla con el NPC, el servidor lista las opciones que ese jugador puede ver, el cliente las muestra como botones, y cuando el jugador elige una, el servidor la corre. Las opciones del kit abren tiendas, teletransportan, enseñan skills, ofrecen misiones, corren líneas de diálogo, abren el banco, el mercado, el banco del gremio, la forja, el correo, los recaudadores, la fundación de gremios y las casas de gremio, y activan disparadores del mundo.

Un tipo nuevo es una clase. NpcOption es [Serializable] y la lista es [SerializeReference, PickType], así que la tuya aparece en el menú + de las Options de cada NPC, y en las Options anidadas de cada línea de diálogo.

Dónde va el archivo: el ensamblado Game. Las escenas guardan la opción en el NPC, así que las dos builds cargan la clase, aunque solo el servidor la corre.

#La clase base

NpcOption vive en Blunnyn.KitARPG.Net.

#Campos del inspector

Campo Qué hace Por defecto
Label (label) Texto del botón. Vacío usa DefaultLabel. vacío
Required Level (requiredLevel) Oculta para los personajes de nivel menor. 0
Conditions (conditions) Oculta mientras alguna no se cumpla. ninguna
Show When Locked (showWhenLocked) La muestra en gris con el motivo en lugar de ocultarla. apagado

#Miembros para reemplazar

Miembro Qué hace Por defecto
protected abstract string DefaultLabel { get; } Texto del botón cuando Label está vacío. Obligatorio.
virtual string LabelFor(PlayerCharacter player) Servidor. El texto que ve este jugador, para etiquetas que cambian según el jugador. Label
virtual bool AvailableTo(PlayerCharacter player) Servidor. False la oculta para este jugador, incluso con Show When Locked. true
virtual KitModule Module El módulo del kit al que pertenece. Cuando ese módulo está apagado en KitARPG > Modules, la opción desaparece. KitModule.None
abstract string Run(Npc npc, PlayerCharacter player) Servidor. La ejecuta. Devuelve un código de error para el jugador, o null. Obligatorio.

#Ayudas que puedes llamar

Miembro Qué devuelve
string Label Label o DefaultLabel.
string Locked(PlayerCharacter player) Por qué el jugador no puede elegirla (nivel, luego condiciones), o null.
bool Offered(PlayerCharacter player) Módulo encendido, no bloqueada y AvailableTo.
bool Listed(PlayerCharacter player) Si el jugador la ve, la pueda elegir o no.

#Qué revisa el servidor antes de Run

El cliente del dueño pide mediante PlayerInteraction. Antes de que se llame a tu Run, el servidor ya:

  1. Confirmó que el jugador está vivo, cargado y hablando con ese NPC.
  2. Gastó del presupuesto de pedidos por jugador (Max Requests Per Second, maxRequestsPerSecond, 10 en PlayerInteraction).
  3. Revisó que el jugador esté dentro del Talk Range del NPC (talkRange, 3 m, más medio metro). Si está demasiado lejos responde too_far.
  4. Encontró la opción por su índice en la lista en pantalla, y revisó Offered(player): módulo, nivel, condiciones y AvailableTo.

Así que dentro de Run sabes que el jugador está junto al NPC y que puede elegir la opción. Todo lo que tu opción cueste o requiera además de eso, revísalo de nuevo en Run.

#Responderle al jugador

Run devuelve un texto que se envía al cliente del dueño como PlayerInteraction.ErrorReceived. De las ventanas del kit, solo la ventana de la tienda los muestra, mientras está abierta, y convierte los códigos conocidos (NpcErrors.NotEnoughMoney, NpcErrors.TooFar y los errores de inventario) en frases.

Para una opción de diálogo simple, avísale tú al jugador y devuelve null:

player.ServerAnnounce("Blessed!", new Color(1f, 0.85f, 0.4f));    // floating text over the player
if (player.TryGetComponent(out PlayerChat chat)) chat.Tell("The priest blesses you."); // a system line in the chat
return null;

DialogueOption hace lo mismo con los motivos de rechazo de sus acciones. La opción del ejemplo de recompensas usa PlayerChat.Tell.

#Ejemplo: la plantilla

Create > KitARPG > Scripts > NPC Option crea una bendición que cura a cambio de oro, y le avisa al jugador en el chat cuando no puede pagar. Consulta Plantillas.

#Ejemplo: bendición, respondida en el chat

La plantilla con una etiqueta que muestra el precio, un estado de bendición en lugar de una curación completa, y una línea en el chat después de la bendición:

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class BlessingOption : NpcOption
    {
        public long price = 50;
        public StatusData blessing;
        public float seconds = 300;

        protected override string DefaultLabel => "Bless me";

        public override string LabelFor(PlayerCharacter player) =>
            $"{Label} ({price:N0} {GameInstance.Database.GoldName})";

        public override bool AvailableTo(PlayerCharacter player) => blessing != null;

        public override string Run(Npc npc, PlayerCharacter player)
        {
            var inventory = player.GetComponent<PlayerInventory>();
            if (inventory.gold < price)
            {
                Tell(player, $"That costs {price:N0} {GameInstance.Database.GoldName}.");
                return null;
            }
            inventory.AddGold(-price);
            player.AddStatus(blessing, 1, seconds);
            GameLog.Write("mygame.blessing", player, gold: price, detail: npc.Id);
            Tell(player, $"{npc.displayName} blesses you.");
            return null;
        }

        static void Tell(PlayerCharacter player, string text)
        {
            if (player.TryGetComponent(out PlayerChat chat)) chat.Tell(text);
        }
    }
}

PlayerCharacter.AddStatus es el método de IItemUser; el jugador lo implementa.

#Ejemplo: una opción que abre una ventana propia

Las opciones corren en el servidor, así que para abrir una ventana en el cliente la opción le envía un mensaje al dueño. Esta abre una ventana de "alijo" y le dice a la ventana de qué NPC vino.

using System;
using Blunnyn.KitARPG.Net;
using Mirror;
using UnityEngine;

namespace Game
{
    public struct OpenStashMessage : NetworkMessage
    {
        public string npcId;
    }

    [Serializable]
    public class StashOption : NpcOption
    {
        protected override string DefaultLabel => "Open the stash";

        public override string Run(Npc npc, PlayerCharacter player)
        {
            player.connectionToClient?.Send(new OpenStashMessage { npcId = npc.Id });
            return null;
        }
    }

    public static class StashClient
    {
        public static event Action<Npc> Opened;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void ResetStatics() => Opened = null;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Hook()
        {
            KitNetworkManager manager = KitNetworkManager.Instance;
            if (manager == null) return;
            manager.ClientConnected += () => NetworkClient.ReplaceHandler<OpenStashMessage>(OnOpen);
        }

        static void OnOpen(OpenStashMessage message)
        {
            if (Npc.TryFind(message.npcId, out Npc npc)) Opened?.Invoke(npc);
        }
    }
}

Tu ventana se suscribe a StashClient.Opened, se abre, y se cierra sola cuando el jugador se aleja fuera de npc.InReach(PlayerCharacter.Local.transform.position). Cada pedido que la ventana devuelva debe revisar otra vez en el servidor que el jugador esté cerca de ese NPC (npc.InReach(player.transform.position)). Consulta Mensajes de red.

#Ejemplo: una etiqueta que cambia según el jugador

La opción del ejemplo de recompensas dice "Today's bounty" o "Turn in the bounty" según el jugador:

public override string LabelFor(PlayerCharacter player) =>
    Bounties.Current(player.Facts, out _) != null ? "Turn in the bounty" : "Today's bounty";

#Ejemplo: pertenecer a un módulo

Una opción que pertenece a uno de los módulos del kit desaparece cuando ese módulo está apagado:

public override KitModule Module => KitModule.Guilds;

#Estado en una opción

Una instancia de opción vive en un NPC de una escena, y todos los jugadores que hablan con ese NPC la comparten. Usa campos de instancia solo para el estado del NPC, nunca de un jugador. Marca los campos solo de ejecución con [NonSerialized] para que no terminen en la escena. El ShopOption del kit guarda así su stock limitado por NPC:

[NonSerialized] int[] left;

Para el estado por jugador, usa marcas, PlayerData o un sistema del jugador (consulta Guardar datos).

#Agregar la opción a un NPC

  1. Selecciona el NPC en su escena (un GameObject con el componente Npc).
  2. En Options, presiona + y elige tu clase en el menú.
  3. Completa sus campos, su Label, su Required Level y sus Conditions.
  4. Dentro de una opción Dialogue, la lista anidada Options también acepta tu clase, así que puede aparecer después de una línea de charla.

Las opciones con Label vacío usan su DefaultLabel. Cuando un NPC no tiene saludo y tiene una sola opción, hablarle corre esa opción al instante.

#Servidor y cliente

Corre en
LabelFor, AvailableTo, Locked, Offered, Run Servidor
Etiquetas y motivos de bloqueo Se envían como texto al cliente
El componente Npc Ambos: los clientes lo usan por su nombre, su posición y su alcance

En un jugador el host corre la mitad del servidor en el mismo proceso.

#Errores comunes

  • Devolver una frase desde Run y esperar que el diálogo la muestre. Usa ServerAnnounce o PlayerChat.Tell.
  • Confiar en la ventana que sigue. Una ventana abierta por una opción envía sus propios pedidos; cada uno debe revisar otra vez el alcance y las reglas.
  • Guardar datos por jugador en la opción. La comparten todos los que hablan con ese NPC.
  • Cambiar el orden de las opciones mientras un jugador está hablando. El cliente elige por índice; reordena en el editor, no en tiempo de ejecución.
