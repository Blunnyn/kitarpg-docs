Comandos de GM en código

Cómo agregar tus propios comandos con barra: registrar un GmCommand, leer argumentos con GmContext, elegir un nivel, cómo funciona la auditoría, y ejemplos completos.

#Qué es un comando

Los jugadores escriben comandos en el chat, empezando con /. El chat envía la línea al servidor de mapa, que busca el comando, compara el nivel del jugador con el nivel del comando, lo ejecuta y muestra la respuesta como una línea del sistema en el chat. El panel de GM (F8 o /gm) ejecuta los mismos comandos. Los comandos del kit están listados en Comandos de GM.

Los comandos se registran desde código con GmCommands.Register. GmCommands vive en KitARPG.Server (namespace Blunnyn.KitARPG.Server), que los clientes online nunca llevan.

Dónde va el archivo: en el ensamblado Game.Server (consulta Ensamblados). Así los comandos existen en los servidores de mapa, en un jugador y en el editor, y nunca en una build de cliente online.

#Registrar un comando

using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Server;
using UnityEngine;

namespace Game
{
    public static class MyCommands
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Register()
        {
            GmCommands.Register(new GmCommand
            {
                name = "refresh",
                aliases = new[] { "fill" },
                rank = GmRank.Moderator,
                usage = "refresh [player]",
                description = "Fills a player's health.",
                run = c =>
                {
                    PlayerCharacter target = c.Target(0);
                    if (target == null) return "Nobody by that name here.";
                    target.ServerHeal(target.maxHealth, null);
                    return $"Healed {target.characterName}.";
                },
            });
        }
    }
}

El kit vacía la lista y registra sus propios comandos en SubsystemRegistration en cada Play, así que registra los tuyos en AfterSceneLoad (o AfterAssembliesLoaded). Registrar un nombre que ya existe reemplaza al comando anterior, incluidos los del kit. Así se cambia un comando del kit; también es así como se rompe uno sin querer, así que elige nombres propios.

#Campos de GmCommand

Campo Qué es Por defecto
name Lo que los jugadores escriben después de /.
aliases Otros nombres para el mismo comando. ninguno
rank El nivel que pide por defecto (ver abajo). GmRank.Admin
usage Lo muestra /help, como "item id [amount] [player]".
description Una línea para /help.
run Func<GmContext, string>: lo hace y devuelve la respuesta a mostrar, o null para ninguna.

#Niveles

GmRank Valor Significado
Player 1 Cualquiera.
Moderator 2 Moderación del chat y de jugadores.
GameMaster 3 Cambios en el juego: ítems, teletransportes, monstruos.
Admin 4 Todo, incluidos los roles.

El nivel que pide un comando es GmCommands.LevelOf(command): el nivel puesto para su nombre en Game Settings > GM commands (GameInstance.gmCommandLevels) cuando hay uno, y si no su rank. Los diseñadores pueden subir o bajar cualquier comando, incluidos los tuyos, sin código. /role siempre pide Admin.

El nivel de un jugador es GmCommands.RankOf(player): el rol de la cuenta en la base de datos (accounts.Role), o GmCommands.EveryoneRank si es mayor. En un jugador, Single Player Commands (singlePlayerCommands, activado por defecto) hace que EveryoneRank sea Admin, así que cada comando funciona como truco. Online es Player.

Un jugador por debajo del nivel del comando recibe "Unknown command", como si no existiera.

#GmContext

Lo que recibe run:

Miembro Qué es
PlayerCharacter player Quién lo escribió.
string[] args Las palabras después del nombre, separadas por espacios.
string rest Todo lo que viene después del nombre, tal como se escribió. Úsalo para texto libre.
int level El nivel que pide este comando. Pásalo a Central en los comandos que Central vuelve a revisar.
string Arg(int i) La palabra i, o null.
int Int(int i, int fallback) La palabra i como entero, o fallback.
long Long(int i, long fallback) Lo mismo, como long.
float Float(int i, float fallback) Lo mismo, como float. Rechaza NaN e infinito.
PlayerCharacter Target(int i) El jugador nombrado por la palabra i en este mapa, o quien lo escribió cuando falta la palabra. Null cuando el nombre no está en este mapa.
T Data<T>(int i) Los datos del juego de tipo T cuyo id es la palabra i, o null.

Los números se leen con la cultura invariante, así que 1.5 funciona en cualquier máquina.

#Auditoría

Cada comando cuyo nivel está por encima de Player (2 o más) es trabajo del staff y queda registrado:

  • Cada uso, permitido o rechazado por su nivel, va a la auditoría de GM (tabla gm_audit online, el guardado en un jugador) con la cuenta, el personaje, el nivel, el comando, la línea, el objetivo y el resultado.
  • Cada uso que se ejecutó también escribe una línea en el registro del juego de tipo gm.command con la respuesta.
  • Cuando la auditoría no se puede registrar (Central no responde), los comandos del staff se pausan y responden "GM commands are paused". Nada de nivel staff se ejecuta sin su registro.

Los comandos de nivel Player no se auditan.

GmCommands.ServerUsed (PlayerCharacter, string line) se lanza para cada comando que se ejecuta, antes de ejecutarlo. GmAudit.Recorded (GmAuditEntry) se lanza para cada línea de auditoría. Consulta Eventos.

#Límites

GmCommands tiene topes que los comandos del kit respetan, para que un error de tipeo o una cuenta de staff robada no inunden la economía. Respétalos en tus propios comandos que reparten cosas:

Campo Por defecto
MaxItems 9.999
MaxGold 1.000.000.000
MaxExperience 1.000.000.000
MaxPoints 1.000
MaxStatusSeconds 3.600
MaxKillRange 100
MaxMuteMinutes 525.600

Son campos estáticos que se reinician en cada Play. Cámbialos desde tu propio método AfterSceneLoad si tu juego necesita otros límites.

#Ejemplos

#Dar puntos de atributo, con tope

GmCommands.Register(new GmCommand
{
    name = "points", rank = GmRank.GameMaster, usage = "points amount [player]", description = "Gives attribute points.",
    run = c =>
    {
        int amount = c.Int(0, 0);
        if (amount <= 0) return "Usage: /points amount [player]";
        amount = Mathf.Min(amount, GmCommands.MaxPoints);
        PlayerCharacter target = c.Target(1);
        if (target == null) return "Nobody by that name here.";
        target.GainPoints(amount, 0);
        return $"{target.characterName} got {amount} attribute points.";
    },
});

#Buscar datos del juego por id

Data<T> encuentra datos del juego por id:

GmCommands.Register(new GmCommand
{
    name = "where", rank = GmRank.Player, usage = "where monster_id", description = "Maps where a monster lives.",
    run = c =>
    {
        MonsterData monster = c.Data<MonsterData>(0);
        if (monster == null) return "No monster with that id.";
        var maps = new System.Collections.Generic.List<string>();
        foreach (MapData map in GameInstance.Database.maps)
            if (map != null && System.Array.IndexOf(map.monsters, monster) >= 0) maps.Add(map.DisplayName);
        return maps.Count == 0 ? $"{monster.DisplayName} lives nowhere listed." : $"{monster.DisplayName}: {string.Join(", ", maps)}";
    },
});

#Un comando para jugadores

Los comandos de nivel Player son una forma rápida de agregar funciones al chat. El /hunters del ejemplo de recompensas le pide a Central una clasificación:

GmCommands.Register(new GmCommand
{
    name = "hunters", rank = GmRank.Player, usage = "hunters", description = "The best bounty hunters on every map, and your last hunts.",
    run = c =>
    {
        string mine = Last(c.player);
        if (!CentralMessages.Online) return "The hunters board is kept online." + mine;
        CentralMessages.Send(new BountyBoardAsk { characterId = c.player.State.id });
        return "Asking the guild of hunters..." + mine;
    },
});

La respuesta de Central llega después y se muestra con SocialHub.Notice. Consulta Hablar con Central.

#Texto libre

rest conserva los espacios:

GmCommands.Register(new GmCommand
{
    name = "notice", rank = GmRank.Moderator, usage = "notice text", description = "Sets the notice board.",
    run = c => string.IsNullOrWhiteSpace(c.rest) ? "Usage: /notice text" : SetNotice(c.rest),
});

Limpia todo texto que vayan a ver otros jugadores con PlayerText.Clean(text, maxLength).

#/help

/help lista los comandos del chat y luego cada comando que permite el nivel del jugador, incluidos los de nivel Player, cada uno con su uso y descripción. Los comandos por encima del nivel Player terminan con su nivel entre corchetes, como [3]; los de nivel Player se muestran sin él.

#Errores

Una excepción dentro de run se atrapa: se registra en el log del servidor y el jugador ve "/name failed: message". Devuelve una frase en lugar de lanzar una excepción para todo lo que el jugador hizo mal.

#Servidor y cliente

Los comandos se ejecutan solo en el servidor de mapa (o en el host de un jugador). El cliente envía la línea escrita; la línea se corta en 300 caracteres y se limita al mismo ritmo que el chat. Un cliente no puede llegar a nada de tu run salvo por esa línea, y la revisión del nivel ocurre antes de que se ejecute.

#Errores comunes

  • Poner comandos en el ensamblado Game. No ve KitARPG.Server, y si lo viera, los clientes llevarían el código del comando.
  • Registrar en SubsystemRegistration. El kit vacía la lista ahí; el orden entre esos métodos no está definido.
  • Reutilizar el nombre de un comando del kit. El tuyo lo reemplaza.
  • Cantidades sin tope. Usa los campos Max....
  • Actuar sobre un nombre sin Target. Target solo encuentra jugadores en este mapa; para jugadores en otro lugar, pasa por Central.
