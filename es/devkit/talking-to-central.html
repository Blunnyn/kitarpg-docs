Hablar con Central

Cómo los servidores de mapa intercambian mensajes propios con un módulo de Central, para funciones que abarcan varios mapas o personajes: rankings, eventos del mundo, contadores de todo el servidor. Esta página cubre el lado del mapa (CentralMessages); el lado de Central está en Módulos de servicio.

#Cuándo necesitas Central

En línea, cada mapa corre en su propio proceso de servidor y nunca toca la base de datos. Central los une a todos, mantiene las sesiones y escribe en la base de datos. Todo lo que un solo mapa no puede saber necesita Central:

  • un ranking de todos los personajes (el tablero de cazadores del ejemplo de recompensas),
  • un evento que empieza en todos los mapas a la vez,
  • un contador de todo el servidor,
  • datos de personajes que no están en línea.

Los datos por personaje que viajan con el personaje no necesitan Central: usa marcas o PlayerData (consulta Guardar datos).

En un jugador no hay Central. Toda función que lo use necesita una alternativa, aunque la alternativa sea "solo en línea".

#Cómo viaja un mensaje

Map server (Unity)                       Central (.NET)
CentralMessages.Send(new BountyFinished)  ->  module handler for BountyFinished
                                               m.Reply(new BountyBoardList)
CentralMessages.On<BountyBoardList>(...)  <-   (to the map that asked)
  1. En el mapa, CentralMessages.Send escribe el nombre de la clase del mensaje y su JSON (JsonUtility de Unity) por el enlace autenticado del mapa con Central (LiteNetLib, confiable y en orden).
  2. Central busca qué módulo registró ese nombre de clase y le entrega el mensaje, deserializado con System.Text.Json, junto con qué mapa lo mandó.
  3. El módulo responde al mapa que preguntó (Reply), al mapa donde está un personaje (SendToCharacter), a un mapa por id (Send) o a todos los mapas (Broadcast).
  4. En el mapa, los manejadores de CentralMessages.On<T> corren en el hilo principal.

#CentralMessages

CentralMessages vive en KitARPG.Server (namespace Blunnyn.KitARPG.Server), así que el código que lo usa va en un ensamblado solo de servidor, como Game.Server.

Miembro Qué hace
static bool Online El mapa está registrado en Central. False en un jugador y mientras Central no está.
static bool Send<T>(T message) Manda a los módulos de Central. False cuando no se puede llegar a Central; no se encola nada. Lanza una excepción si el nombre es de un mensaje del kit.
static void On<T>(Action<T> handler) Llama a handler en el hilo principal por cada T que manda Central. Un manejador por tipo: una segunda llamada reemplaza a la primera; null lo quita. Lanza una excepción si el nombre es de un mensaje del kit.

Los manejadores se borran al empezar cada Play; regístralos en AfterSceneLoad (o AfterAssembliesLoaded). Una excepción dentro de un manejador se registra en el log y no corta el enlace.

#Escribir los mensajes

Los mensajes son clases simples de C#, que compilan Unity y tu módulo de Central desde el mismo archivo:

using System;

namespace Game
{
    /// <summary>Map to Central: a character finished a bounty.</summary>
    [Serializable]
    public class BountyFinished
    {
        public long characterId;
        public string name;
        public string monster;
    }

    /// <summary>Central to the map the asking character is on.</summary>
    [Serializable]
    public class BountyBoardList
    {
        public long characterId;
        public BountyHunter[] top = new BountyHunter[0];
        public int mine;
    }

    [Serializable]
    public class BountyHunter
    {
        public string name;
        public int bounties;
    }
}

Reglas, porque los leen dos bibliotecas de JSON distintas:

  • Clases [Serializable] con campos públicos. Sin propiedades, sin constructores con parámetros, sin diccionarios.
  • Nombres de campos en lowerCamelCase. Central escribe el JSON en camelCase; JsonUtility de Unity compara los nombres exactos, así que un campo llamado CharacterId volvería vacío en el mapa.
  • Tipos que leen los dos lados: int, long, float, double, bool, string, enums (como números), arreglos y listas de esos y de otras clases de mensaje.
  • Sin tipos de Unity (Vector3, Color). Manda números.
  • Nombres propios. Los mensajes viajan solo por nombre de clase (sin namespace). Los nombres del kit se rechazan en los dos lados: en el mapa, Send y On lanzan una excepción; en Central, el módulo no arranca. Ponles un prefijo (BountyFinished, no Finished).

Guarda el archivo en un ensamblado sin referencias al motor (noEngineReferences: true) para que no se cuele nada exclusivo de Unity, y enlázalo desde el .csproj del módulo. El ejemplo lo guarda en DevKit/Example/Bounties/Shared/BountyBoardMessages.cs, ensamblado Game.Bounties.Shared. Consulta Ensamblados.

#Mandar

// Offline the board just misses this one; the character's own history still has it.
CentralMessages.Send(new BountyFinished { characterId = player.State.id, name = player.characterName, monster = monster.Id });

player.State.id es el id del personaje en la base de datos. Central revisa que este mapa realmente tenga a ese personaje antes de actuar (MapMessage.Hosts), así que un mapa solo puede hablar por sus propios jugadores.

Send devuelve false cuando el mapa no está conectado. No se guarda nada para después: si el dato no se debe perder, guárdalo también en el personaje (PlayerData) y vuelve a mandarlo cuando Online regrese, o diseña el módulo para que acepte un estado completo en lugar de incrementos.

#Recibir

using System.Text;
using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Server;
using UnityEngine;

namespace Game
{
    public static class HuntersBoard
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Register()
        {
            CentralMessages.On<BountyBoardList>(OnBoard);
        }

        static void OnBoard(BountyBoardList board)
        {
            var text = new StringBuilder("Best bounty hunters:");
            int rank = 1;
            foreach (BountyHunter hunter in board.top ?? new BountyHunter[0])
                text.Append($"\n{rank++}. {PlayerText.NoTags(hunter.name)}: {hunter.bounties}");
            if (rank == 1) text.Append("\nNobody yet.");
            text.Append($"\nYou: {board.mine}");
            SocialHub.Notice(board.characterId, text.ToString());
        }
    }
}
  • Una respuesta sobre un personaje lleva su id, y el mapa encuentra al jugador con PlayerCharacter.ServerFind(characterId) o muestra una línea de sistema con SocialHub.Notice(characterId, text). Cualquiera de los dos no hace nada si el personaje se fue mientras tanto.
  • El texto que vino de jugadores (nombres, notas) se muestra con PlayerText.NoTags, para que no pueda abrir etiquetas de texto enriquecido en otras pantallas.
  • Los arreglos pueden llegar null desde el JSON; protégete con ?? new T[0].

#Un ejemplo completo: un evento del mundo en todos los mapas

Un moderador empieza una hora de "oro doble" en todos los mapas. El módulo la guarda y la difunde; cada mapa la aplica a sus propios jugadores.

Mensajes compartidos (en Game.Shared, enlazado por el módulo):

[Serializable]
public class GoldHourStart
{
    public long characterId;   // who asked, so Central can check the map hosts them
    public int minutes;
}

[Serializable]
public class GoldHourState
{
    public long endsUnixSeconds;   // 0 when none
}

Lado del mapa (en Game.Server):

using System;
using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Server;
using UnityEngine;

namespace Game
{
    public static class GoldHour
    {
        static long endsAt;

        public static bool Active => DateTimeOffset.UtcNow.ToUnixTimeSeconds() < endsAt;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void ResetStatics() => endsAt = 0;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Register()
        {
            CentralMessages.On<GoldHourState>(state => endsAt = state.endsUnixSeconds);
            GmCommands.Register(new GmCommand
            {
                name = "goldhour", rank = GmRank.GameMaster, usage = "goldhour minutes", description = "Double gold on every map.",
                run = c =>
                {
                    int minutes = Mathf.Clamp(c.Int(0, 60), 1, 24 * 60);
                    if (!CentralMessages.Send(new GoldHourStart { characterId = c.player.State.id, minutes = minutes }))
                        return "Only online.";
                    return $"Starting a {minutes} minute gold hour everywhere.";
                },
            });
        }
    }
}

Lado de Central (en el módulo, consulta Módulos de servicio):

public void OnMapLink(IMapLink link)
{
    link.On<GoldHourStart>(m =>
    {
        if (!m.Hosts(m.Message.characterId) || m.Message.minutes < 1 || m.Message.minutes > 1440) return Task.CompletedTask;
        long ends = DateTimeOffset.UtcNow.AddMinutes(m.Message.minutes).ToUnixTimeSeconds();
        link.Broadcast(new GoldHourState { endsUnixSeconds = ends });
        return Task.CompletedTask;
    });
}

Tu propio código de recompensas lee GoldHour.Active. Para las tasas de experiencia, botín y oro del kit no necesitas nada de esto: el comando /rates ya empieza eventos de tasas con tiempo que Central reparte a todos los mapas.

El comando de GM ya revisó el nivel en el mapa, y la auditoría lo registró. Un mapa que se une después no sabe del evento; manda el estado a los mapas cuando lo pidan, o guárdalo en el módulo y responde un GoldHourAsk de cada mapa al arrancar.

#Un jugador

CentralMessages.Online es false y Send devuelve false. Decide por función:

  • Solo en línea: díselo al jugador, como hace /hunters ("The hunters board is kept online").
  • Alternativa local: guarda una versión por personaje con PlayerData, como el ejemplo guarda las últimas cacerías de cada personaje.

#Errores comunes

  • Usar CentralMessages desde el ensamblado Game. Vive en KitARPG.Server; el código va en Game.Server.
  • Campos en PascalCase. Las respuestas de Central llegan vacías al mapa.
  • Confiar en un id de personaje en el lado de Central sin m.Hosts(id).
  • Esperar que Send encole. No lo hace; planea para cuando Central no esté.
  • Registrar dos manejadores para un tipo. El segundo reemplaza al primero.
