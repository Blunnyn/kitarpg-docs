DevKit

Fórmulas

Cómo cambiar las cuentas del juego sin tocar el kit: la CombatFormula para daño, curación, velocidad de ataque y experiencia, y la StatFormula para cómo se suman clase, nivel, atributos y equipo en las stats.

#Cómo se instalan las fórmulas

El kit tiene dos objetos de fórmula en GameInstance:

Propiedad Tipo Decide
GameInstance.Combat CombatFormula Daño, pulsos de daño en el tiempo, curaciones, tiempo entre ataques, experiencia por muerte
GameInstance.Formula StatFormula Hojas de stats, puntos de atributo y puntos de skill ganados por nivel

Las dos son clases de C# comunes en KitARPG.Data con métodos virtual. Para cambiar una regla, hereda de una, sobrescribe lo que necesites y asigna una instancia al iniciar:

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
static void Install() => GameInstance.Combat = new MyCombatFormula();

El kit vuelve a poner sus propias fórmulas en SubsystemRegistration en cada Play (consulta Play sin recarga de dominio). BeforeSceneLoad se ejecuta después de eso y antes de cualquier escena, así que nadie pelea antes de que tu fórmula esté puesta.

Dónde va el archivo: en el ensamblado Game, para que cada build la instale. El servidor es quien aplica las fórmulas, pero el cliente también usa Combat.Experience: el bestiario muestra la experiencia que un monstruo le da al jugador local. Una fórmula solo en Game.Server haría que el bestiario no coincidiera con lo que ganan los jugadores.

#CombatFormula

Método Se llama cuando Qué devuelve
Hit Attack(StatSheet attacker, IReadOnlyList<ElementDamage> rolls, StatSheet defender, float scale = 1) Ataques básicos de jugadores y monstruos, y DamageEffect en las skills El golpe: total, crítico, elemento principal
float Element(StatSheet attacker, DamageElement element, float roll, StatSheet defender) Desde Attack y Tick, para la parte de cada elemento El daño de ese elemento después de las resistencias
Hit Tick(StatSheet caster, DamageElement element, float amount, StatSheet holder) Cada pulso de un estado de daño en el tiempo El golpe del pulso, nunca crítico, al menos 1
int Heal(StatSheet healer, float amount) HealEffect y estados de curación La curación final
float AttackInterval(float attacksPerSecond, StatSheet attacker) Cada ataque básico de jugadores y monstruos Segundos hasta el siguiente ataque
long Experience(MonsterData monster, int playerLevel) Una muerte, para quien mató y para cada miembro del grupo que la comparte; el bestiario La experiencia antes de bonificaciones y tasas

#Las reglas del kit

  • Ataque: cada tirada se calcula aparte para su elemento. La tirada (un valor al azar entre su mínimo y su máximo, por scale) más el daño del atacante para ese elemento, aumentado por el poder del atacante. Luego se resta la resistencia fija del defensor a ese elemento y después su resistencia porcentual, con tope en el Max Resistance (maxResistance) del elemento (0,5 cuando la tirada no tiene elemento). Los totales se suman. Un golpe crítico (probabilidad critChance) multiplica el total por 1 + critDamage. El resultado se redondea y es al menos 1.
  • Pulso: la misma regla de elemento con las stats del lanzador tal como estaban cuando cayó el estado; no es crítico.
  • Curación: (amount + healer.healing) * (1 + healer.healingBonus), redondeado.
  • Intervalo de ataque: 1 / (attacksPerSecond * (1 + attackSpeed)), con al menos 0,1 ataques por segundo.
  • Experiencia: la experiencia completa del monstruo hasta 3 niveles por debajo del jugador; luego 20 % menos por cada nivel más abajo, hasta un mínimo de 10 %.

Después de Experience, el kit aplica la stat de ganancia de experiencia del jugador, las tasas del servidor (experienceRate y los eventos de /rates) y el reparto del grupo. Tu fórmula devuelve la cantidad base.

#StatSheet

Lo que son el atacante, el defensor y el que cura:

Miembro Qué es
CharacterStats stats maxHealth, maxMana, healthRegen, manaRegen, power, critChance, critDamage, healing, healingBonus, attackSpeed, moveSpeed, carryWeight, experienceGain, lootChance. Las proporciones son fracciones: critChance 0.05 es 5 %.
ElementStats Element(DamageElement e) El damage, la resistance y el resistancePercent del elemento. Un elemento null lee el predeterminado.
int Attribute(AttributeData a) El total de un atributo.
DamageElement fallback El elemento predeterminado del juego.

#Ejemplo: diferencia de nivel más dura

Los monstruos muy por debajo del jugador no dan nada a partir de 8 niveles:

using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    public class MyCombatFormula : CombatFormula
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
        static void Install() => GameInstance.Combat = new MyCombatFormula();

        public override long Experience(MonsterData monster, int playerLevel)
        {
            int gap = playerLevel - monster.level;
            if (gap >= 8) return 0;
            return base.Experience(monster, playerLevel);
        }
    }
}

#Ejemplo: armadura a partir de un atributo

Una reducción fija a partir de un atributo de tu juego (aquí uno con id toughness), aplicada a cada elemento antes de la resistencia porcentual:

public class ToughnessFormula : CombatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Combat = new ToughnessFormula();

    AttributeData toughness;

    public override float Element(StatSheet attacker, DamageElement element, float roll, StatSheet defender)
    {
        if (toughness == null) GameInstance.Database.TryGet("toughness", out toughness);
        float damage = base.Element(attacker, element, roll, defender);
        int points = toughness != null ? defender.Attribute(toughness) : 0;
        return Mathf.Max(0, damage - points * 0.5f);
    }
}

toughness es un campo de instancia: Install crea una fórmula nueva en cada Play, así que el asset en caché empieza vacío cada vez, aun sin recarga de dominio. Una caché static sobreviviría al Play y guardaría una referencia vieja si la base de datos cambiara entre Plays; reinicia esos estáticos en SubsystemRegistration (consulta Play sin recarga de dominio).

#Ejemplo: probabilidad de crítico y velocidad de ataque con tope

using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using UnityEngine;

public class CappedFormula : CombatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Combat = new CappedFormula();

    public override Hit Attack(StatSheet attacker, IReadOnlyList<ElementDamage> rolls, StatSheet defender, float scale = 1)
    {
        // Capped for this attack only, then put back.
        float chance = attacker.stats.critChance;
        attacker.stats.critChance = Mathf.Min(chance, 0.5f);
        try { return base.Attack(attacker, rolls, defender, scale); }
        finally { attacker.stats.critChance = chance; }
    }

    public override float AttackInterval(float attacksPerSecond, StatSheet attacker) =>
        Mathf.Max(0.25f, base.AttackInterval(attacksPerSecond, attacker));
}

stats es un campo struct de la hoja, así que el cambio se hace y se deshace alrededor de la llamada a la base.

#StatFormula

Método Se llama cuando Devuelve
StatSheet Sheet(CharacterClass characterClass, int level, IReadOnlyList<AttributeAmount> spent, GameDatabase database, IReadOnlyList<IStatSource> sources = null) Cada vez que se calculan las stats de un jugador (PlayerCharacter.RecalculateStats: cambió el nivel, los atributos, el equipo o los buffs), y para personajes nuevos en un jugador La hoja completa
int PointsEarned(CharacterClass characterClass, int level) Subidas de nivel Los puntos de atributo ganados hasta ese nivel
int SkillPointsEarned(CharacterClass characterClass, int level) Totales de puntos de skill Los puntos de skill ganados hasta ese nivel

#El orden del kit

  1. Los atributos de la clase en este nivel, luego los puntos repartidos, luego las bonificaciones de atributo de cada fuente (equipo, buffs, pasivas).
  2. Las stats base de la clase más sus stats por nivel por level - 1.
  3. Las stats Per Point de cada atributo por su total.
  4. Los modificadores de stats de cada fuente. Las bonificaciones porcentuales se aplican al final.

Los valores predeterminados de puntos son el Points Per Level (pointsPerLevel, 5) y el Skill Points Per Level (skillPointsPerLevel, 1) de la clase, por level - 1.

Los monstruos no usan la fórmula de stats; sus stats vienen de sus datos.

#Ejemplo: dos puntos de atributo por nivel

public class MyStatFormula : StatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Formula = new MyStatFormula();

    // Two attribute points per level instead of the class's own number.
    public override int PointsEarned(CharacterClass characterClass, int level) => 2 * (level - 1);
}

#Ejemplo: vida que crece en una proporción por nivel

using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Shared.Characters;
using UnityEngine;

public class GrowingHealthFormula : StatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Formula = new GrowingHealthFormula();

    public override StatSheet Sheet(CharacterClass characterClass, int level, IReadOnlyList<AttributeAmount> spent,
        GameDatabase database, IReadOnlyList<IStatSource> sources = null)
    {
        StatSheet sheet = base.Sheet(characterClass, level, spent, database, sources);
        // +2% max health per level after the first, kept whole.
        sheet.stats.maxHealth = Mathf.Round(sheet.stats.maxHealth * (1 + 0.02f * (level - 1)));
        return sheet;
    }
}

En el kit, las stats son números enteros y las bonificaciones porcentuales son puntos enteros. Redondea lo que agregues, como arriba, para que los tooltips y las hojas coincidan.

#Ejemplo: un punto de skill cada dos niveles

public override int SkillPointsEarned(CharacterClass characterClass, int level) => (level - 1) / 2;

#Cambiar las reglas en un juego en marcha

Las fórmulas deciden números nuevos; no reescriben los guardados. Cambiar PointsEarned cambia lo que se gana de ahora en adelante. Los personajes conservan los puntos que tienen: los puntos libres se guardan y en cada subida de nivel solo se suma la diferencia. Si bajas los puntos por nivel en un juego en marcha, dales a los jugadores una forma de empezar de nuevo (el ResetAttributesAction del kit o el Scroll of Second Thoughts).

#Servidor y cliente

Servidor Cliente
Attack, Element, Tick, Heal, AttackInterval Sí No
Experience Sí El bestiario
Sheet, PointsEarned, SkillPointsEarned Sí No; el dueño recibe la hoja terminada

Online, una fórmula en una build de cliente distinta de la del servidor de mapa solo cambia lo que muestra el bestiario de ese cliente. En un jugador, las dos mitades se ejecutan en un solo proceso.

#Errores comunes

  • Instalar en SubsystemRegistration. El kit reinicia las fórmulas ahí; el orden no está definido.
  • Instalar solo en Game.Server. El bestiario de los clientes muestra entonces los números del kit.
  • Devolver decimales desde Sheet. Redondea lo que agregas.
  • Guardar estado por combatiente en la fórmula. Una sola instancia sirve a todos los combatientes del mapa.
  • Aplicar tasas dentro de Experience. El kit aplica la stat de experiencia y las tasas del servidor después, así que contarían dos veces.
