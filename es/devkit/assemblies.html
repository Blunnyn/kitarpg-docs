Ensamblados

Cómo se divide el código del kit en ensamblados, qué builds llevan cada uno y cómo preparar los ensamblados de tu propio código (Game, Game.Server y Game.Editor).

#Qué es un ensamblado aquí

Unity compila los scripts en ensamblados definidos por archivos .asmdef. Un script pertenece al ensamblado cuyo .asmdef está en su carpeta o en la carpeta padre más cercana. Un ensamblado solo ve los ensamblados que lista en sus referencias.

Los ensamblados del kit no se referencian solos. Los scripts de Assets que no tienen un .asmdef propio (el Assembly-CSharp por defecto) no pueden ver el kit. Es a propósito: tu código tiene su propio ensamblado, lo que mantiene cortos los tiempos de compilación y separa tu código del del kit.

#Los ensamblados del kit

Ensamblado Referencias Restricción de define En qué builds
KitARPG.Shared nada (sin referencias al motor) ninguna Todas. Los servicios .NET compilan los mismos archivos.
KitARPG.Data Shared ninguna Todas
KitARPG.Net Shared, Data, Mirror ninguna Todas
KitARPG.Client Shared, Data, Net, Mirror, UI, TextMeshPro, URP, Input System ninguna Todas (los servidores de mapa lo llevan pero no lo muestran)
KitARPG.Server Shared, Data, Net, Mirror, KCP, AI Navigation UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER Servidores de mapa, un jugador, editor
KitARPG.Local Shared, Data, Net, Server, Client UNITY_EDITOR || KITARPG_SINGLEPLAYER Solo un jugador y editor
KitARPG.Modes.TopDown, KitARPG.Modes.ThirdPerson Shared, Data, Net, Client ninguna Todas
KitARPG.Modes.TopDown.Server, KitARPG.Modes.ThirdPerson.Server Shared, Data, Net, Server, el modo UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER Servidores de mapa, un jugador, editor
KitARPG.Editor todo lo anterior Solo plataforma Editor Nunca en una build

KitARPG.Shared también es el contrato con los servicios: Services/Shared/KitARPG.Shared.csproj compila todos los archivos de Runtime/Shared, así que una clase de mensaje definida ahí se lee igual en Unity y en Central.

#Símbolos de build

Qué ensamblados lleva una build depende de sus scripting define symbols. Los menús de build del kit los ponen por ti.

Símbolo Compila Builds
KITARPG_SERVER (o UNITY_SERVER) KitARPG.Server, todos los KitARPG.Modes.*.Server y todo ensamblado cuyo nombre termina en .Server Servidor de mapa y un jugador
KITARPG_SINGLEPLAYER KitARPG.Local (el guardado local) Solo un jugador
KITARPG_DEV o una development build Herramientas de prueba (inicio automático, prueba de humo, sandbox) Editor y development builds
KITARPG_LOADTEST Bots de prueba de carga Solo builds de prueba de carga; los menús del kit lo agregan y lo quitan

Una build de cliente en línea no tiene ninguno de los símbolos de servidor, así que no lleva nada de código de servidor. Una build de un jugador es cliente y servidor en una, así que tiene KITARPG_SERVER y KITARPG_SINGLEPLAYER.

#La revisión de separación de builds

Antes de cada build, desde cualquier menú o Build Profile, el kit corre BuildSeparation. Lee todos los ensamblados del proyecto, evalúa sus restricciones de define con los símbolos de esa build y detiene la build cuando:

  • un cliente en línea llevaría código de servidor (cualquier ensamblado .Server, KitARPG.Server) o el guardado local,
  • un servidor de mapa llevaría el guardado local,
  • una build de release llevaría herramientas de prueba,
  • a una build de un jugador le faltaría el servidor,
  • un cliente en línea de release se compilaría con Mono en lugar de IL2CPP (su código viajaría como DLL legibles).

Un cliente de desarrollo compilado con Mono recibe una advertencia en su lugar. KitARPG > Check Build Separation muestra qué entra en cada tipo de build. La revisión no se puede apagar. Tus propios ensamblados se revisan igual: un ensamblado llamado Something.Server sin la restricción de define de servidor detiene las builds de cliente en línea.

#Tus ensamblados

Créalos desde Create > KitARPG > Scripts con la carpeta seleccionada en la ventana Project.

Menú Archivo Para
Game Assembly Game.asmdef Todo lo que corre en todas las builds: efectos, condiciones, acciones, objetivos, opciones de NPC, sistemas del jugador, mensajes, ventanas, fórmulas, líneas de menú, ajustes.
Game Server Assembly Game.Server.asmdef Código que solo pueden llevar los servidores de mapa y un jugador: comandos de GM, CentralMessages, todo lo que use KitARPG.Server.
Game Editor Assembly Game.Editor.asmdef Herramientas del editor: páginas de la ventana KitARPG, revisiones del validador, actualizaciones del kit, menús de configuración.

#Game

El menú escribe este archivo:

{
    "name": "Game",
    "rootNamespace": "Game",
    "references": [
        "KitARPG.Shared",
        "KitARPG.Data",
        "KitARPG.Net",
        "KitARPG.Client",
        "Mirror",
        "Unity.TextMeshPro",
        "UnityEngine.UI"
    ],
    "autoReferenced": true
}

rootNamespace es Game, así que los scripts creados con las plantillas en esta carpeta llevan namespace Game. Agrega referencias cuando las necesites: KitARPG.Modes.TopDown para usar las clases de input top-down, Unity.InputSystem para el Input System, Unity.AI.Navigation para los componentes de NavMesh.

#Game.Server

{
    "name": "Game.Server",
    "rootNamespace": "Game",
    "references": [
        "Game",
        "KitARPG.Shared",
        "KitARPG.Data",
        "KitARPG.Net",
        "KitARPG.Server",
        "Mirror"
    ],
    "defineConstraints": [
        "UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER"
    ],
    "autoReferenced": false
}

La restricción de define lo deja fuera de las builds de cliente en línea. Compila en el editor, en los servidores de mapa y en un jugador. Ponlo en su propia carpeta, por ejemplo Assets/Game/Server, para que sus scripts no caigan en Game.

#Game.Editor

{
    "name": "Game.Editor",
    "rootNamespace": "Game",
    "references": [
        "Game",
        "KitARPG.Shared",
        "KitARPG.Data",
        "KitARPG.Net",
        "KitARPG.Editor"
    ],
    "includePlatforms": [ "Editor" ]
}

Unity también trata de forma especial cualquier carpeta llamada Editor, pero con definiciones de ensamblado lo que lo deja fuera de las builds es la línea includePlatforms. Ponlo en Assets/Game/Editor.

#Una organización sugerida

Assets/Game/
    Game.asmdef
    Effects/          skill and item effects
    Logic/            conditions, actions, objectives, NPC options
    Systems/          player systems and network messages
    UI/               windows and menu lines
    Data/             your own ScriptableObject types
    Shared/
        Game.Shared.asmdef   plain C# shared with your Central module

    Editor/

        Checks.cs

#Hacia dónde van las referencias

Game.Server hace referencia a Game, nunca al revés. Los clientes en línea tienen Game pero no Game.Server, así que Game no puede depender de nada que solo tengan los servidores.

Cuando el código de Game necesita pasarle algo a código solo de servidor, lanza un evento en Game y suscríbete desde Game.Server. El ejemplo de recompensas hace exactamente eso:

// In Game.Bounties (every build): raised when a bounty is paid.
public static event Action<PlayerCharacter, MonsterData> ServerTurnedIn;

// In Game.Bounties.Server (server builds): forwards it to Central.
Bounties.ServerTurnedIn += OnTurnedIn;

Lo mismo vale para los tipos de KitARPG.Server como GmCommands y CentralMessages: solo el código de un ensamblado solo de servidor puede usarlos.

#Un ensamblado de C# puro para mensajes

Los mensajes que tus servidores de mapa intercambian con un módulo de Central se compilan dos veces: en Unity y en el módulo .NET. Guárdalos en un ensamblado sin referencias al motor, para que no se cuele nada exclusivo de Unity:

{
    "name": "Game.Shared",
    "rootNamespace": "Game",
    "references": [],
    "noEngineReferences": true,
    "autoReferenced": false
}

Haz referencia a Game.Shared desde Game.Server (y desde Game si el cliente necesita los tipos), y enlaza el mismo archivo .cs desde el .csproj del módulo. Consulta Hablar con Central y Módulos de servicio.

#Varios ensamblados por función

Un juego grande puede separar funciones en sus propios ensamblados, como hace el ejemplo con Game.Bounties, Game.Bounties.Server, Game.Bounties.Shared y Game.Bounties.Editor. Así cada función compila sola y se puede borrar quitando su carpeta. Sigue los mismos nombres: el sufijo .Server y la restricción de define de servidor para las mitades de servidor, includePlatforms: Editor para las mitades de editor.

#Mirror y tus ensamblados

El weaver de Mirror procesa todo ensamblado que hace referencia a Mirror, así que los NetworkBehaviour, [SyncVar], [Command] y structs NetworkMessage de Game funcionan igual que los del kit. De eso salen dos cosas:

  • Versión de red. El kit calcula un hash de todos los campos sincronizados y tipos de mensaje (NetworkVersion), incluidos los tuyos. Un cliente y un servidor de mapa compilados con código distinto dan valores distintos, y el mapa rechaza al cliente con version_mismatch. Vuelve a compilar los dos después de cambiar cualquier cosa que cruce la red.
  • Orden de los componentes. Mirror empareja los NetworkBehaviour por su índice en el objeto. Cliente y servidor deben tener los mismos componentes en el mismo orden en cada prefab en red. Nunca agregues ni quites un NetworkBehaviour en un solo tipo de build.

#Problemas comunes

Síntoma Causa Solución
The type or namespace 'Blunnyn' could not be found El script no está bajo una carpeta con tu ensamblado, así que compila en Assembly-CSharp. Muévelo bajo la carpeta con Game.asmdef, o crea el ensamblado ahí.
No se encuentra GmCommands o CentralMessages El script está en Game, que no hace referencia a KitARPG.Server. Muévelo a la carpeta de Game.Server.
La build de cliente se detiene con un error de separación de builds que nombra tu ensamblado A un ensamblado .Server le falta la restricción de define, o un ensamblado de cliente hace referencia a uno de servidor. Agrega UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER, y haz que la referencia vaya del ensamblado de servidor al de cliente.
Tu clase de plantilla no aparece en el menú de tipos del inspector No compila, es abstracta o no es [Serializable]. Corrige los errores de la Console; deja la clase pública, concreta y [Serializable].
version_mismatch al entrar Cliente y servidor de mapa se compilaron con código distinto. Vuelve a compilar los dos.
