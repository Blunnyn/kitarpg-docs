Assemblies

Esta página aún no está traducida. Se muestra en inglés.

How the kit's code is split into assemblies, which builds carry each one, and how to set up the assemblies for your own code (Game, Game.Server and Game.Editor).

#What an assembly is here

Unity compiles scripts into assemblies defined by .asmdef files. A script belongs to the assembly whose .asmdef sits in its folder or the nearest parent folder. An assembly only sees the assemblies it lists in its references.

The kit's assemblies are not auto-referenced. Scripts in Assets that have no .asmdef of their own (the default Assembly-CSharp) can't see the kit. That is on purpose: your code gets its own assembly, which keeps compile times short and keeps your code apart from the kit's.

#The kit's assemblies

Assembly References Define constraint In which builds
KitARPG.Shared nothing (no engine references) none All. The .NET services compile the same files.
KitARPG.Data Shared none All
KitARPG.Net Shared, Data, Mirror none All
KitARPG.Client Shared, Data, Net, Mirror, UI, TextMeshPro, URP, Input System none All (map servers carry it but don't show it)
KitARPG.Server Shared, Data, Net, Mirror, KCP, AI Navigation UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER Map servers, single player, editor
KitARPG.Local Shared, Data, Net, Server, Client UNITY_EDITOR || KITARPG_SINGLEPLAYER Single player and editor only
KitARPG.Modes.TopDown, KitARPG.Modes.ThirdPerson Shared, Data, Net, Client none All
KitARPG.Modes.TopDown.Server, KitARPG.Modes.ThirdPerson.Server Shared, Data, Net, Server, the mode UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER Map servers, single player, editor
KitARPG.Editor everything above Editor platform only Never in a build

KitARPG.Shared is also the contract with the services: Services/Shared/KitARPG.Shared.csproj compiles every file under Runtime/Shared, so a message class defined there reads the same in Unity and in Central.

#Build symbols

Which assemblies a build carries depends on its scripting define symbols. The kit's build menus set them for you.

Symbol Compiles Builds
KITARPG_SERVER (or UNITY_SERVER) KitARPG.Server, every KitARPG.Modes.*.Server, and every assembly whose name ends in .Server Map server and single player
KITARPG_SINGLEPLAYER KitARPG.Local (the local save) Single player only
KITARPG_DEV or a development build Test tools (auto login, smoke test, sandbox) Editor and development builds
KITARPG_LOADTEST Load test bots Load test builds only; the kit's menus add and remove it

An online client build has none of the server symbols, so it carries no server code at all. A single player build is a client and a server in one, so it has KITARPG_SERVER and KITARPG_SINGLEPLAYER.

#The build separation check

Before every build, from any menu or Build Profile, the kit runs BuildSeparation. It reads every assembly in the project, evaluates its define constraints with that build's symbols, and stops the build when:

  • an online client would carry server code (any .Server assembly, KitARPG.Server) or the local save,
  • a map server would carry the local save,
  • a release build would carry test tools,
  • a single player build would lack the server.

It also warns when a client is built with Mono instead of IL2CPP, or as a development build. KitARPG > Check Build Separation shows what goes into each kind of build. The check can't be turned off. Your own assemblies are checked the same way: an assembly named Something.Server without the server define constraint stops online client builds.

#Your assemblies

Make them from Create > KitARPG > Scripts with the folder selected in the Project window.

Menu File For
Game Assembly Game.asmdef Everything that runs in every build: effects, conditions, actions, objectives, NPC options, player systems, messages, windows, formulas, menu lines, settings.
Game Server Assembly Game.Server.asmdef Code only map servers and single player may carry: GM commands, CentralMessages, anything that uses KitARPG.Server.
Game Editor Assembly Game.Editor.asmdef Editor tools: KitARPG window pages, validator checks, kit updates, setup menus.

#Game

The menu writes this file:

{
    "name": "Game",
    "rootNamespace": "Game",
    "references": [
        "KitARPG.Shared",
        "KitARPG.Data",
        "KitARPG.Net",
        "KitARPG.Client",
        "Mirror",
        "Unity.TextMeshPro",
        "UnityEngine.UI"
    ],
    "autoReferenced": true
}

rootNamespace is Game, so scripts made from the templates in this folder get namespace Game. Add references when you need them: KitARPG.Modes.TopDown to use the top-down input classes, Unity.InputSystem for the Input System, Unity.AI.Navigation for NavMesh components.

#Game.Server

{
    "name": "Game.Server",
    "rootNamespace": "Game",
    "references": [
        "Game",
        "KitARPG.Shared",
        "KitARPG.Data",
        "KitARPG.Net",
        "KitARPG.Server",
        "Mirror"
    ],
    "defineConstraints": [
        "UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER"
    ],
    "autoReferenced": false
}

The define constraint keeps it out of online client builds. It compiles in the editor, in map servers and in single player. Put it in its own folder, for example Assets/Game/Server, so its scripts don't land in Game.

#Game.Editor

{
    "name": "Game.Editor",
    "rootNamespace": "Game",
    "references": [
        "Game",
        "KitARPG.Shared",
        "KitARPG.Data",
        "KitARPG.Net",
        "KitARPG.Editor"
    ],
    "includePlatforms": [ "Editor" ]
}

Unity also treats any folder named Editor specially, but with assembly definitions the includePlatforms line is what keeps it out of builds. Put it in Assets/Game/Editor.

#A suggested layout

Assets/Game/
    Game.asmdef
    Effects/          skill and item effects
    Logic/            conditions, actions, objectives, NPC options
    Systems/          player systems and network messages
    UI/               windows and menu lines
    Data/             your own ScriptableObject types
    Shared/
        Game.Shared.asmdef   plain C# shared with your Central module
        Messages.cs
    Server/
        Game.Server.asmdef
        Commands.cs
        CentralLink.cs
    Editor/
        Game.Editor.asmdef
        Checks.cs
        Updates.cs

#Which way references go

Game.Server references Game, never the other way around. Online clients have Game but not Game.Server, so Game can't depend on anything that only servers have.

When code in Game needs to hand something to server-only code, raise an event in Game and subscribe from Game.Server. The bounty example does exactly this:

// In Game.Bounties (every build): raised when a bounty is paid.
public static event Action<PlayerCharacter, MonsterData> ServerTurnedIn;

// In Game.Bounties.Server (server builds): forwards it to Central.
Bounties.ServerTurnedIn += OnTurnedIn;

The same applies to KitARPG.Server types such as GmCommands and CentralMessages: only code in a server-only assembly can use them.

#A plain C# assembly for messages

Messages your map servers exchange with a Central module are compiled twice: by Unity and by the .NET module. Keep them in an assembly with no engine references, so nothing Unity-only slips in:

{
    "name": "Game.Shared",
    "rootNamespace": "Game",
    "references": [],
    "noEngineReferences": true,
    "autoReferenced": false
}

Reference Game.Shared from Game.Server (and from Game if the client needs the types), and link the same .cs file from the module's .csproj. See Talking to Central and Service modules.

#Several feature assemblies

A large game can split features into their own assemblies, the way the example does with Game.Bounties, Game.Bounties.Server, Game.Bounties.Shared and Game.Bounties.Editor. Each feature then compiles alone and can be deleted by removing its folder. Follow the same naming: a .Server suffix and the server define constraint for server halves, includePlatforms: Editor for editor halves.

#Mirror and your assemblies

Mirror's weaver processes every assembly that references Mirror, so NetworkBehaviours, [SyncVar]s, [Command]s and NetworkMessage structs in Game work like the kit's own. Two things follow from it:

  • Network version. The kit hashes every synced field and message type (NetworkVersion), yours included. A client and a map server built from different code get different values, and the map refuses the client with version_mismatch. Rebuild both after changing anything that crosses the network.
  • Component order. Mirror matches NetworkBehaviours by their index on the object. Client and server must have the same components in the same order on every networked prefab. Never add or remove a NetworkBehaviour only in one kind of build.

#Common problems

Symptom Cause Fix
The type or namespace 'Blunnyn' could not be found The script is not under a folder with your assembly, so it compiles in Assembly-CSharp. Move it under the folder with Game.asmdef, or make the assembly there.
GmCommands or CentralMessages not found The script is in Game, which doesn't reference KitARPG.Server. Move it to the Game.Server folder.
The client build stops with a build separation error naming your assembly A .Server assembly lacks the define constraint, or a client assembly references a server one. Add UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER, and make the reference go from the server assembly to the client one.
Your template class doesn't show in the inspector's type menu It doesn't compile, it is abstract, or it isn't [Serializable]. Fix the Console errors; keep the class public, concrete and [Serializable].
version_mismatch when joining Client and map server were built from different code. Rebuild both.
