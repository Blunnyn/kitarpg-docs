Actualizaciones del kit en código

Cómo llevar cambios a juegos que ya se hicieron con tu paquete o plantilla: la clase KitUpdate, cómo Overview encuentra y aplica actualizaciones, y ejemplos completos que agregan un componente a cada prefab de jugador y un ajuste al juego.

#Qué es una actualización del kit

Cuando una versión nueva de KitARPG agrega algo que un juego necesita (una moneda, un componente en el jugador, una ventana en el HUD), no puede rearmar los prefabs y datos del comprador: borraría sus cambios. En su lugar trae una actualización: una clase pequeña que revisa si eso falta y, cuando se le pide, agrega solo eso.

Tú puedes hacer lo mismo. Si vendes o reutilizas un paquete hecho sobre KitARPG (un juego plantilla, un módulo que compartes entre tus proyectos), cada versión tuya puede traer actualizaciones para los juegos que ya se hicieron con él. Aparecen en la misma lista que las del kit.

Dónde va el archivo: en un ensamblado Game.Editor (o en el ensamblado de editor de tu paquete).

#Dónde aparecen las actualizaciones

  • Overview en la ventana KitARPG muestra cuántas actualizaciones esperan, con Apply.
  • Project Check lista cada una como advertencia con un botón Apply.
  • Play & Servers y la página Shop avisan cuando hay actualizaciones pendientes.

Apply abre un diálogo que lista cada actualización pendiente con su Title y sus Changes, seguido de "Nothing else changes". Al confirmar, cada actualización que todavía haga falta se ejecuta según Order. Las actualizaciones no se pueden aplicar durante Play.

#La clase KitUpdate

KitUpdate vive en Blunnyn.KitARPG.Editor. Cada subclase no abstracta con un constructor sin parámetros se encuentra con el TypeCache de Unity.

Miembro Qué hace Por defecto
abstract string Title Una línea, como "Shop window in the HUD".
abstract string Changes Exactamente lo que cambiará Apply, mostrado antes de que se ejecute. Nombra los assets y los campos.
abstract bool Needed() Verdadero cuando al proyecto le falta. Las ventanas lo llaman cada pocos segundos (la respuesta se guarda en caché unos dos segundos), así que debe ser barato.
abstract string Apply() Hace el cambio y devuelve lo que hizo. Lanza una excepción para avisar que no pudo.
virtual int Order Los más bajos van primero, para actualizaciones que dependen de otra. El kit usa de 10 a 80. 100

KitUpdates las ejecuta:

Miembro Qué hace
KitUpdates.All Todas las actualizaciones, en orden.
KitUpdates.Pending() Las actualizaciones cuyo Needed() es verdadero ahora.
KitUpdates.Run(update, out string result) Ejecuta una, guarda los assets y registra el resultado en el log. Falso cuando lanzó una excepción.
KitUpdates.ApplyAll(updates) Pregunta una vez con la lista y luego ejecuta las que todavía hagan falta.

Una excepción en Needed() se registra como advertencia y la actualización se trata como no necesaria.

#Reglas para una buena actualización

  • Agrega solo lo que falta. Revisa la cosa exacta (un componente, el valor de un campo, un asset) y agrega solo eso.
  • Nunca rearmes. No vuelvas a crear un prefab, un HUD ni un asset de datos; cárgalo, cambia una cosa y guárdalo.
  • Encuentra las cosas como las tiene el juego. Los compradores renombran y mueven assets. Búscalos a través de GameInstance y la base de datos del juego (ModulesWindow.Find()), no por ruta.
  • Sé idempotente. Después de Apply, Needed() debe devolver falso. Ejecutarla dos veces no debe cambiar nada la segunda vez.
  • Di qué cambió. Changes antes, el texto devuelto después.

#Ejemplo: la plantilla

Create > KitARPG > Scripts > Kit Update (Editor) agrega una palabra al filtro del chat:

using System.Linq;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Editor;
using UnityEditor;

namespace Game
{
    /// <summary>
    /// Something your own package adds to games already made with it. It shows in Overview with Apply
    /// next to the kit's updates. Only add what is missing; never rebuild what the game changed.
    /// </summary>
    public class MyGameUpdate : KitUpdate
    {
        const string Word = "badword";

        public override string Title => "My game: chat filter word";
        public override string Changes => $"Game Settings > Chat: adds \"{Word}\" to the blocked words.";

        public override bool Needed()
        {
            GameInstance game = ModulesWindow.Find();
            return game != null && !game.blockedWords.Contains(Word);
        }

        public override string Apply()
        {
            GameInstance game = ModulesWindow.Find();
            game.blockedWords = game.blockedWords.Append(Word).ToArray();
            EditorUtility.SetDirty(game);
            AssetDatabase.SaveAssets();
            return $"Added \"{Word}\" to the blocked words.";
        }
    }
}

#Ejemplo: agregar un sistema del jugador a cada modelo de jugador

Un componente tuyo (consulta Sistemas del jugador) debe estar en cada prefab de modelo de jugador, incluidos los modelos que el comprador haga después. Esta actualización encuentra los modelos desde la base de datos del juego y lo agrega donde falta:

using System.Collections.Generic;
using System.Linq;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Editor;
using UnityEditor;
using UnityEngine;

namespace Game
{
    public class AddReputationUpdate : KitUpdate
    {
        public override string Title => "Reputation on every player model";

        public override string Changes =>
            "Adds the Player Reputation component to each player model prefab that doesn't have it: "
            + string.Join(", ", Missing().Select(m => m.name)) + ". Nothing else on the prefabs changes.";

        public override int Order => 200;

        static IEnumerable<GameObject> Missing()
        {
            GameInstance game = ModulesWindow.Find();
            if (game == null || game.database == null) return Enumerable.Empty<GameObject>();
            return game.database.playerModels.Where(m => m != null && m.GetComponent<PlayerReputation>() == null);
        }

        public override bool Needed() => Missing().Any();

        public override string Apply()
        {
            var done = new List<string>();
            foreach (GameObject model in Missing().ToList())
            {
                string path = AssetDatabase.GetAssetPath(model);
                GameObject root = PrefabUtility.LoadPrefabContents(path);
                try
                {
                    if (root.GetComponent<PlayerReputation>() == null) root.AddComponent<PlayerReputation>();
                    PrefabUtility.SaveAsPrefabAsset(root, path);
                    done.Add(model.name);
                }
                finally { PrefabUtility.UnloadPrefabContents(root); }
            }
            return done.Count == 0 ? "Every model already had it." : "Added to " + string.Join(", ", done) + ".";
        }
    }
}

LoadPrefabContents y SaveAsPrefabAsset editan el asset del prefab en sí, igual que las actualizaciones del propio kit. Como Mirror necesita los mismos componentes en el cliente y en el servidor, vuelve a compilar los dos después de aplicarla.

#Ejemplo: agregar una ventana bajo el HUD

Las actualizaciones del kit que agregan ventanas al HUD cargan el prefab del HUD desde GameInstance.hudPrefab, buscan el grupo al que pertenecen, agregan su objeto y guardan. La misma forma para una ventana tuya:

using System.Linq;
using Blunnyn.KitARPG.Editor;
using UnityEditor;
using UnityEngine;

public class AddReputationWindowUpdate : KitUpdate
{
    public override string Title => "Reputation window in the HUD";

    public override string Changes => "Adds a Reputation Window object under Windows in the HUD prefab.";

    static GameObject Hud => ModulesWindow.Find()?.hudPrefab;

    public override bool Needed()
    {
        GameObject hud = Hud;
        return hud != null && hud.GetComponentInChildren<ReputationWindow>(true) == null;
    }

    public override string Apply()
    {
        GameObject hud = Hud ?? throw new System.InvalidOperationException("The GameInstance has no HUD prefab.");
        string path = AssetDatabase.GetAssetPath(hud);
        GameObject root = PrefabUtility.LoadPrefabContents(path);
        try
        {
            if (root.GetComponentInChildren<ReputationWindow>(true) != null) return "The HUD already had it.";
            Transform windows = root.GetComponentsInChildren<Transform>(true).FirstOrDefault(t => t.name == "Windows") ?? root.transform;
            var go = new GameObject("Reputation Window", typeof(RectTransform));
            go.transform.SetParent(windows, false);
            go.AddComponent<ReputationWindow>();
            PrefabUtility.SaveAsPrefabAsset(root, path);
            return $"Added the window to {hud.name}.";
        }
        finally { PrefabUtility.UnloadPrefabContents(root); }
    }
}

(ReputationWindow representa un componente de ventana tuyo.) Busca los grupos del HUD por nombre con una alternativa, ya que los compradores pueden reorganizar su HUD. La estructura del HUD se describe en HUD y ventanas.

#Ejemplo: agregar un asset de datos del juego

Algunas actualizaciones agregan contenido: una moneda, un ítem que necesita la función nueva. Crea el asset junto a la base de datos del juego y agrégalo a su lista:

using System.Linq;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Editor;
using UnityEditor;
using UnityEngine;

public class AddTokenCurrencyUpdate : KitUpdate
{
    public override string Title => "Arena Token currency";
    public override string Changes => "Creates the Arena Token currency next to the game database and lists it under Currencies.";

    static GameDatabase Database => ModulesWindow.Find()?.database;

    public override bool Needed()
    {
        GameDatabase db = Database;
        return db != null && !db.TryGet("arena_token", out CurrencyData _);
    }

    public override string Apply()
    {
        GameDatabase db = Database ?? throw new System.InvalidOperationException("No game database.");
        string folder = System.IO.Path.GetDirectoryName(AssetDatabase.GetAssetPath(db));
        var token = ScriptableObject.CreateInstance<CurrencyData>();
        token.name = "Arena Token";
        AssetDatabase.CreateAsset(token, AssetDatabase.GenerateUniqueAssetPath($"{folder}/Arena Token.asset"));
        // GameData ids are made from the name when empty.
        var so = new SerializedObject(token);
        so.FindProperty("id").stringValue = "arena_token";
        so.ApplyModifiedPropertiesWithoutUndo();
        db.currencies = db.currencies.Append(token).ToArray();
        EditorUtility.SetDirty(db);
        return "Created Arena Token and added it to the database.";
    }
}

El id se pone con SerializedObject porque GameData.id es un campo serializado privado. Elige el id una sola vez; los guardados lo almacenan.

#Actualizaciones y Start over

Las actualizaciones son para juegos que conservan su contenido. Start over en Overview arma en cambio la muestra Starter desde cero y pierde los cambios hechos a la muestra. Tus actualizaciones también deben funcionar en una muestra recién creada: después de Start over, Needed() vuelve a decidir.

#Errores comunes

  • Un Needed() que carga cada prefab del proyecto. Se ejecuta cada pocos segundos. Usa las listas de la base de datos.
  • Rearmar en lugar de agregar. Se pierden los cambios del comprador.
  • Rutas a los assets. Los compradores los mueven y renombran.
  • Needed() sigue siendo verdadero después de Apply. La actualización aparece para siempre.
  • Código de editor en un ensamblado de ejecución. Las actualizaciones viven en un ensamblado de editor.
