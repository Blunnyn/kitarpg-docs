Quest objectives

Esta página aún no está traducida. Se muestra en inglés.

How to add a new kind of quest goal: the QuestObjective base class, the two ways an objective can count (events or current state), how to advance it with PlayerQuests.ServerAdvance, and complete examples.

#What an objective is

A quest has a list of objectives (QuestData.objectives). Each has a text, an optional hint, and a number it must reach. The kit ships five kinds:

Kind Counts How
KillObjective Kills of one monster, or any Event: Monster.ServerKilled, shared with party members nearby
CollectObjective Items in the bag State: reads the bag; can take them on turn in
TalkObjective Talking to an NPC by id Event: the NPC conversation
ExploreObjective Reaching a point or a zone Polled every Explore Interval (exploreInterval, 0.5 s)
TriggerObjective Setting off a world trigger Event: WorldTrigger

A new kind is a class plus a piece of server code that advances it. Objectives are [Serializable] and held with [SerializeReference, PickType], so yours shows in the + menu of every quest's Objectives in the Game Database.

Where the files go: the Game assembly. The quest log on the client reads the objective's text and icon.

#The base class

QuestObjective lives in Blunnyn.KitARPG.Data.

Member What it does Default
string text Inspector field: shown in the quest log. Empty uses DefaultText. empty
string hint Inspector field: unfolds under the objective in the quest log. empty
string Text text or DefaultText.
abstract string DefaultText { get; } Your default text, like "Slay Slimes". Required.
virtual int Required The count to reach. 1
virtual Sprite Icon Icon in the quest log. null
virtual int Current(IPlayerFacts holder) For state-based objectives: the count right now. Return -1 for objectives counted by events. -1
virtual void Visit(Action<GameData> visit) Hand over every asset the objective points at. Nothing

#Two ways to count

#Counted by events

Most objectives count things as they happen. The quest keeps a counter per objective, saved with the character. Your code calls ServerAdvance when the thing happens:

// PlayerQuests, server only.
public void ServerAdvance<T>(Predicate<T> match, int amount = 1) where T : QuestObjective

It walks every active quest of that player, finds objectives of type T for which match returns true and that aren't full yet, adds amount (capped at Required), shows "Objective 2/5" over the player's head, says "ready to turn in" when the quest is done, and syncs the log to the owner.

#Read from the current state

Override Current to return the count from what the character has now, as CollectObjective does with the bag. The quest reads it:

  • when the quest is accepted,
  • every time the player's bag or gear changes (PlayerInventory.ServerChanged),
  • when the player tries to turn the quest in (the final check).

Current overrides the stored counter. If the count can go down (items sold), the objective goes down too.

Nota

Outside bag changes, nothing refreshes a state-based count in the quest log. A Current that reads the level, for example, shows the old number until the bag changes, although turning in works as soon as the level is reached. For state that changes without bag changes, count by events instead.

#Example: the template

Create > KitARPG > Scripts > Quest Objective makes an objective and a counter that advances it on every level up. See Templates, and move its subscription to AfterAssembliesLoaded as noted there.

#Example: win duels

Counts duels the player wins. PlayerPvp.ServerDefeated gives the killer, the victim and whether it was a duel.

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class WinDuelsObjective : QuestObjective
    {
        public int count = 3;
        [Tooltip("Only opponents at this level or above count. 0 counts anyone.")]
        public int minOpponentLevel;

        protected override string DefaultText => "Win duels";

        public override int Required => Mathf.Max(1, count);

        public bool Counts(PlayerCharacter opponent) => minOpponentLevel <= 0 || opponent.level >= minOpponentLevel;
    }

    public static class WinDuelsCounter
    {
        // After the kit cleared its events in SubsystemRegistration.
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
        static void Hook()
        {
            PlayerPvp.ServerDefeated -= OnDefeated;
            PlayerPvp.ServerDefeated += OnDefeated;
        }

        static void OnDefeated(PlayerCharacter winner, PlayerCharacter loser, bool duel)
        {
            if (!duel || winner == null || loser == null) return;
            if (winner.TryGetComponent(out PlayerQuests quests))
                quests.ServerAdvance<WinDuelsObjective>(o => o.Counts(loser));
        }
    }
}

#Example: upgrade gear at the forge

PlayerForge.ServerUpgraded gives the player, the item id, whether the step worked and the level it ended at.

[Serializable]
public class UpgradeObjective : QuestObjective
{
    [Tooltip("Upgrades that reach this level or more count.")]
    public int toLevel = 3;
    public int count = 1;

    protected override string DefaultText => $"Upgrade gear to +{toLevel}";

    public override int Required => Mathf.Max(1, count);
}

public static class UpgradeCounter
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
    static void Hook()
    {
        PlayerForge.ServerUpgraded -= OnUpgraded;
        PlayerForge.ServerUpgraded += OnUpgraded;
    }

    static void OnUpgraded(PlayerCharacter player, string itemId, bool success, int level)
    {
        if (success && player.TryGetComponent(out PlayerQuests quests))
            quests.ServerAdvance<UpgradeObjective>(o => level >= o.toLevel);
    }
}

#Example: carry gold (state-based)

Reads the purse. It refreshes whenever the bag changes, and the turn in checks it again.

[Serializable]
public class GoldObjective : QuestObjective
{
    public long gold = 1000;

    protected override string DefaultText => $"Gather {gold:N0} gold";

    // Counts are whole numbers; a large target is shown as one step.
    public override int Required => 1;

    public override int Current(IPlayerFacts holder) => holder.Balance(null) >= gold ? 1 : 0;
}

The refresh comes from PlayerInventory.ServerChanged, raised when the bag or gear is published. Gold changing alone doesn't raise it, so the log may show 0 until the next bag change, although turning in works. Prefer this pattern for items. For currencies, an event-based objective advanced from your own code is more reliable.

#Example: an objective advanced from your own feature

Any server code can advance objectives. The bounty example could count paid bounties toward a quest:

[Serializable]
public class BountiesObjective : QuestObjective
{
    public MonsterData monster;
    public int count = 3;

    protected override string DefaultText => monster != null ? $"Finish {monster.DisplayName} bounties" : "Finish bounties";
    public override int Required => Mathf.Max(1, count);
    public override Sprite Icon => monster != null ? monster.Icon : null;
    public override void Visit(Action<GameData> visit) => visit(monster);
}

// Wherever a bounty is paid, on the server:
if (player.TryGetComponent(out PlayerQuests quests))
    quests.ServerAdvance<BountiesObjective>(o => o.monster == null || o.monster == paidFor);

#Server and client

Runs on
ServerAdvance, your counter Server only
Current Server (the count that matters)
Text, hint, Icon, Required Client, in the quest log and tracker

The counts reach the owner through PlayerQuests.active, a synced list. Saving is automatic: counters are part of the quest progress saved with the character, in single player and online.

#Quest events you can use

Event When
PlayerQuests.ServerCompleted (PlayerCharacter, QuestData) A quest was turned in. Server.
PlayerQuests.Shown (Npc, QuestData) The owner's client was shown a quest by an NPC.
PlayerQuests.Changed (instance event) The owner's quest list changed. Client.

PlayerQuests server methods are virtual (ServerAccept, ServerTurnIn, ServerAbandon, ServerFinishObjectives, ServerForget, ServerTalked, ServerLoad) if you need to change the flow itself. See Overriding kit behaviour.

#Common mistakes

  • Subscribing in SubsystemRegistration. The kit clears its events there; the order is undefined. Use AfterAssembliesLoaded.
  • Advancing from the client. ServerAdvance is server only; a client request must be checked and turned into progress by server code.
  • Matching too broadly. ServerAdvance<T>(o => true) advances every objective of that type in every active quest. Put the rule in the predicate.
  • Keeping per-player counts in the objective's fields. The quest holds the counters. Fields are designer settings shared by every player.
