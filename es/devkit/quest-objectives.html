Objetivos de misión

Cómo agregar un tipo nuevo de objetivo de misión: la clase base QuestObjective, las dos formas en que un objetivo puede contar (eventos o estado actual), cómo avanzarlo con PlayerQuests.ServerAdvance, y ejemplos completos.

#Qué es un objetivo

Una misión tiene una lista de objetivos (QuestData.objectives). Cada uno tiene un texto, una pista opcional y un número que debe alcanzar. El kit trae cinco tipos:

Tipo Cuenta Cómo
KillObjective Muertes de un monstruo, o de cualquiera Evento: Monster.ServerKilled, compartido con los miembros del grupo cercanos
CollectObjective Ítems en la bolsa Estado: lee la bolsa; puede quitarlos al entregar la misión
TalkObjective Hablar con un NPC por id Evento: la conversación con el NPC
ExploreObjective Llegar a un punto o a una zona Se consulta cada Explore Interval (exploreInterval, 0,5 s)
TriggerObjective Activar un disparador del mundo Evento: WorldTrigger

Un tipo nuevo es una clase más un trozo de código de servidor que la hace avanzar. Los objetivos son [Serializable] y se guardan con [SerializeReference, PickType], así que el tuyo aparece en el menú + de Objectives de cada misión en la Game Database.

Dónde van los archivos: en el ensamblado Game. El registro de misiones del cliente lee el texto y el ícono del objetivo.

#La clase base

QuestObjective vive en Blunnyn.KitARPG.Data.

Miembro Qué hace Por defecto
string text Campo del inspector: se muestra en el registro de misiones. Si está vacío se usa DefaultText. vacío
string hint Campo del inspector: se despliega bajo el objetivo en el registro de misiones. vacío
string Text text o DefaultText.
protected abstract string DefaultText { get; } Tu texto predeterminado, como "Slay Slimes". Obligatorio.
virtual int Required La cantidad a alcanzar. 1
virtual Sprite Icon Ícono en el registro de misiones. null
virtual int Current(IPlayerFacts holder) Para objetivos basados en el estado: la cantidad en este momento. Devuelve -1 para objetivos que se cuentan por eventos. -1
virtual void Visit(Action<GameData> visit) Entrega cada asset al que apunta el objetivo. Nada

#Dos formas de contar

#Por eventos

La mayoría de los objetivos cuentan las cosas a medida que pasan. La misión guarda un contador por objetivo, que se guarda con el personaje. Tu código llama a ServerAdvance cuando pasa la cosa:

// PlayerQuests, server only.
public void ServerAdvance<T>(Predicate<T> match, int amount = 1) where T : QuestObjective

Recorre cada misión activa de ese jugador, busca los objetivos de tipo T para los que match devuelve verdadero y que todavía no están completos, suma amount (con tope en Required), muestra "Objective 2/5" sobre la cabeza del jugador, dice "ready to turn in" cuando la misión está lista, y sincroniza el registro con el dueño.

#Leídos del estado actual

Sobrescribe Current para devolver la cantidad a partir de lo que el personaje tiene ahora, como hace CollectObjective con la bolsa. La misión lo lee:

  • cuando se acepta la misión,
  • cada vez que cambia la bolsa o el equipo del jugador (PlayerInventory.ServerChanged),
  • cuando el jugador intenta entregar la misión (la revisión final).

Current reemplaza al contador guardado. Si la cantidad puede bajar (ítems vendidos), el objetivo también baja.

Nota

Fuera de los cambios de la bolsa, nada actualiza en el registro de misiones una cantidad basada en el estado. Un Current que lee el nivel, por ejemplo, muestra el número viejo hasta que cambia la bolsa, aunque la entrega funciona apenas se alcanza el nivel. Para estado que cambia sin cambios en la bolsa, cuenta por eventos.

#Ejemplo: la plantilla

Create > KitARPG > Scripts > Quest Objective crea un objetivo y un contador que lo hace avanzar en cada subida de nivel. Consulta Plantillas.

#Ejemplo: ganar duelos

Cuenta los duelos que gana el jugador. PlayerPvp.ServerDefeated da el ganador, la víctima y si fue un duelo.

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class WinDuelsObjective : QuestObjective
    {
        public int count = 3;
        [Tooltip("Only opponents at this level or above count. 0 counts anyone.")]
        public int minOpponentLevel;

        protected override string DefaultText => "Win duels";

        public override int Required => Mathf.Max(1, count);

        public bool Counts(PlayerCharacter opponent) => minOpponentLevel <= 0 || opponent.level >= minOpponentLevel;
    }

    public static class WinDuelsCounter
    {
        // After the kit cleared its events in SubsystemRegistration.
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
        static void Hook()
        {
            PlayerPvp.ServerDefeated -= OnDefeated;
            PlayerPvp.ServerDefeated += OnDefeated;
        }

        static void OnDefeated(PlayerCharacter winner, PlayerCharacter loser, bool duel)
        {
            if (!duel || winner == null || loser == null) return;
            if (winner.TryGetComponent(out PlayerQuests quests))
                quests.ServerAdvance<WinDuelsObjective>(o => o.Counts(loser));
        }
    }
}

#Ejemplo: mejorar equipo en la forja

PlayerForge.ServerUpgraded da el jugador, el id del ítem, si el paso funcionó y el nivel en que quedó.

[Serializable]
public class UpgradeObjective : QuestObjective
{
    [Tooltip("Upgrades that reach this level or more count.")]
    public int toLevel = 3;
    public int count = 1;

    protected override string DefaultText => $"Upgrade gear to +{toLevel}";

    public override int Required => Mathf.Max(1, count);
}

public static class UpgradeCounter
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
    static void Hook()
    {
        PlayerForge.ServerUpgraded -= OnUpgraded;
        PlayerForge.ServerUpgraded += OnUpgraded;
    }

    static void OnUpgraded(PlayerCharacter player, string itemId, bool success, int level)
    {
        if (success && player.TryGetComponent(out PlayerQuests quests))
            quests.ServerAdvance<UpgradeObjective>(o => level >= o.toLevel);
    }
}

#Ejemplo: llevar oro (basado en el estado)

Lee el monedero. Se actualiza cada vez que cambia la bolsa, y la entrega lo vuelve a revisar.

[Serializable]
public class GoldObjective : QuestObjective
{
    public long gold = 1000;

    protected override string DefaultText => $"Gather {gold:N0} gold";

    // Counts are whole numbers; a large target is shown as one step.
    public override int Required => 1;

    public override int Current(IPlayerFacts holder) => holder.Balance(null) >= gold ? 1 : 0;
}

La actualización viene de PlayerInventory.ServerChanged, que se lanza cuando se publica la bolsa o el equipo. Un cambio solo de oro no lo lanza, así que el registro puede mostrar 0 hasta el siguiente cambio de la bolsa, aunque la entrega funciona. Prefiere este patrón para ítems. Para monedas, un objetivo basado en eventos que avanza desde tu propio código es más confiable.

#Ejemplo: un objetivo que avanza desde una función tuya

Cualquier código de servidor puede hacer avanzar objetivos. El ejemplo de recompensas podría contar las recompensas pagadas para una misión:

[Serializable]
public class BountiesObjective : QuestObjective
{
    public MonsterData monster;
    public int count = 3;

    protected override string DefaultText => monster != null ? $"Finish {monster.DisplayName} bounties" : "Finish bounties";
    public override int Required => Mathf.Max(1, count);
    public override Sprite Icon => monster != null ? monster.Icon : null;
    public override void Visit(Action<GameData> visit) => visit(monster);
}

// Wherever a bounty is paid, on the server:
if (player.TryGetComponent(out PlayerQuests quests))
    quests.ServerAdvance<BountiesObjective>(o => o.monster == null || o.monster == paidFor);

#Servidor y cliente

Se ejecuta en
ServerAdvance, tu contador Solo servidor
Current Servidor (la cantidad que importa)
Text, hint, Icon, Required Cliente, en el registro de misiones y el seguimiento

Las cantidades llegan al dueño mediante PlayerQuests.active, una lista sincronizada. El guardado es automático: los contadores son parte del progreso de la misión que se guarda con el personaje, en un jugador y online.

#Eventos de misiones que puedes usar

Evento Cuándo
PlayerQuests.ServerCompleted (PlayerCharacter, QuestData) Se entregó una misión. Servidor.
PlayerQuests.Shown (Npc, QuestData) Un NPC le mostró una misión al cliente del dueño.
PlayerQuests.Changed (evento de instancia) Cambió la lista de misiones del dueño. Cliente.

Los métodos de servidor de PlayerQuests son virtual (ServerAccept, ServerTurnIn, ServerAbandon, ServerFinishObjectives, ServerForget, ServerTalked, ServerLoad) por si necesitas cambiar el flujo en sí. Consulta Cambiar el comportamiento del kit.

#Errores comunes

  • Suscribirse en SubsystemRegistration. El kit vacía sus eventos ahí; el orden no está definido. Usa AfterAssembliesLoaded.
  • Avanzar desde el cliente. ServerAdvance es solo de servidor; un pedido del cliente lo tiene que revisar el código del servidor y convertirlo en progreso.
  • Coincidencias demasiado amplias. ServerAdvance<T>(o => true) hace avanzar todos los objetivos de ese tipo en todas las misiones activas. Pon la regla en el predicado.
  • Guardar cantidades por jugador en los campos del objetivo. La misión tiene los contadores. Los campos son ajustes del diseñador que comparten todos los jugadores.
