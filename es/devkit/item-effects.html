Efectos de ítems

Cómo escribir tus propios efectos para ítems consumibles: la clase base ItemEffect, la interfaz IItemUser con la que trabaja, cómo fluye el uso de un ítem en el servidor y ejemplos completos.

#Qué es un efecto de ítem

Un consumible (ConsumableData: pociones, pergaminos, comida) recupera vida y maná con sus propios campos y luego ejecuta una lista de efectos (ConsumableData.effects). El kit trae efectos para experiencia, niveles, aprender skills, puntos de atributo y de skill, reiniciar atributos, lanzar una skill, agregar un estado y viajar. Cualquier otra cosa que deba hacer un ítem es una clase de efecto nueva.

Los efectos son clases [Serializable] guardadas por referencia con [SerializeReference, PickType]. Cuando la tuya compila, aparece en el menú de tipos + de Effects en cada Consumable de KitARPG > Game Database > Items.

Dónde va el archivo: en el ensamblado Game. Los tooltips del cliente también leen el efecto.

#La clase base

ItemEffect vive en Blunnyn.KitARPG.Data.

Miembro Qué hace Por defecto
string Summary Texto corto en el editor de ítems y la línea predeterminada del tooltip. El nombre de la clase
string Check(IItemUser user) Servidor. Por qué este usuario no puede usarlo ahora, o null. Se revisan todos los efectos del ítem antes de que se ejecute alguno. null
void Use(IItemUser user, ItemData item) Servidor. Aplica el efecto. item es lo que se usó, para devolverlo si algo falla después. Obligatorio.
void Describe(ItemDescription description, IItemUser viewer) Líneas para el tooltip del ítem. viewer puede ser null (un tooltip en el editor, o del ítem de otro jugador). Agrega Summary
void Visit(Action<GameData> visit) Le pasa a la base de datos del juego cada asset al que apunta el efecto. Nada

#Qué pasa cuando un jugador usa un ítem

  1. El cliente del dueño lo pide (PlayerInventory.Use(slot), desde la bolsa, el menú del ítem o una casilla de la barra rápida).
  2. En el servidor, PlayerInventory revisa su propio ritmo, que la casilla tenga un ítem y que el ítem sea usable (IUsable).
  3. Revisa el tiempo de espera del Cooldown Group del ítem (cooldownGroup, por defecto potion).
  4. Llama a ConsumableData.CheckUse(player): los jugadores muertos no pueden usar ítems; luego se ejecuta el Check de cada efecto en orden y la primera respuesta que no sea null detiene todo. Esa respuesta se muestra sobre la cabeza del jugador.
  5. Un consumible sin efectos solo se puede usar mientras recupere algo.
  6. ConsumableData.Use recupera vida y maná, y luego llama al Use de cada efecto en orden.
  7. Empieza el tiempo de espera y se quita un ítem de la pila.

Como todos los Check se ejecutan antes de cualquier Use, un ítem con tres efectos hace los tres o ninguno. Pon cada motivo para rechazar en Check. Una vez que se ejecuta Use, el ítem ya se gastó.

#IItemUser

El jugador tal como lo ven los ítems. En el servidor es el PlayerCharacter; en el cliente, los tooltips reciben al jugador local.

Miembro Qué hace Dónde
CharacterClass Class, int Level Clase y nivel. Ambos
IReadOnlyList<string> WornItemIds Id del ítem en cada posición de equipo, vacío donde no hay nada puesto. Ambos
bool IsDead, int Health, int MaxHealth, int Mana, int MaxMana Estado actual. Ambos
void RestoreHealth(int), void RestoreMana(int) Recupera. Servidor
long ExperienceToNext Experiencia que aún falta, 0 en el nivel máximo. Ambos
void GainExperience(long) Suma experiencia, con subidas de nivel. Servidor
void GainLevel() Sube un nivel, como si se hubiera ganado la experiencia. Servidor
void GainPoints(int attributePoints, int skillPoints) Suma puntos para repartir. Servidor
int SpentAttributePoints Puntos repartidos hasta ahora. Ambos
void ResetAttributes() Devuelve todos los puntos de atributo repartidos. Servidor
string CanLearnSkill(SkillData, int rank), void LearnSkill(SkillData, int rank) Aprender skills dentro de las reglas de la skill. Revisar en ambos, aprender en servidor
string CanCastFromItem(SkillData), void CastFromItem(SkillData, int rank) Lanza una skill sin conocerla, sin costo de maná ni tiempo de espera. Revisar en ambos, lanzar en servidor
void AddStatus(StatusData, int level, float seconds) Agrega un estado. Servidor
void TravelTo(MapData, Vector3, ItemData refund) Lleva al jugador a un mapa; devuelve refund si el viaje falla. Servidor

Para todo lo que no esté en la interfaz, convierte a PlayerCharacter (namespace Blunnyn.KitARPG.Net) y usa sus componentes. El ensamblado Game referencia KitARPG.Net, así que esto funciona:

if (!(user is PlayerCharacter player)) return;
var inventory = player.GetComponent<PlayerInventory>();

#Ejemplo: la plantilla

Create > KitARPG > Scripts > Item Effect crea un efecto de experiencia. Consulta Plantillas.

#Ejemplo: bolsa de oro

Se abre y da una cantidad de oro al azar. No se puede abrir con el monedero lleno (Check lo rechaza con "Your purse is full"); cuando el monedero tiene lugar pero no para todo, ServerReceiveGold manda el resto al banco.

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class GoldPouchEffect : ItemEffect
    {
        public int min = 50;
        public int max = 200;

        public override string Summary => $"{min}-{max} gold";

        public override string Check(IItemUser user)
        {
            if (!(user is PlayerCharacter player) || !player.TryGetComponent(out PlayerInventory inventory)) return "Nothing happens";
            return inventory.GoldRoom <= 0 ? "Your purse is full" : null;
        }

        public override void Use(IItemUser user, ItemData item)
        {
            var player = (PlayerCharacter)user;
            int amount = UnityEngine.Random.Range(min, max + 1);
            player.GetComponent<PlayerInventory>().ServerReceiveGold(amount);
            player.ServerAnnounce($"+{amount:N0} {GameInstance.Database.GoldName}", new Color(1f, 0.85f, 0.3f));
            GameLog.Write("mygame.gold_pouch", player, itemId: item.Id, gold: amount);
        }

        public override void Describe(ItemDescription description, IItemUser viewer) =>
            description.Add($"Holds {min:N0} to {max:N0} {GameInstance.Database?.GoldName ?? "Gold"}", ItemDescription.Kind.Effect);
    }
}

Check y Use se ejecutan en el servidor, así que ahí la conversión es segura. Describe nunca convierte al viewer: puede ser null.

#Ejemplo: regresar a la ciudad

Envía al jugador al mapa de inicio del juego. Si el viaje falla, el pergamino vuelve.

[Serializable]
public class RecallEffect : ItemEffect
{
    public override string Summary => "Recall to town";

    public override string Check(IItemUser user)
    {
        MapData town = GameInstance.Database != null ? GameInstance.Database.startMap : null;
        return town == null ? "Leads nowhere" : null;
    }

    public override void Use(IItemUser user, ItemData item)
    {
        MapData town = GameInstance.Database.startMap;
        user.TravelTo(town, town.startPosition, item);
    }

    public override void Describe(ItemDescription description, IItemUser viewer) =>
        description.Add("Takes you back to town", ItemDescription.Kind.Effect);
}

El TravelItemEffect del kit hace lo mismo para un mapa y una posición fijos que se ponen en el inspector.

#Ejemplo: una caja de ítems

Se abre y da cada ítem de su lista, y no se puede usar si alguna entrada no cabe en la bolsa. IPlayerActor (el jugador tal como lo ven las acciones) tiene RoomFor y GiveItem; lo obtienes de PlayerCharacter.Facts.

[Serializable]
public class BoxEffect : ItemEffect
{
    [Serializable]
    public struct Entry
    {
        public ItemData item;
        public int amount;
    }

    public Entry[] contents = new Entry[0];

    public override string Summary => $"Box of {contents.Length}";

    public override string Check(IItemUser user)
    {
        if (!(user is PlayerCharacter player)) return "Nothing happens";
        foreach (Entry e in contents)
        {
            if (e.item == null) continue;
            string why = player.Facts.RoomFor(e.item, Mathf.Max(1, e.amount));
            if (why != null) return why;
        }
        return null;
    }

    public override void Use(IItemUser user, ItemData item)
    {
        IPlayerActor actor = ((PlayerCharacter)user).Facts;
        foreach (Entry e in contents)
            if (e.item != null) actor.GiveItem(e.item, Mathf.Max(1, e.amount));
    }

    public override void Describe(ItemDescription description, IItemUser viewer)
    {
        foreach (Entry e in contents)
            if (e.item != null) description.Add($"{e.item.DisplayName} x{Mathf.Max(1, e.amount)}", ItemDescription.Kind.Effect, e.item.Icon);
    }

    public override void Visit(Action<GameData> visit)
    {
        foreach (Entry e in contents) visit(e.item);
    }
}

RoomFor revisa cada entrada por separado contra la bolsa actual. Varias entradas que caben solas pueden no caber juntas; para una revisión exacta, prueba la lista completa con PlayerInventory.ServerRoomFor, o entrega con GiveOrBank para que nunca se pierda nada (consulta Inventario y banco).

#Tooltips

Describe arma las líneas del tooltip. ItemDescription.Add(text, kind, icon) agrega una línea; los tipos son:

Tipo Se usa para
Normal Texto simple.
Heading Un título de sección.
Effect Lo que hace el ítem.
Muted Detalles secundarios, como requisitos que el viewer cumple.
Warning Requisitos que el viewer no cumple.

Usa el viewer para colorear los requisitos: Warning cuando el jugador local no puede usarlo, Muted cuando sí puede. Contempla siempre viewer == null.

#Servidor y cliente

Se ejecuta en
Check, Use Servidor. El cliente nunca decide si un ítem funciona.
Describe, Summary Cliente (tooltips) y editor.

En un jugador, los dos lados se ejecutan en la misma máquina, con el mismo código.

#Otros tipos de ítems usables

Los efectos cubren los consumibles. Para un tipo de ítem completamente nuevo, hereda de ItemData (o ConsumableData) e implementa las interfaces que correspondan (IUsable, IConsumable, IEquippable). ConsumableData.CheckUse y Use son virtual. Para intervenir en cada uso de ítem, sobrescribe PlayerInventory.UseItem en una subclase de PlayerInventory (consulta Cambiar el comportamiento del kit).

#Errores comunes

  • Rechazar dentro de Use. Para entonces el ítem ya se gastó. Rechaza en Check.
  • Leer viewer sin revisar si es null en Describe.
  • Dar ítems con Inventory.Add directamente sobre el inventario. Pasa por PlayerInventory (Give, GiveOrBank, ServerReceive) o por IPlayerActor.GiveItem, para que la bolsa se sincronice, el peso se actualice y el guardado quede bien.
  • Olvidar Visit para los ítems, estados, mapas o skills a los que apunta el efecto.
  • Guardar estado en campos durante la ejecución. Una sola instancia del efecto sirve a todas las copias del ítem para todos los jugadores.
