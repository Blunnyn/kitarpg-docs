DevKit

Extensiones del editor

Cómo agregar tus propias páginas a la ventana KitARPG, tus propias revisiones a Project Check y a la revisión antes de las builds, y cómo usar el aspecto del editor del kit en tus herramientas.

Dónde van los archivos: el ensamblado Game.Editor (consulta Ensamblados). Todo lo de esta página usa KitARPG.Editor y UnityEditor, que nunca entran en una build.

#Páginas en la ventana KitARPG

La ventana KitARPG (KitARPG > Open KitARPG, Ctrl/Cmd+Shift+K) tiene una barra lateral de páginas: Overview, Play & Servers, Game Database, Game Settings, Shop, Modules y Project Check. Cada subclase no abstracta de KitPage con un constructor sin parámetros la encuentra el TypeCache de Unity y se agrega a la barra lateral. No hay nada que registrar.

#KitPage

Miembro Qué hace Por defecto
abstract string Name El nombre de la página en la barra lateral.
virtual string Group El encabezado de la barra lateral bajo el que va. El kit usa "" (arriba), "Game" y "Project", en ese orden; los demás nombres van después. "Game"
virtual int Order Orden dentro del grupo, los menores primero. Luego por nombre. 100
virtual string IconName El nombre de un ícono integrado del editor, como "Settings" o "d_Favorite". "ScriptableObject Icon"
virtual string Badge Texto corto junto al nombre, como una cantidad de problemas. Null no muestra nada. null
virtual KitGUI.State BadgeState El color de la insignia. Off
virtual bool FullWidth True le da a la página toda el área en lugar de una columna centrada con desplazamiento, para páginas con columnas propias. false
virtual void OnEnable(), OnDisable() Cuando la página se muestra y se oculta.
virtual void Tick() Unas diez veces por segundo mientras la ventana está abierta, para consultar cambios.
abstract void OnGUI() Dibuja la página, con IMGUI.
KitWindow Window La ventana.
Rect Area El área en la que dibuja la página.
void Repaint() Le pide a la ventana que se vuelva a dibujar.

Las páginas del kit usan estos órdenes: Overview 0 y Play & Servers 1 (grupo ""); Game Database 10, Game Settings 20, Shop 25, Modules 30 (grupo "Game"); Project Check 10 (grupo "Project").

KitWindow.Show<T>() abre la ventana en una página: KitWindow.Show<GameDatabaseWindow>(), KitWindow.Show<MyGamePage>().

#Ejemplo: una página para tu contenido

Lista cada tablero de recompensas del proyecto, con un botón para seleccionar cada uno y una insignia de advertencia cuando alguno está vacío. El tipo del tablero vive en el ensamblado Game.Bounties del ejemplo, así que el ensamblado de editor que contiene esta página lo referencia.

using System.Linq;
using Blunnyn.KitARPG.Editor;
using Game.Bounties;
using UnityEditor;
using UnityEngine;

namespace Game
{
    public class BountyBoardsPage : KitPage
    {
        BountyBoardData[] boards = new BountyBoardData[0];

        public override string Name => "Bounty Boards";
        public override int Order => 500;
        public override string IconName => "d_Favorite";

        int Empty => boards.Count(b => b != null && b.bounties.Length == 0);

        public override string Badge => Empty > 0 ? Empty.ToString() : null;
        public override KitGUI.State BadgeState => KitGUI.State.Warning;

        public override void OnEnable() => Load();

        void Load() => boards = AssetDatabase.FindAssets("t:BountyBoardData")
            .Select(g => AssetDatabase.LoadAssetAtPath<BountyBoardData>(AssetDatabase.GUIDToAssetPath(g)))
            .Where(b => b != null).ToArray();

        public override void OnGUI()
        {
            KitGUI.Header("Bounty Boards", "Every board asset in the project and its hunts.");
            if (boards.Length == 0) KitGUI.Empty("No boards yet", "Create one with Create > KitARPG > DevKit Example > Bounty Board.");
            foreach (BountyBoardData board in boards)
            {
                KitGUI.State state = board.bounties.Length == 0 ? KitGUI.State.Warning : KitGUI.State.Done;
                string detail = board.bounties.Length == 0 ? "No hunts" : $"{board.bounties.Length} hunts";
                if (KitGUI.Status(state, board.name, detail, "Select")) Selection.activeObject = board;
            }
            KitGUI.Line();
            if (KitGUI.Secondary("Refresh", 120)) Load();
        }
    }
}

#El aspecto del editor del kit

KitGUI (namespace Blunnyn.KitARPG.Editor) dibuja las tarjetas, los encabezados, las filas de estado y los botones de las ventanas del kit, con IMGUI simple, para que tus páginas combinen.

Miembro Qué dibuja
Header(text, sub, icon) Un título de página con una línea debajo.
BeginCard(heading, sub, stripe) / EndCard(), o using (new KitGUI.CardScope(heading)) Una tarjeta con esquinas redondeadas.
Status(state, heading, detail, button, primaryButton) Una fila de lista de tareas con una luz de color y un botón opcional; devuelve true cuando se presiona.
Primary(text, width, height), Secondary(...) Botones; devuelven true cuando se presionan.
Segmented(value, options, height) Un control segmentado; devuelve el índice elegido.
Switch(rect, on) Un interruptor de encendido y apagado.
Pill(text, color) Una etiqueta pequeña de color.
Tile(rect, value, caption, state) Un número con una leyenda.
Empty(heading, detail) Un marcador para listas vacías.
Message(text, state) Una línea de mensaje de color.
Line(space) Un separador.
Icon(name) Un ícono integrado del editor.
Accent, Good, Warn, Bad, Of(state) La paleta, para los temas claro y oscuro del editor.

KitGUI.State es Done, Todo, Warning, Error, Off y Busy (una luz que late).

#Inspectores para tus datos

El inspector del kit para los datos del juego (GameDataEditor) dibuja cada asset GameData como tarjetas separadas por sus atributos [Header], y también se aplica a las subclases. Un tipo GameData tuyo recibe el mismo aspecto sin un editor propio. Usa [Header], [Tooltip] y [Range] en tus campos y se leerá como los datos del propio kit.

#Revisiones del proyecto

KitARPG > Project Check (la página Project Check) corre cada revisión de ProjectValidator.Checks y lista lo que encuentran como errores, advertencias y notas, cada uno con un botón para seleccionar aquello a lo que se refiere y, cuando lo hay, un botón para arreglarlo. La misma lista corre antes de cada build, sin abrir escenas, y detiene la build cuando hay errores (BuildCheck, que se puede apagar en la página Project Check).

#ProjectValidator

Miembro Qué es
static List<Action<List<ValidationIssue>>> Checks Cada revisión, en orden. Cada una agrega lo que encuentra a la lista que recibe. Agrega las tuyas.
static List<ValidationIssue> Run(bool scenes = true) Las corre todas. Con scenes en false, se saltan las revisiones que abren escenas, como antes de las builds.
static bool IncludeScenes Si la ejecución en curso abre escenas. Léelo en una revisión que abriría escenas.

#ValidationIssue

Campo Qué es
IssueLevel level Error (detiene las builds), Warning o Info.
string area Un nombre de grupo corto, como "My game".
string message Una línea que dice qué está mal.
Object context El asset u objeto al que se refiere; el botón Select lo señala.
string fixLabel El texto del botón de arreglo.
Action fix Qué hace el botón de arreglo. Null no muestra botón.

#Registrar una revisión

ProjectValidator.Checks es una lista estática que vive lo mismo que el dominio del editor. Registra desde [InitializeOnLoadMethod], que corre después de cada recarga de scripts, y quita antes de agregar para que una revisión nunca corra dos veces:

[InitializeOnLoadMethod]
static void Register()
{
    ProjectValidator.Checks.Remove(Check);
    ProjectValidator.Checks.Add(Check);
}

#Ejemplo: tablones de recompensas con recompensas vacías, con arreglo

using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Editor;
using Game.Bounties;
using UnityEditor;

namespace Game
{
    public static class BountyChecks
    {
        [InitializeOnLoadMethod]
        static void Register()
        {
            ProjectValidator.Checks.Remove(Check);
            ProjectValidator.Checks.Add(Check);
        }

        static void Check(List<ValidationIssue> issues)
        {
            foreach (string guid in AssetDatabase.FindAssets("t:BountyBoardData"))
            {
                var board = AssetDatabase.LoadAssetAtPath<BountyBoardData>(AssetDatabase.GUIDToAssetPath(guid));
                if (board == null) continue;
                for (int i = 0; i < board.bounties.Length; i++)
                {
                    BountyBoardData.Bounty bounty = board.bounties[i];
                    if (bounty.monster == null)
                        issues.Add(new ValidationIssue
                        {
                            level = IssueLevel.Error, area = "Bounties", context = board,
                            message = $"{board.name}: hunt {i + 1} has no monster.",
                        });
                    else if (bounty.rewards.Length == 0)
                    {
                        BountyBoardData.Bounty b = bounty;
                        issues.Add(new ValidationIssue
                        {
                            level = IssueLevel.Warning, area = "Bounties", context = board,
                            message = $"{board.name}: hunting {bounty.monster.DisplayName} pays nothing.",
                            fixLabel = "Add 100 gold",
                            fix = () =>
                            {
                                Undo.RecordObject(board, "Add bounty reward");
                                b.rewards = new GameAction[] { new GiveCurrencyAction { amount = 100 } };
                                EditorUtility.SetDirty(board);
                            },
                        });
                    }
                }
            }
        }
    }
}

#Pautas para las revisiones

  • Los errores detienen las builds. Usa Error solo para lo que va a fallar en el juego. Usa Warning para errores probables e Info para sugerencias.
  • Sé rápido. Las revisiones corren antes de cada build. Evita abrir escenas salvo que ProjectValidator.IncludeScenes sea true.
  • Señala el asset. Pon context para que funcione el botón Select.
  • Los arreglos son seguros. Un arreglo solo debe agregar lo que falta o corregir una cosa clara, con Undo y SetDirty.

#Encontrar los ajustes y la base de datos del juego

ModulesWindow.Find() devuelve el GameInstance del proyecto (el del prefab KitNetwork), guardado en caché por unos segundos. Su campo database es el GameDatabase:

GameInstance game = ModulesWindow.Find();
GameDatabase database = game != null ? game.database : null;

GameDatabase.All<T>() lista todos los assets de un tipo y TryGet<T>(id, out T) encuentra uno por su id.

#Elementos de menú

Los [MenuItem] comunes de Unity funcionan como siempre. Para poner los tuyos junto a los del kit, usa la raíz KitARPG/, como hace el ejemplo con KitARPG > DevKit > Add Bounty Board to the Open Scene:

[MenuItem("KitARPG/My Game/Rebuild Recipes", priority = 200)]
static void Rebuild() { /* ... */ }

#Errores comunes

  • Código de editor en Game. Referencia UnityEditor y la build falla. Usa Game.Editor.
  • Registrar una revisión sin quitarla antes. Corre una vez más después de cada recarga de scripts.
  • Tick u OnGUI lentos. Corren seguido; guarda en caché lo que cargas, como hace la página de arriba en OnEnable.
  • Una página sin constructor sin parámetros. No se encuentra.
