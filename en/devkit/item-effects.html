Item effects

How to write your own effects for consumable items: the ItemEffect base class, the IItemUser interface it works with, how using an item flows on the server, and complete examples.

#What an item effect is

A consumable (ConsumableData: potions, scrolls, food) restores health and mana with its own fields, then runs a list of effects (ConsumableData.effects). The kit ships effects for experience, levels, learning skills, attribute and skill points, resetting attributes, casting a skill, adding a status and traveling. Anything else an item should do is a new effect class.

Effects are [Serializable] classes held by reference with [SerializeReference, PickType]. Once yours compiles, it shows in the + type menu of Effects on every Consumable in KitARPG > Game Database > Items.

Where the file goes: the Game assembly. Tooltips on the client read the effect too.

#The base class

ItemEffect lives in Blunnyn.KitARPG.Data.

Member What it does Default
string Summary Short text in the item editor and the default tooltip line. The class name
string Check(IItemUser user) Server. Why this user can't use it now, or null. Every effect of the item is checked before any runs. null
void Use(IItemUser user, ItemData item) Server. Does the effect. item is what was used, to give back if something fails later. Required.
void Describe(ItemDescription description, IItemUser viewer) Lines for the item's tooltip. viewer can be null (a tooltip in the editor, or for another player's item). Adds Summary
void Visit(Action<GameData> visit) Hands the game database every asset the effect points at. Nothing

#What happens when a player uses an item

  1. The owner's client asks (PlayerInventory.Use(slot), from the bag, the item menu or a hotbar slot).
  2. On the server, PlayerInventory checks its own pace, that the slot holds an item, and that the item is usable (IUsable).
  3. It checks the cooldown of the item's Cooldown Group (cooldownGroup, default potion).
  4. It calls ConsumableData.CheckUse(player): dead players can't use items, then every effect's Check runs in order and the first non-null answer stops everything. That answer is shown over the player's head.
  5. A consumable with no effects is usable only while it would restore something.
  6. ConsumableData.Use restores health and mana, then calls every effect's Use in order.
  7. The cooldown starts and one item is taken from the stack.

Because every Check runs before any Use, an item with three effects either does all three or none. Put every reason to refuse in Check. Once Use runs, the item is spent.

#IItemUser

The player as items see it. On the server it is the PlayerCharacter; on the client, tooltips get the local player.

Member What it does Where
CharacterClass Class, int Level Class and level. Both
IReadOnlyList<string> WornItemIds Item id at each equipment position, empty where nothing is worn. Both
bool IsDead, int Health, int MaxHealth, int Mana, int MaxMana Current state. Both
void RestoreHealth(int), void RestoreMana(int) Restores. Server
long ExperienceToNext Experience still needed, 0 at the highest level. Both
void GainExperience(long) Adds experience, with level ups. Server
void GainLevel() One level up, as if the experience had been earned. Server
void GainPoints(int attributePoints, int skillPoints) Adds points to spend. Server
int SpentAttributePoints Points spent so far. Both
void ResetAttributes() Gives back every spent attribute point. Server
string CanLearnSkill(SkillData, int rank), void LearnSkill(SkillData, int rank) Skill learning within the skill's rules. Check both, learn server
string CanCastFromItem(SkillData), void CastFromItem(SkillData, int rank) Casts a skill without knowing it, with no mana cost or cooldown. Check both, cast server
void AddStatus(StatusData, int level, float seconds) Adds a status. Server
void TravelTo(MapData, Vector3, ItemData refund) Moves the player to a map; gives refund back if the trip fails. Server

For anything not on the interface, cast to PlayerCharacter (namespace Blunnyn.KitARPG.Net) and use its components. The Game assembly references KitARPG.Net, so this works:

if (!(user is PlayerCharacter player)) return;
var inventory = player.GetComponent<PlayerInventory>();

#Example: the template

Create > KitARPG > Scripts > Item Effect makes an experience effect. See Templates.

#Example: gold pouch

Opens into a random amount of gold. It can't be opened while the purse is full (Check refuses with "Your purse is full"); when the purse has room but not for all of it, ServerReceiveGold sends the rest to the bank.

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class GoldPouchEffect : ItemEffect
    {
        public int min = 50;
        public int max = 200;

        public override string Summary => $"{min}-{max} gold";

        public override string Check(IItemUser user)
        {
            if (!(user is PlayerCharacter player) || !player.TryGetComponent(out PlayerInventory inventory)) return "Nothing happens";
            return inventory.GoldRoom <= 0 ? "Your purse is full" : null;
        }

        public override void Use(IItemUser user, ItemData item)
        {
            var player = (PlayerCharacter)user;
            int amount = UnityEngine.Random.Range(min, max + 1);
            player.GetComponent<PlayerInventory>().ServerReceiveGold(amount);
            player.ServerAnnounce($"+{amount:N0} {GameInstance.Database.GoldName}", new Color(1f, 0.85f, 0.3f));
            GameLog.Write("mygame.gold_pouch", player, itemId: item.Id, gold: amount);
        }

        public override void Describe(ItemDescription description, IItemUser viewer) =>
            description.Add($"Holds {min:N0} to {max:N0} {GameInstance.Database?.GoldName ?? "Gold"}", ItemDescription.Kind.Effect);
    }
}

Check and Use run on the server, so the cast is safe there. Describe never casts the viewer: it may be null.

#Example: recall to town

Sends the player to the game's start map. If the trip fails, the scroll comes back.

[Serializable]
public class RecallEffect : ItemEffect
{
    public override string Summary => "Recall to town";

    public override string Check(IItemUser user)
    {
        MapData town = GameInstance.Database != null ? GameInstance.Database.startMap : null;
        return town == null ? "Leads nowhere" : null;
    }

    public override void Use(IItemUser user, ItemData item)
    {
        MapData town = GameInstance.Database.startMap;
        user.TravelTo(town, town.startPosition, item);
    }

    public override void Describe(ItemDescription description, IItemUser viewer) =>
        description.Add("Takes you back to town", ItemDescription.Kind.Effect);
}

The kit's TravelItemEffect does the same for a fixed map and position set in the inspector.

#Example: a box of items

Opens into every item on its list, and can't be used unless each entry fits in the bag. IPlayerActor (the player as actions see it) has RoomFor and GiveItem; get it from PlayerCharacter.Facts.

[Serializable]
public class BoxEffect : ItemEffect
{
    [Serializable]
    public struct Entry
    {
        public ItemData item;
        public int amount;
    }

    public Entry[] contents = new Entry[0];

    public override string Summary => $"Box of {contents.Length}";

    public override string Check(IItemUser user)
    {
        if (!(user is PlayerCharacter player)) return "Nothing happens";
        foreach (Entry e in contents)
        {
            if (e.item == null) continue;
            string why = player.Facts.RoomFor(e.item, Mathf.Max(1, e.amount));
            if (why != null) return why;
        }
        return null;
    }

    public override void Use(IItemUser user, ItemData item)
    {
        IPlayerActor actor = ((PlayerCharacter)user).Facts;
        foreach (Entry e in contents)
            if (e.item != null) actor.GiveItem(e.item, Mathf.Max(1, e.amount));
    }

    public override void Describe(ItemDescription description, IItemUser viewer)
    {
        foreach (Entry e in contents)
            if (e.item != null) description.Add($"{e.item.DisplayName} x{Mathf.Max(1, e.amount)}", ItemDescription.Kind.Effect, e.item.Icon);
    }

    public override void Visit(Action<GameData> visit)
    {
        foreach (Entry e in contents) visit(e.item);
    }
}

RoomFor checks each entry on its own against the current bag. Several entries that each fit alone may not fit together; for an exact check, test the whole list with PlayerInventory.ServerRoomFor, or give with GiveOrBank so nothing is ever lost (see Inventory and bank).

#Tooltips

Describe builds the tooltip lines. ItemDescription.Add(text, kind, icon) adds a line; the kinds are:

Kind Used for
Normal Plain text.
Heading A section title.
Effect What the item does.
Muted Secondary details, like requirements the viewer meets.
Warning Requirements the viewer doesn't meet.

Use the viewer to color requirements: Warning when the local player can't use it, Muted when they can. Always handle viewer == null.

#Server and client

Runs on
Check, Use Server. The client never decides whether an item works.
Describe, Summary Client (tooltips) and editor.

In single player both sides run on the same machine, with the same code.

#Other kinds of usable items

Effects cover consumables. For a whole new kind of item, subclass ItemData (or ConsumableData) and implement the interfaces that apply (IUsable, IConsumable, IEquippable). ConsumableData.CheckUse and Use are virtual. To step in for every item use, override PlayerInventory.UseItem in a subclass of PlayerInventory (see Overriding kit behaviour).

#Common mistakes

  • Refusing inside Use. By then the item is spent. Refuse in Check.
  • Reading viewer without a null check in Describe.
  • Giving items with Inventory.Add straight on the inventory. Go through PlayerInventory (Give, GiveOrBank, ServerReceive) or IPlayerActor.GiveItem, so the bag syncs, weight updates and saving stays right.
  • Forgetting Visit for items, statuses, maps or skills the effect points at.
  • Storing state in fields at runtime. One effect instance serves every copy of the item for every player.
