NPC options

How to add your own buttons to NPCs: the NpcOption base class, what the server checks before running it, how to answer the player, how to open a window of your own, and complete examples.

#What an NPC option is

An Npc component in a scene has a list of options (Npc.options). When a player talks to the NPC, the server lists the options that player may see, the client shows them as buttons, and when the player picks one the server runs it. The kit's options open shops, teleport, train skills, offer quests, run dialogue lines, open the bank, the market, the guild bank, the forge, the mail, collectors, guild founding and guild halls, and fire world triggers.

A new kind is a class. NpcOption is [Serializable] and the list is [SerializeReference, PickType], so yours shows in the + menu of every NPC's Options, and of every dialogue line's nested Options.

Where the file goes: the Game assembly. Scenes hold the option on the NPC, so both builds load the class, though only the server runs it.

#The base class

NpcOption lives in Blunnyn.KitARPG.Net.

#Inspector fields

Field What it does Default
Label (label) Button text. Empty uses DefaultLabel. empty
Required Level (requiredLevel) Hidden from characters below this level. 0
Conditions (conditions) Hidden while one isn't met. none
Show When Locked (showWhenLocked) Show it greyed out with the reason instead of hiding it. off

#Members to override

Member What it does Default
protected abstract string DefaultLabel { get; } Button text when Label is empty. Required.
virtual string LabelFor(PlayerCharacter player) Server. The text this player sees, for labels that change per player. Label
virtual bool AvailableTo(PlayerCharacter player) Server. False hides it from this player, even with Show When Locked. true
virtual KitModule Module The kit module it belongs to. When that module is off in KitARPG > Modules, the option disappears. KitModule.None
abstract string Run(Npc npc, PlayerCharacter player) Server. Does it. Returns an error code for the player, or null. Required.

#Helpers you can call

Member What it returns
string Label Label or DefaultLabel.
string Locked(PlayerCharacter player) Why the player can't pick it (level, then conditions), or null.
bool Offered(PlayerCharacter player) Module on, not locked, and AvailableTo.
bool Listed(PlayerCharacter player) Whether the player sees it, picked or not.

#What the server checks before Run

The owner's client asks through PlayerInteraction. Before your Run is called, the server has already:

  1. Confirmed the player is alive, loaded and talking to that NPC.
  2. Spent from the per-player request budget (Max Requests Per Second, maxRequestsPerSecond, 10 on PlayerInteraction).
  3. Checked the player is within the NPC's Talk Range (talkRange, 3 m, plus half a meter). Too far answers too_far.
  4. Found the option by its index in the list on screen, and checked Offered(player): module, level, conditions and AvailableTo.

So inside Run you know the player is next to the NPC and allowed to pick the option. Anything your option costs or requires beyond that, check again in Run.

#Answering the player

Run returns a string that is sent to the owner's client as PlayerInteraction.ErrorReceived. Of the kit's windows, only the shop window shows those, while it is open, and it turns known codes (NpcErrors.NotEnoughMoney, NpcErrors.TooFar and the inventory errors) into sentences.

For a plain dialogue option, tell the player yourself and return null:

player.ServerAnnounce("Blessed!", new Color(1f, 0.85f, 0.4f));    // floating text over the player
if (player.TryGetComponent(out PlayerChat chat)) chat.Tell("The priest blesses you."); // a system line in the chat
return null;

DialogueOption does the same with its actions' refusal reasons. The bounty example's option uses PlayerChat.Tell.

#Example: the template

Create > KitARPG > Scripts > NPC Option makes a blessing that heals for gold, and tells the player in the chat when they can't pay. See Templates.

#Example: blessing, answered in the chat

The template with a label that shows the price, a blessing status instead of a full heal, and a line in the chat after the blessing:

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class BlessingOption : NpcOption
    {
        public long price = 50;
        public StatusData blessing;
        public float seconds = 300;

        protected override string DefaultLabel => "Bless me";

        public override string LabelFor(PlayerCharacter player) =>
            $"{Label} ({price:N0} {GameInstance.Database.GoldName})";

        public override bool AvailableTo(PlayerCharacter player) => blessing != null;

        public override string Run(Npc npc, PlayerCharacter player)
        {
            var inventory = player.GetComponent<PlayerInventory>();
            if (inventory.gold < price)
            {
                Tell(player, $"That costs {price:N0} {GameInstance.Database.GoldName}.");
                return null;
            }
            inventory.AddGold(-price);
            player.AddStatus(blessing, 1, seconds);
            GameLog.Write("mygame.blessing", player, gold: price, detail: npc.Id);
            Tell(player, $"{npc.displayName} blesses you.");
            return null;
        }

        static void Tell(PlayerCharacter player, string text)
        {
            if (player.TryGetComponent(out PlayerChat chat)) chat.Tell(text);
        }
    }
}

PlayerCharacter.AddStatus is the IItemUser method; the player implements it.

#Example: an option that opens your own window

Options run on the server, so to open a window on the client the option sends a message to the owner. This one opens a "stash" window and lets the window know which NPC it came from.

using System;
using Blunnyn.KitARPG.Net;
using Mirror;
using UnityEngine;

namespace Game
{
    public struct OpenStashMessage : NetworkMessage
    {
        public string npcId;
    }

    [Serializable]
    public class StashOption : NpcOption
    {
        protected override string DefaultLabel => "Open the stash";

        public override string Run(Npc npc, PlayerCharacter player)
        {
            player.connectionToClient?.Send(new OpenStashMessage { npcId = npc.Id });
            return null;
        }
    }

    public static class StashClient
    {
        public static event Action<Npc> Opened;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void ResetStatics() => Opened = null;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Hook()
        {
            KitNetworkManager manager = KitNetworkManager.Instance;
            if (manager == null) return;
            manager.ClientConnected += () => NetworkClient.ReplaceHandler<OpenStashMessage>(OnOpen);
        }

        static void OnOpen(OpenStashMessage message)
        {
            if (Npc.TryFind(message.npcId, out Npc npc)) Opened?.Invoke(npc);
        }
    }
}

Your window subscribes to StashClient.Opened, opens, and closes itself when the player walks out of npc.InReach(PlayerCharacter.Local.transform.position). Every request the window sends back must check again on the server that the player is near that NPC (npc.InReach(player.transform.position)). See Network messages.

#Example: a label that changes per player

The bounty example's option says "Today's bounty" or "Turn in the bounty" depending on the player:

public override string LabelFor(PlayerCharacter player) =>
    Bounties.Current(player.Facts, out _) != null ? "Turn in the bounty" : "Today's bounty";

#Example: belonging to a module

An option that belongs to one of the kit's modules disappears when that module is off:

public override KitModule Module => KitModule.Guilds;

#State on an option

One option instance lives on one NPC in one scene, and every player who talks to that NPC shares it. Use instance fields only for state of the NPC, never of a player. Mark runtime-only fields [NonSerialized] so they don't end up in the scene. The kit's ShopOption keeps its limited stock per NPC this way:

[NonSerialized] int[] left;

For state per player, use flags, PlayerData or a player system (see Saving data).

#Adding the option to an NPC

  1. Select the NPC in its scene (a GameObject with the Npc component).
  2. In Options, press + and pick your class from the menu.
  3. Fill its fields, its Label, Required Level and Conditions.
  4. Inside a Dialogue option, the nested Options list takes your class too, so it can appear after a line of talk.

Options with an empty Label use their DefaultLabel. When an NPC has no greeting and only one option, talking to it runs that option at once.

#Server and client

Runs on
LabelFor, AvailableTo, Locked, Offered, Run Server
Labels and locked reasons Sent as text to the client
The Npc component Both: clients use it for its name, position and range

In single player the host runs the server half in the same process.

#Common mistakes

  • Returning a sentence from Run and expecting the dialogue to show it. Use ServerAnnounce or PlayerChat.Tell.
  • Trusting the window that follows. A window opened by an option sends its own requests; each must check range and rules again.
  • Keeping per-player data on the option. It is shared by everyone who talks to that NPC.
  • Changing the order of options while a player is talking. The client picks by index; reorder in the editor, not at runtime.
