Add-ons

An add-on is a feature in its own folder and assemblies that plugs into KitARPG without changing the kit. This page covers what makes an add-on, how to create one, its HUD window as a prefab, and every hook it can use.

#What an add-on is

The kit keeps what almost every RPG needs in its core. Optional features ship as add-ons: the bestiary is the first one, in Assets/Blunnyn/KitARPG/Addons/Bestiary. Your own features can be add-ons too, so a kit update never touches them and you can reuse them between projects or share them.

An add-on:

  • Lives in its own folder, with a runtime assembly and usually .Editor and .Server ones.
  • Shows up in KitARPG > Modules by itself, with its version, and turns on and off there like the kit's modules.
  • Keeps its HUD window as a prefab of its own, which the HUD holds an instance of.

#Creating one

  1. Open KitARPG > Create Add-on....
  2. Type a Name. The Id fills in from it: lowercase letters, digits and underscores.
  3. Pick where it goes (by default Assets/Game/Addons).
  4. Tick A HUD window with a toolbar button and A server part with a GM command if you want them.
  5. Click Create.

You get a folder with:

File What it is
Runtime/Game.Addons.Name.asmdef The add-on's code that runs in the game
Runtime/NameAddon.cs The declaration the kit finds the add-on by, and its id
Runtime/NameWindow.cs The window, if you asked for one
Editor/Game.Addons.Name.Editor.asmdef Editor code
Editor/NameHud.cs The window's place in the HUD and its toolbar button
Server/Game.Addons.Name.Server.asmdef Server-only code, if you asked for it. Never in an online client build
Server/NameCommands.cs A GM command that belongs to the add-on

#The declaration

One line in the runtime assembly makes it an add-on:

[assembly: KitAddon("pet_arena", "Pet Arena", "1.0.0",
    Description = "Pets fight each other in the arena.", MinKitVersion = "1.0.0",
    Needs = new[] { "pets" }, NeedsModules = KitModule.Parties, Group = "World")]
[assembly: AlwaysLinkAssembly]
Field What it does
Id Names the add-on in saves, settings and logs. Keep it once players have saves
Name, Version Shown in Modules
Description, Author Shown on its card in Modules
MinKitVersion The oldest KitARPG it works with. Project Check stops builds on an older kit
Needs Ids of add-ons it can't work without. Turning it on turns them on
NeedsModules Kit modules it can't work without
Replaces A kit module it took over. A game that had that module off keeps the add-on off
Icon A kit icon name or the path of a sprite
Group Where its card sits in Modules: Social, Economy, World, or a group of its own

Assemblies named after the runtime one (Game.Addons.PetArena.Editor, .Server) belong to the add-on.

#Turning it on and off

KitARPG > Modules lists every installed add-on next to the kit's modules. The switch saves in the GameInstance of the network prefab (disabledAddons), so client and server builds agree.

In code, check it before doing anything:

if (!GameInstance.Has(PetArenaAddon.Id)) return;

Refuse requests on the server and hide windows, menu lines and NPC options while it is off. The code stays, so turning it back on loses nothing.

#Its window in the HUD

The window is a prefab in the add-on's Prefabs folder, with the rows it copies in Prefabs/UI. The HUD holds an instance of that prefab: change the prefab and every HUD follows.

  • The prefab's root has the window component, which implements IHudWindow (IsOpen and SetOpen).
  • NameHud (a HudAddition) says which component the window is and which toolbar button opens it.
  • The first time it is needed, HudAddition.Build makes the prefab with KitUi, the same pieces the starter HUD is built from. After that it isn't called again: edit the prefab. KitARPG > Make Add-on Window Prefabs makes the missing ones right away.
  • The starter HUD places the window with the kit's own and adds its button before Menu.
  • A HUD made before the add-on gets the window and the button from the kit update Add-on windows in the HUD in Overview. Only those two pieces are added.
  • A button you add by hand opens any window: set its HudButton.window. The toolbar wires it and hides it while the add-on is off.

#Other hooks

To... Use
Add to games made before it A KitUpdate whose Addon is the id. It isn't offered while the add-on is off. See Kit updates in code
Add a GM command Register it with addon set to the id. While the add-on is off the command doesn't exist and /help leaves it out. See GM commands in code
Write to the game log A kind that starts with the id, like pet_arena.won
Save per character PlayerData / IPlayerSave, keyed by the id. Works online and in single player. See Saving data
Keep tables of its own A Login or Central module with its own DbContext. Never change the kit's tables. See Service modules
Describe its HUD part A HudPartEditor subclass that overrides Description

#Single player and MMO

An add-on runs the same in both. Clients and map servers compare the installed add-ons and their versions as part of the network version, so a client without the add-on, or with another version, can't join a map server that has it. Rebuild clients and servers together after adding or updating one.

#Common mistakes

  • The add-on doesn't show in Modules. The KitAddon line is missing, or the id has capitals or spaces. The Console names an invalid id.
  • The window opens nowhere. The HUD doesn't have it yet: apply Add-on windows in the HUD in Overview.
  • Changes to the window don't show. You edited the copy inside one HUD instead of the prefab in the add-on's Prefabs folder.
  • Clients are turned away with a version mismatch. The client and the map server were built with different add-ons.
