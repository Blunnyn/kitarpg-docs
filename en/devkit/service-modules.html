Service modules

How to extend the Login and Central services with .NET modules of your own: the module interfaces, map messages, HTTP endpoints, your own database tables and migrations, building and installing, and the security rules for modules.

#What a module is

Login and Central are ASP.NET Core services (.NET 10). You don't edit them: a game adds code to them as modules, class libraries the services load at startup from a folder. A module can:

  • handle messages from map servers and answer them (Central),
  • keep its own tables in the kit's database, with its own migrations,
  • add HTTP endpoints (Login or Central),
  • register services in the dependency injection container.

Updating the kit replaces the services' code but never touches your modules.

Write a Central module for data that spans maps or characters (rankings, world events). Write a Login module for account-side features reached over HTTP. For the Unity side of map messages, see Talking to Central.

#The contract

Modules reference one small project, Services/Modules/KitARPG.Services.Modules.csproj (namespace Blunnyn.KitARPG.Services.Modules). It is kept small so modules keep building across kit updates. In the Asset Store package the services sit in Assets/Blunnyn/KitARPG/Services~ (unpacked by the kit from Services.zip), so the path is Services~/Modules/....

#IKitModule

Member What it does
string Name Unique among the service's modules: letters, digits and underscores, up to 40.
void ConfigureServices(IServiceCollection services, IConfiguration configuration) Registers services and the module's database. Runs before the service is built. Optional.
void MapEndpoints(IEndpointRouteBuilder endpoints) Adds HTTP endpoints. They are open to anyone unless they call RequireAuthorization(). Optional.

A module is a public class with a public parameterless constructor implementing one of:

Interface Service
ILoginModule Login
ICentralModule Central. Adds void OnMapLink(IMapLink link), called once at startup: register every map message handler there.

#IMapLink

Member What it does
IServiceProvider Services Central's services: scopes, loggers, your DbContext.
void On<T>(Func<MapMessage<T>, Task> handler) Handles every T a map sends, by class name. Kit names, and names another module took, are refused at startup.
bool Send(string mapId, object message) Sends to one map. False when it isn't connected.
bool SendToCharacter(long characterId, object message) Sends to the map the character is playing on. False when it isn't playing.
void Broadcast(object message) Sends to every connected map.

#MapMessage<T>

Member What it is
string MapId The map that sent it.
T Message The message.
void Reply(object message) Sends a message back to that map.
bool Hosts(long characterId) True only when that character is playing on the map that sent this.

A map is authenticated, but it speaks for its players. Check Hosts(characterId) before acting for a character, so a compromised map can't act for players it doesn't hold.

#AddModuleDatabase

services.AddModuleDatabase<TContext>(configuration, name);

Registers your DbContext on the kit's database and provider (Database:Provider, Database:ConnectionString), with its own migrations history table __ModuleMigrations_<name>. Your migrations run at startup after the kit's, when Database:MigrateOnStartup is on (the default).

#Making a Central module, step by step

#1. The project

Make a class library next to your Unity project, for example Services/MyGame.Central/MyGame.Central.csproj. The bounty example's project file:

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
    <RootNamespace>Game.Bounties</RootNamespace>
    <EnableDynamicLoading>true</EnableDynamicLoading>
    <!-- The linked messages are Unity code, written without nullable annotations. -->
    <NoWarn>$(NoWarn);CS8618</NoWarn>
  </PropertyGroup>

  <ItemGroup>
    <!-- Central already has these; Private and ExcludeAssets keep copies out of the module folder. -->
    <ProjectReference Include="..\..\Modules\KitARPG.Services.Modules.csproj">
      <Private>false</Private>
      <ExcludeAssets>runtime;native</ExcludeAssets>
    </ProjectReference>
  </ItemGroup>

  <ItemGroup>
    <!-- The same message file Unity compiles. -->
    <Compile Include="$(KitFolder)DevKit/Example/Bounties/Shared/BountyBoardMessages.cs" Link="Shared/BountyBoardMessages.cs" />
  </ItemGroup>

  <Target Name="CopyToKitModules" AfterTargets="Build" Condition="'$(KitModulesDir)' != ''">
    <PropertyGroup>
      <KitModuleFolder>$([System.IO.Path]::GetFullPath('$(KitModulesDir)', '$(MSBuildStartupDirectory)'))/$(AssemblyName)</KitModuleFolder>
    </PropertyGroup>
    <ItemGroup>
      <ModuleFiles Include="$(OutDir)**/*" />
    </ItemGroup>
    <Copy SourceFiles="@(ModuleFiles)" DestinationFolder="$(KitModuleFolder)/%(RecursiveDir)" SkipUnchangedFiles="true" />
    <Message Importance="high" Text="Module copied to $(KitModuleFolder)" />
  </Target>
</Project>
  • EnableDynamicLoading makes the build output carry what a plugin needs.
  • Private=false keeps the contract's own DLL out of your module folder, and ExcludeAssets=runtime;native keeps out the runtime and native files of the packages that come through it (EF Core, Npgsql). Your code still compiles against them; at run time the service's own copies are used.
  • $(KitFolder) comes from Services/Directory.Build.props: the kit's folder in the Unity project. Link your own message file from your game folder the same way, with a relative path.
  • The CopyToKitModules target copies the build into <KitModulesDir>/<AssemblyName>/ when you pass -p:KitModulesDir=....

Add packages your module needs. Microsoft.EntityFrameworkCore and the SQLite and PostgreSQL providers come through the contract, for compiling only, as described above.

#2. The module class

The bounty example's module, which keeps a ranking of finished bounties:

using Blunnyn.KitARPG.Services.Modules;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Logging;

namespace Game.Bounties;

/// <summary>Counts finished bounties per character and answers the board's ranking.</summary>
public class BountiesModule : ICentralModule
{
    public const int TopCount = 10;
    public const int MaxNameLength = 32;

    // One writer at a time, so two bounties finished together can't both insert the same row.
    readonly SemaphoreSlim writing = new(1, 1);
    IServiceScopeFactory scopes = null!;
    ILogger log = null!;

    public string Name => "Bounties";

    public void ConfigureServices(IServiceCollection services, IConfiguration configuration) =>
        services.AddModuleDatabase<BountyContext>(configuration, Name);

    public void OnMapLink(IMapLink link)
    {
        scopes = link.Services.GetRequiredService<IServiceScopeFactory>();
        log = link.Services.GetRequiredService<ILoggerFactory>().CreateLogger<BountiesModule>();
        link.On<BountyFinished>(Finished);
        link.On<BountyBoardAsk>(Ask);
    }

    async Task Finished(MapMessage<BountyFinished> m)
    {
        BountyFinished b = m.Message;
        string name = b.name?.Trim() ?? "";
        if (name.Length == 0 || name.Length > MaxNameLength || !m.Hosts(b.characterId))
        {
            log.LogWarning("Ignored a bounty from {Map} for character {Character}", m.MapId, b.characterId);
            return;
        }
        await writing.WaitAsync();
        try
        {
            using var scope = scopes.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<BountyContext>();
            var row = await db.Hunters.FindAsync(b.characterId);
            if (row == null) db.Hunters.Add(new BountyHunterRow { CharacterId = b.characterId, Name = name, Count = 1 });
            else
            {
                row.Count++;
                row.Name = name;
            }
            await db.SaveChangesAsync();
        }
        finally
        {
            writing.Release();
        }
    }

    async Task Ask(MapMessage<BountyBoardAsk> m)
    {
        long id = m.Message.characterId;
        if (!m.Hosts(id)) return;
        using var scope = scopes.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<BountyContext>();
        var top = await db.Hunters.AsNoTracking()
            .OrderByDescending(h => h.Count).ThenBy(h => h.CharacterId)
            .Take(TopCount)
            .Select(h => new BountyHunter { name = h.Name, bounties = h.Count })
            .ToArrayAsync();
        int mine = await db.Hunters.Where(h => h.CharacterId == id).Select(h => h.Count).FirstOrDefaultAsync();
        m.Reply(new BountyBoardList { characterId = id, top = top, mine = mine });
    }
}

Points to copy:

  • One module instance serves every map. DbContext is scoped, so each handler makes its own scope with IServiceScopeFactory.
  • Handlers run off the network thread and side by side. Two messages may finish in any order, and two handlers may run at once. The example serializes its writes with a SemaphoreSlim; a unique index and a retry would work too.
  • Validate every field (lengths, ranges) and check Hosts before acting.
  • Log refusals with the map id, so a misbehaving map shows in Central's log.

#3. Your tables

using Microsoft.EntityFrameworkCore;

namespace Game.Bounties;

public class BountyHunterRow
{
    public long CharacterId { get; set; }
    public string Name { get; set; } = "";
    public int Count { get; set; }
}

/// <summary>The module's own table, next to the kit's in the same database.</summary>
public class BountyContext : DbContext
{
    public BountyContext(DbContextOptions<BountyContext> options) : base(options) { }

    public DbSet<BountyHunterRow> Hunters => Set<BountyHunterRow>();

    protected override void OnModelCreating(ModelBuilder model)
    {
        model.Entity<BountyHunterRow>(e =>
        {
            e.ToTable("bounty_hunters");
            e.HasKey(h => h.CharacterId);
            e.Property(h => h.CharacterId).HasColumnName("character_id").ValueGeneratedNever();
            e.Property(h => h.Name).HasColumnName("name").HasMaxLength(BountiesModule.MaxNameLength);
            e.Property(h => h.Count).HasColumnName("count");
            e.HasIndex(h => h.Count);
        });
    }
}

Rules for module tables:

  • Never create, change or drop the kit's tables. That is the kit's migrations' job, and an update would break against your changes. Read the kit's data through messages from the maps, not through its tables.
  • Prefix your tables with your feature's name (bounty_hunters).
  • Character ids are stable. Key per-character rows by character_id, as the example does. Rows of deleted characters stay until you remove them.

#4. Migrations

Generate migrations with the EF Core tools. They need Microsoft.EntityFrameworkCore.Design and a design-time factory while you run them:

using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Design;

namespace Game.Bounties;

public class BountyContextFactory : IDesignTimeDbContextFactory<BountyContext>
{
    public BountyContext CreateDbContext(string[] args) =>
        new(new DbContextOptionsBuilder<BountyContext>().UseSqlite("Data Source=design.db").Options);
}

cd Services
dotnet ef migrations add BountyHunters --project Examples/Bounties

One set of migrations serves SQLite and PostgreSQL when column types are left to the provider. Remove every type: argument and HasColumnType call from the generated migration, as the example does:

character_id = table.Column<long>(nullable: false),
name = table.Column<string>(maxLength: 32, nullable: false),
count = table.Column<int>(nullable: false)

AddModuleDatabase logs the "pending model changes" warning instead of failing on it, because the snapshot's types differ between providers. If you need provider-specific types, keep one context per provider instead.

#5. Build and install

Each service loads modules from its Modules Path (Modules:Path, default modules, relative to the service's content root): one folder per module, named like its dll.

modules/
    Game.Bounties.Central/
        Game.Bounties.Central.dll
        (its own dependencies)
How you run the services Login's folder Central's folder
The launcher (and Play & Servers) modules/login next to launcher.json (ModulesFolder in launcher.json) modules/central
Docker Compose Deploy/modules/login, mounted read-only Deploy/modules/central, mounted read-only

Build straight into the folder:

cd Services
dotnet build Examples/Bounties -c Release -p:KitModulesDir=<launcher folder>/modules/central
dotnet build Examples/Bounties -c Release -p:KitModulesDir=../Deploy/modules/central   # Docker

In the editor, launcher.json lives in UserSettings/KitARPG, so the launcher folder is UserSettings/KitARPG and the modules go in UserSettings/KitARPG/modules/central.

Restart the service. Its log lists each module: Module Bounties loaded from .../Game.Bounties.Central.dll (SHA-256 ...). Modules load once, at startup; to update one, replace its folder and restart.

#Endpoints

MapEndpoints adds minimal API endpoints to the service. They are public unless they call RequireAuthorization(), which checks the player's Login token (a short-lived JWT). The account id is the token's sub claim:

using System.Security.Claims;
using Blunnyn.KitARPG.Services.Modules;
using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Routing;

public class NewsModule : ILoginModule
{
    public string Name => "News";

    public void MapEndpoints(IEndpointRouteBuilder endpoints)
    {
        // Anyone, for the title screen.
        endpoints.MapGet("/api/news", () => Results.Ok(new[] { "Welcome to the open beta." }));

        // Only logged-in players.
        endpoints.MapGet("/api/news/mine", (ClaimsPrincipal user) =>
        {
            if (!long.TryParse(user.FindFirstValue("sub"), out long accountId)) return Results.Unauthorized();
            return Results.Ok(new { accountId });
        }).RequireAuthorization();
    }
}

Prefix your routes with your game's name to stay clear of the kit's. Validate every input, and limit what each call can do or read: endpoints face the internet.

#Loading and security

A module runs inside the service with its full rights, like the kit's own code. Only the operator of the server installs modules.

  • Only the configured folder is read, never a path from a request or a map.
  • Modules Allow (Modules:Allow, or Modules__Allow__0, Modules__Allow__1 as environment variables) lists the dll names allowed. With it set, any other module stops the service.
  • The log names each module with its file and SHA-256. The assembly is loaded from the same bytes that were hashed.
  • Fail closed: a module that fails to load, configure its services, register its message handlers, map its endpoints or migrate stops the service with the error. A loose dll in the modules folder, or a folder without its dll, stops it too.
  • In Docker the module folders are mounted read-only.
  • Each module gets its own load context. Assemblies the service already has (the kit, ASP.NET Core, EF Core, Npgsql) always come from the service, so your module's interfaces and entities are the same types the service sees; anything else comes from the module's folder.

#Testing

AddKitModule registers a module made in code, without a folder, for tests or a host of your own:

services.AddKitModule<ICentralModule>(new BountiesModule(), configuration);

The kit's own tests (Services/Tests/ModuleTests.cs) run Central with test modules this way.

#Common mistakes

  • Copying the contract or EF Core into the module folder. Use Private=false and ExcludeAssets on the reference.
  • A module class without a public parameterless constructor. It can't be created.
  • Handling a kit message name. Central refuses to start.
  • Acting without Hosts. A map could act for players it doesn't hold.
  • Column types in migrations. They break on the other provider.
  • Endpoints without RequireAuthorization() that return private data.
  • Long work in a handler without a scope, or sharing one DbContext across handlers.
