Menus and settings options

How to add lines to the item menu and the player menu, and options to the Settings window, from code of your own.

All three are client-side lists the kit fills with its own entries at the start of every Play. You add yours after that, from a static method in the Game assembly.

#Item menu

Right click on an item in the bag or the gear opens the item menu (ItemMenu). Its lines come from ItemMenu.Entries, in order, starting with the kit's own: the action of the window open beside the bag (sell, store, offer), Equip, Take off, Use, Split, Salvage all, Possible values, View set and Destroy.

#ItemMenuEntry

Field What it is
string label The line's text.
Func<ItemMenuTarget, string> labelFor The text for this item, when it changes. Null uses label.
Func<ItemMenuTarget, bool> shows Whether the line shows for this item. Null always shows it.
Action<ItemMenuTarget> run What picking the line does.

#ItemMenuTarget

Member What it is
UIItem view The item's slot on screen.
InventoryWindow window The inventory window the menu opened from.
ItemContainer Container Bag, Equipment or Bank.
int Slot The slot index in that container.
ItemSlotState State What the slot holds: item id, amount, upgrade level, rolls.
IItem Item The item's data (ItemData and its subclasses implement it).
bool InBag Container == ItemContainer.Bag.

#Example: compare with what you wear

using Blunnyn.KitARPG.Client;
using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    public static class CompareLine
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
        static void Register()
        {
            ItemMenu.Entries.Add(new ItemMenuEntry
            {
                label = "Compare",
                shows = t => t.InBag && t.Item is IEquippable,
                run = t => CompareWindow.Instance?.Show((IEquippable)t.Item),
            });
        }
    }
}

(CompareWindow stands for a window of your own.)

#Example: insert a line at a position

Entries is a plain List<ItemMenuEntry>. Insert to place a line before the kit's Destroy:

int destroy = ItemMenu.Entries.FindIndex(e => e.label == "Destroy");
ItemMenu.Entries.Insert(destroy >= 0 ? destroy : ItemMenu.Entries.Count, myEntry);

#Lines that change the game

The menu runs on the client. A line that does something to the game asks the server, through a player system command or a network message, and the server checks everything again: that the slot holds that item, that the player may do it. The kit's own lines call PlayerInventory.Local.Equip(slot), Use(slot) and so on, which are requests. See Player systems and Network messages.

#Player menu

Right click on another player in top-down, or on a name in the chat, opens the player menu (PlayerMenu). Its lines come from PlayerMenu.Entries: Whisper, Trade, Invite to party, Make leader, Remove from party, Add friend, Invite to guild, Duel, Report and Give up the duel. Each kit line hides itself when its module is off.

#PlayerMenuEntry

Field What it is
string label The line's text.
Func<PlayerMenuTarget, bool> shows Whether the line shows for this player. Null always shows it.
Action<PlayerMenuTarget> run What picking the line does.

#PlayerMenuTarget

Field What it is
string name The character's name.
PlayerCharacter character The player on screen, or null when they were only named in the chat.

#Example: inspect a player's gear

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
static void Register()
{
    PlayerMenu.Entries.Add(new PlayerMenuEntry
    {
        label = "Inspect",
        shows = t => t.character != null,
        run = t => InspectWindow.Instance?.Show(t.character),
    });
}

Worn gear is synced to everyone who sees the player (PlayerCharacter.gear, item ids by equipment position), so an inspect window can read it on the client. The bag is private to the owner.

#Example: a line for one of your modules

PlayerMenu.Entries.Add(new PlayerMenuEntry
{
    label = "Challenge to a race",
    shows = t => t.character != null && RaceRules.Enabled,
    run = t => Races.Ask(t.name),
});

Races.Ask sends a request by name; the server finds the player by name on its map (PlayerCharacter.ServerFind(name)) and checks distance and rules.

#Settings window

The Settings window (Esc or the gear, then Settings, and on the title screen) has tabs: Graphics, Audio, Interface, plus Controls from the top-down mode, and any page you add. Each line is a GameOption in ClientOptions.All. Values live on the player's computer and never reach the server.

#Kinds of option

All have these fields:

Field What it is
string page The tab: ClientOptions.Graphics, ClientOptions.Audio, ClientOptions.Interface, or a new name, which becomes a new tab at the end.
string label The line's text.
string hint A short explanation.
Func<bool> available Hides the line when it says no, for options a platform doesn't have.
Action reset Puts the value back, for the tab's Reset button.
Kind Extra fields
ToggleOption Func<bool> get, Action<bool> set
SliderOption int min (0), int max (100), int step (5), Func<int> get, Action<int> set, Func<int, string> format (shows "50%" by default)
ChoiceOption Func<string[]> choices, Func<int> get, Action<int> set (the index)

ClientOptions.Add(option) adds one. Changes apply as the player makes them; the kit saves its own values when the window closes, and your set stores yours.

#Example: the template

using Blunnyn.KitARPG.Client;
using UnityEngine;

namespace Game
{
    /// <summary>
    /// An option of your own in the Settings window. Kept on the player's computer and never sent
    /// anywhere, so use it for how the game looks and sounds, not for anything the server decides.
    /// </summary>
    public static class MySettings
    {
        const string Key = "MyGame.ShowHints";

        public static bool ShowHints
        {
            get => PlayerPrefs.GetInt(Key, 1) == 1;
            set => PlayerPrefs.SetInt(Key, value ? 1 : 0);
        }

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
        static void Register()
        {
            ClientOptions.Add(new ToggleOption
            {
                // A page name the kit doesn't have becomes a new tab.
                page = ClientOptions.Interface,
                label = "Show hints",
                hint = "Short tips the first time something new shows up.",
                get = () => ShowHints,
                set = v => ShowHints = v,
                reset = () => ShowHints = true,
            });
        }
    }
}

#Example: a slider and a choice on a page of your own

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
static void Register()
{
    ClientOptions.Add(new SliderOption
    {
        page = "Gameplay",
        label = "Screen shake",
        min = 0, max = 100, step = 10,
        get = () => PlayerPrefs.GetInt("MyGame.Shake", 50),
        set = v => PlayerPrefs.SetInt("MyGame.Shake", v),
        reset = () => PlayerPrefs.DeleteKey("MyGame.Shake"),
    });

    ClientOptions.Add(new ChoiceOption
    {
        page = "Gameplay",
        label = "Damage numbers",
        choices = () => new[] { "All", "Mine only", "None" },
        get = () => PlayerPrefs.GetInt("MyGame.Numbers", 0),
        set = i => PlayerPrefs.SetInt("MyGame.Numbers", i),
        reset = () => PlayerPrefs.DeleteKey("MyGame.Numbers"),
    });
}

A slider moves in whole steps. Give every option a reset, so the tab's Reset button covers it.

available = () => Application.platform == RuntimePlatform.WindowsPlayer,

#What settings are for

Settings are for how the game looks, sounds and handles on that computer. Anything that affects other players or the rules (PvP on or off, loot sharing) belongs on the server, in a player system with a command, not in PlayerPrefs. For keys of your own, check GameInstance.KeysOn before reading them: with the Touch input layout the game's keys are off.

#When to register

The kit rebuilds ItemMenu.Entries and PlayerMenu.Entries from its own lines, and clears ClientOptions.All, in SubsystemRegistration at the start of every Play. Register yours in AfterAssembliesLoaded or later. The Settings window reads the list when it opens, so options added any time before that show up.

Map servers run in batch mode and never open these menus; registering there is harmless.

#Common mistakes

  • Registering in SubsystemRegistration. The kit may reset the list after you.
  • Doing the change in run. Menus are client code; ask the server.
  • No reset. The tab's Reset button leaves your option as it was.
  • Game rules in PlayerPrefs. Players can edit them.
