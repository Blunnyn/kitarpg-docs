DevKit

Editor extensions

How to add your own pages to the KitARPG window, your own checks to Project Check and the check before builds, and how to use the kit's editor look in your tools.

Where the files go: the Game.Editor assembly (see Assemblies). Everything on this page uses KitARPG.Editor and UnityEditor, which never go into a build.

#Pages in the KitARPG window

The KitARPG window (KitARPG > Open KitARPG, Ctrl/Cmd+Shift+K) has a sidebar of pages: Overview, Play & Servers, Game Database, Game Settings, Shop, Modules and Project Check. Every non-abstract subclass of KitPage with a parameterless constructor is found by Unity's TypeCache and added to the sidebar. There is nothing to register.

#KitPage

Member What it does Default
abstract string Name The page's name in the sidebar.
virtual string Group The sidebar heading it sits under. The kit uses "" (top), "Game" and "Project", in that order; other names go after them. "Game"
virtual int Order Order inside the group, lower first. Then by name. 100
virtual string IconName A built-in editor icon name, like "Settings" or "d_Favorite". "ScriptableObject Icon"
virtual string Badge Short text next to the name, like a count of problems. Null shows none. null
virtual KitGUI.State BadgeState The badge's color. Off
virtual bool FullWidth True gives the page the whole area instead of a centered scroll column, for pages with their own columns. false
virtual void OnEnable(), OnDisable() When the page is shown and hidden.
virtual void Tick() About ten times a second while the window is open, for polling.
abstract void OnGUI() Draws the page, with IMGUI.
KitWindow Window The window.
Rect Area The area the page draws in.
void Repaint() Asks the window to repaint.

The kit's pages use these orders: Overview 0 and Play & Servers 1 (group ""); Game Database 10, Game Settings 20, Shop 25, Modules 30 (group "Game"); Project Check 10 (group "Project").

KitWindow.Show<T>() opens the window on a page: KitWindow.Show<GameDatabaseWindow>(), KitWindow.Show<MyGamePage>().

#Example: a page for your content

Lists every bounty board in the project, with a button to select each and a warning badge when one is empty. The board type lives in the example's Game.Bounties assembly, so the editor assembly holding this page references it.

using System.Linq;
using Blunnyn.KitARPG.Editor;
using Game.Bounties;
using UnityEditor;
using UnityEngine;

namespace Game
{
    public class BountyBoardsPage : KitPage
    {
        BountyBoardData[] boards = new BountyBoardData[0];

        public override string Name => "Bounty Boards";
        public override int Order => 500;
        public override string IconName => "d_Favorite";

        int Empty => boards.Count(b => b != null && b.bounties.Length == 0);

        public override string Badge => Empty > 0 ? Empty.ToString() : null;
        public override KitGUI.State BadgeState => KitGUI.State.Warning;

        public override void OnEnable() => Load();

        void Load() => boards = AssetDatabase.FindAssets("t:BountyBoardData")
            .Select(g => AssetDatabase.LoadAssetAtPath<BountyBoardData>(AssetDatabase.GUIDToAssetPath(g)))
            .Where(b => b != null).ToArray();

        public override void OnGUI()
        {
            KitGUI.Header("Bounty Boards", "Every board asset in the project and its hunts.");
            if (boards.Length == 0) KitGUI.Empty("No boards yet", "Create one with Create > KitARPG > DevKit Example > Bounty Board.");
            foreach (BountyBoardData board in boards)
            {
                KitGUI.State state = board.bounties.Length == 0 ? KitGUI.State.Warning : KitGUI.State.Done;
                string detail = board.bounties.Length == 0 ? "No hunts" : $"{board.bounties.Length} hunts";
                if (KitGUI.Status(state, board.name, detail, "Select")) Selection.activeObject = board;
            }
            KitGUI.Line();
            if (KitGUI.Secondary("Refresh", 120)) Load();
        }
    }
}

#The kit's editor look

KitGUI (namespace Blunnyn.KitARPG.Editor) draws the cards, headers, status rows and buttons of the kit's windows, in plain IMGUI, so your pages match.

Member What it draws
Header(text, sub, icon) A page title with a line under it.
BeginCard(heading, sub, stripe) / EndCard(), or using (new KitGUI.CardScope(heading)) A rounded card.
Status(state, heading, detail, button, primaryButton) A checklist row with a colored light and an optional button; returns true when pressed.
Primary(text, width, height), Secondary(...) Buttons; return true when pressed.
Segmented(value, options, height) A segmented control; returns the picked index.
Switch(rect, on) An on/off switch.
Pill(text, color) A small colored label.
Tile(rect, value, caption, state) A number with a caption.
Empty(heading, detail) A placeholder for empty lists.
Message(text, state) A colored message line.
Line(space) A divider.
Icon(name) A built-in editor icon.
Accent, Good, Warn, Bad, Of(state) The palette, for light and dark editor skins.

KitGUI.State is Done, Todo, Warning, Error, Off and Busy (a pulsing light).

#Inspectors for your data

The kit's inspector for game data (GameDataEditor) draws every GameData asset as cards split by its [Header] attributes, and it applies to subclasses too. A GameData type of yours gets the same look without an editor of its own. Use [Header], [Tooltip] and [Range] on your fields and it reads like the kit's own data.

#Project checks

KitARPG > Project Check (the Project Check page) runs every check in ProjectValidator.Checks and lists what they find as errors, warnings and notes, each with a button to select what it is about and, when there is one, a button to fix it. The same list runs before every build, without opening scenes, and stops the build when there are errors (BuildCheck, which can be turned off on the Project Check page).

#ProjectValidator

Member What it is
static List<Action<List<ValidationIssue>>> Checks Every check, in order. Each adds what it finds to the list it is given. Add yours.
static List<ValidationIssue> Run(bool scenes = true) Runs them all. With scenes false, checks that open scenes are skipped, as before builds.
static bool IncludeScenes Whether the run in progress opens scenes. Read it in a check that would open scenes.

#ValidationIssue

Field What it is
IssueLevel level Error (stops builds), Warning or Info.
string area A short group name, like "My game".
string message One line saying what is wrong.
Object context The asset or object it is about; the Select button pings it.
string fixLabel Text of the fix button.
Action fix What the fix button does. Null shows no button.

#Registering a check

ProjectValidator.Checks is a static list that lives as long as the editor's domain. Register from [InitializeOnLoadMethod], which runs after every script reload, and remove before adding so a check never runs twice:

[InitializeOnLoadMethod]
static void Register()
{
    ProjectValidator.Checks.Remove(Check);
    ProjectValidator.Checks.Add(Check);
}

#Example: bounty boards with empty rewards, with a fix

using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Editor;
using Game.Bounties;
using UnityEditor;

namespace Game
{
    public static class BountyChecks
    {
        [InitializeOnLoadMethod]
        static void Register()
        {
            ProjectValidator.Checks.Remove(Check);
            ProjectValidator.Checks.Add(Check);
        }

        static void Check(List<ValidationIssue> issues)
        {
            foreach (string guid in AssetDatabase.FindAssets("t:BountyBoardData"))
            {
                var board = AssetDatabase.LoadAssetAtPath<BountyBoardData>(AssetDatabase.GUIDToAssetPath(guid));
                if (board == null) continue;
                for (int i = 0; i < board.bounties.Length; i++)
                {
                    BountyBoardData.Bounty bounty = board.bounties[i];
                    if (bounty.monster == null)
                        issues.Add(new ValidationIssue
                        {
                            level = IssueLevel.Error, area = "Bounties", context = board,
                            message = $"{board.name}: hunt {i + 1} has no monster.",
                        });
                    else if (bounty.rewards.Length == 0)
                    {
                        BountyBoardData.Bounty b = bounty;
                        issues.Add(new ValidationIssue
                        {
                            level = IssueLevel.Warning, area = "Bounties", context = board,
                            message = $"{board.name}: hunting {bounty.monster.DisplayName} pays nothing.",
                            fixLabel = "Add 100 gold",
                            fix = () =>
                            {
                                Undo.RecordObject(board, "Add bounty reward");
                                b.rewards = new GameAction[] { new GiveCurrencyAction { amount = 100 } };
                                EditorUtility.SetDirty(board);
                            },
                        });
                    }
                }
            }
        }
    }
}

#Guidelines for checks

  • Errors stop builds. Use Error only for things that will break in the game. Use Warning for likely mistakes and Info for suggestions.
  • Be fast. Checks run before every build. Avoid opening scenes unless ProjectValidator.IncludeScenes is true.
  • Point at the asset. Set context so the Select button works.
  • Fixes are safe. A fix must only add what is missing or correct one clear thing, with Undo and SetDirty.

#Finding the game's settings and database

ModulesWindow.Find() returns the project's GameInstance (the one on the KitNetwork prefab), cached for a few seconds. Its database field is the GameDatabase:

GameInstance game = ModulesWindow.Find();
GameDatabase database = game != null ? game.database : null;

GameDatabase.All<T>() lists every asset of a type and TryGet<T>(id, out T) finds one by id.

#Menu items

Plain Unity [MenuItem]s work as usual. To put yours next to the kit's, use the KitARPG/ root, as the example does with KitARPG > DevKit > Add Bounty Board to the Open Scene:

[MenuItem("KitARPG/My Game/Rebuild Recipes", priority = 200)]
static void Rebuild() { /* ... */ }

#Common mistakes

  • Editor code in Game. It references UnityEditor and the build fails. Use Game.Editor.
  • Registering a check without removing it first. It runs once more after every script reload.
  • Slow Tick or OnGUI. They run often; cache what you load, as the page above does in OnEnable.
  • A page without a parameterless constructor. It isn't found.
