Game modes in code

How control modes are built and registered, what a mode's client and server halves must do, and a complete skeleton for a mode of your own.

#How modes work

The game's control mode is a string in Game Settings > Game mode (GameInstance.controlMode): TopDown, FreeCamera or ThirdPerson in the kit. The same scenes play in every mode. Each mode is a set of components:

  • Client components, added to the main camera of each map scene: the camera and the input. They read the mouse, keys and touch controls, aim, and send requests to the server.
  • Server components, added to the network manager on the map server (and on the single player host): they receive the movement and action requests, check them, and move and act for the player.

GameModes (namespace Blunnyn.KitARPG.Net) keeps the list. When a map loads, the kit adds the playing mode's components and switches off every other mode's. The kit's modes live in their own assemblies: KitARPG.Modes.TopDown with KitARPG.Modes.TopDown.Server, and KitARPG.Modes.ThirdPerson with KitARPG.Modes.ThirdPerson.Server (which serves both third person and free camera).

#GameModes

Member What it does
const string TopDown, ThirdPerson, FreeCamera The kit's mode names.
string Current The playing mode: GameInstance.controlMode, or TopDown when empty.
bool Is(string mode) Whether that mode is playing (ignores case).
IEnumerable<string> Known Every mode a component was registered for.
void AddServer(string mode, Type component) Registers a server component for a mode.
void AddClient(string mode, Type component) Registers a client component for a mode.
void EquipServer(GameObject host), EquipClient(GameObject camera) Adds the playing mode's components and turns the rest off. The kit calls them.
bool HasClientParts(GameObject target) Whether the object carries a client component of any mode.

#When the kit equips

  • Server: when a map server starts, or the single player host starts a map, EquipServer runs on the network manager's object.
  • Client: when a scene loads whose main camera already carries a mode's client component, and again when the local player spawns, EquipClient runs on Camera.main. A component another mode registered is disabled; one the playing mode registered is added if missing and enabled.

Components shared between modes stay on: the kit's third person and free camera modes register the same classes.

#Registering

Register from SubsystemRegistration. Unlike the kit's other statics, the mode tables are never cleared, so registration order doesn't matter, and adding the same type twice is ignored:

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
static void RegisterMode()
{
    GameModes.AddClient("Grid", typeof(GridCamera));
    GameModes.AddClient("Grid", typeof(GridInput));
}

Server registration goes in a server-only assembly, with the server component:

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
static void RegisterMode() => GameModes.AddServer("Grid", typeof(GridServer));

#Picking your mode

The Game mode dropdown lists the kit's three modes plus every name in GameModes.Known. Registrations run when Play starts, so press Play once with your code compiled, then pick your mode from the dropdown. The name stays saved in GameInstance after that.

#Server and client must match

The client sends its mode with its ticket. A map server playing another mode refuses it with mode_mismatch ("The server plays a different game mode. Update the game."), because the client would send requests the server has no handler for. Build the client and the map server with the same Game mode.

#What a client half does

Job How
Camera Follow PlayerCharacter.Local (null until the player spawns).
Movement input Read KitInput (keys and mouse) and TouchControls.Axis("Move"); send requests.
Aim Set AimInput.Pointer to where the player aims: AimInput.Mouse, AimInput.Center (a crosshair) or a function of your own. The kit's skill aiming, previews and hotbar use it.
Actions Attack, talk, pick up: send the kit's messages or your own.
Respect the layout Check GameInstance.KeysOn before reading game keys: with the Touch layout the keys are off.
Turn itself off In OnEnable, return early when !GameModes.Is("YourMode"): scenes may carry your components while another mode plays.

The kit's own client code also sends requests that your server must answer, whatever the mode:

Message Sent by Fields
CastSkillMessage Skill aiming and the hotbar (AimInput) skillId, target (netId), point
PickupMessage Interact on touch and the F key (Interactables) drop
TalkMessage Same npc (the NPC's id)

Other messages the kit's modes use, which yours may reuse: MoveToMessage (destination), MoveDirectionMessage (direction), AttackMessage (target), SwingMessage (aim, target), PlayerInputMessage and MoveAckMessage (third person's predicted movement). They live in KitARPG.Net.

#What a server half does

A server half is a MonoBehaviour on the network manager's object. It:

  1. Registers its message handlers on every server start (the single player host restarts on each map change): subscribe to KitNetworkManager.ServerStarted and also register at once if NetworkServer.active.
  2. Takes over each player as it spawns (PlayerCharacter.ServerSpawned): its NavMeshAgent, its speed.
  3. Checks every request: pace, the sender's player from conn.identity, alive and loaded, finite positions, distances, line of sight (Sight.Clear), targets through Fighters.TargetFor.
  4. Acts through the kit's server methods:
To Call
Basic attack player.ServerTryAttack(target) (false while it recharges)
Cast a skill player.GetComponent<PlayerSkills>().ServerCast(skill, target, point) (checks mana, cooldown, range and target; returns why not)
Pick up Rewards.Instance.Pickup(player, dropId) (checks reach; returns an error code)
Talk player.GetComponent<PlayerInteraction>().ServerTalk(npc) after npc.InReach(...)
Can it move player.Statuses.CanMove, !player.Motion.Busy, !inventory.Overloaded
How fast player.Stats.moveSpeed
Attack reach player.AttackRange

TopDownServer and ThirdPersonServer are complete examples; read them before writing your own.

#A complete skeleton: a grid mode

A mode that walks one tile at a time with the arrow keys, on a 1 m grid, with a fixed camera. It reuses the kit's messages for actions.

#Shared message (Game assembly)

using Mirror;

namespace Game
{
    /// <summary>Client to server: one tile in a direction (-1, 0 or 1 on each axis).</summary>
    public struct GridStepMessage : NetworkMessage
    {
        public sbyte x;
        public sbyte z;
    }
}

#Client half (Game assembly)

using Blunnyn.KitARPG.Client;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using Mirror;
using UnityEngine;

namespace Game
{
    public class GridCamera : MonoBehaviour
    {
        public Vector3 offset = new Vector3(0, 12, -8);

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void RegisterMode()
        {
            GameModes.AddClient("Grid", typeof(GridCamera));
            GameModes.AddClient("Grid", typeof(GridInput));
        }

        protected virtual void LateUpdate()
        {
            PlayerCharacter player = PlayerCharacter.Local;
            if (player == null) return;
            transform.position = player.transform.position + offset;
            transform.LookAt(player.transform.position);
        }
    }

    public class GridInput : MonoBehaviour
    {
        public float repeatSeconds = 0.25f;
        float next;

        protected virtual void OnEnable()
        {
            if (!GameModes.Is("Grid")) return;
            AimInput.Pointer = AimInput.Mouse;
        }

        protected virtual void Update()
        {
            if (!NetworkClient.ready || PlayerCharacter.Local == null || !GameInstance.KeysOn) return;
            if (Time.unscaledTime < next) return;
            int x = (KitInput.GetKey(KeyCode.RightArrow) ? 1 : 0) - (KitInput.GetKey(KeyCode.LeftArrow) ? 1 : 0);
            int z = (KitInput.GetKey(KeyCode.UpArrow) ? 1 : 0) - (KitInput.GetKey(KeyCode.DownArrow) ? 1 : 0);
            Vector2 stick = TouchControls.Axis("Move");
            if (x == 0 && z == 0 && stick.sqrMagnitude > 0.25f)
            {
                x = Mathf.RoundToInt(stick.x);
                z = Mathf.RoundToInt(stick.y);
            }
            if (x == 0 && z == 0) return;
            next = Time.unscaledTime + repeatSeconds;
            NetworkClient.Send(new GridStepMessage { x = (sbyte)x, z = (sbyte)z });
        }
    }
}

#Server half (Game.Server assembly)

using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Server;
using Mirror;
using UnityEngine;
using UnityEngine.AI;

namespace Game
{
    public class GridServer : MonoBehaviour
    {
        static readonly Color Refused = new Color(1f, 0.5f, 0.45f);

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void RegisterMode() => GameModes.AddServer("Grid", typeof(GridServer));

        protected virtual void OnEnable()
        {
            PlayerCharacter.ServerSpawned += TakeOver;
            KitNetworkManager manager = GetComponent<KitNetworkManager>();
            if (manager != null) manager.ServerStarted += Register;
            if (NetworkServer.active) Register();
        }

        protected virtual void OnDisable()
        {
            PlayerCharacter.ServerSpawned -= TakeOver;
            KitNetworkManager manager = GetComponent<KitNetworkManager>();
            if (manager != null) manager.ServerStarted -= Register;
        }

        void Register()
        {
            NetworkServer.ReplaceHandler<GridStepMessage>(OnStep);
            NetworkServer.ReplaceHandler<AttackMessage>(OnAttack);
            NetworkServer.ReplaceHandler<CastSkillMessage>(OnCastSkill);
            NetworkServer.ReplaceHandler<PickupMessage>(OnPickup);
            NetworkServer.ReplaceHandler<TalkMessage>(OnTalk);
        }

        void TakeOver(PlayerCharacter player)
        {
            if (!player.TryGetComponent(out NavMeshAgent agent)) return;
            agent.enabled = true;
            agent.Warp(player.transform.position);
            agent.speed = player.Stats.moveSpeed > 0 ? player.Stats.moveSpeed : 3.5f;
        }

        static bool TryGetPlayer(NetworkConnectionToClient conn, out PlayerCharacter player)
        {
            player = conn.identity != null ? conn.identity.GetComponent<PlayerCharacter>() : null;
            return player != null && player.State != null && !player.Released && !player.IsDead;
        }

        void OnStep(NetworkConnectionToClient conn, GridStepMessage msg)
        {
            if (!CommandPacing.Allow(conn) || !TryGetPlayer(conn, out PlayerCharacter player)) return;
            if (Mathf.Abs(msg.x) > 1 || Mathf.Abs(msg.z) > 1 || (msg.x == 0 && msg.z == 0)) return;
            if (!player.Statuses.CanMove || player.Motion.Busy) return;
            if (player.TryGetComponent(out PlayerInventory inventory) && inventory.Overloaded) return;
            if (!player.TryGetComponent(out NavMeshAgent agent) || !agent.isOnNavMesh) return;
            Vector3 here = player.transform.position;
            Vector3 tile = new Vector3(Mathf.Round(here.x) + msg.x, here.y, Mathf.Round(here.z) + msg.z);
            if (NavMesh.SamplePosition(tile, out NavMeshHit hit, 0.5f, NavMesh.AllAreas)) agent.SetDestination(hit.position);
        }

        void OnAttack(NetworkConnectionToClient conn, AttackMessage msg)
        {
            if (!CommandPacing.Allow(conn) || !TryGetPlayer(conn, out PlayerCharacter player)) return;
            ICombatant target = Fighters.TargetFor(conn, player, msg.target);
            if (target == null || target.IsDead || !Fighters.Enemies(player, target)) return;
            Vector3 to = target.transform.position - player.transform.position;
            to.y = 0;
            if (to.magnitude > player.AttackRange + 0.5f || !Sight.Clear(player.transform.position, target.transform.position))
            {
                player.ServerAnnounce("Too far", Refused);
                return;
            }
            if (to.sqrMagnitude > 0.001f) player.transform.rotation = Quaternion.LookRotation(to);
            player.ServerTryAttack(target);
        }

        void OnCastSkill(NetworkConnectionToClient conn, CastSkillMessage msg)
        {
            if (!CommandPacing.Allow(conn) || !TryGetPlayer(conn, out PlayerCharacter player)) return;
            if (!player.TryGetComponent(out PlayerSkills skills) || skills.IsBusy) return;
            if (GameInstance.Database == null || !GameInstance.Database.TryGet(msg.skillId ?? "", out SkillData skill)) return;
            Vector3 p = msg.point;
            if (!float.IsFinite(p.x) || !float.IsFinite(p.y) || !float.IsFinite(p.z)) return;
            ICombatant target = Fighters.TargetFor(conn, player, msg.target);
            string error = skills.ServerCast(skill, target, p);
            if (error != null) player.ServerAnnounce(error, Refused);
        }

        void OnPickup(NetworkConnectionToClient conn, PickupMessage msg)
        {
            if (!CommandPacing.Allow(conn) || !TryGetPlayer(conn, out PlayerCharacter player) || Rewards.Instance == null) return;
            string error = Rewards.Instance.Pickup(player, msg.drop);
            if (error != null && player.TryGetComponent(out PlayerInventory inventory)) inventory.ServerError(error);
        }

        void OnTalk(NetworkConnectionToClient conn, TalkMessage msg)
        {
            if (!CommandPacing.Allow(conn) || !TryGetPlayer(conn, out PlayerCharacter player)) return;
            if (!Npc.TryFind(msg.npc, out Npc npc) || !player.TryGetComponent(out PlayerInteraction interaction)) return;
            if (!npc.InReach(player.transform.position))
            {
                player.ServerAnnounce("Too far", Refused);
                return;
            }
            interaction.ServerTalk(npc);
        }
    }
}

This skeleton leaves out what the kit's modes add on top: walking into range before attacking or casting, chasing targets, refreshing speed when stats change (player.ServerStatsChanged), and the third person mode's client prediction. Copy those parts from TopDownServer or ThirdPersonServer as your mode needs them.

#Reusing a kit mode's parts

You can register the kit's components under your own mode name, for example TopDownServer with a camera of yours. Read each component first: TopDownInput.OnEnable only sets up aiming when GameModes.Is(GameModes.TopDown), so under another name it leaves AimInput.Pointer to you. A mode that only changes the camera is often simpler as a different CameraSettings asset (third person and free camera read theirs from GameInstance.thirdPersonCamera and freeCamera).

#Single player and MMO

The same components run in both. In single player the host runs the server half and the client half in one process; the host restarts on each map change, which is why server halves register their handlers on every ServerStarted.

#Common mistakes

  • Server code in the client assembly. Put the server half in a .Server assembly so clients don't carry it.
  • Forgetting the kit's own messages. Without handlers for CastSkillMessage, PickupMessage and TalkMessage, the hotbar and the interact button do nothing in your mode.
  • Trusting positions from the client. Clamp distances, sample the NavMesh, check line of sight.
  • Client components that don't check GameModes.Is. They run in scenes where another mode plays.
  • Different modes on client and map server. Players get mode_mismatch.
