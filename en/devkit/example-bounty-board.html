DevKit

Example: bounty board

A walk through the DevKit example, file by file: a bounty board that hands out one hunt a day, counts kills, shows progress on the HUD, pays rewards, and keeps a ranking of the best hunters in Central. It is built only with the extension points in this section, without changing the kit.

#What it does

  1. A board in town is an NPC with a Bounties button.
  2. Each character gets one hunt a day from the board's list: kill a number of one monster. The hunt is the same all day for that character and different between characters.
  3. Kills count on the server and a line under the clock shows "Bounty: Slime 3/8".
  4. Back at the board, the button turns the hunt in and pays the rewards set on the board (gold, experience, anything the kit's actions can do).
  5. Online, every paid bounty goes to a module in Central, and /hunters shows the ten best hunters across all maps.

#Try it

  1. Open the Town or Forest scene.
  2. Pick KitARPG > DevKit > Add Bounty Board to the Open Scene. A wooden board appears at the Scene view's pivot, and the first time, a Sample Bounty Board asset is made from the first two normal monsters in your database. Save the scene.
  3. Play, walk to the board and press Today's bounty. Hunt; the line under the clock counts.
  4. Back at the board, press Turn in the bounty.
  5. To test quickly: /bounty done fills the kills and /bounty reset clears today's hunt (admin level; in single player every command works).
  6. Online: build the Central module and install it (see The Central module below), restart the services, and type /hunters.

#The files

#BountyBoardData.cs: the data

[CreateAssetMenu(menuName = "KitARPG/DevKit Example/Bounty Board", order = 900)]
public class BountyBoardData : ScriptableObject
{
    [Serializable]
    public class Bounty
    {
        public MonsterData monster;
        public int count = 10;
        [Tooltip("Paid on turning it in.")]
        [SerializeReference, PickType] public GameAction[] rewards = new GameAction[0];
    }

    public Bounty[] bounties = new Bounty[0];

    /// <summary>Today's bounty for a character. The same all day, different between characters.</summary>
    public int Pick(long characterId, int day) =>
        bounties.Length == 0 ? -1 : (int)((characterId * 31 + day) % bounties.Length);

    public Bounty At(int index) => index >= 0 && index < bounties.Length ? bounties[index] : null;
}
  • A plain ScriptableObject: only the example's code points at it, so it doesn't need to be a GameData with an id.
  • rewards is a list of the kit's actions with [SerializeReference, PickType], so designers pick Give Currency, Experience, Give Item or any action of yours from the same menu quests use. See Conditions and actions in code.
  • Pick derives the day's hunt from the character id and the day number, so nothing has to be stored to remember which hunt was offered.

#BountyOption.cs: the button

[Serializable]
public class BountyOption : NpcOption
{
    public BountyBoardData board;

    protected override string DefaultLabel => "Bounties";

    public override string LabelFor(PlayerCharacter player) =>
        Bounties.Current(player.Facts, out _) != null ? "Turn in the bounty" : "Today's bounty";

    public override bool AvailableTo(PlayerCharacter player) => board != null;

    public override string Run(Npc npc, PlayerCharacter player)
    {
        Bounties.Register(board);
        string answer = Bounties.Current(player.Facts, out _) != null ? Bounties.TurnIn(player) : Bounties.Take(player, board);
        if (player.TryGetComponent(out PlayerChat chat)) chat.Tell(answer);
        return null;
    }
}
  • LabelFor gives each player their own text.
  • AvailableTo hides the button on a board with no data.
  • Run already knows the player is next to the board: the kit checked reach before calling it. It answers in the chat with PlayerChat.Tell and returns null. See NPC options.

#Bounties.cs: the server rules

#Progress in flags

public const string BoardFlag = "bounty.board";
public const string IndexFlag = "bounty.index";
public const string KillsFlag = "bounty.kills";
public const string DayFlag = "bounty.day";
public const string DoneFlag = "bounty.done";
public const string LogKind = "bounty.done";

All progress is character flags, through IPlayerActor.SetFlag and Flag. They are saved with the character in single player and online, and synced to the owner, with no code for saving. The board is stored as a hash of its asset name (Animator.StringToHash(board.name)), the hunt as its index plus one (0 means none), and the day as days since 2020-01-01 UTC. See Saving data.

#Finding boards after a restart

static readonly Dictionary<int, BountyBoardData> boards = ...;
static bool scanned;

static BountyBoardData Board(int key)
{
    if (boards.TryGetValue(key, out BountyBoardData board) || scanned) return board;
    scanned = true;
    foreach (Npc npc in UnityEngine.Object.FindObjectsByType<Npc>(FindObjectsSortMode.None))
        foreach (NpcOption option in npc.AllOptions())
            if (option is BountyOption b && b.board != null) Register(b.board);
    boards.TryGetValue(key, out board);
    return board;
}

A character's flags point at a board by hash. After a server restart, nobody has used a board yet, so the first lookup scans the NPCs of the loaded scenes once (Npc.AllOptions() includes options nested in dialogue lines). A new scene resets the scan.

#Hooking in

// Cleared before anything subscribes, so listeners from other assemblies are never wiped.
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
static void ResetStatics()
{
    boards.Clear();
    scanned = false;
    ServerTurnedIn = null;
}

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
static void Hook()
{
    SceneManager.sceneLoaded -= OnSceneLoaded;
    SceneManager.sceneLoaded += OnSceneLoaded;
    Monster.ServerKilled -= OnKilled;
    Monster.ServerKilled += OnKilled;
    PlayerCharacter.LocalSpawned -= AskOnSpawn;
    PlayerCharacter.LocalSpawned += AskOnSpawn;
    KitNetworkManager manager = KitNetworkManager.Instance;
    if (manager == null) return;
    manager.ServerStarted += () => NetworkServer.ReplaceHandler<BountyAsk>(OnAsk);
    manager.ClientConnected += () => NetworkClient.ReplaceHandler<BountyState>(BountyTracker.Show);
}
  • ResetStatics clears the static state (boards, scanned and the ServerTurnedIn event) in SubsystemRegistration, at the start of each Play, because the project plays without domain reload. Clearing it there, before anything subscribes, lets BountyHunters in Game.Bounties.Server subscribe to ServerTurnedIn later without being wiped (see Play without domain reload).
  • Hook subscribes to static events with -= first, and before checking the network manager, so kills, spawns and scene loads are hooked even when the first scene has no KitNetworkManager.
  • Message handlers are registered on every server start and client connection (see Network messages).
  • Monster.ServerKilled counts kills on the server; PlayerCharacter.LocalSpawned asks for the state on the client.

#Taking a bounty

public static string Take(PlayerCharacter player, BountyBoardData board)
{
    IPlayerActor actor = player.Facts;
    if (actor.Flag(DayFlag) == Today && actor.Flag(IndexFlag) == 0) return "You already hunted today's bounty. Come back tomorrow.";
    int index = board.Pick(player.State.id, Today);
    BountyBoardData.Bounty bounty = board.At(index);
    if (bounty == null || bounty.monster == null) return "The board is empty.";
    actor.SetFlag(BoardFlag, Register(board));
    actor.SetFlag(IndexFlag, index + 1);
    actor.SetFlag(KillsFlag, 0);
    actor.SetFlag(DayFlag, Today);
    Send(player);
    return $"Today's bounty: slay {bounty.count} {bounty.monster.DisplayName}.";
}

Every decision uses server state: the character's flags and its database id. Nothing comes from the client.

#Counting kills

static void OnKilled(Monster monster, PlayerCharacter killer)
{
    if (killer == null || killer.State == null || monster.Data == null) return;
    IPlayerActor actor = killer.Facts;
    BountyBoardData.Bounty bounty = Current(actor, out _);
    if (bounty == null || bounty.monster != monster.Data) return;
    int kills = actor.Flag(KillsFlag);
    if (kills >= bounty.count) return;
    actor.SetFlag(KillsFlag, kills + 1);
    if (kills + 1 == bounty.count) killer.ServerAnnounce("Bounty complete! Turn it in at the board.", new Color(1f, 0.85f, 0.3f));
    Send(killer);
}

ServerKilled gives the player who earned the kill (it may be null). The count stops at the target.

#Turning in

public static string TurnIn(PlayerCharacter player)
{
    IPlayerActor actor = player.Facts;
    BountyBoardData.Bounty bounty = Current(actor, out _);
    if (bounty == null) return "You have no bounty.";
    int kills = actor.Flag(KillsFlag);
    if (kills < bounty.count) return $"{kills} of {bounty.count} {bounty.monster.DisplayName} so far.";
    string why = GameAction.RunAll(bounty.rewards, actor);
    if (why != null) return why;
    actor.SetFlag(IndexFlag, 0);
    actor.SetFlag(DoneFlag, actor.Flag(DoneFlag) + 1);
    GameLog.Write(LogKind, player, itemId: bounty.monster.Id, amount: bounty.count);
    ServerTurnedIn?.Invoke(player, bounty.monster);
    Send(player);
    return "Bounty paid. Well hunted.";
}
  • GameAction.RunAll checks every reward first (a full bag refuses Give Item), then pays them all.
  • GameLog.Write writes a bounty.done line; moderators find it with /logs (see Game log and reports).
  • ServerTurnedIn is the example's own event, raised in Game.Bounties and listened to by Game.Bounties.Server, which online clients don't have.

#Telling the client

public static void Send(PlayerCharacter player)
{
    BountyBoardData.Bounty bounty = Current(player.Facts, out _);
    player.connectionToClient?.Send(bounty == null
        ? new BountyState()
        : new BountyState { monster = bounty.monster.DisplayName, kills = player.Facts.Flag(KillsFlag), required = bounty.count });
}

static void AskOnSpawn(PlayerCharacter _) => NetworkClient.Send(new BountyAsk());

// The connection says who asks; the message carries nothing to trust.
static void OnAsk(NetworkConnectionToClient conn, BountyAsk _)
{
    if (!CommandPacing.Allow(conn)) return;
    if (conn.identity != null && conn.identity.TryGetComponent(out PlayerCharacter player) && player.State != null) Send(player);
}

The client's request is empty: the server knows who asked from the connection. It is paced with CommandPacing.

public struct BountyAsk : NetworkMessage { }

#BountyTracker.cs: the HUD line

public static void Show(BountyState state)
{
    if (label == null) Build();
    if (label == null) return;
    bool has = !string.IsNullOrEmpty(state.monster);
    label.gameObject.SetActive(has);
    if (!has) return;
    bool done = state.kills >= state.required;
    label.text = done
        ? $"<color=#F5D67F>Bounty: {state.monster} {state.kills}/{state.required}, turn it in</color>"
        : $"Bounty: {state.monster} {state.kills}/{state.required}";
}

static void Build()
{
    GameObject hud = GameInstance.Hud;
    Canvas canvas = hud != null ? hud.GetComponentInChildren<Canvas>() : null;
    if (canvas == null) return;
    var go = new GameObject("Bounty Tracker", typeof(RectTransform));
    go.transform.SetParent(canvas.transform, false);
    // anchored to the top right, under the clock
    ...
}

GameInstance.Hud is the running HUD instance. The line is built from code the first time a state arrives. For a real game, put your UI in the HUD prefab instead, so designers can move and style it (and ship it to existing games with a kit update). The static label is reset in SubsystemRegistration.

#BountiesDoneCondition.cs: a condition for designers

[Serializable]
public class BountiesDoneCondition : Condition
{
    public int atLeast = 5;

    protected override string DefaultText => $"Needs {atLeast} bounties done";

    public override bool Met(IPlayerFacts facts) => facts.Flag(Bounties.DoneFlag) >= atLeast;
}

It reads a flag, which the owner's client has too, so quest markers and locked lines show correctly. Designers can put it on a shop option that opens after five bounties, a quest, or a greeting.

#Server/BountyCommands.cs: the GM command

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
static void Register()
{
    GmCommands.Register(new GmCommand
    {
        name = "bounty", rank = GmRank.Admin, usage = "bounty reset|done [player]", description = "Clears a player's bounty for today, or fills its kills.",
        run = c =>
        {
            PlayerCharacter target = c.Target(1);
            if (target == null) return "Nobody by that name here.";
            IPlayerActor actor = target.Facts;
            switch (c.Arg(0))
            {
                case "reset":
                    actor.SetFlag(Bounties.DayFlag, 0);
                    actor.SetFlag(Bounties.IndexFlag, 0);
                    break;
                case "done":
                    BountyBoardData.Bounty bounty = Bounties.Current(actor, out _);
                    if (bounty == null) return $"{target.characterName} has no bounty.";
                    actor.SetFlag(Bounties.KillsFlag, bounty.count);
                    break;
                default:
                    return "Usage: /bounty reset|done [player]";
            }
            Bounties.Send(target);
            return $"Bounty of {target.characterName}: {c.Arg(0)}.";
        },
    });
}

It lives in Game.Bounties.Server, so client builds leave it out. Admin level means every use is audited. See GM commands in code.

#Server/BountyHunters.cs: Central and saved history

public const string HistoryKey = "bounties.history";

[Serializable]
public class History
{
    public List<string> monsters = new List<string>();
}

static void OnTurnedIn(PlayerCharacter player, MonsterData monster)
{
    History history = PlayerData.Get<History>(player, HistoryKey);
    history.monsters.Insert(0, monster.DisplayName);
    if (history.monsters.Count > HistorySize) history.monsters.RemoveRange(HistorySize, history.monsters.Count - HistorySize);
    PlayerData.Set(player, HistoryKey, history);
    // Offline the board just misses this one; the character's own history still has it.
    CentralMessages.Send(new BountyFinished { characterId = player.State.id, name = player.characterName, monster = monster.Id });
}
  • Each character keeps its last ten hunts with PlayerData, saved with the character and never sent to clients.
  • Each paid bounty goes to Central. Send returns false in single player or while Central is away, and nothing is queued: the ranking misses that one, the history doesn't.
CentralMessages.On<BountyBoardList>(OnBoard);
GmCommands.Register(new GmCommand
{
    name = "hunters", rank = GmRank.Player, usage = "hunters", description = "The best bounty hunters on every map, and your last hunts.",
    run = c =>
    {
        string mine = Last(c.player);
        if (!CentralMessages.Online) return "The hunters board is kept online." + mine;
        CentralMessages.Send(new BountyBoardAsk { characterId = c.player.State.id });
        return "Asking the guild of hunters..." + mine;
    },
});

static void OnBoard(BountyBoardList board)
{
    var text = new StringBuilder("Best bounty hunters:");
    int rank = 1;
    foreach (BountyHunter hunter in board.top ?? new BountyHunter[0])
        text.Append($"\n{rank++}. {PlayerText.NoTags(hunter.name)}: {hunter.bounties}");
    if (rank == 1) text.Append("\nNobody yet.");
    text.Append($"\nYou: {board.mine}");
    SocialHub.Notice(board.characterId, text.ToString());
}
  • /hunters is a player-level command: a chat feature, not a staff tool, so it isn't audited.
  • The answer comes back later through CentralMessages.On and is shown in the asker's chat with SocialHub.Notice.
  • Names that came from players are shown with PlayerText.NoTags.

See Talking to Central.

#Shared/BountyBoardMessages.cs: messages for Central

// Messages between the map servers and the Bounties module in Central. Plain C# with public fields,
// so Unity's JsonUtility and the service's System.Text.Json read them alike. The service links this file.
namespace Game.Bounties
{
    [Serializable] public class BountyFinished { public long characterId; public string name; public string monster; }
    [Serializable] public class BountyBoardAsk { public long characterId; }
    [Serializable] public class BountyHunter { public string name; public int bounties; }
    [Serializable] public class BountyBoardList { public long characterId; public BountyHunter[] top = new BountyHunter[0]; public int mine; }
}

In Game.Bounties.Shared, an assembly with no engine references. Unity compiles it, and the Central module links the same file, so both sides always agree.

#Editor/BountySetup.cs: the setup menu

KitARPG > DevKit > Add Bounty Board to the Open Scene:

  • builds a board from three cubes at the Scene view's pivot, with an Npc (id bounty_board, name Bounty Board), a BoxCollider for clicks and a Nameplate,
  • adds a BountyOption pointing at Sample Bounty Board,
  • makes Sample Bounty Board the first time, next to the script, from the first two normal monsters with a prefab in the game database: 8 and 10 kills, paying 150 and 200 gold and 200 and 300 experience,
  • registers Undo and marks the scene dirty.

It uses ModulesWindow.Find() to reach the game's database. See Editor extensions.

#The Central module

Services/Examples/Bounties/ is the Central side:

File What it does
Game.Bounties.Central.csproj References the module contract without copying it, links BountyBoardMessages.cs, and copies the build to -p:KitModulesDir.
BountiesModule.cs ICentralModule named Bounties. Registers BountyContext, handles BountyFinished (validates the name, 1 to 32 characters, and m.Hosts(characterId), then adds one to the row under a SemaphoreSlim) and BountyBoardAsk (answers the top 10 and the asker's own count).
BountyContext.cs The bounty_hunters table: character_id (key), name, count (indexed).
Migrations/ One migration with no column types, so it runs on SQLite and PostgreSQL.

Build and install it:

cd Services
dotnet build Examples/Bounties -c Release -p:KitModulesDir=<launcher folder>/modules/central
dotnet build Examples/Bounties -c Release -p:KitModulesDir=../Deploy/modules/central   # Docker

Restart Central. Its log shows Module Bounties loaded from .... The full code and the rules for modules are on Service modules.

#Make it yours

  • Add hunts to Sample Bounty Board, or make other board assets with Create > KitARPG > DevKit Example > Bounty Board. Any reward the kit's actions can give fits.
  • Swap the flags for a player system when you need synced state beyond a few numbers.
  • Add a quest objective that counts bounties, advanced from Bounties.ServerTurnedIn.
  • Copy the folder structure (feature assembly, .Server, .Shared, .Editor) for your own features.
  • In your own code, clear static events in SubsystemRegistration and subscribe to them in AfterAssembliesLoaded or later, so the order of startup methods never matters.
  • Delete DevKit/Example/Bounties to remove the example. Remove the board from your scenes first: they reference BountyOption.
