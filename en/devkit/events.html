DevKit

Events

Every event the kit raises that your code can listen to, where it runs, what it hands you, how to subscribe so it survives Play without domain reload, and examples.

#Static events

Most kit events are static: you subscribe once, for every player or monster, from a static class of yours. They come in three kinds:

  • Server events start with Server and run on the map server (and the single player host). Use them for rules: rewards, progress, logging.
  • Owner's client events run on the client of the player concerned. Use them for the interface.
  • Client events run on every client that sees the thing, such as combat effects.

#Subscribing correctly

The kit's project plays without domain reload, so every class clears its static events in a SubsystemRegistration method at the start of each Play. Unity doesn't define the order between SubsystemRegistration methods, so subscribe later, in AfterAssembliesLoaded:

public static class LevelRewards
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
    static void Hook()
    {
        PlayerCharacter.ServerLeveledUp -= OnLevel;
        PlayerCharacter.ServerLeveledUp += OnLevel;
    }

    static void OnLevel(PlayerCharacter player) { /* ... */ }
}

The -= before += keeps you from subscribing twice if the method ever runs again. Subscribe with named methods, not lambdas, so -= works. AfterSceneLoad works too; it runs later.

See Play without domain reload for the full rules.

#Server events

Event Arguments Raised when
PlayerCharacter.ServerSpawned PlayerCharacter A player spawns on this map, after its saved state loaded.
PlayerCharacter.ServerLeveledUp PlayerCharacter After one or more levels were gained.
PlayerCharacter.ServerExperienceGained PlayerCharacter, long amount Experience was earned, before level ups.
Monster.ServerKilled Monster, PlayerCharacter killer A monster died. The killer is the player that earned the kill, or null.
Monster.ServerPhaseStarted Monster, int phase A boss started a phase; the index is into its data's phases.
PlayerQuests.ServerCompleted PlayerCharacter, QuestData A quest was turned in.
PlayerTrade.ServerTraded PlayerCharacter a, PlayerCharacter b A trade went through.
PlayerForge.ServerUpgraded PlayerCharacter, string itemId, bool success, int level An upgrade worked (true) or failed (false); level is where it ended, -1 when the piece broke.
PlayerProgress.ServerFlagChanged PlayerCharacter, string key, int value A character flag changed.
PlayerProgress.ServerDiscovered PlayerCharacter, string placeId A map or zone was discovered.
PlayerPvp.ServerDefeated PlayerCharacter killer, PlayerCharacter victim, bool duel A player beat another, in PvP or a duel.
WorldTrigger.ServerFired WorldTrigger, PlayerCharacter A world trigger went off (for "everyone" triggers, the player who set it off).
GmCommands.ServerUsed PlayerCharacter, string line A slash command is about to run. Server-only assembly.
GmAudit.Recorded GmAuditEntry A GM audit line was recorded. Server-only assembly.
MapInstances.ServerChanged string key, bool made A copy of an instanced map was made (true) or let go. Server-only assembly.
GameLog.Written GameLogEntry Any game log line, as it is written.

#Client events for effects

CombatEvents (namespace Blunnyn.KitARPG.Net) tells every client what happened in combat nearby, for animations, effects, damage numbers and sounds:

Event Arguments
CombatEvents.Damaged Transform who, int amount, bool critical, DamageElement element, GameData source
CombatEvents.Healed Transform who, int amount, GameData cause
CombatEvents.Announced Transform who, string text, Color color (short text over someone, like "+12 XP")
CombatEvents.Shouted Transform boss, string text (a boss phase line)
CombatEvents.SkillLanded Transform caster, SkillData skill, Vector3 point
CombatEvents.ActionStarted ActionEvent
CombatEvents.CastStarted, CastStopped Transform, SkillData, float seconds; Transform
CombatEvents.Bounced SkillData, Transform from, Transform to
CombatEvents.ZoneStarted SkillData, Vector3 where, float seconds
FighterStatus.AnyChanged FighterStatus (any fighter's statuses changed)

Other client-wide events: GameRates.Changed (RatesState, an experience or loot event started or ended), ClientOptions.Changed (a setting changed).

Per-object client events: Monster.Acted (CombatAction) and DeadChanged (bool) on monsters, DeadChanged on players.

#Network manager events

KitNetworkManager.Instance raises ServerStarted, ServerStopping, ServerDisconnecting (NetworkConnectionToClient), ClientConnected and ClientDisconnected. These are instance events on an object that is made again each Play, and the old object goes away with its subscribers, so subscribe in AfterSceneLoad without -=. Static events still get -= first: subscribe to them before checking Instance for null, so they are hooked even in a scene without the network manager. See Network messages.

#Examples

#Reward every fifth level

Server, in the Game assembly:

using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    public static class MilestoneRewards
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
        static void Hook()
        {
            PlayerCharacter.ServerLeveledUp -= OnLevel;
            PlayerCharacter.ServerLeveledUp += OnLevel;
        }

        static void OnLevel(PlayerCharacter player)
        {
            if (player.level % 5 != 0) return;
            // A flag per milestone, so leveling down and up again (death penalties) pays once.
            string key = $"mygame.milestone_{player.level}";
            IPlayerActor actor = player.Facts;
            if (actor.Flag(key) != 0) return;
            actor.SetFlag(key, 1);
            actor.AddCurrency(null, player.level * 100);
            player.ServerAnnounce($"Level {player.level} milestone!", new Color(1f, 0.85f, 0.3f));
        }
    }
}

#Welcome back message

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
static void Hook()
{
    PlayerCharacter.ServerSpawned -= OnSpawned;
    PlayerCharacter.ServerSpawned += OnSpawned;
}

static void OnSpawned(PlayerCharacter player)
{
    if (player.TryGetComponent(out PlayerChat chat)) chat.Tell($"Welcome back, {player.characterName}.");
}

ServerSpawned fires on every map a character enters, not only on login.

#Kill streaks, kept in memory

static readonly Dictionary<PlayerCharacter, int> streaks = new Dictionary<PlayerCharacter, int>();

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
static void ResetStatics() => streaks.Clear();

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
static void Hook()
{
    Monster.ServerKilled -= OnKilled;
    Monster.ServerKilled += OnKilled;
    PlayerPvp.ServerDefeated -= OnDefeated;
    PlayerPvp.ServerDefeated += OnDefeated;
}

static void OnKilled(Monster monster, PlayerCharacter killer)
{
    if (killer == null) return;
    streaks.TryGetValue(killer, out int n);
    streaks[killer] = ++n;
    if (n % 10 == 0) killer.ServerAnnounce($"{n} kills!", Color.yellow);
}

static void OnDefeated(PlayerCharacter killer, PlayerCharacter victim, bool duel) => streaks.Remove(victim);

Dictionaries keyed by players grow as players come and go. Remove entries when they leave (KitNetworkManager.ServerDisconnecting) or skip destroyed ones (player == null).

#A sound on critical hits

Client, in the Game assembly. The clip is loaded from a Resources folder of yours:

static AudioClip clip;

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
static void Hook()
{
    clip = Resources.Load<AudioClip>("MyGame/CriticalHit");
    CombatEvents.Damaged -= OnDamaged;
    CombatEvents.Damaged += OnDamaged;
}

static void OnDamaged(Transform who, int amount, bool critical, DamageElement element, GameData source)
{
    if (critical && clip != null) GameAudio.PlayAt(clip, who.position, SoundChannel.Effects);
}

GameAudio.PlayAt respects the player's volume sliders.

#Send rare loot to a webhook

GameLog.Written sees every log line, including item.loot for notable drops. See the Game Log Listener template on Templates.

#Events of your own

Raise your own static events the same way, and clear them in SubsystemRegistration:

public static event Action<PlayerCharacter, MonsterData> ServerTurnedIn;

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
static void ResetStatics() => ServerTurnedIn = null;

Code in Game.Server then subscribes to events raised in Game (see Assemblies).

#Common mistakes

  • Subscribing in SubsystemRegistration. The kit may clear the event after you subscribed.
  • Subscribing with a lambda you can't remove, in a method that may run twice.
  • Server events in client code. They never fire on an online client.
  • Heavy work in CombatEvents or GameLog.Written. They fire often; keep handlers short.
  • Throwing in a handler. Other subscribers after you may not run. GameLog.Written catches exceptions; most other events don't.
