Formulas

How to change the game's math without touching the kit: the CombatFormula for damage, healing, attack speed and experience, and the StatFormula for how class, level, attributes and gear add up to stats.

#How formulas are installed

The kit keeps two formula objects on GameInstance:

Property Type Decides
GameInstance.Combat CombatFormula Damage, damage over time ticks, heals, time between attacks, experience per kill
GameInstance.Formula StatFormula Stat sheets, attribute points and skill points earned per level

Both are plain C# classes in KitARPG.Data with virtual methods. To change a rule, subclass one, override what you need and assign an instance at startup:

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
static void Install() => GameInstance.Combat = new MyCombatFormula();

The kit puts its own formulas back in SubsystemRegistration on every Play (see Play without domain reload). BeforeSceneLoad runs after that and before any scene, so nothing fights before your formula is in place.

Where the file goes: the Game assembly, so every build installs it. The server is what applies formulas, but the client uses Combat.Experience too: the bestiary shows the experience a monster gives the local player. A formula only in Game.Server would make the bestiary disagree with what players earn.

#CombatFormula

Method Called when What it returns
Hit Attack(StatSheet attacker, IReadOnlyList<ElementDamage> rolls, StatSheet defender, float scale = 1) Basic attacks of players and monsters, and DamageEffect on skills The hit: total, critical, main element
float Element(StatSheet attacker, DamageElement element, float roll, StatSheet defender) By Attack and Tick, for each element's share That element's damage after resistances
Hit Tick(StatSheet caster, DamageElement element, float amount, StatSheet holder) Each tick of a damage over time status The tick's hit, never critical, at least 1
int Heal(StatSheet healer, float amount) HealEffect and healing statuses The final heal
float AttackInterval(float attacksPerSecond, StatSheet attacker) Every basic attack of players and monsters Seconds until the next attack
long Experience(MonsterData monster, int playerLevel) A kill, for the killer and each party member sharing it; the bestiary Experience before bonuses and rates

#The kit's rules

  • Attack: each roll is worked out apart for its element. The roll (a random value between its min and max, times scale) plus the attacker's damage for that element, grown by the attacker's power. Then the defender's flat resistance to that element is taken off, then its percent resistance, capped at the element's Max Resistance (maxResistance, 0.5 when the roll has no element). The totals add up. A critical hit (chance critChance) multiplies the total by 1 + critDamage. The result is rounded and at least 1.
  • Tick: the same element rule with the caster's stats as they were when the status landed; not critical.
  • Heal: (amount + healer.healing) * (1 + healer.healingBonus), rounded.
  • Attack interval: 1 / (attacksPerSecond * (1 + attackSpeed)), with at least 0.1 attacks per second.
  • Experience: the monster's experience in full up to 3 levels below the player; then 20% less for each level further below, down to 10%.

After Experience, the kit applies the player's experience gain stat, the server's rates (experienceRate and events from /rates) and party sharing. Your formula returns the base amount.

#StatSheet

What attacker, defender and healer are:

Member What it is
CharacterStats stats maxHealth, maxMana, healthRegen, manaRegen, power, critChance, critDamage, healing, healingBonus, attackSpeed, moveSpeed, carryWeight, experienceGain, lootChance. Shares are fractions: critChance 0.05 is 5%.
ElementStats Element(DamageElement e) The element's damage, resistance and resistancePercent. A null element reads the fallback.
int Attribute(AttributeData a) An attribute's total.
DamageElement fallback The game's default element.

#Example: harsher level gap

Monsters far below the player give nothing at all after 8 levels:

using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    public class MyCombatFormula : CombatFormula
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
        static void Install() => GameInstance.Combat = new MyCombatFormula();

        public override long Experience(MonsterData monster, int playerLevel)
        {
            int gap = playerLevel - monster.level;
            if (gap >= 8) return 0;
            return base.Experience(monster, playerLevel);
        }
    }
}

#Example: armor from an attribute

A flat reduction from an attribute of your game (here one with id toughness), applied to every element before the percent resistance:

public class ToughnessFormula : CombatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Combat = new ToughnessFormula();

    AttributeData toughness;

    public override float Element(StatSheet attacker, DamageElement element, float roll, StatSheet defender)
    {
        if (toughness == null) GameInstance.Database.TryGet("toughness", out toughness);
        float damage = base.Element(attacker, element, roll, defender);
        int points = toughness != null ? defender.Attribute(toughness) : 0;
        return Mathf.Max(0, damage - points * 0.5f);
    }
}

toughness is an instance field: Install makes a new formula on every Play, so the cached asset starts empty each time, even without domain reload. A static cache would outlive Play and keep an old reference if the database changed between Plays; reset such statics in SubsystemRegistration (see Play without domain reload).

#Example: capped critical chance and attack speed

using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using UnityEngine;

public class CappedFormula : CombatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Combat = new CappedFormula();

    public override Hit Attack(StatSheet attacker, IReadOnlyList<ElementDamage> rolls, StatSheet defender, float scale = 1)
    {
        // Capped for this attack only, then put back.
        float chance = attacker.stats.critChance;
        attacker.stats.critChance = Mathf.Min(chance, 0.5f);
        try { return base.Attack(attacker, rolls, defender, scale); }
        finally { attacker.stats.critChance = chance; }
    }

    public override float AttackInterval(float attacksPerSecond, StatSheet attacker) =>
        Mathf.Max(0.25f, base.AttackInterval(attacksPerSecond, attacker));
}

stats is a struct field on the sheet, so the change is made and undone around the base call.

#StatFormula

Method Called when Returns
StatSheet Sheet(CharacterClass characterClass, int level, IReadOnlyList<AttributeAmount> spent, GameDatabase database, IReadOnlyList<IStatSource> sources = null) Every time a player's stats are worked out (PlayerCharacter.RecalculateStats: level, attributes, gear or buffs changed), and for new characters in single player The full sheet
int PointsEarned(CharacterClass characterClass, int level) Level ups Attribute points earned by that level
int SkillPointsEarned(CharacterClass characterClass, int level) Skill point totals Skill points earned by that level

#The kit's order

  1. The class's attributes at this level, then the spent points, then attribute bonuses from every source (gear, buffs, passives).
  2. The class's base stats plus its stats per level times level - 1.
  3. Each attribute's Per Point stats times its total.
  4. Every source's stat modifiers. Percent bonuses apply last.

The defaults for points are the class's Points Per Level (pointsPerLevel, 5) and Skill Points Per Level (skillPointsPerLevel, 1), times level - 1.

Monsters don't use the stat formula; their stats come from their data.

#Example: two attribute points per level

public class MyStatFormula : StatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Formula = new MyStatFormula();

    // Two attribute points per level instead of the class's own number.
    public override int PointsEarned(CharacterClass characterClass, int level) => 2 * (level - 1);
}

#Example: health that grows by a share per level

using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Shared.Characters;
using UnityEngine;

public class GrowingHealthFormula : StatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Formula = new GrowingHealthFormula();

    public override StatSheet Sheet(CharacterClass characterClass, int level, IReadOnlyList<AttributeAmount> spent,
        GameDatabase database, IReadOnlyList<IStatSource> sources = null)
    {
        StatSheet sheet = base.Sheet(characterClass, level, spent, database, sources);
        // +2% max health per level after the first, kept whole.
        sheet.stats.maxHealth = Mathf.Round(sheet.stats.maxHealth * (1 + 0.02f * (level - 1)));
        return sheet;
    }
}

Stats in the kit are whole numbers and percent bonuses are whole points. Round what you add, as above, so tooltips and sheets agree.

#Example: a skill point every other level

public override int SkillPointsEarned(CharacterClass characterClass, int level) => (level - 1) / 2;

#Changing the rules on a live game

Formulas decide new numbers; they don't rewrite saved ones. Changing PointsEarned changes what is earned from now on. Characters keep the points they have: free points are stored and only the difference at each level up is added. If you lower the points per level on a live game, give players a way to start over (the kit's ResetAttributesAction or Scroll of Second Thoughts).

#Server and client

Server Client
Attack, Element, Tick, Heal, AttackInterval Yes No
Experience Yes The bestiary
Sheet, PointsEarned, SkillPointsEarned Yes No; the owner receives the finished sheet

Online, a formula in a client build that differs from the map server's only changes what that client's bestiary shows. Single player runs both halves in one process.

#Common mistakes

  • Installing in SubsystemRegistration. The kit resets the formulas there; the order is undefined.
  • Installing only in Game.Server. The bestiary on clients then shows the kit's numbers.
  • Returning decimals from Sheet. Round your additions.
  • Keeping per-fighter state in the formula. One instance serves every fighter on the map.
  • Applying rates inside Experience. The kit applies the experience stat and server rates after it, so they would count twice.
