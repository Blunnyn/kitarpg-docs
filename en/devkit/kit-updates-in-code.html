Kit updates in code

How to ship changes to games that were already made with your package or template: the KitUpdate class, how Overview finds and applies updates, and complete examples that add a component to every player prefab and a setting to the game.

#What a kit update is

When a new version of KitARPG adds something a game needs (a currency, a component on the player, a window in the HUD), it can't rebuild the buyer's prefabs and data: that would erase their changes. Instead it ships an update: a small class that checks whether the thing is missing and, when asked, adds only that.

You can do the same. If you sell or reuse a package built on KitARPG (a template game, a module you share between your projects), each of your releases can bring updates for the games already made with it. They show in the same list as the kit's own.

Where the file goes: a Game.Editor assembly (or the editor assembly of your package).

#Where updates show

  • Overview in the KitARPG window shows how many updates are waiting, with Apply.
  • Project Check lists each one as a warning with an Apply button.
  • Play & Servers and the Shop page warn when updates are waiting.

Apply opens a dialog that lists every waiting update with its Title and Changes, followed by "Nothing else changes". After confirming, each still needed update runs in Order. Updates can't be applied during Play.

#The KitUpdate class

KitUpdate lives in Blunnyn.KitARPG.Editor. Every non-abstract subclass with a parameterless constructor is found through Unity's TypeCache.

Member What it does Default
abstract string Title One line, like "Shop window in the HUD".
abstract string Changes Exactly what Apply will change, shown before it runs. Name the assets and fields.
abstract bool Needed() True when the project lacks it. Called every few seconds by the windows (the answer is cached about two seconds), so keep it cheap.
abstract string Apply() Makes the change and returns what it did. Throw an exception to report that it couldn't.
virtual int Order Lower runs first, for updates that rely on another. The kit uses 10 to 80. 100

KitUpdates runs them:

Member What it does
KitUpdates.All Every update, in order.
KitUpdates.Pending() The updates whose Needed() is true now.
KitUpdates.Run(update, out string result) Runs one, saves assets, logs the result. False when it threw.
KitUpdates.ApplyAll(updates) Asks once with the list, then runs those still needed.

An exception in Needed() is logged as a warning and the update is treated as not needed.

#Rules for a good update

  • Only add what is missing. Check for the exact thing (a component, a field value, an asset) and add only that.
  • Never rebuild. Don't recreate a prefab, a HUD or a data asset; load it, change one thing, save it.
  • Find things the way the game has them. Buyers rename and move assets. Look them up through GameInstance and the game database (ModulesWindow.Find()), not by path.
  • Be idempotent. After Apply, Needed() must return false. Running twice must change nothing the second time.
  • Say what changed. Changes before, the returned string after.

#Example: the template

Create > KitARPG > Scripts > Kit Update (Editor) adds a word to the chat filter:

using System.Linq;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Editor;
using UnityEditor;

namespace Game
{
    /// <summary>
    /// Something your own package adds to games already made with it. It shows in Overview with Apply
    /// next to the kit's updates. Only add what is missing; never rebuild what the game changed.
    /// </summary>
    public class MyGameUpdate : KitUpdate
    {
        const string Word = "badword";

        public override string Title => "My game: chat filter word";
        public override string Changes => $"Game Settings > Chat: adds \"{Word}\" to the blocked words.";

        public override bool Needed()
        {
            GameInstance game = ModulesWindow.Find();
            return game != null && !game.blockedWords.Contains(Word);
        }

        public override string Apply()
        {
            GameInstance game = ModulesWindow.Find();
            game.blockedWords = game.blockedWords.Append(Word).ToArray();
            EditorUtility.SetDirty(game);
            AssetDatabase.SaveAssets();
            return $"Added \"{Word}\" to the blocked words.";
        }
    }
}

#Example: add a player system to every player model

A component of yours (see Player systems) must be on every player model prefab, including models the buyer makes later. This update finds the models from the game database and adds it where it is missing:

using System.Collections.Generic;
using System.Linq;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Editor;
using UnityEditor;
using UnityEngine;

namespace Game
{
    public class AddReputationUpdate : KitUpdate
    {
        public override string Title => "Reputation on every player model";

        public override string Changes =>
            "Adds the Player Reputation component to each player model prefab that doesn't have it: "
            + string.Join(", ", Missing().Select(m => m.name)) + ". Nothing else on the prefabs changes.";

        public override int Order => 200;

        static IEnumerable<GameObject> Missing()
        {
            GameInstance game = ModulesWindow.Find();
            if (game == null || game.database == null) return Enumerable.Empty<GameObject>();
            return game.database.playerModels.Where(m => m != null && m.GetComponent<PlayerReputation>() == null);
        }

        public override bool Needed() => Missing().Any();

        public override string Apply()
        {
            var done = new List<string>();
            foreach (GameObject model in Missing().ToList())
            {
                string path = AssetDatabase.GetAssetPath(model);
                GameObject root = PrefabUtility.LoadPrefabContents(path);
                try
                {
                    if (root.GetComponent<PlayerReputation>() == null) root.AddComponent<PlayerReputation>();
                    PrefabUtility.SaveAsPrefabAsset(root, path);
                    done.Add(model.name);
                }
                finally { PrefabUtility.UnloadPrefabContents(root); }
            }
            return done.Count == 0 ? "Every model already had it." : "Added to " + string.Join(", ", done) + ".";
        }
    }
}

LoadPrefabContents and SaveAsPrefabAsset edit the prefab asset itself, the same way the kit's own updates do. Because Mirror needs the same components on client and server, rebuild both after applying.

#Example: add a window under the HUD

The kit's updates that add HUD windows load the HUD prefab from GameInstance.hudPrefab, find the group they belong in, add their object, and save. The same shape for a window of yours:

using System.Linq;
using Blunnyn.KitARPG.Editor;
using UnityEditor;
using UnityEngine;

public class AddReputationWindowUpdate : KitUpdate
{
    public override string Title => "Reputation window in the HUD";

    public override string Changes => "Adds a Reputation Window object under Windows in the HUD prefab.";

    static GameObject Hud => ModulesWindow.Find()?.hudPrefab;

    public override bool Needed()
    {
        GameObject hud = Hud;
        return hud != null && hud.GetComponentInChildren<ReputationWindow>(true) == null;
    }

    public override string Apply()
    {
        GameObject hud = Hud ?? throw new System.InvalidOperationException("The GameInstance has no HUD prefab.");
        string path = AssetDatabase.GetAssetPath(hud);
        GameObject root = PrefabUtility.LoadPrefabContents(path);
        try
        {
            if (root.GetComponentInChildren<ReputationWindow>(true) != null) return "The HUD already had it.";
            Transform windows = root.GetComponentsInChildren<Transform>(true).FirstOrDefault(t => t.name == "Windows") ?? root.transform;
            var go = new GameObject("Reputation Window", typeof(RectTransform));
            go.transform.SetParent(windows, false);
            go.AddComponent<ReputationWindow>();
            PrefabUtility.SaveAsPrefabAsset(root, path);
            return $"Added the window to {hud.name}.";
        }
        finally { PrefabUtility.UnloadPrefabContents(root); }
    }
}

(ReputationWindow stands for a window component of yours.) Look up the HUD's groups by name with a fallback, since buyers can reorganise their HUD. The HUD's structure is described on HUD and windows.

#Example: add a game data asset

Some updates add content: a currency, an item the new feature needs. Create the asset next to the game's database and list it there:

using System.Linq;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Editor;
using UnityEditor;
using UnityEngine;

public class AddTokenCurrencyUpdate : KitUpdate
{
    public override string Title => "Arena Token currency";
    public override string Changes => "Creates the Arena Token currency next to the game database and lists it under Currencies.";

    static GameDatabase Database => ModulesWindow.Find()?.database;

    public override bool Needed()
    {
        GameDatabase db = Database;
        return db != null && !db.TryGet("arena_token", out CurrencyData _);
    }

    public override string Apply()
    {
        GameDatabase db = Database ?? throw new System.InvalidOperationException("No game database.");
        string folder = System.IO.Path.GetDirectoryName(AssetDatabase.GetAssetPath(db));
        var token = ScriptableObject.CreateInstance<CurrencyData>();
        token.name = "Arena Token";
        AssetDatabase.CreateAsset(token, AssetDatabase.GenerateUniqueAssetPath($"{folder}/Arena Token.asset"));
        // GameData ids are made from the name when empty.
        var so = new SerializedObject(token);
        so.FindProperty("id").stringValue = "arena_token";
        so.ApplyModifiedPropertiesWithoutUndo();
        db.currencies = db.currencies.Append(token).ToArray();
        EditorUtility.SetDirty(db);
        return "Created Arena Token and added it to the database.";
    }
}

The id is set through SerializedObject because GameData.id is a private serialized field. Pick the id once; saves store it.

#Updates and Start over

Updates are for games that keep their content. Start over in Overview builds the starter sample from scratch instead, losing changes made to the sample. Your updates should work on a fresh sample too: after Start over, Needed() decides again.

#Common mistakes

  • Needed() that loads every prefab in the project. It runs every few seconds. Go through the database's lists.
  • Rebuilding instead of adding. The buyer's changes are lost.
  • Paths to assets. Buyers move and rename them.
  • Needed() still true after Apply. The update shows forever.
  • Editor code in a runtime assembly. Updates live in an editor assembly.
