Network messages

How to make the client and the server talk with Mirror network messages, without adding a component to the player prefab: defining messages, registering handlers at the right moment, validating on the server, and sending to one player, nearby players or everyone.

#Messages or a player system

Network messages A player system (NetworkBehaviour)
Prefab change None Added to every player model prefab
Synced state None; you send what changes [SyncVar] and sync collections
Who sent it conn.identity on the server The component's own player
Good for Requests and answers, notices, features you want to delete by removing a folder State the interface reads all the time

The bounty example uses messages: the client asks for its bounty when it spawns, and the server sends the bounty whenever it changes. See Player systems for the other option.

Where the file goes: the Game assembly. Both sides need the message types and their handlers.

#Defining a message

A message is a struct that implements Mirror.NetworkMessage, with public fields of types Mirror can write: numbers, bool, string, Vector3, enums, arrays and lists of those, and other structs made of them.

using Mirror;

public struct CraftRequest : NetworkMessage
{
    public string recipeId;
    public int amount;
}

public struct CraftResult : NetworkMessage
{
    public bool ok;
    public string text;
}

Mirror's weaver generates the code that reads and writes them, in your assembly, at compile time.

#Registering handlers

Handlers are registered on the server when it starts and on the client when it connects. KitNetworkManager raises events for both:

Event When
ServerStarted A server or host starts. In single player the host restarts on every map change, so this fires again each time.
ServerStopping Before the server stops.
ServerDisconnecting (NetworkConnectionToClient) Before a connection's player is destroyed.
ClientConnected The client connected to a map.
ClientDisconnected The client left a map.

KitNetworkManager.Instance is the manager, on the KitNetwork object of the Title scene (clients and single player) and the Server scene (map servers), the scenes a game starts from. It survives scene changes, so hook in AfterSceneLoad, when the first scene has loaded it:

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
static void Hook()
{
    KitNetworkManager manager = KitNetworkManager.Instance;
    if (manager == null) return;
    manager.ServerStarted += () => NetworkServer.ReplaceHandler<CraftRequest>(OnCraft);
    manager.ClientConnected += () => NetworkClient.ReplaceHandler<CraftResult>(OnResult);
}

static void OnResult(CraftResult result) => Debug.Log(result.text);

Use ReplaceHandler, not RegisterHandler: it doesn't complain when the same handler is registered again on the next start. Server handlers only accept messages from authenticated connections (players who presented a valid ticket).

#Handling a request on the server

static void OnCraft(NetworkConnectionToClient conn, CraftRequest message)
{
    // 1. Spend from this connection's budget; floods get disconnected.
    if (!CommandPacing.Allow(conn)) return;

    // 2. Who sent it comes from the connection, never from the message.
    if (conn.identity == null || !conn.identity.TryGetComponent(out PlayerCharacter player)) return;
    if (player.State == null || player.IsDead) return;

    // 3. Validate every field.
    if (string.IsNullOrEmpty(message.recipeId) || message.recipeId.Length > 64) return;
    if (message.amount < 1 || message.amount > 99) return;
    if (!GameInstance.Database.TryGet(message.recipeId, out RecipeData recipe)) return;

    // 4. Do it through the kit's systems, then answer.
    string why = Crafting.ServerCraft(player, recipe, message.amount);
    conn.Send(new CraftResult { ok = why == null, text = why ?? $"Crafted {recipe.DisplayName}." });
}

(RecipeData and Crafting stand for your own data type and rules.)

The four steps apply to every handler:

  1. Pace. CommandPacing.Allow(conn) shares one budget per connection with every [Command] in the game (30 a second, burst 60). Far over it, the connection is kicked with KickReasons.Flooding. Use CommandPacing.AllowCentral(conn) for requests that make work for Central (2 a second, burst 10).
  2. Identity. conn.identity is the player object of the connection that sent it. Never put a character id, account id or player name in a request and act on it.
  3. Validation. Strings have lengths, numbers have ranges and must be finite (float.IsFinite), ids must exist in the database, and references to things in the world (an NPC, a monster, a drop) must be near and visible to that player.
  4. Kit systems. Change items, gold and progress through PlayerInventory, IPlayerActor, PlayerQuests and PlayerProgress.

#Naming things in the world

To name a monster or player, send its netId and resolve it on the server with Fighters.TargetFor, which returns null for anything that connection isn't meant to see (out of its view, an invisible enemy, an event monster spawned for someone else):

ICombatant target = Fighters.TargetFor(conn, player, message.targetNetId);
if (target == null) return;

To name an NPC, send its id and check range:

if (!Npc.TryFind(message.npcId, out Npc npc) || !npc.InReach(player.transform.position)) return;

#Sending from the server

To How
One player player.connectionToClient.Send(message) (or conn.Send in a handler)
Everyone who sees a player NetworkServer.SendToReadyObservers(player.netIdentity, message)
Everyone on this map server NetworkServer.SendToAll(message)
Everyone on every map Through Central: see Talking to Central

connectionToClient is null on objects with no owner and can be null while a player is leaving; use ?.Send. Instanced maps (dungeons, guild halls) run their copies inside the same map server process, so SendToAll reaches every copy. To limit a notice to one copy, loop over PlayerCharacter.ServerAll() and compare gameObject.scene.

#Sending from the client

public static void Craft(string recipeId, int amount) =>
    NetworkClient.Send(new CraftRequest { recipeId = recipeId, amount = amount });

Only send while connected (NetworkClient.isConnected). Messages sent before the player spawned arrive with conn.identity null, which the handler above ignores.

#Asking when the player spawns

The client knows its player exists when PlayerCharacter.LocalSpawned fires. The bounty example asks for its state there:

PlayerCharacter.LocalSpawned -= AskOnSpawn;
PlayerCharacter.LocalSpawned += AskOnSpawn;

static void AskOnSpawn(PlayerCharacter _) => NetworkClient.Send(new BountyAsk());

#A complete example: a world notice board

Players read a server-wide message of the day, and moderators change it with a GM command. The notice is kept on the map server.

using Blunnyn.KitARPG.Net;
using Mirror;
using UnityEngine;

namespace Game
{
    public struct NoticeAsk : NetworkMessage { }

    public struct NoticeText : NetworkMessage
    {
        public string text;
    }

    public static class NoticeBoard
    {
        public const int MaxLength = 300;

        /// <summary>Server: the current notice.</summary>
        public static string Current { get; private set; } = "";

        /// <summary>Client: the notice arrived.</summary>
        public static event System.Action<string> Received;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void ResetStatics()
        {
            Current = "";
            Received = null;
        }

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Hook()
        {
            PlayerCharacter.LocalSpawned -= AskOnSpawn;
            PlayerCharacter.LocalSpawned += AskOnSpawn;
            KitNetworkManager manager = KitNetworkManager.Instance;
            if (manager == null) return;
            manager.ServerStarted += () => NetworkServer.ReplaceHandler<NoticeAsk>(OnAsk);
            manager.ClientConnected += () => NetworkClient.ReplaceHandler<NoticeText>(OnText);
        }

        static void OnText(NoticeText message) => Received?.Invoke(message.text);

        static void AskOnSpawn(PlayerCharacter _) => NetworkClient.Send(new NoticeAsk());

        static void OnAsk(NetworkConnectionToClient conn, NoticeAsk _)
        {
            if (!CommandPacing.Allow(conn) || conn.identity == null) return;
            conn.Send(new NoticeText { text = Current });
        }

        /// <summary>Server only. Sets the notice and shows it to everyone on this map server.</summary>
        public static void ServerSet(string text)
        {
            Current = PlayerText.Clean(text ?? "", MaxLength);
            NetworkServer.SendToAll(new NoticeText { text = Current });
        }
    }
}

Hook follows Play without domain reload: the static PlayerCharacter.LocalSpawned gets -= before +=, and comes before the manager check, so it is hooked even in a scene without the network manager. The manager's own events need no -=: the manager is made again on each Play, and the old one goes away with its subscribers.

The GM command, in the Game.Server assembly:

GmCommands.Register(new GmCommand
{
    name = "notice", rank = GmRank.Moderator, usage = "notice text", description = "Sets the notice board.",
    run = c =>
    {
        NoticeBoard.ServerSet(c.rest);
        return "Notice set.";
    },
});

PlayerText.Clean trims the text, removes control characters, cuts it at a length and breaks rich text tags, so a notice can't inject TextMeshPro markup into other players' screens. To set it on every map at once, send it through Central (see Talking to Central).

#Network version

The kit hashes every network message and synced field in the project, yours included (NetworkVersion). The client sends the hash with its ticket and a map server built from different code refuses it with version_mismatch. After adding or changing a message, rebuild both the client and the map server. In the editor the value is computed from the current code, so Play always matches itself.

#Single player and MMO

Messages work the same in both. In single player the client and the host run in one process: NetworkClient.Send reaches the host's handler through a local connection, which CommandPacing never limits. Because the host restarts on each map change, handlers registered from ServerStarted are registered again each time, which is why ReplaceHandler is used.

#Common mistakes

  • Trusting an id in the message. A player sends their own name or id and the server acts for someone else. Use conn.identity.
  • No pacing. Every handler a client can trigger must call CommandPacing.Allow.
  • Registering only once at startup. The single player host restarts; register in ServerStarted and ClientConnected.
  • Sending private data to observers. SendToReadyObservers reaches everyone nearby.
  • Unbounded strings and arrays. Check lengths before using them, and before storing or relaying them.
  • Forgetting to rebuild the map server after changing a message.
