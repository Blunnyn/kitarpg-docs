GM commands in code

How to add slash commands of your own: registering a GmCommand, reading arguments with GmContext, picking a level, how the audit works, and complete examples.

#What a command is

Players type commands in the chat, starting with /. The chat sends the line to the map server, which looks the command up, checks the player's level against the command's level, runs it and shows the answer as a system line in the chat. The GM panel (F8 or /gm) runs the same commands. The kit's own commands are listed on GM commands.

Commands are registered from code with GmCommands.Register. GmCommands lives in KitARPG.Server (namespace Blunnyn.KitARPG.Server), which online clients never carry.

Where the file goes: the Game.Server assembly (see Assemblies). Commands then exist in map servers, in single player and in the editor, and never in an online client build.

#Registering a command

using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Server;
using UnityEngine;

namespace Game
{
    public static class MyCommands
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Register()
        {
            GmCommands.Register(new GmCommand
            {
                name = "refresh",
                aliases = new[] { "fill" },
                rank = GmRank.Moderator,
                usage = "refresh [player]",
                description = "Fills a player's health.",
                run = c =>
                {
                    PlayerCharacter target = c.Target(0);
                    if (target == null) return "Nobody by that name here.";
                    target.ServerHeal(target.maxHealth, null);
                    return $"Healed {target.characterName}.";
                },
            });
        }
    }
}

The kit clears and registers its own commands in SubsystemRegistration on every Play, so register yours in AfterSceneLoad (or AfterAssembliesLoaded). Registering a name that already exists replaces the old command, the kit's included. That is how you change a kit command; it is also how you break one by accident, so pick names of your own.

#GmCommand fields

Field What it is Default
name What players type after /.
aliases Other names for the same command. none
rank The level it asks for by default (see below). GmRank.Admin
usage Shown by /help, like "item id [amount] [player]".
description One line for /help.
run Func<GmContext, string>: does it and returns the answer to show, or null for none.

#Levels

GmRank Value Meaning
Player 1 Anyone.
Moderator 2 Chat and player moderation.
GameMaster 3 Game changes: items, teleports, monsters.
Admin 4 Everything, including roles.

The level a command asks for is GmCommands.LevelOf(command): the level set for its name in Game Settings > GM commands (GameInstance.gmCommandLevels) when there is one, otherwise its rank. Designers can move any command, yours included, up or down without code. /role always asks for Admin.

A player's level is GmCommands.RankOf(player): the account's role from the database (accounts.Role), or GmCommands.EveryoneRank if that is higher. In single player, Single Player Commands (singlePlayerCommands, on by default) makes EveryoneRank Admin, so every command works as a cheat. Online it is Player.

A player below the command's level gets "Unknown command", as if it didn't exist.

#GmContext

What run receives:

Member What it is
PlayerCharacter player Who typed it.
string[] args The words after the name, split on spaces.
string rest Everything after the name, as typed. Use it for free text.
int level The level this command asks for. Pass it to Central for commands that Central checks again.
string Arg(int i) Word i, or null.
int Int(int i, int fallback) Word i as an integer, or fallback.
long Long(int i, long fallback) Same, as a long.
float Float(int i, float fallback) Same, as a float. Refuses NaN and infinity.
PlayerCharacter Target(int i) The player named by word i on this map, or the one who typed it when the word is missing. Null when the name isn't on this map.
T Data<T>(int i) The game data of type T whose id is word i, or null.

Numbers are parsed with the invariant culture, so 1.5 works on every machine.

#Auditing

Every command whose level is above Player (2 or more) is staff work and is recorded:

  • Each use, allowed or refused for its level, goes to the GM audit (gm_audit table online, the save in single player) with the account, character, level, command, line, target and result.
  • Each use that ran also writes a game log line of kind gm.command with the answer.
  • When the audit can't be recorded (Central unreachable), staff commands pause and answer "GM commands are paused". Nothing staff-level runs without its record.

Player-level commands are not audited.

GmCommands.ServerUsed (PlayerCharacter, string line) is raised for every command that runs, before it runs. GmAudit.Recorded (GmAuditEntry) is raised for every audit line. See Events.

#Limits

GmCommands has caps that the kit's commands respect, so a typo or a stolen staff account can't flood the economy. Respect them in your own commands that hand things out:

Field Default
MaxItems 9,999
MaxGold 1,000,000,000
MaxExperience 1,000,000,000
MaxPoints 1,000
MaxStatusSeconds 3,600
MaxKillRange 100
MaxMuteMinutes 525,600

They are static fields, reset on every Play. Change them from your own AfterSceneLoad method if your game needs other limits.

#Examples

#Give attribute points, capped

GmCommands.Register(new GmCommand
{
    name = "points", rank = GmRank.GameMaster, usage = "points amount [player]", description = "Gives attribute points.",
    run = c =>
    {
        int amount = c.Int(0, 0);
        if (amount <= 0) return "Usage: /points amount [player]";
        amount = Mathf.Min(amount, GmCommands.MaxPoints);
        PlayerCharacter target = c.Target(1);
        if (target == null) return "Nobody by that name here.";
        target.GainPoints(amount, 0);
        return $"{target.characterName} got {amount} attribute points.";
    },
});

#Look up game data by id

Data<T> finds game data by id:

GmCommands.Register(new GmCommand
{
    name = "where", rank = GmRank.Player, usage = "where monster_id", description = "Maps where a monster lives.",
    run = c =>
    {
        MonsterData monster = c.Data<MonsterData>(0);
        if (monster == null) return "No monster with that id.";
        var maps = new System.Collections.Generic.List<string>();
        foreach (MapData map in GameInstance.Database.maps)
            if (map != null && System.Array.IndexOf(map.monsters, monster) >= 0) maps.Add(map.DisplayName);
        return maps.Count == 0 ? $"{monster.DisplayName} lives nowhere listed." : $"{monster.DisplayName}: {string.Join(", ", maps)}";
    },
});

#A command for players

Player-level commands are a quick way to add chat features. The bounty example's /hunters asks Central for a ranking:

GmCommands.Register(new GmCommand
{
    name = "hunters", rank = GmRank.Player, usage = "hunters", description = "The best bounty hunters on every map, and your last hunts.",
    run = c =>
    {
        string mine = Last(c.player);
        if (!CentralMessages.Online) return "The hunters board is kept online." + mine;
        CentralMessages.Send(new BountyBoardAsk { characterId = c.player.State.id });
        return "Asking the guild of hunters..." + mine;
    },
});

Central's answer arrives later and is shown with SocialHub.Notice. See Talking to Central.

#Free text

rest keeps the spaces:

GmCommands.Register(new GmCommand
{
    name = "notice", rank = GmRank.Moderator, usage = "notice text", description = "Sets the notice board.",
    run = c => string.IsNullOrWhiteSpace(c.rest) ? "Usage: /notice text" : SetNotice(c.rest),
});

Clean any text that other players will see with PlayerText.Clean(text, maxLength).

#/help

/help lists the chat commands, then every command the player's level allows, player-level ones included, each with its usage and description. Commands above Player level end with their level in brackets, like [3]; player-level ones show without it.

#Errors

An exception inside run is caught: it is logged on the server and the player sees "/name failed: message". Return a sentence instead of throwing for anything the player did wrong.

#Server and client

Commands run only on the map server (or the single player host). The client sends the typed line; the line is cut at 300 characters and paced like chat. Nothing in your run can be reached by a client except through that line, and the level check happens before it runs.

#Common mistakes

  • Putting commands in the Game assembly. It doesn't see KitARPG.Server, and if it did, clients would carry the command code.
  • Registering in SubsystemRegistration. The kit clears the list there; the order between those methods is undefined.
  • Reusing a kit command's name. Yours replaces it.
  • Uncapped amounts. Use the Max... fields.
  • Acting on a name without Target. Target only finds players on this map; for players elsewhere, go through Central.
