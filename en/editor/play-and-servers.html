The editor

Play & Servers

Play & Servers is where you choose how your game runs, single player or MMO, and follow numbered steps to play it from the editor. In MMO it builds and starts the services (Login, Central and the map servers), sets up the database, shows each service's state and its log, and plays with one or two players.

#Where it is

  • KitARPG > Play and Servers, or
  • the Play & Servers page in the KitARPG window (Ctrl/Cmd+Shift+K), second in the sidebar.

In MMO, the sidebar shows On next to the page when Login and Central both answer, and ... while they start.

#Choosing single player or MMO

The page opens with two large cards. Click one to pick it:

Card Description shown What it means
Single player "The game hosts its own world and saves on the player's computer. No servers to run." The game is client and server at once and saves to a local SQLite file. See Quick start: single player
MMO "Players log in to your servers: Login, Central and one server per map." Players sign in to your services and meet in shared maps. See Quick start: MMO

The choice is saved in the settings asset Assets/Settings/Resources/KitARPGSettings.asset (the mode field of KitSettings). Builds made from the kit's build menus set the mode they need for the build and put yours back afterwards.

If the project has no settings asset yet, the page shows a No settings yet card with Create settings. Press it to make the asset.

The settings asset also holds these fields, which you can edit in the Inspector:

Field What it does Default
Mode (mode) Online (MMO) or Single Player Online
Login Url (loginUrl) Where clients reach the Login service http://127.0.0.1:5100
Central Url (centralUrl) Where clients reach Central http://127.0.0.1:5200
Save File (saveFile) Single player save, a SQLite file in the player's persistent data folder savegame.db

#How the steps work

Under the cards come numbered steps. Each step is a card with a number, a title, a summary line and a pill:

Pill Means
Done The step is complete. Its card folds away and the number becomes a check mark
To do Not done yet. The first step that isn't done has a gold outline and opens by itself
Locked An earlier step must be done first. Locked steps don't open

Click a step's header to open or fold it. The arrow on the right (▸ or ▾) shows which.

#Single player steps

#1. Check the project

Summary: "Scenes and the SQLite library are in place." or "Something the game needs is missing."

Row Done when Fix
Scenes in Build Settings The first enabled scene in Build Settings is Title. The detail lists the scenes Use starter scenes puts the sample scenes in Build Settings in the right order
SQLite library for this platform The native SQLite library for your editor is in Plugins/SQLite (macOS/libe_sqlite3.dylib, Windows/e_sqlite3.dll or Linux/libe_sqlite3.so) Import the KitARPG package again

#2. Play

Summary: "The editor is the client and the server at once." Locked until step 1 is done.

  • ▶ Play single player opens the Title scene and enters Play mode with the argument -mode single. If the open scene has unsaved changes, Unity asks to save them first. Greyed out while already playing.
  • Save data shows the path of the save file the editor uses.
  • Show folder opens the persistent data folder in Finder or Explorer.
  • Delete save data asks "Delete every single player character saved by the editor?" and deletes the save file with its -wal and -shm companions. Greyed out in Play mode or when there is no save.

#3. Build the game

Summary: "Builds go to Builds/Starter and carry the server code, so the game hosts itself."

Button Output
Build for Mac Builds/Starter/MacSinglePlayer/KitARPG.app
Build for Windows Builds/Starter/WindowsSinglePlayer/KitARPG.exe

The Builds folder is created next to your Unity project folder, in the folder that contains it. See Builds.

#MMO steps

#1. Check the project

The summary counts what is ready, for example "3 of 5 ready", and reads "Scenes, .NET, the services and the map server build are ready." when all five are.

Row Done when Button
Scenes in Build Settings Title is the first enabled scene and Server is listed Use starter scenes
.NET 10 SDK dotnet --list-sdks reports a 10.x SDK. The detail lists what is installed, or "dotnet was not found" Get .NET opens the .NET 10 download page. Check again looks for dotnet again after you install it, without restarting Unity
Services source The folder with KitARPG.Services.slnx was found. The detail shows its path Browse lets you pick it by hand
Services built Login, Central and the launcher are compiled. "Building..." while it runs Build services, or Rebuild once built. Greyed out without the source or the SDK
Map server build The local map server build exists and has the scene of every map. Grey when every map runs in the editor and the build isn't needed Build, or Rebuild once built

When a build of the services fails, a red box under the row shows up to eight error lines. If none could be read it says "dotnet build failed. Run it in a terminal to see why."

The editor looks for the services source in this order: a folder you picked with Browse (remembered per project), Services next to the Unity project, Services inside it, and Assets/Blunnyn/KitARPG/Services~, where the kit unpacks the services that come in the package.

Two more rows can appear:

  • N kit updates (warning): "Things this kit adds that the game doesn't have yet. Apply them before building the map server, so both have them." Review opens Overview.
  • In-game shop, when the Shop service is in the project: off ("Off. The Shop service is optional."), running, or on but not running. Open Shop opens the Shop page.

The map server build goes to Builds/Starter/MacServer/KitARPGServer.app on Mac and Builds/Starter/WindowsServer/KitARPGServer.exe on Windows. It is a normal player build with the server code compiled in, run by the launcher in batch mode without graphics; it doesn't need Unity's Dedicated Server module. After each build, a KitARPGScenes.txt file next to it lists its scenes, which is how the page knows a map added later is missing from it.

Note

The row says "Missing the scene of a map: ..." when a map was added after the last build. Players who travel there would end up back at the login. Rebuild the map server.

#2. Pick the database

Locked until step 1 is done. The summary shows the current choice.

A two-way switch picks where the services keep accounts, characters and items:

Choice Use it for
SQLite: a local file Development and small servers. Nothing to install. The page shows the file path, UserSettings/KitARPG/data/kitarpg.db by default
PostgreSQL: for production Real servers, or to develop against the same database you ship with

With PostgreSQL picked, a status row reads Connection ready with the connection string (password hidden) or No connection yet. Then:

  • Set up PostgreSQL... opens the PostgreSQL setup window. See Setting up PostgreSQL.
  • Write the connection string by hand, a foldout with a text field. The expected form is shown under it: Host=localhost;Port=5432;Database=kitarpg;Username=kitarpg;Password=...

The database can't be changed while the services run ("Stop the services to change the database.").

Keys: "Signing and map keys are made for this machine and kept in UserSettings/KitARPG." New keys makes a new signing key (32 random bytes, used to sign login tokens) and a new map key (16 random bytes, what map servers show Central) and saves them. Greyed out while the services run.

See Database for what each database needs in production.

#3. Start the services

Locked until steps 1 and 2 are done. The summary reads "Login, Central and the maps, on this computer.", "Starting..." or "Running. Maps: town (1 player), ...".

Three rows show each part with a light (grey off, gold starting, green up):

Service Detail Port
Login Accounts and characters 5100
Central Sessions, chat, guilds and maps 5200
Maps "Started by Central when someone enters", or the maps running with their player counts One port per map, 7777 for town, 7778 for forest, 7779 for crypt

Map in the editor chooses where maps run:

Choice Meaning
None, every map runs from the map server build Central starts every map from the build. The default
town: runs in this editor, to debug it (one line per map) Central waits for that map to come from the editor instead. You play it with Play map server in step 4. Use this to debug server code with breakpoints

The choice can't change while the services run.

Buttons:

  • Start services starts the launcher in headless mode with UserSettings/KitARPG/launcher.json. Before starting, the page writes the game data from your game database to UserSettings/KitARPG/gamedata.json, so Login makes characters from your data as it is now.
  • Restart stops the services and starts them again once their ports are free (at most ten seconds). A Restart button also sits in the step's header while it is folded.
  • Stop stops the launcher, which closes Login, Central and every map it started.

The services stop by themselves when you quit Unity. They keep running across script reloads and Play mode.

Warnings this step can show:

Warning Meaning Fix
"Services from an earlier editor session are still running (process ...)" A launcher started by an editor that closed without stopping it holds the ports. Mac and Linux only Stop the old services
"The services or the map server were rebuilt after they started, so they still run the old code. Restart them." You rebuilt after starting Restart
"Something else is using port ..." Another program listens on the Login or Central port, often services started from a terminal Stop that program first

#4. Play

Locked until the services run.

  • ▶ Play client opens the Title scene and plays as a client of the local services (-mode online -login http://127.0.0.1:5100 -centralUrl http://127.0.0.1:5200).
  • Play map server: town appears when a map runs in the editor. It opens the Server scene and plays as that map's server, connected to Central with the map key.
  • Two players: Play with two opens a second editor and logs both in. See Playing with two players.
  • Built client: Open starts the client build next to the editor, as many times as you like, for more players at once. Build or Rebuild makes it (Builds/Starter/MacClient/KitARPG.app or Builds/Starter/WindowsClient/KitARPG.exe). Release clients are compiled with IL2CPP, so this build takes longer than a Mono one.

#The log

The Log card at the bottom folds open to show the last 120 lines of the services' output. Open log file opens UserSettings/KitARPG/services.log in your text editor. The log starts empty each time the services start.

#Step by step: start the MMO services

  1. Open Play & Servers and click the MMO card.
  2. In step 1, fix every red row. Usually: press Use starter scenes, install the .NET 10 SDK if asked (then Check again), press Build services and wait, then press Build on Map server build and wait for the Unity build to finish.
  3. In step 2, keep SQLite: a local file for now.
  4. In step 3, leave Map in the editor on None and press Start services. The Login and Central lights turn green after a few seconds.
  5. In step 4, press ▶ Play client. On the title screen, register an account, make a character and enter the world. Central starts the town map server the first time someone goes there.
  6. When you change scripts or scenes, rebuild the map server and press Restart. Overview's To do list tells you when.

#Setting up PostgreSQL

Set up PostgreSQL... in step 2 opens the PostgreSQL Setup window. It works with the launcher (KitARPG.Launcher --postgres), so build the services first; without them the window says "The services aren't built yet; they do the talking to PostgreSQL. Build them in Play & Servers first."

The top switch picks where PostgreSQL runs: A server I run or Docker on this computer.

#A server I run

Where is PostgreSQL?

Field What it does Default
Host Address of the server. localhost for this computer localhost
Port Its port 5432
SSL Prefer, Require or Disable. Hosted servers (a VPS, RDS, Supabase, Neon) usually need Require Prefer

Then pick Create the database for me or Use a database I have.

With Create the database for me:

  1. Fill Admin login (User, Password): an account allowed to make databases and users. It is used once and never saved. On Mac with Homebrew or Postgres.app the admin is usually your own user, with no password. Default user: postgres.
  2. Fill For the game: Database (kitarpg), User (kitarpg) and Password. The password starts as a random one; Show reveals it and New makes another.
  3. Press Create and use. The window makes the database and the user, tests the login and, when it works, fills the connection string in Play & Servers and switches it to PostgreSQL.

With Use a database I have, fill Login (Database, User, Password) and press Test and use.

The message under the button says what happened, or why it failed. The window gives up after a minute without an answer ("PostgreSQL didn't answer in a minute.").

#Docker on this computer

Needs Docker Desktop (OrbStack also works). Create and use runs PostgreSQL 17 (postgres:17-alpine) in a container named kitarpg-postgres, with its data in the volume kitarpg-pgdata, listening on 127.0.0.1 on the first free port from 5432. It sets a new random password for the user kitarpg and fills the connection string in Play & Servers.

The container keeps running after you close Unity and restarts with Docker. Pressing Create and use again reuses the container and gives it a fresh password. The first time, downloading the image can take a minute.

Messages you may see:

Message Fix
"Docker was not found. Install Docker Desktop, or write the connection string of your own server." Install Docker Desktop, or use A server I run
"Docker is installed but not running. Open Docker Desktop and try again." Start Docker Desktop
"The container kitarpg-postgres doesn't publish port 5432. Remove it in Docker Desktop and try again." Delete the old container in Docker Desktop
"PostgreSQL didn't start. Its log is in Docker Desktop, container kitarpg-postgres." Read the container log in Docker Desktop

The connection string, with its password, is saved in UserSettings/KitARPG/launcher.json, outside the project's assets and out of version control by default.

#Playing with two players

Play with two (step 4), Play with two players (Overview) and KitARPG > Play With Two Players all do the same:

  1. If the mode isn't MMO, a dialog says "Two players need the MMO mode, where players meet on servers." and opens Play & Servers.
  2. If Unity's Multiplayer Play Mode package (com.unity.multiplayer.playmode) is missing, a dialog offers Install. Press the button again once it is installed.
  3. If the services aren't running, it starts them. If they aren't built, it asks you to build them first.
  4. It opens Player 2, a second editor of the same project, through Multiplayer Play Mode. The first time, that editor imports the project, which takes a while.
  5. When Login answers and Player 2 is open, both editors enter Play. Each signs in with its own test account, makes its character if it doesn't exist, and enters the world without the title screen.

The test accounts are kitplayer1 and kitplayer2, with the characters Aria and Bram, a random password made for this machine, the first player model and its first class. They are kept in UserSettings/KitARPG/quickplay.json; edit that file to use other names. They are made only on your local services.

If Player 2 can't start by itself, the Console says so and Unity opens Window > Multiplayer > Multiplayer Play Mode: turn on Player 2 there, then press the button again. If nothing is ready after 15 minutes, the Console reports it.

Maps run from the map server build, or in this editor when one is picked in Map in the editor.

#Files this page uses

All of them live in UserSettings/KitARPG/, per user and kept out of version control:

File Holds
launcher.json Ports, keys, database, maps and paths the launcher reads
data/kitarpg.db The SQLite database of the local services
gamedata.json The game data Login and Central read, written at each start
services.log Output of the services
launcher.pid The running launcher, so the editor finds it after a restart
quickplay.json Test accounts for two players

The launcher settings list the maps and their ports. The editor starts with town on 7777 (started with the services), forest on 7778 and crypt on 7779, and the launcher adds guild_hall on 7780. Every other map of the game database gets the next free port when you start the services, so a new map needs no setup. To change ports, edit launcher.json while the services are stopped. See Launcher and Configuration.

#Tips

  • Keep Map in the editor on None unless you are debugging server code. Playing a map server in the editor means the editor can't also be a client; use Built client or two players for that.
  • After changing classes, items or other data that Login uses to make characters, restart the services so they read the new game data.
  • Play in the normal Unity toolbar doesn't pass the window's arguments. Use the buttons on this page or Overview, or start from the Title scene.

#Common mistakes

  • Starting the services without a map server build. Login and Central start, but no map registers and players stay on the title screen. Build the map server.
  • Forgetting to restart after a rebuild. The services keep running the old code. The step shows a warning and Overview lists Restart the services.
  • Ports taken by services from a terminal. Stop those first; two launchers can't share the ports.
