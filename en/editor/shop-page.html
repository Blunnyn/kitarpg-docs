The editor

Shop page

The Shop page runs the in-game shop from the editor. The in-game shop sells items for a premium currency the account holds, such as Gems. It runs as its own service, the Shop service, which keeps the catalog, the balances and every purchase, and takes real-money payments; the game only shows it. This page turns the shop on, starts the Shop service on your computer, edits its offers and products, and publishes them to your live server.

#Where it is

  • KitARPG > Shop, or
  • the Shop page in the KitARPG window (Ctrl/Cmd+Shift+K).

The sidebar shows On next to it when the Shop service on your computer answers.

#Before you start

  • The shop is for MMO games. Single player games never have a shop.
  • The Shop service must be in the project: the Shop folder of the services source. If it isn't, the page only shows The Shop service isn't in this project with the folder it looked in, and the game has no shop button.
  • The game database needs a premium currency: a currency with Premium ticked. The starter sample has Gems.
  • Player prefabs need the Player Shop component, and the HUD needs the shop window. The kit updates add both to older games. See Updating the kit.

#The tabs

The page has three tabs: Service, Offers and Real money. The last tab you used is remembered for the editor session. Messages from the last action (saved, published, refused) show under the tabs, with problems in red lines.

#Service tab

#In the game

"Shows the shop button in the HUD (P) in online games, on PC and on touch screens. Single player games never have a shop."

A switch with The game has an in-game shop or No in-game shop. It turns on or off both the In-game shop module and the shop in the launcher settings, which gives map servers the shop's address and key. Turning it off also stops the Shop service on this computer. Turning it on also turns on Mail, which the shop needs.

Under the switch, status rows:

Row Means Fix
No game database No database was found Pick one in Game Database
No premium currency No currency has Premium ticked; offers charge in it Tick Premium on a currency, or apply the update below to add Gems
Premium currency for the shop, Shop on the player prefabs, Shop window in the HUD Kit updates the shop needs that your game doesn't have yet Apply
Premium currency: Gems (gems) The premium currencies found. "Held by the account, spent only at the shop." Nothing to do

#On this computer

"The Shop service next to Login and Central, on the same database. It starts on its own, apart from the other services."

State Detail Button
Not built yet Build the services solution to get the Shop service and the launcher Build compiles the services. If it fails, the error goes to the Console
Stopped Starts at http://127.0.0.1:5300 with the catalog in UserSettings/KitARPG/shop-conf.json Start the shop
Starting Waiting for the service to answer Stop
Running "Answering at http://127.0.0.1:5300. Saved offers go live here right away." Stop

Start the shop turns the shop on in the game if it was off, makes sure the port is free, copies the sample catalog that comes with the service when you have none yet, and starts the launcher in shop-only mode. If Login and Central already run, it tells you to restart them so the map servers they launch find the shop; Play in the editor finds it right away. If the port is taken, the message says to stop what uses it or change ShopPort in UserSettings/KitARPG/launcher.json.

The Shop service stops by itself when you quit Unity.

Two foldouts:

  • Keys: the Map key (what map servers show the Shop) and the Admin key (what this page uses to publish), each with Copy. Only the first four characters are shown. "Made for this computer and kept in UserSettings, out of version control. The live server uses its own."
  • Log: the last 30 lines of UserSettings/KitARPG/shop.log.

#Online server

"Where Publish sends the offers for the live game: the Shop service's address and its admin key (KITARPG_SHOP_ADMIN_KEY). Its admin API is only reachable from inside the server's network, so use a tunnel or a private address."

Field What it is
Address The live Shop service's address, for example through an SSH tunnel
Admin key The live service's admin key, hidden as you type

Check asks the address for its health and says whether it answers. Both values are saved in UserSettings/KitARPG/shop-remote.json, outside the project, so the key never reaches version control.

#Offers tab

#The publish bar

At the top of the Offers and Real money tabs:

Element What it does
Pill Unsaved changes, Live on this computer (saved and the local shop runs) or Saved
Revert Throws away unsaved changes and loads the saved catalog. Greyed out without changes
Save Checks the catalog and writes it to UserSettings/KitARPG/shop-conf.json. A running local shop reloads it at once. Greyed out without changes
Pull from server Loads the catalog of the online server into the page. Asks first if you have unsaved changes. Save afterwards to keep it on this computer too
Publish to server Checks the catalog, asks "Replace every offer on ... with these N? Players see them at once.", and sends it to the online server

Pull and Publish are greyed out until the online server's address and admin key are set. Without an address, a line under the bar explains that Save keeps the offers on this computer.

Save and Publish refuse a catalog with problems and list them in red. The server checks the catalog again and changes nothing unless every offer passes; when it refuses, the page says "The server refused the catalog and kept the one it had." with its reasons. When it accepts, it says "Published N offers to ... (version ...)."

#The offer list

The Offers card lists every offer: the icon, the name, the category and id, the price with its currency, and a state pill:

State Means
On sale Sold now
Scheduled Its start date is in the future
Ended Its end date has passed
Hidden Kept for its history, not sold
Problem Something in it is wrong; open it to see what

Click an offer to open it under the list; click it again to close it. Buttons under the list:

Button What it does
Add offer Adds "New Offer" with the id new_offer (or new_offer_2...), the first premium currency and a price of 100
Duplicate Copies the open offer with a new id and " (copy)" after its name
Move up, Move down Moves the open offer in the list
Delete Asks first. To stop selling an offer but keep it, tick Hidden instead

#Offer fields

"The id never changes once players bought it: limits and history count by it."

Field What it does Default
Id Lowercase, no spaces, up to 64 characters. Never reuse one for something else Required
Name Shown on the card
Description Shown on the offer's page
Category The tab it shows under in the game Featured
Currency A premium currency of the game database First premium currency
Price Above 0 Required
Icon Item whose icon the card shows. Empty uses the first item's Empty
Badge Ribbon on the card's corner, such as New or Sale, up to 24 characters. Empty has none; offers that end show Limited time Empty
Order Lower comes first when the shop is sorted by relevance 0
Picture Card and offer page picture. Empty draws the icon Empty
Banner Wide picture. Offers with one take turns in the banner on the shop's first page Empty

Items: one row per item the offer gives, with the item's icon, the item field, the amount (at least 1) and ✕ to remove it. Add item adds a row. An offer needs at least one item. An item the database doesn't have shows "'id' not in the database".

Starts UTC date and time, like 2026-12-24T18:00:00Z. Empty is always. The local time it means is shown next to it. Now fills in the current time Empty
Ends Same format. Must be after Starts Empty

Problems with the offer show in red at the bottom of its card.

#Pictures

Pictures and banners are sprites. The catalog is text, so the offer only keeps a key and the sprite lives in the Shop Art asset of the Game Instance. The first time you pick a picture, the page makes ShopArt.asset next to the network prefab and sets it in Game Settings. A key with no sprite shows "'key' not in the shop art". Pictures ship with the game build, so new pictures need a new client build; offers don't.

#Real money tab

#Products

"What one unit of a product bought with real money gives. The id is the one your payment provider sends (Stripe's metadata.product, or your web shop's)."

Each row: the product id, "gives", the amount, the premium currency and ✕. Add product adds a row such as gems_100 giving 100 of the first premium currency. A product needs an id, an amount above 0 and a premium currency, and ids must be unique.

#Letters

"Bought items always arrive by mail, gifts too."

Field What it does Default
Sender Who the letters with bought items come from Shop
Days to collect After this the letter and its items are gone. 1 to 365 30

Whether bought items go straight to the bag is set by Shop Auto Take in Game Settings.

#Step by step: run the shop locally

  1. In Play & Servers, pick MMO, build the services and start them.
  2. Open KitARPG > Shop, Service tab. Apply any shop kit updates listed.
  3. Turn on the switch in In the game.
  4. Press Start the shop. Wait for Running.
  5. Press Restart in Play & Servers so the map servers it launches find the shop.
  6. Press ▶ Play client, enter the world and press P to open the shop. Give yourself premium currency to test a purchase with the GM command /currency gems 1000 (admin level). See GM commands.

#Step by step: publish the catalog

  1. On the Offers tab, add or edit offers. Check that none shows Problem.
  2. On the Real money tab, set your products and letters.
  3. Press Save. The local shop, if running, uses the new catalog at once. Try it in Play.
  4. On the Service tab, fill Online server: the address of your live Shop service, reachable through a tunnel or a private address, and its admin key (KITARPG_SHOP_ADMIN_KEY on the server). Press Check.
  5. Back on Offers, press Publish to server and confirm. Players see the new offers at once; no build or restart is needed.
Tip

Press Pull from server before editing when someone else may have changed the live catalog. Publishing replaces every offer on the server.

Important

Never put the live admin key in a file inside Assets or in version control. The page keeps it in UserSettings/KitARPG/shop-remote.json for that reason.

#Single player and MMO

The shop exists only in MMO games. In single player the switch and the module have no effect and the shop button never shows.

#Common mistakes

  • Changing an offer's id after it sold. Purchase limits and history count by id. Make a new offer instead and hide the old one.
  • The shop button doesn't show. The module is off, the player prefab lacks Player Shop, the HUD lacks the shop window, or the map server can't reach the Shop service. Apply the kit updates and restart the services after starting the shop.
  • Selling a quest item. Project Check warns about it.
  • Pictures don't show in a built client. The Shop Art asset with the new sprites must be in the client build.
