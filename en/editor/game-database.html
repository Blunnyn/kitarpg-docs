The editor

Game Database

The Game Database page shows every piece of game data in one place: player models, classes, attributes, skills, items, monsters, loot, shops, quests, maps and the database's own settings. You browse by kind on the left, pick an entry in the middle and edit it on the right. It also has two assistants that make a new player model or a new monster from a 3D model.

#Where it is

  • KitARPG > Game Database, or
  • the Game Database page in the KitARPG window (Ctrl/Cmd+Shift+K).

When the data has problems, the sidebar shows their count next to the page.

#What the game database is

The game database is a GameDatabase asset. The game reads all of its data through it, by id. You list the main entries in it (player models, maps, monsters, items and so on); everything those entries point at (a class's skills, a monster's loot table, a loot table's items) is collected by itself. So a skill added to a class is in the game without listing it twice.

The database is set on the Game Instance of the network prefab. The starter sample makes one at Assets/Blunnyn/KitARPG/Samples/Starter/Data/StarterDatabase.asset. Login and Central get a copy of it as gamedata.json each time Play & Servers starts the services.

#The layout

The page uses the whole window width, in three columns under a toolbar.

#Toolbar

Element What it does
Game Database field The database being edited. Pick another one to switch; the choice is remembered
N problems pill Shows when the data has problems. The Settings page lists them
Collect referenced Writes every entry the database only reaches through references into its own lists, so each list shows everything. Player models aren't touched
Export for services Writes gamedata.json into the Login folder of the services source, for services you run by hand. Same as KitARPG > Export Game Data for Services

When the project has no game database, the page shows No game database yet with Create game database. Pick where to save it; data you create later goes into folders next to it.

#Entries (middle)

The title and hint of the category, a search field and the list. Each row shows the entry's icon (or its first letter when it has none), its name and a second line: the id, or for items the category and the id, or for models the model id and how many classes it has.

  • Type in the search field to filter by name or id.
  • Click a row to edit it. Double click also selects the asset in the Project window.
  • Up and Down arrows move through the list.
  • The button at the bottom makes a new entry: + New class, + New skill, + New weapon and so on. When a category can make more than one kind (Items can make a weapon, equipment, a consumable or a plain item), a menu asks which.

New entries are named "New ..." with an id made from the name, saved in a folder named after the category next to the database asset (for example Data/Skills), added to the database's list and opened. Rename them in their fields.

The Models and Monsters categories have their own buttons, described in New player model and New monster.

#Entry page (right)

The top of the page shows the icon, the name, a pill with the kind (Weapon, Skill, Monster...) and a pill with the id, plus three buttons:

Button What it does
Show file Selects the asset in the Project window
Duplicate Copies the asset next to it, with an id made from the copy's name, adds it to the same list and opens it. Not on models
Delete Asks "Move ... to the trash? Characters that saved its id lose it." and moves the asset to the trash. On models the button is Remove: it takes the model out of the database and keeps the prefab

Under it, the asset path, then the fields in cards, one card per group of fields. The fields are the same you see in the Inspector.

Some kinds get extra cards above the fields:

  • Items: an In game card with the tooltip players see, rarity and category, description, every bonus (rolled bonuses as ranges), the level and classes for gear, the sell and buy price, stacking, weight and whether it is bound, and the item's icon.
  • Gear with fixed bonuses: "N fixed bonuses that never roll. Turn them into min and max ranges, 25% up and down?" with Make them roll, which moves the fixed bonuses into random ranges. See Equipment.
  • Models: a Look card with a preview of the prefab (double click it to open the prefab), its classes (the first one marked "(default)") and how many animations are set. Under the fields, an Animations section edits the model's Character Animations: clips for moving, getting hit, dying, attacking with each weapon type and casting each skill. A prefab without that component shows Add Character Animations.
  • Maps: an Adding a map card with what a map needs and where each part stands. See Maps.

#New player model

In Models, the bottom of the list has:

  • + New player model, which opens the assistant in the right column.
  • "Or add a player prefab you already made": a prefab field and Add prefab. It adds a Player Model component when the prefab has none and lists it in the database. Drag a prefab from the Project window; a scene object is refused.

The assistant has four steps shown as a bar on top. Steps you passed can be clicked to go back. Cancel closes it without making anything, Back goes one step back and Next goes on; Next is greyed out while the step has a problem, shown in an orange line.

#Step 1: Model

  1. Drag an FBX or a prefab into the field of The 3D model. A preview shows next to it.
  2. Read the status under it:
    • Humanoid rig: weapons go in its hands and it can share the kit's animations.
    • Generic rig: use animations made for this rig, and set the hand bones on the model afterwards.
    • No Animator: it won't animate. Add an Animator to the model, or set its rig to Humanoid in the import settings.
    • No skinned meshes: gear swaps body parts by skinned mesh, so this model shows without equipment changes.
  3. In Name, check Display name (filled from the model's name) and Id (made from the name until you type your own). The id is saved with characters; changing it later breaks the characters made with it.
  4. Tick Own hair only to keep the body's own hair, ears or horns: no hair styles are offered for it.

#Step 2: Classes

  1. In Classes it can be, tick the classes a character with this look can pick. The first ticked is the default.
  2. To make classes along with the model, press + New class in New classes, type a name and, optionally, pick a class in copy of to start from its attributes, skills and gear. x removes a row.

At least one class is needed. New class names must not match an existing class id.

#Step 3: Animations

  1. Start from a model: pick an existing model to copy its animations (clips, hit timings, per weapon and per skill) and its appearance catalog, or Nothing, start empty. With a model picked:
    • Copy its animations (on by default).
    • Copy the game's own components on it (not the kit's) (on by default): components you added to that model come along with their values.
    • A warning shows when one model is humanoid and the other isn't, since copied clips may not play on this rig.
  2. Upper body (humanoid only): Use an upper body mask (on by default) lets characters attack and cast while walking, the legs still moving. Leave Mask empty to use the kit's mask, or pick your own Avatar Mask.

With empty animations, drop the clips in the model's Animations card afterwards. Hits still land on time.

#Step 4: Create

  1. Check Prefab folder. It defaults to a Prefabs folder next to the database's folder. The full prefab path shows under it. The folder must be inside Assets, and a prefab with that name must not exist.
  2. Read What will be made: the prefab with the Player Model, networking, movement, inventory, stats, skills, quests, chat, friends, party, trade, guild, bank, forge, mail, market, shop, PvP, equipment, appearance, animations and the name over the head; the classes; the animations; the mask; and that it joins the database.
  3. Press Create player.

The assistant makes the new classes (in Classes next to the database), the prefab, adds both to the database and opens the new model, ready to edit. See Player models.

#New monster

In Monsters, the bottom of the list has:

  • + New monster, which opens the assistant.
  • Blank monster data, which makes only a Monster data asset, without a prefab.

#Step 1: Model

  1. Drag an FBX or a prefab into The 3D model.
  2. The status says Animated (you pick its clips in step 3) or No Animator (it hops as it moves and flashes when hit, like the sample's slimes; its attacks still land on time).
  3. Check Display name. The id made from it shows under the field. No other monster may have that id.

#Step 2: Combat

Start from a monster copies everything another monster has: stats, skills, resistances, phases and loot. Pick Nothing, start from the defaults to start from a new monster's values. Picking a monster fills the fields below with its values; change what this one does differently.

How it fights

Field What it does Default

Rank Normal, Elite or Boss. Elites and bosses get a frame on their plate; bosses a bar at the top of the screen Normal
Health Maximum health, at least 1 50
Damage Minimum and maximum damage of its attack, and the element (empty uses the default element) 1 to 3
Attack range (m) About 1.4 for melee; farther for monsters that shoot. At least 0.5 1.4
Attacks per second At least 0.1 0.8
Move speed 3
Aggression Passive, Aggressive, or Pack (joins in when a monster nearby is attacked) Aggressive

Rewards

Field What it does Default
Experience Experience for the kill 10

#Step 3: Animations

Without an Animator, this step only says there is nothing to pick.

With one:

  1. Start from a monster copies the clips and hit timings of an animated monster. Nothing starts empty.
  2. Clips: Idle, Walk, Hit, Death and Attack. Clips you pick replace the copied ones. Empty ones are skipped: without Hit it doesn't flinch, without Death it doesn't fall.
  3. Hit lands at (shown when there is an attack clip): from 0 (start) to 1 (end) of the attack, when the damage lands. Default 0.5.

#Step 4: Create

  1. Check Prefab folder (a Prefabs folder next to the database's folder by default).
  2. Render its bestiary icon (on by default) draws the monster's portrait after it is made.
  3. Read What will be made: the monster data, the prefab (networking, movement, a click area, the Monster component, its animations and the plate over its head, plus the hopping body without an Animator) and that it joins the database.
  4. Press Create monster.

The data goes in Monsters next to the database. A copied monster gets a new portrait instead of the original's. The new monster opens in the list. To put it in the world, add a Monster Spawner to a map scene and pick it. See Monsters.

#Single player and MMO

The data is the same in both. In MMO, Login and Central read a copy (gamedata.json) written when Play & Servers starts the services, so restart them after changing data that Login uses to make characters, such as classes, start items or the start map. Map servers read the database from their build, so rebuild the map server after changing data. See Play & Servers.

#Tips

  • Keep ids short, lowercase, with letters, digits, - and _. Project Check warns about other characters.
  • Never change the id of something players already have. Saves point at ids.
  • Use Duplicate to make variants, such as a stronger copy of a monster or a recolored item.
  • Collect referenced is useful after importing data made elsewhere, so every list shows what the game really contains.

#Common mistakes

  • Making assets with Create > KitARPG in the Project window and forgetting to list them. The game only knows what the database reaches. Project Check lists unreachable assets as notes. Making entries from this page lists them by itself.
  • A model with no classes. Nobody can pick it. The database reports "Player model '...' has no classes".
  • Two entries of the same kind with the same id. Only one is found. Project Check reports it as an error.
