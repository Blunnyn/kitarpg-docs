Servers and deployment

Builds

How to build every part of an online KitARPG game: the client players install, the map servers for your computer and for Linux, the single player game, and the .NET services. It also covers the checks every build goes through and what each build may carry.

#The build menus

All of them are under KitARPG > Starter. Each takes its scenes from the maps in your Game Database, so a new map is in every build without extra steps. Builds go to a Builds/Starter folder next to your Unity project folder (the Linux server goes to Deploy/builds/starter).

Menu What it makes Output Scripting backend Extra defines
Build Mac Client The MMO client for macOS Builds/Starter/MacClient/KitARPG.app IL2CPP (set by the menu) None
Build Windows Client The MMO client for Windows Builds/Starter/WindowsClient/KitARPG.exe IL2CPP (set by the menu) None
Build Mac Server A map server the launcher runs on a Mac Builds/Starter/MacServer/KitARPGServer.app Project setting KITARPG_SERVER
Build Windows Server A map server the launcher runs on Windows Builds/Starter/WindowsServer/KitARPGServer.exe Project setting KITARPG_SERVER
Build Linux Server The map server for Docker and Linux hosts (Dedicated Server) Deploy/builds/starter/KitARPGServer.x86_64 IL2CPP (set by the menu) None (Unity adds UNITY_SERVER)
Build Mac Single Player A single player game for macOS Builds/Starter/MacSinglePlayer/KitARPG.app Project setting KITARPG_SERVER, KITARPG_SINGLEPLAYER
Build Windows Single Player A single player game for Windows Builds/Starter/WindowsSinglePlayer/KitARPG.exe Project setting KITARPG_SERVER, KITARPG_SINGLEPLAYER
Build Mac Test Client A client with the test tools, for your own checks Builds/Starter/MacTestClient/KitARPGTest.app Mono (restored after) KITARPG_DEV

Next to each build the menu writes KitARPGScenes.txt with the scenes it carries. Play & Servers reads it to tell you when a map server lacks a map's scene.

The Mac and Windows servers are normal player builds with the server code compiled in, started with -batchmode -nographics. They don't need the Dedicated Server module. The Linux server is a real Dedicated Server build: smaller, no graphics at all.

#What every build checks first

  1. Scenes. Every map in the Game Database names its scene. If a scene file is missing, the build stops and says which. The Title scene is always first.
  2. Project Check. The validator runs before every build and stops it on errors. You can turn that off in Project Check with Stop builds on errors. See Project Check.
  3. Build separation. The kit checks which assemblies the build would compile and stops it when one doesn't belong. This check runs for every build, from the kit's menus, from File > Build Profiles or from a script, and can't be turned off.
  4. Mode. The build carries KitARPGSettings with the mode it is built for (online or single player). The menu puts your editor's mode back afterwards.
  5. Network version. A hash of everything Mirror sends is written into the build. See Network version.

#Defines and what goes where

Define What it compiles Used by
KITARPG_SERVER (or Unity's UNITY_SERVER) KitARPG.Server, every KitARPG.Modes.*.Server and every assembly whose name ends in .Server: the map server, the link to Central, GM commands, server-side rules Map servers and single player
KITARPG_SINGLEPLAYER KitARPG.Local: the local SQLite save Single player only
KITARPG_DEV Test tools: automatic login, the smoke test, -save, -mode, -login, -centralUrl The editor and the test client only
KITARPG_LOADTEST Load test tools Load test builds only
Build Carries Never carries
MMO client Game, interface, networking Server code, GM commands, the local save, test tools, keys, connection strings
Map server Server code The local save
Single player Server code and the local save Test tools

Build separation stops a build when:

  • an MMO client would carry server code or the local save, or is built with KITARPG_SERVER or KITARPG_SINGLEPLAYER;
  • an assembly that goes into an MMO client references a server assembly;
  • a map server would carry KitARPG.Local;
  • a release build would carry test tools;
  • an editor or test assembly would go into any build;
  • a single player build lacks the server code or the local save;
  • an MMO client for release is built with Mono;
  • an MMO client for release points at Login or Central over plain HTTP on anything but this computer.

It warns (and goes on) for a development client or a client built with Mono in development.

KitARPG > Check Build Separation shows the table for your project: which assemblies go into each kind of build.

Your own server-only code goes in an assembly whose name ends in .Server, with the define constraint UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER (Create > KitARPG > Scripts > Game Server Assembly makes one). See Assemblies.

#Building the MMO client

  1. Set Login Url and Central Url in Assets/Settings/Resources/KitARPGSettings.asset to your public HTTPS addresses, for example https://login.mygame.com and https://central.mygame.com. See Configuration.
  2. Pick the same control mode the map servers are built with (Game Settings). A client in another mode is refused with mode_mismatch.
  3. KitARPG > Starter > Build Mac Client or Build Windows Client.
  4. Build the map servers from the same code, so the network versions match.

Release clients are always IL2CPP: their code ships as native code instead of DLLs anyone can read and change. Unity builds a Windows IL2CPP player only on Windows, and a Mac one only on a Mac.

A release client ignores the -login, -centralUrl and -mode arguments, and talks to Login and Central over HTTPS only.

#Building the Linux map server

The map server that runs in Docker or on a Linux host.

Before the first build, install in Unity Hub for your editor:

  • Linux Dedicated Server Build Support;
  • IL2CPP for Linux;
  • on a Mac, the com.unity.toolchain.macos-arm64-linux package (Package Manager), which lets a Mac compile for Linux.

Then:

  1. Save your scenes and apply any pending kit updates (Overview lists them), so the server has them.
  2. KitARPG > Starter > Build Linux Server.
  3. The build lands in Deploy/builds/starter/: KitARPGServer.x86_64, KitARPGServer_Data, GameAssembly.so, UnityPlayer.so and a KitARPGServer_BackUpThisFolder_ButDontShipItWithYourGame folder with IL2CPP debug symbols. Keep the symbols for reading crash reports; the Docker image leaves them out.

The image is about 72 MB. The server runs headless and reads its map, port and Central address from the command line (see Configuration). One build serves every map; each container runs it with a different -map.

#Building for your own computer

Build Mac Server or Build Windows Server makes the map server the launcher and Play & Servers start. Rebuild it after you change scenes, server code or anything that travels over the network. Play & Servers tells you when it is older than the running services.

#Single player builds

Build Mac Single Player and Build Windows Single Player make a game that hosts its own world and saves to a file on the player's computer. They need no services. See Quick start: single player.

#The test client

Build Mac Test Client makes a client with the kit's test tools: automatic login, the smoke test and -smoketest systems, where two clients play the social and economy systems against real servers. It uses Mono for a fast build and its own folder so it can't be mistaken for the release client.

KITARPG_DEV is the only way test tools get into a build: a plain development build doesn't carry them. Never give the test client to players.

#Network version

Every build carries a short hash of everything that travels over Mirror: synced fields, synced lists and dictionaries, and network messages, with the fields of the types inside them. The client sends it with its ticket, and a map server built from different code refuses it with version_mismatch ("The game and the server are different versions") instead of failing halfway through reading a component.

  • The value is computed when the build starts and stored as a temporary resource in Assets/KitARPGBuild, which is deleted after the build.
  • The editor computes it from its own code.
  • If either side has no value, they aren't compared. Hand-written serializers aren't part of the hash.

When you change a synced field or a message, rebuild both the client and the map servers.

#Building from the command line

Every menu is a static method you can call from a build machine:

Unity -batchmode -quit -projectPath MyGame \
  -executeMethod Blunnyn.KitARPG.Editor.StarterBuilder.BuildLinuxServer
Menu Method
Build Mac Client Blunnyn.KitARPG.Editor.StarterBuilder.BuildMacClient
Build Windows Client Blunnyn.KitARPG.Editor.StarterBuilder.BuildWindowsClient
Build Mac Server Blunnyn.KitARPG.Editor.StarterBuilder.BuildMacServer
Build Windows Server Blunnyn.KitARPG.Editor.StarterBuilder.BuildWindowsServer
Build Linux Server Blunnyn.KitARPG.Editor.StarterBuilder.BuildLinuxServer
Build Mac Single Player Blunnyn.KitARPG.Editor.StarterBuilder.BuildMacSinglePlayer
Build Windows Single Player Blunnyn.KitARPG.Editor.StarterBuilder.BuildWindowsSinglePlayer

In batch mode a failed build throws, so Unity exits with an error code and your build machine sees the failure.

#Building the services

The .NET services build with the .NET 10 SDK.

Goal Command (from the Services folder)
Build everything for the launcher dotnet build
Run the tests dotnet test
Publish one service for a server dotnet publish Login -c Release -o out/Login
Docker images docker compose build from Deploy (see Docker)

Before you publish Login or build its image, run KitARPG > Export Game Data for Services. It writes Services/Login/gamedata.json, which the build copies next to the service. Without it Login can't create characters.

#Common mistakes

  • "KitARPG stopped the OnlineClient build." The Console lists each problem with its fix. Usually server code in a client assembly, or a plain HTTP Login Url.
  • "The game and the server are different versions." The client and the map server were built from different code. Rebuild the one that is older.
  • Players who change map land back at the login. The map server lacks that map's scene. Rebuild it; Play & Servers names the missing scene.
  • The Linux build fails on a Mac. The Linux toolchain package or the Linux Dedicated Server module is missing.
  • The Windows client fails to build on a Mac. IL2CPP for Windows builds only on Windows. Build it on a Windows machine.
