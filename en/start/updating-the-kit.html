Updating the kit

How to bring a newer version of KitARPG into a game you already made, without losing your work: what the import replaces, what kit updates are, every update the kit ships, and what to rebuild afterwards.

#Which version you have

  • Overview in the KitARPG window shows "Version" with the kit's version, for example 1.0.0.
  • KitARPG > What's New shows the changelog with your version highlighted.
  • The Changelog page lists every version.

#Two kinds of change

A new version of the kit changes your project in two ways:

Change How it arrives What it touches
New and fixed kit files Importing the new package Files inside Assets/Blunnyn/KitARPG, Assets/Blunnyn/Art, Assets/Mirror, and the services in Services~
Kit updates You apply them in Overview Things your game lacks that the new kit expects: a currency in your database, a component on your player prefabs, a window in your HUD

The import replaces kit files. Kit updates then add what your own game assets need, without rebuilding them.

#Before you update

  1. Commit or back up your project. Every later step is then safe to undo.
  2. Keep your game outside the kit's folders. Anything you changed inside Assets/Blunnyn can be replaced by the import. That includes the starter sample in Samples/Starter: if you built your game by editing the sample in place, copy your changed assets to your own folder first. See Project structure.
  3. Stop Play and stop the services in Play & Servers.
  4. Read the new version's entry in the Changelog.

#Step by step

  1. Open Window > Package Manager > My Assets, find KitARPG and press Update (or Download), then Import.
  2. The Import Unity Package window marks new and changed files. Import everything that belongs to the kit.
  3. Unity imports and compiles. If the new version declares newer Unity packages, Unity installs them.
  4. The services are unpacked again. When the new Services.zip carries a different services version, the editor unpacks it over Assets/Blunnyn/KitARPG/Services~. The Console shows [KitARPG] Services <version> unpacked to ....
  5. What's New opens once. It lists every version, newest first, with your new version highlighted. Open the file opens Documentation/CHANGELOG.md. Close closes it.
  6. Apply the kit updates. Open the KitARPG window. Overview's To do shows "N kit updates" with their titles, and the sidebar shows a badge with the count. See Applying kit updates.
  7. Run Project Check and fix what it finds.
  8. In MMO, rebuild what runs outside the editor, in this order:
    1. Play & Servers > step 1 > Services built > Rebuild.
    2. Play & Servers > step 1 > Map server build > Rebuild.
    3. Restart the services.
    4. Rebuild your clients. The client and the map server must come from the same code, or players get "The game and the server are different versions".
Warning

Changes you made by hand inside Services~ are overwritten when a new services version is unpacked. To change the services, use service modules, or copy the services to a Services folder next to your project and point Services source at it. A project with its own Services folder never uses the zip.

#Applying kit updates

A kit update is something a newer kit adds to a game made with an older one. It only adds what is missing: it never rebuilds your HUD, prefabs or data, so whatever you changed by hand stays.

#Where you see them

Place What it shows
Overview > To do "N kit updates" with the titles and an Apply button
KitARPG window sidebar A badge with the count on Overview
Play & Servers, MMO step 1 "N kit updates" with Review, reminding you to apply them before building the map server
Shop page Updates the shop needs
Project Check A warning per update ("... is missing."), with its own Apply

#Running them

  1. Press Apply. If the editor is in Play, a dialog says "Stop Play first."
  2. A dialog titled Kit updates lists each update with exactly what it will change, and ends with "Nothing else changes."
  3. Press Apply to run them, or Cancel.
  4. They run in order. Each logs [KitARPG] <title>: <result> to the Console and saves the assets.
  5. If one fails, a dialog lists "Some couldn't be applied:" with the reason; the others still run. Fix the cause (often a missing HUD prefab or database) and apply again.

An update that is no longer needed when its turn comes is skipped. Updates check themselves every few seconds, so the count drops as soon as they are applied.

#The updates in this version

Listed in the order they run.

Update Shows when What it changes
Premium currency for the shop The In-game shop module is on and the database has no premium currency and no gems Creates the currency Gems (id gems, Premium, not shown in the bag) next to your other currencies and adds it to your Game Database. Existing currencies stay as they are
Shop on the player prefabs The shop is on and a player model lacks PlayerShop Adds the PlayerShop component to the listed player prefabs. Nothing else on them changes
Shop window in the HUD The shop is on and the HUD prefab has no Cash Shop Window Adds a Cash Shop Window under Windows in your HUD, and a Shop button after Mail on the toolbar, moving the buttons after it to make room
New shop window: categories, banner and offer pages The HUD has the old shop window Replaces the shop window with the new one: categories and search, sorting, the balance with a top-up button, a banner, cards with a corner ribbon, and a page per offer. Changes you made by hand to the old shop window are lost; the rest of the HUD stays
Guild emblems The Guilds module is on and the database has no Guild Emblems asset Creates a Guild Emblems asset (8 shapes, 24 symbols, 12 colors) next to your database and sets it there. Guilds then pick an emblem when founding
Guild roles, emblem, history and alliance windows in the HUD The Guilds module is on and the HUD's guild window lacks the alliance window, the permissions list or the role dropdown Adds the Guild Emblem Picker, Guild History Window and Alliance Window under Windows; Emblem, History and Alliance buttons in the guild window; a line for what founding asks for. Members get a role dropdown in place of Up and Down, and the Roles tab is made again as a list of roles next to the picked role's permissions
Upper body mask on the player models A humanoid player model has no upper body mask Creates the Upper Body mask (spine, head and arms) if missing and sets it on each listed model's Character Animations, so attacks and casts that start while walking move only the upper body. Clear the field on a model to undo it
Touch controls: skills 1 to 4 and potion on 5 The touch controls prefab still has the Dodge button or the skill buttons aren't in the arc Moves Skill 1 to 4 into an arc around Attack and the Consumable button to the top left, and removes Dodge (dodge stays on its key in third person). Buttons you moved by hand are moved back
Unread mail count on the Mail button The HUD toolbar has a Mail button without a badge Adds a red badge with the number of unread letters to the Mail button. Nothing else in the HUD changes
Note

Two updates replace a piece instead of adding to it: the new shop window, and the guild window's Roles tab. If you restyled those pieces, read the dialog before pressing Apply and redo your changes after.

#Start over is not an update

Start over in Overview (the same as KitARPG > Starter > Build Scenes and Prefabs when the sample exists) builds the starter sample again from scratch. It asks first, and it loses every change made to the sample's scenes, prefabs, HUD and data. Your own assets in other folders stay.

Use it to get a clean sample to look at. Never use it to update a game you built on the sample: use the import and kit updates instead.

#Writing your own updates

You can ship updates of your own, for example in a template you reuse across games. A subclass of KitUpdate with a title, the changes it makes, a check and the change itself appears in Overview by itself. See Kit updates in code.

#Common mistakes

Mistake Result Fix
Editing the sample in place, then importing a new kit Your changes to sample files can be replaced Keep your game in your own folder
Not rebuilding the map server after an update Players get "The game and the server are different versions" Rebuild it and restart the services
Applying updates after building the map server The map server lacks what the updates added Apply updates first, then build
Pressing Start over to update The sample is rebuilt and your changes to it are lost Use kit updates
Ignoring the updates list Windows or components the new code expects are missing Apply them, or review each one in Project Check
