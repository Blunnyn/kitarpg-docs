Getting started

Quick start: MMO

Run the sample as an MMO on your own computer: build the services and the map server, start them, create an account, play, and see two players meet. Everything is driven from the Play & Servers page of the KitARPG window.

#What you are about to run

Piece What it does Port on your computer
Login Accounts, sign in, character list and creation 5100 (HTTP)
Central Sessions, one-use tickets to enter maps, chat, friends, parties, guilds, mail, market; starts map servers 5200 (HTTP), 7700 (UDP map link)
Map servers One Unity server per map, running the game 7777 town, 7778 forest, 7779 crypt (UDP)
Shop (optional) Premium currency, offers, purchases, payments 5300 (HTTP)
Database SQLite file or PostgreSQL

The editor runs all of this through the launcher, without a window. Central starts each map server from your map server build when the first player needs it; town starts with the services.

#Before you start

  • Finish the Setup Wizard.
  • Install the .NET 10 SDK from https://dotnet.microsoft.com/download/dotnet/10.0. See Requirements.
  • Make sure ports 5100, 5200, 7700 and 7777 to 7779 are free.

#Step by step

#1. Open Play & Servers and pick MMO

  1. Open the KitARPG window: KitARPG > Open KitARPG or Ctrl/Cmd+Shift+K.
  2. Go to Play & Servers.
  3. Click the MMO card at the top.

Four numbered steps appear below the cards. They unlock in order: finished steps fold away with a check, the current step opens, and locked steps can't be opened yet. The header of each step summarises where it stands.

#2. Step 1: Check the project

The step header shows how many checks are ready ("3 of 5 ready."). Work through the rows from top to bottom:

Row Fine when What to press
Scenes in Build Settings Title is the first scene and Server is listed Use starter scenes
.NET 10 SDK "Installed: 10.x..." Get .NET opens the download page. After installing, press Check again
Services source Shows the folder with KitARPG.Services.slnx, normally Assets/Blunnyn/KitARPG/Services~ Browse to pick another folder
Services built "Login, Central and the launcher are compiled." Build services. It runs dotnet build on the services, once. Later it reads Rebuild
Map server build "Ready. Rebuild after changing scenes or server code." Build. On a Mac it runs KitARPG > Starter > Build Mac Server, on Windows Build Windows Server. The first build takes a few minutes

Two more rows can appear:

  • N kit updates, when the kit has updates your game lacks. Press Review and apply them before building the map server, so both have them.
  • In-game shop, when the Shop service is available. It says whether the shop is off, running, or on but not running, with Open Shop. The shop is optional; see Shop page.

The map server build goes to Builds/Starter/MacServer/KitARPGServer.app or Builds/Starter/WindowsServer/KitARPGServer.exe, in a Builds folder next to your Unity project folder. Each build writes down the scenes it carries, so Play & Servers knows when a map's scene is missing from it.

Warning

Rebuild the map server after you change a scene, add a map, or change server code. A map server older than your code may refuse clients with "The game and the server are different versions", and one that lacks a map's scene sends players who travel there back to the login.

If Build services fails, the step shows the first error lines. If there are none: "dotnet build failed. Run it in a terminal to see why." Open a terminal in the services folder and run dotnet build to see the full output.

#3. Step 2: Pick the database

Option When to use it
SQLite: a local file (default) Development and small servers. Nothing to install
PostgreSQL: for production Production, or to develop against the same database you deploy

Leave SQLite for this quick start. The file is UserSettings/KitARPG/data/kitarpg.db.

PostgreSQL needs a connection: Set up PostgreSQL... connects to a server you run, can create the database and user for you, or runs PostgreSQL 17 in Docker. You can also write the connection string by hand. See Database.

The Keys line explains that the signing and map keys are made for this computer and kept in UserSettings/KitARPG. New keys makes a new signing key and map key. It is disabled while the services run. Tokens signed with the old key stop being accepted, so clients that were signed in have to sign in again.

You can't change the database while the services run: "Stop the services to change the database."

#4. Step 3: Start the services

  1. Press Start services.

  2. Three lights appear:

    Light Detail
    Login Accounts and characters, port 5100
    Central Sessions, chat, guilds and maps, port 5200
    Maps "Started by Central when someone enters", then the maps that registered

    Each light reads off, starting or up.

  3. Wait until Login and Central are up. The step header then says "Running. Maps: ..." and folds away.

While the services run, the step offers Restart and Stop. Before they start, the export of the game data runs: Play & Servers writes the gamedata.json that Login reads to create characters.

Map in the editor picks a map to run inside this editor instead of from the build, so you can debug it. Leave it on "None, every map runs from the map server build" for now. It can only change while the services are stopped.

Warnings this step can show:

Message Meaning Fix
"Services from an earlier editor session are still running (process ...)" A launcher started before the editor restarted still holds the ports Stop the old services
"Something else is using port ..." Services started from a terminal or another session hold the ports Stop them, then start these
"The services or the map server were rebuilt after they started, so they still run the old code. Restart them." You rebuilt while they ran Restart

#5. Step 4: Play

  1. Press Play client. The editor opens Title and joins the running services as a client at http://127.0.0.1:5100 (Login) and http://127.0.0.1:5200 (Central).
  2. The login screen appears with Username, Password, Remember me, Sign in automatically, Sign in and Create account.
  3. Type a username (3 to 16 letters, digits or _) and a password (8 or more characters), then press Create account. The status reads "Creating account...", then "Account created, signing in...".
  4. The character list opens. Press New, fill Name, Look, Class and Hair, and press Create. See Quick start: single player for the rules of each field.
  5. Select the character and press Play. Central gives the client a ticket for town, and you appear in the town.

Remember me keeps a one-use token on this computer so you don't type the password next time; the password itself is never saved. Sign in automatically (only with Remember me) signs in at start. To sign in as someone else, press Sign out on the character list.

#Two players at once

Play with two in step 4 (also on Overview and in KitARPG > Play With Two Players) shows two players meeting:

  1. It starts the services if they are stopped.
  2. It opens a second editor with Unity's Multiplayer Play Mode. If the package is missing, it offers to install it ("Install").
  3. When Login answers and the second editor is open, it presses Play in both. Each one signs in by itself with a test account and character made for this computer: kitplayer1 playing Aria and kitplayer2 playing Bram. They are kept in UserSettings/KitARPG/quickplay.json.

The first time, the second editor imports the project, which takes a while. If Player 2 can't be started automatically, the Multiplayer Play Mode window opens: turn on Player 2 there and press the button again.

For more than two players, Built client in step 4 has Build (an MMO client for your platform) and Open: open as many built clients as you like. Each opens connected to the local services.

#Running a map in the editor

To debug server code of one map:

  1. Stop the services.
  2. In step 3, set Map in the editor to the map, for example forest: runs in this editor, to debug it.
  3. Start the services. Central now waits for that map to register instead of starting it.
  4. In step 4, press Play map server: forest. The editor plays the Server scene as that map server.
  5. Join with a built client or with Play with two: a player who walks into the forest lands on your editor.

#Making yourself an admin

New accounts start at GM level 1 (Player). To use GM commands online, set the first admin in the database. With the default SQLite database, stop the services and run:

sqlite3 UserSettings/KitARPG/data/kitarpg.db "UPDATE accounts SET \"Role\" = 4 WHERE \"Username\" = 'yourname';"

With PostgreSQL:

UPDATE accounts SET "Role" = 4 WHERE "Username" = 'yourname';

After that, admins change levels in game with /role player level. See GM commands.

#The log

The Log card at the bottom of Play & Servers shows the last lines of the services' output. Open log file opens UserSettings/KitARPG/services.log. Each map server writes its own log to UserSettings/KitARPG/data/logs/map-<id>.log.

#Stopping

Press Stop in step 3. The launcher stops Login, Central and every map server it started. Closing the editor doesn't always stop them: if they are still running next time, Play & Servers offers Stop the old services.

#What goes wrong most often

Symptom Fix
"Can't reach the server." on the login screen The services aren't running, or Login isn't up yet. Check step 3
"That map is not running right now. Try again in a moment." Central couldn't start the map. The map server build is missing or broken; check the map's log in UserSettings/KitARPG/data/logs
"The game and the server are different versions. Update the game." The map server was built from older code. Rebuild it and press Restart
"No map reached Central" in Overview The map server build is missing or out of date. Build it and restart
Travelling to a map sends you back to the login The map server build lacks that map's scene. Rebuild it
"Your character is still being saved. Try again in a moment." You signed in again while the old session was saving. Wait a few seconds
