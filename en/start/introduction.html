Getting started

Introduction

KitARPG is a Unity kit for online action RPGs in the MMO-lite style: shared towns, instanced dungeons, guilds, trading and a real server behind it. This page explains what the kit is, how it is built, who it is for and how to read this manual.

#What KitARPG is

KitARPG, published by Blunnyn, gives you a complete, playable action RPG that you turn into your own game. It is made for people who love RPGs, from those who have never written a line of code to experienced developers.

When you import it you get:

  • A starter sample you can play a few minutes after importing: a town, a forest, a dungeon (the Sunken Crypt), monsters, bosses, quests, shops and the whole interface.
  • Editor tools that let you change the game without code: the KitARPG window with its Game Database, Game Settings, Modules, Play & Servers and Project Check pages, plus step-by-step assistants for new player models and new monsters.
  • The servers: Login, Central and the optional Shop, written in .NET 10, plus a launcher that starts everything with one click.
  • A DevKit for when you want to write code: templates, events, virtual methods and a complete example feature built without touching the kit.

#Two ways to run the same game

The same Unity project and the same scenes run in two ways. You pick one in the Setup Wizard and can change it later in Play & Servers.

Mode Who runs what Saves What you need
Single player The game hosts its own world. The player's computer is client and server at once A SQLite file on the player's computer Unity only
MMO Players log in to your servers: a Login service, a Central service and one Unity server per map One database: SQLite on one computer, PostgreSQL in production Unity and the .NET 10 SDK

The map code is identical in both. A single player game can become an MMO later: you switch the mode, build the servers and keep every map, item and quest you made.

#How an MMO session works

You don't need to know this to play the sample, but it helps when something goes wrong.

  1. Login. The client sends a username and password to the Login service over HTTP (HTTPS in production). Login checks the password hash and answers with a short-lived token and the character list.
  2. Pick a character. The client asks Central to play a character. Central answers with the address of that character's map server and a ticket that works once and expires after 30 seconds.
  3. Enter the map. The client connects to the map server with Mirror (UDP, KCP transport) and shows the ticket. The map checks it with Central, loads the character and spawns it.
  4. Play. The client only asks; the server decides everything. The map saves the character every 60 seconds, when it leaves and when it changes maps.
  5. Change maps. A portal saves the character and asks Central for a ticket to the next map. Central starts that map server if it isn't running yet. The client shows a loading screen and connects to the new map.

One session per account: if someone signs in again with the same account, the old session is closed. The Architecture page goes deeper.

#Design principles

These choices run through the whole kit. Knowing them explains many behaviours you will see.

  • The server decides. Every action is a request. Damage, loot, prices, trades and quest progress are computed on the server. A modified client gains nothing.
  • Every item copy has one owner. In the MMO, items live in one table and each copy belongs to exactly one character, account, guild, letter, tax collector or market lot. Moves between owners happen in database transactions, so items can't be duplicated.
  • Data, not code. Classes, items, skills, monsters, quests and maps are assets edited in the Game Database. Each has a text id, like fire_bolt, that never changes once made.
  • The kit stays read-only. You put your content and code in your own folders. Kit updates add what a newer version brings without overwriting what you changed.
  • Whole numbers. Stat bonuses are always whole numbers, and percentages are whole points.
  • Builds carry only their own code. An MMO client has no server code, GM commands, local save or keys. The editor checks this before every build.

#Conventions

  • Menu paths are in bold with >: KitARPG > Setup Wizard.
  • Field names are in code: autoGold. The label the inspector shows is in italics with its field the first time: Auto Gold (autoGold).
  • Keys are written like Ctrl/Cmd+Shift+K: Ctrl on Windows and Linux, Cmd on Mac.
  • Paths starting with Assets/ are inside your Unity project. UserSettings/KitARPG/ is also inside the project folder, next to Assets, and is never shipped.
