Game content

Maps

A map is a place players can be: a MapData entry in the Game Database plus a Unity scene. This page covers every field of a map, what a map scene needs, how players travel between maps, instanced maps, and a full step by step to add a new map, from the scene to the builds and the servers.

#What a map is

A map has two parts:

  • The entry (MapData, Game Database > World > Maps). Its id is what Central, saves, portals and quests use. It names the scene, its start position, music, whether it is instanced and its PvP rules.
  • The scene. What loads: the ground, the NavMesh, the spawn point, the monsters, the NPCs, the portals.

Builds take every map's scene from the Game Database. You never keep a list of scenes by hand.

The sample has four maps:

Id Scene What it shows
town Town NPCs, shops, quests, the bank, the market, guild services. The start map.
forest Forest Monster spawners, night spawners, the Mushroom King, a discovery zone, world triggers, tax collector spots, PvP in zones from level 5.
crypt Crypt Sunken Crypt, an instanced dungeon with the Void Herald boss.
guild_hall GuildHall An instanced map: each guild that buys its hall gets its own copy.

#Where it is in the editor

Game Database > World > Maps. + New map makes one in a Maps folder next to the database and adds it to the database's maps list. You can also use Create > KitARPG > Map.

A map's card starts with the Adding a map card, which shows each step with a dot (done or to do) and a button where one helps:

  1. A scene: the scene's path once it exists.
  2. Picked below, in Scene.
  3. In Build Settings, for Play: an Add button puts it there.
  4. Reached from another map: reminds you of the portal or teleport, with the map's id.
  5. Monsters for the bestiary: how many were read, with a Read from scene button.
  6. Map server rebuilt.

The start map for new characters is a database setting: Game Database > Database > Settings, Start Map (startMap). A class can override it with its own start map.

#Fields

Field What it does Default
Id (id) What Central, saves, portals, teleports and quests use. Filled from the file name once, then kept. Changing it strands characters saved on this map. From the file name
Display Name (displayName) Name shown in game, for example in "Travel to Forest" and "Discovered: Forest". Empty (asset name)
Description (description) Shown where maps are described. Empty
Scene (scene) The scene that loads for this map. It needs a SpawnPoint and a NavMesh. The field is a scene picker that also says whether the scene is in Build Settings. Empty
Start Position (startPosition) Where new characters appear when this is their start map. 0, 0, 0
Monsters (monsters) Monsters that live here, for the bestiary. Filled by Read from scene from the scene's spawners, plus the adds their bosses call. Empty
Music (music) Loops while players are here. Empty: the music from before keeps playing. None

#Instances

Field What it does Default
Instanced (instanced) Each party, or each player alone, gets its own copy: a dungeon. Online only; a single player world is one copy anyway. Off
Instance Spacing (instanceSpacing) Meters between copies on the map server, so they never see each other. 1000
Empty Minutes (emptyMinutes) Minutes a copy stays after its last player leaves, for those who come back. 5

#Player against player

Field What it does Default
Pvp (pvp) Off, Zones (only inside PvP zones, both players) or Everywhere. Duels work anywhere. Off
Pvp Min Level (pvpMinLevel) Players below this level can't fight others, nor be attacked. 1
Pvp Spare Party (pvpSpareParty) Members of the same party never hurt each other. On
Pvp Spare Guild (pvpSpareGuild) Members of the same guild never hurt each other. On

PvP zones are PvpZone components in the scene (a circle with a Radius, 15 m by default). See PvP and duels.

#What a map scene needs

Object Why Required
SpawnPoint Where characters appear when their saved position isn't usable: a brand new character, someone coming back after dying, someone arriving in an instanced copy. Radius (2 m by default) spreads them out. Project Check reports a map scene without one. Yes
A baked NavMesh (NavMeshSurface) The server moves players and monsters on it, and by default line of sight treats its holes as walls. Yes
Camera, input and effects The sample maps have a Main Camera with the mode's camera and input, an EventSystem, and a Combat Effects object with FloatingText, LootDropsView, SkillEffectsView and CombatEffectsView. Yes, for clients
DayNightCycle Turns the sun and sky with the game clock. Leave it out for maps with fixed light, like the crypt. See Day and night. No
Portal Sends players to another map. To reach other maps
MonsterSpawner Keeps monsters on the map. See Monsters. No
Npc People and objects to talk to. See NPCs. No
DiscoveryZone, WorldTrigger, PvpZone, CollectorSpot Named places, events, PvP areas, tax collector spots. No

Duplicating a sample map scene (Forest is a good start) gives you all of the required objects at once.

#Travelling between maps

#Portals

A Portal sends a player who walks into it to another map.

Field What it does Default
Target Map (targetMap) The id of the map the player arrives on, as Central knows it. forest
Target Position (targetPosition) Where the player appears on the target map. 0, 0, 0
Radius (radius) Meters around the portal that send the player. Drawn as a blue circle in the scene view. 1.5

The portal component is plain data; the map server watches for players inside its radius. The sample's portals are stone gates with a glow; their pieces are left out of the NavMesh bake with a NavMeshModifier set to Ignore From Build, so the gate is walkable.

#Teleport options

An NPC with a Teleport option takes the player to a map and a position, for gold. It can also move them within the same map. See NPCs. A TravelAction does the same from a dialogue line or a quest, without a price. See Conditions and actions.

#Where the player appears

  • Through a portal or teleport, at the target position, moved onto the NavMesh.
  • Logging in, at the saved position on the saved map.
  • When the saved position isn't on the NavMesh (the map changed), at the scene's SpawnPoint.
  • In an instanced map, always at the copy's SpawnPoint.

#Discovering maps

Entering a map marks it as discovered for that character, with "Discovered: <name>". Conditions can ask for it (DiscoveredCondition). See Conditions and actions.

#Instanced maps

With Instanced on, each party gets its own copy of the map, and a player without a party gets one alone. Members of a party end up in the same copy even when they enter separately.

  • MMO: Central picks the copy (party-<id> or solo-<id>) and sends it with the ticket. On the map server, the first scene loaded is a template whose spawners stay idle. Each copy is the same scene loaded again and moved Instance Spacing meters along X, with its own NavMesh, monsters, world triggers and boss. Players always arrive at the copy's SpawnPoint. A copy closes Empty Minutes after its last player leaves.
  • Single player: an instanced map is a normal map. There is already only one copy.
  • Guild halls use the same system with one copy per guild (guild-<id>). See Guilds.

Keep your instanced scene smaller than Instance Spacing, so copies never reach each other. See Dungeons.

#Add a new map, end to end

This adds a map called Caves, reached from the Forest.

#1. Make the scene

  1. In the Project window, find Assets/Blunnyn/KitARPG/Samples/Starter/Scenes/Forest.unity (or your own map scene). Select it and press Ctrl/Cmd+D.
  2. Rename the copy Caves and move it to your own folder, for example Assets/Game/Scenes.
  3. Open it. Delete what you don't want: spawners, NPCs, the altar, collector spots, triggers. Keep the camera, the EventSystem, Combat Effects, Spawn (the SpawnPoint) and NavMesh objects.
  4. Build your level. Keep walls and obstacles as geometry the NavMesh sees.
  5. Select the NavMesh object and press Bake on its NavMeshSurface. The surface's data is saved next to the scene.
  6. Move the Spawn object to where players should stand when they arrive.
  7. Save the scene.
Warning

Each scene needs its own NavMesh data. After duplicating a scene, bake again so the copy doesn't keep pointing to the Forest's NavMesh asset.

#2. Add the map to the database

  1. Game Database > World > Maps > + New map. Rename it Caves. Its id becomes caves.
  2. In Scene, pick Caves.
  3. On the Adding a map card, press Add next to In Build Settings, for Play. Build Settings only matters for Play in the editor; builds add the scene by themselves.
  4. Set Music, Pvp and Instanced if you want them.

#3. Connect it

In the Forest scene:

  1. Duplicate the Forest's portal (or add an empty object with a Portal).
  2. Set Target Map to caves and Target Position to a point near the Caves' spawn.
  3. In the Caves scene, add a portal back with Target Map forest.

Or give an NPC a Teleport option whose Map is Caves.

#4. Fill it

  1. Add Monster Spawners, NPCs, discovery zones and triggers.
  2. On the map's card, press Read from scene next to Monsters for the bestiary.
  3. KitARPG > Render Missing Monster Icons for any monster without a portrait.

#5. Play it in single player

In Play & Servers, pick single player and press Play. Walk through the portal. See Play and Servers.

#6. Make it work online

Each map runs on its own map server, and Central must know the map's id and port.

  1. Central learns the map by itself on your computer. When Play & Servers starts the services, every map of the game database that isn't in UserSettings/KitARPG/launcher.json yet gets an entry there, on the next free port from 7777. To pick the port yourself, or to start the map with the services, stop the services and edit its entry:

    "Maps": [
  { "Id": "town", "Port": 7777, "AutoStart": true },
  { "Id": "forest", "Port": 7778, "AutoStart": false },
  { "Id": "crypt", "Port": 7779, "AutoStart": false },
  { "Id": "guild_hall", "Port": 7780, "AutoStart": false },
  { "Id": "caves", "Port": 7781, "AutoStart": false }
]

    AutoStart starts the map server with the services; otherwise Central starts it when the first player goes there. See Launcher and Configuration.

  2. Rebuild the map server. Each build writes down its scenes, and Play & Servers marks the Map server build step as pending when a map's scene is missing from it. Press Build there, or use KitARPG > Starter > Build Mac Server (or the Windows or Linux one). See Builds.

  3. Start the services again and press Play client. Starting the services also exports the game data that Login reads.

  4. Docker: add the map to Central's list (Central__Maps__N__Id and Central__Maps__N__Port) and copy a map service block in Deploy/docker-compose.yml with the new id and port, then rebuild the Linux server image. See Docker.

  5. Firewall: open the new map's UDP port on the server.

Warning

Without the map in the map server build, players who travel there end up back at the login. Without the map in Central's list, Central can't send anyone there.

#7. Check

Run Project Check. It reports a map with no scene, a scene name that doesn't exist, a scene missing from Build Settings, a scene without a SpawnPoint, two NPCs with the same id, missing scripts and spawners without a monster. See Project Check.

#The world map

The map window (M) shows the current map from above. With a World Map in the Game Database Settings (worldMap), it shows a picture of the whole world instead, with a zone for each map: players drag to move, scroll to zoom, see where they are and each zone's name and levels, click a zone to list its monsters, and a monster to see where it lives and what it drops, with the chance of each. The search at the top finds zones and monsters by name. The sample's island is painted by Art/Tools/make_world_map.py.

#Draw your own

  1. Open KitARPG > World Map Editor and press New world map. It is created next to the game database and set on it.
  2. Set the Picture: any sprite of your world.
  3. Drag on empty space to make a zone. Click a zone to pick it and drag its corners; Add corner and Remove corner change its shape.
  4. On the right, set its Map. Name is optional (the map's name shows otherwise), and so are Min Level and Max Level: left at 0, they come from the map's monsters.
  5. Press World area from the scene: it reads how much ground the map's scene covers, so players show in the right part of the zone. Without it they show in its middle.

Scroll to zoom the editor and drag with the middle button, or with Alt, to move. A HUD made before the world map gets it from the kit update World map with zones in the map window in Overview.

#Single player and MMO

  • Single player: every map runs inside the game, which is the host. Travelling loads the other scene.
  • MMO: one Unity map server per map, each on its own UDP port. A client signs in to Login, asks Central for a one-use ticket and joins the map server with it. Travelling asks Central for a ticket to the other map; Central starts that map's server if it isn't running. See Architecture.

The scene code is the same in both, so a map made for single player works online.

#Common mistakes

  • Back at the login after a portal. The map server build doesn't have the scene, or Central doesn't list the map. Rebuild, and check launcher.json.
  • Players fall or stand in the air. The NavMesh isn't baked, or the scene uses another scene's NavMesh data.
  • Monsters missing from the bestiary for this map. Press Read from scene after placing spawners.
  • Portal does nothing. Target Map is the display name instead of the id, or there is a typo. Ids are lower case with underscores.
  • Instanced copies see each other. The scene is larger than Instance Spacing.
