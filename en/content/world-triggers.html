World triggers

A world trigger makes something happen in the world when a player walks into a spot, or when a dialogue line, a quest or a clicked object sets it off: monsters show up, objects appear or vanish, and actions run on the player. This page covers every field of the WorldTrigger component, personal and shared triggers, how they repeat and reset, and step by step examples.

#What a world trigger is

A WorldTrigger is a component on an object in a map scene. Like a portal, it is plain scene data: the client and the server both have it, the server decides when it goes off and tells the clients what to show.

When it goes off, it can:

  • run actions on the player who set it off,
  • spawn monsters around it,
  • show objects (a portal, a chest, a glowing rune) and hide others (a wall, a sealed door),
  • count for quests with a Trigger objective naming it.

It goes off in one of two ways:

  • Enter: a player walks within its radius.
  • Manual: a Trigger option on an NPC or object, a Fire Trigger action, the GM command /trigger id, or code.

And it happens for one of two audiences:

  • Personal: only the player who set it off sees what it does. Its monsters are theirs alone.
  • Everyone: it happens for everyone on the map.

#Where it is in the editor

Select any object in a map scene and Add Component > World Trigger. The scene view draws its radius on the ground: purple for personal triggers, orange for shared ones (a small circle for manual triggers).

#Fields

#Setting it off

Field What it does Default
Trigger Id (triggerId) Unique on its map. Quests, actions and dialogue lines name it. Empty uses the object's name. Empty
Activation (activation) Enter: walking within the radius. Manual: only from a Trigger option, a Fire Trigger action, the GM command or code. Enter
Radius (radius) Meters around the object, on the ground, for Enter triggers. 4
Scope (scope) Personal: only the player who set it off sees what it does. Everyone: everyone on the map. Personal
Conditions (conditions) Who can set it off: a quest in progress, an item carried, a class. Empty
Once (once) Once per player when personal (it stays done), once while the map runs for everyone. Otherwise again after the cooldown. On
Cooldown (cooldown) Seconds before it can go off again when not once. For personal triggers, the cooldown is per player. 30
Reset After (resetAfter) Seconds until the objects go back as they were. 0 leaves them. A personal trigger is also armed again for that player. 0

#What happens

Field What it does Default
Actions (actions) Run on the player who set it off. If one can't, nothing happens. Empty
Monsters (monsters) Monsters it spawns (below). Empty
Monster Lifetime (monsterLifetime) Seconds the monsters stay; 0 until killed. Personal ones also go when their player leaves. 120
Show (show) Objects shown when it goes off: a portal, a chest, a glowing rune. They start hidden. Empty
Hide (hide) Objects hidden when it goes off: a wall, a sealed door. Empty

#Each monster entry

Field What it does Default
Monster (monster) The monster. None
Count (count) How many. 1
Offset (offset) From the trigger, where they appear. 0, 0, 0
Spread (spread) Meters around that point they scatter. 2

#How it goes off

On the server, for each attempt:

  1. A player who is dead or leaving is ignored.
  2. Conditions are checked. If one fails, a manual trigger tells the player why (over their head); an Enter trigger stays quiet. Either way the player isn't checked again for 3 seconds, so walking around inside doesn't repeat the refusal.
  3. Quest progress: a Trigger objective naming this trigger counts for the player now, even if the trigger is spent.
  4. If the trigger is spent (see below), it stops here.
  5. Actions are checked and run. If one can't run, nothing happens and the player is told why (manual triggers).
  6. The trigger is marked as done, objects are shown and hidden, monsters spawn.

Enter triggers check the players inside their radius four times a second.

#Spent, once and cooldown

Scope Once on Once off
Personal Once per player, for good. It is saved as the story mark trigger.<id> on the character. Again for that player after Cooldown.
Everyone Once while the map server runs. A restart arms it again. Again for anyone after Cooldown.

#Reset After

With Reset After above 0:

  • Everyone: after that many seconds, shown objects hide again and hidden ones come back, for everyone.
  • Personal: after that many seconds, the player's trigger.<id> mark is cleared, so the objects go back on their screen and the trigger is armed again for them.

#Personal and everyone

#Personal

  • Objects change only on that player's screen. Each client shows what its own player's trigger.<id> mark says, so a rune lit yesterday is still lit when the player comes back.
  • Monsters are event monsters for that player alone: only that player sees them, fights them and can hurt them, with their summons. Other players' attacks don't reach them. They go when the player leaves the map.
  • A Flag condition with Key trigger.<id> tells whether a player already did it.
Warning

On a dedicated map server, a personal trigger's objects change only on the client. The server's NavMesh doesn't change. To really open a passage (a wall that falls), use a trigger for everyone, or make sure the object doesn't block the server's NavMesh.

#Everyone

  • The server switches the objects and tells every player on the map. A player who arrives later gets the current state when they enter.
  • Monsters are event monsters anyone can fight.
  • In an instanced map, "everyone" is everyone in the same copy. Each copy has its own triggers.

#Event monsters

Monsters a trigger spawns:

  • don't come back after dying; they go 4 seconds later,
  • go after Monster Lifetime seconds (0: only when killed),
  • give experience and loot like any other monster.

#Make a lever, altar or chest

The sample's Strange Altar in the Forest: with the quest "Whispers in the Woods" taken, touching it wakes two mushroom guardians and lights a rune, and only that player sees them.

  1. Build the object: a stone base and a Rune child. Leave the rune active in the editor; the trigger hides objects in Show when the scene starts.
  2. Add Component > Npc. Npc Id altar, Display Name "Strange Altar", Greeting empty, Talk Range 2.5. Give it a collider.
  3. Under Add option, press Trigger. Trigger forest_altar, Label "Touch the altar". With no greeting and one option, clicking the altar fires it at once.
  4. Add Component > World Trigger on the same object:
    • Trigger Id forest_altar, Activation Manual, Scope Personal.
    • Conditions: Quest, Quest Whispers in the Woods, Check Taken, Fail Text "The stone is cold and silent."
    • Actions: Message, Text "The altar hums. Something stirs!"
    • Monsters: Mushroom, Count 2, Offset 0, 0, 3, Spread 1.5.
    • Show: the Rune.
  5. Make the quest: objectives Trigger (Trigger forest_altar, Target Name "the altar in the forest") and Kill Mushroom x2 with the text "Defeat what the altar called". See Quests.
  6. Give the quest to an NPC with a Quest option.

Without the quest, clicking the altar shows "The stone is cold and silent." With it, the rune lights and the guardians come out.

#Make an area event for everyone

The sample's Slime Swarm in the middle of the Forest: from level 2, walking in makes 4 slimes pour out for everyone, and it rests 2 minutes.

  1. GameObject > Create Empty in the clearing, named Slime Swarm Trigger.
  2. Add Component > World Trigger:
    • Trigger Id slime_swarm, Activation Enter, Radius 3, Scope Everyone.
    • Once off, Cooldown 120.
    • Conditions: Level, Min 2.
    • Actions: Message, Text "Slimes pour out of the bushes!", an orange color.
    • Monsters: Slime, Count 4, Offset 0, 0, 4, Spread 3.
    • Monster Lifetime 90.

#Make an ambush when a quest is taken

  1. Place a manual trigger bandit_ambush with Scope Personal and bandits in Monsters, by the road.
  2. On the quest, On Accept: Fire Trigger bandit_ambush.

The quest's NPC must be on the same map as the trigger: Fire Trigger sets off a trigger on the player's current map.

#Make a door that opens after a talk

  1. A wall object, and a World Trigger old_gate with Activation Manual, Scope Everyone, Hide: the wall, Reset After 300.
  2. A dialogue line on the gatekeeper with Actions: Fire Trigger old_gate.

Everyone sees the wall go for 5 minutes, then it comes back. See Dialogues.

#Test triggers

  • /trigger forest_altar sets it off as if you clicked it, conditions included.
  • /flag trigger.forest_altar 0 arms a personal trigger again for you.
  • Restarting the map (stopping Play, or the map server) arms triggers for everyone.

See GM commands.

#Single player and MMO

  • Single player: the game is the host; personal and everyone triggers behave the same, and a personal trigger's objects really change in the one world there is.
  • MMO: the map server decides and tells the clients. Personal monsters are only sent to their player, so no other client, even a modified one, can see them. Everyone triggers that are Once fire once per map server run.

#For programmers

WorldTrigger.ServerFire(id, player, tell) sets one off from code. WorldTrigger.ServerFired (trigger, player) tells other systems one went off. Monster.ServerMakeEvent(player, seconds) turns a monster you spawn into an event monster. See Events.

#Common mistakes

  • Nothing happens on click. The Trigger option's id doesn't match the trigger's Trigger Id, or they are on different maps.
  • The objects in Show are visible before it fires. They are hidden when the scene starts; check they are listed in Show, not in Hide.
  • It fires once and never again. Once is on. Turn it off and set a Cooldown.
  • Other players walk through a "fallen" wall. It was a personal trigger. Use Everyone for things that change the path.
  • The quest step doesn't count. The objective's Trigger doesn't match, or the player doesn't meet the trigger's conditions.
