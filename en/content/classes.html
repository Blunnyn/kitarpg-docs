Classes

A class is what a character is: the attributes and stats it gets at each level, the skills it can learn, the statuses it shrugs off, the items it starts with and the map it starts on. This page covers every field of a class, the experience table, and how to make a new class step by step.

#What a class is

Every character has exactly one class, picked on the character creation screen and saved with the character as its class id. The class decides:

  • The attribute points the character gets for free at each level, before the player spends any.
  • The base stats at level 1 and what each level after it adds.
  • How many attribute points and skill points the player earns per level.
  • Which skills the character can learn with skill points, from which level, and up to which rank.
  • Which statuses it is immune to or resists.
  • The items a new character starts with, worn or in the bag.
  • The map a new character appears on.

A class does not list weapons or armor. Each weapon and piece of gear says which classes can use it (see Equipment), so adding a new weapon never means editing your classes.

Which classes a player can pick depends on the look they choose: every player model lists the classes it can be. The sample has four classes: Warrior, Hunter and Mage, which the male and female bodies can take, and Monk, which only the panda body can take.

#Where classes are in the editor

Open the KitARPG window (KitARPG > Open KitARPG, Ctrl/Cmd+Shift+K) and go to Game Database. Classes are in the Characters group, under Classes. The list shows each class with its icon, name and id; the panel on the right shows the selected class.

You can also create a class asset from the Project window with Create > KitARPG > Character Class. A class made that way only counts once it is reachable from the game database: list it under Classes, or add it to a player model (the database collects classes from the models on its own).

Tip

The fastest way to get a new class that plays well is to duplicate an existing one. Select the class in Game Database and press Duplicate, or use + New class with copy of in the new player model wizard.

#Fields

Every class also has the four fields every game data asset has.

Field What it does Default
Id (id) Saved with characters and sent in network messages. Filled from the file name when the asset is made (Fire Bolt becomes fire_bolt) and never changes after, so renaming the file is safe. Changing it by hand breaks every saved character of this class. From the file name
Display Name (displayName) The name players see. Empty uses the file name. Empty
Description (description) Shown on the character creation screen and in tooltips. Empty
Icon (icon) Shown in lists, on the creation screen and in the Game Database. None

#Attributes

Field What it does Default
Attributes (attributes) A list of attribute and amount pairs. Each entry gives the character points in that attribute at every level, before the points the player spends. Empty
Attribute (attribute) The attribute the entry raises. None
Amount (amount) A level value: Base Value (baseValue) is the amount at level 1 and Per Level (perLevel) is added for each level after the first. The result is rounded to a whole number of points. 0, 0

A level value always works the same way across the kit: value at level L = baseValue + perLevel × (L − 1).

For example, the sample Warrior has Strength 8 base and 2 per level. At level 10 that is 8 + 2 × 9 = 26 points of Strength from the class alone. Agility 4 base and 1 per level gives 13 at level 10. Intelligence 2 base and 0.5 per level gives 6.5, rounded to 7.

#Stats

Field What it does Default
Base Stats (baseStats) The class's stats at level 1, before attributes, gear and buffs. Every stat can be set here. Max Health 80, Max Mana 30, Move Speed 3.5, Crit Damage 0.5 (50%), everything else 0
Stats Per Level (statsPerLevel) Added to the base stats for each level after the first. Max Health 12, Max Mana 4, everything else 0

The base stats are the only place where a stat can keep decimals: a walk speed of 3.7 meters per second is fine. Every bonus from attributes, gear, sets, gems and statuses counts in whole numbers and whole percents (see whole numbers).

Percent stats are written as fractions in the base stats: critChance = 0.05 is 5%, critDamage = 0.5 is +50% damage on a critical hit.

#Points per level

Field What it does Default
Points Per Level (pointsPerLevel) Attribute points the player earns for each level after the first, to spend in the Character window (C). 5
Skill Points Per Level (skillPointsPerLevel) Skill points the player earns for each level after the first, to spend in the Skills window (K). Skills this class unlocks at level 1 start learned at rank 1 without spending points. 1
Exp Table (expTable) The experience needed for each level. Empty uses the game database's table. None

Points are never stored as a free total. The server works out free attribute points as earned minus spent, and free skill points as earned (plus any bonus points from scrolls) minus spent, every time. So if you change Points Per Level later, existing characters get the new amount on their next login.

#Skills

Field What it does Default
Skills (skills) The skills this class can learn with skill points. Empty
Skill (skill) The skill. None
Unlock Level (unlockLevel) Character level needed for rank 1. Later ranks need more levels: rank n needs unlockLevel + (n − 1) × levelsPerRank, where Levels Per Rank is set on the skill. 0
Max Level (maxLevel) Highest rank this class can raise the skill to. 0 uses the skill's own Max Level. A value above the skill's own max is capped to it. 0

Skills with an unlock level of 1 (or 0) start learned at rank 1 for new characters, without spending a point.

Example: the sample Warrior has Cleave at 1, War Cry at 3, Ground Slam at 5, Unbreakable at 6, Shield Wall at 7, Charge at 9, Leap Strike at 11. Cleave has Levels Per Rank 2, so rank 3 of Cleave needs level 1 + 2 × 2 = 5.

Characters can also learn skills that are not in their class, from books, scrolls and trainer NPCs. That is set on the skill itself; see Learning outside the class.

#Status defense

Field What it does Default
Status Defense (statusDefense) Statuses the class is immune to or that last less on it. Same block as on monsters and on statuses. See Immunities and resistances. Empty

This only stops harmful statuses that enemies put on the character. Buffs from the character itself or its allies always land.

#Start items and start map

Field What it does Default
Start Items (startItems) What a new character of this class gets. Empty
Item (item) The item. None
Amount (amount) How many. Values below 1 count as 1. 0
Equipped (equipped) Worn on creation instead of going to the bag. Only works for items that can be worn; if the slot is taken or the character can't wear it, it goes to the bag. Off
Start Map (startMap) The map a new character appears on. Empty uses the game database's Start Map. None

Gear with random bonuses rolls its values for each start item copy, so two new warriors can start with slightly different swords. See Random bonuses.

Example: the sample Hunter starts with the Longbow and the Ranger Armor worn, 200 Arrows worn in the ammo slot, 5 Health Potions and 3 Mana Potions.

#The experience table

Each class can have its own experience table, or share the one in Game Database > Settings (Exp Table). Create one with Create > KitARPG > Experience Table.

Field What it does Default
Max Level (maxLevel) The level cap. Characters at this level stop gaining levels. 60
First Level (firstLevel) Experience to go from level 1 to 2, when the table uses the curve. 100
Growth (growth) Each level needs this many times the previous one, when the table uses the curve. 1.15
Exp To Next (expToNext) Experience from each level to the next, written by hand. Index 0 is level 1 to 2. Empty uses the curve. Levels past the end of the list also use the curve. Empty

With the curve, the experience from level L to L + 1 is firstLevel × growth^(L − 1), rounded. With the defaults: 100 to reach level 2, 115 to reach 3, 132 to reach 4, and so on.

To write the curve's values into the list so you can tweak single levels, right click the table asset's header in the Inspector and pick Fill table from curve.

#How a class shapes a character, step by step

When the server works out a character's numbers (on login, on level up, when gear, attributes, buffs or passive skills change), it does this:

  1. Takes the class's attribute amounts at the character's level.
  2. Adds the attribute points the player spent.
  3. Adds attribute points from gear, sets, gems, buffs and passives.
  4. Adds the class's base stats plus Stats Per Level × (level − 1).
  5. Adds what each attribute point gives, for every attribute.
  6. Adds every flat bonus from gear, sets, gems, statuses and passive skills.
  7. Applies every percent bonus to the totals and rounds.

The full detail, with a worked example, is in How stats are computed.

#Make a new class

This example makes a Paladin: a melee class with Vitality and Strength, some healing, and resistance to stuns.

  1. Open Game Database > Classes and select Warrior. Press Duplicate. The copy gets its id from its new file name (something like warrior_1). Since no character uses it yet, type paladin in Id and Paladin in Display Name.
  2. Write a Description, for example "Holy warrior. Vitality, strength and a few heals." Set an Icon.
  3. In Attributes, give it Vitality 8 base 2 per level, Strength 6 base 1.5 per level, Intelligence 4 base 1 per level. Remove Luck and Agility or give them small values.
  4. In Base Stats, set Max Health 100, Max Mana 35, Move Speed 3.4, Crit Damage 0.5. In Stats Per Level, set Max Health 15, Max Mana 3.
  5. Leave Points Per Level at 5 and Skill Points Per Level at 1.
  6. In Skills, keep Cleave at level 1 and Shield Wall at level 7, and add Heal at level 3 and Divine Shield at level 6. Set Max Level on Heal to 3 if you want paladins to heal less well than mages.
  7. In Status Defense, open Resistances and add one with Tag control and Percent 30: stuns, roots and silences last 30% less on a paladin.
  8. In Start Items, keep the Sword equipped, replace the Knight Armor with what you want, and keep 5 Health Potions in the bag.
  9. Add the class to a player model: open Models, select the male or female body and add Paladin to its Classes. Without this, nobody can pick it.
  10. For the class to use your new skills from a mace, open each mace in Items > Weapons and add Paladin to its Classes (or leave the weapon's Classes empty so any class can use it).
  11. Press Play from the Title scene and make a character. The class appears in the class list of the bodies you added it to.
Warning

Gear that lists classes in Classes is only usable by those classes. If you duplicated the Warrior, the Knight set still lists only the Warrior. Add the new class to each piece it should wear, or clear the list.

#Single player and MMO

The class data is the same in both modes, and the server rules (stats, points, skills) run on the map server in MMO and inside the game in single player.

In MMO, character creation goes through the Login service, which doesn't run Unity. It reads a gamedata.json exported from your game database with, for each class: its id, health and mana at level 1, start map and position, and start items (already placed in the bag or worn). Login also checks that the class is one the chosen model offers, and refuses a class that isn't.

  • Play & Servers exports gamedata.json every time it starts the services, so in the editor this is automatic.
  • For builds and Docker, export it with KitARPG > Export Game Data for Services, which writes it next to the Login service so the image carries it.

If you change a class's start items or start map and Login still creates characters the old way, the export is out of date.

In single player there is no Login service: the game creates the character itself from the class asset.

#Tips

  • Give each class one or two attributes that clearly grow faster than the others. Players read the class from those.
  • Keep Stats Per Level modest and let attributes do most of the work. Then spending points matters.
  • To make a class that can't be picked at creation (for example, one a quest turns you into later), keep it out of every player model. It still exists in the database if something references it.

#Common mistakes

  • The class doesn't appear on the creation screen. It isn't in any player model's Classes. Add it to a model.
  • Saved characters lost their class. The class id was changed. Put the old id back.
  • Login says the class is not allowed. The gamedata.json Login reads is older than your change. Export again or restart the services from Play & Servers.
  • A start item lands in the bag instead of being worn. The class can't wear it (Classes or Required Level on the item), or two start items want the same slot.
