Player models

A player model is a player prefab: a body players pick when they make a character, with the classes that body can be, its hair styles, how gear shows on it and its animations. This page covers the PlayerModel component, modular bodies and gear pieces, hair, animations, and the New player model wizard.

#What a player model is

Every playable character is spawned from a player prefab. The prefab carries:

  • Player Model (PlayerModel): the id saved with characters, the name on the creation screen, the classes this body can take and the hand bones.
  • Every player system: networking, movement, inventory, stats, skills, quests, chat, friends, party, trade, guild, bank, forge, mail, market, shop, PvP.
  • Modular Character (ModularCharacter): swaps body regions for gear pieces and bakes them into one mesh.
  • Equipment View (EquipmentView): shows worn gear, armor on the body and weapons in the hands.
  • Character Appearance View (CharacterAppearanceView): applies the hair style picked at creation.
  • Character Animations (CharacterAnimations): every clip and its hit timings.
  • Nameplate (Nameplate): the name over the head.

A character saves its model id (appearance.model) and its class id. The sample has three models: a male body, a female body (both can be Warrior, Hunter or Mage) and a panda body (voxel_panda) that can only be a Monk.

#Where models are in the editor

Game Database > Characters > Models lists every player prefab in the database. Selecting one shows a preview (double click opens the prefab), its id, name and classes, and the Animations cards. If a prefab has no Character Animations component, the page offers Add Character Animations.

The database's Player Models (playerModels) field holds the prefabs. Whatever they reference is collected on its own: classes from the models, skills and start items from the classes, and so on.

#The Player Model component

Field What it does Default
Model Id (modelId) Saved with characters. Filled from the GameObject's name the first time. Changing it later makes existing characters of this model appear with the first model in the list instead. From the name
Display Name (displayName) Shown on the creation screen. Empty uses the GameObject's name. Empty
Classes (classes) Classes a character with this model can be. The first one is the default on the creation screen. Empty
Own Hair Only (ownHairOnly) Keeps the body's own hair, ears or horns. The creation screen offers no hair styles for this model. The panda uses it for its ears. Off
Right Hand Bone (rightHandBone) Name of the bone that holds main hand weapons. mixamorig:RightHand
Left Hand Bone (leftHandBone) Name of the bone that holds shields, off hand weapons and bows. mixamorig:LeftHand

The server (Login in MMO, the game itself in single player) refuses a class the chosen model doesn't list. A model with no classes shows up as a problem in the database's problem list.

If you remove a model from the database, characters made with it are not locked out: they appear with the first model in the list.

#Modular bodies

Gear changes how a character looks by swapping whole body regions. A body is split into regions, each one its own skinned mesh on a shared skeleton:

Region Body mesh name Gear that replaces it
Head Body_Head Head slot
Chest Body_Chest Chest slot
Hands Body_Hands Hands slot
Legs Body_Legs Legs slot
Feet Body_Feet Feet slot
Hair Body_Hair Hair style
Back none Back slot (capes, packs, wings)

A gear piece is the whole region remade with the gear on, named <Set>_<Region>: Knight_Chest, Short_Hair, Wizard_Head. Since the piece replaces the region, the skin under the armor doesn't exist and nothing is drawn twice. The body has nothing on its back, so a back piece only adds.

A body may ship without some regions (a bald body has no hair); gear can still go there.

#Modular Character

Field What it does Default
Combine Meshes (combineMeshes) Bakes every region into a single mesh: one skinning pass and one draw call per character. Needs Read/Write turned on in the import settings of every mesh. Characters with the same gear share the same baked mesh. If a mesh is not readable, the kit logs a warning and draws the regions apart. On
Head Gear Hides Hair (headGearHidesHair) Helmets and hats hide the hair. Turn it off if your head gear is modeled to sit over the hair. Single pieces can keep the hair with Keeps Hair on the item. On
Region Meshes (regionMeshes) The body's mesh for a region when its name doesn't say which: a mesh called Helmet or 821381 for the head. Regions left out are found by name. Empty

The kit finds each region's mesh by name: first Body_Head, then any mesh whose last word (after _ or a space) is the region or a common word for it, like Helmet, Torso, Gloves, Boots or Cape. Under the component, Regions shows which mesh each region uses and whether it was found by name or set by hand. A region with no mesh is fine: hair styles and capes still go there. Words of your own go in ModularCharacter.RegionNames from code.

Gear pieces must use the same bone names as the body. The piece's bones are matched by name, so a piece rigged to a different skeleton won't follow the body.

#Gear per body

An item has one Model and optional Model Variants: a different piece per player model id. The sample's armor has a male piece as the default and a voxel_female variant, and every body piece has a _Panda copy assigned as the voxel_panda variant. See Look and wear.

#Weapons and shields

Items in the main hand and off hand slots are not body regions. They are props hung from the hand bones named on the Player Model. Each item sets which hand holds it and its offset (Left Hand, Hold Position, Hold Rotation). A second one-handed weapon in the off hand is shown mirrored.

Equipment View also has Model Id, Right Hand Bone and Left Hand Bone fields. On a player prefab they are taken from the Player Model, so you don't set them.

#Fixed outfits

For a character that never changes gear, like an NPC, add Character Outfit (CharacterOutfit) next to a Modular Character and list models in Outfits (outfits). Every piece named <Set>_<Region> in those models goes on the body when it starts.

#Hair styles

Hair styles are in an Appearance Catalog asset (Create > KitARPG > Appearance Catalog), set on each player prefab's Character Appearance View in Catalog (catalog).

Field What it does Default
Hair Styles (hairStyles) The styles players can pick on the creation screen. Empty
Id (id) Saved with characters. Changing it changes the look of characters that use it. Empty
Display Name (displayName) Shown in the hair list. Empty
Model (model) A model whose mesh is named <Something>_Hair. None

The creation screen's hair list starts with Body default, which keeps the body's own hair. A model with Own Hair Only disables the list.

#Animations

Character Animations lists every clip a character plays and when each attack and skill lands. The Animator needs no setup: every character uses the kit's controller (KitARPG/KitCharacter, in Runtime/Resources) and this component swaps its clips in. Don't edit that controller.

The server reads the hit timings from here, so damage lands when the animation strikes. A clip left empty is not played, but its timing still counts.

Field What it does Default
Animator (animator) The Animator to drive. Found in the children when empty. Without one nothing plays, but hits still land on time. None
Idle (idle) Standing still. None
Walk (walk) Walking. Empty uses the run. None
Run (run) Running. None
Run Speed (runSpeed) Meters per second the run clip is made for. Faster or slower movement plays it faster or slower. 3.5
Hit (hit) When taking damage, unless attacking or casting. None
Death (death) Dying. None
Stunned (stunned) Looped while stunned. None
Attack (attack) Bare handed, or with a weapon type not listed in Weapons. One hit at 0.5
Weapons (weapons) One attack per weapon type: Weapon Type and Attack. Empty
Cast (cast) Looped while casting or channeling a skill not listed in Skills. None
Skill (skill) Using a skill not listed in Skills. Skills with Use Weapon Attack play the weapon's attack instead. One hit at 0.5
Skills (skills) Per skill: Skill, Cast (looped while casting; empty uses the default cast) and Use (when the cast ends; its effects land on the hit frames). Empty
Upper Body Mask (upperBodyMask) The bones attacks, skills and casts move while the legs keep walking: usually spine, arms and head. Create one with Create > Avatar Mask. Empty plays actions on the whole body. None
Mask Only While Moving (maskOnlyWhileMoving) Use the mask only for actions that start while moving; standing still they play on the whole body. Off: always masked, so the legs keep their idle. On
Mask Casts (maskCasts) Casts and channels use the mask too. On
Moving Speed (movingSpeed) Meters per second from which the character counts as moving. 0.3

Each attack and skill use is an action animation:

Field What it does Default
Clip (clip) Played on characters with an Animator. None
Duration (duration) Seconds it lasts at normal speed. 0 uses the clip's length (0.6 seconds without a clip). 0
Hits (hits) When each hit lands, from 0 (start) to 1 (end). Damage is split between them: two hits at 0.3 and 0.7 each deal half. One at 0.5
Sound (sound) Played when it starts. None
Full Body (fullBody) Plays on the whole body even while moving, for jumps and spins. Only matters with an upper body mask. Off

When attack speed makes attacks faster than the clip, the clip speeds up to fit. Moving cuts an attack or a cast; a projectile already launched still arrives.

#Make a new player model

The New player model wizard turns a 3D model into a playable body in four steps.

  1. Open Game Database > Models and press + New player model. The wizard opens on the right.

  2. Model. Drop an FBX or a prefab from the Project window into the field. The wizard tells you:

    • whether it has an Animator ("No Animator" means it won't animate);
    • whether the rig is Humanoid (weapons go in its hands and it can share the kit's animations) or Generic (use animations made for that rig and set the hand bones afterwards);
    • if it has no skinned meshes (gear then can't swap body parts).

    Give it a Display name and an Id. The id is saved with characters; changing it later breaks the characters made with it. Tick Own hair only if the body has its own hair, ears or horns.

  3. Classes. Tick the classes this body can be. The first ticked is the default. Under New classes, + New class adds a class made with this model, empty or as a copy of another class. Each new class needs a unique name.

  4. Animations. In Start from a model, pick an existing model to copy its animations (clips, hit timings, per weapon and per skill) and its appearance catalog. Copy its animations and Copy the game's own components on it (not the kit's) are both on by default. The wizard warns when one model is humanoid and the other isn't, since the clips may not play. With Nothing, start empty you fill the clips in afterwards; hits still land on time. For a humanoid rig, Use an upper body mask (on by default) lets it attack and cast while walking; leave the mask field empty to use the kit's.

  5. Create. Check the Prefab folder (inside Assets, by default a Prefabs folder next to your database's data folder), read the summary of what will be made, and press Create player.

The prefab is made with every player system, added to the database's Player Models, new classes are created in a Classes folder next to the database and added to Classes, and the new model opens in the Game Database to edit.

If you built a player prefab by hand, drag it into Add prefab on the Models page instead.

#Making gear fit a new body

For gear to swap on your body:

  1. Split the body into skinned meshes named Body_Head, Body_Chest, Body_Hands, Body_Legs, Body_Feet and optionally Body_Hair.
  2. Make each gear piece as the full region with the gear on, rigged to the same skeleton (same bone names), named <Set>_<Region>.
  3. Turn on Read/Write in the import settings of every mesh, or turn off Combine Meshes.
  4. On each item, set Model to the model that holds the piece, or add a Model Variants entry with your model id if the default model is fitted to another body.

#Single player and MMO

Models work the same in both modes. In MMO, the Login service creates characters without Unity, so it reads the models and their class lists from gamedata.json, exported from your database (automatically by Play & Servers when it starts the services, or with KitARPG > Export Game Data for Services for builds). A new model, or a class added to a model, needs a fresh export before Login accepts it.

A headless map server doesn't draw anything, so Equipment View turns itself off there; the gear ids still travel to every client, which draws them.

#Tips

  • Copy animations from a sample model when your rig is humanoid. You get every attack and skill timing at once and can swap clips later.
  • Keep Combine Meshes on. It is the biggest saving in crowded towns.
  • One model per body type, with the same skeleton, lets every set work on every body with only a fitted variant per piece.

#Common mistakes

  • Gear appears white or doesn't swap. The piece's mesh name doesn't end in a region name (_Chest, _Head...), or its bones have different names from the body's.
  • "is not readable" warning in the Console. Turn on Read/Write in the mesh's import settings.
  • Weapons float next to the hand. The hand bone names on the Player Model don't match the rig, or the item's Hold Position is off.
  • Characters changed body after an update. The model id was changed or the model was removed; they fall back to the first model.
