Reference

FAQ

Answers to the questions buyers ask most about KitARPG: what it can do, how single player and MMO differ, content, servers, costs, security and extending it. Each answer links to the page with the details.

#About the kit

#Do I need to know how to code?

No. You can make classes, items, skills, monsters, quests, NPCs and maps from the KitARPG window and the inspector, set how the game plays in Game Settings and turn systems on and off in Modules. Code is for when you want something the kit doesn't do. See Game Database.

#Which Unity version do I need?

Unity 6000.6.0f1 (Unity 6.6) or newer, with the Universal Render Pipeline. The Setup Wizard sets URP up for you. See Requirements.

#Does it work with the Built-in render pipeline or HDRP?

No. The kit's materials and sample are made for URP 17.6 in Linear color. With another pipeline they show pink.

#Does it work with the new Input System, the old Input Manager, or both?

Both. The kit reads keys and the mouse through KitInput, which uses the Input System package when Active Input Handling includes it and the Input Manager otherwise. Set everything up and Project Check's Fix scenes give each scene's EventSystem the UI module of the input you use. See Keys.

#What networking library does it use?

Mirror with the KCP transport (UDP) between clients and map servers, and LiteNetLib between map servers and Central. Mirror ships inside the package. See Architecture.

#Which platforms can I build for?

The kit's menus build Mac and Windows clients and single player games, Mac and Windows map servers for local testing, and Linux map servers for Docker. Touch controls are included for touch screens. See Builds.

#Is the art included and can I use it in my game?

Yes. The voxel characters, gear, weapons, monsters, icons and animations ship in Assets/Blunnyn/Art as part of the package.

#Single player and MMO

#What is the difference between single player and MMO?

In single player the game hosts its own world and saves on the player's computer; there is nothing else to run. In MMO, players log in to your servers (Login, Central and one map server per map) that share one database. The scenes, data and code are the same. See Introduction.

#Can I make a single player game into an MMO later?

Yes. Pick MMO in Play & Servers, build the services and the map server, and start them. Your maps, data and code stay as they are. Single player saves don't move to the MMO database.

#Can I play the MMO without a server machine?

Yes. On your computer, Play & Servers builds and starts Login, Central and the map servers with a local SQLite database. See Quick start: MMO.

#How many players can a map hold?

The kit sets no fixed limit. How many players a map holds depends on your maps, monsters, skills and server machine, so measure with your own content. Each map runs in its own process, and players only receive what is near them, so you add maps rather than overload one. See Performance.

#Can a player have more than one character?

Yes, up to 6 per account by default. Change maxCharactersPerAccount in the Game Database settings.

#What happens if a player signs in twice?

One session per account. The second sign in closes the first: the old map saves the character and drops it, and the first client sees "You logged in from somewhere else." If the save is still in progress, the new sign in gets "Your character is still being saved. Try again in a moment."

#Do cheats work in single player?

Yes, GM commands work like cheats in single player while Game Settings > Single Player Commands is on (the default). Turn it off to ship a game without them. See GM commands.

#Content

#Can I use my own character models?

Yes, with + New player model in Game Database > Models. A humanoid rig can share the kit's animations and hold weapons in its hands; any rig works with its own animations. See Player models.

#Can I use my own monster models?

Yes, with + New monster in Game Database > Monsters. With an Animator the monster plays its clips; without one it hops and flashes when hit, like the sample's slimes. See Monsters.

#How do I add a new map?

Duplicate the sample's Forest scene, add a map in Game Database > Maps, pick the scene, connect it with a portal or a teleport NPC, and rebuild the map server. See Maps.

#Why does every asset have an id?

Saved characters and the database point to data by id, like fire_bolt. The id is filled from the file name when the asset is made and never changes after, so renaming or moving a file doesn't break saves. Changing an id by hand breaks every character that uses it.

#Why are stat bonuses always whole numbers?

So players read clean numbers and rounding never differs between client and server. Percentages are whole points too. Gear rolls each bonus between a minimum and a maximum for every copy.

#Can players sell items to NPCs?

Not by default, so items move between players, to the market or to the forge. Turn on Game Settings > Players Sell To Npcs to allow it. See NPC shops.

#What happens when the bag is full?

Loot can go past the weight limit, and the character then can't walk until it drops, sells or stores something. Items from mail, the guild, tax collectors and quests go to the bank when the bag can't hold them. Nothing is lost. See Inventory and bank.

#How do I change keys?

Each window's key is a field on its component in the HUD prefab, and the movement keys are fields on the mode components. Players can't rebind keys in game. See Keys.

#Which control mode should I pick?

Top-down for a Diablo-style game with click to move; free camera for a cursor-aimed game with an orbiting camera; third person for crosshair aim with client prediction. The same scenes work for all three, and you can change it later. See Control modes.

#Servers and costs

#What do I need to run an MMO for real players?

A Linux machine with Docker, two domain names (one for Login, one for Central) and the Linux map server build. The Deploy Docker Compose file runs PostgreSQL, Caddy (HTTPS), Login, Central and one container per map. See Docker.

#SQLite or PostgreSQL?

SQLite is a local file and needs nothing installed: use it to develop and for small servers. Use PostgreSQL in production. The services work with either; you switch in Play & Servers or in the services' settings. See Database.

#Can I run several Central servers for more players?

No. Run exactly one Central per database: it keeps sessions, tickets and item locks in memory, and two would hand out the same items twice. Login can run as several instances. Map servers scale by adding maps. Run one Shop per database too.

#Do map servers need to be on the same machine as Central?

No, but the map link (UDP 7700) isn't encrypted. Map servers on other machines must reach Central over a private network or a WireGuard tunnel, never the internet.

#How do I make myself an admin?

Set your account's Role to 4 in the accounts table once, then use /role in game for others. See GM commands.

#Can I sell items for real money?

Yes, with the optional in-game shop. It runs as its own service with its own premium currency, held per account. Players top up through payment webhooks: Stripe, or a signed webhook from your own web shop. Bought items go straight to the bag. See Cash shop and Shop service.

#Does the shop work in single player?

No. The in-game shop needs the Shop service and is MMO only.

#Security

#Can players cheat by modifying the client?

The server decides everything: damage, loot, prices, trades, quests and movement. The client only asks, and every request is checked on the server. Targets must be visible to the player, commands are rate limited, and player text can't inject formatting. An MMO client build carries no server code, GM commands, local save or keys. See Security.

#Can items be duplicated?

Every item copy has exactly one owner in the database, and moves between owners happen in transactions through one ledger. Map tickets work once, and a relog waits for the old save before letting the character in again.

#How are passwords stored?

Hashed with Argon2id. Players sign in with a short-lived token. "Remember me" keeps a one-use token, never the password, and reusing a spent token signs out every computer that had it.

#What happens after many wrong passwords?

After 5 wrong passwords in 15 minutes, the username is locked for 15 minutes ("Too many wrong passwords."), without telling whether the account exists. Login also limits requests per address to 10 a minute.

#Updating and extending

#Will an update overwrite my changes?

Not if you keep your game in your own folders and use kit updates. Importing a new kit replaces kit files; kit updates add what your game lacks without rebuilding it. Only Start over rebuilds the sample from scratch. See Updating the kit.

#Can I edit the kit's code?

You can, but the next update replaces it. Extend the kit from your own assemblies instead: templates, events, virtual methods and registrable types cover the common needs. See DevKit overview.

#How do I add my own GM command, skill effect or quest objective?

Right click a folder, pick Create > KitARPG > Scripts and the matching template. Start with Game Assembly so your scripts see the kit. See Templates.

#Can I extend Login and Central?

Yes, with modules: a .NET 10 class library with a class that implements ILoginModule or ICentralModule, dropped into the service's modules folder. See Service modules.

#Where is the API reference?

In Assets/Blunnyn/KitARPG/Documentation/API/, one page per public type.

#How do I check that the kit works in my project?

KitARPG > Run Play Mode Tests runs the kit's tests in single player on a throwaway save: entering a map, travelling through a portal, saving gold, fighting, and each humanoid model attacking with each weapon type. See Troubleshooting.
