开发套件

不重新加载域的 Play

为什么你代码中的静态状态必须手动重置，每个启动方法在什么时候运行，以及套件为了让每次 Play 都干净地开始而使用的做法。

#什么是域重新加载

按下 Play 时，Unity 可以重新加载脚本域：丢弃所有已加载的程序集和所有静态值，然后重新加载。这样每次 Play 都干净地开始，但在 KitARPG 这么大的项目中要花很多秒。

套件的项目关闭了它：Project Settings > Editor > Enter Play Mode Settings 中的 Reload Domain 是关闭的（场景仍会重新加载）。于是 Play 在一两秒内就能开始。代价是静态字段会保留上一次 Play 的值：

  • 静态列表仍然保存着上次添加的条目，
  • 静态事件仍然有上次 Play 的订阅者，它们指向已销毁的对象，
  • 静态 Local 仍然指向之前的本地玩家，
  • 静态计数器会继续计数。

构建版本总是干净地开始。这些问题只会出现在编辑器中，并且只在第二次及之后的 Play 中出现，所以很容易被忽略。你的项目可能开启了 Reload Domain；编写代码时要让它在两种情况下都能工作。

#启动时机

[RuntimeInitializeOnLoadMethod] 会在每次 Play（以及每次启动构建版本）的固定时机运行一个静态方法：

加载类型 何时 用来
SubsystemRegistration 最先，早于一切 清除你自己的静态值。
AfterAssembliesLoaded 所有程序集加载之后 订阅其他类的静态事件；添加菜单条目和选项。
BeforeSplashScreen 启动画面之前 （很少需要）
BeforeSceneLoad 第一个场景加载之前 安装公式和其他替换。
AfterSceneLoad 第一个场景加载之后 需要场景对象的东西：KitNetworkManager.Instance、GM 命令。

在同一种加载类型中，Unity 不规定不同类的方法之间的顺序。套件的规则正是由此而来。

#套件的规则

  1. 每个类在 SubsystemRegistration 中清除自己的静态值。 保存状态的字段、事件、集合和缓存会在一个通常叫 ResetStatics 的方法中恢复到初始值。
  2. 在 AfterAssembliesLoaded 或之后订阅其他类的静态事件。 那个类会在 SubsystemRegistration 中清除它们；如果你在同一阶段订阅，你的订阅可能会在你订阅之后被清除。
  3. 套件用自己的条目填充的列表会在 SubsystemRegistration 中重建（ItemMenu.Entries、PlayerMenu.Entries、ClientOptions.All、GM 命令）。在之后添加你的条目。
  4. 套件的公式会在 SubsystemRegistration 中恢复为套件自己的（GameInstance.Formula、GameInstance.Combat）。在 BeforeSceneLoad 中安装你的公式。
  5. 在 SubsystemRegistration 中注册自己内容的类，在同一个方法中先清除再注册， 这样它与其他类的顺序就无关紧要（GmCommands）。
  6. 每次使用都会清空的工作缓冲区和始终有效的缓存不需要清除。 用作临时空间的静态 List，或在会话期间不会改变的计算值，可以保留。

游戏模式表（GameModes）是个例外：它们从不清除，因此模式程序集可以在 SubsystemRegistration 中以任意顺序注册。

#你代码中的写法

using System;
using System.Collections.Generic;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    public static class Kills
    {
        // State of this class.
        static readonly Dictionary<long, int> counts = new Dictionary<long, int>();
        public static event Action<PlayerCharacter, int> ServerCounted;

        // 1. Clear own state first.
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void ResetStatics()
        {
            counts.Clear();
            ServerCounted = null;
        }

        // 2. Subscribe to the kit's events after the kit cleared them.
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
        static void Hook()
        {
            Monster.ServerKilled -= OnKilled;
            Monster.ServerKilled += OnKilled;
        }

        static void OnKilled(Monster monster, PlayerCharacter killer)
        {
            if (killer == null || killer.State == null) return;
            counts.TryGetValue(killer.State.id, out int n);
            counts[killer.State.id] = ++n;
            ServerCounted?.Invoke(killer, n);
        }
    }
}

先 -= 再 +=，即使方法运行两次，订阅也是安全的。使用具名方法（而不是 lambda）才能 -=。

#组件上的静态成员

带有静态成员的 NetworkBehaviour 或 MonoBehaviour 遵循同样的规则：

public class PlayerPet : NetworkBehaviour
{
    public static PlayerPet Local { get; private set; }
    public static event Action<string> Told;

    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
    static void ResetStatics()
    {
        Local = null;
        Told = null;
    }

    public override void OnStartAuthority() => Local = this;

    public override void OnStopAuthority()
    {
        if (Local == this) Local = null;
    }
}

玩家系统和保存数据的模板已经这样做了。

#位于场景对象上的东西

每次 Play 都会重新创建的对象（网络管理器、HUD 中的窗口）上的事件不需要清除：旧对象连同它的订阅者一起消失了。这就是为什么套件的模板在 AfterSceneLoad 中订阅 KitNetworkManager.ServerStarted 而不取消订阅。

#延迟缓存

static AttributeData toughness;

public static AttributeData Toughness
{
    get
    {
        if (toughness == null && GameInstance.Database != null) GameInstance.Database.TryGet("toughness", out toughness);
        return toughness;
    }
}

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
static void ResetStatics() => toughness = null;

如果资源不会改变，资源的缓存跨 Play 保留也无害，但清除它没有任何代价，还能覆盖两次 Play 之间所做的修改。

#检查清单

对于你代码中的每个 static，问一问：

它是 做法
游戏过程中会改变的值（计数器、Local、玩家字典） 在 SubsystemRegistration 中重置。
你的类的静态事件 在 SubsystemRegistration 中设为 null。
对别人静态事件的订阅 在 AfterAssembliesLoaded 或之后订阅，先 -=。
套件列表中的条目（菜单、选项、命令、编辑器中的校验器检查） 在套件填充列表之后添加。
从不改变的 const 或 static readonly 值 什么都不用做。
每次使用前都会清空的临时缓冲区 什么都不用做。

仅编辑器的静态值（校验器检查、页面）遵循编辑器自己的生命周期，而不是 Play：在 [InitializeOnLoadMethod] 中注册它们，并在添加前先移除（参见编辑器扩展）。

#测试

  1. 按下 Play，执行你的功能所做的事，然后停止。
  2. 再次按下 Play，再做一遍。
  3. 留意重复的消息、触发两次的事件、没有从零开始的计数，以及来自已销毁对象的 MissingReferenceException。

套件本身就是这样测试的：在单人模式中连续两次 Play，得到的订阅者、命令和菜单条目都相同。

#常见错误

  • 在 SubsystemRegistration 中订阅。 套件可能在你之后清除该事件。请在 AfterAssembliesLoaded 或之后订阅。
  • 清除别人的事件。 每个类只清除自己的。
  • 在一个启动方法中清除你的事件，又在同一类型的另一个启动方法中订阅它。 顺序是未定义的：在 SubsystemRegistration 中清除，在之后的阶段订阅。
  • 在 += 中使用每次 Play 都会运行的 lambda，而该事件又不会被清除。
  • 对场景对象的静态引用没有重置：它们会变成已销毁的对象，与 null 比较相等，但仍然占用内存。
