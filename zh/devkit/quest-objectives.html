开发套件

任务目标

如何添加一种新的任务目标：QuestObjective 基类、目标计数的两种方式（事件或当前状态）、如何用 PlayerQuests.ServerAdvance 推进它，以及完整示例。

#目标是什么

一个任务有一组目标（QuestData.objectives）。每个目标有一段文本、一个可选的提示，以及一个必须达到的数值。套件自带五种：

种类 计数对象 方式
KillObjective 击杀某种怪物或任意怪物 事件：Monster.ServerKilled，与附近的队伍成员共享
CollectObjective 背包中的物品 状态：读取背包；交付时可以收走这些物品
TalkObjective 按 id 与某个 NPC 对话 事件：NPC 对话
ExploreObjective 到达某个点或区域 每隔 Explore Interval（exploreInterval，0.5 秒）轮询一次
TriggerObjective 触发一个世界触发器 事件：WorldTrigger

一种新的目标就是一个类，加上一段推进它的服务器代码。目标是 [Serializable] 的，并以 [SerializeReference, PickType] 保存，所以你的目标会出现在 Game Database 中每个任务的 Objectives 的 + 菜单里。

文件放在哪里：Game 程序集。客户端的任务日志会读取目标的文本和图标。

#基类

QuestObjective 位于 Blunnyn.KitARPG.Data。

成员 作用 默认值
string text 检查器字段：显示在任务日志中。为空时使用 DefaultText。 空
string hint 检查器字段：在任务日志中展开显示在目标下方。 空
string Text text 或 DefaultText。
protected abstract string DefaultText { get; } 你的默认文本，例如 "Slay Slimes"。必须实现。
virtual int Required 要达到的数值。 1
virtual Sprite Icon 任务日志中的图标。 null
virtual int Current(IPlayerFacts holder) 用于基于状态的目标：当前的数值。按事件计数的目标返回 -1。 -1
virtual void Visit(Action<GameData> visit) 交出目标引用的每个资源。 不做任何事

#两种计数方式

#按事件计数

大多数目标在事情发生时计数。任务为每个目标保存一个计数器，随角色一起保存。事情发生时你的代码调用 ServerAdvance：

// PlayerQuests, server only.
public void ServerAdvance<T>(Predicate<T> match, int amount = 1) where T : QuestObjective

它遍历该玩家的每个进行中的任务，找到类型为 T、match 返回 true 且尚未满的目标，加上 amount（以 Required 为上限），在玩家头顶显示 "Objective 2/5"，任务完成时提示 "ready to turn in"，并把日志同步给拥有者。

#从当前状态读取

重写 Current，根据角色当前拥有的东西返回数值，就像 CollectObjective 对背包所做的那样。任务会在以下时候读取它：

  • 接受任务时，
  • 每次玩家的背包或装备变化时（PlayerInventory.ServerChanged），
  • 玩家尝试交付任务时（最终检查）。

Current 会覆盖保存的计数器。如果数值会下降（物品被卖掉），目标也会随之下降。

注意

除了背包变化之外，没有任何东西会刷新任务日志中基于状态的数值。例如，读取等级的 Current 在背包变化之前会一直显示旧数字，尽管一达到该等级就可以交付。对于不伴随背包变化的状态，请改用事件计数。

#示例：模板

Create > KitARPG > Scripts > Quest Objective 会创建一个目标，以及一个在每次升级时推进它的计数器。见模板。

#示例：赢得决斗

统计玩家赢得的决斗。PlayerPvp.ServerDefeated 提供击杀者、被击败者以及是否为决斗。

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class WinDuelsObjective : QuestObjective
    {
        public int count = 3;
        [Tooltip("Only opponents at this level or above count. 0 counts anyone.")]
        public int minOpponentLevel;

        protected override string DefaultText => "Win duels";

        public override int Required => Mathf.Max(1, count);

        public bool Counts(PlayerCharacter opponent) => minOpponentLevel <= 0 || opponent.level >= minOpponentLevel;
    }

    public static class WinDuelsCounter
    {
        // After the kit cleared its events in SubsystemRegistration.
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
        static void Hook()
        {
            PlayerPvp.ServerDefeated -= OnDefeated;
            PlayerPvp.ServerDefeated += OnDefeated;
        }

        static void OnDefeated(PlayerCharacter winner, PlayerCharacter loser, bool duel)
        {
            if (!duel || winner == null || loser == null) return;
            if (winner.TryGetComponent(out PlayerQuests quests))
                quests.ServerAdvance<WinDuelsObjective>(o => o.Counts(loser));
        }
    }
}

#示例：在锻造台强化装备

PlayerForge.ServerUpgraded 提供玩家、物品 id、这一步是否成功以及最终达到的等级。

[Serializable]
public class UpgradeObjective : QuestObjective
{
    [Tooltip("Upgrades that reach this level or more count.")]
    public int toLevel = 3;
    public int count = 1;

    protected override string DefaultText => $"Upgrade gear to +{toLevel}";

    public override int Required => Mathf.Max(1, count);
}

public static class UpgradeCounter
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
    static void Hook()
    {
        PlayerForge.ServerUpgraded -= OnUpgraded;
        PlayerForge.ServerUpgraded += OnUpgraded;
    }

    static void OnUpgraded(PlayerCharacter player, string itemId, bool success, int level)
    {
        if (success && player.TryGetComponent(out PlayerQuests quests))
            quests.ServerAdvance<UpgradeObjective>(o => level >= o.toLevel);
    }
}

#示例：持有金币（基于状态）

读取钱包。每当背包变化时它会刷新，交付时会再次检查。

[Serializable]
public class GoldObjective : QuestObjective
{
    public long gold = 1000;

    protected override string DefaultText => $"Gather {gold:N0} gold";

    // Counts are whole numbers; a large target is shown as one step.
    public override int Required => 1;

    public override int Current(IPlayerFacts holder) => holder.Balance(null) >= gold ? 1 : 0;
}

刷新来自 PlayerInventory.ServerChanged，它在背包或装备被发布时触发。仅仅金币变化不会触发它，因此日志可能一直显示 0，直到下一次背包变化，尽管交付是可以的。对于物品，优先使用这种模式。对于货币，由你自己的代码推进的基于事件的目标更可靠。

#示例：由你自己的功能推进的目标

任何服务器代码都可以推进目标。悬赏示例可以把已支付的悬赏计入某个任务：

[Serializable]
public class BountiesObjective : QuestObjective
{
    public MonsterData monster;
    public int count = 3;

    protected override string DefaultText => monster != null ? $"Finish {monster.DisplayName} bounties" : "Finish bounties";
    public override int Required => Mathf.Max(1, count);
    public override Sprite Icon => monster != null ? monster.Icon : null;
    public override void Visit(Action<GameData> visit) => visit(monster);
}

// Wherever a bounty is paid, on the server:
if (player.TryGetComponent(out PlayerQuests quests))
    quests.ServerAdvance<BountiesObjective>(o => o.monster == null || o.monster == paidFor);

#服务器与客户端

运行在
ServerAdvance、你的计数器 仅服务器
Current 服务器（起决定作用的数值）
Text、hint、Icon、Required 客户端，在任务日志和追踪器中

数值通过同步列表 PlayerQuests.active 到达拥有者。保存是自动的：计数器是任务进度的一部分，与角色一起保存，单人模式和在线都是如此。

#你可以使用的任务事件

事件 触发时机
PlayerQuests.ServerCompleted（PlayerCharacter, QuestData） 一个任务被交付。服务器。
PlayerQuests.Shown（Npc, QuestData） 拥有者的客户端被 NPC 展示了一个任务。
PlayerQuests.Changed（实例事件） 拥有者的任务列表发生变化。客户端。

如果你需要修改流程本身，PlayerQuests 的服务器方法都是 virtual 的（ServerAccept、ServerTurnIn、ServerAbandon、ServerFinishObjectives、ServerForget、ServerTalked、ServerLoad）。见重写套件的行为。

#常见错误

  • **在 SubsystemRegistration 中订阅。**套件在那里清空它的事件；顺序是不确定的。使用 AfterAssembliesLoaded。
  • 从客户端推进。ServerAdvance 仅限服务器；客户端的请求必须由服务器代码检查后再转换为进度。
  • 匹配范围过宽。ServerAdvance<T>(o => true) 会推进每个进行中任务里该类型的所有目标。把规则写进谓词中。
  • **把每个玩家的计数保存在目标的字段中。**计数器由任务保存。字段是所有玩家共享的设计者设置。
