开发套件

编辑器扩展

如何向 KitARPG 窗口添加你自己的页面，向 Project Check 和构建前检查添加你自己的检查，以及如何在你的工具中使用套件的编辑器外观。

文件放在哪里：Game.Editor 程序集（见程序集）。本页的所有内容都使用 KitARPG.Editor 和 UnityEditor，它们永远不会进入构建。

#KitARPG 窗口中的页面

KitARPG 窗口（KitARPG > Open KitARPG，Ctrl/Cmd+Shift+K）有一个页面侧边栏：Overview、Play & Servers、Game Database、Game Settings、Shop、Modules 和 Project Check。每个非抽象且带无参构造函数的 KitPage 子类都会被 Unity 的 TypeCache 找到并加入侧边栏。不需要注册任何东西。

#KitPage

成员 作用 默认值
abstract string Name 页面在侧边栏中的名称。
virtual string Group 页面所在的侧边栏标题。套件依次使用 ""（顶部）、"Game" 和 "Project"；其他名称排在它们之后。 "Game"
virtual int Order 在分组内的顺序，数值小的在前。然后按名称排序。 100
virtual string IconName 内置编辑器图标的名称，例如 "Settings" 或 "d_Favorite"。 "ScriptableObject Icon"
virtual string Badge 名称旁边的短文本，例如问题数量。为 null 时不显示。 null
virtual KitGUI.State BadgeState 徽标的颜色。 Off
virtual bool FullWidth 为 true 时页面占用整个区域，而不是居中的滚动列，适用于有自己分栏的页面。 false
virtual void OnEnable()、OnDisable() 页面显示和隐藏时调用。
virtual void Tick() 窗口打开时每秒调用约十次，用于轮询。
abstract void OnGUI() 用 IMGUI 绘制页面。
KitWindow Window 窗口。
Rect Area 页面绘制的区域。
void Repaint() 请求窗口重绘。

套件的页面使用以下顺序：Overview 0 和 Play & Servers 1（分组 ""）；Game Database 10、Game Settings 20、Shop 25、Modules 30（分组 "Game"）；Project Check 10（分组 "Project"）。

KitWindow.Show<T>() 打开窗口并显示某个页面：KitWindow.Show<GameDatabaseWindow>()、KitWindow.Show<MyGamePage>()。

#示例：为你的内容做一个页面

列出项目中的每个悬赏板，每个都有一个选中它的按钮，有空悬赏板时显示警告徽标。悬赏板类型位于示例的 Game.Bounties 程序集中，因此包含此页面的编辑器程序集要引用它。

using System.Linq;
using Blunnyn.KitARPG.Editor;
using Game.Bounties;
using UnityEditor;
using UnityEngine;

namespace Game
{
    public class BountyBoardsPage : KitPage
    {
        BountyBoardData[] boards = new BountyBoardData[0];

        public override string Name => "Bounty Boards";
        public override int Order => 500;
        public override string IconName => "d_Favorite";

        int Empty => boards.Count(b => b != null && b.bounties.Length == 0);

        public override string Badge => Empty > 0 ? Empty.ToString() : null;
        public override KitGUI.State BadgeState => KitGUI.State.Warning;

        public override void OnEnable() => Load();

        void Load() => boards = AssetDatabase.FindAssets("t:BountyBoardData")
            .Select(g => AssetDatabase.LoadAssetAtPath<BountyBoardData>(AssetDatabase.GUIDToAssetPath(g)))
            .Where(b => b != null).ToArray();

        public override void OnGUI()
        {
            KitGUI.Header("Bounty Boards", "Every board asset in the project and its hunts.");
            if (boards.Length == 0) KitGUI.Empty("No boards yet", "Create one with Create > KitARPG > DevKit Example > Bounty Board.");
            foreach (BountyBoardData board in boards)
            {
                KitGUI.State state = board.bounties.Length == 0 ? KitGUI.State.Warning : KitGUI.State.Done;
                string detail = board.bounties.Length == 0 ? "No hunts" : $"{board.bounties.Length} hunts";
                if (KitGUI.Status(state, board.name, detail, "Select")) Selection.activeObject = board;
            }
            KitGUI.Line();
            if (KitGUI.Secondary("Refresh", 120)) Load();
        }
    }
}

#套件的编辑器外观

KitGUI（命名空间 Blunnyn.KitARPG.Editor）用普通的 IMGUI 绘制套件窗口中的卡片、标题、状态行和按钮，让你的页面与之风格一致。

成员 绘制什么
Header(text, sub, icon) 下方带一条线的页面标题。
BeginCard(heading, sub, stripe) / EndCard()，或 using (new KitGUI.CardScope(heading)) 圆角卡片。
Status(state, heading, detail, button, primaryButton) 带彩色指示灯和可选按钮的清单行；按下时返回 true。
Primary(text, width, height)、Secondary(...) 按钮；按下时返回 true。
Segmented(value, options, height) 分段控件；返回选中的索引。
Switch(rect, on) 开关。
Pill(text, color) 小的彩色标签。
Tile(rect, value, caption, state) 带说明文字的数字。
Empty(heading, detail) 空列表的占位内容。
Message(text, state) 一行彩色消息。
Line(space) 分隔线。
Icon(name) 内置编辑器图标。
Accent、Good、Warn、Bad、Of(state) 调色板，适用于浅色和深色编辑器皮肤。

KitGUI.State 有 Done、Todo、Warning、Error、Off 和 Busy（闪烁的指示灯）。

#你的数据的 Inspector

套件的游戏数据 Inspector（GameDataEditor）把每个 GameData 资源绘制成按其 [Header] 特性分隔的卡片，并且同样适用于子类。你自己的 GameData 类型无需专门的编辑器就能获得相同的外观。在字段上使用 [Header]、[Tooltip] 和 [Range]，它看起来就和套件自己的数据一样。

#项目检查

KitARPG > Project Check（Project Check 页面）运行 ProjectValidator.Checks 中的每一项检查，并把发现的问题按错误、警告和提示列出，每条都有一个选中相关对象的按钮，如果有修复方法，还有一个修复按钮。同一份列表会在每次构建前运行，不打开场景，有错误时会中止构建（BuildCheck，可以在 Project Check 页面关闭）。

#ProjectValidator

成员 是什么
static List<Action<List<ValidationIssue>>> Checks 所有检查，按顺序排列。每项检查把发现的问题添加到传给它的列表中。把你的检查加进去。
static List<ValidationIssue> Run(bool scenes = true) 运行全部检查。scenes 为 false 时，跳过会打开场景的检查，与构建前一样。
static bool IncludeScenes 正在进行的这次运行是否会打开场景。在会打开场景的检查中读取它。

#ValidationIssue

字段 是什么
IssueLevel level Error（中止构建）、Warning 或 Info。
string area 简短的分组名称，例如 "My game"。
string message 一行文字，说明哪里有问题。
Object context 问题相关的资源或对象；Select 按钮会高亮它。
string fixLabel 修复按钮的文字。
Action fix 修复按钮执行的操作。为 null 时不显示按钮。

#注册检查

ProjectValidator.Checks 是一个静态列表，存活时间与编辑器的域相同。在 [InitializeOnLoadMethod] 中注册，它会在每次脚本重新加载后运行；添加之前先移除，这样检查永远不会运行两次：

[InitializeOnLoadMethod]
static void Register()
{
    ProjectValidator.Checks.Remove(Check);
    ProjectValidator.Checks.Add(Check);
}

#示例：奖励为空的悬赏板，带修复

using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Editor;
using Game.Bounties;
using UnityEditor;

namespace Game
{
    public static class BountyChecks
    {
        [InitializeOnLoadMethod]
        static void Register()
        {
            ProjectValidator.Checks.Remove(Check);
            ProjectValidator.Checks.Add(Check);
        }

        static void Check(List<ValidationIssue> issues)
        {
            foreach (string guid in AssetDatabase.FindAssets("t:BountyBoardData"))
            {
                var board = AssetDatabase.LoadAssetAtPath<BountyBoardData>(AssetDatabase.GUIDToAssetPath(guid));
                if (board == null) continue;
                for (int i = 0; i < board.bounties.Length; i++)
                {
                    BountyBoardData.Bounty bounty = board.bounties[i];
                    if (bounty.monster == null)
                        issues.Add(new ValidationIssue
                        {
                            level = IssueLevel.Error, area = "Bounties", context = board,
                            message = $"{board.name}: hunt {i + 1} has no monster.",
                        });
                    else if (bounty.rewards.Length == 0)
                    {
                        BountyBoardData.Bounty b = bounty;
                        issues.Add(new ValidationIssue
                        {
                            level = IssueLevel.Warning, area = "Bounties", context = board,
                            message = $"{board.name}: hunting {bounty.monster.DisplayName} pays nothing.",
                            fixLabel = "Add 100 gold",
                            fix = () =>
                            {
                                Undo.RecordObject(board, "Add bounty reward");
                                b.rewards = new GameAction[] { new GiveCurrencyAction { amount = 100 } };
                                EditorUtility.SetDirty(board);
                            },
                        });
                    }
                }
            }
        }
    }
}

#检查的编写准则

  • 错误会中止构建。 只有游戏中一定会出问题的情况才用 Error。可能的错误用 Warning，建议用 Info。
  • 要快。 检查在每次构建前运行。除非 ProjectValidator.IncludeScenes 为 true，否则不要打开场景。
  • 指向资源。 设置 context，让 Select 按钮能用。
  • 修复要安全。 修复只能添加缺少的东西或纠正一处明确的问题，并使用 Undo 和 SetDirty。

#找到游戏的设置和数据库

ModulesWindow.Find() 返回项目的 GameInstance（位于 KitNetwork 预制体上的那个），并缓存几秒钟。它的 database 字段就是 GameDatabase：

GameInstance game = ModulesWindow.Find();
GameDatabase database = game != null ? game.database : null;

GameDatabase.All<T>() 列出某个类型的所有资源，TryGet<T>(id, out T) 按 id 查找一个资源。

#菜单项

普通的 Unity [MenuItem] 照常可用。要把你的菜单项放在套件菜单旁边，使用 KitARPG/ 根路径，就像示例中的 KitARPG > DevKit > Add Bounty Board to the Open Scene 那样：

[MenuItem("KitARPG/My Game/Rebuild Recipes", priority = 200)]
static void Rebuild() { /* ... */ }

#常见错误

  • 编辑器代码放在 Game 中。 它引用了 UnityEditor，构建会失败。请使用 Game.Editor。
  • 注册检查前没有先移除。 每次脚本重新加载后它会多运行一次。
  • Tick 或 OnGUI 太慢。 它们调用得很频繁；把加载的东西缓存起来，就像上面的页面在 OnEnable 中做的那样。
  • 页面没有无参构造函数。 它不会被找到。
