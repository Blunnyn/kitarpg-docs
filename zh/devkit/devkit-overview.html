开发套件

DevKit 概览

DevKit 是一组扩展点、模板和示例，让你无需修改套件代码就能在 KitARPG 之上构建任何功能。本页说明其中的规则、你的代码在哪里运行，以及每种修改应该阅读哪一页。

#为什么你永远不修改套件

Assets/Blunnyn/KitARPG/ 下的所有内容都属于套件。安装新版本时，这些文件会被替换。你在那里修改的任何一行都会丢失，而把你的修改与新版本合并，只能由你手动解决。

套件的设计让你永远不需要动它：

  • 数据资源（物品、技能、怪物、任务）属于你。它们保存在你保存的任何位置，套件从不重新生成它们。
  • 行为以小块的多态部件提供（技能效果、物品效果、条件、动作、任务目标、NPC 选项）。你通过编写一个类来添加新类型；Inspector 会把它和套件自带的类型列在一起。
  • 各个系统会触发静态事件并公开 virtual 方法，因此你可以在自己的程序集中响应它们或替换它们。
  • 决定数值的规则（伤害、经验、属性）是可以在启动时替换的对象。
  • 服务（Login 和 Central）会加载你自己的 .NET 模块，模块可以有自己的数据库表。

你的代码放在你自己的程序集中、你自己的文件夹里，例如 Assets/Game。套件更新从不触碰这个文件夹。

#套件的分层

套件按层组织。每一层只知道它下面的层。

层 程序集 里面有什么
共享规则 KitARPG.Shared 不引用 Unity 的纯 C#：背包规则、角色状态、发给 Central 的消息、日志格式。.NET 服务编译的是同一批文件。
数据 KitARPG.Data ScriptableObject 资源和纯规则：物品、技能、怪物、任务、条件、动作、公式、GameInstance。
网络实体 KitARPG.Net 通过 Mirror 存在于网络上的一切：玩家、怪物、NPC、聊天、公会、游戏日志。这些实体的服务器逻辑在这里运行。
仅服务器 KitARPG.Server 地图服务器：掉落发放、与 Central 的连接、GM 命令。绝不出现在在线客户端构建中。
客户端 KitARPG.Client HUD、窗口、相机辅助、标题画面、设置、输入。
游戏模式 KitARPG.Modes.* 每种操控模式如何移动和战斗。每种模式都有客户端部分和 .Server 部分。
编辑器 KitARPG.Editor KitARPG 窗口、验证器、模板。

程序集页面列出了每个程序集、它引用了什么以及哪些构建包含它。

#你的代码在哪里运行

KitARPG 有两种玩法，同一份游戏代码在两者中都会运行：

单人模式 MMO
谁是服务器 游戏本身就是主机：它在一个进程中同时运行地图服务器和客户端。 由单独的地图服务器进程（无图形界面的 Linux 构建，或处于 Play 状态的编辑器）运行每张地图。
保存 保存在玩家电脑上的本地存档（KitARPG.Local）。 Central 把角色保存在 PostgreSQL 或 SQLite 中。
Central 没有。CentralMessages.Online 为 false。 Central 连接所有地图服务器；Login 负责账号。
仅服务器程序集 包含在内（构建定义了 KITARPG_SERVER）。 只在地图服务器构建中。
GM 命令 当 Game Settings 中开启 Single Player Commands（singlePlayerCommands）时，每个玩家都是管理员。 由账号的角色决定。

因此，你写的每段代码都属于以下三处之一：

  • 服务器代码决定发生什么：伤害、物品、金币、任务进度、保存。在线时它在地图服务器上运行，单人模式中在主机上运行。名为 Server... 的方法和 [Command] 处理函数都是服务器代码。
  • 客户端代码负责显示内容并向服务器发出请求：窗口、菜单、声音、相机、输入。它在每个玩家的机器上运行，单人模式中与服务器在同一台机器上运行。
  • 共享代码在两边都运行，例如条件的 Met，服务器用它做检查，客户端用它把锁定的行变灰。

安全规则页面解释了为什么服务器总要再次检查客户端请求的内容。

#你的前五分钟

  1. 在 Project 窗口中新建文件夹 Assets/Game。
  2. 右键点击它，选择 Create > KitARPG > Scripts > Game Assembly。会出现一个 Game.asmdef。这个文件夹中的脚本现在能看到套件，并使用 Game 命名空间。
  3. 再次右键点击该文件夹，选择 Create > KitARPG > Scripts > Skill Effect。把文件命名为 PoisonDart.cs。
  4. 在 KitARPG > Game Database > Skills 中打开任意技能。在它的效果列表中按 +，从类型菜单中选择 PoisonDart。
  5. 按下 Play 并施放该技能。

#示例

Assets/Blunnyn/KitARPG/DevKit/Example/Bounties 是一个只用这些工具构建的完整功能：一个悬赏板，每天发放一次狩猎、统计击杀数、在 HUD 上显示进度、发放奖励，并在 Central 中维护排行榜。示例：悬赏板页面逐个文件讲解它。在开始一个大型功能之前，先读一遍。

#处处适用的规则

  • 永远不要修改 Assets/Blunnyn/KitARPG/ 下的文件。 改为继承、订阅或替换。
  • 服务器做决定。 客户端只发出请求。在服务器上再次检查每个请求。参见安全规则。
  • 仅服务器代码放在仅服务器程序集中（Game.Server），这样在线客户端永远不会携带它。参见程序集。
  • 静态状态由你重置。 套件的项目在不重新加载域的情况下进入 Play，因此静态字段会在多次 Play 之间保留它们的值。参见不重新加载域的 Play。
  • 为你的键和名称加上前缀，使用你游戏的名称（mygame.pets、mygame.bounty_done），这样它们永远不会与套件或其他包的冲突。
