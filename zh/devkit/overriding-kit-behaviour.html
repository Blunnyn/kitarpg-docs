开发套件

重写套件的行为

如何在不编辑套件组件的情况下改变它的行为：继承窗口、玩家系统、怪物或 NPC 组件，重写其虚方法，然后在预制体上替换该组件。

#什么时候需要重写

大多数修改用不着这样做。在重写之前，先检查：

  • Game Settings 中或组件上的某个设置，
  • 可以响应的事件（事件），
  • 公式（公式），
  • 你自己的效果、条件、动作、目标或 NPC 选项。

当套件本身的流程必须以不同方式进行时才重写：一个从你的本地化读取文字的窗口、一个有自己承受伤害方式的怪物、一个拒绝带链接信件的邮件系统。

文件放在哪里：Game 程序集，因为组件位于每个构建都会加载的预制体上。

#哪些可以重写

套件为子类开放了以下内容：

位置 哪些是虚方法
窗口和 HUD 部件（KitARPG.Client） Unity 方法（Awake、OnEnable、OnDisable、Update、OnDestroy）是 protected virtual，另外还有专门用于修改的方法，例如 ShopWindow.Describe（错误文字）
玩家系统（PlayerInventory、PlayerSkills、PlayerQuests、PlayerMail 等） Unity 方法是 protected virtual；服务器方法 Server... 是 public virtual（内部步骤为 protected virtual，例如 PlayerMail.ServerAnnounce(MailList)）
Monster Unity 方法、ServerSetup、ServerDamage、ServerHeal、ServerAddBuff、ServerRemoveBuffs、ServerKnock、ServerRevive、ServerDespawn、Think、TryCast、RunPhase 等
PlayerCharacter ServerSetup、ServerHeal、ServerAddExperience、ServerTryAttack、ServerAnnounce(string, Color) 以及其他服务器方法

Assets/Blunnyn/KitARPG/Documentation/API/ 中的 API 参考列出了每个 virtual 成员。不是虚方法的方法本来就不打算被修改；阅读该类，找到涵盖你所需内容的那个虚步骤。

#如何替换组件

  1. 编写你的子类，等它编译完成。

  2. 打开包含套件组件的预制体：

    组件 预制体
    玩家系统、PlayerCharacter 每个玩家模型预制体（KitARPG > Game Database > Models）
    窗口和 HUD 部件 HUD 预制体（GameInstance.hudPrefab，位于 Game Settings > Interface）
    Monster 每个怪物的预制体（Game Database 中该怪物的 Prefab 字段）
    Npc 场景中的 NPC 对象

  3. 在套件的组件上打开菜单（三个点），选择 Copy Component。

  4. 添加你的组件。在它上面选择 Paste Component Values：套件组件的每个字段都会被复制，因为你的类继承了它们。

  5. 移除套件的组件。

  6. 保存预制体。对于玩家系统，在每个玩家模型预制体上重复操作。

套件代码通过 GetComponent<PlayerMail>() 之类的调用查找组件，这些调用也会返回你的子类。其他什么都不用改。

警告

在联网预制体（玩家、怪物）上，组件在列表中的位置对 Mirror 很重要。替换组件会把新组件移到末尾，只要客户端和服务器构建使用同一个预制体就没有问题。绝不要在运行时或只在某一种构建中替换组件。

#示例：模板

Create > KitARPG > Scripts > Player System Override 会创建 PlayerMail 的一个子类：

using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Shared.Central;

namespace Game
{
    /// <summary>
    /// Changes how one of the kit's player systems behaves, here the mail, without editing the kit.
    /// On every player model prefab, remove the kit's component and add this one in its place
    /// (Copy Component, then Paste Component Values, keeps the settings).
    /// </summary>
    public class MyPlayerMail : PlayerMail
    {
        // Server methods decide for every player; call base for whatever you keep.
        protected override void ServerAnnounce(MailList list)
        {
            base.ServerAnnounce(list);
        }

        // Unity methods are protected virtual too.
        protected override void Awake()
        {
            base.Awake();
        }
    }
}

#示例：伤害减半的怪物

using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    /// <summary>A monster with armor: every hit is reduced before it lands.</summary>
    public class ArmoredMonster : Monster
    {
        [Range(0, 1)] public float reduction = 0.5f;

        public override void ServerDamage(Hit hit, IFighter source)
        {
            hit.amount = Mathf.Max(1, Mathf.RoundToInt(hit.amount * (1 - reduction)));
            base.ServerDamage(hit, source);
        }
    }
}

在该怪物的预制体上把 Monster 替换为 ArmoredMonster。其他怪物保留套件的组件。

#示例：本地化的商店消息

ShopWindow.Describe 把错误代码转换为句子，本来就是用来重写的：

using Blunnyn.KitARPG.Client;
using Blunnyn.KitARPG.Net;

namespace Game
{
    public class MyShopWindow : ShopWindow
    {
        protected override string Describe(string code)
        {
            switch (code)
            {
                case NpcErrors.NotEnoughMoney: return Localize("shop.no_money");
                case NpcErrors.OutOfStock: return Localize("shop.sold_out");
                default: return base.Describe(code);
            }
        }

        static string Localize(string key) => key; // your localization lookup
    }
}

在 HUD 预制体的 Windows 组下替换它。

#示例：对每次使用物品加一条规则

PlayerInventory.UseItem 是让物品发挥作用的服务器步骤。返回 false 会保留该物品：

using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;

public class MyPlayerInventory : PlayerInventory
{
    protected override bool UseItem(IUsable item)
    {
        // No potions inside the arena maps.
        if (item.CooldownGroup == "potion" && gameObject.scene.name.StartsWith("Arena")) return false;
        return base.UseItem(item);
    }
}

#示例：达到一定等级才能打开的邮箱

PlayerMail.ServerOpen 在邮箱 NPC 为玩家打开邮件时运行：

using Blunnyn.KitARPG.Net;
using UnityEngine;

public class LevelGatedMail : PlayerMail
{
    public int minLevel = 5;

    public override string ServerOpen(Npc npc)
    {
        if (TryGetComponent(out PlayerCharacter player) && player.level < minLevel)
        {
            player.ServerAnnounce($"The mailbox opens at level {minLevel}.", new Color(1f, 0.5f, 0.45f));
            return null;
        }
        return base.ServerOpen(npc);
    }
}

同样的规则也可以作为邮箱 NPC 选项上的条件来实现，不用写代码。重写适用于无论从哪里进入该系统都必须成立的规则。

服务器方法替每个玩家做决定。在重写之前先阅读基类方法，并对你保留的每个步骤调用 base。

#服务器端与客户端的重写

重写 效果
某个 Server... 方法 改变该地图服务器上每个玩家的规则。在线时，起作用的是地图服务器构建。
Unity 方法或窗口方法 改变该玩家看到的内容以及他们发出请求的方式。修改过的客户端可以撤销它，所以绝不要依赖它来实现规则。

客户端重写发送给服务器的任何内容都必须在服务器上再次检查，由套件检查或由你的服务器端重写检查。

#基类中的静态字段

玩家系统会在自己的 OnStartAuthority 中设置 PlayerMail.Local 之类的静态字段。如果你重写 OnStartAuthority、OnStopAuthority、Awake 或任何 Unity 方法，要先调用 base，否则这些静态字段会保持为空，套件的窗口就找不到你的组件了。

#套件更新与你的子类

套件更新也用 GetComponent 检查套件的组件，因此带有你子类的预制体被视为已经有该组件：更新不会再添加第二个。为套件组件添加字段的更新同样会作用到你的子类，因为它继承了这些字段。

当套件的新版本修改了你重写的某个虚方法（新增参数、移除方法）时，你的代码将无法编译，更新日志会说明改了什么。让重写保持精简并调用 base，这样套件中的新行为才能进入你的游戏。

#常见错误

  • 在 Unity 方法中没有调用 base。基类设置的静态字段、订阅和同步集合都会缺失。
  • 复制整个套件类而不是继承它。更新将再也无法作用到它。
  • 漏掉某个玩家模型。 每个模型都是独立的预制体；仍带有套件组件的那个会表现不同。
  • 用客户端重写来强制执行规则。 在服务器上做。
