开发套件

代码中的条件和动作

如何编写你自己的条件（玩家必须满足的规则）和动作（对玩家做的事情），它们能读取和改变什么，套件在哪里运行它们，以及如何在你自己的数据中使用它们。

#它们是什么

  • 条件对玩家回答是或否：“10 级或以上”、“已完成 Old Mill 任务”、“现在是夜晚”。任务、NPC 选项、NPC 问候语和世界触发器都有条件列表。
  • 动作改变玩家：支付金币、拿走物品、设置剧情标记、开始任务。对话行、任务（接受时和完成时）以及世界触发器都有动作列表。

面向设计者的内容在条件和动作中。本页介绍如何编写新的种类。

两者都是用 [SerializeReference, PickType] 保存的 [Serializable] 类。你的类编译后，会出现在每个列表的 + 菜单中。

文件放在哪里： Game 程序集。条件也会在客户端运行，所以它们必须包含在每种构建中。

#套件在哪里使用它们

字段 种类 在哪里检查或运行
QuestData.conditions 条件 接任务时在服务器上；任务标记和任务窗口在所有者的客户端上
QuestData.onAccept、QuestData.onComplete 动作 服务器
NpcOption.conditions 条件 服务器，列出 NPC 选项时
Npc.greetings[].conditions 条件 服务器，用于选择问候语
DialogueOption.actions 动作 服务器，选择该对话行时
WorldTrigger.conditions、WorldTrigger.actions 两者 服务器，触发器触发时

#条件

#条件读取的事实

Met(IPlayerFacts facts) 通过 IPlayerFacts（命名空间 Blunnyn.KitARPG.Data）获取玩家。它上面的所有成员在服务器和所有者的客户端上都能使用。

成员 返回什么
int Level 角色的等级。
CharacterClass Class 它的职业。
MapData Map 它所在的地图，如果该地图在数据库中。
int CountItem(string itemId) 背包中携带某个物品的数量。
bool Wears(string itemId) 是否穿戴该物品（不计外观装备）。
long Balance(CurrencyData currency) 货币为 null 时返回金币，否则返回该货币的数量。
int SkillRank(SkillData skill) 某个技能的等级，未学会时为 0。
int Attribute(AttributeData attribute) 该属性的总值：职业、已分配点数和装备。
bool HasStatus(StatusData status) 该状态当前是否在它身上。
QuestState QuestStateOf(QuestData quest) Locked、Available、Active、Ready 或 Done。
bool HasDone(QuestData quest) 至少交付过一次。
bool HasDiscovered(string placeId) 它去过的地图或区域 id。
int Flag(string key) 剧情标记；从未设置时为 0。

它背后的对象是一个 PlayerActor，它也实现了 IPlayerActor。需要玩家的某个组件时，进行转换并使用 Self：

if (facts is IPlayerActor actor && actor.Self.TryGetComponent(out PlayerCharacter player)) { ... }

#基类

成员 作用
string failText 检视面板字段 Fail Text：条件不满足时显示。为空时使用 DefaultText。
string Text failText 或 DefaultText。
protected abstract string DefaultText { get; } 你的默认原因，例如 "Needs level 5"。必须实现。
abstract bool Met(IPlayerFacts facts) 你的规则。必须实现。
virtual void Visit(Action<GameData> visit) 交出条件引用的每个资源。
static string Check(Condition[] conditions, IPlayerFacts facts) 第一个不满足的条件的文本，全部满足时为 null。可用于你自己的列表。

#示例：模板

using System;
using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    /// <summary>A rule quests, dialog lines and NPC options can ask for. Lists of conditions show it on their own.</summary>
    [Serializable]
    public class NewCondition : Condition
    {
        public string flag = "my_game.mark";
        public int atLeast = 1;

        protected override string DefaultText => "Not yet";

        // Runs on the server and on the owner's client, so the client can show what is locked.
        public override bool Met(IPlayerFacts facts) => facts.Flag(flag) >= atLeast;
    }
}

#示例：生命高于一定比例

使用 Self 读取玩家的生命值。生命值会同步给所有人，所以它在两端都能工作。

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class HealthCondition : Condition
    {
        [Range(0, 1)] public float atLeast = 0.5f;

        protected override string DefaultText => $"Needs {atLeast * 100:0}% health";

        public override bool Met(IPlayerFacts facts)
        {
            if (!(facts is IPlayerActor actor) || !actor.Self.TryGetComponent(out PlayerCharacter player)) return false;
            return player.maxHealth > 0 && (float)player.health / player.maxHealth >= atLeast;
        }
    }
}

#示例：穿戴一组物品中的任意一件

它读取资源，所以要把它们交给 Visit。

[Serializable]
public class WearsAnyCondition : Condition
{
    public ItemData[] items = new ItemData[0];

    protected override string DefaultText => "Wear the right gear";

    public override bool Met(IPlayerFacts facts)
    {
        foreach (ItemData item in items)
            if (item != null && facts.Wears(item.Id)) return true;
        return false;
    }

    public override void Visit(Action<GameData> visit)
    {
        foreach (ItemData item in items) visit(item);
    }
}

#内置条件

LevelCondition、ClassCondition、QuestCondition（配合 QuestCheck：NotStarted、Available、Taken、InProgress、Ready、Done、NotDone、NotTaken）、ItemCondition、EquippedCondition、CurrencyCondition、DiscoveredCondition、MapCondition、SkillCondition、AttributeCondition、StatusCondition、FlagCondition（Equal、NotEqual、AtLeast、AtMost）、TimeCondition（游戏内小时，或真实的 UTC 日期和小时），以及组合条件 AnyCondition、AllCondition 和 NotCondition。编写新条件之前先组合这些：“10 级且未接该任务”就是两个现有条件。

#条件会在客户端运行

所有者的客户端会评估任务条件，以便在 NPC 头上显示任务标记，并在任务窗口中显示状态。这有两个后果：

  • 只读取所有者客户端拥有的数据。 标记、任务、背包、装备、技能、状态和等级会同步给所有者。PlayerData 的值不会（它们从不离开服务器），所以读取它们的条件在客户端上总是 false。
  • 永远不要信任客户端的答案。 在任何事情发生之前，服务器都会再检查一次。条件是一个过滤器，而不是由客户端掌握的锁。

#动作

#动作能做什么

Run(IPlayerActor actor) 通过 IPlayerActor 获取玩家，它扩展了 IPlayerFacts。它自己的成员只在服务器上工作。

成员 作用
GameObject Self 玩家对象，用于接口没有覆盖的组件。
IItemUser User 物品眼中的玩家：经验、等级、点数、技能、状态、传送。见物品效果。
string RoomFor(ItemData item, int amount) 这些物品为什么放不进背包，或者 null。
void GiveItem(ItemData item, int amount) 把物品放进背包。
void TakeItem(ItemData item, int amount) 从背包中拿走物品。
void AddCurrency(CurrencyData currency, long amount) 负数表示拿走。货币为 null 时为金币。高级货币通过商店服务进入账号。
void SetFlag(string key, int value) 设置剧情标记；0 清除它。随角色保存。
void Discover(string placeId, string placeName) 把一个地点标记为已发现。
string StartQuest(QuestData quest) 开始一个任务。返回不能开始的原因，或者 null。
void DropQuest(QuestData quest) 放弃该任务。
void RemoveStatus(StatusData status) 移除一个状态。
void Say(string text, Color color) 玩家头上的浮动文字，只有该玩家能看到。
string FireTrigger(string triggerId) 在玩家所在地图上触发一个世界触发器。返回不能触发的原因，或者 null。

#基类

成员 作用 默认值
virtual string Check(IPlayerActor actor) 现在为什么不能运行，或者 null。 null
abstract void Run(IPlayerActor actor) 执行它。必须实现。
virtual string Cost 显示在运行它的对话行旁边的价格，例如 "50 Gold"。 null
virtual void Visit(Action<GameData> visit) 交出它引用的每个资源。 什么都不做
static string RunAll(GameAction[] actions, IPlayerActor actor) 检查每个动作，然后全部运行。返回第一个不能运行的原因，或者 null。
static string Costs(GameAction[] actions) 列表中所有价格拼接在一起，或者 null。

列表要么全部执行，要么都不执行：RunAll 先调用每个 Check，然后才调用每个 Run。把所有拒绝的理由放在 Check 中，永远不要在 Run 中失败。

#示例：模板

using System;
using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    /// <summary>Something done to a player from a dialog line or a quest reward. Server only.</summary>
    [Serializable]
    public class NewAction : GameAction
    {
        public string flag = "my_game.mark";
        public int add = 1;

        // Every action of a list is checked before any runs; return why not, or null.
        public override string Check(IPlayerActor actor) => null;

        public override void Run(IPlayerActor actor) => actor.SetFlag(flag, actor.Flag(flag) + add);
    }
}

#示例：给予物品，永不丢失

套件的 GiveItemAction 在背包满时会拒绝。这个动作无论如何都会给出：先放进背包，然后放进银行，再不行就暂存，直到有空间为止。

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class GiveOrBankAction : GameAction
    {
        public ItemData item;
        public int amount = 1;

        public override string Check(IPlayerActor actor) => item == null ? "Nothing to give" : null;

        public override void Run(IPlayerActor actor)
        {
            if (!actor.Self.TryGetComponent(out PlayerInventory inventory)) return;
            int banked = inventory.GiveOrBank(item, Mathf.Max(1, amount));
            if (banked > 0) actor.Say($"{banked} {item.DisplayName} went to your bank", new Color(1f, 0.85f, 0.4f));
        }

        public override void Visit(Action<GameData> visit) => visit(item);
    }
}

#示例：带价格并写日志的服务

展示 Cost，让标签为 "Heal me" 的对话行显示为 "Heal me (200 Gold)"，并写入一行管理员可以搜索的游戏日志。

[Serializable]
public class PaidHealAction : GameAction
{
    public long price = 200;

    public override string Cost => $"{price:N0} {GameInstance.Database?.GoldName ?? "Gold"}";

    public override string Check(IPlayerActor actor) =>
        actor.Balance(null) < price ? $"You need {price:N0} {GameInstance.Database.GoldName}" : null;

    public override void Run(IPlayerActor actor)
    {
        actor.AddCurrency(null, -price);
        if (actor.Self.TryGetComponent(out PlayerCharacter player))
        {
            player.ServerHeal(player.maxHealth, null);
            GameLog.Write("mygame.paid_heal", player, gold: price);
        }
    }
}

#内置动作

GiveItemAction、TakeItemAction、GiveCurrencyAction、ChargeCurrencyAction、ExperienceAction、PointsAction、ResetAttributesAction、TeachSkillAction、AddStatusAction、RemoveStatusAction、RestoreAction、TravelAction、SetFlagAction、StartQuestAction、DropQuestAction、DiscoverAction、MessageAction 和 FireTriggerAction。

#在你自己的数据中使用列表

你的任何 ScriptableObject 或可序列化类都可以包含列表，由设计者从同样的菜单中填写：

using Blunnyn.KitARPG.Data;
using UnityEngine;

[CreateAssetMenu(menuName = "My Game/Reward Chest")]
public class RewardChestData : ScriptableObject
{
    [SerializeReference, PickType] public Condition[] conditions = new Condition[0];
    [SerializeReference, PickType] public GameAction[] rewards = new GameAction[0];
}

在服务器上：

IPlayerActor actor = player.Facts;
string why = Condition.Check(chest.conditions, actor) ?? GameAction.RunAll(chest.rewards, actor);
if (why != null) player.ServerAnnounce(why, new Color(1f, 0.5f, 0.45f));

没有 [PickType] 时，检视面板显示的 [SerializeReference] 列表无法选择类型。悬赏示例的 BountyBoardData.rewards 就是这样一个列表。

#服务器和客户端

服务器 所有者的客户端
Condition.Met 是，且它的答案是最终结果 是，用于显示锁定的内容
GameAction.Check、Run 是 永远不会
DefaultText、Cost 是（作为文本发送） 是

单人模式在同一台机器上运行两者，答案相同。

#常见错误

  • 在条件中读取仅服务器的数据（PlayerData、服务器私有字段）。客户端会显示错误的状态。
  • 在 Run 中失败。 列表已经通过了检查，所以其他动作已经运行了。在 Check 中检查。
  • 通过原始背包给予物品。 使用 GiveItem、TakeItem 或 PlayerInventory，这样背包会同步，存档也保持正确。
  • 在字段中保存每个玩家的状态。 一个实例为所有玩家服务。使用标记或 PlayerData。
  • 忘记 Visit。 只被你的类引用的资源可能会被排除在游戏数据库之外。
