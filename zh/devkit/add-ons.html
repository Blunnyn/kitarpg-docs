开发套件

扩展

扩展（add-on）是一个拥有自己的文件夹和程序集的功能，它接入 KitARPG 而不改动套件本身。本页介绍扩展由什么组成、如何创建扩展、作为预制体的 HUD 窗口，以及它可以使用的每个接入点。

#扩展是什么

套件在核心中保留几乎每个 RPG 都需要的东西。可选功能以扩展的形式提供：图鉴是第一个，位于 Assets/Blunnyn/KitARPG/Addons/Bestiary。你自己的功能也可以做成扩展，这样套件更新永远不会碰到它们，你也可以在项目之间复用或分享它们。

一个扩展：

  • 位于自己的文件夹中，有一个运行时程序集，通常还有 .Editor 和 .Server 程序集。
  • 会自动出现在 KitARPG > Modules 中并显示版本，可以像套件的模块一样在那里开启和关闭。
  • 把它的 HUD 窗口保存为自己的预制体，HUD 中放着这个预制体的一个实例。

#创建扩展

  1. 打开 KitARPG > Create Add-on...。
  2. 输入 Name。Id 会据此自动填写：小写字母、数字和下划线。
  3. 选择放置位置（默认是 Assets/Game/Addons）。
  4. 如果需要，勾选 A HUD window with a toolbar button 和 A server part with a GM command。
  5. 点击 Create。

你会得到一个文件夹，包含：

文件 说明
Runtime/Game.Addons.Name.asmdef 扩展在游戏中运行的代码
Runtime/NameAddon.cs 套件用来找到扩展的声明，以及它的 id
Runtime/NameWindow.cs 窗口，如果你要求了的话
Editor/Game.Addons.Name.Editor.asmdef 编辑器代码
Editor/NameHud.cs 窗口在 HUD 中的位置及其工具栏按钮
Server/Game.Addons.Name.Server.asmdef 仅服务器代码，如果你要求了的话。永远不会进入在线客户端构建
Server/NameCommands.cs 属于该扩展的一个 GM 命令

#声明

运行时程序集中的一行代码就让它成为扩展：

[assembly: KitAddon("pet_arena", "Pet Arena", "1.0.0",
    Description = "Pets fight each other in the arena.", MinKitVersion = "1.0.0",
    Needs = new[] { "pets" }, NeedsModules = KitModule.Parties, Group = "World")]
[assembly: AlwaysLinkAssembly]
字段 作用
Id 在存档、设置和日志中标识该扩展。玩家有了存档之后就不要再改
Name, Version 显示在 Modules 中
Description, Author 显示在 Modules 中它的卡片上
MinKitVersion 它能配合的最旧 KitARPG 版本。套件版本更旧时 Project Check 会阻止构建
Needs 它离不开的扩展的 id。开启它时会一并开启这些扩展
NeedsModules 它离不开的套件模块
Replaces 它接替的套件模块。原本关闭了该模块的游戏会让这个扩展保持关闭
Icon 套件图标名称或精灵的路径
Group 它的卡片在 Modules 中的位置：Social、Economy、World，或它自己的分组

以运行时程序集命名的程序集（Game.Addons.PetArena.Editor、.Server）属于该扩展。

#开启和关闭

KitARPG > Modules 在套件模块旁边列出每个已安装的扩展。开关保存在网络预制体的 GameInstance 中（disabledAddons），因此客户端和服务器构建保持一致。

在代码中，做任何事之前先检查：

if (!GameInstance.Has(PetArenaAddon.Id)) return;

关闭期间，在服务器上拒绝请求，并隐藏窗口、菜单项和 NPC 选项。代码仍然保留，所以重新开启不会丢失任何东西。

#它在 HUD 中的窗口

窗口是扩展 Prefabs 文件夹中的一个预制体，它复制的行放在 Prefabs/UI 中。HUD 中放着这个预制体的一个实例：修改预制体，所有 HUD 都会跟着变。

  • 预制体的根对象上有窗口组件，它实现 IHudWindow（IsOpen 和 SetOpen）。
  • NameHud（一个 HudAddition）指明哪个组件是窗口，以及哪个工具栏按钮打开它。
  • 第一次需要时，HudAddition.Build 用 KitUi 生成预制体，也就是构建示例 HUD 所用的同一套部件。之后不会再调用它：请编辑预制体。KitARPG > Make Add-on Window Prefabs 会立即生成缺失的预制体。
  • 示例 HUD 把窗口和套件自己的窗口放在一起，并把它的按钮加在 Menu 之前。
  • 在扩展之前做好的 HUD 会通过 Overview 中的套件更新 Add-on windows in the HUD 获得窗口和按钮。只会添加这两样东西。
  • 你手动添加的按钮可以打开任何窗口：设置它的 HudButton.window。工具栏会把它连接好，并在扩展关闭时隐藏它。

#其他接入点

要... 使用
添加到在它之前做好的游戏中 一个 Addon 为该 id 的 KitUpdate。扩展关闭时不会提供它。参见代码中的套件更新
添加 GM 命令 注册时把 addon 设为该 id。扩展关闭时该命令不存在，/help 也不会列出它。参见代码中的 GM 命令
写入游戏日志 以该 id 开头的类型，例如 pet_arena.won
按角色保存 PlayerData / IPlayerSave，以该 id 为键。在线和单人模式都能用。参见保存数据
拥有自己的表 一个带有自己 DbContext 的 Login 或 Central 模块。永远不要修改套件的表。参见服务模块
描述它的 HUD 部件 一个重写 Description 的 HudPartEditor 子类

#单人和 MMO

扩展在两种模式下运行方式相同。客户端和地图服务器会把已安装的扩展及其版本作为网络版本的一部分进行比较，因此没有该扩展或版本不同的客户端无法进入装有它的地图服务器。添加或更新扩展后，请一起重新构建客户端和服务器。

#常见错误

  • 扩展没有出现在 Modules 中。 缺少 KitAddon 这一行，或者 id 包含大写字母或空格。Console 会指出无效的 id。
  • 窗口在哪里都打不开。 HUD 还没有它：在 Overview 中应用 Add-on windows in the HUD。
  • 对窗口的修改没有显示。 你编辑的是某个 HUD 内的副本，而不是扩展 Prefabs 文件夹中的预制体。
  • 客户端因版本不匹配被拒绝。 客户端和地图服务器是用不同的扩展构建的。
