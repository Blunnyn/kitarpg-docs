与 Central 通信

地图服务器如何与 Central 中的模块交换你自己的消息，用于跨地图或跨角色的功能：排行榜、世界事件、全服计数器。本页介绍地图一侧（CentralMessages）；Central 一侧见服务模块。

#什么时候需要 Central

在线时，每张地图运行在各自的服务器进程中，从不接触数据库。Central 连接所有地图，保持会话并写入数据库。凡是单张地图无法知道的，都需要 Central：

  • 涵盖所有角色的排行榜（悬赏示例中的猎人榜），
  • 在所有地图上同时开始的事件，
  • 整个服务器的计数器，
  • 不在线角色的数据。

随角色一起移动的单个角色数据不需要 Central：使用标记或 PlayerData（见保存数据）。

单人模式中没有 Central。每个使用它的功能都需要一个后备方案，哪怕后备方案只是"仅限在线"。

#消息如何传递

Map server (Unity)                       Central (.NET)
CentralMessages.Send(new BountyFinished)  ->  module handler for BountyFinished
                                               m.Reply(new BountyBoardList)
CentralMessages.On<BountyBoardList>(...)  <-   (to the map that asked)
  1. 在地图上，CentralMessages.Send 通过地图与 Central 之间经过认证的链路（LiteNetLib，可靠且有序）写出消息的类名及其 JSON（Unity 的 JsonUtility）。
  2. Central 查找哪个模块注册了该类名，并把用 System.Text.Json 反序列化后的消息连同发送它的地图一起交给该模块。
  3. 模块回复发出请求的地图（Reply）、某个角色所在的地图（SendToCharacter）、按 id 指定的一张地图（Send）或所有地图（Broadcast）。
  4. 在地图上，CentralMessages.On<T> 的处理器在主线程上运行。

#CentralMessages

CentralMessages 位于 KitARPG.Server（命名空间 Blunnyn.KitARPG.Server），因此使用它的代码要放在仅服务器的程序集中，例如 Game.Server。

成员 作用
static bool Online 地图已在 Central 注册。在单人模式中以及 Central 不在线时为 false。
static bool Send<T>(T message) 发送给 Central 的模块。无法连接 Central 时返回 false；不会排队。使用套件的消息名称时抛出异常。
static void On<T>(Action<T> handler) 对 Central 发来的每个 T，在主线程上调用 handler。每种类型一个处理器：第二次调用会替换第一次；传 null 则移除。使用套件的消息名称时抛出异常。

处理器在每次 Play 开始时被清空；请在 AfterSceneLoad（或 AfterAssembliesLoaded）中注册。处理器内部的异常会被记录，不会中断链路。

#编写消息

消息是普通的 C# 类，由 Unity 和你的 Central 模块从同一个文件编译：

using System;

namespace Game
{
    /// <summary>Map to Central: a character finished a bounty.</summary>
    [Serializable]
    public class BountyFinished
    {
        public long characterId;
        public string name;
        public string monster;
    }

    /// <summary>Central to the map the asking character is on.</summary>
    [Serializable]
    public class BountyBoardList
    {
        public long characterId;
        public BountyHunter[] top = new BountyHunter[0];
        public int mine;
    }

    [Serializable]
    public class BountyHunter
    {
        public string name;
        public int bounties;
    }
}

规则如下，因为有两个不同的 JSON 库要读取它们：

  • **带公共字段的 [Serializable] 类。**不用属性，不用带参数的构造函数，不用字典。
  • **字段名用 lowerCamelCase。**Central 以 camelCase 写 JSON；Unity 的 JsonUtility 严格按名称匹配，所以名为 CharacterId 的字段在地图上会是空的。
  • 两边都能读的类型：int、long、float、double、bool、string、枚举（以数字形式），以及由这些类型和其他消息类组成的数组和列表。
  • 不用 Unity 类型（Vector3、Color）。发送数字。
  • **使用你自己的名称。**消息只按类名传递（不含命名空间）。套件的名称在两边都会被拒绝：在地图上，Send 和 On 抛出异常；在 Central 中，模块无法启动。给它们加前缀（BountyFinished，而不是 Finished）。

把这个文件放在不引用引擎的程序集中（noEngineReferences: true），这样任何仅限 Unity 的东西都混不进来，并在模块的 .csproj 中链接它。示例把它放在 DevKit/Example/Bounties/Shared/BountyBoardMessages.cs，程序集为 Game.Bounties.Shared。见程序集。

#发送

// Offline the board just misses this one; the character's own history still has it.
CentralMessages.Send(new BountyFinished { characterId = player.State.id, name = player.characterName, monster = monster.Id });

player.State.id 是角色在数据库中的 id。Central 在处理之前会检查这张地图是否确实承载该角色（MapMessage.Hosts），因此一张地图只能代表它自己的玩家发言。

地图未连接时 Send 返回 false。不会保留任何东西留待以后：如果数据不能丢失，也把它保存在角色上（PlayerData），并在 Online 恢复后再次发送，或者把模块设计成接收完整状态而不是增量。

#接收

using System.Text;
using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Server;
using UnityEngine;

namespace Game
{
    public static class HuntersBoard
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Register()
        {
            CentralMessages.On<BountyBoardList>(OnBoard);
        }

        static void OnBoard(BountyBoardList board)
        {
            var text = new StringBuilder("Best bounty hunters:");
            int rank = 1;
            foreach (BountyHunter hunter in board.top ?? new BountyHunter[0])
                text.Append($"\n{rank++}. {PlayerText.NoTags(hunter.name)}: {hunter.bounties}");
            if (rank == 1) text.Append("\nNobody yet.");
            text.Append($"\nYou: {board.mine}");
            SocialHub.Notice(board.characterId, text.ToString());
        }
    }
}
  • 关于某个角色的回复会带上该角色的 id，地图用 PlayerCharacter.ServerFind(characterId) 找到该玩家，或用 SocialHub.Notice(characterId, text) 显示一条系统消息。如果角色在此期间已离开，两者都不做任何事。
  • 来自玩家的文本（名称、备注）用 PlayerText.NoTags 显示，这样它无法在其他人的屏幕上打开富文本标签。
  • 数组从 JSON 中可能以 null 到达；用 ?? new T[0] 防护。

#完整示例：所有地图上的世界事件

一名管理员在所有地图上开启"双倍金币"一小时。模块保存它并广播；每张地图把它应用到自己的玩家。

共享消息（在 Game.Shared 中，由模块链接）：

[Serializable]
public class GoldHourStart
{
    public long characterId;   // who asked, so Central can check the map hosts them
    public int minutes;
}

[Serializable]
public class GoldHourState
{
    public long endsUnixSeconds;   // 0 when none
}

地图一侧（在 Game.Server 中）：

using System;
using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Server;
using UnityEngine;

namespace Game
{
    public static class GoldHour
    {
        static long endsAt;

        public static bool Active => DateTimeOffset.UtcNow.ToUnixTimeSeconds() < endsAt;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void ResetStatics() => endsAt = 0;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Register()
        {
            CentralMessages.On<GoldHourState>(state => endsAt = state.endsUnixSeconds);
            GmCommands.Register(new GmCommand
            {
                name = "goldhour", rank = GmRank.GameMaster, usage = "goldhour minutes", description = "Double gold on every map.",
                run = c =>
                {
                    int minutes = Mathf.Clamp(c.Int(0, 60), 1, 24 * 60);
                    if (!CentralMessages.Send(new GoldHourStart { characterId = c.player.State.id, minutes = minutes }))
                        return "Only online.";
                    return $"Starting a {minutes} minute gold hour everywhere.";
                },
            });
        }
    }
}

Central 一侧（在模块中，见服务模块）：

public void OnMapLink(IMapLink link)
{
    link.On<GoldHourStart>(m =>
    {
        if (!m.Hosts(m.Message.characterId) || m.Message.minutes < 1 || m.Message.minutes > 1440) return Task.CompletedTask;
        long ends = DateTimeOffset.UtcNow.AddMinutes(m.Message.minutes).ToUnixTimeSeconds();
        link.Broadcast(new GoldHourState { endsUnixSeconds = ends });
        return Task.CompletedTask;
    });
}

你自己的奖励代码读取 GoldHour.Active。对于套件自带的经验、掉落和金币倍率，你不需要这些：/rates 命令已经能开启限时倍率事件，由 Central 分发给每张地图。

GM 命令已经在地图上检查了等级，审计也已记录。之后才加入的地图不知道这个事件；在地图请求时把状态发给它们，或者把状态保存在模块中，并在每张地图启动时回复它发来的 GoldHourAsk。

#单人模式

CentralMessages.Online 为 false，Send 返回 false。按功能决定：

  • **仅限在线：**告诉玩家，就像 /hunters 那样（"The hunters board is kept online"）。
  • **本地后备：**用 PlayerData 保存每个角色的版本，就像示例保存每个角色最近的狩猎那样。

#常见错误

  • **在 Game 程序集中使用 CentralMessages。**它位于 KitARPG.Server；代码要放在 Game.Server 中。
  • **PascalCase 字段。**来自 Central 的回复在地图上会是空的。
  • 在 Central 一侧信任角色 id，而不使用 m.Hosts(id)。
  • **以为 Send 会排队。**它不会；要考虑 Central 不在线的情况。
  • **为同一类型注册两个处理器。**第二个会替换第一个。
