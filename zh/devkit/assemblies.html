开发套件

程序集

套件的代码如何划分为程序集，每个程序集会进入哪些构建，以及如何为你自己的代码设置程序集（Game、Game.Server 和 Game.Editor）。

#这里所说的程序集是什么

Unity 把脚本编译进由 .asmdef 文件定义的程序集。一个脚本属于其所在文件夹或最近的上级文件夹中 .asmdef 所定义的程序集。一个程序集只能看到它在引用中列出的程序集。

套件的程序集不会被自动引用。Assets 中没有自己 .asmdef 的脚本（默认的 Assembly-CSharp）看不到套件。这是有意为之：你的代码拥有自己的程序集，这样编译时间短，你的代码也与套件的代码分开。

#套件的程序集

程序集 引用 定义约束 进入哪些构建
KitARPG.Shared 无（没有引擎引用） 无 全部。.NET 服务编译同样的文件。
KitARPG.Data Shared 无 全部
KitARPG.Net Shared、Data、Mirror 无 全部
KitARPG.Client Shared、Data、Net、Mirror、UI、TextMeshPro、URP、Input System 无 全部（地图服务器带有它但不显示）
KitARPG.Server Shared、Data、Net、Mirror、KCP、AI Navigation UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER 地图服务器、单人模式、编辑器
KitARPG.Local Shared、Data、Net、Server、Client UNITY_EDITOR || KITARPG_SINGLEPLAYER 仅单人模式和编辑器
KitARPG.Modes.TopDown、KitARPG.Modes.ThirdPerson Shared、Data、Net、Client 无 全部
KitARPG.Modes.TopDown.Server、KitARPG.Modes.ThirdPerson.Server Shared、Data、Net、Server、对应的模式 UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER 地图服务器、单人模式、编辑器
KitARPG.Editor 以上全部 仅 Editor 平台 永远不进入构建

KitARPG.Shared 也是与服务之间的约定：Services/Shared/KitARPG.Shared.csproj 编译 Runtime/Shared 下的每个文件，因此在那里定义的消息类在 Unity 和 Central 中读起来完全一样。

#构建符号

一个构建带有哪些程序集取决于它的脚本定义符号。套件的构建菜单会替你设置。

符号 编译什么 构建
KITARPG_SERVER（或 UNITY_SERVER） KitARPG.Server、每个 KitARPG.Modes.*.Server，以及每个名称以 .Server 结尾的程序集 地图服务器和单人模式
KITARPG_SINGLEPLAYER KitARPG.Local（本地存档） 仅单人模式
KITARPG_DEV 或开发构建 测试工具（自动登录、冒烟测试、沙盒） 编辑器和开发构建
KITARPG_LOADTEST 压力测试机器人 仅压力测试构建；由套件的菜单添加和移除

在线客户端构建没有任何服务器符号，因此完全不带服务器代码。单人模式构建同时是客户端和服务器，因此带有 KITARPG_SERVER 和 KITARPG_SINGLEPLAYER。

#构建分离检查

在每次构建之前，无论从哪个菜单或 Build Profile 发起，套件都会运行 BuildSeparation。它读取项目中的每个程序集，用该构建的符号计算其定义约束，并在以下情况停止构建：

  • 在线客户端会带有服务器代码（任何 .Server 程序集、KitARPG.Server）或本地存档，
  • 地图服务器会带有本地存档，
  • 发布构建会带有测试工具，
  • 单人模式构建缺少服务器，
  • 发布版在线客户端使用 Mono 而不是 IL2CPP 构建（其代码会以可读的 DLL 形式发布）。

使用 Mono 构建的开发版客户端只会得到警告。KitARPG > Check Build Separation 显示每种构建会包含什么。这项检查无法关闭。你自己的程序集也以同样方式检查：名为 Something.Server 但没有服务器定义约束的程序集会让在线客户端构建停止。

#你的程序集

在 Project 窗口中选中文件夹，然后从 Create > KitARPG > Scripts 创建它们。

菜单 文件 用途
Game Assembly Game.asmdef 在每个构建中都运行的一切：效果、条件、动作、目标、NPC 选项、玩家系统、消息、窗口、公式、菜单行、设置。
Game Server Assembly Game.Server.asmdef 只有地图服务器和单人模式可以携带的代码：GM 命令、CentralMessages、任何使用 KitARPG.Server 的代码。
Game Editor Assembly Game.Editor.asmdef 编辑器工具：KitARPG 窗口页面、校验器检查、套件更新、设置菜单。

#Game

菜单会写出这个文件：

{
    "name": "Game",
    "rootNamespace": "Game",
    "references": [
        "KitARPG.Shared",
        "KitARPG.Data",
        "KitARPG.Net",
        "KitARPG.Client",
        "Mirror",
        "Unity.TextMeshPro",
        "UnityEngine.UI"
    ],
    "autoReferenced": true
}

rootNamespace 是 Game，因此在这个文件夹中由模板创建的脚本会得到 namespace Game。需要时添加引用：使用俯视角输入类时加 KitARPG.Modes.TopDown，使用 Input System 时加 Unity.InputSystem，使用 NavMesh 组件时加 Unity.AI.Navigation。

#Game.Server

{
    "name": "Game.Server",
    "rootNamespace": "Game",
    "references": [
        "Game",
        "KitARPG.Shared",
        "KitARPG.Data",
        "KitARPG.Net",
        "KitARPG.Server",
        "Mirror"
    ],
    "defineConstraints": [
        "UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER"
    ],
    "autoReferenced": false
}

定义约束让它不进入在线客户端构建。它在编辑器、地图服务器和单人模式中编译。把它放在自己的文件夹中，例如 Assets/Game/Server，这样它的脚本就不会落入 Game。

#Game.Editor

{
    "name": "Game.Editor",
    "rootNamespace": "Game",
    "references": [
        "Game",
        "KitARPG.Shared",
        "KitARPG.Data",
        "KitARPG.Net",
        "KitARPG.Editor"
    ],
    "includePlatforms": [ "Editor" ]
}

Unity 也会特殊对待任何名为 Editor 的文件夹，但使用程序集定义时，让它不进入构建的是 includePlatforms 这一行。把它放在 Assets/Game/Editor。

#建议的目录结构

Assets/Game/
    Game.asmdef
    Effects/          skill and item effects
    Logic/            conditions, actions, objectives, NPC options
    Systems/          player systems and network messages
    UI/               windows and menu lines
    Data/             your own ScriptableObject types
    Shared/
        Game.Shared.asmdef   plain C# shared with your Central module
        Messages.cs
    Server/
        Game.Server.asmdef
        Commands.cs
        CentralLink.cs
    Editor/
        Game.Editor.asmdef
        Checks.cs
        Updates.cs

#引用的方向

Game.Server 引用 Game，绝不能反过来。在线客户端有 Game 但没有 Game.Server，所以 Game 不能依赖只有服务器才有的东西。

当 Game 中的代码需要把某些东西交给仅服务器的代码时，在 Game 中触发一个事件，并在 Game.Server 中订阅它。悬赏示例正是这样做的：

// In Game.Bounties (every build): raised when a bounty is paid.
public static event Action<PlayerCharacter, MonsterData> ServerTurnedIn;

// In Game.Bounties.Server (server builds): forwards it to Central.
Bounties.ServerTurnedIn += OnTurnedIn;

这同样适用于 GmCommands 和 CentralMessages 这样的 KitARPG.Server 类型：只有仅服务器程序集中的代码可以使用它们。

#用于消息的纯 C# 程序集

你的地图服务器与 Central 模块交换的消息会被编译两次：由 Unity 编译，也由 .NET 模块编译。把它们放在没有引擎引用的程序集中，这样就不会混入只属于 Unity 的东西：

{
    "name": "Game.Shared",
    "rootNamespace": "Game",
    "references": [],
    "noEngineReferences": true,
    "autoReferenced": false
}

从 Game.Server 引用 Game.Shared（如果客户端需要这些类型，也从 Game 引用），并在模块的 .csproj 中链接同一个 .cs 文件。参见与 Central 通信和服务模块。

#多个功能程序集

大型游戏可以把各个功能拆分到各自的程序集中，就像示例中的 Game.Bounties、Game.Bounties.Server、Game.Bounties.Shared 和 Game.Bounties.Editor。这样每个功能单独编译，删除它的文件夹即可移除它。遵循同样的命名：服务器部分使用 .Server 后缀和服务器定义约束，编辑器部分使用 includePlatforms: Editor。

#Mirror 与你的程序集

Mirror 的 weaver 会处理每个引用了 Mirror 的程序集，因此 Game 中的 NetworkBehaviour、[SyncVar]、[Command] 和 NetworkMessage 结构体与套件自己的一样能正常工作。由此带来两点：

  • 网络版本。 套件会对每个同步字段和消息类型计算哈希（NetworkVersion），包括你的。由不同代码构建的客户端和地图服务器会得到不同的值，地图会以 version_mismatch 拒绝该客户端。修改任何跨网络传输的内容后，两者都要重新构建。
  • 组件顺序。 Mirror 按 NetworkBehaviour 在对象上的索引进行匹配。在每个联网预制体上，客户端和服务器必须有相同的组件且顺序相同。绝不要只在某一种构建中添加或移除 NetworkBehaviour。

#常见问题

现象 原因 解决办法
The type or namespace 'Blunnyn' could not be found 脚本不在你的程序集所在的文件夹下，因此被编译进 Assembly-CSharp。 把它移到 Game.asmdef 所在的文件夹下，或者在那里创建程序集。
找不到 GmCommands 或 CentralMessages 脚本在 Game 中，而 Game 不引用 KitARPG.Server。 把它移到 Game.Server 文件夹。
客户端构建因构建分离错误而停止，错误中提到你的程序集 某个 .Server 程序集缺少定义约束，或者某个客户端程序集引用了服务器程序集。 添加 UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER，并让引用从服务器程序集指向客户端程序集。
你的模板类没有出现在 Inspector 的类型菜单中 它无法编译、它是抽象类，或者它不是 [Serializable]。 修复 Console 中的错误；让该类保持 public、非抽象并带有 [Serializable]。
加入时出现 version_mismatch 客户端和地图服务器由不同的代码构建。 两者都重新构建。
