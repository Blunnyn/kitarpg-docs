开发套件

代码中的 GM 命令

如何添加你自己的斜杠命令：注册 GmCommand、用 GmContext 读取参数、选择等级、审计如何运作，以及完整示例。

#命令是什么

玩家在聊天中输入以 / 开头的命令。聊天把这一行发送到地图服务器，地图服务器查找该命令，将玩家的等级与命令的等级比较，执行命令，并把回复作为系统消息显示在聊天中。GM 面板（F8 或 /gm）运行的是同样的命令。套件自带的命令列在 GM 命令中。

命令通过代码用 GmCommands.Register 注册。GmCommands 位于 KitARPG.Server（命名空间 Blunnyn.KitARPG.Server），在线客户端从不包含它。

文件放在哪里：Game.Server 程序集（见程序集）。这样命令存在于地图服务器、单人模式和编辑器中，而永远不会出现在在线客户端构建中。

#注册命令

using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Server;
using UnityEngine;

namespace Game
{
    public static class MyCommands
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Register()
        {
            GmCommands.Register(new GmCommand
            {
                name = "refresh",
                aliases = new[] { "fill" },
                rank = GmRank.Moderator,
                usage = "refresh [player]",
                description = "Fills a player's health.",
                run = c =>
                {
                    PlayerCharacter target = c.Target(0);
                    if (target == null) return "Nobody by that name here.";
                    target.ServerHeal(target.maxHealth, null);
                    return $"Healed {target.characterName}.";
                },
            });
        }
    }
}

套件在每次 Play 时于 SubsystemRegistration 中清空并注册自己的命令，所以你要在 AfterSceneLoad（或 AfterAssembliesLoaded）中注册你的命令。注册一个已存在的名称会替换旧命令，包括套件的命令。这就是修改套件命令的方式；这也是意外破坏某个命令的方式，所以请使用你自己的名称。

#GmCommand 字段

字段 是什么 默认值
name 玩家在 / 之后输入的内容。
aliases 同一命令的其他名称。 无
rank 默认要求的等级（见下文）。 GmRank.Admin
usage 由 /help 显示，例如 "item id [amount] [player]"。
description /help 中的一行说明。
run Func<GmContext, string>：执行命令并返回要显示的回复，返回 null 表示不显示。

#等级

GmRank 值 含义
Player 1 任何人。
Moderator 2 聊天和玩家管理。
GameMaster 3 游戏改动：物品、传送、怪物。
Admin 4 一切，包括角色权限。

命令要求的等级是 GmCommands.LevelOf(command)：如果在 Game Settings > GM commands（GameInstance.gmCommandLevels）中为它的名称设置了等级，就用那个等级，否则用它的 rank。设计师无需代码就能把任何命令（包括你的）调高或调低。/role 始终要求 Admin。

玩家的等级是 GmCommands.RankOf(player)：数据库中账号的角色（accounts.Role），如果 GmCommands.EveryoneRank 更高则用后者。在单人模式中，Single Player Commands（singlePlayerCommands，默认开启）会让 EveryoneRank 为 Admin，因此每个命令都能当作作弊命令使用。在线时它是 Player。

等级低于命令等级的玩家会看到 "Unknown command"，就像该命令不存在一样。

#GmContext

run 接收到的内容：

成员 是什么
PlayerCharacter player 输入命令的人。
string[] args 名称之后的单词，按空格拆分。
string rest 名称之后的全部内容，与输入一致。用于自由文本。
int level 此命令要求的等级。对于 Central 会再次检查的命令，把它传给 Central。
string Arg(int i) 第 i 个单词，或 null。
int Int(int i, int fallback) 第 i 个单词转为整数，或 fallback。
long Long(int i, long fallback) 同上，转为 long。
float Float(int i, float fallback) 同上，转为 float。拒绝 NaN 和无穷大。
PlayerCharacter Target(int i) 本地图上由第 i 个单词指定的玩家；该单词缺失时为输入命令的人。名称不在本地图上时为 null。
T Data<T>(int i) id 为第 i 个单词的 T 类型游戏数据，或 null。

数字按不变区域性（invariant culture）解析，因此 1.5 在每台机器上都能用。

#审计

每个等级高于 Player（2 或以上）的命令都属于管理人员的工作，会被记录：

  • 每次使用，无论因等级而被允许还是拒绝，都会写入 GM 审计（在线时为 gm_audit 表，单人模式中为存档），包括账号、角色、等级、命令、整行、目标和结果。
  • 每次实际运行的使用还会写入一条类型为 gm.command 的游戏日志，附带回复。
  • 当审计无法记录时（Central 无法连接），管理命令会暂停并回复 "GM commands are paused"。没有记录，任何管理级别的命令都不会运行。

Player 等级的命令不做审计。

GmCommands.ServerUsed（PlayerCharacter, string line）会在每个命令运行之前触发。GmAudit.Recorded（GmAuditEntry）会在每条审计记录时触发。见事件。

#上限

GmCommands 有一些套件命令会遵守的上限，这样一次输错或一个被盗的管理账号不会冲垮经济。在你自己发放东西的命令中也要遵守它们：

字段 默认值
MaxItems 9,999
MaxGold 1,000,000,000
MaxExperience 1,000,000,000
MaxPoints 1,000
MaxStatusSeconds 3,600
MaxKillRange 100
MaxMuteMinutes 525,600

它们是静态字段，每次 Play 时重置。如果你的游戏需要其他上限，在你自己的 AfterSceneLoad 方法中修改它们。

#示例

#发放属性点，带上限

GmCommands.Register(new GmCommand
{
    name = "points", rank = GmRank.GameMaster, usage = "points amount [player]", description = "Gives attribute points.",
    run = c =>
    {
        int amount = c.Int(0, 0);
        if (amount <= 0) return "Usage: /points amount [player]";
        amount = Mathf.Min(amount, GmCommands.MaxPoints);
        PlayerCharacter target = c.Target(1);
        if (target == null) return "Nobody by that name here.";
        target.GainPoints(amount, 0);
        return $"{target.characterName} got {amount} attribute points.";
    },
});

#按 id 查找游戏数据

Data<T> 按 id 查找游戏数据：

GmCommands.Register(new GmCommand
{
    name = "where", rank = GmRank.Player, usage = "where monster_id", description = "Maps where a monster lives.",
    run = c =>
    {
        MonsterData monster = c.Data<MonsterData>(0);
        if (monster == null) return "No monster with that id.";
        var maps = new System.Collections.Generic.List<string>();
        foreach (MapData map in GameInstance.Database.maps)
            if (map != null && System.Array.IndexOf(map.monsters, monster) >= 0) maps.Add(map.DisplayName);
        return maps.Count == 0 ? $"{monster.DisplayName} lives nowhere listed." : $"{monster.DisplayName}: {string.Join(", ", maps)}";
    },
});

#给玩家用的命令

Player 等级的命令是添加聊天功能的快捷方式。悬赏示例中的 /hunters 会向 Central 请求排行榜：

GmCommands.Register(new GmCommand
{
    name = "hunters", rank = GmRank.Player, usage = "hunters", description = "The best bounty hunters on every map, and your last hunts.",
    run = c =>
    {
        string mine = Last(c.player);
        if (!CentralMessages.Online) return "The hunters board is kept online." + mine;
        CentralMessages.Send(new BountyBoardAsk { characterId = c.player.State.id });
        return "Asking the guild of hunters..." + mine;
    },
});

Central 的回复稍后到达，用 SocialHub.Notice 显示。见与 Central 通信。

#自由文本

rest 保留空格：

GmCommands.Register(new GmCommand
{
    name = "notice", rank = GmRank.Moderator, usage = "notice text", description = "Sets the notice board.",
    run = c => string.IsNullOrWhiteSpace(c.rest) ? "Usage: /notice text" : SetNotice(c.rest),
});

其他玩家会看到的任何文本都要用 PlayerText.Clean(text, maxLength) 清理。

#/help

/help 先列出聊天命令，然后列出玩家等级允许使用的每个命令（包括 Player 等级的命令），附带用法和说明。高于 Player 等级的命令末尾用方括号标出等级，例如 [3]；Player 等级的命令不带这个标记。

#错误

run 内部的异常会被捕获：它会记录在服务器日志中，玩家看到 "/name failed: message"。对于玩家操作错误的情况，返回一句话，而不是抛出异常。

#服务器与客户端

命令只在地图服务器（或单人模式的主机）上运行。客户端发送输入的那一行；该行在 300 个字符处截断，并像聊天一样限速。客户端只能通过这一行触及你的 run 中的内容，而等级检查在运行之前进行。

#常见错误

  • **把命令放在 Game 程序集中。**它看不到 KitARPG.Server；即使能看到，客户端也会带上命令代码。
  • **在 SubsystemRegistration 中注册。**套件在那里清空列表；这些方法之间的顺序是不确定的。
  • **重用套件命令的名称。**你的命令会替换它。
  • **数量不设上限。**使用 Max... 字段。
  • 不用 Target 就按名称操作。Target 只能找到本地图上的玩家；对于其他地方的玩家，要通过 Central。
