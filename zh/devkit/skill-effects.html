Skill effects

此页面尚未翻译，以英文显示。

How to write your own skill effects: the SkillEffect base class, what a cast hands you, how targets are chosen, and complete examples that follow the game's damage rules.

#What a skill effect is

A skill is a target, an area and a list of effects (SkillData.effects). When the skill lands, the server works out who it reached and calls each effect once per target. The kit ships effects for damage, heals, stat buffs, statuses, cleanse and dispel, knockback, revive and summons. Anything else a skill should do is a new effect class.

Effects are [Serializable] classes held by reference ([SerializeReference, PickType]). Once your class compiles, it appears in the + type menu of every skill's Effects list in KitARPG > Game Database > Skills. There is nothing to register.

Where the file goes: the Game assembly. Effects are data that both builds load (the client shows them in tooltips), even though only the server applies them.

#The base class

SkillEffect lives in Blunnyn.KitARPG.Data.

Member What it does Default
string Summary Short text shown in the skill editor's effect list and used as the default tooltip line. The class name
bool Harmful true: the effect lands on enemies the skill reaches. false: on the caster and allies it reaches. false
bool OnCaster true: the effect runs once per cast with the caster as the target, whoever else the skill reaches. Used by summons. false
void Apply(SkillCast cast, IFighter target) Server only. Called once per target. Required.
void Describe(ItemDescription description, int level, DamageElement fallback) Lines for the skill's card at a rank. Runs on the client. fallback is the element to name when yours is empty. Adds Summary
void Visit(Action<GameData> visit) Hands the game database every asset the effect points at, so they get registered. Nothing

#How targets are picked

The server's SkillRunner gathers enemies and allies in the skill's area, then for each effect in order:

  • OnCaster effects run once with target set to the caster.
  • Harmful effects run on every enemy reached; the others run on every ally reached (the caster counts as an ally when the area includes it).
  • On skills with Targets Dead set, only dead fighters are reached; otherwise only living ones.

A skill can land several times in one cast:

  • Multi-hit animations split one cast across several hit moments. Each landing carries a share of the damage in cast.scale, and only the first has cast.firstHit true.
  • Zones left on the ground land again every tick, each tick as a fresh cast with firstHit true.
  • Piercing lines hit each target as the projectile passes.
  • Bounces jump to the next target with cast.scale reduced by the skill's Bounce Keep.

Two rules follow. Scale damage and healing by cast.scale. Put buffs, statuses and other one-time effects behind if (!cast.firstHit) return; so they go on once per cast.

#What a cast hands you

SkillCast:

Field What it is
IFighter caster Who cast it: a player or a monster.
SkillData skill The skill.
int level The rank it was cast at, gear bonuses included. Use it with LevelValue.At(level).
IReadOnlyList<ElementDamage> weapon Rolls of the caster's weapon, for effects that scale with it. May be empty or null.
IFighter target The aimed target, if the skill has one.
Vector3 point Where it was aimed: the target's position or a point on the ground.
float scale Share of damage and healing this landing carries. 1 for a single landing.
bool firstHit False on the later landings of one cast.
float projectileSpeed Meters per second of the skill's projectile, 0 without one.
SkillCast Copy() A copy, for effects that land later.

IFighter is anything a skill can touch, on the server:

Member What it does
Transform transform, bool IsDead, int Level Position, state, level.
int Team Players are 0, monsters 1. Different teams are enemies.
StatSheet CombatStats Stats and elements for attacking and defending. Server only.
void ServerDamage(Hit hit, IFighter source) Deals a hit. Shields, immunities and death are handled inside.
void ServerHeal(int amount, IFighter source, GameData cause = null) Heals. The amount is final: the healer's stats are not added again. cause picks the effect clients show.
bool ServerAddBuff(Buff buff) Adds a buff or status. False when it didn't take (immunity, dead).
int ServerRemoveBuffs(Predicate<Buff> match, int max = 0) Removes matching buffs, newest first; 0 removes all. Returns how many.
StatusFlags Status What its statuses stop it from doing now (stunned, rooted, invisible).
bool ServerKnock(Vector3 to, float seconds) Pushes or pulls it. False when it can't be moved.
bool ServerRevive(float health, float mana, IFighter by) Brings it back with a share of health and mana.

On the server, players are PlayerCharacter and monsters are Monster (both in Blunnyn.KitARPG.Net). Cast to them when you need something IFighter doesn't have, such as health.

#Numbers that grow with rank

LevelValue is a value at rank 1 plus an amount per rank after it:

public LevelValue amount = new LevelValue(10, 2);   // 10 at rank 1, 12 at rank 2, 14 at rank 3
float value = amount.At(cast.level);
int whole = amount.AtInt(cast.level);               // rounded

The inspector shows it as Base Value and Per Level.

#Hits and the damage formula

A Hit is amount, critical, element (the element that did most of it, for its color) and source (the skill, weapon type or monster, which picks the hit effect).

To follow the game's damage rules (element damage, power, flat and percent resistance, criticals), let the combat formula build the hit:

var rolls = new List<ElementDamage> { new ElementDamage(element, min.At(cast.level), max.At(cast.level)) };
Hit hit = GameInstance.Combat.Attack(cast.caster.CombatStats, rolls, target.CombatStats, cast.scale);
hit.source = cast.skill;
target.ServerDamage(hit, cast.caster);

For heals, GameInstance.Combat.Heal(cast.caster.CombatStats, amount) adds the caster's heals stat and healing bonus. A game that swapped the formula (see Formulas) changes your effects too.

#Example: the template

Create > KitARPG > Scripts > Skill Effect makes a fixed-damage effect. It skips the formula on purpose to stay short. The Templates page shows it.

#Example: life steal

Damage that heals the caster for a share of what it dealt.

using System;
using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    /// <summary>Hits each enemy and heals the caster for a share of the damage.</summary>
    [Serializable]
    public class LifeStealEffect : SkillEffect
    {
        [Tooltip("Empty uses the database's default element.")]
        public DamageElement element;
        public LevelValue min = new LevelValue(8, 3);
        public LevelValue max = new LevelValue(12, 4);
        [Tooltip("Share of the damage dealt that heals the caster, from 0 to 1.")]
        public LevelValue steal = new LevelValue(0.2f, 0.02f);

        public override string Summary => $"Life steal {min.baseValue:0}-{max.baseValue:0}";

        public override bool Harmful => true;

        public override void Apply(SkillCast cast, IFighter target)
        {
            var rolls = new List<ElementDamage> { new ElementDamage(element, min.At(cast.level), max.At(cast.level)) };
            Hit hit = GameInstance.Combat.Attack(cast.caster.CombatStats, rolls, target.CombatStats, cast.scale);
            hit.source = cast.skill;
            target.ServerDamage(hit, cast.caster);

            int healed = Mathf.RoundToInt(hit.amount * Mathf.Clamp01(steal.At(cast.level)));
            if (healed > 0 && !cast.caster.IsDead) cast.caster.ServerHeal(healed, cast.caster, cast.skill);
        }

        public override void Describe(ItemDescription description, int level, DamageElement fallback)
        {
            DamageElement shown = element != null ? element : fallback;
            description.Add($"{min.At(level):0} to {max.At(level):0} {(shown != null ? shown.DisplayName : "Neutral")} damage",
                ItemDescription.Kind.Effect, shown != null ? shown.Icon : null);
            description.Add($"Heals you for {steal.At(level) * 100:0}% of the damage", ItemDescription.Kind.Effect);
        }

        // The element is an asset: hand it over so the database registers it.
        public override void Visit(Action<GameData> visit) => visit(element);
    }
}

The heal uses the hit's amount before shields soaked any of it. If that matters in your game, compare the target's health before and after (see the next example for reading health).

#Example: execute

Extra damage against targets below a share of their health.

using System;
using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    /// <summary>Hits harder when the target is low on health.</summary>
    [Serializable]
    public class ExecuteEffect : SkillEffect
    {
        public DamageElement element;
        public LevelValue min = new LevelValue(10, 3);
        public LevelValue max = new LevelValue(14, 4);
        [Tooltip("Below this share of health, from 0 to 1, the bonus applies.")]
        [Range(0, 1)] public float below = 0.3f;
        [Tooltip("Extra damage below the threshold: 1 doubles it.")]
        public LevelValue bonus = new LevelValue(1f, 0.25f);

        public override string Summary => $"Execute below {below * 100:0}%";

        public override bool Harmful => true;

        public override void Apply(SkillCast cast, IFighter target)
        {
            float scale = cast.scale;
            if (HealthShare(target) < below) scale *= 1 + bonus.At(cast.level);
            var rolls = new List<ElementDamage> { new ElementDamage(element, min.At(cast.level), max.At(cast.level)) };
            Hit hit = GameInstance.Combat.Attack(cast.caster.CombatStats, rolls, target.CombatStats, scale);
            hit.source = cast.skill;
            target.ServerDamage(hit, cast.caster);
        }

        static float HealthShare(IFighter fighter)
        {
            if (fighter is PlayerCharacter player) return player.maxHealth > 0 ? (float)player.health / player.maxHealth : 1f;
            if (fighter is Monster monster) return monster.maxHealth > 0 ? (float)monster.health / monster.maxHealth : 1f;
            return 1f;
        }

        public override void Describe(ItemDescription description, int level, DamageElement fallback)
        {
            description.Add($"{min.At(level):0} to {max.At(level):0} damage", ItemDescription.Kind.Effect);
            description.Add($"+{bonus.At(level) * 100:0}% against targets below {below * 100:0}% health", ItemDescription.Kind.Effect);
        }

        public override void Visit(Action<GameData> visit) => visit(element);
    }
}

#Example: mana refund on the caster

An OnCaster effect runs once per cast, with the caster as target. This one gives mana back when the skill reached at least one enemy.

using System;
using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class ManaRefundEffect : SkillEffect
    {
        public LevelValue mana = new LevelValue(5, 1);

        public override string Summary => $"Refund {mana.baseValue:0} mana";

        public override bool OnCaster => true;

        public override void Apply(SkillCast cast, IFighter target)
        {
            if (!cast.firstHit) return;
            // Players are item users too, which is how mana is restored from data code.
            if (target is IItemUser user) user.RestoreMana(mana.AtInt(cast.level));
        }

        public override void Describe(ItemDescription description, int level, DamageElement fallback) =>
            description.Add($"Restores {mana.At(level):0} mana when cast", ItemDescription.Kind.Effect);
    }
}

#Example: a status with a chance, from a field

Effects that point at assets (statuses, monsters, items) must hand them to Visit. Without it, an asset only your effect references may be left out of the game database, and the server can't find it by id.

[Serializable]
public class MarkForDeathEffect : SkillEffect
{
    public StatusData status;
    public LevelValue seconds = new LevelValue(6, 0.5f);

    public override string Summary => status != null ? $"Mark: {status.DisplayName}" : "Mark (none)";

    public override bool Harmful => true;

    public override void Apply(SkillCast cast, IFighter target)
    {
        if (status == null || !cast.firstHit) return;
        target.ServerAddBuff(Buff.Of(status, cast.level, seconds.At(cast.level), cast.caster));
    }

    public override void Visit(Action<GameData> visit) => visit(status);
}

For most statuses the kit's ApplyStatusEffect already does this, with a chance and stacks. Write your own only when the rule differs.

#Server and client

Runs on
Apply Server only: the map server online, the host in single player.
Describe, Summary Wherever a skill card is shown: the client, and the editor.
Field values Both: the asset is the same in both builds.

Clients see the result through the kit's own sync: health bars, damage numbers (CombatEvents.Damaged), buff icons and the skill's effects. Your effect doesn't need to send anything.

#Single player and MMO

Nothing changes. In single player the host runs the same Apply. Damage between players only lands where PvP or a duel allows it; that check happens before your effect is called, when targets are gathered.

#Common mistakes

  • Applying a buff on every landing. Multi-hit animations and zones call Apply many times. Guard one-time effects with cast.firstHit.
  • Ignoring cast.scale. A three-hit animation then deals three full hits.
  • Using UnityEngine.Random in Describe. Tooltips must be stable; roll only in Apply.
  • Keeping per-cast state in fields. One effect instance is shared by every cast of that skill, by every player. Store nothing in fields at runtime; use locals, or a dictionary keyed by the fighter in a server-side system.
  • Forgetting Visit. Assets only your effect references may be missing from the database.
  • Renaming the class. Skills store your effect by type name. A rename leaves "missing type" entries that the validator lists. Keep the name, or add [UnityEngine.Scripting.APIUpdating.MovedFrom(...)] with the old name.
  • Calling ServerHeal with a raw number and then the formula again. ServerHeal takes a final amount.
