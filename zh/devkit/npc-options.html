开发套件

NPC 选项

如何给 NPC 添加你自己的按钮：NpcOption 基类、服务器在运行它之前检查什么、如何回应玩家、如何打开你自己的窗口，以及完整的示例。

#NPC 选项是什么

场景中的 Npc 组件有一个选项列表（Npc.options）。玩家与 NPC 交谈时，服务器列出该玩家可以看到的选项，客户端把它们显示为按钮，玩家选择其中一个时由服务器运行它。套件的选项可以打开商店、传送、训练技能、提供任务、运行对话台词、打开银行、市场、公会银行、锻造、邮件、收税官、创建公会和公会大厅，以及触发世界触发器。

新的选项类型就是一个类。NpcOption 是 [Serializable] 的，列表是 [SerializeReference, PickType]，所以你的选项会出现在每个 NPC 的 Options 的 + 菜单中，也会出现在每条对话台词嵌套的 Options 中。

文件放在哪里：Game 程序集。场景把选项保存在 NPC 上，因此两种构建都会加载这个类，不过只有服务器运行它。

#基类

NpcOption 位于 Blunnyn.KitARPG.Net。

#Inspector 字段

字段 作用 默认值
Label（label） 按钮文字。为空时使用 DefaultLabel。 空
Required Level（requiredLevel） 低于这个等级的角色看不到它。 0
Conditions（conditions） 只要有一个条件不满足就隐藏。 无
Show When Locked（showWhenLocked） 以灰色显示并附上原因，而不是隐藏。 关

#可重写的成员

成员 作用 默认值
protected abstract string DefaultLabel { get; } Label 为空时的按钮文字。必须实现。
virtual string LabelFor(PlayerCharacter player) 服务器。 此玩家看到的文字，用于因玩家而异的标签。 Label
virtual bool AvailableTo(PlayerCharacter player) 服务器。 返回 false 时对此玩家隐藏，即使开启了 Show When Locked。 true
virtual KitModule Module 它所属的套件模块。该模块在 KitARPG > Modules 中关闭时，选项消失。 KitModule.None
abstract string Run(Npc npc, PlayerCharacter player) 服务器。 执行它。返回给玩家的错误代码，或 null。必须实现。

#可调用的辅助成员

成员 返回什么
string Label Label 或 DefaultLabel。
string Locked(PlayerCharacter player) 玩家不能选择它的原因（先检查等级，再检查条件），或 null。
bool Offered(PlayerCharacter player) 模块开启、未锁定且 AvailableTo 为真。
bool Listed(PlayerCharacter player) 玩家是否能看到它，无论能否选择。

#服务器在 Run 之前检查什么

拥有者的客户端通过 PlayerInteraction 发出请求。在调用你的 Run 之前，服务器已经：

  1. 确认玩家活着、已加载并且正在与那个 NPC 交谈。
  2. 扣除了每个玩家的请求额度（PlayerInteraction 上的 Max Requests Per Second，maxRequestsPerSecond，10）。
  3. 检查玩家在 NPC 的 Talk Range（talkRange，3 米，再加半米）之内。太远时回应 too_far。
  4. 按屏幕上列表中的索引找到选项，并检查 Offered(player)：模块、等级、条件和 AvailableTo。

因此在 Run 中，你知道玩家就在 NPC 旁边，并且可以选择这个选项。除此之外你的选项需要花费或要求的任何东西，都要在 Run 中再次检查。

#回应玩家

Run 返回一个字符串，作为 PlayerInteraction.ErrorReceived 发送给拥有者的客户端。套件的窗口中只有商店窗口会在打开时显示这些内容，并把已知的代码（NpcErrors.NotEnoughMoney、NpcErrors.TooFar 以及背包错误）转换成句子。

对于普通的对话选项，自己告诉玩家，然后返回 null：

player.ServerAnnounce("Blessed!", new Color(1f, 0.85f, 0.4f));    // floating text over the player
if (player.TryGetComponent(out PlayerChat chat)) chat.Tell("The priest blesses you."); // a system line in the chat
return null;

DialogueOption 对其动作的拒绝原因也是这样处理的。悬赏示例的选项使用 PlayerChat.Tell。

#示例：模板

Create > KitARPG > Scripts > NPC Option 会生成一个花金币治疗的祝福，玩家付不起时会在聊天中告诉他。见模板。

#示例：祝福，在聊天中回应

在模板的基础上，让标签显示价格，用祝福状态代替完全治疗，并在祝福后在聊天中发一行消息：

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class BlessingOption : NpcOption
    {
        public long price = 50;
        public StatusData blessing;
        public float seconds = 300;

        protected override string DefaultLabel => "Bless me";

        public override string LabelFor(PlayerCharacter player) =>
            $"{Label} ({price:N0} {GameInstance.Database.GoldName})";

        public override bool AvailableTo(PlayerCharacter player) => blessing != null;

        public override string Run(Npc npc, PlayerCharacter player)
        {
            var inventory = player.GetComponent<PlayerInventory>();
            if (inventory.gold < price)
            {
                Tell(player, $"That costs {price:N0} {GameInstance.Database.GoldName}.");
                return null;
            }
            inventory.AddGold(-price);
            player.AddStatus(blessing, 1, seconds);
            GameLog.Write("mygame.blessing", player, gold: price, detail: npc.Id);
            Tell(player, $"{npc.displayName} blesses you.");
            return null;
        }

        static void Tell(PlayerCharacter player, string text)
        {
            if (player.TryGetComponent(out PlayerChat chat)) chat.Tell(text);
        }
    }
}

PlayerCharacter.AddStatus 是 IItemUser 的方法；玩家实现了它。

#示例：打开你自己窗口的选项

选项在服务器上运行，所以要在客户端打开窗口，选项需要给拥有者发送一条消息。这个选项打开一个 "stash"（储物箱）窗口，并让窗口知道它来自哪个 NPC。

using System;
using Blunnyn.KitARPG.Net;
using Mirror;
using UnityEngine;

namespace Game
{
    public struct OpenStashMessage : NetworkMessage
    {
        public string npcId;
    }

    [Serializable]
    public class StashOption : NpcOption
    {
        protected override string DefaultLabel => "Open the stash";

        public override string Run(Npc npc, PlayerCharacter player)
        {
            player.connectionToClient?.Send(new OpenStashMessage { npcId = npc.Id });
            return null;
        }
    }

    public static class StashClient
    {
        public static event Action<Npc> Opened;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void ResetStatics() => Opened = null;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Hook()
        {
            KitNetworkManager manager = KitNetworkManager.Instance;
            if (manager == null) return;
            manager.ClientConnected += () => NetworkClient.ReplaceHandler<OpenStashMessage>(OnOpen);
        }

        static void OnOpen(OpenStashMessage message)
        {
            if (Npc.TryFind(message.npcId, out Npc npc)) Opened?.Invoke(npc);
        }
    }
}

你的窗口订阅 StashClient.Opened，打开自己，并在玩家走出 npc.InReach(PlayerCharacter.Local.transform.position) 时自行关闭。窗口发回的每个请求都必须在服务器上再次检查玩家是否在那个 NPC 附近（npc.InReach(player.transform.position)）。见网络消息。

#示例：因玩家而异的标签

悬赏示例的选项会根据玩家显示 "Today's bounty" 或 "Turn in the bounty"：

public override string LabelFor(PlayerCharacter player) =>
    Bounties.Current(player.Facts, out _) != null ? "Turn in the bounty" : "Today's bounty";

#示例：属于某个模块

属于套件某个模块的选项，会在该模块关闭时消失：

public override KitModule Module => KitModule.Guilds;

#选项上的状态

一个选项实例位于一个场景中的一个 NPC 上，与该 NPC 交谈的所有玩家共享它。实例字段只能用于 NPC 的状态，绝不能用于某个玩家的状态。把仅在运行时使用的字段标记为 [NonSerialized]，这样它们不会被存进场景。套件的 ShopOption 就是这样按 NPC 保存有限库存的：

[NonSerialized] int[] left;

对于每个玩家的状态，使用标记、PlayerData 或玩家系统（见保存数据）。

#把选项添加到 NPC

  1. 在场景中选中 NPC（带 Npc 组件的 GameObject）。
  2. 在 Options 中按 +，从菜单中选择你的类。
  3. 填写它的字段、Label、Required Level 和 Conditions。
  4. 在 Dialogue 选项中，嵌套的 Options 列表也接受你的类，因此它可以出现在一句对话之后。

Label 为空的选项使用它们的 DefaultLabel。如果 NPC 没有问候语且只有一个选项，与它交谈时会立即运行这个选项。

#服务器与客户端

运行在
LabelFor、AvailableTo、Locked、Offered、Run 服务器
标签和锁定原因 以文本形式发送到客户端
Npc 组件 两端：客户端用它获取名称、位置和范围

在单人模式中，主机在同一个进程中运行服务器那一半。

#常见错误

  • 从 Run 返回一句话并期望对话框显示它。 使用 ServerAnnounce 或 PlayerChat.Tell。
  • 信任随后打开的窗口。 选项打开的窗口会发送自己的请求；每个请求都必须再次检查范围和规则。
  • 在选项上保存每个玩家的数据。 它被所有与该 NPC 交谈的人共享。
  • 在玩家交谈时改变选项的顺序。 客户端按索引选择；在编辑器中调整顺序，不要在运行时调整。
