开发套件

玩家系统

如何为每个玩家添加你自己的系统：在玩家模型预制体上放一个 NetworkBehaviour，包含同步状态、所有者发送的命令、回复、保存，以及让它在线上保持正确的规则。

#什么时候需要

套件的玩家功能都是玩家预制体上的组件：PlayerInventory、PlayerSkills、PlayerQuests、PlayerProgress、PlayerChat、PlayerGuild、PlayerMail 等等。当你的功能需要以下内容时，添加一个你自己的组件：

  • 其他代码经常读取的状态，在服务器或客户端上（声望值、宠物、制作队列），
  • 界面显示的、或其他玩家能看到的同步值，
  • 来自所有者、有自己规则的请求。

如果你只需要一个请求和一个回答，玩家身上不需要状态，网络消息更轻量，也不用改预制体。如果你只需要保存几个数字，角色标记完全不需要代码。

文件放在哪里：Game 程序集。同一个组件同时在服务器和客户端上运行。

#从模板开始

Create > KitARPG > Scripts > Player System 会生成 PlayerNewSystem。完整代码见模板。它展示了每个玩家系统都有的部分：

部分 用途
[RequireComponent(typeof(PlayerCharacter))] 它只在玩家身上才有意义。
[SyncVar] public int points 由服务器设置、客户端接收的值。
static event Action<int> Changed 值变化时通知所有者的界面。
static PlayerNewSystem Local 本地玩家的那一份，供窗口使用。在 OnStartAuthority 中设置。
SubsystemRegistration 中的 ResetStatics 在不重新加载域的情况下，两次 Play 之间清空静态变量。
OnStartServer 玩家在服务器上生成时加载保存的状态。
public void Earn() => CmdEarn() 窗口调用的客户端方法。
[Command] void CmdEarn() 请求，在服务器上运行。先用 CommandPacing.Allow 消耗连接的额度，再检查一切。
[TargetRpc] void TargetTold(string) 只发给所有者的回答。
OnPointsChanged 钩子 在所有者的客户端上触发 Changed。

#添加到玩家预制体

每个玩家模型都有自己的预制体，列在游戏数据库中（KitARPG > Game Database > Models，字段 GameDatabase.playerModels）。把你的组件添加到每一个预制体上：

  1. 打开 KitARPG > Game Database > Models 并选择一个模型。它的页面链接到它的预制体。
  2. 打开预制体并添加你的组件。
  3. 对每个模型重复以上步骤。

之后用 + New player model 添加的模型会带有套件的系统，但没有你的系统。要自动把你的组件添加到每个模型上，包括以后创建的模型，请发布一个套件更新，在缺少该组件的地方添加它。那一页有完整代码。

警告

Mirror 按组件在对象上的顺序匹配网络组件。客户端和服务器构建中，每个玩家预制体上的 NetworkBehaviour 必须完全相同。绝不要在运行时添加你的组件，也不要只在某一种构建中添加。

#同步状态

工具 送达 用于
字段上的 [SyncVar] 能看到该玩家的客户端（或只有所有者，见下文） 单个值
SyncList<T>、SyncDictionary<K,V>、SyncHashSet<T>（作为 readonly 字段） 同上 集合
[TargetRpc] 只有所有者 一次性的回答和事件
[ClientRpc] 每个能看到该玩家的客户端 其他人必须看到的效果

每个 NetworkBehaviour 都有一个 Sync Mode（同步模式）：Observers（每个能看到该玩家的人都会收到这些值）或 Owner（只有所有者收到）。套件的私有系统（PlayerQuests、PlayerProgress、PlayerInventory 的背包内容）在 Reset() 中设置为 Owner：

void Reset() => syncMode = SyncMode.Owner;

Reset 在你于编辑器中添加组件时运行。任何其他玩家不应读取的数据都选 Owner：被篡改的客户端能读取它收到的每一个值。

谁能看到某个玩家由套件的兴趣管理（空间网格）决定。远处的玩家，或在地下城另一个副本中的玩家，不会收到你的值或 [ClientRpc]。

#命令：所有者发出请求

[Command] 在服务器上运行，并且知道调用者的身份：只有所有者的客户端能对自己的玩家调用命令。在命令内部：

  1. 从连接的配额中扣除。CommandPacing.Allow(connectionToClient) 给每个连接每秒 30 个命令、突发 60 个，由所有组件共享，并断开刷屏的连接。对于最终会变成 Central 工作的命令，使用 CommandPacing.AllowCentral（每秒 2 个，突发 10 个）。
  2. **校验每个参数。**长度、范围、有限的数字、数据库中存在的 id。
  3. **检查玩家的状态。**活着、已加载（player.State != null）、不忙、在其操作对象的范围内。
  4. **通过套件的系统修改状态。**物品和金币通过 PlayerInventory，标记通过 PlayerProgress，任务通过 PlayerQuests。

#完整示例：声望

每个阵营一个声望值，通过击杀获得，在窗口中显示，在 NPC 处消耗。它通过 IPlayerSave 用 PlayerData 保存自己，并且只同步给所有者。

using System;
using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using Blunnyn.KitARPG.Shared.Characters;
using Mirror;
using UnityEngine;

namespace Game
{
    [RequireComponent(typeof(PlayerCharacter))]
    public class PlayerReputation : NetworkBehaviour, IPlayerSave
    {
        const string Key = "mygame.reputation";
        public const int Max = 100000;

        [Serializable]
        class Saved
        {
            public List<string> factions = new List<string>();
            public List<int> values = new List<int>();
        }

        /// <summary>Faction id to reputation. Owner only.</summary>
        public readonly SyncDictionary<string, int> standing = new SyncDictionary<string, int>();

        /// <summary>Owner's client: something changed.</summary>
        public event Action Changed;

        /// <summary>Owner's client: a message for the reputation window.</summary>
        public static event Action<string> Told;

        public static PlayerReputation Local { get; private set; }

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void ResetStatics()
        {
            Local = null;
            Told = null;
        }

        void Reset() => syncMode = SyncMode.Owner;

        PlayerCharacter player;

        protected virtual void Awake()
        {
            player = GetComponent<PlayerCharacter>();
            standing.OnChange += (_, __, ___) => Changed?.Invoke();
        }

        public override void OnStartAuthority() => Local = this;

        public override void OnStopAuthority()
        {
            if (Local == this) Local = null;
        }

        public int Of(string faction) => standing.TryGetValue(faction, out int v) ? v : 0;

        // Saving: loaded as the character enters a map, written before every save.

        public void ServerLoad(PlayerCharacter owner, CharacterState state)
        {
            standing.Clear();
            Saved saved = PlayerData.Get<Saved>(owner, Key);
            for (int i = 0; i < saved.factions.Count && i < saved.values.Count; i++)
                standing[saved.factions[i]] = saved.values[i];
        }

        public void WriteTo(PlayerCharacter owner, CharacterState state)
        {
            var saved = new Saved();
            foreach (KeyValuePair<string, int> pair in standing)
            {
                saved.factions.Add(pair.Key);
                saved.values.Add(pair.Value);
            }
            PlayerData.Set(owner, Key, saved);
        }

        /// <summary>Server only. Called by your own rules, never from a client's word.</summary>
        [Server]
        public void ServerAdd(string faction, int amount)
        {
            if (string.IsNullOrEmpty(faction) || amount == 0) return;
            standing[faction] = Mathf.Clamp(Of(faction) + amount, -Max, Max);
        }

        // Spending: the owner asks, the server checks everything.

        public void Spend(string npcId, string faction, int amount) => CmdSpend(npcId, faction, amount);

        [Command]
        void CmdSpend(string npcId, string faction, int amount)
        {
            if (!CommandPacing.Allow(connectionToClient)) return;
            if (player.State == null || player.IsDead) return;
            if (string.IsNullOrEmpty(faction) || faction.Length > 32 || amount <= 0 || amount > Max) return;
            if (!Npc.TryFind(npcId, out Npc npc) || !npc.InReach(transform.position)) return;
            if (Of(faction) < amount)
            {
                TargetTold("Not enough reputation.");
                return;
            }
            standing[faction] = Of(faction) - amount;
            GameLog.Write("mygame.reputation_spent", player, amount: amount, detail: $"{faction} at {npc.Id}");
            TargetTold($"Spent {amount} reputation with {faction}.");
        }

        // Runs on the owner's client: hand it to the interface.
        [TargetRpc]
        void TargetTold(string text) => Told?.Invoke(text);
    }
}

你自己的窗口订阅 PlayerReputation.Told 和 PlayerReputation.Local.Changed，并在按钮中调用 PlayerReputation.Local.Spend(...)。

获得声望的服务器规则可以放在 Game 程序集中的任何地方：

public static class ReputationRules
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
    static void Hook()
    {
        Monster.ServerKilled -= OnKilled;
        Monster.ServerKilled += OnKilled;
    }

    static void OnKilled(Monster monster, PlayerCharacter killer)
    {
        if (killer == null || monster.Data == null) return;
        if (killer.TryGetComponent(out PlayerReputation reputation)) reputation.ServerAdd("forest_wardens", 5);
    }
}

#加载和保存

方式 如何加载 何时保存 客户端能否看到
角色标记（PlayerProgress.SetFlag、IPlayerActor.SetFlag） 随角色加载，在生成之前 随角色保存 所有者，已同步
带 IPlayerSave 的 PlayerData 你的 ServerLoad，在生成之前 你的 WriteTo，在每次保存之前 永远看不到；需要的部分自行同步

角色进入时地图服务器上的顺序：

  1. 实例化玩家预制体。
  2. PlayerCharacter.ServerSetup 加载套件的系统（背包、银行、技能、带标记的进度、任务），然后对每个 IPlayerSave 组件调用 ServerLoad。
  3. 生成玩家：每个组件上运行 OnStartServer，然后触发 PlayerCharacter.ServerSpawned。

所以 OnStartServer 可以读取标记，模板就是这样做的。在 ServerLoad 中对象还没有生成：isServer 仍为 false，所以 PlayerData.Set 会拒绝写入，[Server] 方法在那里会记录一条警告。在 ServerLoad 中读取；稍后再写入。

保存发生在每隔 Save Interval Seconds（saveIntervalSeconds，地图服务器上为 60）、玩家离开或切换地图时，以及服务器停止时。参见保存数据。

#用模块关闭你的系统

GameInstance.Has(KitModule.X) 告诉你套件的某个模块是否开启。对于你自己的开关，在你的某个资源中添加一个字段，并在每个命令中于服务器上检查它。绝不要改为移除组件：预制体在每种构建中都必须保留相同的网络组件。

#覆写而不是添加

要修改套件的某个玩家系统而不是添加新系统，请继承它并在预制体上替换该组件。参见重写套件的行为。

#服务器和客户端

服务器 所有者的客户端 其他客户端
[Command] 方法体 运行 调用它 否
[TargetRpc] 方法体 调用它 运行 否
[ClientRpc] 方法体 调用它 运行 如果能看到该玩家则运行
[SyncVar]（Observers） 设置 接收 接收
[SyncVar]（Owner） 设置 接收 否
OnStartServer、IPlayerSave 运行 否 否
OnStartAuthority、OnStartLocalPlayer 否 运行 否

在单人模式中，主机同时是服务器和所有者：命令在同一进程中运行，CommandPacing 放行主机自己的连接，OnStartServer 和 OnStartAuthority 都在同一个对象上运行。

#常见错误

  • **[Command] 中没有 CommandPacing。**被修改的客户端可以每秒调用它数千次。
  • **因为发送参数的按钮被隐藏就信任该参数。**客户端可以发送任何东西。
  • **客户端和服务器构建中的组件不同。**Mirror 会读错组件，连接中断。
  • **静态变量没有重置。**上一次 Play 留下的 Local 指向一个已销毁的对象。参见不重新加载域的 Play。
  • **私有数据使用 Observers 同步模式。**附近的每个客户端都会收到它。
  • **在 ServerLoad 中写入 PlayerData。**玩家还没有生成；写入会被拒绝。
