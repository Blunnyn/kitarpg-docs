开发套件

公式

如何在不改动套件的情况下修改游戏的数值计算：负责伤害、治疗、攻击速度和经验的 CombatFormula，以及负责职业、等级、属性和装备如何累加成各项数值的 StatFormula。

#公式如何安装

套件在 GameInstance 上保存两个公式对象：

属性 类型 决定什么
GameInstance.Combat CombatFormula 伤害、持续伤害的每跳、治疗、两次攻击之间的时间、每次击杀获得的经验
GameInstance.Formula StatFormula 数值表、每级获得的属性点和技能点

两者都是 KitARPG.Data 中带 virtual 方法的普通 C# 类。要修改某条规则，继承其中一个，重写你需要的方法，并在启动时赋值一个实例：

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
static void Install() => GameInstance.Combat = new MyCombatFormula();

套件每次 Play 时会在 SubsystemRegistration 中把自己的公式放回去（见不重新加载域的 Play）。BeforeSceneLoad 在那之后、任何场景之前运行，因此在你的公式就位之前不会发生任何战斗。

文件放在哪里：Game 程序集，这样每个构建都会安装它。应用公式的是服务器，但客户端也会用到 Combat.Experience：怪物图鉴会显示一只怪物给本地玩家的经验。只放在 Game.Server 中的公式会让图鉴显示的数值与玩家实际获得的不一致。

#CombatFormula

方法 何时调用 返回什么
Hit Attack(StatSheet attacker, IReadOnlyList<ElementDamage> rolls, StatSheet defender, float scale = 1) 玩家和怪物的普通攻击，以及技能上的 DamageEffect 这次命中：总量、是否暴击、主元素
float Element(StatSheet attacker, DamageElement element, float roll, StatSheet defender) 由 Attack 和 Tick 调用，针对每个元素的那一份 该元素经过抗性后的伤害
Hit Tick(StatSheet caster, DamageElement element, float amount, StatSheet holder) 持续伤害状态的每一跳 这一跳的命中，永不暴击，至少为 1
int Heal(StatSheet healer, float amount) HealEffect 和治疗类状态 最终治疗量
float AttackInterval(float attacksPerSecond, StatSheet attacker) 玩家和怪物的每次普通攻击 距离下一次攻击的秒数
long Experience(MonsterData monster, int playerLevel) 一次击杀时，针对击杀者和每个分享经验的队伍成员；怪物图鉴 加成和倍率之前的经验

#套件的规则

  • Attack： 每个伤害骰按其元素单独计算。骰值（在最小值和最大值之间的随机值，乘以 scale）加上攻击者对该元素的伤害，再按攻击者的强度放大。然后减去防御者对该元素的固定抗性，再减去其百分比抗性，百分比抗性上限为该元素的 Max Resistance（maxResistance，骰值没有元素时为 0.5）。各项结果相加。暴击（几率为 critChance）会把总量乘以 1 + critDamage。结果取整，至少为 1。
  • Tick： 使用同样的元素规则，施法者的数值取状态生效那一刻的数值；不会暴击。
  • Heal： (amount + healer.healing) * (1 + healer.healingBonus)，取整。
  • Attack interval： 1 / (attacksPerSecond * (1 + attackSpeed))，至少每秒 0.1 次攻击。
  • Experience： 怪物等级不低于玩家 3 级以内时给全额经验；之后每再低一级少 20%，最低为 10%。

在 Experience 之后，套件会应用玩家的经验获取数值、服务器倍率（experienceRate 以及来自 /rates 的活动）和队伍分享。你的公式只返回基础数量。

#StatSheet

攻击者、防御者和治疗者是什么：

成员 是什么
CharacterStats stats maxHealth、maxMana、healthRegen、manaRegen、power、critChance、critDamage、healing、healingBonus、attackSpeed、moveSpeed、carryWeight、experienceGain、lootChance。比例用小数表示：critChance 为 0.05 即 5%。
ElementStats Element(DamageElement e) 该元素的 damage、resistance 和 resistancePercent。元素为 null 时读取后备元素。
int Attribute(AttributeData a) 某个属性的总值。
DamageElement fallback 游戏的默认元素。

#示例：更严格的等级差

比玩家低 8 级及以上的怪物完全不给经验：

using Blunnyn.KitARPG.Data;
using UnityEngine;

namespace Game
{
    public class MyCombatFormula : CombatFormula
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
        static void Install() => GameInstance.Combat = new MyCombatFormula();

        public override long Experience(MonsterData monster, int playerLevel)
        {
            int gap = playerLevel - monster.level;
            if (gap >= 8) return 0;
            return base.Experience(monster, playerLevel);
        }
    }
}

#示例：由属性提供护甲

根据你游戏中的某个属性（这里 id 为 toughness）提供固定减伤，在百分比抗性之前作用于每种元素：

public class ToughnessFormula : CombatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Combat = new ToughnessFormula();

    AttributeData toughness;

    public override float Element(StatSheet attacker, DamageElement element, float roll, StatSheet defender)
    {
        if (toughness == null) GameInstance.Database.TryGet("toughness", out toughness);
        float damage = base.Element(attacker, element, roll, defender);
        int points = toughness != null ? defender.Attribute(toughness) : 0;
        return Mathf.Max(0, damage - points * 0.5f);
    }
}

toughness 是实例字段：Install 每次 Play 都会创建新的公式，所以即使不重新加载域，缓存的资源每次也从空开始。static 缓存会在 Play 之间保留下来，如果两次 Play 之间换了数据库，就会保留旧的引用；这类静态字段要在 SubsystemRegistration 中重置（参见不重新加载域的 Play）。

#示例：限制暴击几率和攻击速度

using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using UnityEngine;

public class CappedFormula : CombatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Combat = new CappedFormula();

    public override Hit Attack(StatSheet attacker, IReadOnlyList<ElementDamage> rolls, StatSheet defender, float scale = 1)
    {
        // Capped for this attack only, then put back.
        float chance = attacker.stats.critChance;
        attacker.stats.critChance = Mathf.Min(chance, 0.5f);
        try { return base.Attack(attacker, rolls, defender, scale); }
        finally { attacker.stats.critChance = chance; }
    }

    public override float AttackInterval(float attacksPerSecond, StatSheet attacker) =>
        Mathf.Max(0.25f, base.AttackInterval(attacksPerSecond, attacker));
}

stats 是数值表上的一个结构体字段，因此修改在调用基类方法前做出，在调用后撤销。

#StatFormula

方法 何时调用 返回
StatSheet Sheet(CharacterClass characterClass, int level, IReadOnlyList<AttributeAmount> spent, GameDatabase database, IReadOnlyList<IStatSource> sources = null) 每次计算玩家数值时（PlayerCharacter.RecalculateStats：等级、属性、装备或增益发生变化），以及单人模式中的新角色 完整的数值表
int PointsEarned(CharacterClass characterClass, int level) 升级时 到该等级为止获得的属性点
int SkillPointsEarned(CharacterClass characterClass, int level) 技能点总数 到该等级为止获得的技能点

#套件的计算顺序

  1. 职业在该等级的属性，然后是已分配的点数，然后是来自每个来源（装备、增益、被动）的属性加成。
  2. 职业的基础数值加上每级数值乘以 level - 1。
  3. 每个属性的 Per Point 数值乘以该属性的总值。
  4. 每个来源的数值修正。百分比加成最后应用。

点数的默认值是职业的 Points Per Level（pointsPerLevel，5）和 Skill Points Per Level（skillPointsPerLevel，1），乘以 level - 1。

怪物不使用数值公式；它们的数值来自各自的数据。

#示例：每级两个属性点

public class MyStatFormula : StatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Formula = new MyStatFormula();

    // Two attribute points per level instead of the class's own number.
    public override int PointsEarned(CharacterClass characterClass, int level) => 2 * (level - 1);
}

#示例：每级按比例增长的生命值

using System.Collections.Generic;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Shared.Characters;
using UnityEngine;

public class GrowingHealthFormula : StatFormula
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Install() => GameInstance.Formula = new GrowingHealthFormula();

    public override StatSheet Sheet(CharacterClass characterClass, int level, IReadOnlyList<AttributeAmount> spent,
        GameDatabase database, IReadOnlyList<IStatSource> sources = null)
    {
        StatSheet sheet = base.Sheet(characterClass, level, spent, database, sources);
        // +2% max health per level after the first, kept whole.
        sheet.stats.maxHealth = Mathf.Round(sheet.stats.maxHealth * (1 + 0.02f * (level - 1)));
        return sheet;
    }
}

套件中的数值都是整数，百分比加成都是整数点。像上面那样对你加上的部分取整，这样提示框和数值表才会一致。

#示例：每两级一个技能点

public override int SkillPointsEarned(CharacterClass characterClass, int level) => (level - 1) / 2;

#在运营中的游戏上修改规则

公式决定新的数值；它们不会改写已保存的数值。修改 PointsEarned 会改变从现在起获得的点数。角色保留已有的点数：未分配的点数会被保存，每次升级只加上差值。如果你在运营中的游戏上降低每级点数，要给玩家一个重新分配的途径（套件的 ResetAttributesAction 或 Scroll of Second Thoughts）。

#服务器与客户端

服务器 客户端
Attack、Element、Tick、Heal、AttackInterval 是 否
Experience 是 怪物图鉴
Sheet、PointsEarned、SkillPointsEarned 是 否；拥有者收到的是计算好的数值表

在线时，客户端构建中与地图服务器不同的公式只会改变该客户端图鉴显示的内容。单人模式在一个进程中同时运行两部分。

#常见错误

  • 在 SubsystemRegistration 中安装。 套件在那里重置公式；顺序不确定。
  • 只在 Game.Server 中安装。 这样客户端的怪物图鉴会显示套件的数值。
  • 从 Sheet 返回小数。 对你加上的部分取整。
  • 在公式中保存每个战斗者的状态。 一个实例服务于地图上的所有战斗者。
  • 在 Experience 中应用倍率。 套件会在它之后应用经验数值和服务器倍率，这样会被计算两次。
