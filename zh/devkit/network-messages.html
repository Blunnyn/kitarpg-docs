网络消息

如何用 Mirror 网络消息让客户端和服务器通信，而无需在玩家预制体上添加组件：定义消息，在正确的时机注册处理函数，在服务器上校验，以及发送给一名玩家、附近的玩家或所有人。

#消息还是玩家系统

网络消息 玩家系统（NetworkBehaviour）
预制体改动 无 添加到每个玩家模型预制体
同步状态 无；你发送变化的内容 [SyncVar] 和同步集合
谁发送的 服务器上的 conn.identity 组件自己的玩家
适合 请求和回答、通知，以及你想通过删除一个文件夹就能移除的功能 界面一直在读取的状态

悬赏示例使用消息：客户端在生成时请求自己的悬赏，服务器在悬赏变化时发送它。另一种做法参见玩家系统。

文件放在哪里：Game 程序集。两端都需要消息类型和它们的处理函数。

#定义消息

消息是一个实现 Mirror.NetworkMessage 的 struct，带有 Mirror 能写入的类型的公共字段：数字、bool、string、Vector3、枚举、这些类型的数组和列表，以及由它们组成的其他结构体。

using Mirror;

public struct CraftRequest : NetworkMessage
{
    public string recipeId;
    public int amount;
}

public struct CraftResult : NetworkMessage
{
    public bool ok;
    public string text;
}

Mirror 的 weaver 会在编译时于你的程序集中生成读写它们的代码。

#注册处理函数

处理函数在服务器启动时于服务器上注册，在客户端连接时于客户端上注册。KitNetworkManager 为两者都触发事件：

事件 时机
ServerStarted 服务器或主机启动。在单人模式中，主机在每次切换地图时都会重启，所以每次都会再次触发。
ServerStopping 服务器停止之前。
ServerDisconnecting（NetworkConnectionToClient） 某个连接的玩家被销毁之前。
ClientConnected 客户端连接到一张地图。
ClientDisconnected 客户端离开一张地图。

KitNetworkManager.Instance 就是该管理器，位于 Title 场景（客户端和单人模式）和 Server 场景（地图服务器）的 KitNetwork 对象上，这两个场景是游戏启动的起点。它在场景切换中保留下来，所以在 AfterSceneLoad 中挂接，此时第一个场景已经加载了它：

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
static void Hook()
{
    KitNetworkManager manager = KitNetworkManager.Instance;
    if (manager == null) return;
    manager.ServerStarted += () => NetworkServer.ReplaceHandler<CraftRequest>(OnCraft);
    manager.ClientConnected += () => NetworkClient.ReplaceHandler<CraftResult>(OnResult);
}

static void OnResult(CraftResult result) => Debug.Log(result.text);

使用 ReplaceHandler，不要用 RegisterHandler：下一次启动时再次注册同一个处理函数，它不会报错。服务器处理函数只接受来自已认证连接（出示了有效票据的玩家）的消息。

#在服务器上处理请求

static void OnCraft(NetworkConnectionToClient conn, CraftRequest message)
{
    // 1. Spend from this connection's budget; floods get disconnected.
    if (!CommandPacing.Allow(conn)) return;

    // 2. Who sent it comes from the connection, never from the message.
    if (conn.identity == null || !conn.identity.TryGetComponent(out PlayerCharacter player)) return;
    if (player.State == null || player.IsDead) return;

    // 3. Validate every field.
    if (string.IsNullOrEmpty(message.recipeId) || message.recipeId.Length > 64) return;
    if (message.amount < 1 || message.amount > 99) return;
    if (!GameInstance.Database.TryGet(message.recipeId, out RecipeData recipe)) return;

    // 4. Do it through the kit's systems, then answer.
    string why = Crafting.ServerCraft(player, recipe, message.amount);
    conn.Send(new CraftResult { ok = why == null, text = why ?? $"Crafted {recipe.DisplayName}." });
}

（RecipeData 和 Crafting 代表你自己的数据类型和规则。）

这四个步骤适用于每个处理函数：

  1. 限速。CommandPacing.Allow(conn) 让每个连接与游戏中的每个 [Command] 共享同一份配额（每秒 30 个，突发 60 个）。远远超出时，该连接会以 KickReasons.Flooding 被踢出。对于会给 Central 带来工作的请求，使用 CommandPacing.AllowCentral(conn)（每秒 2 个，突发 10 个）。
  2. 身份。conn.identity 是发送消息的那个连接的玩家对象。绝不要在请求中放入角色 id、账号 id 或玩家名字并据此行事。
  3. **校验。**字符串有长度限制，数字有范围且必须是有限值（float.IsFinite），id 必须存在于数据库中，对世界中事物（NPC、怪物、掉落）的引用必须离该玩家很近且对其可见。
  4. **套件系统。**通过 PlayerInventory、IPlayerActor、PlayerQuests 和 PlayerProgress 修改物品、金币和进度。

#指明世界中的事物

要指明一个怪物或玩家，发送它的 netId，并在服务器上用 Fighters.TargetFor 解析，对于该连接不应看到的任何东西（在其视野之外、隐身的敌人、为别人生成的活动怪物），它返回 null：

ICombatant target = Fighters.TargetFor(conn, player, message.targetNetId);
if (target == null) return;

要指明一个 NPC，发送它的 id 并检查距离：

if (!Npc.TryFind(message.npcId, out Npc npc) || !npc.InReach(player.transform.position)) return;

#从服务器发送

发给 方法
一名玩家 player.connectionToClient.Send(message)（或在处理函数中用 conn.Send）
每个能看到某玩家的人 NetworkServer.SendToReadyObservers(player.netIdentity, message)
此地图服务器上的所有人 NetworkServer.SendToAll(message)
每张地图上的所有人 通过 Central：参见与 Central 通信

没有所有者的对象上 connectionToClient 为 null，玩家正在离开时也可能为 null；使用 ?.Send。副本地图（地下城、公会大厅）的各个副本在同一个地图服务器进程中运行，所以 SendToAll 会送达每个副本。要把通知限制在一个副本内，遍历 PlayerCharacter.ServerAll() 并比较 gameObject.scene。

#从客户端发送

public static void Craft(string recipeId, int amount) =>
    NetworkClient.Send(new CraftRequest { recipeId = recipeId, amount = amount });

只在已连接时发送（NetworkClient.isConnected）。在玩家生成之前发送的消息到达时 conn.identity 为 null，上面的处理函数会忽略它们。

#在玩家生成时请求

当 PlayerCharacter.LocalSpawned 触发时，客户端就知道自己的玩家已经存在。悬赏示例在那里请求自己的状态：

PlayerCharacter.LocalSpawned -= AskOnSpawn;
PlayerCharacter.LocalSpawned += AskOnSpawn;

static void AskOnSpawn(PlayerCharacter _) => NetworkClient.Send(new BountyAsk());

#完整示例：世界公告板

玩家阅读一条全服的每日消息，版主用一条 GM 命令修改它。公告保存在地图服务器上。

using Blunnyn.KitARPG.Net;
using Mirror;
using UnityEngine;

namespace Game
{
    public struct NoticeAsk : NetworkMessage { }

    public struct NoticeText : NetworkMessage
    {
        public string text;
    }

    public static class NoticeBoard
    {
        public const int MaxLength = 300;

        /// <summary>Server: the current notice.</summary>
        public static string Current { get; private set; } = "";

        /// <summary>Client: the notice arrived.</summary>
        public static event System.Action<string> Received;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        static void ResetStatics()
        {
            Current = "";
            Received = null;
        }

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        static void Hook()
        {
            PlayerCharacter.LocalSpawned -= AskOnSpawn;
            PlayerCharacter.LocalSpawned += AskOnSpawn;
            KitNetworkManager manager = KitNetworkManager.Instance;
            if (manager == null) return;
            manager.ServerStarted += () => NetworkServer.ReplaceHandler<NoticeAsk>(OnAsk);
            manager.ClientConnected += () => NetworkClient.ReplaceHandler<NoticeText>(OnText);
        }

        static void OnText(NoticeText message) => Received?.Invoke(message.text);

        static void AskOnSpawn(PlayerCharacter _) => NetworkClient.Send(new NoticeAsk());

        static void OnAsk(NetworkConnectionToClient conn, NoticeAsk _)
        {
            if (!CommandPacing.Allow(conn) || conn.identity == null) return;
            conn.Send(new NoticeText { text = Current });
        }

        /// <summary>Server only. Sets the notice and shows it to everyone on this map server.</summary>
        public static void ServerSet(string text)
        {
            Current = PlayerText.Clean(text ?? "", MaxLength);
            NetworkServer.SendToAll(new NoticeText { text = Current });
        }
    }
}

Hook 遵循不重新加载域的 Play：静态事件 PlayerCharacter.LocalSpawned 先 -= 再 +=，并放在检查网络管理器之前，这样即使场景中没有网络管理器也会订阅。网络管理器自己的事件不需要 -=：每次 Play 都会重新创建网络管理器，旧的会连同它的订阅者一起消失。

GM 命令，在 Game.Server 程序集中：

GmCommands.Register(new GmCommand
{
    name = "notice", rank = GmRank.Moderator, usage = "notice text", description = "Sets the notice board.",
    run = c =>
    {
        NoticeBoard.ServerSet(c.rest);
        return "Notice set.";
    },
});

PlayerText.Clean 会修剪文本、移除控制字符、按长度截断并破坏富文本标签，因此公告无法向其他玩家的屏幕注入 TextMeshPro 标记。要一次在每张地图上设置它，请通过 Central 发送（参见与 Central 通信）。

#网络版本

套件会对项目中的每个网络消息和同步字段计算哈希，包括你的（NetworkVersion）。客户端随票据发送该哈希，由不同代码构建的地图服务器会以 version_mismatch 拒绝它。添加或修改消息之后，要同时重新构建客户端和地图服务器。在编辑器中，该值根据当前代码计算，所以 Play 总是与自身匹配。

#单人模式和 MMO

消息在两者中的工作方式相同。在单人模式中，客户端和主机在同一个进程中运行：NetworkClient.Send 通过本地连接送达主机的处理函数，CommandPacing 从不限制本地连接。由于主机在每次切换地图时都会重启，从 ServerStarted 注册的处理函数每次都会再注册一遍，这就是使用 ReplaceHandler 的原因。

#常见错误

  • **信任消息中的 id。**玩家发送自己的名字或 id，服务器却替别人行事。使用 conn.identity。
  • **没有限速。**客户端能触发的每个处理函数都必须调用 CommandPacing.Allow。
  • **只在启动时注册一次。**单人模式的主机会重启；在 ServerStarted 和 ClientConnected 中注册。
  • 把私有数据发送给观察者。SendToReadyObservers 会送达附近的每个人。
  • **不设上限的字符串和数组。**在使用之前，以及在存储或转发之前检查长度。
  • 修改消息后忘记重新构建地图服务器。
