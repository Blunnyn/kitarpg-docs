代码中的物品效果

如何为消耗品编写你自己的效果：ItemEffect 基类、与它配合的 IItemUser 接口、服务器上使用物品的流程，以及完整的示例。

#物品效果是什么

消耗品（ConsumableData：药水、卷轴、食物）先用自己的字段恢复生命和法力，然后运行一个效果列表（ConsumableData.effects）。套件自带的效果包括：经验、等级、学习技能、属性点和技能点、重置属性、施放技能、添加状态和传送。物品要做的其他任何事情都是一个新的效果类。

效果是 [Serializable] 类，通过 [SerializeReference, PickType] 以引用方式保存。你的效果编译通过后，就会出现在 KitARPG > Game Database > Items 中每个 Consumable 的 Effects 的 + 类型菜单里。

文件放在哪里：Game 程序集。客户端上的提示框也会读取效果。

#基类

ItemEffect 位于 Blunnyn.KitARPG.Data。

成员 作用 默认值
string Summary 物品编辑器中的短文本，也是默认的提示框行。 类名
string Check(IItemUser user) 服务器。 此用户现在不能使用它的原因，或 null。在任何效果运行之前，会先检查物品的每个效果。 null
void Use(IItemUser user, ItemData item) 服务器。 执行效果。item 是被使用的物品，以便之后失败时退还。必须实现。
void Describe(ItemDescription description, IItemUser viewer) 物品提示框中的行。viewer 可能为 null（编辑器中的提示框，或其他玩家物品的提示框）。 添加 Summary
void Visit(Action<GameData> visit) 把效果引用的每个资源交给游戏数据库。 什么都不做

#玩家使用物品时发生什么

  1. 拥有者的客户端发出请求（PlayerInventory.Use(slot)，来自背包、物品菜单或快捷栏格子）。
  2. 在服务器上，PlayerInventory 检查自己的请求频率、该格子里有物品，并且物品可以使用（IUsable）。
  3. 它检查物品 Cooldown Group（cooldownGroup，默认 potion）的冷却时间。
  4. 它调用 ConsumableData.CheckUse(player)：死亡的玩家不能使用物品，然后按顺序运行每个效果的 Check，第一个非 null 的结果会中止一切。这个结果显示在玩家头顶上。
  5. 没有效果的消耗品只有在能恢复某些东西时才能使用。
  6. ConsumableData.Use 恢复生命和法力，然后按顺序调用每个效果的 Use。
  7. 冷却开始，并从该堆叠中扣除一个物品。

因为所有 Check 都在任何 Use 之前运行，带三个效果的物品要么三个都生效，要么一个都不生效。把所有拒绝的理由都放在 Check 中。一旦 Use 运行，物品就已经消耗了。

#IItemUser

物品眼中的玩家。在服务器上它是 PlayerCharacter；在客户端上，提示框拿到的是本地玩家。

成员 作用 在哪里
CharacterClass Class、int Level 职业和等级。 两端
IReadOnlyList<string> WornItemIds 每个装备位置上的物品 id，没有穿戴时为空。 两端
bool IsDead、int Health、int MaxHealth、int Mana、int MaxMana 当前状态。 两端
void RestoreHealth(int)、void RestoreMana(int) 恢复。 服务器
long ExperienceToNext 还需要的经验，最高等级时为 0。 两端
void GainExperience(long) 增加经验，包括升级。 服务器
void GainLevel() 升一级，就像获得了所需经验一样。 服务器
void GainPoints(int attributePoints, int skillPoints) 增加可分配的点数。 服务器
int SpentAttributePoints 到目前为止已分配的点数。 两端
void ResetAttributes() 退还所有已分配的属性点。 服务器
string CanLearnSkill(SkillData, int rank)、void LearnSkill(SkillData, int rank) 按技能自身的规则学习技能。 检查在两端，学习在服务器
string CanCastFromItem(SkillData)、void CastFromItem(SkillData, int rank) 不需要学会就能施放技能，不消耗法力，也没有冷却。 检查在两端，施放在服务器
void AddStatus(StatusData, int level, float seconds) 添加状态。 服务器
void TravelTo(MapData, Vector3, ItemData refund) 把玩家送到某张地图；传送失败时退还 refund。 服务器

接口上没有的东西，把它转换为 PlayerCharacter（命名空间 Blunnyn.KitARPG.Net）并使用它的组件。Game 程序集引用了 KitARPG.Net，所以这样可行：

if (!(user is PlayerCharacter player)) return;
var inventory = player.GetComponent<PlayerInventory>();

Create > KitARPG > Scripts > Item Effect 会生成一个经验效果。见模板。

#示例：金币袋

打开后得到随机数量的金币。钱包已满时无法打开（Check 以 "Your purse is full" 拒绝）；钱包还有空间但放不下全部时，ServerReceiveGold 把剩下的送进银行。

using System;
using Blunnyn.KitARPG.Data;
using Blunnyn.KitARPG.Net;
using UnityEngine;

namespace Game
{
    [Serializable]
    public class GoldPouchEffect : ItemEffect
    {
        public int min = 50;
        public int max = 200;

        public override string Summary => $"{min}-{max} gold";

        public override string Check(IItemUser user)
        {
            if (!(user is PlayerCharacter player) || !player.TryGetComponent(out PlayerInventory inventory)) return "Nothing happens";
            return inventory.GoldRoom <= 0 ? "Your purse is full" : null;
        }

        public override void Use(IItemUser user, ItemData item)
        {
            var player = (PlayerCharacter)user;
            int amount = UnityEngine.Random.Range(min, max + 1);
            player.GetComponent<PlayerInventory>().ServerReceiveGold(amount);
            player.ServerAnnounce($"+{amount:N0} {GameInstance.Database.GoldName}", new Color(1f, 0.85f, 0.3f));
            GameLog.Write("mygame.gold_pouch", player, itemId: item.Id, gold: amount);
        }

        public override void Describe(ItemDescription description, IItemUser viewer) =>
            description.Add($"Holds {min:N0} to {max:N0} {GameInstance.Database?.GoldName ?? "Gold"}", ItemDescription.Kind.Effect);
    }
}

Check 和 Use 在服务器上运行，所以在那里做类型转换是安全的。Describe 从不转换 viewer：它可能为 null。

#示例：回城

把玩家送到游戏的起始地图。如果传送失败，卷轴会退还。

[Serializable]
public class RecallEffect : ItemEffect
{
    public override string Summary => "Recall to town";

    public override string Check(IItemUser user)
    {
        MapData town = GameInstance.Database != null ? GameInstance.Database.startMap : null;
        return town == null ? "Leads nowhere" : null;
    }

    public override void Use(IItemUser user, ItemData item)
    {
        MapData town = GameInstance.Database.startMap;
        user.TravelTo(town, town.startPosition, item);
    }

    public override void Describe(ItemDescription description, IItemUser viewer) =>
        description.Add("Takes you back to town", ItemDescription.Kind.Effect);
}

套件的 TravelItemEffect 做的是同样的事，只是地图和位置固定，在 Inspector 中设置。

#示例：一箱物品

打开后给予列表中的每个物品；只要有一项放不进背包，就无法使用。IPlayerActor（动作眼中的玩家）有 RoomFor 和 GiveItem；从 PlayerCharacter.Facts 获取它。

[Serializable]
public class BoxEffect : ItemEffect
{
    [Serializable]
    public struct Entry
    {
        public ItemData item;
        public int amount;
    }

    public Entry[] contents = new Entry[0];

    public override string Summary => $"Box of {contents.Length}";

    public override string Check(IItemUser user)
    {
        if (!(user is PlayerCharacter player)) return "Nothing happens";
        foreach (Entry e in contents)
        {
            if (e.item == null) continue;
            string why = player.Facts.RoomFor(e.item, Mathf.Max(1, e.amount));
            if (why != null) return why;
        }
        return null;
    }

    public override void Use(IItemUser user, ItemData item)
    {
        IPlayerActor actor = ((PlayerCharacter)user).Facts;
        foreach (Entry e in contents)
            if (e.item != null) actor.GiveItem(e.item, Mathf.Max(1, e.amount));
    }

    public override void Describe(ItemDescription description, IItemUser viewer)
    {
        foreach (Entry e in contents)
            if (e.item != null) description.Add($"{e.item.DisplayName} x{Mathf.Max(1, e.amount)}", ItemDescription.Kind.Effect, e.item.Icon);
    }

    public override void Visit(Action<GameData> visit)
    {
        foreach (Entry e in contents) visit(e.item);
    }
}

RoomFor 针对当前背包单独检查每一项。几项单独都放得下，合在一起却可能放不下；要精确检查，用 PlayerInventory.ServerRoomFor 测试整个列表，或者用 GiveOrBank 给予，这样永远不会丢失任何东西（见背包与银行）。

#提示框

Describe 构建提示框的行。ItemDescription.Add(text, kind, icon) 添加一行；类型有：

类型 用于
Normal 普通文本。
Heading 小节标题。
Effect 物品的作用。
Muted 次要信息，例如查看者已满足的需求。
Warning 查看者未满足的需求。

用 viewer 给需求上色：本地玩家不能使用时用 Warning，能使用时用 Muted。始终处理 viewer == null 的情况。

#服务器与客户端

运行在
Check、Use 服务器。客户端从不决定物品是否生效。
Describe、Summary 客户端（提示框）和编辑器。

在单人模式中，两端在同一台机器上运行同样的代码。

#其他类型的可使用物品

效果针对的是消耗品。要做一种全新的物品，继承 ItemData（或 ConsumableData）并实现适用的接口（IUsable、IConsumable、IEquippable）。ConsumableData.CheckUse 和 Use 是 virtual 的。要介入每一次物品使用，在 PlayerInventory 的子类中重写 PlayerInventory.UseItem（见重写套件的行为）。

#常见错误

  • 在 Use 中拒绝。 到那时物品已经消耗了。在 Check 中拒绝。
  • 在 Describe 中读取 viewer 而不检查 null。
  • 直接在背包数据上用 Inventory.Add 给予物品。 要通过 PlayerInventory（Give、GiveOrBank、ServerReceive）或 IPlayerActor.GiveItem，这样背包会同步、重量会更新、保存也不会出错。
  • 忘记 Visit 效果引用的物品、状态、地图或技能。
  • 运行时在字段中保存状态。 一个效果实例为所有玩家的该物品的每个副本服务。
