游戏系统

游戏日志与举报

有三个工具帮助你运营游戏并保持公平：游戏日志，记录账号、角色、物品和金币发生的事情；玩家举报，把问题连同周围的聊天内容一起交给管理员；聊天过滤，遮蔽或屏蔽你选择的词。本页介绍每个工具、所有设置，以及它们在单人模式和 MMO 中的工作方式。

#游戏日志

游戏日志是一张表 game_logs，每个事件一行：时间、类型、地图、账号、角色、另一方、物品、数量、金币和详情。它没有外键，所以角色被删除后这些行仍然保留。

#记录的内容

类型 时机
account.created、account.login、account.login_failed、account.resumed 账号创建、登录和带 IP 的登录失败、"Remember me" 登录
character.created、character.deleted 角色创建和删除
session.enter、session.leave 进入和离开世界
item.trade 交易，以及双方各自给出的东西
item.shop_buy、item.shop_sell 在 NPC 商店买卖
item.loot 品质为 Log Loot From 或更高的掉落
item.destroy 被销毁的物品
item.forge 锻造强化、镶嵌和分解
bank.deposit、bank.withdraw 账号银行
guild.bank、guild.created、guild.collector 公会银行、新公会、收税官
mail.sent、mail.taken 发送的信件，以及从信件中取出的物品或金币
market.listed、market.sold、market.cancelled、market.expired 市场
shop.premium_buy、shop.premium_gift、shop.premium_grant、shop.premium_topup、shop.premium_refund 商城和高级货币
combat.death、combat.pvp_kill 死亡和 PvP 击杀
character.level、character.experience_lost 升级和死亡时损失的经验
quest.done 完成的任务
chat.line 每一条聊天消息，仅在开启 Log Chat 时
gm.command、gm.ban GM 命令及其回复、封禁
report.sent、report.closed 玩家举报

类型是自由文本，所以你的游戏可以添加自己的类型（参见代码）。

#设置

在 KitARPG > Game Settings 的 Logs 部分：

字段 作用 默认值
Log Loot From（logLootFrom） 该品质或更高的掉落写入游戏日志 Rare
Log Chat（logChat） 每条聊天消息也写入游戏日志。举报总会附带周围的消息 关

在 Login 和 Central 上（appsettings.json 或环境变量）：

设置 作用 默认值
Logs:Days 早于此天数的行每小时删除一次。0 表示永久保留 180

#日志行如何写入

  • 地图服务器收集它的日志行，每 2 秒发送给 Central。如果 Central 宕机，最多可等待 5,000 行。Central 给每一行标上发送它的地图。
  • Login 和 Central 直接写入它们自己的日志行。
  • 写入从队列中分批进行，与各个请求分开，所以记录日志永远不会拖慢登录或交易。

#查看日志

  • 在游戏中，管理员输入 /logs player [kind] 查看该玩家最近的 15 行，可以只看某一类型。item 包含所有 item.* 类型。GM 面板的 Moderation 标签页以及 Players 中每位玩家的日志按钮作用相同。
  • 在游戏外，用任何 SQL 工具查询 game_logs 表。参见数据库。
SELECT "At", "Kind", "Character", "Other", "ItemId", "Amount", "Gold", "Detail"
FROM game_logs WHERE "Kind" LIKE 'item.%' ORDER BY "At" DESC LIMIT 50;

列为 Id、At（UTC）、Kind、MapId、AccountId、CharacterId、Character、OtherId、Other、ItemId、Amount、Gold 和 Detail。在 PostgreSQL 上，名称需要加双引号，如上所示。

#玩家举报

#玩家视角

  • 右键点击一位玩家（或聊天中对方的名字）并选择 Report。一个对话框询问 "Report name to the moderators?"，并有一个文本框用来填写发生了什么（最多 200 个字符）。
  • 或者输入 /report name reason。

玩家两次举报之间要等待 60 秒，Central 每天最多接受一个账号的 10 次举报。

#举报附带的内容

地图会附上举报者最近看到的 30 条聊天消息，这样管理员不需要记录所有聊天也能看到上下文。举报写入 reports 表，并以 report.sent 写入游戏日志。

#管理员视角

  • 有举报到达时，在线的管理员会收到通知。
  • /reports 列出未处理的举报。
  • /closereport id 将一个举报标记为已处理（日志中为 report.closed）。
  • /logs player [kind] 显示该玩家做了什么。

GM 面板的 Moderation 标签页有同样的功能。参见 GM 工具。

#聊天过滤

聊天过滤会隐藏或屏蔽你列出的词。它在服务器上运行。

#设置

在 KitARPG > Game Settings 的 Chat filter 部分：

字段 作用 默认值
Blocked Words（blockedWords） 任何人都不能说的词，每个条目一个。以 * 结尾时，也会匹配以它开头的内容 空
Blocked Words File（blockedWordsFile） 包含更多词的文本资源，每行一个，用于长列表。以 # 开头的行是注释 空
Chat Filter Mode（chatFilterMode） Mask 用星号隐藏屏蔽词；Block 丢弃整行并告知玩家 Mask

#匹配方式

  • 只匹配完整单词，所以 "class" 不会因 "ass" 被屏蔽。
  • 以 * 结尾的条目也匹配更长的词：dumb* 匹配 "dumbest"。
  • 代替字母的数字和符号会被当作字母读取，所以 d4rn 和 @ss 也会被匹配。
  • 不区分大小写。

#适用范围

  • 所有频道的聊天消息。
  • 邮件标题和正文。
  • 公会公告。
  • 公会名称：含有屏蔽词的名称会被拒绝。

#分步操作：添加词表

  1. 在项目中创建一个文本文件，例如 Assets/Game/BlockedWords.txt，每行一个词，用 # 行写备注。
  2. 在 Game Settings > Chat filter 中，把它拖到 Blocked Words File。
  3. 选择 Chat Filter Mode。
  4. 重新构建地图服务器：过滤在那里运行。

#单人模式与 MMO

单人模式 MMO
游戏日志 在存档文件的 game_logs 表中，保留 90 天 在 Central 的数据库中，保留 Logs:Days
举报、/reports、/logs 不可用 可用
聊天过滤 可用 可用，在地图服务器上

#代码

  • GameLog.Write(kind, player, other, itemId, amount, gold, detail) 从服务器代码添加一行。使用你自己的类型，例如 bounty.claimed。
  • GameLog.Written 对每一行触发，用于把它们同时发送到其他地方。
  • ChatFilter.Mask、ChatFilter.Blocks 和 ChatFilter.Apply 检查任何你允许玩家输入的文本。SocialHub.Filter 在过滤之后运行你自己的聊天规则。

参见事件和安全规则。

#常见错误

  • 过滤漏掉了带后缀的词。 给条目加上 *。
  • 过滤误伤了无辜的词。 删除过短的 * 条目。
  • 掉落从不出现在日志中。 Log Loot From 高于物品的品质。
  • 表变得太大。 降低 Logs:Days，或者保持 Log Chat 关闭。
