游戏系统

商城

商城，即游戏内商店，以高级货币（示例中为 Gems）出售商品，这种货币由账号持有，而不是角色。玩家可以在任何地方按 P 打开商城，浏览分类和横幅，为自己购买或赠送礼物。Shop 服务是一个独立进程，它负责商品目录、余额、每一笔购买以及真实货币支付。本页介绍玩家看到的内容、购买的流程以及服务器检查的内容，还有如何设置带图片和横幅的商品。商城仅在 MMO 中可用。

#玩家视角

按 P 或点击右上角图标栏中的商城按钮。只要游戏内商城模块开启，该按钮就会在联网游戏中显示，PC 和触屏上都有。

#窗口

  • 左侧： 一个搜索框和各个分类。第一个分类 Home 显示所有商品，顶部有横幅。其他每个分类各占一项，名称取自商品的 Category。
  • 顶栏： 排序（Relevance、Newest、Price: low to high、Price: high to low）以及你的余额和货币图标。如果游戏有充值网页，余额旁边的 + 会打开它。
  • 横幅： 在 Home 中，带宽幅图片的商品每 6 秒轮换一次，可以用箭头和圆点切换。点击会打开该商品。
  • 卡片： 每个商品一张，显示它的图片（或其物品的图标）、角上的缎带、名称以及带货币图标的价格。缎带是商品的标签（如 New 或 Sale），没有标签但有结束日期的商品显示 Limited time。

加载时窗口显示 "Loading the shop..."。如果服务器没有商城，显示 "The shop isn't open on this server."；如果服务没有响应，显示 "The shop can't be reached right now. Try again in a moment."。

#商品页面

点击一张卡片打开商品页面：图片、价格、Buy 和 Gift、以物品格子形式显示的内容（悬停查看详情）、描述，以及 "It can be bought once per account." 这类说明。

  • Buy 会询问 "Buy offer for price currency?"，确认后购买。
  • Gift 会要求输入角色名，并将商品送给对方。只有标记为可赠送的商品才能作为礼物，而且你不能送给自己。
  • 达到每账号购买上限的商品显示 Bought。

#购买的物品去哪里

购买的物品和礼物以商城来信的形式送达，地图会在信件到达后立即将物品放入背包。玩家会看到 "subject arrived in your bag."。如果背包和账号银行都没有空间，信件会留在邮件中，并提示玩家一次。游戏设置 Shop Auto Take 可以关闭此功能，这样购买的物品总是留在邮件中。

#购买流程

  1. 客户端向它的地图服务器发出请求。客户端从不与 Shop 服务通信。
  2. 地图用它的商品目录副本检查该商品（是否在售、日期、每账号上限、是否可赠送、是否送给自己），并生成带随机加成的物品副本。
  3. 地图用它的密钥将商品 id 和物品副本发送给 Shop 服务。
  4. Shop 服务按 它自己的价格 扣款，从不使用地图给出的价格，用商品和物品目录检查这些副本，并在一个事务中写入账号账本的扣款和一封带物品的信件。一次只处理一笔购买。
  5. 地图请求 Central 刷新买家（或礼物收件人）的邮箱，并把信件中的物品放入背包。

付款和获得物品是同一次写入，因此失败时绝不会出现扣款未发货或发货未扣款的情况。玩家必须等一笔购买完成后才能进行下一笔（"Wait for the last purchase to go through."）。

每笔购买都会以 shop.premium_buy 或 shop.premium_gift 写入游戏日志。

#余额

余额的每次变动都是 currency_ledger 中的一行（账号、货币、变动、原因、唯一引用）。余额是这些行的总和。唯一引用确保重复的支付、发放或 webhook 只计一次。退款可能使余额变为负数，在余额重新高于价格之前，玩家无法购买。

#获得高级货币

来源 方式
游戏 任何给予高级货币的奖励（任务奖励、Give Currency 动作）都会通过 Shop 服务发放到账号。在示例中，Welcome 任务给 20 gems，国王的任务给 100
GM /currency gems 100 Name，对离线角色也有效。参见 GM 工具
真实货币 来自 Stripe 或你自己网店的支付 webhook，产品列在商品目录中。参见 Shop 服务

#设置

#1. 高级货币

在 Game Database（Currencies）中为某种货币勾选 Premium（premium）。高级货币由账号持有，记在只有服务器能写入的账本中。示例中有 Gems。如果你的项目没有，Shop 页面会提供一个添加 Gems 的套件更新。参见货币。

玩家预制体需要 PlayerShop 组件。套件更新 Shop on the player prefabs 会为旧项目添加它。

#2. 开启并启动服务

打开 KitARPG 窗口的 Shop 页面（KitARPG > Shop）：

  1. 打开 In the game 下的开关。它会开启游戏内商城模块和启动器设置中的商城。
  2. 在 On this computer 下按 Start the shop。它会在需要时构建服务，并以启动器的 --shop-only 模式启动它。

每个按钮的详细说明见 Shop 页面。

#3. 商品

每个商品有：

字段 作用 默认值
Id（id） 一旦有玩家购买就不能再改。最多 64 个字符，唯一 空
Name（name） 显示在卡片和页面上 空
Description（description） 显示在页面上 空
Category（category） 每个分类在商城左侧占一项 Featured
Icon（icon） 卡片没有图片时显示其图标的物品。留空则用第一个物品的 空
Currency（currency） 所需货币的 id 空
Price（price） 大于 0 0
Items（items） 它给予的物品 id 和数量。至少一个 空
Starts At、Ends At（startsAt、endsAt） UTC，ISO 8601（2026-12-01T00:00:00Z）。留空表示一直有效 空
Per Account（perAccount） 一个账号可购买的次数。0 表示不限 0
Giftable（giftable） 可以作为礼物赠送 开
Hidden（hidden） 保留用于历史记录，但不再出售 关
Badge（badge） 卡片上的缎带，如 New 或 Sale。最多 24 个字符 空
Order（order） 按相关度排序时，数值小的排在前面 0
Picture（image） 卡片和页面图片在游戏 Shop Art 中的键 空
Banner（banner） 宽幅图片的键；有宽幅图片的商品会在横幅中轮换 空

#4. 图片和横幅

商品目录在 Shop 服务中是文本，所以无法保存精灵图。图片存放在游戏中的 Shop Art 资源（ShopArt，Create > KitARPG > Shop Art）里，是一个由键和精灵组成的列表。商品通过键来引用图片。

字段 作用 默认值
Shop Art（shopArt），Game Settings > Shop 游戏使用的 Shop Art 资源 示例：ShopArt
Pictures（pictures），在资源上 键和精灵对 空

在 Shop 页面中，为商品的 Picture 或 Banner 选择任意精灵：页面会以精灵的名称把它加入 Shop Art，并把该名称写入商品。

示例中有 13 张卡片图片和 3 张横幅，由 Art/Tools/make_shop_art.py 根据物品图标绘制。

警告

图片随游戏构建一起发布。如果商品的键不在玩家的 Shop Art 中，会改为显示物品的图标。在发布使用新图片的商品之前，先构建并发布游戏。

#分步操作：带横幅的限时商品

  1. 画一张卡片图片和一张宽幅横幅，并以精灵导入。
  2. 在 Shop 页面的 Offers 下添加一个商品。给它一个 id（winter_cloak）、名称、描述以及分类 Seasonal。
  3. 将 Currency 设为 gems，设置价格，并添加物品。
  4. 将 Ends At 设为 UTC 的最后时刻，例如 2026-12-31T23:59:59Z。Badge 留空会显示 Limited time，或者写 Sale。
  5. 在 Picture 中选择卡片精灵，在 Banner 中选择宽幅精灵。设 Order 为 0 让它排在最前。
  6. 按 Save。商城在本机运行时，商品立即生效：在 Play 中打开商城即可看到。
  7. 构建游戏客户端，让玩家拥有这些图片。
  8. 对于线上服务器，填写 Online server（地址和管理密钥）并按 Publish to server。发布要么全部成功，要么全部不变：只要有一个商品有问题，就什么都不会改变，页面会列出这些问题。

服务会在商品目录文件变化时自动重新加载，因此商品无需重新构建游戏或重启服务器就能生效。

#Game Settings

在 KitARPG > Game Settings 的 Shop 部分：

字段 作用 默认值
Shop Art（shopArt） 卡片和横幅的图片，通过商品引用的键查找 空（示例：ShopArt）
Shop Top Up Url（shopTopUpUrl） 玩家购买高级货币的页面，通过余额旁的 + 打开。留空则隐藏该按钮 空
Shop Auto Take（shopAutoTake） 购买的物品和礼物到达后直接进入背包。关闭时，或背包已满时，它们留在邮件中 开

窗口本身（HUD 预制体中的 CashShopWindow）上有：Toggle Key（P）、Home Name（"Home"）、Banner Seconds（6）、Badge Color 和 Sale Badge Color（包含 Sale Word，即 "sale" 的标签使用第二种颜色）。

#单人模式与 MMO

单人模式中没有商城：按钮不会出现，P 也没有作用。单人模式中不会保留从任务获得的高级货币。

在 MMO 中，Shop 服务必须与 Login 和 Central 一起运行。地图服务器通过 -shop url -shopKey key，或 KITARPG_SHOP_URL 和 KITARPG_SHOP_KEY 找到它。在编辑器中，Play 使用 Shop 页面启动的商城。端点、密钥、支付和部署参见 Shop 服务。

游戏内商城模块需要 Mail 模块。

#安全

  • 客户端只向它的地图发出请求。Shop 服务的内部 API 和管理 API 不对互联网开放；只有支付 webhook 是公开的。
  • Shop 服务按它自己的商品目录扣款，并验证每个物品副本，因此被修改的地图或客户端无法改变价格或物品。
  • 每个数据库只运行一个 Shop 服务。

参见安全。

#常见错误

  • 没有商城按钮。 游戏是单人模式、游戏内商城模块已关闭，或者地图服务器没有配置 Shop 服务。
  • "The shop isn't open on this server." 地图服务器启动时没有 -shop 或 KITARPG_SHOP_URL。使用 Play & Servers 时，在 In the game 下开启商城。
  • 商品没有出现。 它被隐藏、不在日期范围内、没有物品，或者引用了数据库中没有的物品。服务会记录并跳过有问题的商品；KitARPG > Project Check 会标出 Game Database 中没有的物品和货币。
  • 卡片显示图标而不是图片。 图片的键不在游戏的 Shop Art 中，或者客户端构建比图片旧。
  • 购买的物品不在背包中。 背包和银行都满了。物品留在邮件中。
