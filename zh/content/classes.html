职业

职业决定角色是什么：每级获得的属性和数值、能学习的技能、能抵御的状态、初始物品以及起始地图。本页介绍职业的每个字段、经验表，以及如何一步步创建新职业。

#职业是什么

每个角色恰好有一个职业，在角色创建界面中选择，并以职业 id 的形式随角色保存。职业决定：

  • 角色在每级免费获得的属性点（在玩家分配任何点数之前）。
  • 1 级的基础数值，以及之后每级增加的数值。
  • 玩家每级获得多少属性点和技能点。
  • 角色可以用技能点学习哪些技能、从哪一级开始、最高到哪一等级。
  • 它对哪些状态免疫或有抗性。
  • 新角色开始时拥有的物品，穿在身上或放在背包里。
  • 新角色出现的地图。

职业不列出武器或盔甲。每件武器和装备会说明哪些职业可以使用它（参见装备），因此添加新武器永远不需要修改你的职业。

玩家能选择哪些职业取决于他们选择的外观：每个玩家模型都列出了它可以担任的职业。示例中有四个职业：男性和女性身体可以担任的 Warrior、Hunter 和 Mage，以及只有熊猫身体可以担任的 Monk。

#职业在编辑器中的位置

打开 KitARPG 窗口（KitARPG > Open KitARPG，Ctrl/Cmd+Shift+K）并进入 Game Database。职业位于 Characters 分组下的 Classes。列表显示每个职业的图标、名称和 id；右侧面板显示所选的职业。

你也可以在 Project 窗口中用 Create > KitARPG > Character Class 创建职业资源。这样创建的职业只有在游戏数据库能访问到时才算数：把它列在 Classes 下，或把它添加到某个玩家模型上（数据库会自动从模型中收集职业）。

提示

获得一个好玩的新职业最快的方法是复制现有职业。在 Game Database 中选择该职业并按 Duplicate，或在新建玩家模型向导中使用 + New class 并设置 copy of。

#字段

每个职业还具有所有游戏数据资源都有的四个字段。

字段 作用 默认值
Id（id） 随角色保存并在网络消息中发送。创建资源时由文件名填入（Fire Bolt 变为 fire_bolt），之后永不更改，因此重命名文件是安全的。手动修改它会破坏该职业的所有已保存角色。 来自文件名
Display Name（displayName） 玩家看到的名称。留空则使用文件名。 空
Description（description） 显示在角色创建界面和提示框中。 空
Icon（icon） 显示在列表、创建界面和 Game Database 中。 None

#属性

字段 作用 默认值
Attributes（attributes） 属性和数量对的列表。每个条目在每一级为角色提供该属性的点数，在玩家分配的点数之前计算。 空
Attribute（attribute） 该条目提升的属性。 None
Amount（amount） 一个等级值：Base Value（baseValue）是 1 级时的数量，Per Level（perLevel）在第一级之后每级增加。结果四舍五入为整数点数。 0, 0

等级值在整个套件中的计算方式始终相同：等级 L 时的值 = baseValue + perLevel × (L − 1)。

例如，示例中的 Warrior 的 Strength 基础值为 8，每级 2。10 级时仅职业就提供 8 + 2 × 9 = 26 点 Strength。Agility 基础 4、每级 1，10 级时为 13。Intelligence 基础 2、每级 0.5，结果为 6.5，四舍五入为 7。

#数值

字段 作用 默认值
Base Stats（baseStats） 职业在 1 级时的数值，在属性、装备和增益之前。这里可以设置每个数值。 Max Health 80、Max Mana 30、Move Speed 3.5、Crit Damage 0.5（50%），其余为 0
Stats Per Level（statsPerLevel） 第一级之后每级加到基础数值上。 Max Health 12、Max Mana 4，其余为 0

基础数值是唯一可以保留小数的地方：3.7 米每秒的步行速度没有问题。来自属性、装备、套装、宝石和状态的每项加成都以整数和整数百分比计算（参见整数）。

百分比数值在基础数值中写成小数：critChance = 0.05 是 5%，critDamage = 0.5 是暴击时 +50% 伤害。

#每级点数

字段 作用 默认值
Points Per Level（pointsPerLevel） 玩家在第一级之后每级获得的属性点，在 Character 窗口（C）中分配。 5
Skill Points Per Level（skillPointsPerLevel） 玩家在第一级之后每级获得的技能点，在 Skills 窗口（K）中分配。该职业在 1 级解锁的技能一开始就以 1 级习得，无需花费点数。 1
Exp Table（expTable） 每级所需的经验。留空则使用游戏数据库的表。 None

点数永远不会以可用总数的形式保存。服务器每次都计算：可用属性点 = 已获得 − 已花费，可用技能点 = 已获得（加上卷轴给予的额外点数）− 已花费。因此如果你以后修改 Points Per Level，现有角色在下次登录时就会得到新的数量。

#技能

字段 作用 默认值
Skills（skills） 该职业可以用技能点学习的技能。 空
Skill（skill） 该技能。 None
Unlock Level（unlockLevel） 1 级技能所需的角色等级。更高的技能等级需要更高的角色等级：技能等级 n 需要 unlockLevel + (n − 1) × levelsPerRank，其中 Levels Per Rank 在技能上设置。 0
Max Level（maxLevel） 该职业能把技能提升到的最高等级。0 使用技能自身的 Max Level。超过技能自身上限的值会被限制为该上限。 0

解锁等级为 1（或 0）的技能对新角色来说一开始就以 1 级习得，无需花费点数。

示例：示例中的 Warrior 在 1 级有 Cleave，3 级 War Cry，5 级 Ground Slam，6 级 Unbreakable，7 级 Shield Wall，9 级 Charge，11 级 Leap Strike。Cleave 的 Levels Per Rank 为 2，因此 Cleave 3 级需要角色等级 1 + 2 × 2 = 5。

角色也可以通过书、卷轴和训练师 NPC 学习不属于其职业的技能。这在技能本身上设置；参见学习职业以外的技能。

#状态防御

字段 作用 默认值
Status Defense（statusDefense） 该职业免疫或持续时间更短的状态。与怪物和状态上的区块相同。参见免疫与抗性。 空

这只会阻挡敌人施加在角色身上的有害状态。来自角色自身或其盟友的增益总会生效。

#初始物品和起始地图

字段 作用 默认值
Start Items（startItems） 该职业的新角色获得的东西。 空
Item（item） 该物品。 None
Amount（amount） 数量。小于 1 的值按 1 计。 0
Equipped（equipped） 创建时直接穿戴，而不是放进背包。只对可以穿戴的物品有效；如果栏位已被占用或角色无法穿戴，它会进入背包。 Off
Start Map（startMap） 新角色出现的地图。留空则使用游戏数据库的 Start Map。 None

带有随机加成的装备会为每份初始物品副本随机取值，因此两名新战士开始时的剑可能略有不同。参见随机加成。

示例：示例中的 Hunter 开始时穿戴着 Longbow 和 Ranger Armor，弹药栏中装有 200 支 Arrows，背包里有 5 瓶 Health Potions 和 3 瓶 Mana Potions。

#经验表

每个职业可以有自己的经验表，也可以共享 Game Database > Settings 中的那个（Exp Table）。用 Create > KitARPG > Experience Table 创建一个。

字段 作用 默认值
Max Level（maxLevel） 等级上限。达到该等级的角色不再升级。 60
First Level（firstLevel） 表使用曲线时，从 1 级升到 2 级所需的经验。 100
Growth（growth） 表使用曲线时，每级所需经验是上一级的多少倍。 1.15
Exp To Next（expToNext） 手动填写的每级到下一级所需经验。索引 0 是 1 级到 2 级。留空则使用曲线。超出列表末尾的等级也使用曲线。 空

使用曲线时，从等级 L 到 L + 1 的经验为 firstLevel × growth^(L − 1)，四舍五入。按默认值：升到 2 级需要 100，升到 3 级需要 115，升到 4 级需要 132，依此类推。

要把曲线的值写入列表以便微调单个等级，在 Inspector 中右键点击经验表资源的标题并选择 Fill table from curve。

#职业如何塑造角色，逐步说明

当服务器计算角色的数值时（登录时、升级时、装备、属性、增益或被动技能变化时），它会这样做：

  1. 取职业在角色当前等级的属性数量。
  2. 加上玩家分配的属性点。
  3. 加上来自装备、套装、宝石、增益和被动技能的属性点。
  4. 加上职业的基础数值，再加上 Stats Per Level × (等级 − 1)。
  5. 对每个属性，加上每个属性点提供的数值。
  6. 加上来自装备、套装、宝石、状态和被动技能的每项固定加成。
  7. 把每项百分比加成作用于总值并四舍五入。

完整的细节及计算示例见数值如何计算。

#创建新职业

本例创建一个 Paladin（圣骑士）：一个以 Vitality 和 Strength 为主、带一些治疗并能抵抗眩晕的近战职业。

  1. 打开 Game Database > Classes 并选择 Warrior。按 Duplicate。副本的 id 来自其新文件名（类似 warrior_1）。由于还没有角色使用它，在 Id 中输入 paladin，在 Display Name 中输入 Paladin。
  2. 写一段 Description，例如 "Holy warrior. Vitality, strength and a few heals."。设置一个 Icon。
  3. 在 Attributes 中，给它 Vitality 基础 8 每级 2、Strength 基础 6 每级 1.5、Intelligence 基础 4 每级 1。移除 Luck 和 Agility，或给它们较小的值。
  4. 在 Base Stats 中，设置 Max Health 100、Max Mana 35、Move Speed 3.4、Crit Damage 0.5。在 Stats Per Level 中，设置 Max Health 15、Max Mana 3。
  5. 让 Points Per Level 保持 5，Skill Points Per Level 保持 1。
  6. 在 Skills 中，保留 1 级的 Cleave 和 7 级的 Shield Wall，并添加 3 级的 Heal 和 6 级的 Divine Shield。如果你希望圣骑士的治疗不如法师，把 Heal 的 Max Level 设为 3。
  7. 在 Status Defense 中，打开 Resistances 并添加一项，Tag 为 control，Percent 为 30：眩晕、定身和沉默在圣骑士身上的持续时间缩短 30%。
  8. 在 Start Items 中，保留装备着的 Sword，把 Knight Armor 换成你想要的，背包中保留 5 瓶 Health Potions。
  9. 把该职业添加到玩家模型上：打开 Models，选择男性或女性身体，并把 Paladin 加入其 Classes。不这样做就没人能选择它。
  10. 要让该职业能用锤类武器使用你的新技能，在 Items > Weapons 中打开每把锤，把 Paladin 加入其 Classes（或让武器的 Classes 保持为空，这样任何职业都能使用）。
  11. 从 Title 场景按 Play 并创建一个角色。该职业会出现在你添加了它的那些身体的职业列表中。
警告

在 Classes 中列出了职业的装备只能被这些职业使用。如果你复制的是 Warrior，Knight 套装仍然只列出 Warrior。把新职业添加到它应该穿戴的每件装备上，或清空该列表。

#单人模式和 MMO

职业数据在两种模式下相同，服务器规则（数值、点数、技能）在 MMO 中运行于地图服务器，在单人模式中运行于游戏内部。

在 MMO 中，角色创建经由 Login 服务完成，而它不运行 Unity。它读取从你的游戏数据库导出的 gamedata.json，其中每个职业包含：id、1 级时的生命值和法力值、起始地图和位置，以及初始物品（已放入背包或已穿戴）。Login 还会检查该职业是否是所选模型提供的职业，并拒绝不是的职业。

  • Play & Servers 每次启动服务时都会导出 gamedata.json，因此在编辑器中这是自动的。
  • 对于构建和 Docker，用 KitARPG > Export Game Data for Services 导出它，它会写在 Login 服务旁边，让镜像携带它。

如果你修改了职业的初始物品或起始地图，而 Login 仍按旧方式创建角色，说明导出已过期。

单人模式中没有 Login 服务：游戏自己根据职业资源创建角色。

#提示

  • 给每个职业一两个明显比其他增长更快的属性。玩家会从这些属性中理解职业。
  • 让 Stats Per Level 保持适中，让属性承担大部分作用。这样分配点数才有意义。
  • 要制作一个在创建时无法选择的职业（例如之后由任务转职而成的职业），不要把它放进任何玩家模型。只要有东西引用它，它就仍存在于数据库中。

#常见错误

  • 职业没有出现在创建界面中。 它不在任何玩家模型的 Classes 中。把它添加到某个模型上。
  • 已保存的角色丢失了职业。 职业 id 被修改了。改回旧的 id。
  • Login 说该职业不被允许。 Login 读取的 gamedata.json 比你的修改更旧。重新导出，或从 Play & Servers 重启服务。
  • 初始物品进了背包而不是被穿上。 该职业无法穿戴它（物品上的 Classes 或 Required Level），或者两个初始物品要占用同一个栏位。
