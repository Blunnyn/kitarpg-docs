服务器与部署

Docker

用 Docker Compose 在一台机器上运行整个在线游戏：PostgreSQL、提供 HTTPS 的 Caddy、Login、Central、每张地图一个容器，以及可选的 Shop。本页介绍 compose 文件中的每个服务、.env 文件、在 VPS 上逐步部署、添加地图以及在其他机器上运行地图服务器、更新和日常命令。

#Deploy 文件夹里有什么

Deploy 文件夹位于你的 Unity 项目文件夹和 Services 文件夹旁边。compose 文件从 Deploy 的上一级文件夹构建服务镜像，所以它要求以下布局：

<your folder>/
  Deploy/            docker-compose.yml, .env, Caddyfile, Dockerfiles
    builds/starter/  the Linux map server build
    modules/login/   Login modules (optional)
    modules/central/ Central modules (optional)
    shop/            the Shop's catalog file (with the shop profile)
  Services/          the .NET services
  Unity/             your Unity project (the shared code in Assets/Blunnyn/KitARPG/Runtime/Shared)
文件 是什么
docker-compose.yml 整套服务
.env.example 这套服务所需的每个变量，带示例值。把它复制为 .env
Caddyfile Caddy 的路由：Login、Central 和 Shop 的 webhook 的 HTTPS
Services.Dockerfile 从 .NET 10 SDK 镜像构建 Login、Central 或 Shop（--build-arg SERVICE=Login），放入 ASP.NET 10 运行时镜像，以非 root 用户在端口 8080 上运行
MapServer.Dockerfile 把 Linux 地图服务器构建打包进 Ubuntu 24.04 镜像，以用户 kit（uid 1001）运行，参数为 -batchmode -nographics -logFile -
注意

Services.Dockerfile 从 Deploy 的上一级文件夹复制 Services/ 和 Unity/Assets/Blunnyn/KitARPG/Runtime/Shared/。如果你的 Unity 项目文件夹是别的名字，请相应修改那一行 COPY。

#compose 文件中的服务

服务 镜像 主机上的端口 卷 说明
caddy caddy:2.10-alpine 80/tcp、443/tcp、443/udp Caddyfile（只读）、caddy-data、caddy-config 获取并续期 TLS 证书。在 compose 网络中的固定地址为 KITARPG_PROXY_ADDRESS
postgres postgres:17-alpine 无 pgdata 数据库 kitarpg，用户 kitarpg，密码 POSTGRES_PASSWORD。用 pg_isready 做健康检查
login kitarpg/login 127.0.0.1:5100 → 8080 modules/login（只读） 等待 PostgreSQL 健康后启动
central kitarpg/central 127.0.0.1:5200 → 8080 modules/central（只读） 地图链路（UDP 7700）只在 compose 网络内
shop kitarpg/shop 127.0.0.1:5300 → 5300 shop 文件夹 仅在使用 --profile shop 时
map-town kitarpg/map-server 7777/udp 无 -map town -port 7777 -central central:7700
map-forest kitarpg/map-server 7778/udp 无 -map forest -port 7778
map-crypt kitarpg/map-server 7779/udp 无 -map crypt -port 7779
map-guild-hall kitarpg/map-server 7780/udp 无 -map guild_hall -port 7780

地图镜像为 linux/amd64 构建。四个地图服务共用一个由 builds/starter 构建的镜像；只有它们的命令不同。

compose 文件为各服务设置的内容：

  • Login 和 Central： Database__Provider=Postgres、带 POSTGRES_PASSWORD 的连接字符串、Auth__SigningKey=KITARPG_SIGNING_KEY、Proxy__Enabled=true，以及设为 Caddy 地址的 Proxy__KnownProxies__0。
  • 仅 Central： Central__MapKey=KITARPG_MAP_KEY、设为 compose 网络的 Central__MapNetworks__0，以及没有可执行文件的地图 town 7777、forest 7778、crypt 7779 和 guild_hall 7780（每张地图是独立的容器，所以 Central 只等待它们注册）。
  • 地图： KITARPG_CENTRAL_KEY=KITARPG_MAP_KEY、KITARPG_SHOP_URL=http://shop:5300、KITARPG_SHOP_KEY，以及 -address KITARPG_PUBLIC_ADDRESS。
  • Shop： 数据库、代理设置、ASPNETCORE_URLS=http://+:5300、Shop__CatalogPath=/app/shop/shop-conf.json、KITARPG_SHOP_KEY、Shop__AdminKey，以及 Stripe 和签名 webhook 的密钥。

每个服务都会自动重启（unless-stopped）。

#.env 文件

把 .env.example 复制为 .env 并修改每个值。缺少必需变量时 compose 文件拒绝启动，服务也会拒绝示例值。

变量 是什么 必需
POSTGRES_PASSWORD 数据库密码 是
KITARPG_SIGNING_KEY Login 和 Central 的令牌签名密钥，至少 32 个随机字符 是
KITARPG_MAP_KEY 地图服务器向 Central 出示的密钥，至少 16 个随机字符 是
KITARPG_PUBLIC_ADDRESS 玩家用来连接地图服务器的地址：你服务器的公网 IP 或域名 默认 127.0.0.1（仅本机）
KITARPG_LOGIN_DOMAIN Login 的公开名称，例如 login.mygame.com 默认 login.localhost
KITARPG_CENTRAL_DOMAIN Central 的公开名称，例如 central.mygame.com 默认 central.localhost
KITARPG_NETWORK compose 网络。仅当主机上该子网已被占用时修改 默认 172.28.0.0/24
KITARPG_PROXY_ADDRESS Caddy 在该网络中的固定地址 默认 172.28.0.10
KITARPG_SHOP_KEY 地图服务器发送给 Shop 的密钥，至少 16 个随机字符 使用 shop 配置文件时
KITARPG_SHOP_ADMIN_KEY Shop 管理 API 的密钥，至少 16 个随机字符 使用 shop 配置文件时
KITARPG_STRIPE_WEBHOOK_SECRET Stripe 的 webhook 签名密钥（whsec_...）。为空则关闭 Stripe 否
KITARPG_SHOP_SIGNED_SECRET 与你自己的网上商店共享的密钥。为空则关闭 否

用 openssl rand -hex 32 生成每个密钥。不要把 .env 放进版本控制。

#在你的电脑上试用

在租用服务器之前，你可以在自己的机器上运行这套服务。使用默认的 *.localhost 名称时，Caddy 使用它自己的本地证书颁发机构。

  1. 安装 Docker Desktop。
  2. 在 Unity 中：KitARPG > Export Game Data for Services，然后 KitARPG > Starter > Build Linux Server。
  3. 在 Deploy 中：cp .env.example .env，然后替换三个必需的密钥。
  4. docker compose up --build。
  5. 在编辑器中开始游戏。compose 文件在 127.0.0.1:5100 和 127.0.0.1:5200 上发布 Login 和 Central，正是客户端的默认地址，所以编辑器中的客户端能连上它们。请先在 Play & Servers 中停止服务，否则端口会被占用。

在使用 Apple 芯片的 Mac 上，地图容器以 x86 仿真方式运行：用于试用没有问题，但不适合测量性能。

#在 VPS 上部署

针对带公网 IP 的 Linux VPS（Ubuntu 24.04 或类似系统）的分步说明。

#1. 准备服务器

  1. 租用一台 x86-64 CPU 的 VPS（地图镜像为 linux/amd64 构建）。根据你自己的测量确定规格；见性能。

  2. 按照 Docker 针对你的发行版的指南，安装带 Compose 插件的 Docker Engine。

  3. 在防火墙中只开放以下端口：

    端口 协议 用途
    22 TCP SSH
    80 TCP Caddy（证书和到 HTTPS 的重定向）
    443 TCP 和 UDP Caddy（HTTPS 和 HTTP/3）
    7777 到 7780 UDP 地图服务器（每张地图一个端口）

    不要开放 5100、5200、5300、5432 或 7700。

#2. 配置域名

创建两条指向 VPS IP 的 DNS A 记录，例如 login.mygame.com 和 central.mygame.com。只有在它们能解析之后，Caddy 才能获取证书。

#3. 构建并复制

在你的电脑上：

  1. KitARPG > Export Game Data for Services。

  2. KitARPG > Starter > Build Linux Server。

  3. 把包含 Deploy、Services 和共享代码的文件夹复制到服务器，例如使用 rsync：

    rsync -av --exclude 'bin' --exclude 'obj' --exclude '*.db' \
  Deploy Services Unity/Assets/Blunnyn/KitARPG/Runtime/Shared \
  user@server:/opt/mygame/ --relative

    --relative 标志会保留路径，所以服务器上会得到 /opt/mygame/Unity/Assets/Blunnyn/KitARPG/Runtime/Shared。

#4. 配置

在服务器上的 /opt/mygame/Deploy 中：

cp .env.example .env
nano .env

设置各个密钥，把 KITARPG_PUBLIC_ADDRESS 设为 VPS 的公网 IP（或指向它的域名），并设置两个域名。

#5. 启动

docker compose up --build -d
docker compose ps
docker compose logs -f central

Central 会记录 Map link listening on UDP 7700，然后为每张地图记录 Map town (...) registered at <address>:7777。在服务器本机上检查各服务：

curl http://127.0.0.1:5100/health
curl http://127.0.0.1:5200/api/maps
curl https://login.mygame.com/health

#6. 构建客户端

在 KitARPGSettings 中把 Login Url 设为 https://login.mygame.com，把 Central Url 设为 https://central.mygame.com，然后执行 Build Mac Client 或 Build Windows Client。见构建。

#7. 设置管理员

在游戏中创建你的账号，然后：

docker compose exec postgres psql -U kitarpg -d kitarpg \
  -c "UPDATE accounts SET \"Role\" = 4 WHERE \"Username\" = 'yourname';"

#8. 备份

安排每晚运行 pg_dump，并把文件复制到服务器以外。见数据库。

#Shop

docker compose --profile shop up --build -d
  • 先在 .env 中设置 KITARPG_SHOP_KEY 和 KITARPG_SHOP_ADMIN_KEY；没有真实密钥时 Shop 拒绝启动。
  • 目录文件是 Deploy/shop/shop-conf.json。首次启动时如果它不存在，会把示例复制过去。修改无需重启即可生效。
  • 为了让管理 API 能保存商品，容器的用户（uid 1654）必须能写入该文件夹：sudo chown 1654 shop。挂载的是文件夹而不是文件，因为保存时通过重命名来替换文件。
  • Caddy 只把 Login 域名上的 /api/shop/webhooks/* 转发给 Shop。管理 API 可在服务器本机的 127.0.0.1:5300 上访问。要从编辑器发布目录，打开一个 SSH 隧道（ssh -L 5300:127.0.0.1:5300 user@server），并把 http://127.0.0.1:5300 用作在线服务器地址。

见 Shop 服务。

#模块

把每个 Login 模块放在 Deploy/modules/login 下各自的文件夹中，把每个 Central 模块放在 Deploy/modules/central 下，然后执行 docker compose restart login 或 central。这些文件夹以只读方式挂载。要拒绝你自己模块以外的任何模块，在服务的环境中添加 Modules__Allow__0: MyGame.Central.dll。见服务模块。

#添加地图

  1. 在 Unity 中添加地图（Game Database 及其场景），并重新构建 Linux 服务器。

  2. 在 docker-compose.yml 中复制一个地图块，修改名称、地图 id 和端口：

    map-desert:
  <<: *map
  command: ["-map", "desert", "-port", "7781", "-central", "central:7700", "-address", "${KITARPG_PUBLIC_ADDRESS:-127.0.0.1}"]
  ports:
    - "7781:7781/udp"

  3. 在 central 服务的环境中告诉 Central 这张地图：

    Central__Maps__4__Id: desert
Central__Maps__4__Port: "7781"

  4. 在防火墙中开放 UDP 7781。

  5. docker compose up --build -d。

每个地图 id 只能在一个容器中运行；Central 会拒绝同一 id 的第二次注册。

#添加地图服务器

繁忙的地图可以迁移到它自己的机器上。地图链路（UDP 7700）没有加密，所以这些机器必须共享一个私有网络或 WireGuard 隧道。绝不要在互联网上发布 7700。

在主机器（运行 Central 的机器）上：

  1. 设置私有网络或隧道。假设主机器为 10.8.0.1，地图机器为 10.8.0.2。

  2. 在 central 服务中，只在隧道地址上发布地图链路：

    ports:
  - "127.0.0.1:5200:8080"
  - "10.8.0.1:7700:7700/udp"

  3. 在 compose 网络之外，再允许隧道网络：

    Central__MapNetworks__1: 10.8.0.0/24

  4. 从这台机器上移除那张地图的容器，保留它的 Central__Maps__N 项。

  5. docker compose up -d。

在地图机器上：

  1. 安装 Docker，并复制 Deploy/MapServer.Dockerfile 和 Deploy/builds/starter。

  2. 构建并运行地图：

    docker build -f MapServer.Dockerfile --build-arg BUILD_DIR=builds/starter -t kitarpg/map-server .
docker run -d --restart unless-stopped --name map-forest \
  -e KITARPG_CENTRAL_KEY=<map key> \
  -p 7778:7778/udp kitarpg/map-server \
  -map forest -port 7778 -central 10.8.0.1:7700 -address <this machine's public IP>

  3. 在这台机器的防火墙中开放 UDP 7778。

Central 会记录该地图的注册。如果它记录 Refused a map link from ...: not in Central:MapNetworks，说明隧道网络尚未被允许。

#更新

当你修改了游戏或应用了套件更新时：

  1. 备份数据库。
  2. 重新构建修改过的部分：在 Unity 中执行 Export Game Data for Services 和 Build Linux Server，以及客户端。
  3. 把新文件复制到服务器。
  4. docker compose up --build -d。有新镜像的服务会重启；迁移在启动时运行。
  5. 同时发布新客户端：由不同网络代码构建的客户端和地图服务器会互相拒绝。

重启 Central 会结束所有会话，留在地图上的玩家在重新登录之前无法保存。请在维护时段、玩家都离线时更新。

#日常命令

任务 命令（在 Deploy 中）
状态 docker compose ps
跟踪某个服务的日志 docker compose logs -f central
某张地图的日志 docker compose logs -f map-town
重启一个服务 docker compose restart login
停止全部 docker compose down（保留卷）
每张地图的玩家数 curl http://127.0.0.1:5200/api/maps
每个容器的 CPU、内存和网络 docker stats
数据库命令行 docker compose exec postgres psql -U kitarpg -d kitarpg
重要

docker compose down -v 会删除卷，包括 pgdata：所有账号和角色都会消失。绝不要在正式服务器上加 -v。

#常见错误

  • Caddy 无法获取证书。 域名还没有指向服务器，或者端口 80 和 443 没有开放。
  • 玩家连接到 127.0.0.1。 KITARPG_PUBLIC_ADDRESS 仍是默认值。把它设为公网 IP 并重启地图。
  • "Set POSTGRES_PASSWORD in Deploy/.env." .env 文件缺失或不完整。
  • 服务退出并提示 "... is empty, too short or a sample value." .env 中某个密钥仍是示例值。
  • 地图容器启动了，但 Central 没有显示任何地图。 检查地图日志：KITARPG_MAP_KEY 错误，或者构建缺少该地图的场景（Unknown map）。
  • 没有人能创建角色。 Login 构建时没有 gamedata.json。导出游戏数据，并用 docker compose up --build -d login 重新构建。
