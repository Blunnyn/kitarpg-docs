服务器与部署

Docker

此页面尚未翻译，以英文显示。

Run the whole online game on one machine with Docker Compose: PostgreSQL, Caddy for HTTPS, Login, Central, one container per map and the optional Shop. This page covers every service in the compose file, the .env file, deploying on a VPS step by step, adding maps and map servers on other machines, updates and day-to-day commands.

#What's in the Deploy folder

The Deploy folder sits next to your Unity project folder and the Services folder. The compose file builds the service images from the folder above Deploy, so it expects this layout:

<your folder>/
  Deploy/            docker-compose.yml, .env, Caddyfile, Dockerfiles
    builds/starter/  the Linux map server build
    modules/login/   Login modules (optional)
    modules/central/ Central modules (optional)
    shop/            the Shop's catalog file (with the shop profile)
  Services/          the .NET services
  Unity/             your Unity project (the shared code in Assets/Blunnyn/KitARPG/Runtime/Shared)
File What it is
docker-compose.yml The stack
.env.example Every variable the stack needs, with sample values. Copy it to .env
Caddyfile Caddy's routes: HTTPS for Login, Central and the Shop's webhooks
Services.Dockerfile Builds Login, Central or the Shop (--build-arg SERVICE=Login) from the .NET 10 SDK image into the ASP.NET 10 runtime image, running as a non-root user on port 8080
MapServer.Dockerfile Packs a Linux map server build into an Ubuntu 24.04 image, running as user kit (uid 1001), with -batchmode -nographics -logFile -
注意

Services.Dockerfile copies Services/ and Unity/Assets/Blunnyn/KitARPG/Runtime/Shared/ from the folder above Deploy. If your Unity project folder has another name, change that COPY line to match.

#The services in the compose file

Service Image Ports on the host Volumes Notes
caddy caddy:2.10-alpine 80/tcp, 443/tcp, 443/udp Caddyfile (read only), caddy-data, caddy-config Gets and renews TLS certificates. Fixed address KITARPG_PROXY_ADDRESS on the compose network
postgres postgres:17-alpine None pgdata Database kitarpg, user kitarpg, password POSTGRES_PASSWORD. Health checked with pg_isready
login kitarpg/login 127.0.0.1:5100 → 8080 modules/login (read only) Waits for PostgreSQL to be healthy
central kitarpg/central 127.0.0.1:5200 → 8080 modules/central (read only) The map link (UDP 7700) stays on the compose network
shop kitarpg/shop 127.0.0.1:5300 → 5300 shop folder Only with --profile shop
map-town kitarpg/map-server 7777/udp None -map town -port 7777 -central central:7700
map-forest kitarpg/map-server 7778/udp None -map forest -port 7778
map-crypt kitarpg/map-server 7779/udp None -map crypt -port 7779

The map images are built for linux/amd64. All three map services share one image built from builds/starter; only their command differs.

What the compose file sets on the services:

  • Login and Central: Database__Provider=Postgres, the connection string with POSTGRES_PASSWORD, Auth__SigningKey=KITARPG_SIGNING_KEY, Proxy__Enabled=true and Proxy__KnownProxies__0 set to Caddy's address.
  • Central only: Central__MapKey=KITARPG_MAP_KEY, Central__MapNetworks__0 set to the compose network, and the maps town 7777, forest 7778 and crypt 7779 without executables (each map is its own container, so Central only waits for them to register).
  • Maps: KITARPG_CENTRAL_KEY=KITARPG_MAP_KEY, KITARPG_SHOP_URL=http://shop:5300, KITARPG_SHOP_KEY, and -address KITARPG_PUBLIC_ADDRESS.
  • Shop: the database, the proxy settings, ASPNETCORE_URLS=http://+:5300, Shop__CatalogPath=/app/shop/shop-conf.json, KITARPG_SHOP_KEY, Shop__AdminKey, and the Stripe and signed webhook secrets.

Every service restarts by itself (unless-stopped).

#The .env file

Copy .env.example to .env and change every value. The compose file refuses to start while a required variable is missing, and the services refuse sample values.

Variable What it is Required
POSTGRES_PASSWORD The database password Yes
KITARPG_SIGNING_KEY Token signing key for Login and Central, at least 32 random characters Yes
KITARPG_MAP_KEY Key the map servers present to Central, at least 16 random characters Yes
KITARPG_PUBLIC_ADDRESS The address players use to reach the map servers: your server's public IP or a domain Default 127.0.0.1 (this machine only)
KITARPG_LOGIN_DOMAIN Public name for Login, such as login.mygame.com Default login.localhost
KITARPG_CENTRAL_DOMAIN Public name for Central, such as central.mygame.com Default central.localhost
KITARPG_NETWORK The compose network. Change only if the subnet is taken on the host Default 172.28.0.0/24
KITARPG_PROXY_ADDRESS Caddy's fixed address in that network Default 172.28.0.10
KITARPG_SHOP_KEY Key map servers send the Shop, at least 16 random characters With the shop profile
KITARPG_SHOP_ADMIN_KEY Key for the Shop's admin API, at least 16 random characters With the shop profile
KITARPG_STRIPE_WEBHOOK_SECRET Stripe's webhook signing secret (whsec_...). Empty turns Stripe off No
KITARPG_SHOP_SIGNED_SECRET Secret shared with your own web shop. Empty turns it off No

Make each secret with openssl rand -hex 32. Keep .env out of version control.

#Try it on your computer

You can run the stack on your own machine before renting a server. With the default *.localhost names Caddy uses its own local certificate authority.

  1. Install Docker Desktop.
  2. In Unity: KitARPG > Export Game Data for Services, then KitARPG > Starter > Build Linux Server.
  3. In Deploy: cp .env.example .env, then replace the three required secrets.
  4. docker compose up --build.
  5. Play in the editor. The compose file publishes Login and Central on 127.0.0.1:5100 and 127.0.0.1:5200, the client's default addresses, so a client in the editor reaches them. Stop the services in Play & Servers first, or the ports are taken.

On a Mac with Apple silicon the map containers run as x86 under emulation: fine for trying, not for measuring performance.

#Deploy on a VPS

A step by step for a Linux VPS (Ubuntu 24.04 or similar) with a public IP.

#1. Prepare the server

  1. Rent a VPS with an x86-64 CPU (the map image is built for linux/amd64). Size it from your own measurements; see Performance.

  2. Install Docker Engine with the Compose plugin, following Docker's guide for your distribution.

  3. Open the firewall for exactly these ports:

    Port Protocol For
    22 TCP SSH
    80 TCP Caddy (certificates and the redirect to HTTPS)
    443 TCP and UDP Caddy (HTTPS and HTTP/3)
    7777 to 7779 UDP The map servers (one port per map)

    Don't open 5100, 5200, 5300, 5432 or 7700.

#2. Point your domains

Create two DNS A records pointing at the VPS's IP, for example login.mygame.com and central.mygame.com. Caddy can only get certificates once they resolve.

#3. Build and copy

On your computer:

  1. KitARPG > Export Game Data for Services.

  2. KitARPG > Starter > Build Linux Server.

  3. Copy the folder with Deploy, Services and the shared code to the server, for example with rsync:

    rsync -av --exclude 'bin' --exclude 'obj' --exclude '*.db' \
  Deploy Services Unity/Assets/Blunnyn/KitARPG/Runtime/Shared \
  user@server:/opt/mygame/ --relative

    The --relative flag keeps the paths, so the server gets /opt/mygame/Unity/Assets/Blunnyn/KitARPG/Runtime/Shared.

#4. Configure

On the server, in /opt/mygame/Deploy:

cp .env.example .env
nano .env

Set the secrets, KITARPG_PUBLIC_ADDRESS to the VPS's public IP (or a domain pointing at it), and the two domains.

#5. Start

docker compose up --build -d
docker compose ps
docker compose logs -f central

Central logs Map link listening on UDP 7700, then Map town (...) registered at <address>:7777 for each map. Check the services from the server itself:

curl http://127.0.0.1:5100/health
curl http://127.0.0.1:5200/api/maps
curl https://login.mygame.com/health

#6. Build the client

Set Login Url to https://login.mygame.com and Central Url to https://central.mygame.com in KitARPGSettings, then Build Mac Client or Build Windows Client. See Builds.

#7. Name your admin

Create your account in the game, then:

docker compose exec postgres psql -U kitarpg -d kitarpg \
  -c "UPDATE accounts SET \"Role\" = 4 WHERE \"Username\" = 'yourname';"

#8. Back up

Schedule a nightly pg_dump and copy the files off the server. See Database.

#The Shop

docker compose --profile shop up --build -d
  • Set KITARPG_SHOP_KEY and KITARPG_SHOP_ADMIN_KEY in .env first; the Shop refuses to start without real keys.
  • The catalog is Deploy/shop/shop-conf.json. The first start copies the sample there if it's missing. Edits are picked up without a restart.
  • For the admin API to save offers, the container's user (uid 1654) must be able to write the folder: sudo chown 1654 shop. The folder is mounted, not the file, because saving replaces the file by renaming.
  • Caddy forwards only /api/shop/webhooks/* on the Login domain to the Shop. The admin API is reachable on 127.0.0.1:5300 from the server itself. To publish the catalog from the editor, open an SSH tunnel (ssh -L 5300:127.0.0.1:5300 user@server) and use http://127.0.0.1:5300 as the online server address.

See Shop service.

#Modules

Put each Login module in its own folder under Deploy/modules/login and each Central module under Deploy/modules/central, then docker compose restart login or central. The folders are mounted read-only. To refuse any module but yours, add Modules__Allow__0: MyGame.Central.dll to the service's environment. See Service modules.

#Adding a map

  1. Add the map in Unity (Game Database and its scene) and build the Linux server again.

  2. In docker-compose.yml, copy a map block and change the name, the map id and the port:

    map-desert:
  <<: *map
  command: ["-map", "desert", "-port", "7780", "-central", "central:7700", "-address", "${KITARPG_PUBLIC_ADDRESS:-127.0.0.1}"]
  ports:
    - "7780:7780/udp"

  3. Tell Central about it, in the central service's environment:

    Central__Maps__3__Id: desert
Central__Maps__3__Port: "7780"

  4. Open UDP 7780 in the firewall.

  5. docker compose up --build -d.

Each map id can run in one container only; Central refuses a second registration of the same id.

#Adding map servers

A busy map can move to its own machine. The map link (UDP 7700) isn't encrypted, so the machines must share a private network or a WireGuard tunnel. Never publish 7700 on the internet.

On the main machine (where Central runs):

  1. Set up the private network or tunnel. Say the main machine is 10.8.0.1 and the map machine is 10.8.0.2.

  2. Publish the map link on the tunnel address only, in the central service:

    ports:
  - "127.0.0.1:5200:8080"
  - "10.8.0.1:7700:7700/udp"

  3. Allow the tunnel network, next to the compose network:

    Central__MapNetworks__1: 10.8.0.0/24

  4. Remove that map's container from this machine and keep its Central__Maps__N entry.

  5. docker compose up -d.

On the map machine:

  1. Install Docker and copy Deploy/MapServer.Dockerfile and Deploy/builds/starter.

  2. Build and run the map:

    docker build -f MapServer.Dockerfile --build-arg BUILD_DIR=builds/starter -t kitarpg/map-server .
docker run -d --restart unless-stopped --name map-forest \
  -e KITARPG_CENTRAL_KEY=<map key> \
  -p 7778:7778/udp kitarpg/map-server \
  -map forest -port 7778 -central 10.8.0.1:7700 -address <this machine's public IP>

  3. Open UDP 7778 in this machine's firewall.

Central logs the map's registration. If it logs Refused a map link from ...: not in Central:MapNetworks, the tunnel network isn't allowed yet.

#Updating

When you change the game or apply a kit update:

  1. Back up the database.
  2. Rebuild what changed: Export Game Data for Services and Build Linux Server in Unity, and the client.
  3. Copy the new files to the server.
  4. docker compose up --build -d. Services with new images restart; migrations run on start.
  5. Release the new client at the same time: a client and a map server built from different network code refuse each other.

Restarting Central ends every session, and players who stay on a map can't save until they sign in again. Update in a maintenance window, with players out.

#Day-to-day commands

Task Command (in Deploy)
Status docker compose ps
Follow a service's log docker compose logs -f central
A map's log docker compose logs -f map-town
Restart one service docker compose restart login
Stop everything docker compose down (keeps the volumes)
Players per map curl http://127.0.0.1:5200/api/maps
CPU, memory and network per container docker stats
Database shell docker compose exec postgres psql -U kitarpg -d kitarpg
重要

docker compose down -v deletes the volumes, including pgdata: every account and character is gone. Never add -v on a live server.

#Common mistakes

  • Caddy can't get a certificate. The domains don't point at the server yet, or ports 80 and 443 are closed.
  • Players connect to 127.0.0.1. KITARPG_PUBLIC_ADDRESS is still the default. Set it to the public IP and restart the maps.
  • "Set POSTGRES_PASSWORD in Deploy/.env." The .env file is missing or incomplete.
  • A service exits with "... is empty, too short or a sample value." A secret in .env still has its sample value.
  • The map containers start, but Central shows no maps. Check the map logs: a wrong KITARPG_MAP_KEY, or the build lacks the map's scene (Unknown map).
  • Nobody can create characters. Login was built without gamedata.json. Export the game data and rebuild with docker compose up --build -d login.
