服务器与部署

配置

Login、Central、Shop 和地图服务器的每项设置，包括默认值、设置它的环境变量，以及让玩家连接到你服务器的客户端设置。

#服务如何读取设置

Login、Central 和 Shop 都是 ASP.NET Core 服务。每个服务按以下顺序读取（后面的优先）：

  1. 服务旁边的 appsettings.json。
  2. appsettings.<Environment>.json，例如 appsettings.Development.json。
  3. 环境变量。
  4. 命令行参数（--Section:Key=value）。

本手册中写作 Section:Key 的设置，对应的环境变量是 Section__Key（两个下划线）。列表项需要加索引：Auth:SigningKeys 的第 0 项是 Auth__SigningKeys__0。

环境由 ASPNETCORE_ENVIRONMENT 设置。Development 以外的任何值都算作生产环境：这时服务会拒绝在密钥为空、过短或为示例值的情况下启动。启动器运行 Login 和 Central 时不设置它（即生产环境），运行 Shop 时设为 Production。

ASPNETCORE_URLS 设置服务监听的地址，例如 http://127.0.0.1:5100。Docker 镜像监听 http://+:8080（Shop 监听 http://+:5300）。

提示

让 appsettings.json 保持出厂状态，把你的值放在环境变量中（启动器和 Docker Compose 都是这样做的）。这样套件更新可以替换服务而不影响你的设置。

#每个服务都读取的设置

#数据库

设置 作用 默认值
Database:Provider Sqlite 或 Postgres Sqlite
Database:ConnectionString 该提供程序的连接字符串 Data Source=kitarpg.db
Database:MigrateOnStartup 启动时应用缺失的迁移（先是套件的，然后是模块的） true

见数据库。

#代理

由 Login、Central 和 Shop 读取。见安全。

设置 作用 默认值
Proxy:Enabled 信任来自已知代理的 X-Forwarded-For 和 X-Forwarded-Proto false
Proxy:KnownProxies 其请求头被信任的代理地址。回环地址始终被信任 空
Proxy:KnownNetworks CIDR 形式的网络（172.28.0.0/24），用于没有固定地址的代理 空
Proxy:ForwardLimit 链路中有多少个代理 1

#日志

设置 作用 默认值
Logs:Days 游戏日志记录在 game_logs 中保留的天数；每小时清理一次。0 表示永久保留 180
Logging:LogLevel:Default 服务自身控制台日志的级别 Information

#模块

由 Login 和 Central 读取。见服务模块。

设置 作用 默认值
Modules:Path 每个模块一个子文件夹的文件夹，相对于服务所在的文件夹 modules
Modules:Allow 允许加载的模块 dll 名称。设置后，任何其他模块都会让服务停止 空（文件夹中的任何模块都会加载）

#认证（Login 和 Central）

Login 签发令牌，Central 校验令牌，所以两者需要相同的 SigningKey、SigningKeys 和 Issuer。

设置 作用 默认值
Auth:SigningKey 访问令牌的 HMAC 密钥，至少 32 字节。必填 空（Development 中为 development-only-key-...）
Auth:SigningKeys 用于轮换的额外密钥。第一个用于签名；所有密钥以及 SigningKey 都被接受 空
Auth:Issuer 令牌的签发者和受众 kitarpg
Auth:TokenMinutes 访问令牌的有效期 30
Auth:RememberDays "Remember me" 令牌的有效天数 30
Auth:AttemptsPerMinute 每个客户端地址每分钟对 /api/auth/* 的请求次数 10
Auth:FailedLoginsPerAccount 一个用户名被锁定前允许的密码错误次数 5
Auth:FailedLoginMinutes 用户名保持锁定的分钟数，也是统计失败次数的时间窗口 15
Auth:BanCheckSeconds 封禁检查结果的缓存时间。被封禁账号的令牌在此时间内失效 5

#角色（Login）

设置 作用 默认值
Characters:GameDataFile 从你的 Game Database 导出的 gamedata.json，相对于服务所在的文件夹 gamedata.json

#Central

设置 作用 默认值
Central:MapLinkPort 地图服务器连接的 UDP 端口 7700
Central:MapKey 地图服务器必须出示的密钥。持有它的人都能冒充地图。必填 空（Development 中为 development-map-key）
Central:MapNetworks 允许地图服务器连接的地址或 CIDR 网络。为空则允许任何地址 空
Central:TicketSeconds 地图票据的有效时间 30
Central:LaunchTimeoutSeconds Central 等待它启动的地图完成注册的时间 60
Central:KickWaitSeconds 新登录等待旧会话所在地图完成保存的时间 5
Central:CentralHost Central 启动的地图服务器用来连接它的主机（其参数中的 {central}） 127.0.0.1
Central:MaxFriends 每个角色的好友数 100
Central:MaxPartySize 每个队伍的玩家数 5
Central:MaxGuildSize 1 级公会的成员数 50
Central:GuildSizePerLevel 第一级之后每升一级公会增加的成员数 2
Central:MaxGuildLevel 公会的最高等级 20
Central:GuildExperienceBase 公会升过某一级所需的经验等于此值乘以等级的平方 2000
Central:GuildPointsPerLevel 第一级之后公会每升一级获得的收税官升级点数 1
Central:GuildStorageSlots 公会银行的格子数 50
Central:GuildHistoryDays 公会历史记录保留的天数 90
Central:MaxAllianceGuilds 每个联盟的公会数 10
Central:AlliesEnterHalls 同盟公会的成员也可以进入某公会的公会大厅 false
Central:MailDays 信件过期前保留的天数 30
Central:MaxMailItems 每封信件的物品堆数 5
Central:MaxMailbox 一个邮箱可容纳的信件数；超出后新信件会被退回 100
Central:MarketDays 拍品在市场上停留的天数，到期后通过邮件退还卖家 14
Central:MaxListings 一个角色同时在售的拍品数 20
Central:MarketPageSize 市场结果每页的拍品数 12
Central:Maps Central 知道的地图（见下文） town 7777、forest 7778、crypt 7779、guild_hall 7780

#Central:Maps

每一项描述一张地图。

字段 作用 默认值
Id 你 Game Database 中的地图 id 空
Executable 要启动的地图服务器构建。为空表示由其他东西启动地图，Central 只等待 3 秒让它注册 空
Arguments 所启动地图的命令行。{map}、{port}、{central}（CentralHost:MapLinkPort）和 {key} 会被替换 -batchmode -nographics -map {map} -port {port} -central {central}
Port 地图的游戏端口 7777
AutoStart 在 Central 启动时就启动该地图，而不是等第一个玩家到来 false

Central 通过 KITARPG_CENTRAL_KEY 把地图密钥传给它启动的进程，机器上的其他用户无法像读取命令行那样读取它。只有当地图构建比这个变量更旧时，才把 {key} 与 -centralKey 一起使用。

以环境变量形式：

Central__Maps__0__Id=town
Central__Maps__0__Port=7777
Central__Maps__0__Executable=/opt/kitarpg/map/KitARPGServer.x86_64
Central__Maps__0__AutoStart=true

#Shop

Shop 的设置（Shop:CatalogPath、Shop:MapKeys、Shop:AdminKey、支付服务商及其速率限制）见 Shop 服务。

#按名称读取的环境变量

除了上面的 Section__Key 形式之外，套件还直接读取这些变量：

变量 由谁读取 是什么
KITARPG_CENTRAL_KEY 地图服务器 连接 Central 的地图密钥。命令行中的 -centralKey 优先于它
KITARPG_SHOP_URL 地图服务器 Shop 的地址，例如 http://shop:5300。-shop 优先于它
KITARPG_SHOP_KEY 地图服务器、Shop 连接 Shop 的地图密钥。在 Shop 上，它会在 Shop:MapKeys 之外再增加一个被接受的密钥。在地图上 -shopKey 优先
ASPNETCORE_ENVIRONMENT 服务 Development 或其他任何值（生产环境）
ASPNETCORE_URLS 服务 监听地址

Docker Compose 的 .env 文件有自己的变量（POSTGRES_PASSWORD、KITARPG_SIGNING_KEY、KITARPG_MAP_KEY、KITARPG_PUBLIC_ADDRESS、域名和 Shop 的密钥），compose 文件会把它们转换为上面的设置。见 Docker。

#地图服务器命令行

地图服务器就是作为服务器构建的你的游戏（见构建）。它读取：

参数 作用 默认值
-batchmode -nographics Unity 用于无窗口运行的标志。地图服务器只有在批处理模式下才会自行启动
-map <id> 运行 Game Database 中的哪张地图 场景中的 MapServer.mapId（town）
-port <port> 玩家连接的 UDP 端口 KitNetwork 中传输层的端口（7777）
-central <host:port> Central 的地图链路 CentralLink.host 和 port（127.0.0.1:7700）
-centralKey <key> 地图密钥。优先使用 KITARPG_CENTRAL_KEY：命令行对机器上的每个用户都可见 KITARPG_CENTRAL_KEY
-address <host> 告知玩家去连接的地址。为空则使用 Central 看到的地图地址 MapServer.publicAddress（空）
-shop <url> Shop 的地址 KITARPG_SHOP_URL
-shopKey <key> 连接 Shop 的密钥 KITARPG_SHOP_KEY
-logFile <file> Unity 的日志文件。- 表示写到标准输出（Docker 镜像就是这样做的） Unity 的默认值

示例：

KITARPG_CENTRAL_KEY=<map key> ./KitARPGServer.x86_64 -batchmode -nographics \
  -map forest -port 7778 -central 10.8.0.1:7700 -address play.mygame.com -logFile -

没有 Shop 地址和密钥时，游戏内商店保持关闭。公网地址上使用普通 http:// 的 Shop 地址会被拒绝，因为密钥会以可读的形式穿过互联网；请使用 https:// 或私有地址（10.x、172.16-31.x、192.168.x、回环地址，或不带点的名称，如 shop）。

地图服务器会记录 Map server '<id>' starting on port <port>, Central at <host>:<port>.，在 Central 接受它之后记录 Registered with Central as <id>.。

#地图服务器组件

这些组件位于 KitNetwork 预制体（示例中为 Assets/Blunnyn/KitARPG/Samples/Starter/Prefabs/KitNetwork.prefab）和场景的地图服务器对象上。修改它们会影响之后的每一次构建。

#Map Server（MapServer）

字段 作用 默认值
Map Id（mapId） 没有 -map 启动时运行的地图 town
Public Address（publicAddress） 客户端连接的地址。为空则让 Central 使用它看到的地址 空
Save Interval Seconds（saveIntervalSeconds） 每个玩家的保存间隔 60
Start In Editor（startInEditor） 在编辑器中进入 Play 模式时启动服务器 开

#Central Link（CentralLink）

字段 作用 默认值
host、port 未提供 -central 时 Central 的地图链路 127.0.0.1、7700
key 既没有设置 -centralKey 也没有设置 KITARPG_CENTRAL_KEY 时的地图密钥 development-map-key
heartbeatSeconds 地图报告玩家人数的间隔 5
retrySeconds 重新尝试连接 Central 的间隔 3
logSeconds 发送游戏日志记录的间隔 2
maxUnconfirmedAudit 等待 Central 确认的 GM 审计记录数，超过后 GM 命令停止执行 500

#网络管理器和传输层

KitNetwork 上的 KitNetworkManager 和 KcpTransport 是 Mirror 自己的组件。套件设置了以下值；修改之前请先阅读性能。

组件 字段 套件的值
KitNetworkManager Send Rate（sendRate）：服务器每秒的 tick 数 30
KitNetworkManager Max Connections（maxConnections）：一个地图服务器接受的玩家数 100
KcpTransport port 7777
KcpTransport Timeout（毫秒） 10000
TicketAuthenticator timeout：客户端出示有效票据的秒数 10
KitInterestManagement visRange：玩家可见的米数 40
KitInterestManagement rebuildInterval：两次可见性重建之间的秒数 1

#客户端设置

客户端通过 Assets/Settings/Resources/KitARPGSettings.asset 找到 Login 和 Central，这个文件由 KitARPG > Play and Servers 编辑。

字段 作用 默认值
Mode（mode） Online 或 SinglePlayer。套件的构建菜单会为每个构建设置它 Online
Login Url（loginUrl） Login 的地址 http://127.0.0.1:5100
Central Url（centralUrl） Central 的地址 http://127.0.0.1:5200
Save File（saveFile） 单人模式存档，位于玩家的持久数据文件夹中 savegame.db

在为玩家构建客户端之前，把 Login Url 和 Central Url 设为你的 HTTPS 地址，例如 https://login.mygame.com 和 https://central.mygame.com。如果其中任何一个在本机以外使用普通 HTTP，发布客户端的构建会停止。

仅在编辑器和带 KITARPG_DEV 的构建中，客户端还会读取：

参数 作用
-mode online 或 -mode single 覆盖 Mode
-login <url> 覆盖 Login Url
-centralUrl <url> 覆盖 Central Url
-save <file> 覆盖 Save File
-autoplay 用测试账号自动登录
-smoketest <mode> 运行自动测试（enter、portal、systems）

发布客户端会忽略所有这些参数，因此快捷方式无法把玩家的密码发送到其他服务器。

#开发值和生产值

密钥 Development 中的值 生产环境需要什么
Auth:SigningKey development-only-key-change-me-... 32 个或更多随机字符，Login 和 Central 上相同
Central:MapKey development-map-key 16 个或更多随机字符，Central 和每张地图上相同
Shop:MapKeys dev-shop-key 16 个或更多随机字符，Shop 和每张地图上相同
Shop:AdminKey dev-shop-admin-key 16 个或更多随机字符，或留空以关闭管理 API
数据库密码 无（SQLite） 长且随机。kitarpg、postgres、password、admin、root、secret 和示例值会被拒绝

启动器和 Play & Servers 会为每台电脑生成随机密钥。要自己生成：

openssl rand -hex 32
