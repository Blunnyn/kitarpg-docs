服务器与部署

安全

KitARPG 如何保证在线游戏的安全，在向玩家开放之前你必须设置什么，如何轮换密钥，以及上线前要逐项检查的清单。

#安全模型

  • 服务器做决定。 客户端只发出请求。移动、战斗、掉落、交易、银行、锻造、商店：地图服务器检查每个请求并执行它。修改过的客户端可以发送任何内容，但无法让服务器接受它。
  • 玩家从不接触数据库。 地图服务器也不接触：它们通过 Central 加载和保存。
  • 票据。 客户端只能凭 Central 发放的一次性票据进入地图，票据有效期 30 秒，且只对那张地图有效。没有人能跳过登录或操控别人的角色。
  • 每个账号一个会话。 再次登录会先关闭旧会话，等它所在的地图保存之后。
  • 物品只有一个所有者。 每个副本是数据库中的一行，恰好有一个所有者，每次转移都经过同一把锁和同一个事务。见服务。
  • 客户端不包含服务器代码。 构建分离把服务器逻辑、GM 命令、密钥和连接字符串排除在你发布的客户端之外。见构建。

本页其余部分是你需要设置的内容，以确保这个模型在你的服务器上成立。

#密钥

密钥 存放位置 谁必须拥有它
令牌签名密钥 Auth:SigningKey / KITARPG_SIGNING_KEY Login 和 Central
地图密钥 Central:MapKey / KITARPG_MAP_KEY，地图上为 KITARPG_CENTRAL_KEY Central 和每个地图服务器
Shop 地图密钥 Shop:MapKeys / KITARPG_SHOP_KEY Shop 和每个地图服务器
Shop 管理密钥 Shop:AdminKey / KITARPG_SHOP_ADMIN_KEY Shop 和负责发布目录的人
支付密钥 Shop:Stripe:WebhookSecret、Shop:Signed:Secret Shop 和你的支付服务商
数据库密码 Database:ConnectionString / POSTGRES_PASSWORD Login、Central、Shop、PostgreSQL

在 Development 之外，只要其中任何一个为空、短于 16 个字符，或是仓库中的示例值（任何包含 change-me 或 kitarpg-dev，或以 development- 或 dev- 开头的值），服务就拒绝启动。签名密钥还必须至少 32 字节。数据库密码不能是 kitarpg、postgres、password、admin、root 或 secret。完全不带密码的连接字符串是允许的，用于密码文件和受信任的本地连接。

启动器和 Play & Servers 会为每台电脑生成随机密钥，并保存在 launcher.json 中（从编辑器运行时位于 UserSettings/KitARPG/）。Docker 从 Deploy/.env 读取它们。不要把这两个文件放进版本控制，也绝不要把任何密钥放进客户端构建。

重要

任何拥有地图密钥的人都能冒充地图服务器并保存任意角色。任何拥有签名密钥的人都能以任意账号登录。请像对待数据库密码一样对待这两个密钥。

#TLS 和反向代理

Login、Central 和 Shop 使用普通 HTTP。在生产环境中，Caddy 位于它们前面（compose 文件会启动它）：

  • Caddy 提供 https://<login domain> 和 https://<central domain>，并转发给私有 compose 网络上的服务。一旦域名指向服务器且端口 80 和 443 开放，它会自行获取和续期证书。
  • 端口 5100、5200 和 5300 只在 127.0.0.1 上发布，用于服务器本机上的健康检查和 Shop 的管理 API。不要在其他网络接口上发布它们。
  • 对于 Shop，Caddy 只转发 Login 域名上的 /api/shop/webhooks/*。
  • 发布客户端在 Login 或 Central 使用普通 HTTP 地址时（本机除外）拒绝构建，并忽略 -login、-centralUrl 和 -mode，因此恶意快捷方式无法把密码发送到别处。

#反向代理

在代理之后，每个请求都来自代理的地址，所以按地址的速率限制会把所有玩家算在一起。服务只在允许时读取 X-Forwarded-For 和 X-Forwarded-Proto：

设置 作用 默认值
Proxy:Enabled 是否信任转发的请求头 false
Proxy:KnownProxies 其请求头被信任的代理地址（回环地址始终被信任） 空
Proxy:KnownNetworks CIDR 形式的网络，用于没有固定地址的代理 空
Proxy:ForwardLimit 链路中的代理数 1

compose 文件给 Caddy 一个固定地址（KITARPG_PROXY_ADDRESS，172.28.0.10），并且只信任这一个地址。

警告

前面没有已知代理时，绝不要开启 Proxy:Enabled。否则客户端可以自己写 X-Forwarded-For 来绕过速率限制。

#账号和令牌

  • 密码使用 Argon2id 哈希（19 MiB，2 轮）。不存在的用户名与错误密码花费的时间相同。
  • 速率限制。 /api/auth/* 允许每个客户端每分钟 Auth:AttemptsPerMinute（10）次请求，IPv4 地址逐个计数，IPv6 地址按 /64 计数。
  • 账号锁定。 Auth:FailedLoginsPerAccount（5）次密码错误会以 login_locked 锁定该用户名 Auth:FailedLoginMinutes（15）分钟，无论账号是否存在。
  • 访问令牌的有效期为 Auth:TokenMinutes（30）。被封禁或删除的账号在 Auth:BanCheckSeconds（5）秒内失去访问权限。
  • Remember me 令牌只以 SHA-256 形式保存，使用一次后换成同一令牌族的下一个令牌。重复使用的令牌会删除整个令牌族。POST /api/auth/forget-all 让一个账号在所有地方登出。

这些计数器保存在每个 Login 进程的内存中：重启会忘记它们，多个 Login 实例各自独立计数。

#地图链路

  • 地图服务器通过 UDP Central:MapLinkPort（7700）连接 Central，并且必须出示 Central:MapKey。
  • Central:MapNetworks 列出允许打开链路的地址或网络。为空则允许任何地址。compose 文件只允许它自己的网络。
  • Central 通过 KITARPG_CENTRAL_KEY 环境变量把密钥传给它启动的地图，机器上的其他用户无法像读取命令行那样读取它。
  • 一张地图只能代表该地图上的玩家发言：Central 会检查每条关于玩家的消息的发送者。
  • 该链路没有加密。 其他机器上的地图通过私有网络或 WireGuard 隧道连接 Central。只在该网络接口的地址上发布 UDP 7700，并把该网络加入 Central:MapNetworks。绝不要在互联网上发布它。

#Shop

  • 地图服务器用 X-Shop-Key 认证，管理 API 用 X-Admin-Key 认证。两者都以常量时间比较。
  • 内部 API 和管理 API 不对互联网开放：只有 webhook 经过 Caddy，端口 5300 只在回环地址上发布。
  • 每组端点都有各自的按客户端地址的速率限制。
  • 只接受签名有效的 webhook；每笔付款只计算一次。
  • 地图服务器拒绝公网 IP 上使用普通 http:// 的 Shop 地址，因为它的密钥会以可读的形式穿过互联网。

见 Shop 服务。

#地图服务器检查什么

保护你免受修改过的客户端影响的简短清单，全部在套件的服务器代码中：

  • 命令节流。 每个客户端命令计入每秒 30 条、突发 60 条的配额；远超配额时连接会被视为刷屏而断开。到达 Central 的命令（邮件、公会、好友、队伍、举报）配额为每秒 2 条、突发 10 条。交易和决斗请求限制为每 2 秒一次。
  • 目标。 玩家只能选中其连接看得到的目标，绝不能选中隐身的敌人。
  • 玩家文本。 聊天、邮件、备注、公会名和职位都会被清理，使其无法打开 TextMeshPro 标签。
  • 数量。 在银行、邮件、交易和市场中，负数、过大或溢出的金币和物品数量会被拒绝。
  • 交付。 在 Central 交付物品（市场、邮件、公会银行、收税官）之前做的存档无法抹去这次交付。
  • GM 命令只对等级合适的账号执行，每条 2 级及以上的命令都会先写入 gm_audit。如果 Central 无法记录，命令就不会执行。见 GM 工具。

你自己的代码也遵循同样的规则。见你的代码的安全规则。

#构建

  • 发布客户端只能使用 IL2CPP。如果发布客户端使用 Mono，构建会停止。
  • MMO 客户端绝不包含服务器程序集、本地存档、测试工具、密钥或连接字符串。如果会包含，构建会停止。
  • 测试工具（KITARPG_DEV）只在测试客户端中。绝不要把测试客户端交给玩家。
  • 保留 IL2CPP 符号文件夹（*_BackUpThisFolder_ButDontShipItWithYourGame）用于崩溃报告，但不要放进你发布的内容中。

#运行服务

  • 每个数据库恰好一个 Central。 会话、票据、队伍和物品锁都在它的内存中。两个 Central 会把同样的物品发放两次。
  • 每个数据库恰好一个 Shop。 购买由其进程内的锁串行处理。
  • Login 可以在代理之后运行多个实例，但每个实例都会增加自己的速率限制额度。
  • 模块以服务的全部权限运行。 只安装你信任的模块，把它们列在 Modules:Allow 中，并让模块文件夹保持只读（compose 文件就是这样挂载的）。启动时会记录每个模块的文件和 SHA-256。
  • 以非 root 用户运行。 Docker 镜像以 app 用户运行服务，以 kit 用户运行地图服务器。

#轮换密钥

当知道密钥的人离开、密钥可能已泄露时，或者按计划定期轮换密钥。

#令牌签名密钥（无需停机）

Auth:SigningKeys 是一个列表。第一个密钥用于签名；列表中的每个密钥以及 Auth:SigningKey 都被接受。

  1. 生成新密钥：openssl rand -hex 32。

  2. 在 Login 和 Central 两者上，先设置新密钥，同时保留旧密钥：

    Auth__SigningKeys__0=<new key>
Auth__SigningKeys__1=<old key>

    在 Docker Compose 中，把这两行加到 login 服务的 &service-env 块中（Central 共用这个块），然后执行 docker compose up -d login central。

  3. 至少等待 Auth:TokenMinutes（30 分钟），让所有用旧密钥签名的令牌都过期。

  4. 移除旧密钥：把 KITARPG_SIGNING_KEY 设为新密钥并删除 SigningKeys 行，然后再次重启。

"Remember me" 令牌不是用这个密钥签名的，所以玩家的记住状态不受影响。

#地图密钥（短暂维护）

Central 同一时间只接受一个地图密钥。

  1. 生成新密钥，并放入 KITARPG_MAP_KEY（或 Central__MapKey 以及每张地图的 KITARPG_CENTRAL_KEY）。
  2. 在玩家都离线时，同时重启 Central 和每个地图服务器：docker compose up -d central map-town map-forest map-crypt map-guild-hall。

仍使用旧密钥的地图会被拒绝，直到它们用新密钥重启。

#Shop 地图密钥（无需停机）

Shop 接受 Shop:MapKeys 中的每个密钥以及 KITARPG_SHOP_KEY。

  1. 把新密钥作为 Shop__MapKeys__0 添加到 Shop，与旧密钥并存，然后重启 Shop。
  2. 给地图服务器设置新的 KITARPG_SHOP_KEY 并重启它们。
  3. 从 Shop 中移除旧密钥并重启它。

#Shop 管理密钥

修改 KITARPG_SHOP_ADMIN_KEY，重启 Shop，并在编辑器的 Shop 页面上更新管理密钥。

#支付密钥

在支付服务商的控制台（Stripe）或你的网上商店中更换 webhook 密钥，把新值放入 .env 并重启 Shop。从此以后，用旧密钥签名的 webhook 会被拒绝。

#数据库密码

  1. 在 PostgreSQL 中：ALTER USER kitarpg PASSWORD '<new password>';
  2. 修改 .env 中的 POSTGRES_PASSWORD（compose 文件用它构建连接字符串）。
  3. docker compose up -d login central shop。

POSTGRES_PASSWORD 只在首次创建 pgdata 卷时设置密码；之后只有 ALTER USER 能修改它。

#上线前检查清单

密钥

  • [ ] .env 中的每个值都已从示例值修改，每个都用 openssl rand -hex 32 生成。
  • [ ] .env 和 launcher.json 不在版本控制中，备份已安全存放。
  • [ ] 没有服务以 ASPNETCORE_ENVIRONMENT=Development 运行。

网络

  • [ ] 防火墙只开放 22/tcp、80/tcp、443/tcp 和 udp，以及地图的 UDP 端口。
  • [ ] 5100、5200、5300、5432 和 7700 无法从互联网访问。
  • [ ] 两个域名都能解析，并以有效证书提供 HTTPS。
  • [ ] KITARPG_PUBLIC_ADDRESS 是服务器的公网地址。
  • [ ] 其他机器上的地图服务器使用私有网络或 WireGuard，并列在 Central:MapNetworks 中。

构建

  • [ ] 客户端用 Build Mac Client 或 Build Windows Client（IL2CPP）构建，Login Url 和 Central Url 为 HTTPS。
  • [ ] KitARPG > Check Build Separation 显示客户端中没有服务器代码。
  • [ ] 测试客户端不在任何玩家能获取的地方。
  • [ ] 客户端和地图服务器由相同的代码构建。

服务

  • [ ] 每个数据库一个 Central，最多一个 Shop。
  • [ ] Proxy 设置只信任 Caddy 的地址。
  • [ ] 如果你使用模块，Modules:Allow 列出了你的模块。
  • [ ] 已设置第一个管理员，Game Settings > Commands 中的 GM 等级符合你的要求。

数据

  • [ ] 每晚备份数据库并复制到服务器以外，且至少测试过一次恢复。
  • [ ] Shop 的管理 API 只能从服务器本机或通过 SSH 隧道访问。
