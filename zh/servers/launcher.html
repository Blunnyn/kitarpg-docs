服务器与部署

启动器

KitARPG 启动器用一个按钮或一条命令启动 Login、Central、地图服务器，以及（如果你需要）Shop。本页介绍它的窗口、命令行、launcher.json 的每个字段，以及如何在服务器上运行它。

#它是什么

启动器是 Services/Launcher 中的一个小型 .NET 10 程序（在 Asset Store 包中位于 Assets/Blunnyn/KitARPG/Services~ 内），用 Avalonia 制作，所以它的窗口在 Windows、macOS 和 Linux 上都能使用。它会：

  • 找到已构建的服务和你的地图服务器构建；
  • 首次运行时为这次安装生成新的密钥；
  • 先启动 Login，然后启动 Central（由它启动地图服务器），需要时还会启动 Shop；
  • 显示它们的输出以及每张地图上的玩家；
  • 一起停止所有服务。

KitARPG > Play and Servers 以无窗口方式使用同一个启动器：Start services 以 --headless --config UserSettings/KitARPG/launcher.json 运行它。大多数时候你从不需要自己打开启动器。见 Play & Servers。

#首次运行之前

  1. 构建服务：在 Services 文件夹中执行 dotnet build，或在 Play & Servers 中按 Build services。
  2. 为你的电脑构建地图服务器：KitARPG > Starter > Build Mac Server 或 Build Windows Server。见构建。
  3. 导出游戏数据，让 Login 能创建角色。Play & Servers 每次启动服务时都会导出。如果你自己运行启动器，请设置 GameDataFile 或使用 KitARPG > Export Game Data for Services。

#窗口

cd Services
dotnet run --project Launcher

窗口显示 KitARPG、一个 Start 按钮、一行状态、各地图及其玩家、一个 Premium shop 复选框，以及每个服务的日志。

  • Start 启动整套服务；按钮随后变为 Stop。
  • 运行时状态行显示 Running. Open the Title scene or the client build to play.。
  • Premium shop 会同时开启 ShopEnabled 和 ShopAutoStart：Shop 随其他服务一起启动和停止，Central 启动的地图会获得它的地址和密钥。

关闭窗口会停止所有服务。

#命令行

参数 作用
（无） 打开窗口
--headless 在终端中运行同一套服务，每个服务的输出都写到标准输出。Ctrl+C 或 SIGTERM 会停止所有服务
--config <file> 使用另一个 launcher.json，而不是启动器旁边的那个。带或不带 --headless 都可以
--headless --shop-only 只运行 Shop。编辑器的 Shop 页面就是这样单独启动和停止它的
--postgres 检查或创建 PostgreSQL 数据库。从标准输入读取一个 JSON 请求，并输出一个 JSON 回答。见检查 PostgreSQL 
dotnet run --project Launcher                                    # window
dotnet run --project Launcher -- --headless                      # terminal
dotnet run --project Launcher -- --headless --config my.json     # another settings file
dotnet run --project Launcher -- --headless --shop-only --config my.json

使用 --headless 时，启动器会先输出它发现的每个问题，每行以 ! 开头，然后启动它能启动的部分，并输出 Login 和 Central 的地址。使用 --shop-only 时，任何问题都会让它以退出码 1 停止。

#launcher.json

启动器读取它旁边的 launcher.json，或 --config 指定的文件。文件不存在时会被创建。每次启动时都会填入空字段并重新保存文件，所以你只需写入想要修改的内容。

字段 作用 默认值
LoginDll KitARPG.Services.Login.dll 的路径 自动查找：启动器旁边的 Login 文件夹，或上级文件夹中的 Login/bin/Debug/net10.0
CentralDll KitARPG.Services.Central.dll 的路径 以同样方式查找
ShopDll KitARPG.Services.Shop.dll 的路径 以同样方式查找
MapServerExecutable 你的地图服务器构建 在上级文件夹中查找：macOS 上为 Builds/Starter/MacServer/KitARPGServer.app/Contents/MacOS/Unity，Windows 上为 Builds/Starter/WindowsServer/KitARPGServer.exe
DataFolder SQLite 数据库和地图日志的存放位置 launcher.json 旁边的 data
ModulesFolder 游戏模块：Login 加载 login/，Central 加载 central/ launcher.json 旁边的 modules（两个子文件夹会被创建为空）
DatabaseProvider Sqlite 或 Postgres Sqlite
ConnectionString PostgreSQL 连接，仅在 Postgres 时使用。使用 Sqlite 时文件为 DataFolder/kitarpg.db 空
Maps Central 知道的地图：Id、Port、AutoStart town 7777（随 Central 启动）、forest 7778、crypt 7779、guild_hall 7780；Play & Servers 会把游戏数据库中的其他所有地图添加到下一个空闲端口
ExternalMaps 由其他程序运行的地图 id，例如在 Play 中的编辑器。Central 等待它们注册，而不是启动它们 空
GameDataFile Login 读取的 gamedata.json 空：Login 服务旁边的那个
LoginPort Login 的 HTTP 端口 5100
CentralPort Central 的 HTTP 端口 5200
MapLinkPort Central 面向地图服务器的 UDP 端口 7700
SigningKey Login 和 Central 的令牌签名密钥 64 个随机十六进制字符，首次运行时生成
MapKey 地图服务器向 Central 出示的密钥 32 个随机十六进制字符，首次运行时生成
ShopPort Shop 的 HTTP 端口 5300
ShopMapKey 地图服务器以 X-Shop-Key 发送给 Shop 的密钥 32 个随机十六进制字符，首次运行时生成
ShopAdminKey Shop 管理 API 的密钥（X-Admin-Key），编辑器用它发布目录 32 个随机十六进制字符，首次运行时生成
ShopCatalogFile Shop 的目录文件。不存在时会把 Shop 服务旁边的示例复制过去 launcher.json 旁边的 shop-conf.json
ShopEnabled Central 获得 KITARPG_SHOP_URL 和 KITARPG_SHOP_KEY，它启动的地图服务器会继承它们 false
ShopAutoStart Shop 随 Login 和 Central 一起启动和停止 false

示例在套件更新中新增的地图（例如 crypt）会被添加到较旧的文件中，除非它的 id 或端口已被占用。

示例：

{
  "DatabaseProvider": "Postgres",
  "ConnectionString": "Host=localhost;Port=5432;Database=kitarpg;Username=kitarpg;Password=...",
  "Maps": [
    { "Id": "town", "Port": 7777, "AutoStart": true },
    { "Id": "forest", "Port": 7778, "AutoStart": false },
    { "Id": "crypt", "Port": 7779, "AutoStart": false },
    { "Id": "guild_hall", "Port": 7780, "AutoStart": false }
  ],
  "ExternalMaps": [ "forest" ],
  "ShopEnabled": true,
  "ShopAutoStart": true
}
重要

launcher.json 以明文保存签名密钥、地图密钥和 Shop 密钥。不要把它放进版本控制和构建中。编辑器把它的副本保存在 UserSettings/KitARPG/ 中，Unity 从不发布这个文件夹。

#它启动什么，以及如何启动

启动器在 dll 所在的文件夹中用 dotnet <dll> 启动每个服务，并以环境变量传递设置。

  1. Login，带 ASPNETCORE_URLS=http://127.0.0.1:<LoginPort>、数据库设置、Auth__SigningKey、Modules__Path=<ModulesFolder>/login，以及（设置时）Characters__GameDataFile。
  2. 暂停 1.5 秒，让 Login 先运行数据库迁移。
  3. Shop，在 ShopAutoStart 时：ASPNETCORE_URLS=http://127.0.0.1:<ShopPort>、ASPNETCORE_ENVIRONMENT=Production、数据库设置、Shop__CatalogPath、Shop__MapKeys__0=<ShopMapKey>、Shop__AdminKey。
  4. Central，带 ASPNETCORE_URLS=http://127.0.0.1:<CentralPort>、数据库设置、Auth__SigningKey、Central__MapLinkPort、Central__MapKey、Modules__Path=<ModulesFolder>/central，以及每张地图一组 Central__Maps__N__*：
    • Executable：MapServerExecutable，外部地图则为空；
    • Port 和 AutoStart（外部地图始终关闭）；
    • Arguments：-batchmode -nographics -map {map} -port {port} -central {central} -logFile <DataFolder>/logs/map-{map}.log。 在 ShopEnabled 时，Central 还会获得 KITARPG_SHOP_URL 和 KITARPG_SHOP_KEY，它们会传给它启动的每张地图。

Central 会立即启动 AutoStart 的地图，其他地图在第一个玩家需要时启动。各服务只监听 127.0.0.1，所以启动器启动的任何东西都无法从其他电脑访问。

每行输出都带有方括号中的服务名，例如 [Login] 或 [Central]。地图服务器写入 <DataFolder>/logs/map-<id>.log。

#在编辑器中运行一张地图

要在 Unity 编辑器中调试一张地图，而其余部分由启动器运行：

  1. 把地图 id 添加到 ExternalMaps（Play & Servers 用 Map in the editor 来做这件事）。
  2. 启动服务。Central 等待这张地图注册，而不是启动构建。
  3. 在编辑器中运行地图服务器。它会像构建一样向 Central 注册。

#检查 PostgreSQL

编辑器的 Set up PostgreSQL 窗口通过 --postgres 与 PostgreSQL 通信。它从标准输入读取一个 JSON 请求：

字段 是什么 默认值
action check 测试游戏的登录信息；create 用管理员登录信息创建数据库和用户 check
host 服务器地址 localhost
port 服务器端口 5432
ssl Prefer、Require 或 Disable Prefer
database 游戏的数据库 kitarpg
user 游戏的用户 kitarpg
password 游戏用户的密码 空
adminUser 管理员登录名，仅用于 create postgres
adminPassword 管理员密码，仅用于 create。从不保存 空
adminDatabase 管理员首先连接的数据库 postgres 
echo '{"action":"check","host":"localhost","port":5432,"database":"kitarpg","user":"kitarpg","password":"..."}' \
  | dotnet run --project Launcher -- --postgres

它输出 { "Ok": true|false, "Message": "...", "ConnectionString": "..." }。check 还会确认该用户能够创建表。create 创建角色（role）和数据库（归该角色所有），授予它所需的全部权限，并且也适用于管理员不是超级用户的托管服务器。见数据库。

#仅限一台电脑

启动器是为在一台电脑上运行所有内容而设计的：

  • Login、Central 和 Shop 只监听 127.0.0.1。
  • 它启动的地图服务器不带 -address，所以它们公布的是 Central 看到的地址，即 127.0.0.1。其他电脑上的玩家会被引向那里。
  • 没有任何东西在服务前面提供 HTTPS。

对于玩家通过互联网访问的服务器，请使用 Docker Compose，它会加入提供 HTTPS 的 Caddy，并为每张地图提供公网地址。见 Docker。

#提示

  • 每种环境使用一个 launcher.json（SQLite 用于快速测试，PostgreSQL 用于预发布环境），并用 --config 切换。
  • 重新构建服务或地图服务器后，重启启动器。当正在运行的服务比其构建旧时，Play & Servers 会提醒你。
  • 如果端口被占用，很可能另一个启动器仍在运行。停止它，或在 launcher.json 中修改端口。

#常见错误

  • "Login service not found." 服务尚未构建，或 LoginDll 指向旧路径。构建它们，或清空该字段让它重新查找。
  • "Map server not found." 为这台电脑构建地图服务器，或设置 MapServerExecutable。
  • "DatabaseProvider is Postgres but ConnectionString is empty." 填写连接字符串，或切换回 Sqlite。
  • 在地图运行时手动修改密钥。 地图服务器保留启动时的密钥。修改密钥后重启整套服务。
