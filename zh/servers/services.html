服务器与部署

服务

Login、Central 和 Shop 是与你的地图服务器一起运行的 .NET 10 Web 服务。本页介绍每个服务做什么、每个端点、地图链路消息，以及它们共同依赖的组件。

#它们在哪里

这些服务是一个 .NET 解决方案 KitARPG.Services.slnx，包含以下项目：

项目 作用
Shared 编译 Assets/Blunnyn/KitARPG/Runtime/Shared/ 中的契约和规则，让服务和 Unity 使用同一份代码
Data EF Core：各张表、每个提供程序（SQLite 和 PostgreSQL）一个数据库上下文及其迁移。见数据库
Hosting 每个服务共用的部分：令牌校验、JSON、请求大小限制、代理请求头、拒绝示例密钥、游戏日志写入器、封禁检查
Modules 你自己的 Login 和 Central 模块的契约和加载器。见服务模块
Login 账号和角色
Central 会话、票据、地图链路以及各地图之间共享的一切
Shop 可选的高级商店。见 Shop 服务
Launcher 用一个按钮或一条命令启动所有内容。见启动器
Examples/Bounties 一个带有自己表的 Central 模块示例
Tests 针对规则、Login、Central（使用模拟的地图服务器）、Shop 和模块的测试，基于 SQLite

在 Asset Store 包中，它们以 Assets/Blunnyn/KitARPG/Services.zip 的形式提供。编辑器在首次打开时把它们解压到 Assets/Blunnyn/KitARPG/Services~，当套件更新带来新的 zip 时会再次解压。Unity 不会导入名称以 ~ 结尾的文件夹。KitARPG > Play and Servers 会替你构建它们；在终端中：

cd Assets/Blunnyn/KitARPG/Services~
dotnet build
dotnet test

#每个服务共用的部分

  • JSON。 请求和回答都是使用 camelCase 名称的 JSON。共享契约使用公共字段，所以 Unity 的 JsonUtility 也能读取它们。
  • 错误。 被拒绝的请求返回 { "code": "...", "message": "..." }。错误码位于共享代码的 ErrorCodes 中，例如 wrong_credentials、login_locked、account_banned、session_busy、map_unavailable、character_limit。
  • 请求体大小。 超过 64 KB 的请求会被拒绝。Shop 的目录发布有自己的 2 MB 限制。
  • 健康检查。 在 Login、Central 和 Shop 上，GET /health 返回 ok。将它用于负载均衡器和监控。
  • 迁移。 开启 Database:MigrateOnStartup（默认）时，每个服务启动时会把数据库结构更新到最新。
  • 示例密钥。 在 Development 环境之外，只要密钥或数据库密码为空、过短或为示例值，服务就拒绝启动。见安全。
  • 游戏日志。 每个服务在请求路径之外分批把自己的记录写入 game_logs。早于 Logs:Days（180）的记录每小时删除一次；0 表示永久保留。

#Login

Login 负责账号和角色。在生产环境中，客户端通过 HTTPS 访问它。

#端点

方法 路由 需要 作用
POST /api/auth/register 无 创建账号：username、password、email（可选）。返回 201，或 409 username_taken
POST /api/auth/login 无 username、password、remember。返回 token、expiresAt（Unix 秒）、accountId、username，在 remember 时还返回 rememberToken
POST /api/auth/resume 记住令牌 用记住令牌换取新的访问令牌和下一个记住令牌
POST /api/auth/forget 记住令牌 删除该令牌所属的令牌族（在这台电脑上登出）
POST /api/auth/forget-all 访问令牌 删除该账号的所有记住令牌（在所有地方登出）
GET /api/characters 访问令牌 该账号的角色和 maxCharacters
POST /api/characters 访问令牌 创建角色：name、classId、appearance
DELETE /api/characters/{id} 访问令牌 删除该账号的一个角色及其持有的所有东西
GET /health 无 ok

每个 /api/auth/* 路由都计入下文的速率限制。

#密码

密码使用 Argon2id 哈希：19 MiB 内存、2 轮、16 字节盐、32 字节哈希。参数保存在每个哈希内部，所以以后可以提高参数而不破坏已有账号。当用户名不存在时，Login 仍会对一个虚拟密码做哈希，所以错误用户名与错误密码花费的时间相同。

#访问令牌

  • 一个用 Auth:SigningKeys 的第一个密钥（或 Auth:SigningKey）以 HMAC-SHA256 签名的 JWT。
  • 有效期为 Auth:TokenMinutes（30）。签发者和受众为 Auth:Issuer（kitarpg）。
  • 携带账号 id（sub）、用户名和 GM 等级。
  • Central 用相同的密钥校验它。被封禁或删除的账号在 Auth:BanCheckSeconds（5）秒内失去访问权限，返回 HTTP 403 account_banned。

#Remember me

  • 使用 remember: true 登录时会返回一个随机的 32 字节令牌。数据库只在 remember_tokens 中保存它的 SHA-256，以及账号、地址和 Auth:RememberDays（30）天的过期时间。
  • POST /api/auth/resume 使用该令牌一次，并返回同一令牌族的下一个令牌。
  • 已经用过的令牌再次出现，说明有人复制了它。Login 会删除整个令牌族，因此拥有者和复制者都必须重新用密码登录。remember token reused 这一行会写入游戏日志。
  • 一个账号最多保留 10 台被记住的电脑；在第 11 台上登录会移除最早的那台。
  • 客户端保存用户名、复选框状态和令牌，从不保存密码。

#速率限制

限制 设置 默认值
每个客户端每分钟对 /api/auth/* 的请求数 Auth:AttemptsPerMinute 10
用户名被锁定前允许的密码错误次数 Auth:FailedLoginsPerAccount 5
锁定时长（分钟） Auth:FailedLoginMinutes 15
  • 客户端按 IPv4 地址计数，或按 IPv6 地址的 /64 计数。
  • 被锁定的用户名返回 HTTP 429 login_locked。不存在的用户名也以同样方式计数，所以回答从不透露账号是否存在。输入正确的密码会清除计数。
  • 计数器保存在内存中：重启会忘记它们，每个 Login 实例各自计数。
  • 在反向代理之后，请开启 Proxy 设置，否则每个玩家看起来都是代理的地址。见安全。

#角色和 gamedata.json

Login 根据 gamedata.json 创建角色，这个文件从你的 Game Database 导出：玩家模型、每个模型可选的职业、每个职业的初始地图、位置、生命、法力和初始物品、物品和技能目录，以及每个账号的最大角色数（Game Database 中的 maxCharactersPerAccount，默认为 6）。

  • Characters:GameDataFile 指定它的位置（默认为服务旁边的 gamedata.json）。
  • KitARPG > Play and Servers 每次启动服务时都会把它导出到 UserSettings/KitARPG/gamedata.json。
  • KitARPG > Export Game Data for Services 把它写入 Services/Login/gamedata.json，这样 Login 的构建或 Docker 镜像会包含它。在为服务器构建 Login 之前运行它。
  • 没有这个文件时，Login 会记录错误，没有人能创建角色。
  • 角色只能选择其模型提供的职业。名称在整个游戏中唯一。

每次启动时，Login 都会把文件中的物品和技能复制到 items 和 skills 表中。被移除的物品不会被删除：它会被标记为已退役，因为可能仍有副本指向它。如果文件中没有物品，目录保持不变。

#Central

Central 是在线世界的中枢。客户端每次进入地图时调用它一次；地图服务器则始终与它保持连接。

#HTTP 端点

方法 路由 需要 作用
POST /api/play 访问令牌 characterId。返回 mapId、address、port 和一个一次性的 ticket。404 character_not_found、403 account_banned、503 map_unavailable 或 session_busy
GET /api/maps 无 已注册的地图及每张地图上的玩家：[{ "mapId": "town", "players": 3 }]
GET /health 无 ok

模块可以添加它们自己的端点。见与 Central 通信。

#票据和会话

  • /api/play 为该账号打开一个处于 Pending 状态的会话，并附带一个随机的 24 字节票据。票据在 Central:TicketSeconds（30）秒后过期。
  • 地图服务器把票据发给 Central；Central 只兑现一次，且只对那张地图有效，会话随之变为 InMap。
  • 只有持有该会话的地图才能保存角色或请求移动它。
  • 游戏中再次登录会先踢出旧会话。见重复登录。

#启动地图服务器

Central 从 Central:Maps 知道各张地图。对于每张地图：

  • 有 Executable 时，Central 在玩家需要时（或在启动时，若设置了 AutoStart）用 Arguments 启动它，并最多等待 Central:LaunchTimeoutSeconds（60）秒让它注册。地图密钥通过 KITARPG_CENTRAL_KEY 环境变量传给进程。
  • 没有时，地图由其他东西启动（Docker、处于 Play 中的编辑器、服务管理器）。Central 等待 3 秒让它注册。
  • 注册了但未列出的地图在运行期间仍然可用；列出它可以让 Central 等待它。
  • 停止 Central 会终止它启动的地图服务器。

每个字段见配置。

#地图链路

地图服务器用 LiteNetLib 通过 UDP Central:MapLinkPort（7700）连接 Central。连接请求必须携带 Central:MapKey，并且当 Central:MapNetworks 列表不为空时，发送者的地址必须在其中。每条消息由其类名加上 JSON 正文组成，以可靠有序的方式发送。

来自地图的消息 Central 做什么
MapRegister 添加该地图，记录其 id、公开地址和端口。如果另一个服务器已经持有该地图 id，则拒绝
MapHeartbeat 更新玩家人数（每 5 秒）
TicketCheck 兑现票据并发送角色
CharacterSave 如果这张地图持有该角色且版本匹配，则保存角色；玩家离开时结束会话
TransferRequest 保存新位置，必要时启动目标地图，并返回目标地图的票据
ChatRelay、FriendCommand、PartyCommand、CharacterLevel 跨地图聊天、好友、队伍、等级变化
GuildCommand、AllianceCommand、GuildExperience、GuildStorageCommand 公会、联盟、公会等级和公会银行
MailSend、MailCommand 邮件
MarketCommand 玩家之间的市场
CollectorCommand 收税官
BanRequest、RoleChange、GmAuditBatch、RatesChange GM 操作；审计记录只在保存后才确认
PlayerReport、ReportCommand 玩家举报
GameLogBatch 游戏日志记录，盖上发送者的地图 id
任何其他类名 交给注册了它的模块，否则记录为未知

Central 会检查关于某个玩家的消息是否来自该玩家所在的地图，所以一张地图只能代表它自己的玩家发言。

#物品通过同一本账本转移

每件物品的每个副本都是 item_instances 中的一行，恰好有一个所有者：角色、账号银行、公会、信件、收税官或市场拍品。Central 的 ItemLedger 在事务中一次处理一次转移来更换所有者：

  • 只有当副本确实在发送者所说的位置时，转移才会发生。由他人持有的副本会被拒绝并记录。
  • 目录中不认识的物品永远不会进入数据库。地图会保留它，并在 Login 拿到新的导出之后重试。
  • 市场、邮件、公会仓库和收税官会在同一事务中增加角色的 Deliveries 计数器。地图记录它最后应用的交付，所以交付之前做的存档无法抹去它。

这就是每个数据库必须恰好有一个 Central 的原因：锁位于它的进程中。

#Central 强制执行的限制

Central 自己的设置（好友、队伍和公会人数，邮件和市场规则）列在配置中。有些限制在代码中是固定的：

限制 值
一封信件中的金币或邮资 1,000,000,000,000,000
一个市场拍品的价格 1,000,000,000,000
一个玩家每天可以发送的举报数 10
来自一张地图的每批 GM 审计记录数 500

#Shop

Shop 是可选且独立的：Central 不知道它的存在。地图服务器用密钥调用它的内部 API；支付服务商调用它的 webhook；你用管理 API 管理它。关于它的一切都在 Shop 服务中。

#手动运行服务

启动器是最简单的方式。要单独运行一个服务以便调试：

cd Services
ASPNETCORE_ENVIRONMENT=Development \
ASPNETCORE_URLS=http://127.0.0.1:5100 \
Database__ConnectionString="Data Source=$PWD/kitarpg.db" \
dotnet run --project Login
  • Development 使用 appsettings.Development.json 中的测试密钥。绝不要在服务器上使用它。
  • 没有 ASPNETCORE_URLS 时，dotnet run 使用项目 Properties/launchSettings.json 中的端口（Login 为 5022，Central 为 5091，Shop 为 5300），而不是客户端期望的 5100 和 5200。
  • 使用 SQLite 时，给每个服务相同的绝对文件路径。默认的 Data Source=kitarpg.db 是相对于每个服务的文件夹，所以 Login 和 Central 会各自创建自己的数据库。
  • 以这种方式启动的 Central 使用 appsettings.json 中不带可执行文件的地图：请自己用 -central 127.0.0.1:7700 和开发用地图密钥启动地图服务器。

#常见错误

  • 没有人能创建角色。 Login 没有找到 gamedata.json。它的日志会说明在哪里查找过。导出它并重启 Login。
  • "Map ... is not running." 该地图没有注册：地图服务器构建缺失、可执行文件路径错误、它崩溃了（查看它的日志），或者它的密钥或地址不被允许。Central 会记录 Refused a map link 和 Map registration refused 以及原因。
  • 玩家收到 session_busy。 旧地图没有在 KickWaitSeconds 内确认存档。通常几秒内就会恢复。如果持续出现，查看那张地图的日志。
  • 令牌在 Login 和 Central 之间校验失败。 两者必须有相同的签名密钥和签发者。
