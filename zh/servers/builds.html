服务器与部署

构建

如何构建在线 KitARPG 游戏的每个部分：玩家安装的客户端、用于你的电脑和 Linux 的地图服务器、单人模式游戏，以及 .NET 服务。本页还介绍每次构建都要经过的检查，以及每种构建可以包含什么。

#构建菜单

所有构建菜单都在 KitARPG > Starter 下。每个构建都从你 Game Database 中的地图获取场景，所以新地图无需额外步骤就会进入每个构建。构建输出到 Unity 项目文件夹旁边的 Builds/Starter 文件夹（Linux 服务器输出到 Deploy/builds/starter）。

菜单 生成什么 输出 脚本后端 额外的宏定义
Build Mac Client macOS 的 MMO 客户端 Builds/Starter/MacClient/KitARPG.app IL2CPP（由菜单设置） 无
Build Windows Client Windows 的 MMO 客户端 Builds/Starter/WindowsClient/KitARPG.exe IL2CPP（由菜单设置） 无
Build Mac Server 启动器在 Mac 上运行的地图服务器 Builds/Starter/MacServer/KitARPGServer.app 项目设置 KITARPG_SERVER
Build Windows Server 启动器在 Windows 上运行的地图服务器 Builds/Starter/WindowsServer/KitARPGServer.exe 项目设置 KITARPG_SERVER
Build Linux Server 用于 Docker 和 Linux 主机的地图服务器（Dedicated Server） Deploy/builds/starter/KitARPGServer.x86_64 IL2CPP（由菜单设置） 无（Unity 会添加 UNITY_SERVER）
Build Mac Single Player macOS 的单人模式游戏 Builds/Starter/MacSinglePlayer/KitARPG.app 项目设置 KITARPG_SERVER、KITARPG_SINGLEPLAYER
Build Windows Single Player Windows 的单人模式游戏 Builds/Starter/WindowsSinglePlayer/KitARPG.exe 项目设置 KITARPG_SERVER、KITARPG_SINGLEPLAYER
Build Mac Test Client 带测试工具的客户端，供你自己检查使用 Builds/Starter/MacTestClient/KitARPGTest.app Mono（构建后恢复） KITARPG_DEV

菜单会在每个构建旁边写入 KitARPGScenes.txt，列出它包含的场景。Play & Servers 读取这个文件，在地图服务器缺少某张地图的场景时提醒你。

Mac 和 Windows 服务器是编译进了服务器代码的普通玩家构建，用 -batchmode -nographics 启动。它们不需要 Dedicated Server 模块。Linux 服务器是真正的 Dedicated Server 构建：更小，完全没有图形。

#每次构建首先检查什么

  1. 场景。 Game Database 中的每张地图都指定了自己的场景。如果某个场景文件缺失，构建会停止并指出是哪个。Title 场景始终排在第一位。
  2. Project Check。 验证器在每次构建前运行，遇到错误会停止构建。你可以在 Project Check 中用 Stop builds on errors 关闭这一点。见 Project Check。
  3. 构建分离。 套件检查构建将会编译哪些程序集，发现不该包含的程序集时停止构建。这项检查对每次构建都会运行，无论是来自套件的菜单、File > Build Profiles 还是脚本，并且无法关闭。
  4. 模式。 构建会带上 KitARPGSettings，其中记录了它所针对的模式（在线或单人模式）。菜单在构建之后会恢复编辑器原来的模式。
  5. 网络版本。 所有经 Mirror 发送的内容的哈希会写入构建。见网络版本。

#宏定义以及各部分去向

宏定义 编译什么 由谁使用
KITARPG_SERVER（或 Unity 的 UNITY_SERVER） KitARPG.Server、每个 KitARPG.Modes.*.Server 以及每个名称以 .Server 结尾的程序集：地图服务器、与 Central 的链路、GM 命令、服务器端规则 地图服务器和单人模式
KITARPG_SINGLEPLAYER KitARPG.Local：本地 SQLite 存档 仅单人模式
KITARPG_DEV 测试工具：自动登录、冒烟测试、-save、-mode、-login、-centralUrl 仅编辑器和测试客户端
KITARPG_LOADTEST 负载测试工具 仅负载测试构建
构建 包含 绝不包含
MMO 客户端 游戏、界面、网络 服务器代码、GM 命令、本地存档、测试工具、密钥、连接字符串
地图服务器 服务器代码 本地存档
单人模式 服务器代码和本地存档 测试工具

构建分离会在以下情况停止构建：

  • MMO 客户端会包含服务器代码或本地存档，或者用 KITARPG_SERVER 或 KITARPG_SINGLEPLAYER 构建；
  • 进入 MMO 客户端的程序集引用了服务器程序集；
  • 地图服务器会包含 KitARPG.Local；
  • 发布构建会包含测试工具；
  • 编辑器或测试程序集会进入任何构建；
  • 单人模式构建缺少服务器代码或本地存档；
  • 用于发布的 MMO 客户端使用 Mono 构建；
  • 用于发布的 MMO 客户端通过普通 HTTP 指向本机以外的 Login 或 Central。

对于开发版客户端，或开发时用 Mono 构建的客户端，它会给出警告（并继续构建）。

KitARPG > Check Build Separation 会为你的项目显示一张表：每种构建包含哪些程序集。

你自己的仅服务器代码放在名称以 .Server 结尾的程序集中，宏定义约束为 UNITY_SERVER || UNITY_EDITOR || KITARPG_SERVER（用 Create > KitARPG > Scripts > Game Server Assembly 创建）。见程序集。

#构建 MMO 客户端

  1. 在 Assets/Settings/Resources/KitARPGSettings.asset 中把 Login Url 和 Central Url 设为你的公网 HTTPS 地址，例如 https://login.mygame.com 和 https://central.mygame.com。见配置。
  2. 选择与地图服务器构建时相同的控制模式（Game Settings）。其他模式的客户端会被 mode_mismatch 拒绝。
  3. KitARPG > Starter > Build Mac Client 或 Build Windows Client。
  4. 用相同的代码构建地图服务器，使网络版本一致。

发布客户端始终使用 IL2CPP：其代码以原生代码发布，而不是任何人都能读取和修改的 DLL。Unity 只能在 Windows 上构建 Windows IL2CPP 播放器，只能在 Mac 上构建 Mac 的。

发布客户端会忽略 -login、-centralUrl 和 -mode 参数，并且只通过 HTTPS 与 Login 和 Central 通信。

#构建 Linux 地图服务器

即在 Docker 或 Linux 主机上运行的地图服务器。

第一次构建之前，在 Unity Hub 中为你的编辑器安装：

  • Linux Dedicated Server Build Support；
  • Linux 的 IL2CPP；
  • 在 Mac 上，还需要 com.unity.toolchain.macos-arm64-linux 包（Package Manager），它让 Mac 能为 Linux 编译。

然后：

  1. 保存你的场景，并应用所有待处理的套件更新（Overview 会列出它们），让服务器包含它们。
  2. KitARPG > Starter > Build Linux Server。
  3. 构建输出到 Deploy/builds/starter/：KitARPGServer.x86_64、KitARPGServer_Data、GameAssembly.so、UnityPlayer.so，以及一个包含 IL2CPP 调试符号的 KitARPGServer_BackUpThisFolder_ButDontShipItWithYourGame 文件夹。保留这些符号用于阅读崩溃报告；Docker 镜像不包含它们。

镜像大约 72 MB。服务器以无界面方式运行，从命令行读取地图、端口和 Central 地址（见配置）。一个构建可以服务所有地图；每个容器用不同的 -map 运行它。

#为你自己的电脑构建

Build Mac Server 或 Build Windows Server 生成启动器和 Play & Servers 启动的地图服务器。在你修改场景、服务器代码或任何经网络传输的内容之后，重新构建它。当它比正在运行的服务旧时，Play & Servers 会提醒你。

#单人模式构建

Build Mac Single Player 和 Build Windows Single Player 生成一款自己托管世界、并保存到玩家电脑上文件中的游戏。它们不需要任何服务。见快速开始：单人模式。

#测试客户端

Build Mac Test Client 生成带有套件测试工具的客户端：自动登录、冒烟测试以及 -smoketest systems，在后者中两个客户端会针对真实服务器运行社交和经济系统。它使用 Mono 以加快构建，并使用独立的文件夹，避免与发布客户端混淆。

KITARPG_DEV 是测试工具进入构建的唯一途径：普通的开发构建不包含它们。绝不要把测试客户端交给玩家。

#网络版本

每个构建都带有一个简短的哈希，涵盖经 Mirror 传输的所有内容：同步字段、同步列表和字典，以及网络消息，包括其中各类型的字段。客户端随票据发送它，用不同代码构建的地图服务器会以 version_mismatch（"The game and the server are different versions"）拒绝它，而不是在读取组件读到一半时失败。

  • 该值在构建开始时计算，并作为临时资源保存在 Assets/KitARPGBuild 中，构建结束后删除。
  • 编辑器根据自己的代码计算它。
  • 如果任一方没有该值，则不进行比较。手写的序列化器不计入哈希。

当你修改了同步字段或消息时，请同时重新构建客户端和地图服务器。

#从命令行构建

每个菜单都是一个可以从构建机器调用的静态方法：

Unity -batchmode -quit -projectPath MyGame \
  -executeMethod Blunnyn.KitARPG.Editor.StarterBuilder.BuildLinuxServer
菜单 方法
Build Mac Client Blunnyn.KitARPG.Editor.StarterBuilder.BuildMacClient
Build Windows Client Blunnyn.KitARPG.Editor.StarterBuilder.BuildWindowsClient
Build Mac Server Blunnyn.KitARPG.Editor.StarterBuilder.BuildMacServer
Build Windows Server Blunnyn.KitARPG.Editor.StarterBuilder.BuildWindowsServer
Build Linux Server Blunnyn.KitARPG.Editor.StarterBuilder.BuildLinuxServer
Build Mac Single Player Blunnyn.KitARPG.Editor.StarterBuilder.BuildMacSinglePlayer
Build Windows Single Player Blunnyn.KitARPG.Editor.StarterBuilder.BuildWindowsSinglePlayer

在批处理模式下，失败的构建会抛出异常，因此 Unity 以错误码退出，你的构建机器能看到失败。

#构建服务

.NET 服务使用 .NET 10 SDK 构建。

目标 命令（在 Services 文件夹中执行）
为启动器构建全部 dotnet build
运行测试 dotnet test
为服务器发布一个服务 dotnet publish Login -c Release -o out/Login
Docker 镜像 在 Deploy 中执行 docker compose build（见 Docker）

在发布 Login 或构建其镜像之前，运行 KitARPG > Export Game Data for Services。它会写入 Services/Login/gamedata.json，构建会把它复制到服务旁边。没有它，Login 无法创建角色。

#常见错误

  • "KitARPG stopped the OnlineClient build." Console 会列出每个问题及其修复方法。通常是客户端程序集中有服务器代码，或者 Login Url 使用了普通 HTTP。
  • "The game and the server are different versions." 客户端和地图服务器由不同的代码构建。重新构建较旧的那个。
  • 玩家切换地图后回到了登录画面。 地图服务器缺少那张地图的场景。重新构建它；Play & Servers 会指出缺少的场景。
  • 在 Mac 上 Linux 构建失败。 缺少 Linux 工具链包或 Linux Dedicated Server 模块。
  • 在 Mac 上无法构建 Windows 客户端。 Windows 的 IL2CPP 只能在 Windows 上构建。请在 Windows 机器上构建。
