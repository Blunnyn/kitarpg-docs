故障排除

使用 KitARPG 时可能遇到的问题、每条消息的含义、发生原因以及如何修复。按部分查找你的症状：设置、游玩、MMO 服务、登录、构建、数据库、服务器和 GM 工具。

#首先检查

在查找具体问题之前，以下四项检查能解决大多数问题：

  1. 停止 Play。 许多设置在 Play 期间是锁定的。
  2. 打开 Project Check（KitARPG > Project Check）并修复每个错误。大多数都有修复按钮。
  3. 在 Overview 中应用待处理的套件更新。
  4. 在 MMO 中，重新构建并重启：Play & Servers > Rebuild 服务，Rebuild 地图服务器，然后 Restart。

要阅读的日志：

日志 位置
Unity Console Window > General > Console
从编辑器启动的服务 Play & Servers > Log 卡片，或 UserSettings/KitARPG/services.log
每个地图服务器 UserSettings/KitARPG/data/logs/map-<id>.log
从编辑器启动的 Shop UserSettings/KitARPG/shop.log
Play 模式测试 Logs/KitARPG-PlayMode-Tests.xml

#设置与导入

#材质是粉色的

URP 不是当前的渲染管线，或某个质量等级仍在使用其他管线。套件的材质是 URP 材质。

修复： 打开 KitARPG > Setup Wizard 并按 Set everything up。它会把 URP 设为默认管线和每个质量等级的管线，并设置 Linear 颜色空间。要手动检查：Project Settings > Graphics > Default Render Pipeline 和 Project Settings > Quality 的每个等级。

#标签没有文字或字体

项目中没有 TextMesh Pro 的基本资源。Project Check 显示错误 "TextMesh Pro's essential resources aren't in the project, so every label in the kit's UI and sample has no font."

修复： 在 Setup Wizard 中按 Set everything up，或按 Project Check 错误上的导入按钮，或使用 Window > TextMeshPro > Import TMP Essential Resources。在批处理模式下导入会进入队列，在 Unity 退出前无法完成；请在普通编辑器中运行一次。

#菜单不响应点击

某个场景的 EventSystem 使用了另一种输入系统的 UI 模块。Project Check 警告："<scene>'s EventSystem has the UI module of the other input system, so menus may not take clicks."

修复： 在警告上按 Fix scenes，或在 Setup Wizard 中按 Set everything up。作为后备，在 Input System 下加载场景时套件也会切换该模块。

#按 Play 时出现关于 Input 类的 InvalidOperationException

项目只使用 Input System（新的 Unity 模板就是这样），而某个脚本直接读取 UnityEngine.Input。套件自己的代码从不这样做。

修复： 在你的脚本中，调用 KitInput.GetKey、KitInput.GetKeyDown、KitInput.GetMouseButton、KitInput.mousePosition 等，而不是 Input。它们在两种项目中都可用。或者把 Project Settings > Player > Active Input Handling 设为 Both。

#Game Settings 中的修改没有作用到某个场景

该场景覆盖了 Game Instance 预制体的字段，因此 Game Settings（编辑的是预制体）无法作用到它。常见情况：Input Layout 设为 Mouse And Keys 时触屏操控仍然出现。Project Check 警告："<scene> overrides Game Settings on its Game Instance (...), so changes in Game Settings don't reach that scene."

修复： 在 Project Check 中按 Fix scenes。它会还原覆盖，使场景跟随预制体。

#"Scenes in Build Settings" 显示红色

Title 不是第一个启用的场景，或者在 MMO 中没有列出 Server。详情显示 "The first scene must be Title, and Server must be listed."

修复： 按 Use starter scenes。它把 Title、Server、Town、Forest 和 Crypt 放入 Build Settings，Title 在最前。如果示例尚不存在，它会提议构建示例。

#缺少 "SQLite library for this platform"

单人模式存档需要 Assets/Blunnyn/KitARPG/Plugins/SQLite/ 中的原生 SQLite 库（macOS/libe_sqlite3.dylib、Windows/e_sqlite3.dll 或 Linux/libe_sqlite3.so）。

修复： 勾选 Plugins/SQLite 文件夹重新导入 KitARPG 包。

#"Stop Play before building the starter sample."

在 Play 期间构建示例会把损坏的对象保存到其预制体中。

修复： 停止 Play 后再构建。

#Setup Wizard 没有打开

它在每个项目中自动打开一次。之后 UserSettings/KitARPG/setup-done 会阻止它再次自动打开。

修复： 打开 KitARPG > Setup Wizard。

#在编辑器中游玩

#我无法修改 Game Settings 或 Modules

它们的字段在 Play 期间是锁定的，因为它们保存在网络预制体中。

修复： 先停止 Play。

#"Add the Title scene to Build Settings first."

Play & Servers 从 Build Settings 中打开 Title。

修复： 按 Use starter scenes，或把你的 Title 场景添加为第一个场景。

#游戏启动时没有标题界面

Unity 的 Play 按钮运行当前打开的场景。单独的地图场景没有会话。

修复： 打开 Title，或使用 Overview 或 Play & Servers 中的 Play，它们会为你打开 Title。

#新地图上的玩家或怪物不移动

该地图的场景没有烘焙 NavMesh。移动和怪物使用服务器上的 NavMesh。

修复： 在场景中添加一个 NavMeshSurface 并烘焙。复制示例的 Forest 可以直接获得已设置好的 NavMesh。参见地图。

#到达某张地图的玩家无处站立

Project Check："<scene> has no SpawnPoint; players arriving at '<map>' have nowhere to stand."

修复： 在场景中添加一个 SpawnPoint。

#单人模式中的功能回答 "Only on an online server."

好友、队伍、公会、邮件、市场、收税员、游戏内商城和部分管理命令需要服务器。

修复： 在 Play & Servers 中切换到 MMO，或在 Modules 中关闭这些系统，让它们不显示。

#MMO 服务

#找不到 .NET 10 SDK

该行显示 "dotnet was not found. Install the .NET 10 SDK, then check again." 或 "Found ...; the services need 10."。Unity 并不总能获取你 shell 的 PATH。

修复： 从 https://dotnet.microsoft.com/download/dotnet/10.0 安装 .NET 10 SDK（不只是运行时），然后按 Check again。如果它安装在不常见的位置，在套件搜索的某个文件夹中放一个指向 dotnet 的链接：Mac 和 Linux 上为 /usr/local/share/dotnet、/usr/local/bin、/opt/homebrew/bin、~/.dotnet，Windows 上为 C:\Program Files\dotnet。安装后重启 Unity Hub 和 Unity 也会刷新 PATH。

#"Services source: Not found."

套件没有找到包含 KitARPG.Services.slnx 的文件夹。它会在你的 Unity 项目文件夹旁边（../Services）、内部（Services）以及 Assets/Blunnyn/KitARPG/Services~ 中查找。

修复： 等待编辑器加载完成（它在加载时解压 Services.zip），或按 Browse 选择文件夹。如果 Services~ 不存在，检查 Assets/Blunnyn/KitARPG/Services.zip 是否已导入。

#"dotnet build failed."

服务没有编译成功。Play & Servers 显示最前面的几行错误。"dotnet build failed. Run it in a terminal to see why." 表示没有可显示的错误行。

修复： 在服务文件夹中打开终端并运行 dotnet build。常见原因：第一次时没有网络（需要下载 NuGet 包）、SDK 版本低于 10，或 Services~ 中的文件被手动修改。重新导入套件会恢复服务。

#"Something else is using port ..."

从终端或之前的会话启动的服务占用着端口 5100、5200 或 7700。它们可能在运行旧代码。

修复： 停止它们。如果 Play & Servers 显示 "Services from an earlier editor session are still running (process ...)"，按 Stop the old services。否则找到该进程（Mac 和 Linux 上用 lsof -i :5100，Windows 上用 netstat -ano | findstr 5100）并结束它。

#"The services or the map server were rebuilt after they started, so they still run the old code. Restart them."

你在它们运行时重新构建了。

修复： 按 Restart。

#"No map reached Central"

当服务在运行但没有地图服务器注册时，Overview 会显示它。通常是地图服务器构建缺失或已过期。

修复： 构建地图服务器（Play & Servers 第 1 步）并重启服务。如果仍然存在，阅读 UserSettings/KitARPG/data/logs/map-town.log。

#地图服务器构建 "Missing the scene of a map"

构建缺少某张地图的场景，因此前往那里的玩家会回到登录界面。

修复： 按 Rebuild。构建从 Game Database 中的地图获取场景。如果构建本身显示 "No scene file named ..."，说明该地图指定了一个不存在的场景：在地图页面上修正名称。

#"Two players need the MMO mode"

双人游玩只在 MMO 中可用。

修复： 在 Play & Servers 中切换到 MMO。

#双人游玩没有启动 Player 2

Unity 的 Multiplayer Play Mode 无法自动激活第二名玩家。Console 会提示开启 Player 2。

修复： 在 Window > Multiplayer > Multiplayer Play Mode 中开启 Player 2，然后再按一次 Play with two。第一次启动会在第二个编辑器中导入项目，需要一段时间。如果对话框显示 "Build the services first"，完成 Play & Servers 的第 1 步。

#我无法更改数据库

"Stop the services to change the database."

修复： 在第 3 步中按 Stop，更改后再启动。

#version_mismatch："The game and the server are different versions"

客户端发送所有通过网络传输的内容（同步字段、列表和消息）的简短哈希。地图服务器把它与自己的哈希比较，并拒绝用不同代码构建的客户端，而不是等到读取数据时才出错。

修复： 重新构建地图服务器（或客户端），让两者来自同一份代码，然后重启服务。修改代码、更新套件或留着旧的地图服务器运行后经常会出现这种情况。

#mode_mismatch："The server plays a different game mode"

客户端和地图服务器用不同的 Game Settings > Control Mode（controlMode）构建。

修复： 用相同的模式构建两者。更改模式后，重新构建地图服务器和每个客户端。

#session_busy："Your character is still being saved"

你在角色仍在某张地图上时再次登录了。Central 要求那张地图保存并移除角色，并最多等待 5 秒（Central:KickWaitSeconds）。如果保存还没到达，它会回答 session_busy，而不是冒着旧存档覆盖更新物品的风险。

修复： 等几秒钟再按 Play。如果一直无法解决，说明旧的地图服务器卡住了：检查其日志或重启服务。

#map_unavailable："That map is not running right now"

Central 无法及时启动地图服务器（Central:LaunchTimeoutSeconds，60），或该地图不在其列表中。

修复： 检查地图服务器构建存在且能运行、该地图的端口空闲，并查看该地图的日志。在 Docker 中，检查该地图在 docker-compose.yml 中有自己的服务，并有一个 Central__Maps__N 条目。

#前往新地图的玩家回到了登录界面

地图服务器构建缺少该地图的场景，或 Central 不知道该地图。

修复： 重新构建地图服务器；Play & Servers 会指出缺失的场景。对于 Docker，添加该地图的服务及其在 Central 地图列表中的条目。

#因刷屏被 "Kicked"

发送的命令远多于人类可能发送的数量（远超每秒 30 次）的客户端会以原因 flooding 被断开连接。这发生在被修改过的客户端或机器人身上。

修复： 对普通玩家无需处理。如果你自己的代码每帧发送一个命令，请降低发送频率。

#构建

#"KitARPG found N problem(s)"

Project Check 在每次构建前运行，遇到错误时中止构建。

修复： 打开 Project Check，修复错误，再次构建。你可以在 Project Check 中用 Stop builds on errors 关闭中止，但问题仍然存在。

#"The client talks to ... without HTTPS"

发布版 MMO 客户端必须通过 HTTPS 访问 Login 和 Central（本机除外）。构建会中止："... so passwords and tokens would cross the internet readable."

修复： 把 Assets/Settings/Resources/KitARPGSettings.asset 中的 Login Url 和 Central Url 设为你的 https:// 地址。要针对没有 HTTPS 的服务器测试，请使用测试客户端，永远不要给玩家使用。

#"The client is built with Mono"

发布版 MMO 客户端必须用 IL2CPP 构建，否则其代码会以可读的 DLL 形式发布。

修复： 把 Player Settings > Scripting Backend 设为 IL2CPP。在 Windows 上构建 Windows 客户端，在 Mac 上构建 Mac 客户端；IL2CPP 不能在两者之间交叉编译。

#"... goes into the online client but uses ..., which is server code."

进入客户端的某个程序集引用了服务器代码。

修复： 把需要服务器的代码移到名称以 .Server 结尾的程序集中（Create > KitARPG > Scripts > Game Server Assembly）。KitARPG > Check Build Separation 会显示什么进入了哪里。

#"Single player hosts its own world and needs ..."

在套件菜单之外进行的单人模式构建缺少服务器代码或本地存档。

修复： 用 KitARPG > Starter > Build Mac Single Player 或 Build Windows Single Player 构建，它们会添加 KITARPG_SERVER 和 KITARPG_SINGLEPLAYER 定义。

#Play 之后构建在 URP 内部失败

如果某次 Play 会话结束时没有恢复项目的渲染管线，某个质量等级可能会指向一个已被销毁的副本。套件会在 Play 结束时和每次构建前自动修复这个问题。

修复： 如果仍然发生，打开 Project Settings > Quality 并为每个等级设置 URP 资源，或再次运行 Set everything up。

#在 Mac 上构建 Linux 服务器失败

在 Mac 上构建 Linux 服务器需要 Linux Dedicated Server Build Support 以及 com.unity.toolchain.macos-arm64-linux 包。

修复： 在 Unity Hub 中添加该模块，并在 Package Manager 中添加该包。

#数据库

#PostgreSQL 设置消息

Set up PostgreSQL... 用通俗的语言报告每个常见问题：

消息 修复
"Wrong user or password." 检查登录信息
"That database doesn't exist. Create it from here with an admin login." 使用 Create the database for me
"The server doesn't take this login from this computer (pg_hba.conf): ..." 在服务器的 pg_hba.conf 中允许你的地址，或使用它允许的主机
"That login isn't allowed to do this: ..." 用管理员登录来创建，或使用拥有该数据库的用户
"No server answered there. Check the host and port, and that PostgreSQL is running." 启动 PostgreSQL，检查主机和端口
"The server didn't answer in time. Check the host, the port and the firewall." 在防火墙中开放该端口
"Connected to PostgreSQL ..., but ... can't create tables in ..." 让该用户成为数据库的所有者，或从窗口创建数据库
"Use a password of 8 characters or more." 使用更长的密码

托管服务器（RDS、Supabase、Neon）通常需要 SSL: Require。

#本机上的 Docker 无法启动

Docker 选项需要 Docker Desktop 正在运行。它会在从 5432 起第一个空闲的端口上启动一个名为 kitarpg-postgres 的容器。

修复： 启动 Docker Desktop 并重试。如果之前的容器存在，套件会复用其卷并设置新密码。

#本地数据库在哪里？

你电脑上的 MMO 使用 UserSettings/KitARPG/data/kitarpg.db。单人模式存档是持久化数据文件夹中的 savegame.db；Play & Servers 会显示其路径。

#生产环境中的服务器

#服务拒绝启动："... is empty, too short or a sample value"

在 Development 之外，Login、Central 和 Shop 会拒绝示例值或缺失的密钥：签名密钥、地图密钥、数据库密码、商城密钥。

修复： 在 Deploy/.env 中设置长的随机值（签名密钥至少需要 32 个字符）。参见安全。

#客户端无法连接到服务器上的地图

地图服务器使用 UDP。玩家需要地图端口是开放的。

修复： 在服务器的防火墙上开放 UDP 7777 到 7779（每张地图一个），以及供 Caddy 使用的 TCP 80 和 443。永远不要把地图连接（UDP 7700）发布到互联网上。

#Login 的频率限制把所有人算作一名玩家

在代理之后，每个请求看起来都来自代理的地址。

修复： 开启 Proxy 设置并填入你代理的地址。Docker Compose 文件已经信任它自己的 Caddy。参见配置。

#GM 工具

#GM 命令显示 "Unknown command"

你账号的等级低于该命令的等级。超出你等级的命令会像不存在一样回答。

修复： 在数据库中设置第一位管理员（参见 GM 命令），然后用 /role 设置其他人。提升的等级在玩家下次进入地图时生效。也请检查 Game Settings > Gm Command Levels。

#"GM commands are paused: they can't be recorded right now."

管理命令只在能被记录到审计中时才会运行，而地图此刻无法连接到 Central。

修复： 等一会儿再试。如果持续存在，检查 Central 是否在运行，以及地图是否已连接到它。

#GM 面板打不开

F8 和 /gm 只为等级 2 或以上的账号打开它（否则显示 "Unknown command /gm. Try /help."）。

修复： 提升该账号的等级。

#游戏内商城

#商城按钮不显示

商城只在线上可用，需要开启 In-game shop 模块并运行 Shop 服务。单人模式没有商城。

修复： 检查 Modules，在 Shop 页面开启商城并启动 Shop 服务。商城窗口会说明它正在加载或无法连接到服务。

#/currency gems 之后显示 "This map has no Shop service."

地图服务器没有获得 Shop 的地址和密钥。

修复： 在开启 The game has an in-game shop 的情况下启动 Shop，这样 Central 会把 KITARPG_SHOP_URL 和 KITARPG_SHOP_KEY 传给它启动的地图。在编辑器中运行的地图不会收到它们。

#测试

#运行套件的测试

KitARPG > Run Play Mode Tests 在单人模式中用一个临时存档运行套件的 Play 模式测试，因此你的角色不受影响。Console 显示通过了多少个，结果写入 Logs/KitARPG-PlayMode-Tests.xml。从命令行运行：

Unity -projectPath . -batchmode -executeMethod Blunnyn.KitARPG.Editor.KitTests.RunPlayMode

在批处理模式下，有测试失败时 Unity 以退出码 1 退出。该菜单需要 Test Framework 包；没有它时该菜单不存在。
