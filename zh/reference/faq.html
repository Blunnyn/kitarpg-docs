常见问题

买家最常问的关于 KitARPG 的问题的回答：它能做什么、单人模式和 MMO 有何不同、内容、服务器、成本、安全以及扩展。每个回答都链接到包含详细信息的页面。

#关于套件

#我需要会写代码吗？

不需要。你可以在 KitARPG 窗口和检视面板中制作职业、物品、技能、怪物、任务、NPC 和地图，在 Game Settings 中设置游戏玩法，并在 Modules 中开启和关闭系统。代码用于你想要套件不提供的功能时。参见 Game Database。

#我需要哪个 Unity 版本？

Unity 6000.6.0f1（Unity 6.6）或更新版本，搭配 Universal Render Pipeline。Setup Wizard 会为你设置 URP。参见系统要求。

#它能在内置渲染管线或 HDRP 上运行吗？

不能。套件的材质和示例是为 Linear 颜色空间下的 URP 17.6 制作的。在其他管线下它们会显示为粉色。

#它支持新的 Input System、旧的 Input Manager，还是两者都支持？

两者都支持。套件通过 KitInput 读取按键和鼠标：当 Active Input Handling 包含 Input System 包时使用它，否则使用 Input Manager。Set everything up 和 Project Check 的 Fix scenes 会为每个场景的 EventSystem 设置你所用输入方式的 UI 模块。参见按键。

#它使用什么网络库？

客户端和地图服务器之间使用 Mirror 加 KCP 传输（UDP），地图服务器和 Central 之间使用 LiteNetLib。Mirror 包含在包内。参见架构。

#我能为哪些平台构建？

套件的菜单可以构建 Mac 和 Windows 的客户端和单人游戏、用于本地测试的 Mac 和 Windows 地图服务器，以及用于 Docker 的 Linux 地图服务器。为触屏提供了触屏操控。参见构建。

#美术资源包含在内吗？我可以在游戏中使用吗？

可以。体素角色、装备、武器、怪物、图标和动画作为包的一部分放在 Assets/Blunnyn/Art 中。

#单人模式和 MMO

#单人模式和 MMO 有什么区别？

在单人模式中，游戏自己托管自己的世界并保存在玩家的电脑上；不需要运行其他任何东西。在 MMO 中，玩家登录到你的服务器（Login、Central 以及每张地图一个地图服务器），它们共享一个数据库。场景、数据和代码是相同的。参见简介。

#我以后可以把单人游戏变成 MMO 吗？

可以。在 Play & Servers 中选择 MMO，构建服务和地图服务器，然后启动它们。你的地图、数据和代码保持不变。单人模式的存档不会转移到 MMO 数据库。

#没有服务器机器也能玩 MMO 吗？

可以。在你的电脑上，Play & Servers 会用本地 SQLite 数据库构建并启动 Login、Central 和地图服务器。参见快速入门：MMO。

#一张地图能容纳多少玩家？

套件没有设置固定上限。一张地图能容纳多少玩家取决于你的地图、怪物、技能和服务器机器，因此请用你自己的内容进行测量。每张地图运行在自己的进程中，玩家只接收附近的内容，因此你应该增加地图而不是让一张地图超载。参见性能。

#一名玩家可以有多个角色吗？

可以，默认每个账号最多 6 个。在 Game Database 设置中修改 maxCharactersPerAccount。

#如果一名玩家登录两次会怎样？

每个账号一个会话。第二次登录会关闭第一次：旧地图保存角色并将其移除，第一个客户端看到 "You logged in from somewhere else."。如果保存仍在进行中，新的登录会得到 "Your character is still being saved. Try again in a moment."。

#作弊在单人模式中有效吗？

有效，当 Game Settings > Single Player Commands 开启时（默认），GM 命令在单人模式中就像作弊码一样可用。关闭它即可发布不含作弊的游戏。参见 GM 命令。

#内容

#我可以使用自己的角色模型吗？

可以，在 Game Database > Models 中使用 + New player model。人形骨骼可以共享套件的动画并在手中持握武器；任何骨骼都可以配合自己的动画使用。参见玩家模型。

#我可以使用自己的怪物模型吗？

可以，在 Game Database > Monsters 中使用 + New monster。有 Animator 时怪物播放其片段；没有时它会跳跃并在被击中时闪烁，就像示例中的史莱姆。参见怪物。

#如何添加新地图？

复制示例的 Forest 场景，在 Game Database > Maps 中添加一张地图，选择该场景，用传送门或传送 NPC 连接它，然后重新构建地图服务器。参见地图。

#为什么每个资源都有一个 id？

已保存的角色和数据库通过 id 指向数据，例如 fire_bolt。id 在资源创建时由文件名填入，之后永不更改，因此重命名或移动文件不会破坏存档。手动修改 id 会破坏所有使用它的角色。

#为什么数值加成总是整数？

这样玩家看到的是整洁的数字，客户端和服务器之间的取整也永远不会不同。百分比也是整数点。装备的每项加成在每个副本中都在最小值和最大值之间随机取值。

#玩家可以把物品卖给 NPC 吗？

默认不可以，因此物品在玩家之间、在市场或在锻造台流转。开启 Game Settings > Players Sell To Npcs 即可允许。参见 NPC 商店。

#背包满了会怎样？

掉落可以超过重量上限，此时角色无法行走，直到丢弃、出售或存放某些东西。来自邮件、公会、收税员和任务的物品在背包放不下时会进入仓库。任何东西都不会丢失。参见背包与仓库。

#如何修改按键？

每个窗口的按键是 HUD 预制体中其组件上的一个字段，移动按键是模式组件上的字段。玩家不能在游戏中重新绑定按键。参见按键。

#我应该选择哪种操控模式？

暗黑破坏神风格、点击移动的游戏选俯视角；光标瞄准、镜头环绕的游戏选自由视角；准星瞄准并带客户端预测的游戏选第三人称。同样的场景适用于全部三种，以后也可以更改。参见操控模式。

#服务器与成本

#为真实玩家运行 MMO 需要什么？

一台装有 Docker 的 Linux 机器、两个域名（一个给 Login，一个给 Central）以及 Linux 地图服务器构建。Deploy 中的 Docker Compose 文件会运行 PostgreSQL、Caddy（HTTPS）、Login、Central 以及每张地图一个容器。参见 Docker。

#SQLite 还是 PostgreSQL？

SQLite 是一个本地文件，无需安装任何东西：用于开发和小型服务器。生产环境请使用 PostgreSQL。服务两者皆可使用；你可以在 Play & Servers 或服务的设置中切换。参见数据库。

#我可以运行多个 Central 服务器来容纳更多玩家吗？

不可以。每个数据库只能运行一个 Central：它在内存中保存会话、票据和物品锁，两个 Central 会把同一件物品发出两次。Login 可以运行多个实例。地图服务器通过增加地图来扩展。每个数据库也只运行一个 Shop。

#地图服务器需要与 Central 在同一台机器上吗？

不需要，但地图连接（UDP 7700）没有加密。位于其他机器上的地图服务器必须通过私有网络或 WireGuard 隧道访问 Central，永远不要通过互联网。

#如何让自己成为管理员？

在 accounts 表中把你账号的 Role 设为 4 一次，之后在游戏中用 /role 设置其他人。参见 GM 命令。

#我可以用真实货币出售物品吗？

可以，通过可选的游戏内商城。它作为独立服务运行，拥有自己的付费货币，按账号持有。玩家通过支付 webhook 充值：Stripe，或来自你自己网店的签名 webhook。购买的物品直接进入背包。参见商城和 Shop 服务。

#商城在单人模式中可用吗？

不可用。游戏内商城需要 Shop 服务，仅限 MMO。

#安全

#玩家可以通过修改客户端作弊吗？

服务器决定一切：伤害、掉落、价格、交易、任务和移动。客户端只发出请求，每个请求都在服务器上检查。目标必须对玩家可见，命令有频率限制，玩家文字无法注入格式。MMO 客户端构建不包含服务器代码、GM 命令、本地存档或密钥。参见安全。

#物品可以被复制吗？

每个物品副本在数据库中恰好有一个所有者，所有者之间的转移通过一个账本在事务中完成。地图票据只能使用一次，重新登录会等待旧的保存完成后才让角色再次进入。

#密码如何保存？

用 Argon2id 哈希。玩家用短时有效的令牌登录。"Remember me" 保存的是一次性令牌，永远不是密码，重复使用已用过的令牌会让所有持有它的电脑都退出登录。

#多次输错密码后会怎样？

15 分钟内输错 5 次密码后，该用户名会被锁定 15 分钟（"Too many wrong passwords."），且不会透露账号是否存在。Login 还把每个地址的请求限制为每分钟 10 次。

#更新与扩展

#更新会覆盖我的修改吗？

如果你把游戏放在自己的文件夹中并使用套件更新，就不会。导入新套件会替换套件文件；套件更新会补充你的游戏缺少的内容而不重建它。只有 Start over 会从头重建示例。参见更新套件。

#我可以编辑套件的代码吗？

可以，但下一次更新会替换它。请改为从你自己的程序集扩展套件：模板、事件、虚方法和可注册类型覆盖了常见需求。参见 DevKit 概览。

#如何添加我自己的 GM 命令、技能效果或任务目标？

右键点击一个文件夹，选择 Create > KitARPG > Scripts 和对应的模板。先创建 Game Assembly，让你的脚本能访问套件。参见模板。

#我可以扩展 Login 和 Central 吗？

可以，通过模块：一个 .NET 10 类库，其中有一个实现 ILoginModule 或 ICentralModule 的类，放入服务的模块文件夹中。参见服务模块。

#API 参考在哪里？

在 Assets/Blunnyn/KitARPG/Documentation/API/ 中，每个公开类型一个页面。

#如何检查套件在我的项目中是否正常运作？

KitARPG > Run Play Mode Tests 在单人模式中用一个临时存档运行套件的测试：进入地图、穿过传送门、保存金币、战斗，以及每个人形模型用每种武器类型攻击。参见故障排除。
