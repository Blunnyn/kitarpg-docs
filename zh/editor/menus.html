编辑器

菜单

本页列出套件添加到 Unity 编辑器中的每个菜单：菜单栏中的 KitARPG 菜单、它的 Starter、Tools 和 DevKit 子菜单，以及 Project 窗口中的 Create > KitARPG 菜单。每个条目都说明了它的作用以及在哪里阅读更多内容。

#KitARPG 菜单

KitARPG 菜单位于 Unity 的菜单栏中。其条目从上到下为：

菜单 快捷键 作用
KitARPG > Open KitARPG Ctrl/Cmd+Shift+K 打开 KitARPG 窗口，定位到你上次使用的页面
KitARPG > Setup Wizard 打开 Setup wizard：游戏的运行方式，然后一键完成图形、字体和示例场景
KitARPG > Play and Servers 打开窗口并定位到 Play & Servers
KitARPG > Game Database 打开窗口并定位到 Game Database
KitARPG > Play With Two Players 必要时启动服务，打开第二个编辑器，并用测试账号让两边都登录。仅 MMO。参见双人游玩
KitARPG > Game Settings 打开窗口并定位到 Game Settings
KitARPG > Export Game Data for Services 把游戏数据库写入服务源码 Login 文件夹中的 gamedata.json，供你手动运行或放入 Docker 的服务使用。Play & Servers 启动服务时会写入自己的副本
KitARPG > Modules 打开窗口并定位到 Modules
KitARPG > Render Missing Item Icons 根据模型为每个没有图标的物品渲染一个 128 x 128 的图标，放入物品旁的 Icons 文件夹。Console 会显示生成了多少个
KitARPG > Shop 打开窗口并定位到 Shop 页面
KitARPG > Render Missing Monster Icons 为每个有预制体但没有图标的怪物渲染头像，供怪物图鉴使用。参见怪物图鉴
KitARPG > Project Check 打开窗口并定位到 Project Check，运行包括场景在内的完整检查
KitARPG > Check Build Separation 针对每种构建（MMO 客户端、MMO 地图服务器、单人模式）检查它会携带哪些套件程序集，并报告构建不应包含的任何代码。对话框显示结果，Console 显示详情。参见安全
KitARPG > DevKit > Add Bounty Board to the Open Scene 在 Scene 视图中央放置 DevKit 示例的悬赏板，并用你自己的怪物生成两个狩猎任务。参见示例：悬赏板
KitARPG > Starter > ... 构建示例和各种构建；见下文
KitARPG > Tools > Rebuild Character Controller 重新生成所有角色使用的 Animator 控制器。见下文
KitARPG > Run Play Mode Tests 运行套件的 Play 模式测试（KitARPG.Tests.PlayMode），并把结果写入 Unity 项目中的 Logs/KitARPG-PlayMode-Tests.xml
KitARPG > Documentation 在浏览器中打开本文档，使用包内的副本，网站支持编辑器语言时使用该语言。可离线使用
KitARPG > What's New 打开更新日志，最新版本在前，并提供 Open the file 来阅读 Documentation/CHANGELOG.md

#KitARPG > Starter

菜单 作用 输出
Build Scenes and Prefabs 构建入门示例：Title、Server、Town、Forest 和副本场景、网络预制体、玩家和怪物预制体、HUD 以及示例数据。再次运行会从头重新制作它们，因此对示例的修改会丢失。请先停止 Play Assets/Blunnyn/KitARPG/Samples/Starter/
Build Mac Server Mac 的本地地图服务器：带有服务器代码（KITARPG_SERVER）的玩家构建，由启动器无图形运行 Builds/Starter/MacServer/KitARPGServer.app
Build Windows Server Windows 的同类构建 Builds/Starter/WindowsServer/KitARPGServer.exe
Build Mac Client Mac 的 MMO 客户端，用 IL2CPP 编译 Builds/Starter/MacClient/KitARPG.app
Build Mac Test Client 带有测试工具（自动登录、冒烟测试）的 Mac 客户端，用 Mono 编译以加快构建。仅用于本地检查，永远不要给玩家 Builds/Starter/MacTestClient/KitARPGTest.app
Build Windows Client Windows 的 MMO 客户端，用 IL2CPP 编译 Builds/Starter/WindowsClient/KitARPG.exe
Build Mac Single Player Mac 的单人游戏，带有服务器代码以便自己托管 Builds/Starter/MacSinglePlayer/KitARPG.app
Build Windows Single Player Windows 的同类构建 Builds/Starter/WindowsSinglePlayer/KitARPG.exe
Build Linux Server 用于 Docker 的 Linux 专用服务器，用 IL2CPP 编译。需要 Unity 的 Linux Dedicated Server 模块 Deploy/builds/starter/KitARPGServer.x86_64

Builds 和 Deploy 路径相对于包含你 Unity 项目文件夹的那个文件夹。

每次构建都会：

  • 从 Game Database 中的地图获取场景，因此新地图无需编辑列表就会出现在每个构建中。如果某张地图指定的场景不存在，构建会中止并说明是哪个；
  • 在设置资源中设置构建所需的游戏模式，之后再恢复你的设置；
  • 先运行 Project Check，遇到错误时中止，除非 Stop builds on errors 已关闭；
  • 检查它只携带应有的代码。

参见构建和 Docker。

#KitARPG > Tools

Rebuild Character Controller 删除并重新生成 Runtime/Resources/KitARPG/KitCharacter.controller，即所有角色共用的唯一 Animator 控制器。它的状态中放的是占位片段，每个角色的 Character Animations 组件会把它们换成自己的，因此你永远不需要编辑它。只在控制器被删除或损坏时使用。

#Create > KitARPG

在 Project 窗口中右键点击，或使用 Assets > Create > KitARPG，来创建套件资源和脚本。

提示

通过此菜单创建的资源存在于项目中，但在游戏数据库能访问到它们之前并不在游戏中。从 Game Database 页面创建条目会为你自动列出；Project Check 会提示它无法访问的那些。

Skill Effect 一个新的技能效果
Item Effect 可用物品的新效果
Condition 用于任务、对话和 NPC 的新条件

Quest Objective 一个新的任务目标
NPC Option 一个新的 NPC 选项

Combat Formula 你自己的伤害和经验规则
Stat Formula 你自己的数值规则
Saved Player Data 随角色保存的你自己的数据
