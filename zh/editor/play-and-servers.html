编辑器

Play & Servers

Play & Servers 是你选择游戏运行方式（单人模式或 MMO），并按照编号步骤在编辑器中游玩的地方。在 MMO 中，它负责构建和启动服务（Login、Central 和地图服务器）、设置数据库、显示每个服务的状态及其日志，并支持单人或双人游玩。

#在哪里

  • KitARPG > Play and Servers，或
  • KitARPG 窗口（Ctrl/Cmd+Shift+K）中的 Play & Servers 页面，在侧边栏中排第二。

在 MMO 中，当 Login 和 Central 都有响应时，侧边栏会在该页面旁显示 On，启动期间显示 ...。

#选择单人模式或 MMO

页面以两张大卡片开头。点击其中一张来选择：

卡片 显示的说明 含义
Single player "The game hosts its own world and saves on the player's computer. No servers to run." 游戏同时是客户端和服务器，保存到本地 SQLite 文件。参见快速入门：单人模式
MMO "Players log in to your servers: Login, Central and one server per map." 玩家登录到你的服务，并在共享地图中相遇。参见快速入门：MMO

该选择保存在设置资源 Assets/Settings/Resources/KitARPGSettings.asset 中（KitSettings 的 mode 字段）。通过套件构建菜单进行的构建会为该构建设置所需的模式，之后再恢复你的设置。

如果项目还没有设置资源，页面会显示一张 No settings yet 卡片，带有 Create settings。按下它来创建该资源。

设置资源还包含以下字段，你可以在 Inspector 中编辑：

字段 作用 默认值
Mode（mode） Online（MMO）或 Single Player Online
Login Url（loginUrl） 客户端访问 Login 服务的地址 http://127.0.0.1:5100
Central Url（centralUrl） 客户端访问 Central 的地址 http://127.0.0.1:5200
Save File（saveFile） 单人模式存档，玩家持久化数据文件夹中的一个 SQLite 文件 savegame.db

#步骤如何运作

卡片下方是编号步骤。每个步骤是一张卡片，带有编号、标题、概要行和一个胶囊标签：

胶囊标签 含义
Done 该步骤已完成。卡片折叠起来，编号变成勾号
To do 尚未完成。第一个未完成的步骤带有金色边框并自动展开
Locked 必须先完成之前的步骤。锁定的步骤无法展开

点击步骤的标题来展开或折叠。右侧的箭头（▸ 或 ▾）表示当前状态。

#单人模式的步骤

#1. Check the project

概要："Scenes and the SQLite library are in place."（场景和 SQLite 库已就位。）或 "Something the game needs is missing."（游戏需要的某些东西缺失。）

行 完成条件 修复
Scenes in Build Settings Build Settings 中第一个启用的场景是 Title。详情列出场景 Use starter scenes 按正确顺序把示例场景放入 Build Settings
SQLite library for this platform 你编辑器所需的原生 SQLite 库位于 Plugins/SQLite 中（macOS/libe_sqlite3.dylib、Windows/e_sqlite3.dll 或 Linux/libe_sqlite3.so） 重新导入 KitARPG 包

#2. Play

概要："The editor is the client and the server at once."（编辑器同时是客户端和服务器。）在第 1 步完成前锁定。

  • ▶ Play single player 打开 Title 场景，并以参数 -mode single 进入 Play 模式。如果打开的场景有未保存的修改，Unity 会先要求保存。已在游玩时显示为灰色。
  • Save data 显示编辑器使用的存档文件路径。
  • Show folder 在 Finder 或资源管理器中打开持久化数据文件夹。
  • Delete save data 询问 "Delete every single player character saved by the editor?"（删除编辑器保存的所有单人模式角色？），然后删除存档文件及其 -wal 和 -shm 附属文件。在 Play 模式下或没有存档时显示为灰色。

#3. Build the game

概要："Builds go to Builds/Starter and carry the server code, so the game hosts itself."（构建输出到 Builds/Starter，并携带服务器代码，因此游戏可以自己托管自己。）

按钮 输出
Build for Mac Builds/Starter/MacSinglePlayer/KitARPG.app
Build for Windows Builds/Starter/WindowsSinglePlayer/KitARPG.exe

Builds 文件夹创建在你的 Unity 项目文件夹旁边，即包含项目的那个文件夹中。参见构建。

#MMO 的步骤

#1. Check the project

概要会统计已就绪的项，例如 "3 of 5 ready"，五项都就绪时显示 "Scenes, .NET, the services and the map server build are ready."。

行 完成条件 按钮
Scenes in Build Settings Title 是第一个启用的场景，且列出了 Server Use starter scenes
.NET 10 SDK dotnet --list-sdks 报告有 10.x SDK。详情列出已安装的版本，或显示 "dotnet was not found" Get .NET 打开 .NET 10 下载页面。Check again 在你安装后重新查找 dotnet，无需重启 Unity
Services source 找到了包含 KitARPG.Services.slnx 的文件夹。详情显示其路径 Browse 让你手动选择
Services built Login、Central 和启动器已编译。运行期间显示 "Building..." Build services，构建后变为 Rebuild。没有源码或 SDK 时显示为灰色
Map server build 本地地图服务器构建存在，且包含每张地图的场景。当所有地图都在编辑器中运行、不需要该构建时显示为灰色 Build，构建后变为 Rebuild

服务构建失败时，该行下方的红框最多显示八行错误。如果无法读取任何错误，它会显示 "dotnet build failed. Run it in a terminal to see why."。

编辑器按以下顺序查找服务源码：你用 Browse 选择的文件夹（按项目记住）、Unity 项目旁边的 Services、项目内部的 Services，以及 Assets/Blunnyn/KitARPG/Services~（套件在此解压包中附带的服务）。

还可能出现另外两行：

  • N kit updates（警告）："Things this kit adds that the game doesn't have yet. Apply them before building the map server, so both have them."（套件添加了游戏还没有的东西。在构建地图服务器前应用它们，这样两者都会包含。）Review 打开 Overview。
  • In-game shop，当项目中有 Shop 服务时出现：关闭（"Off. The Shop service is optional."）、正在运行，或已开启但未运行。Open Shop 打开 Shop 页面。

地图服务器构建在 Mac 上输出到 Builds/Starter/MacServer/KitARPGServer.app，在 Windows 上输出到 Builds/Starter/WindowsServer/KitARPGServer.exe。它是编译进了服务器代码的普通玩家构建，由启动器以批处理模式无图形运行；它不需要 Unity 的 Dedicated Server 模块。每次构建后，旁边会有一个 KitARPGScenes.txt 文件列出它的场景，页面借此得知后来添加的地图在构建中缺失。

注意

当某张地图是在上次构建之后添加的，该行会显示 "Missing the scene of a map: ..."。前往那里的玩家会被送回登录界面。请重新构建地图服务器。

#2. Pick the database

在第 1 步完成前锁定。概要显示当前的选择。

一个双向开关决定服务在哪里保存账号、角色和物品：

选择 用于
SQLite: a local file 开发和小型服务器。无需安装任何东西。页面显示文件路径，默认为 UserSettings/KitARPG/data/kitarpg.db
PostgreSQL: for production 真实的服务器，或在与发布相同的数据库上开发

选择 PostgreSQL 后，状态行会显示 Connection ready 及连接字符串（密码隐藏），或 No connection yet。然后：

  • Set up PostgreSQL... 打开 PostgreSQL 设置窗口。参见设置 PostgreSQL。
  • Write the connection string by hand，一个带有文本字段的折叠区。下方显示期望的格式：Host=localhost;Port=5432;Database=kitarpg;Username=kitarpg;Password=...

服务运行时无法更改数据库（"Stop the services to change the database."）。

Keys："Signing and map keys are made for this machine and kept in UserSettings/KitARPG."（签名密钥和地图密钥为本机生成，保存在 UserSettings/KitARPG 中。）New keys 生成新的签名密钥（32 个随机字节，用于签名登录令牌）和新的地图密钥（16 个随机字节，地图服务器向 Central 出示的凭据）并保存。服务运行时显示为灰色。

每种数据库在生产环境中需要什么，参见数据库。

#3. Start the services

在第 1 步和第 2 步完成前锁定。概要显示 "Login, Central and the maps, on this computer."、"Starting..." 或 "Running. Maps: town (1 player), ..."。

三行分别用指示灯显示各部分（灰色为关闭、金色为启动中、绿色为运行中）：

服务 详情 端口
Login 账号和角色 5100
Central 会话、聊天、公会和地图 5200
Maps "Started by Central when someone enters"，或正在运行的地图及其玩家数 每张地图一个端口，town 为 7777，forest 为 7778，crypt 为 7779

Map in the editor 选择地图在哪里运行：

选择 含义
None, every map runs from the map server build Central 从构建启动每张地图。默认值
town: runs in this editor, to debug it（每张地图一行） Central 改为等待该地图从编辑器连接过来。你在第 4 步中用 Play map server 运行它。用它来通过断点调试服务器代码

服务运行时无法更改该选择。

按钮：

  • Start services 用 UserSettings/KitARPG/launcher.json 以无界面模式启动启动器。启动前，页面会把游戏数据库中的游戏数据写入 UserSettings/KitARPG/gamedata.json，因此 Login 会按你当前的数据创建角色。
  • Restart 停止服务，等它们的端口空闲后（最多十秒）再重新启动。该步骤折叠时，其标题中也有一个 Restart 按钮。
  • Stop 停止启动器，从而关闭 Login、Central 以及它启动的每张地图。

退出 Unity 时服务会自动停止。在脚本重新加载和 Play 模式期间它们会保持运行。

此步骤可能显示的警告：

警告 含义 解决办法
"Services from an earlier editor session are still running (process ...)" 某个已关闭但没有停止它的编辑器所启动的启动器仍占用着端口。仅 Mac 和 Linux Stop the old services
"The services or the map server were rebuilt after they started, so they still run the old code. Restart them." 你在启动后重新构建了 Restart
"Something else is using port ..." 另一个程序在监听 Login 或 Central 的端口，通常是从终端启动的服务 先停止那个程序

#4. Play

在服务运行前锁定。

  • ▶ Play client 打开 Title 场景，并作为本地服务的客户端游玩（-mode online -login http://127.0.0.1:5100 -centralUrl http://127.0.0.1:5200）。
  • Play map server: town 在有地图于编辑器中运行时出现。它打开 Server 场景并作为该地图的服务器运行，用地图密钥连接 Central。
  • Two players：Play with two 打开第二个编辑器并让两边都登录。参见双人游玩。
  • Built client：Open 在编辑器之外启动客户端构建，可以启动任意多次，以同时容纳更多玩家。Build 或 Rebuild 生成它（Builds/Starter/MacClient/KitARPG.app 或 Builds/Starter/WindowsClient/KitARPG.exe）。发布版客户端用 IL2CPP 编译，因此该构建比 Mono 构建耗时更长。

#日志

底部的 Log 卡片展开后显示服务输出的最后 120 行。Open log file 在你的文本编辑器中打开 UserSettings/KitARPG/services.log。每次服务启动时日志都会清空。

#分步操作：启动 MMO 服务

  1. 打开 Play & Servers 并点击 MMO 卡片。
  2. 在第 1 步中修复每个红色行。通常是：按 Use starter scenes，按提示安装 .NET 10 SDK（然后按 Check again），按 Build services 并等待，再在 Map server build 上按 Build 并等待 Unity 构建完成。
  3. 在第 2 步中，暂时保留 SQLite: a local file。
  4. 在第 3 步中，让 Map in the editor 保持 None 并按 Start services。几秒后 Login 和 Central 的指示灯变绿。
  5. 在第 4 步中按 ▶ Play client。在标题界面注册账号、创建角色并进入世界。第一次有人前往 town 时，Central 会启动该地图服务器。
  6. 修改脚本或场景后，重新构建地图服务器并按 Restart。Overview 的 To do 列表会提醒你何时需要这样做。

#设置 PostgreSQL

第 2 步中的 Set up PostgreSQL... 打开 PostgreSQL Setup 窗口。它借助启动器（KitARPG.Launcher --postgres）工作，因此请先构建服务；没有它们时，窗口会显示 "The services aren't built yet; they do the talking to PostgreSQL. Build them in Play & Servers first."（服务尚未构建；由它们与 PostgreSQL 通信。请先在 Play & Servers 中构建。）

顶部的开关选择 PostgreSQL 在哪里运行：A server I run 或 Docker on this computer。

#A server I run

Where is PostgreSQL?

字段 作用 默认值
Host 服务器地址。本机为 localhost localhost
Port 它的端口 5432
SSL Prefer、Require 或 Disable。托管服务器（VPS、RDS、Supabase、Neon）通常需要 Require Prefer

然后选择 Create the database for me 或 Use a database I have。

选择 Create the database for me 时：

  1. 填写 Admin login（User、Password）：一个有权创建数据库和用户的账号。它只使用一次，永远不会被保存。在使用 Homebrew 或 Postgres.app 的 Mac 上，管理员通常就是你自己的用户，没有密码。默认用户：postgres。
  2. 填写 For the game：Database（kitarpg）、User（kitarpg）和 Password。密码一开始是随机的；Show 显示它，New 生成另一个。
  3. 按 Create and use。窗口创建数据库和用户，测试登录，成功后在 Play & Servers 中填入连接字符串并切换到 PostgreSQL。

选择 Use a database I have 时，填写 Login（Database、User、Password）并按 Test and use。

按钮下方的消息会说明发生了什么，或失败的原因。一分钟没有响应时窗口会放弃（"PostgreSQL didn't answer in a minute."）。

#Docker on this computer

需要 Docker Desktop（OrbStack 也可以）。Create and use 在名为 kitarpg-postgres 的容器中运行 PostgreSQL 17（postgres:17-alpine），数据保存在卷 kitarpg-pgdata 中，在 127.0.0.1 上监听从 5432 起第一个空闲的端口。它为用户 kitarpg 设置一个新的随机密码，并在 Play & Servers 中填入连接字符串。

关闭 Unity 后容器会继续运行，并随 Docker 重启。再次按 Create and use 会复用该容器并为它设置新密码。第一次下载镜像可能需要一分钟。

你可能看到的消息：

消息 解决办法
"Docker was not found. Install Docker Desktop, or write the connection string of your own server." 安装 Docker Desktop，或使用 A server I run
"Docker is installed but not running. Open Docker Desktop and try again." 启动 Docker Desktop
"The container kitarpg-postgres doesn't publish port 5432. Remove it in Docker Desktop and try again." 在 Docker Desktop 中删除旧容器
"PostgreSQL didn't start. Its log is in Docker Desktop, container kitarpg-postgres." 在 Docker Desktop 中阅读容器日志

连接字符串及其密码保存在 UserSettings/KitARPG/launcher.json 中，位于项目资源之外，默认也不在版本控制中。

#双人游玩

Play with two（第 4 步）、Play with two players（Overview）和 KitARPG > Play With Two Players 的作用都一样：

  1. 如果模式不是 MMO，对话框会显示 "Two players need the MMO mode, where players meet on servers."（双人游玩需要 MMO 模式，玩家在服务器上相遇。）并打开 Play & Servers。
  2. 如果缺少 Unity 的 Multiplayer Play Mode 包（com.unity.multiplayer.playmode），对话框会提供 Install。安装后再按一次按钮。
  3. 如果服务没有运行，它会启动服务。如果服务尚未构建，它会要求你先构建。
  4. 它通过 Multiplayer Play Mode 打开 Player 2，即同一项目的第二个编辑器。第一次时，该编辑器会导入项目，需要一段时间。
  5. 当 Login 有响应且 Player 2 已打开时，两个编辑器都进入 Play。每一边都用自己的测试账号登录，如果角色不存在就创建它，然后跳过标题界面直接进入世界。

测试账号是 kitplayer1 和 kitplayer2，角色分别为 Aria 和 Bram，使用为本机生成的随机密码、第一个玩家模型及其第一个职业。它们保存在 UserSettings/KitARPG/quickplay.json 中；编辑该文件可使用其他名字。它们只在你的本地服务上创建。

如果 Player 2 无法自动启动，Console 会提示，并且 Unity 会打开 Window > Multiplayer > Multiplayer Play Mode：在那里开启 Player 2，然后再按一次按钮。如果 15 分钟后仍未就绪，Console 会报告。

地图从地图服务器构建运行，或在 Map in the editor 中选择了某张地图时在本编辑器中运行。

#本页面使用的文件

它们都位于 UserSettings/KitARPG/ 中，按用户区分，不纳入版本控制：

文件 保存什么
launcher.json 启动器读取的端口、密钥、数据库、地图和路径
data/kitarpg.db 本地服务的 SQLite 数据库
gamedata.json Login 和 Central 读取的游戏数据，每次启动时写入
services.log 服务的输出
launcher.pid 正在运行的启动器，以便编辑器重启后能找到它
quickplay.json 双人游玩的测试账号

启动器设置列出了地图及其端口。编辑器一开始有 town 在 7777（随服务启动）、forest 在 7778、crypt 在 7779，启动器还会添加 guild_hall 在 7780。启动服务时，游戏数据库中的其他每张地图都会获得下一个空闲端口，因此新地图无需任何设置。要更改端口，在服务停止时编辑 launcher.json。参见启动器和配置。

#提示

  • 除非在调试服务器代码，否则让 Map in the editor 保持 None。在编辑器中运行地图服务器意味着编辑器不能同时作为客户端；此时请使用 Built client 或双人游玩。
  • 修改职业、物品或 Login 用来创建角色的其他数据后，请重启服务，让它们读取新的游戏数据。
  • Unity 普通工具栏中的 Play 不会传递窗口的参数。请使用本页面或 Overview 上的按钮，或从 Title 场景开始。

#常见错误

  • 没有地图服务器构建就启动服务。 Login 和 Central 会启动，但没有地图注册，玩家停留在标题界面。请构建地图服务器。
  • 重新构建后忘记重启。 服务仍在运行旧代码。该步骤会显示警告，Overview 会列出 Restart the services。
  • 端口被从终端启动的服务占用。 先停止它们；两个启动器不能共享端口。
