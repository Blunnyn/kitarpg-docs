Shop 页面

Shop 页面在编辑器中运营游戏内商城。游戏内商城以账号持有的付费货币（例如 Gems）出售物品。它作为独立的服务 Shop 服务运行，负责保存商品目录、余额和每笔购买，并接收真实货币支付；游戏只负责展示它。本页面开启商城、在你的电脑上启动 Shop 服务、编辑其商品和产品，并把它们发布到你的线上服务器。

#在哪里

  • KitARPG > Shop，或
  • KitARPG 窗口（Ctrl/Cmd+Shift+K）中的 Shop 页面。

当你电脑上的 Shop 服务有响应时，侧边栏会在其旁边显示 On。

#开始之前

  • 商城用于 MMO 游戏。单人游戏永远没有商城。
  • 项目中必须有 Shop 服务：服务源码中的 Shop 文件夹。如果没有，页面只会显示 The Shop service isn't in this project 及其查找的文件夹，游戏中也没有商城按钮。
  • 游戏数据库需要一种付费货币：勾选了 Premium 的货币。入门示例中有 Gems。
  • 玩家预制体需要 Player Shop 组件，HUD 需要商城窗口。套件更新会为旧游戏添加这两者。参见更新套件。

#标签页

该页面有三个标签页：Service、Offers 和 Real money。在本次编辑器会话中会记住你上次使用的标签页。上次操作的消息（已保存、已发布、被拒绝）显示在标签页下方，问题以红色行显示。

#Service 标签页

#In the game

"Shows the shop button in the HUD (P) in online games, on PC and on touch screens. Single player games never have a shop."（在线游戏中在 HUD 中显示商城按钮（P），适用于 PC 和触屏。单人游戏永远没有商城。）

一个开关，显示 The game has an in-game shop 或 No in-game shop。它同时开启或关闭 In-game shop 模块以及启动器设置中的商城，后者为地图服务器提供商城的地址和密钥。关闭它也会停止本机上的 Shop 服务。开启它也会开启商城所需的 Mail。

开关下方是状态行：

行 含义 解决办法
No game database 找不到数据库 在 Game Database 中选择一个
No premium currency 没有勾选 Premium 的货币；商品以它计价 在某个货币上勾选 Premium，或应用下面的更新来添加 Gems
Premium currency for the shop、Shop on the player prefabs、Shop window in the HUD 商城需要而你的游戏还没有的套件更新 Apply
Premium currency: Gems (gems) 找到的付费货币。"Held by the account, spent only at the shop."（由账号持有，只能在商城消费。） 无需操作

#On this computer

"The Shop service next to Login and Central, on the same database. It starts on its own, apart from the other services."（Shop 服务与 Login 和 Central 并列，使用同一个数据库。它独立于其他服务单独启动。）

状态 详情 按钮
Not built yet 构建服务解决方案以获得 Shop 服务和启动器 Build 编译服务。失败时错误输出到 Console
Stopped 在 http://127.0.0.1:5300 启动，商品目录位于 UserSettings/KitARPG/shop-conf.json Start the shop
Starting 等待服务响应 Stop
Running "Answering at http://127.0.0.1:5300. Saved offers go live here right away."（正在 http://127.0.0.1:5300 响应。保存的商品会立即在此生效。） Stop

Start the shop 会在游戏中开启商城（如果之前关闭）、确保端口空闲、在你还没有商品目录时复制服务自带的示例目录，并以仅商城模式启动启动器。如果 Login 和 Central 已在运行，它会提示你重启它们，以便它们启动的地图服务器能找到商城；编辑器中的 Play 会立即找到它。如果端口被占用，消息会提示停止占用它的程序，或修改 UserSettings/KitARPG/launcher.json 中的 ShopPort。

退出 Unity 时 Shop 服务会自动停止。

两个折叠区：

  • Keys：Map key（地图服务器向 Shop 出示的凭据）和 Admin key（本页面用于发布的凭据），各带 Copy。只显示前四个字符。"Made for this computer and kept in UserSettings, out of version control. The live server uses its own."（为本机生成，保存在 UserSettings 中，不纳入版本控制。线上服务器使用自己的密钥。）
  • Log：UserSettings/KitARPG/shop.log 的最后 30 行。

#Online server

"Where Publish sends the offers for the live game: the Shop service's address and its admin key (KITARPG_SHOP_ADMIN_KEY). Its admin API is only reachable from inside the server's network, so use a tunnel or a private address."（Publish 把线上游戏的商品发送到哪里：Shop 服务的地址及其管理密钥（KITARPG_SHOP_ADMIN_KEY）。它的管理 API 只能从服务器网络内部访问，因此请使用隧道或私有地址。）

字段 是什么
Address 线上 Shop 服务的地址，例如通过 SSH 隧道
Admin key 线上服务的管理密钥，输入时隐藏

Check 向该地址查询健康状态，并说明它是否有响应。两个值都保存在项目之外的 UserSettings/KitARPG/shop-remote.json 中，因此密钥永远不会进入版本控制。

#Offers 标签页

#发布栏

位于 Offers 和 Real money 标签页顶部：

元素 作用
胶囊标签 Unsaved changes、Live on this computer（已保存且本地商城正在运行）或 Saved
Revert 丢弃未保存的修改并加载已保存的目录。没有修改时显示为灰色
Save 检查目录并写入 UserSettings/KitARPG/shop-conf.json。正在运行的本地商城会立即重新加载它。没有修改时显示为灰色
Pull from server 把线上服务器的目录加载到页面中。如果你有未保存的修改，会先询问。之后保存即可在本机也保留一份
Publish to server 检查目录，询问 "Replace every offer on ... with these N? Players see them at once."（用这 N 个商品替换……上的所有商品？玩家会立即看到。），然后发送到线上服务器

在设置线上服务器的地址和管理密钥之前，Pull 和 Publish 显示为灰色。没有地址时，发布栏下方会有一行说明 Save 会把商品保存在本机。

Save 和 Publish 会拒绝有问题的目录，并以红色列出问题。服务器会再次检查目录，除非每个商品都通过，否则不做任何更改；被拒绝时，页面显示 "The server refused the catalog and kept the one it had."（服务器拒绝了该目录并保留原有目录。）及其原因。接受时显示 "Published N offers to ... (version ...)."。

#商品列表

Offers 卡片列出每个商品：图标、名称、分类和 id、价格及其货币，以及一个状态胶囊标签：

状态 含义
On sale 正在出售
Scheduled 开始日期在未来
Ended 结束日期已过
Hidden 为保留历史而保存，不出售
Problem 其中有错误；打开查看

点击商品会在列表下方打开它；再次点击关闭。列表下方的按钮：

按钮 作用
Add offer 添加 "New Offer"，id 为 new_offer（或 new_offer_2……），使用第一种付费货币，价格为 100
Duplicate 复制打开的商品，使用新 id，并在名称后加上 " (copy)"
Move up、Move down 在列表中移动打开的商品
Delete 会先询问。要停止出售某个商品但保留它，请改为勾选 Hidden

#商品字段

"The id never changes once players bought it: limits and history count by it."（一旦玩家购买过，id 就不能更改：限购和历史都按它计算。）

字段 作用 默认值
Id 小写、无空格，最多 64 个字符。永远不要把一个 id 用于其他东西 必填
Name 显示在卡片上
Description 显示在商品页面上
Category 在游戏中显示的标签页 Featured
Currency 游戏数据库中的一种付费货币 第一种付费货币
Price 大于 0 必填
Icon 卡片显示其图标的物品。留空则使用第一个物品的图标 空
Badge 卡片角上的角标，例如 New 或 Sale，最多 24 个字符。留空则没有；会结束的商品显示 Limited time 空
Order 商城按相关度排序时，较小的值排在前面 0
Picture 卡片和商品页面的图片。留空则绘制图标 空
Banner 宽幅图片。带有横幅的商品会在商城首页的横幅中轮流显示 空

Items：商品给予的每个物品一行，包含物品图标、物品字段、数量（至少 1）以及用于删除的 ✕。Add item 添加一行。商品至少需要一个物品。数据库中不存在的物品会显示 "'id' not in the database"。

Sale

字段 作用 默认值
Starts UTC 日期和时间，例如 2026-12-24T18:00:00Z。留空表示始终有效。旁边显示对应的本地时间。Now 填入当前时间 空
Ends 格式相同。必须晚于 Starts 空
Per account 一个账号可以购买多少次。0 为不限 0
Giftable 玩家可以为其他角色购买；通过邮件送达 On
Hidden 不出售，但为保留历史而保存 Off

商品的问题以红色显示在其卡片底部。

#图片

图片和横幅是精灵。目录是文本，因此商品只保存一个键，精灵存放在 Game Instance 的 Shop Art 资源中。你第一次选择图片时，页面会在网络预制体旁创建 ShopArt.asset，并在 Game Settings 中设置它。没有对应精灵的键会显示 "'key' not in the shop art"。图片随游戏构建发布，因此新图片需要新的客户端构建；商品则不需要。

#Real money 标签页

#Products

"What one unit of a product bought with real money gives. The id is the one your payment provider sends (Stripe's metadata.product, or your web shop's)."（用真实货币购买的一个单位产品给予什么。id 是你的支付提供商发送的那个（Stripe 的 metadata.product，或你的网店的 id）。）

每一行：产品 id、"gives"、数量、付费货币以及 ✕。Add product 添加一行，例如给予 100 个第一种付费货币的 gems_100。产品需要 id、大于 0 的数量和一种付费货币，且 id 必须唯一。

#Letters

"Bought items always arrive by mail, gifts too."（购买的物品总是通过邮件送达，赠礼也是。）

字段 作用 默认值
Sender 装有所购物品的信件的发件人 Shop
Days to collect 超过这个天数后，信件及其物品会消失。1 到 365 30

购买的物品是否直接进入背包，由 Game Settings 中的 Shop Auto Take 设置。

#分步操作：在本地运行商城

  1. 在 Play & Servers 中选择 MMO，构建服务并启动它们。
  2. 打开 KitARPG > Shop 的 Service 标签页。应用列出的所有商城相关套件更新。
  3. 开启 In the game 中的开关。
  4. 按 Start the shop。等待 Running。
  5. 在 Play & Servers 中按 Restart，以便它启动的地图服务器能找到商城。
  6. 按 ▶ Play client，进入世界并按 P 打开商城。用 GM 命令 /currency gems 1000（管理员等级）给自己付费货币来测试购买。参见 GM 命令。

#分步操作：发布目录

  1. 在 Offers 标签页中添加或编辑商品。检查没有显示 Problem 的商品。
  2. 在 Real money 标签页中设置你的产品和信件。
  3. 按 Save。本地商城（如果正在运行）会立即使用新目录。在 Play 中试一试。
  4. 在 Service 标签页中填写 Online server：你线上 Shop 服务的地址（可通过隧道或私有地址访问）及其管理密钥（服务器上的 KITARPG_SHOP_ADMIN_KEY）。按 Check。
  5. 回到 Offers，按 Publish to server 并确认。玩家会立即看到新商品；无需构建或重启。
提示

当其他人可能修改过线上目录时，编辑前先按 Pull from server。发布会替换服务器上的所有商品。

重要

永远不要把线上管理密钥放在 Assets 内的文件中或版本控制中。正因如此，页面把它保存在 UserSettings/KitARPG/shop-remote.json 中。

#单人模式和 MMO

商城只存在于 MMO 游戏中。在单人模式中，开关和模块都没有效果，商城按钮永远不会显示。

#常见错误

  • 商品售出后更改其 id。 限购和历史按 id 计算。请改为新建商品并隐藏旧的。
  • 商城按钮不显示。 模块已关闭、玩家预制体缺少 Player Shop、HUD 缺少商城窗口，或地图服务器无法访问 Shop 服务。应用套件更新，并在启动商城后重启服务。
  • 出售任务物品。 Project Check 会对此发出警告。
  • 构建好的客户端中不显示图片。 带有新精灵的 Shop Art 资源必须在客户端构建中。
