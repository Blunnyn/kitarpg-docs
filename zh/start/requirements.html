入门

系统要求

使用 KitARPG 时你的电脑需要什么、哪些是可选的，以及每一部分的用途。请在安装之前阅读，以免中途卡住。

#简要版本

  • 以单人模式游玩示例：Unity 6.6（6000.6.0f1）或更新版本。不需要其他东西。
  • 在你的电脑上以 MMO 游玩示例：上述内容加上 .NET 10 SDK。
  • 部署 MMO：上述内容加上 Unity 中的 Linux Dedicated Server 构建支持，以及一台装有 Docker 的机器。

#Unity

要求 值 说明
Unity 版本 6000.6.0f1（Unity 6.6）或更新 套件支持的最低版本。更旧的版本无法编译它
渲染管线 Universal Render Pipeline 17.6 Setup Wizard 会开启它。套件的材质是 URP 材质，没有它会显示为粉色
颜色空间 Linear 由 Setup Wizard 设置
TextMesh Pro essentials 已导入项目 由 Setup Wizard 导入。缺少它们，套件 UI 中的每个标签都没有字体
Active Input Handling Input System、Input Manager 或两者 套件通过自己的 KitInput 层读取输入，两者皆可
编辑器平台 macOS 或 Windows 本地地图服务器构建和启动器的默认设置针对 Mac 和 Windows。编辑器的 SQLite 库也附带 Linux 版本

#Unity 包

KitARPG 包声明了它所需的 Unity 包。导入时 Unity 会为你安装它们，因此空项目也可以使用。

包 Id 版本 用途
Universal RP com.unity.render-pipelines.universal 17.6.0 渲染
AI Navigation com.unity.ai.navigation 2.0.14 服务器上玩家和怪物使用的 NavMesh
uGUI com.unity.ugui 2.6.0 整个界面，配合 TextMesh Pro
Input System com.unity.inputsystem 1.20.0 项目使用它时的键盘、鼠标和触屏输入
Test Framework com.unity.test-framework 1.8.0 套件的 Play 模式测试。可选：移除后套件仍能编译

网络使用 Mirror 加 KCP 传输（UDP）。Mirror 包含在包内，位于 Assets/Mirror；你不需要单独安装。

#可选的 Unity 包和模块

项目 用于 如何获取
Multiplayer Play Mode 3.0（com.unity.multiplayer.playmode） Play with two players，会打开第二个编辑器 第一次点击该按钮时会提示安装
Mac Build Support (IL2CPP) Mac 客户端和 Mac 单人游戏 Unity Hub > Installs > Add modules
Windows Build Support (IL2CPP) Windows 客户端和 Windows 单人游戏 Unity Hub > Installs > Add modules
Linux Dedicated Server Build Support (IL2CPP) 用于 Docker 的 Linux 地图服务器（KitARPG > Starter > Build Linux Server） Unity Hub > Installs > Add modules
com.unity.toolchain.macos-arm64-linux 在 Mac 上构建 Linux 地图服务器 Package Manager > Add package by name
注意

发布给玩家的客户端始终用 IL2CPP 构建。构建检查会阻止用 Mono 构建的 MMO 客户端，因为其代码会以可读的 DLL 形式发布。Windows 的 IL2CPP 构建在 Windows 上进行，Mac 的在 Mac 上进行。参见构建。

#MMO 所需：.NET 10 SDK

Login、Central、Shop 和启动器都是 .NET 10 程序。编辑器会为你编译并运行它们，但需要 SDK。

要求 值 说明
.NET SDK 10.x 免费，可从 https://dotnet.microsoft.com/download/dotnet/10.0 获取。仅有运行时不够：编辑器要从源码构建服务

由于 Unity 并不总能拿到你 shell 的 PATH，编辑器会在以下位置查找 dotnet：

  • PATH 中的每个文件夹。
  • Windows：C:\Program Files\dotnet\dotnet.exe。
  • Mac 和 Linux：/usr/local/share/dotnet/dotnet、/usr/local/bin/dotnet、/opt/homebrew/bin/dotnet、/usr/share/dotnet/dotnet 和 ~/.dotnet/dotnet。

安装后，在 Play & Servers 中按下 .NET 10 SDK 那一行下方的 Check again。Play & Servers 会显示它找到的版本（"Installed: ..."）。

#可选：Docker

项目 用于
Docker Desktop（Mac、Windows）或 Docker Engine（Linux） 一键在你的电脑上运行 PostgreSQL（Set up PostgreSQL... > Docker on this computer），以及用 Docker Compose 部署

制作游戏或在本地游玩 MMO 都不需要 Docker：SQLite 无需安装任何东西即可使用。

#可选：PostgreSQL

SQLite 足够用于开发和小型服务器。生产环境请使用 PostgreSQL。任何 PostgreSQL 服务器都可以：你电脑上的、VPS 上的，或者托管服务，例如 RDS、Supabase 或 Neon。使用 Docker 时，套件会为你运行 PostgreSQL 17。参见数据库。

#你的电脑上使用的端口

在本地运行 MMO 时，这些端口必须空闲。如果有其他程序占用它们，Play & Servers 会发出警告。

端口 协议 使用者
5100 TCP (HTTP) Login
5200 TCP (HTTP) Central
5300 TCP (HTTP) Shop（仅在运行时）
7700 UDP Central 的地图连接，地图服务器连接到这里
7777 UDP town 的地图服务器
7778 UDP forest 的地图服务器
7779 UDP crypt 的地图服务器
5432 及以上 TCP Docker 中的 PostgreSQL，使用从 5432 起第一个空闲的端口

#硬件

除了 Unity 6.6 的要求外，套件没有特殊的硬件需求。请注意：

  • 第一次构建地图服务器需要几分钟；之后会更快。
  • Play with two players 会运行第二个 Unity 编辑器，它占用的内存与第一个差不多。第一次打开时它会导入项目。
  • 在 MMO 中，每张正在运行的地图都是一个独立进程。示例会随服务一起启动 town，在玩家第一次进入 forest 和 crypt 时再启动它们。

#对你的游戏玩家而言

构建 玩家需要
单人模式 不需要其他东西。存档是玩家数据文件夹中的一个 SQLite 文件
MMO 客户端 能够连接到你的 Login 和 Central 地址（HTTPS）以及地图服务器 UDP 端口的网络
