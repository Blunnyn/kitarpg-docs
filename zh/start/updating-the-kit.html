更新套件

如何把更新版本的 KitARPG 引入你已经做好的游戏中而不丢失工作成果：导入会替换什么、什么是套件更新、套件附带的每一项更新，以及之后需要重新构建什么。

#你使用的是哪个版本

  • KitARPG 窗口中的 Overview 会在 "Version" 处显示套件版本，例如 1.0.0。
  • KitARPG > What's New 显示更新日志，并高亮你当前的版本。
  • 更新日志页面列出了每个版本。

#两种变化

新版本的套件会以两种方式改变你的项目：

变化 如何到来 影响什么
新增和修复的套件文件 导入新包 Assets/Blunnyn/KitARPG、Assets/Blunnyn/Art、Assets/Mirror 内的文件，以及 Services~ 中的服务
套件更新 你在 Overview 中应用它们 新套件期望而你的游戏缺少的东西：数据库中的某种货币、玩家预制体上的某个组件、HUD 中的某个窗口

导入会替换套件文件。之后套件更新会补充你自己的游戏资源所需的内容，而不重建它们。

#更新之前

  1. 提交或备份你的项目。 这样之后的每一步都可以安全撤销。
  2. 把你的游戏放在套件文件夹之外。 你在 Assets/Blunnyn 内修改的任何东西都可能被导入替换。这包括 Samples/Starter 中的入门示例：如果你是直接修改示例来制作游戏的，请先把修改过的资源复制到你自己的文件夹。参见项目结构。
  3. 在 Play & Servers 中停止 Play 并停止服务。
  4. 阅读更新日志中新版本的条目。

#分步操作

  1. 打开 Window > Package Manager > My Assets，找到 KitARPG 并按下 Update（或 Download），然后按 Import。
  2. Import Unity Package 窗口会标出新增和修改的文件。导入所有属于套件的内容。
  3. Unity 导入并编译。如果新版本声明了更新的 Unity 包，Unity 会安装它们。
  4. 服务被重新解压。 当新的 Services.zip 带有不同的服务版本时，编辑器会把它解压覆盖到 Assets/Blunnyn/KitARPG/Services~。Console 显示 [KitARPG] Services <version> unpacked to ...。
  5. What's New 打开一次。 它列出每个版本，最新的在前，并高亮你的新版本。Open the file 打开 Documentation/CHANGELOG.md。Close 关闭它。
  6. 应用套件更新。 打开 KitARPG 窗口。Overview 的 To do 显示 "N kit updates" 及其标题，侧边栏显示带有数量的角标。参见应用套件更新。
  7. 运行 Project Check 并修复它发现的问题。
  8. 在 MMO 中，重新构建在编辑器之外运行的内容，顺序如下：
    1. Play & Servers > 第 1 步 > Services built > Rebuild。
    2. Play & Servers > 第 1 步 > Map server build > Rebuild。
    3. Restart 服务。
    4. 重新构建你的客户端。客户端和地图服务器必须来自同一份代码，否则玩家会看到 "The game and the server are different versions"。
警告

解压新版本服务时，你在 Services~ 内手动做的修改会被覆盖。要修改服务，请使用服务模块，或者把服务复制到项目旁边的 Services 文件夹，并把 Services source 指向它。拥有自己 Services 文件夹的项目永远不会使用 zip。

#应用套件更新

套件更新是新版套件为用旧版制作的游戏添加的内容。它只添加缺失的东西：永远不会重建你的 HUD、预制体或数据，因此你手动修改过的内容会保留。

#在哪里看到它们

位置 显示什么
Overview > To do "N kit updates" 及其标题，以及一个 Apply 按钮
KitARPG 窗口侧边栏 Overview 上带有数量的角标
Play & Servers，MMO 第 1 步 "N kit updates" 及 Review，提醒你在构建地图服务器之前应用它们
Shop 页面 商城需要的更新
Project Check 每项更新一条警告（"... is missing."），并带有自己的 Apply

#运行更新

  1. 按下 Apply。如果编辑器处于 Play 中，会弹出对话框提示 "Stop Play first."。
  2. 一个标题为 Kit updates 的对话框列出每项更新及其将做的具体改动，最后写着 "Nothing else changes."（不会改动其他任何东西。）
  3. 按 Apply 运行它们，或按 Cancel。
  4. 它们按顺序运行。每项都会在 Console 中记录 [KitARPG] <title>: <result> 并保存资源。
  5. 如果某项失败，对话框会在 "Some couldn't be applied:" 下列出原因；其余的仍会运行。修复原因（通常是缺少 HUD 预制体或数据库）后再次应用。

轮到某项更新时如果它已不再需要，会被跳过。更新每隔几秒检查一次自身，因此一旦应用，数量就会下降。

#本版本中的更新

按运行顺序列出。

更新 何时显示 改动什么
Premium currency for the shop In-game shop 模块已开启，且数据库中没有付费货币也没有 gems 在你其他货币旁创建货币 Gems（id gems，Premium，不在背包中显示），并把它加入你的 Game Database。现有货币保持不变
Shop on the player prefabs 商城已开启，且某个玩家模型缺少 PlayerShop 把 PlayerShop 组件添加到列出的玩家预制体上。它们的其他内容不变
Shop window in the HUD 商城已开启，且 HUD 预制体中没有 Cash Shop Window 在你 HUD 的 Windows 下添加一个 Cash Shop Window，并在工具栏的 Mail 之后添加一个 Shop 按钮，把其后的按钮后移以腾出位置
New shop window: categories, banner and offer pages HUD 中是旧的商城窗口 用新的商城窗口替换它：分类和搜索、排序、带充值按钮的余额、横幅、带角标的卡片，以及每个商品一个页面。你对旧商城窗口的手动修改会丢失；HUD 的其余部分保持不变
Guild emblems Guilds 模块已开启，且数据库中没有 Guild Emblems 资源 在你的数据库旁创建一个 Guild Emblems 资源（8 种形状、24 个符号、12 种颜色）并在数据库中设置它。之后公会在创建时可以选择徽章
Guild roles, emblem, history and alliance windows in the HUD Guilds 模块已开启，且 HUD 的公会窗口缺少联盟窗口、权限列表或职位下拉框 在 Windows 下添加 Guild Emblem Picker、Guild History Window 和 Alliance Window；在公会窗口中添加 Emblem、History 和 Alliance 按钮；添加一行说明创建公会的要求。成员使用职位下拉框代替 Up 和 Down，Roles 标签页重新制作为职位列表，旁边显示所选职位的权限
Upper body mask on the player models 某个人形玩家模型没有上半身遮罩 如果缺失则创建 Upper Body 遮罩（脊柱、头部和手臂），并设置到每个列出模型的 Character Animations 上，这样边走边开始的攻击和施法只会移动上半身。在模型上清空该字段即可撤销
Touch controls: skills 1 to 4 and potion on 5 触屏操控预制体仍有 Dodge 按钮，或技能按钮不在弧形排列中 把 Skill 1 到 4 移到 Attack 周围呈弧形排列，把 Consumable 按钮移到左上角，并移除 Dodge（第三人称中闪避仍在其按键上）。你手动移动过的按钮会被移回
Unread mail count on the Mail button HUD 工具栏有一个不带角标的 Mail 按钮 在 Mail 按钮上添加一个显示未读信件数量的红色角标。HUD 的其他部分不变
注意

有两项更新会替换某个部件而不是在其上添加：新的商城窗口，以及公会窗口的 Roles 标签页。如果你重新设计过这些部件，请在按 Apply 前阅读对话框，并在之后重做你的修改。

#Start over 不是更新

Overview 中的 Start over（示例存在时等同于 KitARPG > Starter > Build Scenes and Prefabs）会从头重新构建入门示例。它会先询问，并且会丢失对示例场景、预制体、HUD 和数据所做的每项修改。你在其他文件夹中的资源会保留。

用它来获取一份干净的示例以供查看。永远不要用它来更新基于示例制作的游戏：请改用导入和套件更新。

#编写你自己的更新

你可以发布自己的更新，例如在你跨多个游戏复用的模板中。一个带有标题、所做改动、检查和改动本身的 KitUpdate 子类会自动出现在 Overview 中。参见代码中的套件更新。

#常见错误

错误 结果 解决办法
直接修改示例，然后导入新套件 你对示例文件的修改可能被替换 把你的游戏放在自己的文件夹中
更新后没有重新构建地图服务器 玩家看到 "The game and the server are different versions" 重新构建并重启服务
在构建地图服务器之后才应用更新 地图服务器缺少更新添加的内容 先应用更新，再构建
按 Start over 来更新 示例被重建，你对它的修改丢失 使用套件更新
忽略更新列表 新代码期望的窗口或组件缺失 应用它们，或在 Project Check 中逐项查看
