入门

项目结构

KitARPG 的每个部分在你的项目和磁盘上位于何处，哪些文件夹你可以编辑，哪些属于套件，哪些永远不会离开你的电脑。在开始添加自己的内容之前请阅读本页，这样更新永远不会覆盖你的工作。

#全局概览

YourWorkspace/
├── YourUnityProject/
│   ├── Assets/
│   │   ├── Blunnyn/
│   │   │   ├── KitARPG/          The kit (read-only for you)
│   │   │   └── Art/              The kit's voxel art
│   │   ├── Mirror/               Networking library
│   │   ├── ScriptTemplates/      Mirror's script templates
│   │   ├── Settings/             URP assets and KitARPGSettings
│   │   └── Game/                 Your game (you make this folder)
│   └── UserSettings/
│       └── KitARPG/              This computer only: keys, local database, logs
└── Builds/
    ├── Starter/                  Builds made from the KitARPG menus
    └── ...

Builds 文件夹位于你的 Unity 项目文件夹旁边，而不是里面。

#套件：Assets/Blunnyn/KitARPG/

文件夹 内容
Runtime/Shared/ 不依赖 Unity 的纯 C#，与 .NET 服务共享：账号和角色规则、背包规则、发给 Central 的消息、错误码。程序集 KitARPG.Shared
Runtime/Data/ 数据资源及其规则：职业、属性、物品、技能、状态、怪物、任务、条件、动作、地图、GameDatabase、GameInstance。程序集 KitARPG.Data
Runtime/Net/ 用 Mirror 处理的所有网络内容：玩家、怪物、NPC、战斗、聊天、公会、游戏日志、网络管理器。程序集 KitARPG.Net
Runtime/Server/ 仅地图服务器使用：与 Central 的连接、GM 命令、实例、奖励、Shop 客户端。程序集 KitARPG.Server，不会进入 MMO 客户端构建
Runtime/Local/ 单人模式的 SQLite 存档。程序集 KitARPG.Local，只在单人模式构建中
Runtime/Client/ 界面、窗口、HUD、标题界面、会话、输入（KitInput）、触屏操控、选项。程序集 KitARPG.Client
Runtime/Resources/KitARPG/ 套件按名称加载的资源，例如角色 Animator 控制器 KitCharacter.controller
Modes/TopDown/ 俯视角模式：Runtime（镜头和输入）和 Server（服务器上的移动和动作）
Modes/ThirdPerson/ 第三人称和自由视角模式，以同样方式划分
Editor/ KitARPG 窗口及其页面、Setup Wizard、Game Database、Project Check、构建工具、入门示例生成器和套件更新。程序集 KitARPG.Editor
DevKit/Example/Bounties/ 悬赏板示例，按游戏的方式构建，有自己的程序集
Samples/Starter/ 入门示例（见下文）
Tests/PlayMode/ 套件的 Play 模式测试。程序集 KitARPG.Tests.PlayMode，永远不会进入构建
Plugins/LiteNetLib/ 地图服务器与 Central 通信所用的库
Plugins/SQLite/ 用于 macOS、Windows 和 Linux 的原生 SQLite 库，供单人模式存档使用
Documentation/ 本文档：Web/ 中的网站版本（由 KitARPG > Documentation 打开）、GettingStarted.md、DevKit.md、CHANGELOG.md、API/ 中的 API 参考以及 PDF 手册
Services.zip .NET 服务的源代码，以包内发布的形式提供
Services~/ 由编辑器解压的 Services.zip。Unity 不会导入它

#程序集

程序集 进入哪里
KitARPG.Shared、KitARPG.Data、KitARPG.Net、KitARPG.Client 每个构建
KitARPG.Modes.TopDown、KitARPG.Modes.ThirdPerson 每个构建
KitARPG.Server、KitARPG.Modes.TopDown.Server、KitARPG.Modes.ThirdPerson.Server 仅地图服务器和单人游戏
KitARPG.Local 仅单人游戏
KitARPG.Editor 仅编辑器
KitARPG.Tests.PlayMode 仅编辑器，且开启测试时

KitARPG > Check Build Separation 会显示每种构建包含哪些代码。参见程序集。

#入门示例：Samples/Starter/

文件夹或文件 内容
Scenes/ Title.unity、Server.unity、Town.unity、Forest.unity、Crypt.unity，以及每个地图场景一个文件夹，存放其光照和 NavMesh 数据
Prefabs/ KitNetwork.prefab（带有保存 Game Settings 的 GameInstance 的网络管理器）、GameHud.prefab、TouchControls.prefab、玩家预制体 PlayerMale、PlayerFemale 和 PlayerPanda、怪物预制体，以及存放可复用 UI 部件的 UI/
Data/ 每个游戏数据资源：StarterDatabase.asset、Attributes/、Classes/、Currencies/、Elements/、Items/、Skills/、Statuses/、WeaponTypes/、Monsters/、Quests/、Shops/、Maps/、Guilds/、镜头设置、经验表、公会徽章、商城美术和上半身遮罩
Effects/ 命中、施法、投射物、区域和状态的粒子特效
Materials/ 示例地图的材质
StarterAppearance.asset 模块化角色的身体、头发和装备网格目录
场景 作用
Title 登录、角色列表和创建。必须是 Build Settings 中的第一个
Server 地图服务器在加载其地图之前启动时所在的空场景。MMO 中需要
Town 起始地图：商店、任务发布者、仓库管理员、公会服务
Forest 怪物、一个首领、分昼夜的刷怪
Crypt Sunken Crypt，一个实例化副本
警告

Overview 中的 Start over 和 KitARPG > Starter > Build Scenes and Prefabs 会从套件代码重新构建示例，并丢失在 Samples/Starter/ 内所做的所有修改。导入更新的套件也可能替换那里的文件。请先把你想修改的东西复制到你自己的文件夹中。参见更新套件。

#美术：Assets/Blunnyn/Art/

文件夹 内容
3D/VoxelHero/ 体素身体（VoxelMale、VoxelFemale、VoxelPanda）、Gear/（头发、帽子、胸甲、背部、手套、腿部、靴子、武器）、Monsters/，以及共享的 VoxelHero.mat 及其调色板纹理

Anims/ 人形角色动画（Little Heroes Mega Pack）和 Humanoid.controller
Sprites/ 物品、技能、元素、数值和分类的 Icons/，公会 Emblems/，Shop/ 美术和 UI 精灵

#套件使用的项目设置

路径 是什么
Assets/Settings/Resources/KitARPGSettings.asset 游戏的运行方式：mode（MMO 或单人模式）、构建使用的 loginUrl 和 centralUrl、单人模式的 saveFile。缺失时会被创建
Assets/Settings/KitARPG_URP.asset 项目没有 URP 资源时 Setup Wizard 创建的那个

KitARPGSettings 字段：

字段 作用 默认值
Mode（mode） Online（MMO）或 SinglePlayer。由 Play & Servers 和 Setup Wizard 设置；构建会根据构建类型设置它 Online
Login Url（loginUrl） MMO 客户端使用的 Login 地址 http://127.0.0.1:5100
Central Url（centralUrl） MMO 客户端使用的 Central 地址 http://127.0.0.1:5200
Save File（saveFile） 单人模式存档，位于玩家的持久化数据文件夹中 savegame.db
重要

在为玩家构建 MMO 客户端之前，把 Login Url 和 Central Url 设为你服务器的 https:// 地址。发布版客户端拒绝明文 HTTP（连接本机除外），如果它们不是 HTTPS，构建会中止。

#仅限本机：UserSettings/KitARPG/

Unity 永远不会把 UserSettings 放进构建，版本控制通常也会忽略它。这里的一切都专属于你的电脑。

文件或文件夹 是什么
setup-done Setup Wizard 已运行过
seen-version 本项目上次打开的套件版本，供 What's New 使用
launcher.json Play & Servers 使用的启动器设置：端口、数据库、地图、密钥
launcher.pid 正在运行的启动器，以便编辑器重启后能找到它
services.log 从编辑器启动的服务的输出
data/kitarpg.db MMO 的本地 SQLite 数据库：账号、角色、物品、公会、邮件
data/logs/map-<id>.log 每个地图服务器的日志
quickplay.json Play with two players 使用的测试账号
shop-conf.json 本地商城目录
shop.log、shop.pid 从编辑器启动的 Shop 服务
modules/ 本地启动器加载的 Login（login/）和 Central（central/）模块
重要

launcher.json 保存着签名密钥和地图密钥。不要提交或分享它。

#服务：Services~/

文件夹 内容

Data/ 数据库实体、每个提供程序（SQLite 和 PostgreSQL）一个上下文及其迁移
Hosting/ 各服务共享的设置：令牌、封禁、游戏日志写入器
Modules/ Login 和 Central 模块的契约
Login/ 账号和角色
Central/ 会话、票据、地图、社交系统
Shop/ 可选的付费商城服务
Launcher/ 启动一切，带窗口或无界面
Examples/Bounties/ 悬赏板示例的 Central 部分
Tests/ 规则、Login 和 Central 的测试
KitARPG.Services.slnx 解决方案
README.md 端点、设置和生产环境安全

参见服务。

#你的游戏放在哪里

把你制作的所有东西都放在 Assets/Blunnyn 之外：

Assets/Game/
├── Game.asmdef           Create > KitARPG > Scripts > Game Assembly
├── Data/                 Your items, skills, monsters, quests, maps
├── Prefabs/              Your player models, monsters, HUD copy
├── Scenes/               Your maps
├── Scripts/              Your code
└── Editor/               Game Editor Assembly and your tools

步骤：

  1. 创建一个文件夹，例如 Assets/Game。
  2. 要写代码，右键点击它并选择 Create > KitARPG > Scripts > Game Assembly。那里的脚本可以访问套件。
  3. 用 Game Database 的 New 按钮创建新数据，然后把资源移到你的文件夹中；或者复制示例资源并移动副本。
  4. 要制作自己的地图，把 Forest.unity 复制到你的文件夹并添加一个地图条目。参见地图。

id 一旦创建就不依赖文件名或文件夹，因此移动资源是安全的。
