入门

快速入门：MMO

在你自己的电脑上以 MMO 方式运行示例：构建服务和地图服务器、启动它们、创建账号、游玩，并看到两名玩家相遇。一切都通过 KitARPG 窗口的 Play & Servers 页面完成。

#你即将运行什么

组件 作用 你电脑上的端口
Login 账号、登录、角色列表和角色创建 5100 (HTTP)
Central 会话、进入地图的一次性票据、聊天、好友、队伍、公会、邮件、市场；启动地图服务器 5200 (HTTP)、7700（UDP 地图连接）
地图服务器 每张地图一个 Unity 服务器，运行游戏 7777 town、7778 forest、7779 crypt (UDP)
Shop（可选） 付费货币、商品、购买、支付 5300 (HTTP)
数据库 SQLite 文件或 PostgreSQL

编辑器通过启动器运行这一切，不显示窗口。第一位玩家需要某张地图时，Central 会从你的地图服务器构建启动该地图服务器；town 随服务一起启动。

#开始之前

  • 完成 Setup Wizard。
  • 从 https://dotnet.microsoft.com/download/dotnet/10.0 安装 .NET 10 SDK。参见系统要求。
  • 确保端口 5100、5200、7700 和 7777 到 7779 空闲。

#分步操作

#1. 打开 Play & Servers 并选择 MMO

  1. 打开 KitARPG 窗口：KitARPG > Open KitARPG 或 Ctrl/Cmd+Shift+K。
  2. 进入 Play & Servers。
  3. 点击顶部的 MMO 卡片。

卡片下方会出现四个编号步骤。它们按顺序解锁：已完成的步骤会带着勾号折叠起来，当前步骤展开，锁定的步骤暂时无法打开。每个步骤的标题会概括它的进展。

#2. Step 1: Check the project

步骤标题显示有多少项检查已就绪（"3 of 5 ready."）。从上到下逐行处理：

行 正常情况 按什么
Scenes in Build Settings Title 是第一个场景，且列出了 Server Use starter scenes
.NET 10 SDK "Installed: 10.x..." Get .NET 打开下载页面。安装后按 Check again
Services source 显示包含 KitARPG.Services.slnx 的文件夹，通常是 Assets/Blunnyn/KitARPG/Services~ Browse 选择其他文件夹
Services built "Login, Central and the launcher are compiled." Build services。它对服务运行一次 dotnet build。之后按钮显示为 Rebuild
Map server build "Ready. Rebuild after changing scenes or server code." Build。在 Mac 上运行 KitARPG > Starter > Build Mac Server，在 Windows 上运行 Build Windows Server。第一次构建需要几分钟

还可能出现另外两行：

  • N kit updates，当套件有你的游戏还没有的更新时出现。在构建地图服务器之前按 Review 并应用它们，这样两者都会包含更新。
  • In-game shop，当 Shop 服务可用时出现。它会说明商城是关闭的、正在运行，还是已开启但未运行，并提供 Open Shop。商城是可选的；参见 Shop 页面。

地图服务器构建输出到 Builds/Starter/MacServer/KitARPGServer.app 或 Builds/Starter/WindowsServer/KitARPGServer.exe，位于你 Unity 项目文件夹旁边的 Builds 文件夹中。每次构建都会记下它携带的场景，因此 Play & Servers 知道某张地图的场景何时缺失。

警告

修改场景、添加地图或修改服务器代码后，请重新构建地图服务器。比你的代码旧的地图服务器可能会以 "The game and the server are different versions" 拒绝客户端；缺少某张地图场景的服务器会把前往那里的玩家送回登录界面。

如果 Build services 失败，该步骤会显示最前面的几行错误。如果没有错误行："dotnet build failed. Run it in a terminal to see why."（dotnet build 失败。请在终端中运行以查看原因。）在服务文件夹中打开终端并运行 dotnet build 查看完整输出。

#3. Step 2: Pick the database

选项 何时使用
SQLite: a local file（默认） 开发和小型服务器。无需安装任何东西
PostgreSQL: for production 生产环境，或者想在与部署相同的数据库上开发

在本快速入门中保留 SQLite。文件是 UserSettings/KitARPG/data/kitarpg.db。

PostgreSQL 需要一个连接：Set up PostgreSQL... 可以连接到你运行的服务器，可以为你创建数据库和用户，也可以在 Docker 中运行 PostgreSQL 17。你也可以手动填写连接字符串。参见数据库。

Keys 一行说明签名密钥和地图密钥是为这台电脑生成的，保存在 UserSettings/KitARPG 中。New keys 会生成新的签名密钥和地图密钥。服务运行时它不可用。用旧密钥签名的令牌将不再被接受，因此已登录的客户端需要重新登录。

服务运行时无法更改数据库："Stop the services to change the database."（停止服务以更改数据库。）

#4. Step 3: Start the services

  1. 按下 Start services。

  2. 出现三个指示灯：

    指示灯 详情
    Login 账号和角色，端口 5100
    Central 会话、聊天、公会和地图，端口 5200
    Maps "Started by Central when someone enters"（有人进入时由 Central 启动），然后是已注册的地图

    每个指示灯显示 off、starting 或 up。

  3. 等到 Login 和 Central 都是 up。然后步骤标题显示 "Running. Maps: ..." 并折叠起来。

服务运行时，该步骤提供 Restart 和 Stop。服务启动前会先导出游戏数据：Play & Servers 写入 Login 用来创建角色的 gamedata.json。

Map in the editor 选择一张在本编辑器中运行、而不是从构建运行的地图，以便你调试它。目前保持 "None, every map runs from the map server build"。只有在服务停止时才能更改它。

此步骤可能显示的警告：

消息 含义 解决办法
"Services from an earlier editor session are still running (process ...)" 编辑器重启前启动的启动器仍占用着端口 Stop the old services
"Something else is using port ..." 从终端或其他会话启动的服务占用着端口 停止它们，再启动这里的服务
"The services or the map server were rebuilt after they started, so they still run the old code. Restart them." 你在它们运行时重新构建了 Restart

#5. Step 4: Play

  1. 按下 Play client。编辑器打开 Title，并以客户端身份加入正在运行的服务，地址为 http://127.0.0.1:5100（Login）和 http://127.0.0.1:5200（Central）。
  2. 登录界面出现，包含 Username、Password、Remember me、Sign in automatically、Sign in 和 Create account。
  3. 输入用户名（3 到 16 个字母、数字或 _）和密码（8 个或更多字符），然后按 Create account。状态显示 "Creating account..."，然后是 "Account created, signing in..."。
  4. 角色列表打开。按 New，填写 Name、Look、Class 和 Hair，然后按 Create。每个字段的规则见快速入门：单人模式。
  5. 选中角色并按 Play。Central 给客户端一张 town 的票据，你出现在城镇中。

Remember me 会在这台电脑上保存一个一次性令牌，这样下次不用输入密码；密码本身永远不会被保存。Sign in automatically（仅在勾选 Remember me 时可用）会在启动时自动登录。要以其他身份登录，在角色列表上按 Sign out。

#同时两名玩家

第 4 步中的 Play with two（Overview 和 KitARPG > Play With Two Players 中也有）会展示两名玩家相遇：

  1. 如果服务已停止，它会启动服务。
  2. 它用 Unity 的 Multiplayer Play Mode 打开第二个编辑器。如果缺少该包，它会提示安装（"Install"）。
  3. 当 Login 有响应且第二个编辑器已打开时，它会在两边都按下 Play。每一边都会用为这台电脑创建的测试账号和角色自动登录：kitplayer1 操控 Aria，kitplayer2 操控 Bram。它们保存在 UserSettings/KitARPG/quickplay.json 中。

第一次时，第二个编辑器会导入项目，需要一段时间。如果 Player 2 无法自动启动，Multiplayer Play Mode 窗口会打开：在那里开启 Player 2，然后再按一次按钮。

要超过两名玩家，第 4 步中的 Built client 提供 Build（为你的平台构建 MMO 客户端）和 Open：想开多少个构建好的客户端都可以。每个打开时都会连接到本地服务。

#在编辑器中运行一张地图

要调试某张地图的服务器代码：

  1. 停止服务。
  2. 在第 3 步中，把 Map in the editor 设为该地图，例如 forest: runs in this editor, to debug it。
  3. 启动服务。Central 现在会等待该地图注册，而不是启动它。
  4. 在第 4 步中，按 Play map server: forest。编辑器以该地图服务器的身份运行 Server 场景。
  5. 用构建好的客户端或 Play with two 加入：走进森林的玩家会落在你的编辑器中。

#让自己成为管理员

新账号的 GM 等级从 1（Player）开始。要在线上使用 GM 命令，需要在数据库中设置第一位管理员。使用默认的 SQLite 数据库时，停止服务并运行：

sqlite3 UserSettings/KitARPG/data/kitarpg.db "UPDATE accounts SET \"Role\" = 4 WHERE \"Username\" = 'yourname';"

使用 PostgreSQL 时：

UPDATE accounts SET "Role" = 4 WHERE "Username" = 'yourname';

之后，管理员可以在游戏中用 /role player level 更改等级。参见 GM 命令。

#日志

Play & Servers 底部的 Log 卡片显示服务输出的最后几行。Open log file 打开 UserSettings/KitARPG/services.log。每个地图服务器把自己的日志写入 UserSettings/KitARPG/data/logs/map-<id>.log。

#停止

在第 3 步中按 Stop。启动器会停止 Login、Central 以及它启动的每个地图服务器。关闭编辑器并不总能停止它们：如果下次它们还在运行，Play & Servers 会提供 Stop the old services。

#最常见的问题

症状 解决办法
登录界面显示 "Can't reach the server." 服务没有运行，或 Login 还没有 up。检查第 3 步
"That map is not running right now. Try again in a moment." Central 无法启动该地图。地图服务器构建缺失或损坏；检查 UserSettings/KitARPG/data/logs 中该地图的日志
"The game and the server are different versions. Update the game." 地图服务器是用旧代码构建的。重新构建并按 Restart
Overview 中显示 "No map reached Central" 地图服务器构建缺失或已过期。构建它并重启
前往某张地图时被送回登录界面 地图服务器构建缺少该地图的场景。重新构建
"Your character is still being saved. Try again in a moment." 你在旧会话保存期间再次登录了。等几秒钟

更多内容见故障排除。
